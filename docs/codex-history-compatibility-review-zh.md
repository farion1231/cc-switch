# Codex 历史会话连接兼容评审与验证

初始修复基线：`cb90a2440d1a771d67f46b65b2e0f2ea5106ce85`。本轮合并检查基线：上游 main `cae7c375`。

## 需求与设计评审

| 维度 | 收敛结果 |
|---|---|
| 用户价值 | 一次性处理受管旧标识，后续切换仅更新共享连接，不反复全量改历史 |
| 事实与范围 | 配置兼容属于既有缺口，不依赖多供应商计费；不更改用量或账单 |
| 可信度 | 文件可读、配置可载入与真实推理分开验收，不能互相代替 |
| 演进 | 自定义来源须有卡片连接定义，旧完成标记不屏蔽用户再次手动迁入的新历史 |
| 效能 | 修改仅在有旧标识时发生，扩展补迁须在设置中确认，启动和切换不自动扩大迁移范围 |
| 变更成本 | 复用备份、压缩和索引定位模块，不增加配置系统或外部运行时 |
| 可维护 | 迁移与恢复共用等长 JSON 补丁，避免两个不同安全实现 |
| 数据安全 | 不改正文/模型/凭据；目标增长无法保持偏移时跳过并计数，不假装全部成功 |
| 并发与恢复 | 普通文件局部比较写入、保留追加；跨文件部分成功用原件和幂等重试收口 |
| 可观测 | 致命失败不写完成标记；文件级跳过记录数量及后端日志，手动界面报告处理结果 |

评审结论：可以实现；已明确外部客户端配置缓存、跨后端加密内容和过长 provider ID 的能力边界。此评审是多维度自审，不是外部独立验收。

## v4.0.19 合并检查与恢复边界复查

合并检查基线为上游 `d8983bb1`（v4.0.19）。没有文本冲突；复查发现以下两类恢复边界问题，并补充五项回归。

| 问题 | 修正与验收证据 |
|---|---|
| 手动迁入仅校验日志路径列，缺少 ID 或 provider 列时仍可能先改日志 | 文件处理前检查 `threads` 及 `id`、`model_provider`、`rollout_path` 三列；四种缺失布局验证返回错误且原文件不变 |
| 索引阶段失败后，先前日志备份缺少目录归属，可能作用到另一目录相同 ID 的会话 | 备份原件前写入并验证目录归属；真实 SQLite BLOB ID 解析失败发生后，另一目录的同 ID 日志仍保持原值、不被账本采纳 |
| 损坏的显式归属信息被当作无目录旧备份 | JSON 损坏、缺少字段、字段类型错误和归属文件不可读均拒绝；现有无归属文件的早期备份兼容测试继续通过 |
| 备份目录已属于别的来源，原日志仍被改写 | 备份写入前验证现有归属，不匹配时停止该文件的改写 |
| 归属文件是失效符号链接时，被误认为完全不存在 | 检查目录项本身是否缺失；失效链接既不能作为早期备份被采纳，也不能被新归属信息静默覆盖，原日志不变 |

五项新增回归均先在修改前观察到预期失败，再验证修复后通过。聚焦命令 `cargo test --manifest-path src-tauri/Cargo.toml --lib codex_history_migration::tests:: -- --test-threads=1`：macOS 下 51 项通过、0 失败，其中失效符号链接回归仅在 Unix 平台运行。文档同步明确并发、备份损坏和跨后端恢复的能力边界，不作“所有异常下都不会丢失”的承诺。

| 演进与兼容 | 完成状态及来源按目录保存，兼容读取旧单条记录；无目录标记不能证明当前目录，A→B→A 不混用、不丢失来源 |
| 效能与变更成本 | 不在供应商切换时扫描会话，不改计费或正文；复用既有备份、索引事务、设置保存与还原命令；严格枚举仍按现有深度上限执行 |
