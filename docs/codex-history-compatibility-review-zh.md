# Codex 历史会话连接兼容评审与验证

基线：`cb90a2440d1a771d67f46b65b2e0f2ea5106ce85`（本次获取的上游 main）。需求及设计沿用仓库 `docs/` 根目录技术文档的放置方式。

## 需求与设计评审

| 维度 | 收敛结果 |
|---|---|
| 用户价值 | 一次性处理受管旧标识，后续切换仅更新共享连接，不反复全量改历史 |
| 事实与范围 | 配置兼容属于既有缺口，不依赖多供应商计费；不更改用量或账单 |
| 可信度 | 文件可读、配置可载入与真实推理分开验收，不能互相代替 |
| 演进 | 自定义来源须有卡片连接定义，旧完成标记不屏蔽用户再次手动迁入的新历史 |
| 效能 | 修改仅在有旧标识时发生，扩展补迁须在设置中确认，启动和切换不自动扩大迁移范围 |
| 变更成本 | 复用备份、压缩和索引定位模块，不增加配置系统或外部运行时 |
| 可维护 | 迁移与恢复共用等长 JSON 补丁，避免两个不同安全实现 |
| 数据安全 | 不改正文/模型/凭据；目标增长无法保持偏移时跳过并计数，不假装全部成功 |
| 并发与恢复 | 普通文件局部比较写入、保留追加；跨文件部分成功用原件和幂等重试收口 |
| 可观测 | 致命失败不写完成标记；文件级跳过记录数量及后端日志，手动界面报告处理结果 |

评审结论：可以实现；已明确外部客户端配置缓存、跨后端加密内容和过长 provider ID 的能力边界。此评审是多维度自审，不是外部独立验收。

## 第三轮边界评审与修正

| 维度 | 决策与验证 |
|---|---|
| 认证安全 | profile 引用的受管旧连接若无自身 token/env key 而要求官方登录，补丁前拒绝并提示手动修正；合成夹具验证拒绝时输入不变，有独立凭据时仍正常投影 |
| 数据一致性与可信度 | 先完整枚举目录再改日志，读取失败及错误布局不写完成标记；索引核验暂态 IO 单独标为待重试，文件恢复后仅补迁未完成行 |
| 演进与兼容 | 完成状态及来源按目录保存，兼容读取旧单条记录；无目录标记不能证明当前目录，A→B→A 不混用、不丢失来源 |
| 效能与变更成本 | 不在供应商切换时扫描会话，不改计费或正文；复用既有备份、索引事务、设置保存与还原命令；严格枚举仍按现有深度上限执行 |
| 操作恢复 | 统一开关关闭后仍可按备份手动还原，挂载和取消不调用还原；部分成功后再次确认即可重试，无需重新开关 |
| 并发 | 排队任务取得操作锁后核验最新开关与意愿；通道同步回归确定性复现了修改前继续迁移、修改后无写入，不依赖固定睡眠 |
| 可维护与可观测 | Rust/TypeScript 设置记录同步；沿用错误、跳过计数和日志，暂态错误不冒充完成；新交互文案覆盖五种语言 |

本轮六项行为回归（profile、索引重试、扫描完整性、目录切换、还原重试入口、排队取消）均先观察到修改前失败，再验证实现后通过；另覆盖目录往返和旧无目录记录的兼容边界。

验证结果：Rust 全量 4152 项通过、0 失败、11 项按仓库配置忽略，包含全部 53 项历史迁移测试；连接投影 12 项通过。前端全量复验 247 个文件、3170 项通过。类型、格式、渲染器构建与 Clippy 均通过。

执行差异：默认并行的前端全量运行曾有 8 项失败，集中在未修改的 `IconPicker`、`PiProviderForm` 两文件，包含超时及后继 DOM 干扰；同一源码单 worker 隔离运行这两文件，58 项全部通过。随后使用 `pnpm exec vitest run --maxWorkers=2 --minWorkers=1` 复验全量，3170 项全部通过，未修改测试断言或超时时间。Rust 使用隔离的 `CC_SWITCH_TEST_HOME`、项目 `.tmp/` 与 `umask 022` 执行全量测试。

本轮在 macOS 隔离目录执行，不读取实际账号或会话。Windows/WSL/Linux 实际运行、真实供应商网络往返、跨后端加密兼容与真实桌面操作：NOT_RUN。上述多维度评审为源码与回归验证，不替代外部客户端实测。

## PR 评审后修正

| 问题 | 修正与验证 |
|---|---|
| 单个短 ID 或歧义文件中止整批 | 按文件跳过并统计，安全文件和已验证索引继续；本批跳过路径禁止推进索引；永久不支持的布局结束启动扫描，暂态错误保留重试，手动入口仍可重试 |
| Windows 创建时间不能判断替换 | 保留原文件句柄，使用卷序列号和 128 位文件 ID 比较身份；查询失败则拒绝写入；替换回归同时断言旧文件和新路径都没有被补丁修改 |
| 手动迁移错误无后端日志 | 命令层记录任务及迁移错误，跳过文件、索引行记录路径及原因 |
| Bedrock 内置连接被当作自定义来源 | 复用连接投影的 `BUILT_IN_IDS`，回归覆盖全部内置 ID |
| 案例命名不通用 | 测试夹具和文档统一使用中性的合成连接名称 |

本轮验证：`pnpm typecheck`、`pnpm format:check`、`cargo fmt --check`、`cargo clippy -- -D warnings` 均通过。前端全量 247 个文件 / 3167 项通过；Rust 全量 4139 项通过、0 失败、11 项按仓库配置忽略，包含全部 42 项历史迁移测试。新增的三项 Rust 回归及部分迁移界面回归均展示了修改前失败、修改后通过。

本轮本地执行平台为 macOS；Windows 运行结果由更新后的 PR CI 验证，不把 macOS 结果写作 Windows 实测通过。文件身份依据见 [Microsoft FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)。

## 第二轮评审修正

| 问题 | 修正与验收证据 |
|---|---|
| 保留的退役连接回落使用当前官方登录 | 仅对兼容保留的受管旧表关闭 `requires_openai_auth`；空认证、独立 token、环境变量和请求头四种夹具验证官方凭据回落被禁用、自身认证保持、当前官方共享连接仍使用官方认证 |
| 还原遇到坏元数据中止整批 | 普通/压缩兄弟文件去重、按文件跳过并计数；复用索引逐行验证与官方账本白名单。一个健康文件、两个坏文件、缺失日志、非账本会话及同文件内新会话共同验证，仅健康账本项及其索引被还原 |
| 平台无法加锁被升级为持续错误 | 文件写入前安静延后，不写完成标记；索引批处理防御性跳过。注入不可加锁判定的隔离测试验证不可用库未修改，其他可用库能继续、结果保留重试状态；设置界面显示环境处理提示，无成功或失败误报 |
| 暂态错误仍写扫描完成标记 | 永久布局拒绝与文件 IO/并发变化分开归类，暂态跳过不结束扫描。第三方旧预设、官方统一、旧官方别名三条启动路径均验证文件恢复后下次迁移成功；手动自定义来源仍须确认，启动不扩展其范围且不会丢失来源账本 |
| 部分结果仍显示完成 | 设置界面显示还原量与跳过量，暂态迁入追加重试说明，后台日志将待重试与完成区分；五种语言保持键与占位符一致 |
| 空还原也获取数据库写锁 | 无符合来源和账本条件的候选行时提前返回；持有另一个写事务的隔离测试验证空操作不等待写锁、不生成备份 |
