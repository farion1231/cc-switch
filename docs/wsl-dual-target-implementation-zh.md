# Windows / WSL 多环境配置：第一阶段实现说明

对应设计稿「Windows / WSL 多环境配置设计」（2026-11-13）。本文记录这一轮实际落到代码里的范围、和设计稿的差异，以及还没做的部分。

**2026-11-13 评审后的调整**：去掉「以哪个为准」，改为各环境独立选择直连供应商。

- 主环境不再由用户选：勾选了 Windows 就是 Windows，否则保留原来的 WSL 主环境，它也取消了就用第一个勾选的环境（`AppTargetsConfig::derived_primary`）。主环境只决定旧单目录投影（会话、用量、导入从哪读）、托管登录写到哪，以及路由 / 聚合作用于哪个环境。
- 供应商页直连视图里，每张卡用环境开关代替单个「切换」：Windows 开关沿用原有切换（含需要路由、回到直连等确认）；WSL 开关只写那个环境（`activate_app_target_provider`），写入成功后才算换过去，失败时保持原来那家。
- 主环境切换不再复制到其他环境；编辑供应商只重写正在用它的环境；其他环境还在用的供应商不能删除。
- 新环境保存时：没有配置 / 与当前供应商一致 → 默认用主环境当前那家；已有其他配置 → 保留原配置暂不选（默认）、备份后用当前供应商、或导入成卡并继续用。主环境变化时（比如取消 Windows），新主环境里的原配置也会先问（只提供「导入并使用」「备份后覆盖」）。
- 托管官方登录不能在 WSL 环境启用。

**按安装情况显示 WSL（2026-11-13 第三轮）**：

- 每个发行版里 Claude Code、Codex、Gemini CLI、OpenCode 的安装情况（`app_targets::installs`，复用应用页的 WSL 版本探测）：运行中的发行版缓存 10 分钟后重新探测，停止的只用上次结果并标「未运行 · 上次检测」，「重新检测」时才启动；探测失败记「未检测」，不当成未安装。
- 设置页只列出装了这个客户端的 WSL 发行版（已保存的目标照常显示）；一个都没有时这个应用保持单目录。多环境界面在某个 WSL 里装了支持的客户端、或已有 WSL 目标时才出现。
- 供应商页：装了客户端、还没加入写入环境的 WSL 也在卡片上给开关（虚线），点了先确认，再加入写入环境、备份它原有的配置并启用。
- 应用页：四个客户端的行下面列出每个 WSL 发行版的版本和状态，可以在那个发行版里安装 / 更新（`run_wsl_tool_lifecycle_action`）。WSL 里的卸载需要先预览卸载计划，还没做。
- 应用页分组计入 WSL：任一环境（Windows 或某个 WSL）装了就归「已安装」；所有环境都确认没装才归「未安装」；Windows 没装、某个 WSL 还没检测出来或探测失败时归「未检测」。有 WSL 条目时主行标「Windows」。
- 没绑托管账号的官方卡（比如 Codex 官方登录）可以在 WSL 启用，用那个环境自己的登录；绑了 CC Switch 托管账号的官方卡在 WSL 开关上置灰并说明原因。

**路由 / 聚合（共用一套，各环境自选接入）**：

- 路由服务、路由目标、故障转移队列、聚合名单仍按应用只有一套，跑在 Windows 上；主环境总是跟随应用的模式。
- 其他环境在供应商页「写入目标」弹层里单独开关「接入路由 / 聚合」（`set_app_target_route`，保存在目标配置的 `route` 字段）。应用在路由 / 聚合模式时，接入的环境在自己的作用域里写同一份代理契约（`controller::reconcile_follower`，复用 `write_proxy`），地址换成它自己的客户端主机；不接入的保持自己的直连供应商。
- 主环境的契约每次落定（进入、换路由、故障转移、聚合名单变化、启动接上）后，后台同步接入的环境；应用退出路由、或取消接入时，写回那个环境自己的直连供应商；退出 CC Switch 时（`detach_all`）同步把它们指回直连，下次启动再接上。同一应用的路由同步串行执行。
- 接在路由上时切换那个环境的直连供应商：只记下，退出路由时写回，不覆盖代理契约。跟随环境的模式状态在它自己的状态目录里，不改应用级的 `proxy_config.enabled`。
- 客户端主机按发行版保存（设置 → 本地路由 → WSL 客户端地址，`proxyWslClientHosts`，设备本地）；留空时自动推导：`wslinfo --networking-mode` 为 mirrored 用 127.0.0.1，否则用发行版的默认网关。「测试连接」从发行版里访问路由服务的 `/health`。监听只在回环、而 WSL 要经网关访问时给出提示，不自动改监听地址。
- 环境名称和目录在截断处加了应用统一的悬停提示；Podman 自带的 `podman-machine-*` 发行版不再列出。


## 已实现

后端（`src-tauri/src/app_targets/`）：

| 模块 | 内容 |
| --- | --- |
| `model.rs` | `appTargets` 数据结构（`primary` + `windows` + `wsl[]`，不存 mode）；旧单目录的只读幂等迁移；目录校验（Windows 行拒绝 WSL UNC、WSL 行只认本发行版、`..`、控制字符、`wsl$` / `wsl.localhost` 别名和大小写归一后的重复目的地、至少一个目标、主环境必须已启用）；旧 `*ConfigDir` 的兼容投影；各应用在 Linux 里的默认目录（Codex 认 `CODEX_HOME`，OpenCode 认 `XDG_CONFIG_HOME`，Claude 认 `CLAUDE_CONFIG_DIR`） |
| `wsl.rs` | `wsl.exe -l -q` / `--running` 枚举（不随系统语言变化、不启动发行版）；进发行版读 HOME 等变量（带 15 秒超时）；结果缓存在 `~/.cc-switch/wsl-environments.json`，停止的发行版用上次结果 |
| `scope.rs` | 线程局部的目标作用域：作用域里 `get_*_override_dir` 指向目标目录，`DeviceStore::for_device` 指向 `~/.cc-switch/targets/<app>/<目标>/`，写锁键为 `<app>@<目标>`。写前意图、首写备份、Codex 登录暂存和托管登录标记都按目标隔离 |
| `sync.rs` | 跟随写入：主环境走现有链路成功后，跟随目标各开线程在作用域里复用直连写入、MCP、提示词和 Skills 投影；WSL 10 秒 / Windows 30 秒超时；按目标的操作代次，过期结果不记；托管字段指纹与外部修改检测；冲突检查、导入成供应商卡（按关键字段去重）、写前备份 |
| `service.rs` | 设置页概览、保存前检查、按应用保存（冲突必须给出处理方式；导入和备份在保存之前，失败则什么都不保存）、立即同步 / 重试 |
| `status.rs` | 每个跟随目标的最近结果（`~/.cc-switch/app-targets-state.json`，设备本地） |

接入点：

- `ProviderService::switch`：主环境成功后写跟随环境，结果放进 `SwitchResult.targets`，有失败时加 `targets_partial_failed` 警告；主环境失败时不启动跟随写入。
- 新增 / 编辑 / 删除供应商、加入 / 移出 live（OpenCode 总是同步，切换式应用只在改的是当前那家时同步）。
- MCP、提示词、Skills 的增删改和开关：后台同步跟随环境。
- 写入 WSL 目标时跳过 Windows 专用的 stdio MCP（`.exe/.cmd/.bat/.ps1`、`cmd`/`powershell`、盘符或反斜杠路径），不删除那个环境里的同名条目，并在结果里提示。
- `save_settings` 的合并规则：`appTargets` 只经 `save_app_targets` 保存；保存过目标的应用，旧目录字段由后端拥有。

前端：

- 设置 → 应用配置：Windows 上检测到发行版（或已有 WSL 目标）时，四个应用显示多环境表单：每个环境一行（勾选、目录、自定义 / 默认 / 自动、浏览、恢复默认、运行状态、「写入时将启动」、「未获取到用户目录」、发行版不可用、最近结果），两个以上目标时出现「以哪个为准」；每个应用独立保存 / 撤销；冲突逐个弹出「暂不写入 / 备份后同步 / 先导入再同步」，取消任一步不保存。
- 供应商页头的「写入目标」入口（目标不是默认「仅 Windows」时出现）：每个环境的目录、上次写入的供应商、状态和原因，「重试未同步」只重试失败 / 待同步 / 外部已修改的目标。
- 切换后的提示：跟随环境未同步、保持原配置、跳过 MCP 时单独说明。
- 八种界面语言的文案。

## 与设计稿的差异

1. **迁移不写盘**：没有 `appTargets` 时，目标配置每次从旧单目录推导（规则 1、2、4），用户第一次在新表单里保存时才写入 `appTargets`。效果等同幂等迁移，但没有「迁移版本」标记，也没有一次性说明弹窗；旧 WSL UNC 用户在表单里会看到「已保留原来的 WSL 目录」的提示。
2. **路由模式下不写跟随环境**：代理接管 / 恢复按目标备份尚未接入，应用处于路由模式时跟随环境标「待同步 · 路由模式下暂不同步」，退出路由后切换或立即同步即可补写。
3. **托管登录**：Claude 绑号官方卡、Codex 官方卡在跟随环境标「保持原配置」，不写。设计稿要求「主环境为 WSL 时禁用托管登录切换」——为不影响已经在用 WSL UNC 单目录的老用户，后端只在通过新表单把主环境改成 WSL 时拦截（「请先启用 API Key 供应商」），没有禁用切换按钮本身。
4. **跟随环境并发**：每个跟随目标独立线程、独立写锁，和设计一致；超时只把结果标「超时，结果未知」，后台写入不会被强行中止（文件写入无法安全取消），完成后若代次仍最新会更新为实际结果。
5. **冲突判定**依据关键字段（地址、Key 摘要、模型等）是否和当前供应商一致；OpenCode 是累加式，不做冲突检查，直接合并写入。
