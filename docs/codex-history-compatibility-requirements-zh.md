# Codex 历史会话连接兼容需求

切换官方订阅与第三方 API 后，部分旧会话因仍引用已删除的 `legacy-relay`、其他自定义 provider 而无法加载；旧 `custom` 会话还可能进入已经停止的本地代理。本需求修复 CC Switch 的历史连接兼容，不依赖用量归属或计费功能。

## 目标与边界

开启“统一 Codex 会话历史”后，官方与第三方继续共用固定 `custom` 标识，切换只更新连接定义，不为每次切换重写全部会话。用户在设置中明确确认后，允许补迁能由 CC Switch 卡片配置证明的旧 ID；未受管理的 provider、历史消息、工具内容、加密推理内容、模型记录与登录凭据不改写。

补迁应兼容以后导入的历史、fork 副本和同一文件内后续的元数据记录。配置已保存不表示已经打开的 Codex 进程已采用配置，使用者可能需要重新打开聊天或重启客户端。

## 功能要求

1. 共享连接投影保持官方订阅/API 双向一致，直连仍然直连；不把所有旧 provider 静默指向另一家供应商。
2. 旧连接清理不能删除仍可能被历史会话引用的非保留自定义定义，避免制造新的 `provider not found`。兼容保留的旧连接必须关闭官方登录凭据回落；保留自身密钥、环境变量和请求头，缺少自身凭据时由用户配置或明确迁入共享连接。
3. 统一历史开关开启且用户点击迁入并确认时，从本机第三方卡片中有定义的路由发现自定义旧 ID，不只识别内置旧预设名单。内建 provider 及非受管配置保留专属边界；启动时维持既有保守来源规则，不自动扩大到用户自定义 ID。
4. 旧完成标记不永久屏蔽用户再次手动迁入的新历史。补迁幂等，无需修改的文件不写入、不生成重复备份；原件继续使用既有迁移备份机制保存。
5. 每条元数据补丁必须保持解压后行字节数，分页偏移不变；只改 `session_meta.model_provider`，包括同一文件中的多条记录。无法等长替换或布局有歧义时跳过该文件并计数，其余文件继续；跳过的文件不推进对应 state DB。
6. 普通日志原位局部改写，保持 inode，保留原尾部和并发追加；检测到替换或截断时跳过该文件；迁移前提示退出 Codex，不能把局部校验宣称为跨进程原子事务。压缩日志保持 zstd 形态和原 mtime，并防止与正在解压产生的普通日志竞争。
7. 迁移期间的外部变化不得被整份覆盖。永久无法等长修改或布局有歧义的文件可记录跳过并结束启动扫描；正在写入、解压、替换或暂时不可读的文件不得触发完成标记，既有启动迁移保留重试机会，用户自定义来源仍通过手动入口重试。平台不能安全加锁的状态库须安静延后，不发出持续失败提示；手动操作须说明本次未修改历史及可操作的环境。目录或数据库级致命错误不写完成标记。
8. 本次不重建用量、不更改计费证据、不增删原始会话正文，也不承诺任意供应商都能解释另一后端的加密状态或工具协议。
9. 按备份账本还原时，坏文件不能中止其他会话的还原；带路径的索引须核对对应会话已还原且本批未跳过，无路径的旧索引在存在文件级跳过时保守跳过。界面分别报告还原与跳过的文件、索引数量。

## 功能要求补充

10. profile 引用的受管旧连接若缺少独立 token 或环境密钥，却要求使用官方登录，应在配置写入前拒绝并指出 profile 与连接，提示用户补密钥或移除回落指令；不静默改写用户的 profile。
11. 会话目录或目录项无法完整枚举时，本批不得写入历史或标记扫描完成。日志核验中的暂态 IO 错误须保留索引重试机会，永久不支持的布局仍按已有跳过规则处理。
12. 第三方迁移完成状态与来源账本须绑定规范化 Codex 目录。切换目录后重新进行保守扫描，不能借另一目录的来源记录扩大当前手动迁移范围；旧无目录标记不能证明当前目录已完成。
13. 关闭统一开关后，存在备份时仍提供显式还原入口。部分还原或失败后可以再次确认重试，不必重新开关统一历史；界面挂载、目录变化和错误提示均不自动还原。
14. 官方迁移取得操作锁后重新核验统一开关和迁移意愿；等待期间已取消的任务不得改写历史。单批操作固定目录与配置快照，防止预检和索引处理使用不同目录。
15. 手动迁入须在文件写入前确认索引具有 `threads.id`、`threads.model_provider` 与 `threads.rollout_path`；任一缺失都应拒绝本次迁入，日志保持原值，不能先改日志再发现索引无法更新。
16. 原件备份首次写入前须持久化来源目录信息；后续索引处理失败时，已保存的备份仍只能用于原目录。已存在但损坏、不可读或缺少有效目录字段的归属信息不构成还原依据，不能退化为无目录的旧格式；完全没有该文件的早期备份保留既有兼容方式。无法验证备份归属时，原日志不得先被改写。

## 验收

新增验收覆盖：危险 profile 拒绝且输入原样保留、自带密钥 profile 正常；扫描错误无完成标记；索引短暂不可读后能够补迁；目录 A/B 的完成状态与来源隔离及往返切换；还原入口的挂载、取消、确认及重试；排队期间关闭开关后无历史写入。

| 场景 | 结果 |
|---|---|
| 官方与第三方配置投影 | 共享标识一致，认证仍匹配，第三方不取得官方凭据 |
| 旧自定义 ID、旧完成标记及新导入副本 | 开启统一并明确确认后可补迁；启动和切换时不自动扩大受管范围 |
| 普通、压缩、归档、重复元数据 | 只修改目标字段，解压后长度与消息位置不变 |
| 普通文件尾部追加 | inode 与追加字节保留 |
| 目标 ID 无法容纳、并发替换/截断 | 单项跳过并计数，原件与该行索引保留，其余继续 |
| 未迁移完的旧连接定义 | 配置仍可解析，不能因清理变成缺失 provider |
| 旧连接依赖过期的全局认证 | 禁止读取当前官方登录凭据，保留旧连接自身认证配置 |
| 暂态文件错误后恢复可读 | 既有启动迁移下次重试，手动来源不会被启动逻辑自动扩展 |
| 还原遇到坏文件或缺失日志 | 其他会话继续，坏文件及未验证索引保持原值并计数 |
| 重复执行 | 无新增迁移变化和重复副作用 |

手动迁移须显示成功量及跳过量；致命失败须显示处理提示，错误详情与跳过文件路径必须落后端日志；无法安全完成的操作、聊天重开和客户端退出均交由用户处理。
