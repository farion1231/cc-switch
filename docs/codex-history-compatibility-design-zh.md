# Codex 历史会话连接兼容设计

本设计落实[需求](codex-history-compatibility-requirements-zh.md)。保持现有共享连接投影，修正旧定义清理、来源发现和历史补丁；当前连接的网络路径和认证投影保持不变，已退役的兼容定义隔离官方登录凭据回落。

## 来源和重试

用户确认手动迁入时，迁移候选来自已有第三方卡片配置中确实有定义的自定义路由，以及此前已成功迁移记录保留的来源 ID；复用连接投影的 `BUILT_IN_IDS` 排除内建连接（包括 Bedrock 两种 ID），另排除共享 ID 和 CC Switch 官方保留路由。启动迁移沿用既有旧预设名单。卡片 ID 本身不等于客户端路由 ID，不凭任意卡片 ID 收编会话。来源发现不扫描未知历史后把所有 provider 自动收编。

设置 → 应用配置 → Codex 中，统一开关开启后显示“迁入第三方旧会话”。确认框说明退出 Codex、备份以及迁入后使用当前连接。只有确认操作调用扩展迁移；取消、启动和供应商切换均不调用。手动操作不以旧完成标记短路，可以重试和补迁后来导入的历史。普通和压缩的同名副本先去重；原始日志已是目标值时不改写、不备份。

## 等长补丁

先解析元数据确认语义，再定位唯一的 provider JSON 字符串值。替换后使用 JSON 空白补齐字节数，并再次核对只改变目标字段。目标值过长、重复字段或未知布局不能安全修改时，保留该文件并计入跳过数，不重新序列化整行；继续处理其他文件。

普通日志保存变更区间，备份后用同一个文件句柄逐段比较旧字节再原位写入。保持 inode，不截断文件；目标元数据范围内变化、路径替换或截断时跳过该文件。Unix 比较句柄的设备号和 inode，Windows 使用 `GetFileInformationByHandleEx(FileIdInfo)` 比较卷序列号和 128 位文件 ID；无法查询身份时不放行，不能用创建时间代替文件身份。校验和写入之间仍不能锁住不协作的外部写入者，因此要求用户先退出 Codex，不承诺跨进程原子性。文件尾部追加可以保留。压缩日志在校验文件未变且没有普通兄弟文件后，按既有压缩写回路径保存，保留 mtime。

扩展迁移先检查索引布局是否支持日志路径验证，未知布局提示人工处理。平台不能安全加锁时，在文件写入前返回 `state_db_unlockable`，不报致命错误、不写完成标记；手动界面提示在客户端所在环境处理。索引批处理也防御性跳过不可加锁库，保留待重试状态。

文件处理后再迁移索引；本次跳过文件的路径作为排除集传入索引阶段。带日志路径的索引行须验证目标元数据、对应会话 ID 和目录边界，再在事务内按原 ID/旧 provider 更新；缺失或未验证的行计入跳过，其他行继续。无路径的旧索引在本批存在文件跳过时保守跳过相关行。

永久不支持的元数据布局使用 `InvalidInput` 分类，扫描完成后可记录完成标记，避免启动反复处理；文件 IO、未写完的元数据及并发变化均保留 `retryPending`，不标记扫描完成。既有启动迁移下次重试；扩展自定义来源仍须用户再次确认，不扩大启动操作范围。已证明的来源 ID 与扫描完成状态分开保留，启动扫描不覆盖丢失手动来源账本。致命错误不写完成标记。跨文件与索引不存在单一事务，故保留原件、明确错误并允许幂等重试；不得把整库备份覆盖活跃数据库。

## 旧定义

存在历史目录或 Codex 索引库时，非保留的旧自定义表不因“曾由 CC Switch 写入”而被删除。该检查只查存储位置是否存在，不在每次切换时扫描聊天内容。保留原有地址及连接自身的密钥、环境变量或请求头，但将兼容保留表的 `requires_openai_auth` 置为 `false`，防止旧全局 API Key 已被清除后回落到当前官方登录。缺少自身凭据时需要用户配置或手动迁入，不能把旧 ID 自动指向另一供应商。仅处理能证明已退役且不受 profile 引用的自定义表，当前共享连接、内建连接和用户自有表不受此兼容处理影响。确实没有历史存储时仍清理已证明属于旧投影的表及其旧 Key。官方旧代理保留 ID、无真实认证的代理占位表仍按既有专属规则清理。

## 按账本还原

还原复用文件的等长补丁和索引逐行验证。单个坏文件记录日志、路径与跳过数，其他文件继续；普通与压缩兄弟副本先去重。索引更新增加官方备份账本 ID 白名单，且只核对该索引对应的会话 ID，文件中的其他会话记录不构成归属证据。坏文件、缺失日志、非账本会话均不推进索引；无路径的旧索引在发生文件级跳过时保守保留。没有任何变化也没有跳过才返回 `nothing_to_restore`，全部跳过时仍显示部分处理提示。

## 失败提示

手动操作分别返回迁移成功与跳过的文件、索引数量；有跳过时显示人工处理提示，不宣称全部成功。致命失败显示失败提示，详情在命令层写入后端日志，指导退出客户端、查看日志、恢复原连接定义及手动重试。后台既有迁移失败通过事件与进程内状态快照通知界面，先订阅再读取，避免启动竞态吞掉提示。配置缓存所需的聊天重开或客户端重启均由用户执行。

## 验证

### 边界处理决策

认证检查在配置补丁前执行：仅针对能证明受管理、被 profile 引用、指向旧连接且缺少自身 token/env key 的官方登录回落；拒绝本次写入并给出手动修正提示，保留用户配置。内建连接和当前官方连接继续遵循现有投影。

历史目录先完整枚举再改写，目录不存在视为无存量，读取失败、目录项错误和超出扫描深度均明确报错；不得把不完整清单当作完成。索引核验区分已验证、永久不支持及暂态读取失败；只有暂态失败设置待重试，不能因一条未完成索引而永久结束启动迁移。

第三方完成状态与来源记录按规范化 Codex 目录存入同一映射，往返切换目录也不丢失各自账本。旧单条记录仅作兼容读取，首次写入新映射时转换可证明归属的记录并清理旧入口；无目录的旧标记按未完成处理，仅重跑既有保守启动来源。手动来源必须由当前目录账本或当前卡片证明。每次操作固定 Codex 目录与配置文本，索引定位不再重新读取另一份全局配置。

关闭统一开关后的还原入口复用原还原命令、备份检测与确认框，不引入自动还原。执行期间禁止重复发起，关闭或重新开启设置不视为还原授权。

官方迁移把开关与意愿检查移到操作锁内；等待中的旧任务在获得锁后按最新状态取消。现有互斥与幂等机制继续承担跨文件部分完成后的恢复，不承诺锁住外部 Codex 进程。

隔离目录下构造普通与压缩、归档和多条元数据日志，验证正文、字节位置、inode、mtime、并发追加及失败行为。用合成卡片验证受管来源和统一开关边界。复用现有官方/API 投影回归，最后运行格式、静态检查和相关 Rust 测试，不使用真实业务会话做请求测试。
