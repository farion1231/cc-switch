# CC Switch v4.0.27

This release lets session management search message text, adds Density and Zoom settings, makes the model pricing table searchable, and lets the Grok Build provider in use open a terminal too. The Installed page of Skills has a new layout, and provider icons follow the light or dark theme. Fixes cover config files that are symlinks being replaced by regular files or failing to be written, providers getting stuck recovering from the circuit breaker after a request was cancelled until a restart, Codex plan mode failing after custom permissions were set, Skills that had been run being reported as having updates, Skills repositories showing 0 Skills, Python's `pi.exe` being taken for Pi on Windows, model price sync timing out, the window not being draggable while a dialog was open, right-click opening a browser menu, and display problems with the Linux tray panel. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### Searching session message text

Search on the session management page used to cover only titles, folders and session IDs, so when you remembered what was discussed but not which session it was in, you could not find it ([#7896](https://github.com/farion1231/cc-switch/pull/7896), [#7420](https://github.com/farion1231/cc-switch/issues/7420)).

Now you can turn on "Search message text": turn it on in the "⋯" menu at the top right of the page, or, when a search finds nothing, click the button in the message shown. Once it is on, search results list the matching text excerpts and how many messages matched.

- It is off by default. When it is on, CC Switch builds a local index of message text and shows progress while doing so; during that time text matches may be incomplete.
- The index is a separate local file, `session-index.db`, which is not cloud-synced and not included in backups; turning the option off deletes it.

### Density and Zoom

"Settings → General → Appearance" has two new settings ([#9209](https://github.com/farion1231/cc-switch/pull/9209)):

- **Density**: "Compact" is the original size and the default; "Comfortable" uses text one step larger and slightly taller buttons and input boxes.
- **Zoom**: four levels, 90%, 100%, 110% and 125%. You can also press Ctrl (⌘ on macOS) with `+` or `-` to adjust it, and Ctrl/⌘ with `0` to reset.

Both settings are saved only on this computer, like the theme. The tray panel always keeps the compact size.

### Searching the model pricing table

The model pricing table has a search box above it that filters by model ID or name ([#9205](https://github.com/farion1231/cc-switch/pull/9205)). Pressing Enter edits the first result; when no model matches, Enter adds pricing for the model you typed.

### Open Terminal for Grok Build

Grok Build provider cards now have the "Open Terminal" button too ([#9234](https://github.com/farion1231/cc-switch/pull/9234)). Grok CLI cannot switch providers for just one terminal, so the button appears only on the provider in use, and the terminal it opens uses the Grok config managed by CC Switch directly; when "Skip permission prompts" is selected, `--always-approve` is added.

## Changes

- **New layout for the Installed page of Skills** ([#9210](https://github.com/farion1231/cc-switch/pull/9210)):
  - The name column stays fixed on the left, and when the window is narrow, the app columns scroll horizontally under it.
  - The status and source filters move into a toolbar like the one on the "Discover" page, and are no longer covered once Skills are selected; batch actions keep update, uninstall, and "Enable in" / "Turn off in" per app.
  - The "N updates" link in the page header is gone, since the toolbar's "Update all" already shows the count; click the "Update" badge on a row to update that Skill.
  - The "…" menu on each row keeps Open docs, Open folder and Uninstall; when a write fails, the error is shown where the description was.
- **Provider icons follow the theme** ([#8438](https://github.com/farion1231/cc-switch/pull/8438)): the fixed white backing behind card icons is gone. Single-color dark icons follow the text color, so they stay visible in dark mode; multi-color icons with dark strokes, image icons and icons you uploaded still have a light backing in dark mode.
- **Right-click no longer opens a browser menu** ([#8919](https://github.com/farion1231/cc-switch/pull/8919), [#8921](https://github.com/farion1231/cc-switch/issues/8921)): right-clicking in the main window or the tray panel used to show the browser's own menu (on Windows: "Back", "Reload", "Save as", "Print" and so on). This no longer happens; input boxes, code editors and selected text can still be right-clicked to copy and paste.
- **Circuit breaker logs name the provider** ([#9292](https://github.com/farion1231/cc-switch/issues/9292)): the circuit breaker's log lines (`CB-001` to `CB-006`) now all include "app:provider id"; when the circuit breaker refuses a provider, a `FWD-004` line is also logged with the provider's name, instead of the provider being skipped silently. Only the logs changed; routing and circuit breaker behavior are unchanged.
- **Presets:** the default model of the Mistral AI presets changes to `mistral-large-4` (Mistral has announced that Mistral Medium 3.5 is deprecated), and the Mistral AI presets for Claude Code, Codex and Claude Desktop are no longer hidden. Mistral Vibe plans share their quota with the API, so "Get API Key" now opens the Vibe CLI key page, which works for free, subscription and pay-as-you-go use; searching "Vibe" when adding a provider also finds it. Genesis ([#9269](https://github.com/farion1231/cc-switch/pull/9269)) and TokenPlus ([#9296](https://github.com/farion1231/cc-switch/pull/9296)) were added. Providers you have already added are not affected.

## Fixes

- **When a config file was a symlink, switching providers replaced it with a regular file, and on Windows the switch failed with an error** ([#6764](https://github.com/farion1231/cc-switch/issues/6764), [#9283](https://github.com/farion1231/cc-switch/issues/9283)). Files such as `~/.claude/settings.json`, `~/.codex/config.toml` and `opencode.json` are usually symlinks when managed with a dotfiles tool or a synced folder. Writes used to replace the link itself: on macOS and Linux the link became a regular file cut off from the original, and on Windows an "atomic replace failed" error was reported (os error 1464). Now the real file the link points to is written, and the link stays as it is.
- **After a request was cancelled midway, a provider could stay in circuit breaker recovery until a restart** ([#7206](https://github.com/farion1231/cc-switch/issues/7206), [#9292](https://github.com/farion1231/cc-switch/issues/9292)). During recovery, the circuit breaker lets only one probe request through; if the client disconnected before that request finished, the slot was never returned, and every later request to that provider was refused. Now the slot is returned however the request ends.
- **After custom permissions were set in Codex, plan mode failed with an error** ([#7349](https://github.com/farion1231/cc-switch/pull/7349), [#7294](https://github.com/farion1231/cc-switch/issues/7294)). Newer Codex versions require `model_catalog_json` to be an absolute path when reading custom permissions, but CC Switch used to write a file name, so Codex reported `AbsolutePathBuf deserialized without a base path`. Now an absolute path is written; when the config directory is in WSL, the file name is still written.
- **A Skill that had been run once was shown as "Update", and updating it overwrote the whole folder** ([#7780](https://github.com/farion1231/cc-switch/pull/7780), [#7772](https://github.com/farion1231/cc-switch/issues/7772)). The `__pycache__` and `.pyc` files that Python generates at runtime were counted as part of the Skill's content. Now these files are ignored when checking for updates; old records saved by earlier versions are converted automatically, so they do not cause false reports either.
- **Skills repositories showed "0 skills detected"** ([#9273](https://github.com/farion1231/cc-switch/issues/9273)). When a repository added during import had its branch recorded as `HEAD`, or a repository whose default branch is master was configured as main, the count was always 0. Now the count follows the branch that was actually read; repositories that could not be read show "Read failed" with the reason, and after importing Skills adds new repositories, they are read again the next time you open the page.
- **On Windows, `pi.exe` from a Python package was taken for Pi** ([#9267](https://github.com/farion1231/cc-switch/issues/9267)). An unrelated `pi` package on PyPI installs `Scripts\pi.exe`, and the Apps page showed it as "Can't run". Pi is published only through npm, so in a Python `Scripts` folder, `pi.exe` is no longer recognized as Pi.
- **Model price sync failed with only `error decoding response body`** ([#9262](https://github.com/farion1231/cc-switch/issues/9262)). On slow networks or through a proxy, downloading the price table from models.dev timed out halfway through reading it. Now the timeout is raised from 15 seconds to 60 seconds, and when it fails, the sync status shows the real cause.
- **Adding a DeepSeek Harness provider only reported `Invalid DeepSeek Harness profile YAML`, without saying which file** ([#9297](https://github.com/farion1231/cc-switch/issues/9297)). Now the error shows the path of the config file with the problem and the specific YAML error, so the file is easy to find and fix.
- **Connectivity checks judged relays that redirect as unreachable** ([#9253](https://github.com/farion1231/cc-switch/pull/9253), [#5747](https://github.com/farion1231/cc-switch/issues/5747)). Some gateways redirect back and forth between `/v1` and `/v1/`; now a check that receives a redirect counts as reachable.
- **The window could not be dragged while a dialog was open** ([#9140](https://github.com/farion1231/cc-switch/pull/9140)). Now the window can still be dragged while a dialog is open; on Windows and Linux, when the in-app window buttons are used, the minimize, maximize and close buttons also keep working.
- **Display problems with the Linux tray panel**: the panel and windows reopened in Lightweight mode rendered incorrectly ([#9233](https://github.com/farion1231/cc-switch/pull/9233), [#9216](https://github.com/farion1231/cc-switch/issues/9216)), and part of the panel was cut off when display scaling was set ([#9287](https://github.com/farion1231/cc-switch/pull/9287), [#8556](https://github.com/farion1231/cc-switch/issues/8556)). The panel on Linux now has an opaque background.
- **When a provider name started with an emoji or similar character, or with spaces, the first character shown on cards without an icon was garbled or blank** ([#8139](https://github.com/farion1231/cc-switch/pull/8139)).
- **The risk warning for one-click import links missed IPv6 addresses that embed an IPv4 address** ([#8127](https://github.com/farion1231/cc-switch/pull/8127)). Such addresses are now judged as local or internal by the IPv4 address they actually point to.
