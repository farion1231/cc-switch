# CC Switch v4.0.5

### 4.0 正式版の最初の修正リリース

Codex で GitHub Copilot アカウントを使えるようになりました。使用量の「すべて」のヒートマップは直近 1 年だけでなく、記録のある最初の日までさかのぼって見られるようになりました。このバージョンでは、Claude Code を Responses プロトコル経由で GPT にマッピングしたときにサブエージェントが常に worktree に送られる問題と、Codex の集約モードで GLM などのモデルが `/model` から消える問題も修正しました。Linux の deb、rpm パッケージもアプリ内で更新できるようになりました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

> **Linux の deb、rpm をお使いの方は、このバージョンを手動でインストールしてください。** インストール済みの deb、rpm 版には古いインストール種別の目印が残っているため、アプリ内でこのバージョンに更新しても権限不足と表示されます。4.0.5 を一度手動でダウンロードしてインストールすれば、それ以降は通常どおり自動更新されます。

---

## 新機能

**Codex で GitHub Copilot アカウントを使えるように。** Codex でプロバイダーを追加するときに「GitHub Copilot」プリセットを選び、「アカウント」で GitHub アカウントにログインするだけです。Claude Code ですでにログインした Copilot アカウントはそのまま使えます。Codex のルーティングをオンにする必要があります。Copilot ではモデルによって対応するプロトコルが異なるため、ローカルルーティングがモデルに応じて Responses か Chat Completions を自動で選びます。エディターの「上流フォーマット」で手動で指定することもできます。アカウントのプランによってコンテキストウィンドウが異なるため、プリセットはデフォルトで控えめな値を使います。「モデル一覧を取得」を押すと、お使いのアカウントの実際のウィンドウと推論レベルでモデルカタログを埋めます。

**「すべて」のヒートマップで全履歴を見られるように。** これまでは期間で「すべて」を選んでも、ヒートマップには直近 53 週しか表示されませんでした。現在もデフォルトは直近 53 週ですが、「もっと見る」を押すと 53 週ごとに 1 段ずつさかのぼって並び、記録のある最初の日まで表示します。各段には期間、Token 数、リクエスト数、コストを表示し、段どうしで色の濃さをそのまま比較できます。

## 修正

- **Claude Code を Responses プロトコル経由で GPT にマッピングすると、サブエージェントが常に worktree に送られていた問題。** Claude Code がサブエージェントを呼び出すとき、「分離方式」と「モデル」は省略可能なパラメータですが、Responses プロトコルは明示されていないと省略可能なパラメータを必須として扱うため、モデルが毎回値を入れていました。その結果、サブエージェントが worktree で実行され、git リポジトリの外ではそのまま失敗したり、サブエージェント自身に設定したモデルが上書きされたりしていました。現在は変換時にこれらのパラメータが省略可能であることを明示します。Responses プロトコルを使うプロバイダーと ChatGPT アカウントの両方が影響を受けていましたが、どちらも修正しました。
- **Codex の集約モードで、GLM などのモデルが `/model` に表示されなかった問題。** CC Switch はモデルカタログを生成するときに公式の gpt-5.5 エントリをテンプレートにしています。公式がこのエントリを非表示に設定したため、集約内のサードパーティのモデルもすべて一緒に非表示になっていましたが、集約の件数にはそれらが数えられたままでした。
- **Codex の MoArk プリセットで、`/model` にモデルが 1 つしか表示されなかった問題。** プリセットにモデルカタログが含まれていなかったため、Codex はデフォルトのモデルしか表示していませんでした。現在は 5 つのモデルがすべて表示され、コンテキストウィンドウ、画像入力、推論レベルも付きます。すでに追加済みの MoArk プロバイダーは自動では更新されないため、プリセットからもう一度追加してください。
- **Linux で deb、rpm からインストールした版で、アプリ内更新が権限不足と表示されていた問題。** これまで更新プログラムは deb、rpm のインストールを認識できず、AppImage と同じ方法で `/usr/bin` にファイルを書き込もうとしていました。現在は deb、rpm それぞれに専用の更新パッケージがあります。インストール済みの版では、先にこのバージョンを一度手動でインストールする必要があります。上の案内をご覧ください。
- **Linux の Wayland で、タイトルバーの最小化、最大化、閉じるボタンを押しても反応しなかった問題。** 初めてウィンドウを開いたときや、トレイからウィンドウを開き直した後に、ボタンの上に見えない領域が重なっていました。
- **Windows で MSI からアップグレードした後、タスクバーにピン留めしたアイコンが PC の再起動後に空白になっていた問題。** これまでショートカットはアップグレードのたびに削除されるアイコンキャッシュを指していましたが、現在はプログラム自体のアイコンを直接使います。以前ピン留めしたアイコンは、今回のアップグレード後にもう一度空白になることがあります。その場合はピン留めを外して、もう一度ピン留めしてください。今後のアップグレードでは起きなくなります。
- **npm 12 で Claude Code をインストールすると実行できず、Windows では互換性のないプログラムと表示されていた問題。** npm 12 はデフォルトで Claude Code のインストールスクリプトを実行しないのに、インストール成功と表示し、残るのはプレースホルダーのファイルだけでした。現在は「アプリ」ページのインストールとアップグレード、そしてコピーできるインストールコマンドのすべてで、このインストールスクリプトの実行を許可します。
- **ルーティングをオンにしていないとき、Grok Build の使用量が使用量統計に表示されるまで 10 分かかっていた問題**。現在は 1 分ほどで表示されます。

**その他：**
- ユーザーマニュアルと README を 4.0 の画面に合わせて更新しました。

## アップグレードに関する注意

**データベースの構造は変わっていません。** バージョンは 20 のままです。

**Linux の deb、rpm をお使いの方は、このバージョンを手動でインストールしてください。** その後は通常どおり自動更新されます。

**Windows をお使いの方**：アップグレード後にタスクバーにピン留めしたアイコンが空白になった場合は、ピン留めを外してもう一度ピン留めしてください。
