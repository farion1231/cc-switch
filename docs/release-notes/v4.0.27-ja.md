# CC Switch v4.0.27

今回のリリースでは、セッション管理でメッセージ本文を検索できるようになり、表示密度と表示倍率の設定が加わりました。モデル料金の表を検索できるようになり、Grok Build で使用中のプロバイダーからもターミナルを開けるようになりました。Skills の「インストール済み」ページのレイアウトを見直し、プロバイダーのアイコンはライト / ダークのテーマに合わせて変わるようになりました。また、設定ファイルがシンボリックリンクのときに通常のファイルに置き換えられたり書き込みに失敗したりする、リクエストを取り消した後にプロバイダーが再起動までサーキットブレーカーの回復中のままになる、Codex でカスタム権限を設定すると plan モードでエラーになる、一度実行した Skill に更新があると誤って表示される、Skills のリポジトリで Skill が 0 件と表示される、Windows で Python の `pi.exe` を Pi と認識する、モデル価格の同期がタイムアウトする、ダイアログを開いているとウィンドウをドラッグできない、右クリックでブラウザーのメニューが出る、Linux のクイックパネルの表示がおかしい、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### セッションのメッセージ本文を検索

これまでセッション管理ページの検索ではタイトル、ディレクトリ、セッション ID しか探せず、話した内容は覚えていても、どのセッションだったか思い出せないときには見つけられませんでした（[#7896](https://github.com/farion1231/cc-switch/pull/7896)、[#7420](https://github.com/farion1231/cc-switch/issues/7420)）。

現在は「メッセージ本文を検索」をオンにできます。ページ右上の「⋯」メニューからオンにするか、検索結果がないときに案内に表示されるボタンを押してください。オンにすると、検索結果に一致した本文の抜粋と、一致したメッセージの件数が表示されます。

- 既定ではオフです。オンにすると CC Switch がローカルでメッセージ本文のインデックスを作成し、作成中は進捗が表示されます。その間は本文の検索結果がまだ揃っていないことがあります。
- インデックスは独立したローカルファイル `session-index.db` で、クラウド同期の対象にもバックアップの対象にもなりません。このスイッチをオフにすると削除されます。

### 表示密度と表示倍率

「設定 → 一般 → 外観」に 2 つの項目が加わりました（[#9209](https://github.com/farion1231/cc-switch/pull/9209)）：

- **表示密度**：「コンパクト」は従来のサイズで、既定値です。「標準」は文字が 1 段階大きく、ボタンや入力欄が少し高くなります。
- **表示倍率**：90%、100%、110%、125% の 4 段階で、Ctrl（macOS では ⌘）と `+`、`-` でも調整でき、Ctrl/⌘ と `0` で元に戻ります。

どちらの設定もテーマと同じく、このパソコンにだけ保存されます。トレイのクイックパネルは常にコンパクトのサイズのままです。

### モデル料金の表を検索

モデル料金の表の上に検索ボックスを追加し、モデル ID または名前で絞り込めるようにしました（[#9205](https://github.com/farion1231/cc-switch/pull/9205)）。Enter を押すと最初の結果を編集します。一致するモデルがない場合は、Enter で入力したモデルの料金を追加します。

### Grok Build でターミナルを開く

Grok Build のプロバイダーカードにも「ターミナルを開く」ボタンが付きました（[#9234](https://github.com/farion1231/cc-switch/pull/9234)）。Grok CLI は特定のターミナルだけプロバイダーを切り替えることができないため、このボタンは使用中のプロバイダーにだけ表示され、開いたターミナルは CC Switch が管理している Grok の設定をそのまま使います。「権限の確認をスキップ」を選ぶと `--always-approve` が付きます。

## 変更

- **Skills の「インストール済み」ページのレイアウトを見直しました**（[#9210](https://github.com/farion1231/cc-switch/pull/9210)）：
  - 名前の列を左側に固定し、ウィンドウが狭いときは各アプリの列がその下で横にスクロールします。
  - 状態とソースの絞り込みを「見つける」ページと同じツールバーに移し、Skill を選択しても隠れなくなりました。一括操作には更新、アンインストール、アプリごとの「有効にする先」/「オフにする」を残しました。
  - ページ上部の「N 件の更新」リンクを削除しました。ツールバーの「すべて更新」に件数が表示されています。各行の「更新あり」の印を押すと、その Skill を更新できます。
  - 各行の「…」メニューには「ドキュメントを開く」「フォルダーを開く」「アンインストール」を残しました。書き込みに失敗したときは、説明の位置にエラーメッセージを表示します。
- **プロバイダーのアイコンがテーマに合わせて変わるようになりました**（[#8438](https://github.com/farion1231/cc-switch/pull/8438)）：カードのアイコンの後ろにあった固定の白い背景を取り除きました。単色の暗いアイコンは文字色に合わせて色が変わり、ダークモードでも見やすくなります。暗い線を含む多色のアイコン、画像のアイコン、自分でアップロードしたアイコンは、ダークモードでは引き続き明るい背景が付きます。
- **右クリックでブラウザーのメニューが出なくなりました**（[#8919](https://github.com/farion1231/cc-switch/pull/8919)、[#8921](https://github.com/farion1231/cc-switch/issues/8921)）：これまではメインウィンドウやトレイパネルで右クリックすると、ブラウザー標準のメニュー（Windows では「戻る」「再読み込み」「名前を付けて保存」「印刷」など）が表示されていました。現在は表示されません。入力欄、コードエディター、選択した文字では引き続き右クリックでコピーや貼り付けができます。
- **サーキットブレーカーのログにどのプロバイダーかを記録するようにしました**（[#9292](https://github.com/farion1231/cc-switch/issues/9292)）：サーキットブレーカーのログ（`CB-001` から `CB-006`）にはすべて「アプリ:プロバイダー id」を付けました。サーキットブレーカーがプロバイダーを拒否したときも `FWD-004` のログを 1 行記録してプロバイダー名を書き、黙ってスキップしなくなりました。変更したのはログだけで、ルーティングとサーキットブレーカーの動作は変わりません。
- **プリセット：** Mistral AI プリセットの既定のモデルを `mistral-large-4` に変更し（Mistral Medium 3.5 は Mistral が非推奨を発表済み）、Claude Code、Codex、Claude Desktop の Mistral AI プリセットを非表示にしないようにしました。Mistral Vibe のプランと API はクォータを共有するため、「API Key を取得」は Vibe CLI のキーのページを開くように変更し、無料、サブスクリプション、従量課金のいずれでも使えます。プロバイダーを追加するときに「Vibe」で検索しても見つかります。Genesis（[#9269](https://github.com/farion1231/cc-switch/pull/9269)）、TokenPlus（[#9296](https://github.com/farion1231/cc-switch/pull/9296)）を追加しました。追加済みのプロバイダーには影響しません。

## 修正

- **設定ファイルがシンボリックリンクのとき、プロバイダーを切り替えると通常のファイルに置き換えられ、Windows ではそのままエラーになる問題**（[#6764](https://github.com/farion1231/cc-switch/issues/6764)、[#9283](https://github.com/farion1231/cc-switch/issues/9283)）。dotfiles 管理ツールや同期フォルダーで `~/.claude/settings.json`、`~/.codex/config.toml`、`opencode.json` などのファイルを管理していると、これらは通常シンボリックリンクになっています。これまでは書き込み時にリンク自体を置き換えていたため、macOS と Linux ではリンクが通常のファイルになって元のファイルとのつながりが切れ、Windows では「原子替换失败」（os error 1464）というエラーになっていました。現在はリンク先の実際のファイルに書き込み、リンクはそのまま残ります。
- **リクエストが途中で取り消されると、CC Switch を再起動するまでプロバイダーがサーキットブレーカーの回復中のままになることがある問題**（[#7206](https://github.com/farion1231/cc-switch/issues/7206)、[#9292](https://github.com/farion1231/cc-switch/issues/9292)）。回復中、サーキットブレーカーはプローブのリクエストを 1 つだけ通します。このリクエストが終わる前にクライアントが切断すると枠が返されず、その後このプロバイダーへのリクエストはすべて拒否されていました。現在はリクエストがどのように終わっても枠を返します。
- **Codex でカスタム権限を設定していると、plan モードでエラーになる問題**（[#7349](https://github.com/farion1231/cc-switch/pull/7349)、[#7294](https://github.com/farion1231/cc-switch/issues/7294)）。新しい Codex はカスタム権限を読み込むときに `model_catalog_json` が絶対パスであることを求めますが、これまで CC Switch はファイル名だけを書いていたため、Codex が `AbsolutePathBuf deserialized without a base path` を報告していました。現在は絶対パスで書き込みます。設定ディレクトリが WSL 内にある場合は引き続きファイル名を書きます。
- **一度実行した Skill が「更新あり」と表示され、更新するとディレクトリ全体が上書きされる問題**（[#7780](https://github.com/farion1231/cc-switch/pull/7780)、[#7772](https://github.com/farion1231/cc-switch/issues/7772)）。Python の実行時に生成される `__pycache__` と `.pyc` ファイルが Skill の内容に含まれていました。現在は更新の確認でこれらのファイルを無視します。以前のバージョンで保存した古い記録は自動で換算するため、これによる誤検知はありません。
- **Skills のリポジトリに「0 件のスキルを検出」と表示される問題**（[#9273](https://github.com/farion1231/cc-switch/issues/9273)）。インポート時に追加されたリポジトリのブランチが `HEAD` として記録されている場合や、既定のブランチが master のリポジトリを main で設定している場合に、件数が常に 0 になっていました。現在は実際に読み込んだブランチで数えます。読み込みに失敗したリポジトリには「読み込み失敗」と理由を表示し、Skill のインポートでリポジトリが追加された場合は、次に開いたときに読み込み直します。
- **Windows で Python パッケージの `pi.exe` を Pi と認識する問題**（[#9267](https://github.com/farion1231/cc-switch/issues/9267)）。PyPI にある無関係の `pi` パッケージは `Scripts\pi.exe` をインストールし、アプリページではこれが「実行できません」と表示されていました。Pi は npm でのみ配布されているため、現在は Python の `Scripts` ディレクトリにある `pi.exe` を Pi として認識しません。
- **モデル価格の同期に失敗し、`error decoding response body` としか表示されない問題**（[#9262](https://github.com/farion1231/cc-switch/issues/9262)）。ネットワークが遅い場合やプロキシを経由する場合、models.dev から価格表をダウンロードする途中でタイムアウトしていました。現在はタイムアウトを 15 秒から 60 秒に延ばし、失敗したときは同期の状態に本当の原因を表示します。
- **DeepSeek Harness のプロバイダーを追加するときに `Invalid DeepSeek Harness profile YAML` としか表示されず、どのファイルか分からない問題**（[#9297](https://github.com/farion1231/cc-switch/issues/9297)）。現在はエラーに問題のある設定ファイルのパスと YAML の具体的なエラーを表示するため、ファイルを見つけて修正しやすくなりました。
- **接続テストで、リダイレクトする中継サービスを接続不可と判定する問題**（[#9253](https://github.com/farion1231/cc-switch/pull/9253)、[#5747](https://github.com/farion1231/cc-switch/issues/5747)）。`/v1` と `/v1/` の間で互いにリダイレクトするゲートウェイがあるため、現在はテストでリダイレクトを受け取れば接続できたとみなします。
- **ダイアログを開いているとウィンドウをドラッグできない問題**（[#9140](https://github.com/farion1231/cc-switch/pull/9140)）。現在はダイアログを開いていてもウィンドウをドラッグできます。Windows と Linux でアプリ内のウィンドウボタンを使っている場合も、最小化、最大化、閉じるボタンが通常どおり使えます。
- **Linux のクイックパネルの表示がおかしい問題**：軽量モードで開き直したパネルとウィンドウの描画が崩れる（[#9233](https://github.com/farion1231/cc-switch/pull/9233)、[#9216](https://github.com/farion1231/cc-switch/issues/9216)）、ディスプレイの拡大率を設定しているとパネルの一部が切れる（[#9287](https://github.com/farion1231/cc-switch/pull/9287)、[#8556](https://github.com/farion1231/cc-switch/issues/8556)）。Linux のパネルは不透明な背景に変更しました。
- **プロバイダー名が絵文字などの文字で始まる場合や先頭に空白がある場合に、アイコンのないカードに表示される頭文字が文字化けしたり空白になったりする問題**（[#8139](https://github.com/farion1231/cc-switch/pull/8139)）。
- **ワンクリックインポートのリンクのリスク表示で、IPv4 アドレスを埋め込んだ IPv6 アドレスを見落としていた問題**（[#8127](https://github.com/farion1231/cc-switch/pull/8127)）。現在はこのようなアドレスを、実際に指している IPv4 アドレスでローカルか内部ネットワークかを判定します。
