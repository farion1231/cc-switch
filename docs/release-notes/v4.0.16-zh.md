# CC Switch v4.0.16

本版本把托盘改为快捷面板，并修复了一批 Codex 与路由问题。现在点托盘图标会弹出面板，能看到各应用正在用的供应商、模式、额度和用量，也能直接搜索、切换供应商；想用原来的菜单，可以在「设置 → 通用 → 托盘样式」里换回。Codex 聚合模式下，会话在默认供应商和其他成员之间切换后不会再卡在原来那家反复压缩失败；Codex 走路由时，每次重启 CC Switch 都要重新登录 ChatGPT 的问题也已修复。Codex 经路由连 Chat 上游时，并行工具结果不再被中途插入的提示拆开、报 400；自己填的 GPT 上下文窗口对官方同名模型也生效了，4.0.13 加的 272K 封顶改为只限制借用原厂数据的窗口。上游是 5.5 模型时，Claude Code 路由和 Claude Desktop 路由模式都改用 5.5 的模型 ID。另外修复了智谱按量付费账号显示「额度没查到」、新建的火山套餐卡片额度直接报错、Windows 上认不出 fnm 管理的 Node 工具、空闲的卡片删不掉、编辑供应商时「获取 API Key」链接不见等问题，macOS 图标底色也改成了柔和的浅灰。OpenCode 的卡片现在可以设为 OpenCode 的默认模型。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

---

## 新增

**托盘改为快捷面板**（[#8432](https://github.com/farion1231/cc-switch/pull/8432)）。在 macOS 和 Windows 上，点托盘图标现在会弹出快捷面板：「配置」页列出各应用正在用的供应商、当前模式（直连、路由、聚合用和主界面相同的颜色）和额度，可以搜索、切换供应商；「用量」页的趋势图跟随主界面选的币种和图表样式。macOS 上是系统毛玻璃，叠在深色窗口上也看得清；Windows 上是不透明卡片。想用原来的菜单，可以在「设置 → 通用 → 窗口与终端」的「托盘样式」里选「菜单」，立即生效，不用重启。Linux 仍是原生菜单，最上面多了一项「打开快捷面板」。

**OpenCode 卡片可以设为默认模型**（[#8509](https://github.com/farion1231/cc-switch/issues/8509)）。OpenCode 启动时按 `opencode.json` 顶层的 `model` 选模型，以前 CC Switch 没法设置，只能手改文件。现在已添加的 OpenCode 卡片上有「设为默认」，选一个模型即可；只改顶层的 `model`，注释和 `small_model` 原样保留。

## 改进

**MiniMax 官方预设默认用 MiniMax-M3.1-Flash**（[#8518](https://github.com/farion1231/cc-switch/pull/8518)）。Claude Code、Claude Desktop、Codex、Hermes、OpenCode、OpenClaw、Pi 都已更新，MiniMax-M3 仍可选择。

**「获取 API Key」链接恢复为浅蓝色**，不再带下划线。

**侧栏「今日」恢复「今日」前缀**，撤回 4.0.15 的改动。

**价格更新**：Kimi K3 补上缓存写入价（每百万 Token 3 美元，原来记成 0）；Step 5 Preview 的缓存读取价按阶跃星辰 10 月 14 日的调价改为每百万 Token 0.70 元；新增 qwen3.7-flash、qwen3.6-27b、qwen3.8-omni-flash 的价格。这两项改价会自动更新到已有的价格表，手动改过的除外。

**智谱的「获取 API Key」链接去掉了邀请码。**

**土耳其语**：改进了 17 处界面用语（[#8481](https://github.com/farion1231/cc-switch/pull/8481)）。

**预设：** 新增 AllTokens SI。

## 修复

- **Codex 聚合模式下，会话换到另一家供应商后一直报错**（[#8485](https://github.com/farion1231/cc-switch/issues/8485)）。会话在聚合的默认供应商和其他聚合成员之间换模型时，Codex 会先用原来那家压缩上下文；那家额度用完时压缩失败，之后每一轮都卡在同一处。现在聚合模式下第三方路由的模型和聚合成员用同一套压缩标识，不会再触发这次压缩，已经卡住的会话也能恢复。官方路由不受影响。
- **Codex 走路由时，每次重启 CC Switch 都要重新登录 ChatGPT**（[#8431](https://github.com/farion1231/cc-switch/issues/8431)）。Codex 桌面版 26.1013 起，继续会话需要登录 ChatGPT。关闭「非接管切换时保留官方登录」、直连供应商是第三方时，退出 CC Switch 会收起登录并删掉 `auth.json`，下次启动也没有还回去。现在退出 CC Switch 时一律保留登录，真正退出路由时仍按这个设置处理；进入或接上第三方路由时，如果 `auth.json` 里没有登录，会还回最近收起的那份，之前已经这样丢掉的登录也能找回。
- **Codex 经路由连 Chat 上游时，并行工具结果被中途的提示拆开，报 400「No tool output found」**（[#7190](https://github.com/farion1231/cc-switch/issues/7190)、[#7569](https://github.com/farion1231/cc-switch/issues/7569)）。例如 Codex 看图片时插入的 `image_resize_notice`。现在这类提示不再打断工具结果，校验严格的 Chat 上游（如 DeepSeek）不再拒收。
- **自己填的 GPT 上下文窗口对官方同名模型不生效**（[#8366](https://github.com/farion1231/cc-switch/issues/8366)、[#8350](https://github.com/farion1231/cc-switch/issues/8350)）。现在按供应商或按模型填的窗口都会写进 Codex 的模型目录，自动压缩的阈值随之调整；没填时仍用官方默认值。Codex 经路由连 Gemini 时如果输入超长，现在会返回 Codex 认得的「上下文超长」错误，让 Codex 自己压缩。
- **4.0.13 的 GPT 272K 封顶把真有 1.05M 窗口的平台也封了。** 现在只有借用原厂数据的窗口才封顶到 272K：同一地址的预设、models.dev 按地址认出的供应商用它们自己的窗口，手填的窗口也照用；GPT 窗口超过 272K 时，Codex、Hermes、OpenClaw、OpenCode、Pi 的表单会在输入框下方提醒。OpenRouter、Vercel AI Gateway、Cloudflare AI Gateway、DigitalOcean 的预设恢复 1.05M。
- **路由下上游是 5.5 模型时，Claude Code 仍当成 5 的模型**（[#8450](https://github.com/farion1231/cc-switch/pull/8450)）。现在 Opus、Sonnet 档的上游是 5.5 时，写给 Claude Code 的是 `claude-opus-5-5` / `claude-sonnet-5-5`，Claude Code 显示正确的模型，输出上限也从 64K 变为 128K；子代理模型同样处理。
- **Claude Desktop 路由模式下，目标是 5.5 模型时请求被上游拒收**（[#8082](https://github.com/farion1231/cc-switch/issues/8082)）。以前发布给 Desktop 的模型名固定是 `claude-opus-5` / `claude-sonnet-5`，Desktop 按 5 的参数构造请求，5.5 上游不接受；手改生成的配置又会被下次写入覆盖。现在目标是 5.5 时发布 5.5 的模型 ID；映射表本身不变，旧配置发来的请求仍指向原来的目标。
- **Claude Code 经 Codex OAuth 使用带次数上限的 WebSearch 时直接报错**（[#7936](https://github.com/farion1231/cc-switch/pull/7936)）。以前只有强制使用 WebSearch 时才放行，现在不强制也能用，次数上限通过提示约束，超出次数时这一轮响应会在返回时截断。
- **智谱按量付费账号的卡片显示「额度没查到」**（[#8465](https://github.com/farion1231/cc-switch/issues/8465)）。智谱卡片默认查套餐额度，没有 Coding Plan 的账号会被当成出错。现在没有套餐时改为显示账户余额（团队套餐不回落）。
- **新建的火山 Agent / Coding Plan 卡片一上来就显示「额度没查到」**（[#8494](https://github.com/farion1231/cc-switch/issues/8494)）。火山的套餐额度要用账号的 AccessKey ID 和 SecretAccessKey 查询，不是推理用的 API Key。现在用量设置里会预选火山，但填好 AccessKey 之前不启用查询；一键导入链接里明确写了启用的，照常启用。
- **Codex 官方卡的编辑器里，`auth.json` 显示的是旧登录。** 以前显示的是旧版本存下的登录快照，Codex 换过令牌后就和 `~/.codex/auth.json` 对不上；跟随当前登录的卡片则显示为空。现在未绑定托管账号的官方卡显示的是切换到这张卡后 `auth.json` 的内容；不动这个框直接保存，卡片原来的登录信息保持不变。切换时实际写入的文件一直是对的。
- **Windows 上用 fnm 管理 Node 时，认不出已安装的 Codex 等工具**（[#8484](https://github.com/farion1231/cc-switch/issues/8484)）。fnm 只在各个终端里临时加 PATH，CC Switch 找不到 node 和 npm，应用内安装也报「'npm' 不是内部或外部命令」。现在会把 fnm 默认 Node 版本的目录加到 PATH 末尾，原有的 PATH 仍然优先。
- **空闲的供应商卡片删不掉，提示「无法删除当前正在使用的供应商」**（[#8506](https://github.com/farion1231/cc-switch/issues/8506)）。常见于带着旧版 Claude Desktop 映射卡升级后，数据库里旧的「当前」标记还指着它。现在只看实际在用的直连供应商和路由目标，和界面上禁用删除的规则一致。
- **编辑供应商时「获取 API Key」链接不见了。** 现在编辑时会按当前地址找到对应的预设，显示它的链接，和添加时一样。
- **macOS / Linux 上误报环境变量冲突。** 以前会把 CC Switch 从启动它的程序继承来的环境变量也算进去（例如从 Claude Desktop 打开的终端里自带的 `ANTHROPIC_BASE_URL`），这些在应用里也删不掉。现在只检查 shell 配置文件里的定义，Windows 不变。
- **MiniMax Code 的部分用量记录模型显示为 unknown。** 现在会从同一会话、同一时间的那条回复里找回模型名，能正常计价；已经导入的记录保持原样。
- **Hermes 里添加 MiniMax 官方供应商后请求发不出去**（[#8538](https://github.com/farion1231/cc-switch/pull/8538)）。供应商标识按直觉填成 `minimax` 时，和 Hermes 内置的 MiniMax 重名，Hermes 会改用内置那家、要求设置 `MINIMAX_API_KEY`。现在 MiniMax 预设会预填 `cc-switch-minimax` / `cc-switch-minimax-en`；之前已经用 `minimax` 添加的，请改用别的标识重新添加。MiniMax-M3.1-Flash 也标为支持图片输入。
- **中文和日文下用量图的纵轴太宽。** 「5000万」「2000亿」这样的刻度改写成「5千万」「2千亿」，用量页和托盘面板的纵轴按最宽的刻度自动调整宽度，短刻度不再留空，长金额不再被截掉。
- **macOS 图标的白底太亮**（[#8495](https://github.com/farion1231/cc-switch/issues/8495)）。4.0.15 的白色圆角方块改为浅灰，形状不变；Windows 和 Linux 图标不变。
- **「关于」卡片的 Logo 模糊**（[#8470](https://github.com/farion1231/cc-switch/issues/8470)）。改用矢量图。

## 升级说明

**数据库结构没有变化**，仍然是 20。

- 升级后点托盘图标会弹出快捷面板；想用原来的菜单，请到「设置 → 通用 → 托盘样式」里选「菜单」（macOS、Windows）。Windows 上左键点托盘图标以前是打开主界面，现在也弹出面板，主界面从面板底部的「打开主窗口」进入。
- 已保存的 GPT 模型窗口不做迁移。4.0.13 之前保存、自动填成 1.05M 的 Codex GPT 模型，这个值现在会生效；打开表单时会看到提醒，如果实际只有 272K，请手动改小。
