# CC Switch v4.0.29

今回のリリースでは、管理対象アプリに **GitHub Copilot CLI** を追加しました。自前の Key を使うプロバイダーは Copilot 自身の `providers.json` に書き込まれ、`copilot` の `/model` で公式モデルと一緒に選べます。CC Switch を経由する必要はありません。インターフェースに韓国語とロシア語を追加し、7 つの言語をそろえて保守するようになったため、未翻訳の箇所が英語で表示されることはなくなりました。

このほか、Windows で Codex デスクトップ版が WSL 内で Codex を実行しているとき、サードパーティプロバイダーで起動するとエラーになる問題、Codex の新しい会話がルーティング経由でサードパーティのネイティブ Responses 上流に接続すると 400 になる問題、Codex がルーティング経由で Anthropic 形式の上流に接続すると長い回答が 8192 の出力上限で途切れる問題、Codex の公式カードがルーティングモードでアカウント固有のモデル一覧を取得できない問題などを修正しました。

## 新機能

### GitHub Copilot CLI

GitHub Copilot CLI（`copilot`）が新しい管理対象アプリになりました（[#8753](https://github.com/farion1231/cc-switch/pull/8753)、要望は [#5768](https://github.com/farion1231/cc-switch/issues/5768)）。プロバイダーカードは 2 種類あります：

- **公式ログイン**：Copilot CLI 自身の GitHub ログインを使い、ファイルには何も書き込みません。「ターミナルを開く」はカードのモデルと推論の強さで `copilot` を起動します。カードに「アカウント」ページの GitHub アカウントを紐付けている場合は、そのアカウントで起動します。カードにはそのアカウントの Copilot クォータを表示します。
- **自前の Key を使うプロバイダー**：「追加」をクリックすると Copilot 自身の `providers.json`（`$COPILOT_HOME/providers.json`）に書き込まれます。以後このパソコンのどこで `copilot` を起動しても、`/model` で公式モデルと並んで「カード ID/モデル」を選べ、リクエストは CC Switch のルーティングを経由せず直接プロバイダーに送られます。GitHub にログインしていなくても使えます。
  - CC Switch が変更するのはこのプロバイダー自身のエントリだけで、ファイル内のほかのエントリ（Copilot 自身もこのファイルに書き込みます）と順序はそのまま残します。`providers.json` が壊れると Copilot が起動できなくなるため、書き込む前に Copilot のルールに従ってファイル全体を検証します。たとえば、モデルの最大出力がコンテキストウィンドウ全体を占めてはいけません。
  - Copilot の現在の既定モデルを持つプロバイダーは既定として表示され、Copilot から外すことも、カードを削除することもできません。変更するには、先に `copilot` の `/model` でほかのプロバイダーのモデルに切り替えてください。
  - カードのターミナルボタンは追加した後に使えます。起動時にはこのカードの先頭のモデルを直接選びます。
  - プリセットは Pi のプロバイダープリセットを流用しています。

このほか、次の機能にも対応しています：

- **MCP、Skills、プロンプト**：Copilot の `mcp-config.json`、Skills フォルダー、指示ファイルに同期します。
- **セッション管理**：Copilot のセッションを一覧表示し、ターミナルで再開できます。
- **使用量統計**：Copilot のセッションログから使用量をインポートします。自前の Key を使うプロバイダーは、セッションで選ばれたカードごとに集計します。
- **ワンクリックインポートのリンク**：Copilot のプロバイダーをインポートできます。`providers.json` の書き方を認識し、`bearerToken` に対応し、リンク内のモデル ID をすべて保持します。

### 韓国語・ロシア語のインターフェース、7 言語をそろえて保守

- **韓国語**（[#8794](https://github.com/farion1231/cc-switch/pull/8794)、要望は [#2704](https://github.com/farion1231/cc-switch/issues/2704)）と**ロシア語**（[#7788](https://github.com/farion1231/cc-switch/pull/7788)、要望は [#6010](https://github.com/farion1231/cc-switch/issues/6010)）：初回起動時にシステムの言語に合わせて自動で選ばれ、トレイメニューとクイックパネルも翻訳済みです。使用量統計の「通貨」に韓国ウォン（KRW）を追加し、為替レートの自動取得に対応しました。
- トルコ語、韓国語、ロシア語は「コミュニティ翻訳で、未翻訳の箇所は英語で表示」ではなくなりました：インターフェースのすべての文言が简体中文、繁體中文、English、日本語、한국어、Türkçe、Русский の 7 言語でそろっており、今後追加・変更する文言も 7 言語を同時に更新します。
- アップグレード後に表示される更新の概要は、今のところ簡体字中国語、繁体字中国語、英語、日本語のみで、その他の言語では英語で表示されます。

## 変更

- **Copilot のモデル一覧が空のときに理由を説明**（[#5500](https://github.com/farion1231/cc-switch/issues/5500)）：Copilot Free アカウントはモデルを取得できますが、モデル選択で使えるものが 1 つもなく、これまではモデルが見つからないと表示されるだけでした。現在は、このアカウントで Copilot Pro が有効になっていない可能性があると表示します。Claude Code と Claude Desktop のフォームでは、`gpt-4.1` または `gpt-4o` を手動で入力できることも案内します。アカウントにモデルはあるものの、選択中の上流形式に対応したものがない場合は、Codex のフォームで別途説明します。

## 修正

- **Windows で Codex デスクトップ版が WSL 内で Codex を実行しているとき、サードパーティプロバイダーで起動するとすぐに「No such file or directory (os error 2)」が出る問題**（[#9375](https://github.com/farion1231/cc-switch/issues/9375)）。v4.0.27 から、CC Switch は `config.toml` にモデルカタログファイルを Windows の絶対パスで書き込んでいましたが、WSL 内の Codex はこのパスを解釈できず、直接接続・ルーティング・集約の 3 つのモードすべてに影響がありました。現在は Windows 上で、Codex デスクトップ版の WSL で Codex を実行する設定がオンのとき、ファイル名だけを書き込むように戻し、次回の書き込み時に自動で修正します。
- **Codex の新しい会話がルーティング経由でサードパーティのネイティブ Responses 上流に接続すると 400 になる問題**（[#9328](https://github.com/farion1231/cc-switch/pull/9328)、関連 [#7074](https://github.com/farion1231/cc-switch/issues/7074)、[#9379](https://github.com/farion1231/cc-switch/issues/9379)）。新しい Codex デスクトップ版は、新しい会話に `call_id` のないページコンテキストのツール結果を含めます。オートメーションやタスク間のディスパッチの受領通知も同様で、検証の厳しい上流はリクエスト全体を拒否します。これまでは xAI に対してのみ書き換えていましたが、現在は公式以外のすべてのネイティブ Responses 上流に対して、内容を保ったまま 1 件のユーザーメッセージに書き換えます。公式サブスクリプションと、`call_id` のあるツール結果には影響しません。
- **Codex がルーティング経由で Anthropic 形式の上流に接続すると、長い回答が途中で切れて「Incomplete response returned, reason: max_output_tokens」と表示され、再試行しても同じになる問題**。Codex のリクエストには出力上限が含まれず、これまでは 8192 として送っていました。思考もこれに含まれるため、1 回でファイル全体を書き出すツール呼び出しで使い切っていました。現在は既定値を 32000 に変更しました。上流の出力上限がこれより低い場合は 400 が返るので、プロバイダーの「最大出力トークン」に上流が対応する値を入力してください。
- **Codex の公式カードがルーティングモードでアカウント固有のモデル一覧を取得できない問題**：Codex は組み込みの一覧しか使えず、アカウント専用のモデルが欠けていました。Codex デスクトップ版で Daybreak をオンにすると、公式モデルがすべてグレーアウトしていました。現在は、ルーティングで公式カードを使っていて、「公式ログインを一時停止」をオンにしていない場合、ルーティングが公式のモデル一覧をそのまま Codex に渡します。サードパーティプロバイダーでは転送しません。
- **Claude Code がルーティング経由で Mistral 上の DeepSeek モデルに接続すると、ツール呼び出し後のターンがすべて 422 になる問題**（[#9385](https://github.com/farion1231/cc-switch/issues/9385)、[#9388](https://github.com/farion1231/cc-switch/pull/9388)）。
- **ルーティング経由でしか使えない Claude Code のカードで「ターミナルを開く」をクリックすると、Claude Code が毎回未ログイン（「Not logged in」）と表示し、リクエストがまったく送信されない問題**。GitHub Copilot、Codex OAuth、xAI OAuth のようなカードは認証情報をルーティングが提供し、Anthropic 形式以外のカードはルーティングによる形式変換が必要なため、ターミナルからカードのアドレスに直接接続しても使えません。現在はこうしたカードの「ターミナルを開く」ボタンをグレーアウトし、ルーティングを有効にしてからターミナルでクライアントを直接起動するよう説明します。Codex ページでも、こうしたカードはボタンを非表示にする代わりに同じくグレーアウトするようにしました。
- **Claude の公式カードに別のアカウントのクォータが表示されることがある問題**：このパソコンの既定のログインを別のアカウントに切り替えると、使用中のカードが既定のログイン側のアカウントのクォータを読み込んでいました。現在は、既定のログインがこのアカウントのものかを先に確認します。
- **Antigravity のクォータが `agy /usage` と一致しない問題、Google AI Ultra 5x と 20x がどちらも「Google AI Ultra」とだけ表示される問題**（[#9317](https://github.com/farion1231/cc-switch/issues/9317)、[#9319](https://github.com/farion1231/cc-switch/pull/9319)）。
