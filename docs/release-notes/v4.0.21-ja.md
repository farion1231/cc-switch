# CC Switch v4.0.21

今回のリリースでは、Claude Code で複数の公式サブスクリプションアカウントを切り替えられるようになりました。「アカウント」ページで Claude アカウントをいくつか追加し、公式カードごとに 1 つずつ選んでおくと、切り替えたカードのアカウントを Claude Code が使います。複数のアカウントを同時に使いたい場合は、カードから「ターミナルを開く」と、そのターミナルはカードのアカウントに固定されます。ログインは Claude Code 公式の手順で行い、トークンはこのパソコンの Claude Code の中にだけ残ります。CC Switch はアップロードも、更新も、ログアウトもしません。アカウントを選んだカードと「アカウント」ページには、各アカウントのプランと残りの利用枠が表示されます。このほか、「ターミナルを開く」をカード上に移し、Codex のモデル一覧をドラッグで並べ替えられるようにし、軽量モードが再起動後も保持されるようにしました。マネージド ChatGPT アカウントが再起動後に誤ってログインの期限切れと表示される、Codex がルーティングを経由するときにリクエストが別のアドレスに送られる、Codex の MCP 設定に `timeout` / `autoApprove` が余計に入る、npm 12 で OpenCode と Grok Build が正しくインストールされない、Kimi Code の使用量の時刻が正しくない、Oh My Pi の `models.yml` に `&`、`*`、`!` があると編集できない、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### 複数の Claude 公式サブスクリプションアカウントの切り替え

Claude のサブスクリプションを複数持っている場合（個人の Max と会社の Team、あるいは複数の Pro アカウントなど）、これまでは Claude Code で `/logout` してから `/login` するか、アカウントごとに設定ディレクトリを自分で作るしかありませんでした。現在は CC Switch で複数のアカウントを管理できます（[#1928](https://github.com/farion1231/cc-switch/issues/1928)）。

**セキュリティとコンプライアンス。** サブスクリプションアカウントをツールに管理させるうえで最も重要なのは、トークンの安全性と、Anthropic の規約に違反しないことです。この機能は Claude Code 公式ドキュメントの方法に従って実装しており、トークンは常にお使いのパソコンの Claude Code の中にだけあります：

- **ログインは公式の手順で行います。** アカウントを追加するときに実行するのは Claude Code に組み込まれた `claude auth login --claudeai` で、パスワードの入力と認可はすべて claude.ai の公式ページで行います。CC Switch には独自の Claude ログインも、独自の OAuth クライアントもありません。Anthropic の[法的事項とコンプライアンスのページ](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)は、Claude アカウントのログインを Anthropic 自身のフローを通じて行わなければならないと定めており、ユーザーが自分のサブスクリプションで未改変の Claude Code にログインすることは制限しないと明記しています。
- **複数アカウントには公式が推奨する方法を使います。** アカウントごとに独立した設定ディレクトリを用意し、`CLAUDE_CONFIG_DIR` で区別します。Claude Code の[認証ドキュメント](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)の「Log in with multiple accounts」の節と同じ方法で、CC Switch はディレクトリの作成とターミナルの起動を代わりに行うだけです。
- **トークンはこのパソコンから出ません。** トークンは Claude Code 自身の保存場所（macOS ではキーチェーン、Linux と Windows では `.credentials.json`）にだけ保存され、アップロードされず、クラウド同期の対象にもならず、CC Switch のデータベースにも書き込まれません。CC Switch 自身が記録するのは、メールアドレス、組織、プランといったアカウント情報とログインの有効期限だけで、トークンは記録しません。
- **代わりにリクエストを送りません。** CC Switch にはサーバーがなく、サブスクリプションのトークンでモデルを呼び出すこともありません。会話のリクエストはすべて、このパソコンの未改変の Claude Code が Anthropic に直接送り、使用量はあなた自身のアカウントに計上されます。利用枠を照会するときは、このパソコンから Anthropic 公式の利用枠 API を直接照会しており、Claude Code 自身の `/usage` と同じデータを参照します。
- **更新せず、ログアウトせず、Claude Code を変更しません。** トークンの更新はすべて Claude Code 自身が行います。アカウントを削除しても、CC Switch がそのアカウント用に作ったディレクトリ（macOS ではそのディレクトリのキーチェーン項目も）を削除するだけで、そのアカウントがどこかでログアウトされることはありません。CC Switch は Claude Code のプログラムファイルを変更しません。
- **管理するのはあなた自身のアカウントだけです。** 利用枠に応じてアカウントを自動でローテーションすることはなく、サブスクリプションをほかの人と共有する機能もありません。

カードの切り替えでアカウントを切り替える仕組みは、このパソコンの Claude Code の保存場所のあいだでログインを移動させます（Claude Code 自身の形式だけに従います）。この使い方は公式ドキュメントでは特に取り上げられていません。ドキュメントに明記された方法だけを使いたい場合は、カードを「Claude Code のログインに追従」のままにし、ほかのアカウントはカードの「ターミナルを開く」からだけ使ってください。

**使い方：**

- **アカウントの追加。** 「アカウント」ページの Claude グループで「アカウントを追加」をクリックします。ブラウザで claude.ai の公式の認可ページが開き、ログインするとアカウントが自動で一覧に表示されます。ブラウザでの認可後にこのパソコンへ戻れない場合は、アドレスバーのアドレスかページに表示されたコードを貼り付けて戻すこともできます。各アカウントのディレクトリは互いに干渉せず、`~/.claude` にある設定、MCP、`CLAUDE.md` が同期されます（ログイン情報とルーティング関連の設定は除きます）。
- **公式カードでアカウントを選ぶ。** Claude 公式カードの「ログイン方法」ドロップダウンは Codex 公式カードと同じで、上にログイン済みのアカウント、下に「Claude アカウントを追加または管理」（「アカウント」ページに移動）と「Claude Code のログインに追従」があります。カードは 1 アカウントにつき 1 枚作れば十分です。
- **カードを切り替えるとアカウントも切り替わります。** アカウントを選んだ公式カードに切り替えると、CC Switch はそのアカウントのログインを Claude Code が既定で読み込む場所に置き、それまでのアカウントはそのアカウント自身のディレクトリに戻します。ターミナル、IDE プラグイン、スクリプトの `claude` はすべてこのアカウントを使うようになり、実行中の Claude Code もすぐに切り替わるので、再起動は不要です。アカウントを選んだ公式カードに切り替えるとき、現在のログインがまだ「アカウント」ページにない場合は、先に取り込みます。切り替え中は Claude Code 自身のロックを保持します。切り替えの途中で CC Switch が予期せず終了した場合は、次の切り替えまたは起動時に自動で完了するか取り消します。「Claude Code のログインに追従」を選んだカードはログインに触れないので、アカウントを追加しない人には影響しません。
- **複数のアカウントを同時に使う。** アカウントを選んだカードで「ターミナルを開く」と、そのターミナルはカードのアカウントに固定され、その後カードを切り替えても影響を受けません。
- **プランと利用枠。** カードのサブタイトルにアカウントとプラン（`Max 20x` など）を表示し、ログインの更新が必要なときは通知を添えます。カードの下部には既定でこのアカウントの残りの利用枠を表示し、「アカウント」ページの各アカウントにも同じ利用枠の列があります。使っていないアカウントのトークンが期限切れになった場合、CC Switch はそのアカウントのディレクトリで Claude Code に組み込まれた `claude -p /usage` を一度実行し（各アカウント最大 10 分に 1 回）、Claude Code 自身がログインを更新して利用枠を照会します。CC Switch は結果を読むだけです。`/usage` はモデルを呼び出さず、会話の利用枠を消費しません。アカウントを選んでいない公式カードにも、現在ログインしているアカウントのプランが表示されます。

いくつかの注意点：

- アカウントを切り替えると、使用中の Remote Control は切断されます。切り替え後の最初のメッセージではプロンプトキャッシュを作り直すため、少し遅くなり、利用枠も少し多く消費します。
- 設定で Claude の設定ディレクトリを上書きしている場合（WSL を指している場合を含む）、カードを切り替えてもログインは切り替わらず、画面で「ターミナルを開く」を使うよう案内します。

### Codex のモデル一覧をドラッグで並べ替えられるように

Codex のプロバイダーフォームのモデル一覧では、各行の先頭にドラッグ用のハンドルがあり、マウスまたはキーボードで順序を変えられます（[#8870](https://github.com/farion1231/cc-switch/issues/8870)）。この順序がそのまま Codex の `/model` メニューの順序になります。1 行目が既定のモデルを表す場合は、1 行目にドラッグしたモデルが新しい既定のモデルになります。これまでは位置を変えるには削除して追加し直す必要がありました。

## 改善

**「ターミナルを開く」をカード上に移しました。** これまでは ⋯ メニューにありましたが、現在は「編集」の左にあるアイコンボタンです。ツールチップは「このプロバイダーでターミナルを開く」で、ターミナルがこのカードに固定される場合（自分のアドレスと Key を入力したカード、Claude アカウントを選んだ公式カード）は「（環境を分離）」が付きます。

**「アカウント」ページの各グループの「アカウントを追加」ボタンを見出しの右に固定しました。** これまではアカウントがないとボタンが空の案内の中に移動し、グループごとにボタンの高さがそろっていませんでした。ChatGPT のログイン方法は、ボタンの横の小さなドロップダウンに変わりました。見出しにあった「すべてのアカウントを削除」メニューはなくなり、アカウントはそれぞれの行のメニューから削除します。各アカウントの利用枠のバーもそろい、長さが同じになりました。

**軽量モードが再起動後も保持されるように。** 軽量モードのまま CC Switch を終了すると、次回の起動も軽量モードになり、メイン画面は表示されなくなりました。`ccswitch://` リンクからコールドスタートした場合は、インポートのダイアログを表示するため、通常どおりメイン画面を開きます。

**Hermes のカードに「既定」と表示し、「既定にする」を ⋯ メニューに移しました。** Hermes は追加したプロバイダーをすべて `config.yaml` に書き込み、現在のプロバイダーは既定値にすぎません。OpenClaw、OpenCode、Kimi Code と同じです。これまでの電源アイコンの「有効にする」ボタンはスイッチのように見えていました。

**カードが「使用中」になったときに、使用量の欄が左右にずれなくなりました。**

**MCP で SSE を選んだとき、対応していないアプリを通知するように**（[#8882](https://github.com/farion1231/cc-switch/issues/8882)）。Codex は stdio と HTTP にしか対応しておらず、SSE の URL を HTTP として接続するため、サーバーが SSE にしか対応していない場合は接続できません。Pi と Antigravity は保存時にエラーになります。現在は「書き込み先」の下で事前に通知します。

**Claude Desktop の上流アドレスに `githubcopilot.com` を入力したとき、上流フォーマットに「モデルに応じてルーティングが自動選択」と表示するように**（[#8838](https://github.com/farion1231/cc-switch/pull/8838)）。GitHub Copilot のプロバイダーを選んだときと同じです。

**OpenCode の OMO、OMO Slim のカードに「接続チェック」を表示しないように**（[#8842](https://github.com/farion1231/cc-switch/pull/8842)）。これらはエージェントとモデルの対応関係にすぎず、テストできるアドレスがないため、これまではクリックするとエラーになっていました。

**トルコ語の翻訳を補完しました**（[#8836](https://github.com/farion1231/cc-switch/pull/8836)）。

**プリセット：** DeepSeek はすべて Flash モデルに変更しました。Kimi 公式プリセットに K3.1 Pro と K3.1 Pro HighSpeed を追加し、low / high / max の思考レベルを選べます（[#8867](https://github.com/farion1231/cc-switch/issues/8867)）。OpenClaw の MiniMax M3.1 Flash で max を選べるようにしました。ClinePass（[#8885](https://github.com/farion1231/cc-switch/issues/8885)）、TeamoRouter Claude（[#8266](https://github.com/farion1231/cc-switch/pull/8266)）を追加しました。Claude Desktop の OpenCode Go は公式ドキュメントのアドレスに変更し、利用枠も照会できるようになりました（[#8720](https://github.com/farion1231/cc-switch/pull/8720)、[#8779](https://github.com/farion1231/cc-switch/issues/8779)）。

## 修正

- **マネージド ChatGPT アカウントが再起動後に「ログインの期限切れ」と表示されて切り替えられず、しばらくすると自然に直る問題**（[#8901](https://github.com/farion1231/cc-switch/issues/8901)）。これまではログインを更新するときにどんな HTTP 403 もログインの失効とみなし、ネットワークエラーも期限切れとして表示していました。現在は Codex CLI と同じく、401 または明確なトークン失効のエラーだけを期限切れとみなします。一時的なネットワークの問題は通常どおり再試行し、利用枠は前回の結果を保持します。トレイで切り替えた後、メイン画面で照会に失敗していた利用枠も再照会します。
- **Codex がローカルルーティングを経由するとき、リクエストが別のアドレスに送られる問題**（[#8849](https://github.com/farion1231/cc-switch/pull/8849)、[#8848](https://github.com/farion1231/cc-switch/issues/8848)）。`config.toml` に複数のプロバイダーのテーブルがある場合や、その上にコメントアウトされた古いアドレスの行がある場合、これまではテキスト中の最初の `base_url` を使っていたため、選択中のプロバイダーの Key を付けて別の場所に送っていました。現在は `model_provider` で選ばれたテーブルからアドレスを取ります。
- **Codex のリモート圧縮の使用量がときどき記録されない問題**（[#8879](https://github.com/farion1231/cc-switch/pull/8879)）。
- **Codex の MCP 設定に `timeout`、`autoApprove` が余計に入り、Codex デスクトップ版が不明な設定として報告し、`--strict-config` では読み込みを拒否される問題**（[#8843](https://github.com/farion1231/cc-switch/issues/8843)）。この 2 つのフィールドはほかのクライアントのもので、これまではそのまま `config.toml` に書き込んでおり、手動で削除しても次の同期でまた書き戻されていました。現在は Codex に書き込むときに取り除きます。ほかのアプリには影響しません。
- **Codex が中継経由で複数の Azure リソースに接続するとき、セッションの途中で 400「created under a different Azure OpenAI resource」になり、続けられない問題**（[#8877](https://github.com/farion1231/cc-switch/issues/8877)）。現在はこのエラーを受け取ると、履歴の項目 ID を取り除いて 1 回再試行します。通常のリクエストには影響しません。
- **ClinePass のように Chat Completions の結果を `data` に包んで返す上流で、非ストリーミングのリクエストが 422「No choices in response」になる問題**（[#5658](https://github.com/farion1231/cc-switch/issues/5658)）。
- **npm 12 で、「アプリ」ページからインストールした OpenCode が Windows で「実行中の Windows のバージョンと互換性がありません」と表示され、Grok Build はアップグレード後も古いバージョンが動き続ける問題**（[#8863](https://github.com/farion1231/cc-switch/issues/8863)）。npm 12 は既定でインストールスクリプトを実行しませんが、この 2 つのパッケージは本体のプログラムを配置するのにインストールスクリプトが必要です。現在はインストールとアップグレードのときに、これらのインストールスクリプトを許可します。
- **Windows で Hermes が「アプリ」ページに 2 か所のインストールとして表示される問題**（[#8839](https://github.com/farion1231/cc-switch/issues/8839)）。同じディレクトリに残っている `hermes.cmd` は、別のインストールとして数えなくなりました。
- **Kimi Code の使用量で、1 ターン分の会話のリクエスト時刻がすべて同じになり、時間ごとの集計で最後の 1 時間に集中する問題**（[#8899](https://github.com/farion1231/cc-switch/issues/8899)）。現在はリクエストごとの完了時刻で記録します。取り込み済みの記録は、セッションファイルが次に変化したときに修正されます。
- **Oh My Pi の `models.yml` に `name: Search & Fetch` のような `&`、`*`、`!` を含む値があると、プロバイダーの保存時に「この YAML の構造は CC Switch で安全に編集できません」と表示される問題**（[#8897](https://github.com/farion1231/cc-switch/issues/8897)）。
- **`~/.gemini/.env` に `export GEMINI_API_KEY=...` と書いてあると、インポート後に Key がなく、既定のプロバイダーに戻すとファイルから削除されてしまう問題**（[#8862](https://github.com/farion1231/cc-switch/pull/8862)、[#8861](https://github.com/farion1231/cc-switch/issues/8861)）。
- **プロンプトを有効にしていたプロジェクトから、プロンプトのないプロジェクトに切り替えても、元のプロンプトが無効にならない問題。**
- **「使用量」ページでサイドバーを開閉すると、トレンドグラフの右端がずれる問題**（[#8548](https://github.com/farion1231/cc-switch/pull/8548)）。
