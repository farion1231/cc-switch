# CC Switch v4.0.19

This release adds support for Kimi Code, the 12th app managed by CC Switch. **Kimi Code's command-line and desktop versions share the same configuration, so CC Switch's support covers both.** Several Kimi Code providers can be written into its configuration at the same time, and you can add them, remove them and set the default in CC Switch; MCP, Skills and prompts sync to Kimi Code, sessions can be browsed and resumed, and usage is imported from session logs; the "Apps" page can install, upgrade and uninstall Kimi Code. You can also sign in to the Kimi coding plan in Accounts and add several accounts, each showing its nickname and quota. The Usage page has a new layout: time, app, provider and model sit on one row, the selected metric drives both the trend chart and the heatmap, the detail tables become tabs with counts, and you can choose how many request logs to show per page. Other fixes cover Codex reporting `unsupported call: exec` on every turn after switching from a third-party GPT to another model in Aggregation mode, the whole app freezing when opening the "About" page on Linux/WSL when CC Switch is launched from a terminal, image input being turned off after choosing a model for Codex, Claude Code's VS Code extension showing a `redacted_thinking` error through a Responses upstream, Claude subscription quota reading the wrong Keychain entry on macOS, the Gemini group missing from Antigravity quota, the console starting on Windows when Hermes is installed in WSL, and a single Esc closing every stacked panel. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### Kimi Code

Kimi Code (the command is `kimi`) is now a separate app with its own providers, MCP, Skills, prompts, sessions and usage ([#8687](https://github.com/farion1231/cc-switch/pull/8687)). Its configuration is in `~/.kimi-code/config.toml`, or in the folder set by `KIMI_CODE_HOME` when that is set.

> **💡 Works for both the command-line and desktop versions.** Kimi Code's command-line and desktop versions share the same configuration and sign-in in `~/.kimi-code`, so the providers, MCP, Skills, prompts and official accounts you add in CC Switch can be used directly by both.

- **Providers can be enabled at the same time.** As with OpenCode, several providers can be written into Kimi Code's configuration at once, and you choose among them with `/model` in Kimi Code. Clicking "Add" on an "Available" card writes it into the configuration without changing the default model; a card already added can be removed with "Remove", and "Set as default" is in the card's more menu. A provider that Kimi Code is currently using as its default model or subagent model cannot be removed; you are asked to switch it in Kimi Code first. Only the providers and models CC Switch manages are changed; the rest of the configuration is left as it is.
- **Adding providers.** As in other apps, presets are grouped into "Model vendors", "Third-party platforms", "Cloud providers" and "Local", plus an "Account sign-in" group for signing in with an official Kimi account. After "Fetch Models", the models you select get their context window, thinking and image input filled in automatically; each model has its own row, where you can enter a display name (shown in Kimi Code's `/model`). "Always thinking" and "Load tools on demand" have a "?" explanation next to them; request headers have moved into "Advanced Options".
- **MCP, Skills, prompts.** MCP supports stdio, HTTP and SSE; Skills do not overwrite skills with the same name in Kimi Code's own folder.
- **Sessions and usage.** You can browse and resume Kimi Code sessions; usage is imported from session logs, including input, output, cache, time to first token and duration.
- **Manage Kimi Code on the "Apps" page.** It is installed with the official installer, and can be upgraded and uninstalled.
- Kimi Code does not go through local routing and has no Aggregation mode.

### Official Kimi accounts

In Accounts you can click "Sign in to Kimi" (choosing "Kimi Code official sign-in" when adding a provider also takes you there), choose the China or international version, and once you finish authorizing in the browser, the official models are added automatically ([#8710](https://github.com/farion1231/cc-switch/pull/8710), [#8726](https://github.com/farion1231/cc-switch/pull/8726)).

- **Multiple accounts.** The first account uses Kimi Code's own sign-in location; each account added after that has its own credentials, provider and models, and appears as "Kimi Subscription <nickname>" in Kimi Code's model list. Click "Use this account" in Accounts, or choose "Set as default" from the card's more menu, to switch Kimi Code's default model to that account's. Official cards cannot be edited or deleted on the Providers page; manage them in Accounts.
- **Nicknames and quota.** Each account and official card shows its nickname and quota. Sign-ins that are about to expire are renewed in the background using the same lock as Kimi Code itself, so the two never compete; on Windows, quota is only read and sign-ins are not renewed.
- **Signing in again and removing.** Signing in again with the same account updates the existing copy instead of adding another; removing a separately added account also deletes its provider, models, credentials and card, and an account in use cannot be removed. The account Kimi Code itself is signed in with is only taken off the list; CC Switch does not sign it out of Kimi Code.
- An account already signed in to Kimi Code appears in Accounts automatically.

## Improvements

**The Usage page has a new layout** ([#8711](https://github.com/farion1231/cc-switch/pull/8711)).

- The top right of the page keeps only a sync button (showing the last sync time) and a settings button; data source, display and price settings are all in the settings. Which columns the request log shows is now chosen from the "Request log columns" menu on the right of the request log tab.
- Time, app, provider and model sit on one row, and provider and model are combined into one two-level menu.
- Click a metric in the overview, and the trend chart and heatmap show it; the four token metrics (input, output, cache read and cache write) can expand into a second row.
- The detail tabs drop "Settings", leaving "Request Logs", "Providers" and "Models", each with a count on its label; tables size their columns to the content and scroll horizontally when too wide, with the time and app columns pinned on the left.
- Request logs can show 10, 20 or 50 per page, 20 by default, and your choice is remembered. Cells with no data show "—".

**"Set as default" for OpenCode and OpenClaw moves into the more menu.** The star icon on added cards was hard to recognize, and it was not clear whether it was selected. It is now in the card's more menu, and for providers with several models you can pick the default model from a submenu. The default provider for OpenCode, OpenClaw, Hermes and Kimi Code is now marked in the same blue as "In use".

**Pi's provider key is always shown.** It is also shown and prefilled when adding from a preset, and can be changed; if it duplicates another Pi card, a hint appears below the input and the card cannot be saved. Before, the error only appeared when saving.

**MCP servers show their custom display name** ([#8692](https://github.com/farion1231/cc-switch/pull/8692)). For servers with a display name set, the list and the delete confirmation show it, with the ID written next to it.

**The whole project group header on the Sessions page can be clicked to expand and collapse** ([#8709](https://github.com/farion1231/cc-switch/pull/8709)).

**Presets:** Added BuyToken and V-API.

## Fixes

- **In Aggregation mode, after switching from a third-party GPT to DeepSeek, Kimi or similar models, Codex reported `unsupported call: exec` on every turn** ([#8676](https://github.com/farion1231/cc-switch/issues/8676)). Third-party GPT models and other models call command-line tools differently; before, Codex did not compact the history first when switching, and the new model copied calls from the history that it does not support. Now, when switching between these two kinds of models, Codex first compacts once with the previous model; switching within the same kind still does not compact.
- **On Linux or WSL, with CC Switch launched from a terminal, opening "Settings → About" froze the whole app** ([#3241](https://github.com/farion1231/cc-switch/issues/3241)). The command that checks tool versions took over the terminal and was suspended by the system. This check no longer uses the terminal and waits at most 10 seconds.
- **After choosing a fetched model for Codex, image input was turned off** ([#8682](https://github.com/farion1231/cc-switch/issues/8682)). When the model data found said the model only supports text, it used to be written as "text only", so Codex rejected images and the form had no way to change it back. Now this field is filled in only when the data says images are supported; otherwise it is left to Codex's default judgment.
- **Picking some relay models filled in another vendor's parameters** ([#8765](https://github.com/farion1231/cc-switch/issues/8765)). For example, models.dev has no DeepSeek entry for DeepSeek-V4.1-Flash-1017, so CC Switch used to borrow a fine-tuned version hosted by another provider, filling in text-only input and a 262K context window, a quarter of the real one. When the vendor's own entry can't be found, these fields are now left empty instead of borrowing from another host.
- **Claude Code's VS Code extension showed `Unsupported content type: redacted_thinking` before tool calls through an OpenAI Responses upstream** ([#8691](https://github.com/farion1231/cc-switch/issues/8691)). Thinking with only encrypted content used to be converted into a format the extension does not recognize; it now becomes an empty thinking block, as with Anthropic, and requests sent back upstream are unchanged. Thinking summaries that only arrive at the end are filled in too.
- **Claude subscription quota queries failed on macOS** ([#8764](https://github.com/farion1231/cc-switch/pull/8764), [#8762](https://github.com/farion1231/cc-switch/issues/8762)). When the Keychain had several entries with the same name, an old entry holding only MCP sign-in data could be read. It now looks up the current user's account first, and falls back to the previous method only if no usable sign-in is found.
- **On macOS, quota on Antigravity official cards showed only Claude/GPT, without Gemini.** Google returns Gemini quota only to newer versions of agy; queries now include the local agy's version.
- **On Windows, a black command-line window popped up when refreshing Antigravity quota or fetching the model list** ([#8700](https://github.com/farion1231/cc-switch/issues/8700)).
- **On Windows with Hermes installed in WSL, clicking "Open terminal & launch" while the Web UI was not running started the Hermes on Windows** ([#8689](https://github.com/farion1231/cc-switch/issues/8689)). When the Hermes config folder points to a WSL path, `hermes dashboard` now runs in that WSL distribution.
- **Routing did not recognize the session when Codex requests carried a `session-id` or `thread-id` header** ([#8718](https://github.com/farion1231/cc-switch/pull/8718)).
- **The model list could not be fetched from the Anthropic address of Alibaba Cloud Bailian and Qwen Token Plan** ([#8755](https://github.com/farion1231/cc-switch/pull/8755)).
- **OpenCode Zen and Go providers could not get full model parameters from models.dev.** models.dev changed the addresses of these two; the old addresses now match too, so models such as `deepseek-v4.1-flash` get their parameters filled in automatically again.
- **With several full-screen panels stacked open, a single Esc closed them all.** Now it closes only the top one.
- **When a second deep link arrived while the first was still importing, the first import finishing closed the second one's confirmation** ([#8696](https://github.com/farion1231/cc-switch/issues/8696)).
- **The "Last 7 days", "Last 14 days" and "Last 30 days" ranges on the Usage page counted one day too many or too few around daylight saving time changes** ([#8719](https://github.com/farion1231/cc-switch/issues/8719)).
- **When the request log was on one of the later pages and the total shrank, the table went empty with no way back.** It now moves back to the last page.
- **On the "Apps" page, tools that are not installed showed a redundant "not installed" line under the version column.**
- **The text jumped when clicking "Advanced Options".**

## Upgrade Notes

**The database schema goes from 21 to 22**, adding Kimi Code toggles for MCP and Skills. The database is backed up automatically before the upgrade; if you go back to an older version after upgrading, it reports that the database version is too new and cannot open it.

- Kimi Code is shown in the sidebar by default; if you don't use it, you can turn off "Show Kimi Code in the sidebar" on the "Apps" page.
