# CC Switch v4.0.16

今回のリリースでは、トレイをクイックパネルに変え、Codex とルーティングに関する問題をまとめて修正しました。トレイアイコンをクリックするとパネルが開き、各アプリで使用中のプロバイダー、モード、利用枠、使用量を確認でき、そのままプロバイダーを検索して切り替えられます。従来のメニューに戻したい場合は「設定 → 一般 → トレイの表示」で戻せます。Codex の集約モードでは、セッションを既定のプロバイダーと他のメンバーとの間で切り替えた後、元のプロバイダーで圧縮に失敗し続けて止まってしまうことはなくなりました。Codex をルーティング経由で使っているとき、CC Switch を再起動するたびに ChatGPT へのログインをやり直す必要があった問題も修正しました。Codex がルーティング経由で Chat のアップストリームに接続するとき、並列のツール結果が途中に挿入された通知で分断されて 400 になることはなくなりました。自分で入力した GPT のコンテキストウィンドウが公式と同名のモデルにも反映されるようになり、4.0.13 で追加した 272K の上限は、メーカー本家のデータを借用したウィンドウにだけ適用されるようになりました。アップストリームが 5.5 のモデルの場合、Claude Code のルーティングと Claude Desktop のルーティングモードはどちらも 5.5 のモデル ID を使うようになりました。ほかにも、Zhipu の従量課金アカウントで「残量を取得できません」と表示される問題、新しく作成した火山のプランのカードで利用枠がいきなりエラーになる問題、Windows で fnm が管理する Node のツールを認識できない問題、使われていないカードを削除できない問題、プロバイダーの編集時に「API Key を取得」リンクが表示されない問題などを修正し、macOS のアイコンの背景も柔らかいライトグレーに変えました。OpenCode のカードを OpenCode のデフォルトモデルに設定できるようにもなりました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

---

## 新機能

**トレイがクイックパネルに**（[#8432](https://github.com/farion1231/cc-switch/pull/8432)）。macOS と Windows では、トレイアイコンをクリックするとクイックパネルが開くようになりました。「構成」タブには各アプリで使用中のプロバイダー、現在のモード（直接接続、ルーティング、集約をメイン画面と同じ色で表示）、利用枠が並び、プロバイダーを検索して切り替えられます。「使用量」タブの推移グラフは、メイン画面で選んだ通貨とグラフの種類に従います。macOS ではシステムのすりガラス効果を使い、暗いウィンドウの上に重なっても読みやすくなっています。Windows では不透明なカードです。従来のメニューに戻すには「設定 → 一般 → ウィンドウとターミナル」の「トレイの表示」で「メニュー」を選んでください。すぐに反映され、再起動は不要です。Linux は引き続きネイティブメニューで、一番上に「クイックパネルを開く」が追加されました。

**OpenCode のカードをデフォルトモデルに設定できるようになりました**（[#8509](https://github.com/farion1231/cc-switch/issues/8509)）。OpenCode は起動時に `opencode.json` の最上位の `model` でモデルを選びますが、これまで CC Switch からは設定できず、ファイルを手で編集するしかありませんでした。現在は追加済みの OpenCode のカードに「既定にする」があり、モデルを 1 つ選ぶだけで設定できます。変更するのは最上位の `model` だけで、コメントと `small_model` はそのまま残ります。

**MiniMax の公式プリセットのデフォルトモデルが MiniMax-M3.1-Flash になりました**（[#8518](https://github.com/farion1231/cc-switch/pull/8518)）。Claude Code、Claude Desktop、Codex、Hermes、OpenCode、OpenClaw、Pi のすべてを更新しており、MiniMax-M3 も引き続き選べます。

**「API Key を取得」リンクが明るい青色に戻りました。** 下線も付かなくなりました。

**サイドバーの「今日」に「今日」の接頭辞が戻りました。** 4.0.15 の変更を取り消しました。

**料金の更新**：Kimi K3 にキャッシュ書き込みの料金（100 万トークンあたり 3 ドル。これまでは 0 と記録されていました）を追加しました。Step 5 Preview のキャッシュ読み取りの料金は、StepFun の 10 月 14 日の値上げに合わせて 100 万トークンあたり 0.70 元に変更しました。qwen3.7-flash、qwen3.6-27b、qwen3.8-omni-flash の料金を追加しました。この 2 つの料金変更は既存の料金表にも自動で反映されます。ただし、手動で変更したものは除きます。

**Zhipu の「API Key を取得」リンクから招待コードを外しました。**

**トルコ語**：17 か所の UI の文言を改善しました（[#8481](https://github.com/farion1231/cc-switch/pull/8481)）。

**プリセット：** AllTokens SI を追加しました。

## 修正

- **Codex の集約モードで、セッションを別のプロバイダーに切り替えた後、エラーが続いていた問題**（[#8485](https://github.com/farion1231/cc-switch/issues/8485)）。セッションのモデルを集約の既定のプロバイダーと他の集約メンバーとの間で切り替えると、Codex はまず元のプロバイダーでコンテキストを圧縮します。そのプロバイダーの利用枠が尽きていると圧縮に失敗し、それ以降は毎ターン同じところで止まっていました。現在は集約モードで、サードパーティのルーティング先のモデルと集約のメンバーが同じ圧縮の識別子を使うので、この圧縮は発生しなくなり、すでに止まってしまったセッションも回復します。公式のルーティングには影響しません。
- **Codex をルーティング経由で使っているとき、CC Switch を再起動するたびに ChatGPT へのログインをやり直す必要があった問題**（[#8431](https://github.com/farion1231/cc-switch/issues/8431)）。Codex デスクトップ版 26.1013 以降、セッションを続けるには ChatGPT へのログインが必要です。「直接切替時に公式ログインを保持」をオフにしていて、直接接続のプロバイダーがサードパーティの場合、CC Switch を終了するとログインを退避して `auth.json` を削除し、次回の起動時にも戻していませんでした。現在は CC Switch の終了時には常にログインを残し、実際にルーティングをやめるときは引き続きこの設定に従います。サードパーティのルーティングに入るとき、または接続し直すときに `auth.json` にログインがなければ、最後に退避したログインを戻すので、以前にこうして失われたログインも取り戻せます。
- **Codex がルーティング経由で Chat のアップストリームに接続するとき、並列のツール結果が途中の通知で分断され、400「No tool output found」になっていた問題**（[#7190](https://github.com/farion1231/cc-switch/issues/7190)、[#7569](https://github.com/farion1231/cc-switch/issues/7569)）。たとえば Codex が画像を見るときに挿入する `image_resize_notice` です。現在はこうした通知でツール結果が分断されなくなり、検証の厳しい Chat のアップストリーム（DeepSeek など）にも拒否されなくなりました。
- **自分で入力した GPT のコンテキストウィンドウが、公式と同名のモデルに反映されていなかった問題**（[#8366](https://github.com/farion1231/cc-switch/issues/8366)、[#8350](https://github.com/farion1231/cc-switch/issues/8350)）。現在はプロバイダー単位でもモデル単位でも、入力したウィンドウは Codex のモデルカタログに書き込まれ、自動圧縮のしきい値もそれに合わせて調整されます。入力していない場合は引き続き公式のデフォルト値を使います。Codex がルーティング経由で Gemini に接続していて入力が長すぎる場合は、Codex が理解できる「コンテキスト超過」のエラーを返し、Codex 自身に圧縮させるようになりました。
- **4.0.13 の GPT 272K の上限が、実際に 1.05M のウィンドウを持つプラットフォームにまで適用されていた問題。** 現在 272K の上限がかかるのは、メーカー本家のデータを借用したウィンドウだけです。同じアドレスのプリセットや、models.dev がアドレスから識別したプロバイダーはそれぞれ自身のウィンドウを使い、手で入力したウィンドウもそのまま使います。GPT のウィンドウが 272K を超える場合、Codex、Hermes、OpenClaw、OpenCode、Pi のフォームでは入力欄の下に注意が表示されます。OpenRouter、Vercel AI Gateway、Cloudflare AI Gateway、DigitalOcean のプリセットは 1.05M に戻しました。
- **ルーティングでアップストリームが 5.5 のモデルなのに、Claude Code が 5 のモデルとして扱っていた問題**（[#8450](https://github.com/farion1231/cc-switch/pull/8450)）。現在は Opus、Sonnet の枠のアップストリームが 5.5 のとき、Claude Code には `claude-opus-5-5` / `claude-sonnet-5-5` を書き込むので、Claude Code に正しいモデルが表示され、出力上限も 64K から 128K になります。サブエージェントのモデルも同様に扱います。
- **Claude Desktop のルーティングモードで、ターゲットが 5.5 のモデルのときにリクエストがアップストリームに拒否されていた問題**（[#8082](https://github.com/farion1231/cc-switch/issues/8082)）。これまで Desktop に公開するモデル名は `claude-opus-5` / `claude-sonnet-5` に固定されており、Desktop は 5 のパラメーターでリクエストを組み立てるため、5.5 のアップストリームが受け付けませんでした。生成された設定を手で直しても、次の書き込みで上書きされていました。現在はターゲットが 5.5 のとき 5.5 のモデル ID を公開します。マッピング表自体は変わらないので、古い設定から送られたリクエストも引き続き元のターゲットに向かいます。
- **Claude Code が Codex OAuth 経由で回数上限付きの WebSearch を使うと、すぐにエラーになっていた問題**（[#7936](https://github.com/farion1231/cc-switch/pull/7936)）。これまでは WebSearch の使用を強制した場合にしか通していませんでしたが、現在は強制しなくても使えます。回数の上限はプロンプトで指示し、上限を超えるとそのターンの応答を返す段階で打ち切ります。
- **Zhipu の従量課金アカウントのカードに「残量を取得できません」と表示されていた問題**（[#8465](https://github.com/farion1231/cc-switch/issues/8465)）。Zhipu のカードはデフォルトでプランの利用枠を照会するため、Coding Plan のないアカウントはエラー扱いになっていました。現在はプランがない場合にアカウントの残高を表示します（チームプランでは残高に切り替えません）。
- **新しく作成した火山 Agent / Coding Plan のカードで、最初から「残量を取得できません」と表示されていた問題**（[#8494](https://github.com/farion1231/cc-switch/issues/8494)）。火山のプランの利用枠は、推論に使う API Key ではなく、アカウントの AccessKey ID と SecretAccessKey で照会します。現在は使用量の照会設定で火山があらかじめ選ばれますが、AccessKey を入力するまで照会は有効になりません。ワンクリックインポートのリンクで有効化が明示されている場合は、これまでどおり有効にします。
- **Codex の公式カードのエディターで、`auth.json` に古いログインが表示されていた問題。** これまでは旧バージョンが保存したログインのスナップショットを表示していたため、Codex がトークンを更新すると `~/.codex/auth.json` と食い違っていました。現在のログインに従うカードでは空と表示されていました。現在は、管理アカウントに紐づいていない公式カードでは、このカードに切り替えた後の `auth.json` の内容を表示します。この欄に触れずに保存した場合、カードにもともと保存されていたログイン情報はそのまま変わりません。切り替え時に実際に書き込まれるファイルは、これまでも正しいものでした。
- **Windows で fnm で Node を管理していると、インストール済みの Codex などのツールを認識できなかった問題**（[#8484](https://github.com/farion1231/cc-switch/issues/8484)）。fnm は各ターミナルで一時的に PATH を追加するだけなので、CC Switch は node と npm を見つけられず、アプリ内でのインストールも「'npm' は、内部コマンドまたは外部コマンド、操作可能なプログラムまたはバッチ ファイルとして認識されていません」になっていました。現在は fnm のデフォルトの Node バージョンのディレクトリを PATH の末尾に追加し、既存の PATH が引き続き優先されます。
- **使われていないプロバイダーのカードを削除できず、「无法删除当前正在使用的供应商」（使用中のプロバイダーは削除できません）と表示されていた問題**（[#8506](https://github.com/farion1231/cc-switch/issues/8506)）。古い Claude Desktop のマッピングカードを持ったままアップグレードした後、データベースに残った古い「現在」のフラグがまだそのカードを指している場合によく起きていました。現在は実際に使っている直接接続のプロバイダーとルーティング先だけを見るようになり、画面上で削除を無効にする規則と一致します。
- **プロバイダーの編集時に「API Key を取得」リンクが表示されなかった問題。** 現在は編集時も現在のアドレスから対応するプリセットを探してそのリンクを表示し、追加時と同じになりました。
- **macOS / Linux で環境変数の競合が誤って報告されていた問題。** これまでは CC Switch が起動元のプログラムから引き継いだ環境変数も数えていました（たとえば Claude Desktop から開いたターミナルに最初から入っている `ANTHROPIC_BASE_URL`）。これらはアプリ内から削除することもできません。現在はシェルの設定ファイルにある定義だけをチェックします。Windows は変わりません。
- **MiniMax Code の一部の使用量レコードで、モデルが unknown と表示されていた問題。** 現在は同じセッション・同じ時刻の応答からモデル名を取り戻し、正しく料金を計算できます。すでにインポート済みのレコードはそのままです。
- **Hermes で MiniMax 公式プロバイダーを追加してもリクエストが送られなかった問題**（[#8538](https://github.com/farion1231/cc-switch/pull/8538)）。プロバイダーキーを `minimax` にすると Hermes 組み込みの MiniMax と名前が重なり、Hermes は組み込みの方を使って `MINIMAX_API_KEY` を求めていました。現在は MiniMax のプリセットに `cc-switch-minimax` / `cc-switch-minimax-en` があらかじめ入ります。すでに `minimax` で追加している場合は、別のキーで追加し直してください。MiniMax-M3.1-Flash も画像入力に対応と設定しました。
- **中国語と日本語で、使用量グラフの縦軸の幅が広すぎた問題。** 「5000万」「2000億」のような目盛りを「5千万」「2千億」のように書き換え、使用量ページとトレイパネルの縦軸は一番幅の広い目盛りに合わせて幅を自動で調整します。短い目盛りで余白が空くことも、長い金額が切れることもなくなりました。
- **macOS のアイコンの白い背景が明るすぎた問題**（[#8495](https://github.com/farion1231/cc-switch/issues/8495)）。4.0.15 の白い角丸の四角をライトグレーに変え、形は変わりません。Windows と Linux のアイコンは変わりません。
- **「情報」カードのロゴがぼやけていた問題**（[#8470](https://github.com/farion1231/cc-switch/issues/8470)）。ベクター画像を使うようにしました。

## アップグレードに関する注意

**データベースの構造は変わっていません。** バージョンは 20 のままです。

- アップグレード後、トレイアイコンをクリックするとクイックパネルが開きます。従来のメニューを使うには「設定 → 一般 → トレイの表示」で「メニュー」を選んでください（macOS、Windows）。Windows ではこれまでトレイアイコンの左クリックでメイン画面が開いていましたが、現在はパネルが開きます。メイン画面はパネル下部の「メインウィンドウを開く」から開けます。
- 保存済みの GPT モデルのウィンドウは移行しません。4.0.13 より前に保存され、自動で 1.05M が入力された Codex の GPT モデルは、この値が有効になります。フォームを開くと注意が表示されるので、実際には 272K しかない場合は手動で小さくしてください。
