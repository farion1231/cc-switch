# CC Switch v4.0.38

本版本以修复为主。一键导入链接现在可以导入 **WorkBuddy** 供应商；Linux 上也能在授权中心切换 **Antigravity** 账号；Antigravity 的会话列表不再混进空会话和内部子会话，会话阅读器能看到思考、工具调用和结果。

另外修复了 DeepSeek Harness 的配置文件经过某些 YAML 工具后，所有第三方供应商都消失；从访达打开 CC Switch 时，「应用」页把能正常用的 npm 安装标成「无法运行」；技能仓库不是 GitHub / GitLab / Gitea 时只提示「0 个技能」而不报错；Codex 给模型选的思考等级有时没生效；Codex 经路由的几处格式转换错误；用量重复计算；会话正文搜索失败时显示「没有会话包含这个词」；主界面变成一条白条或被 macOS 菜单栏遮住；Linux AppImage 里点链接没反应等问题。

---

## 新增

### WorkBuddy 支持一键导入链接

`ccswitch://` 供应商链接现在可以导入 WorkBuddy 供应商（[#9768](https://github.com/farion1231/cc-switch/pull/9768)），生成的卡片和在 WorkBuddy 页手动添加的一样。

- 链接必须带模型；`apiFormat` 只支持 `openai_chat`。
- 模型 ID 已被别的卡片占用时，导入会被拒绝，不会留下半截卡片。

### Linux 上切换 Antigravity 账号

Linux 上也能在授权中心管理 agy 的登录、切换账号，官方卡片上显示所绑定账号的额度（[#9774](https://github.com/farion1231/cc-switch/pull/9774)，相关 [#9245](https://github.com/farion1231/cc-switch/issues/9245)）。

- 登录凭据存在系统的钥匙串（Secret Service）里。钥匙串锁着时，后台查状态和额度会跳过，主动切号时会请求解锁。
- Linux 上绑了账号的卡片，「打开终端」对话框里多了「本次使用 agy 当前登录」：本机没有绑定的账号或钥匙串不可用时，可以先用当前登录打开终端，卡片的绑定保留不变。

## 变更

- **Antigravity 会话列表和会话阅读器**（[#9266](https://github.com/farion1231/cc-switch/pull/9266)，见 [#9265](https://github.com/farion1231/cc-switch/issues/9265)）：在终端里只查一下 `/usage` 就退出留下的空会话（显示为 `Jan 1`）、已删除或从别的设备同步来的残留记录、`/boost` 子代理和 `/btw` 旁路提问不再出现在列表里，它们的用量照常统计。没有标题的会话用预览或第一句提问当标题。会话阅读器能看到思考、正文、工具调用（含 MCP、浏览器等）和工具结果（含命令退出码、中断状态），文件改动显示增删行数。升级后会话正文索引会自动重建一次。
- **会话搜索和用量统计更快**（[#9823](https://github.com/farion1231/cc-switch/pull/9823)、[#9825](https://github.com/farion1231/cc-switch/pull/9825)）：会话页切换应用时不再为每个会话 ID 和路径重建搜索索引，内存占用也小得多；用量统计的查询能用上数据库索引，首字时间只读一遍，价格每次查询只加载一次。
- **授权中心里 Google 账号的套餐名去掉多余的「Google」**（[#9834](https://github.com/farion1231/cc-switch/pull/9834)）：Antigravity 和 Gemini CLI 账号的「Google AI Pro」现在显示为「AI Pro」。

## 修复

- **DeepSeek Harness 里所有第三方供应商突然消失**（见 [#9785](https://github.com/farion1231/cc-switch/issues/9785)）：`cordis.patch.yml` 经过某些 YAML 工具保存后，思考档位里的 `off` 会变成 `false`。CC Switch 以前会原样存下来、每次同步都写回去，DeepSeek Harness 因为这一个非法键把整段供应商配置都判为无效。现在读写时都会改正（`false` 改回 `off`，不认识的档位去掉）。
- **从访达打开 CC Switch 时，「应用」页把能正常用的 npm 安装标成「无法运行」**（见 [#9810](https://github.com/farion1231/cc-switch/issues/9810)）：检测安装时用的 PATH 里找不到 node，用 `npm --prefix`、volta、pnpm、bun 等方式装的命令行工具就会被判成无法运行，界面还会建议重装或卸载。现在检测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。Windows 不受影响。
- **添加不支持的站点（如 cnb.cool）上的技能仓库时，只提示「0 个技能」而不报错**（见 [#9812](https://github.com/farion1231/cc-switch/issues/9812)）：这类站点对任何地址都返回一个网页，以前下载到的网页被当成压缩包，失败了也没有提示。现在会提示「下载到的不是压缩包：这个站点可能不是 GitHub / GitLab / Gitea 仓库，暂不支持」。
- **Codex 给模型手动选的思考等级（如 `max`、`ultra`）有时没生效**（[#9017](https://github.com/farion1231/cc-switch/pull/9017)，见 [#8952](https://github.com/farion1231/cc-switch/issues/8952)）：模型名和 Codex 官方模型对得上时，生成的模型目录用的是官方的思考等级。现在按卡片里选的写入。
- **Codex 经路由转成 Chat 格式时，名字相近的工具会撞名**（[#9554](https://github.com/farion1231/cc-switch/pull/9554)，见 [#9551](https://github.com/farion1231/cc-switch/issues/9551)）：工具名或命名空间里自带 `__` 时，以前可能丢掉工具，或者把调用发给错的工具。现在每个工具都有唯一的名字，调用能准确对回去。
- **Codex 经路由用过第三方模型的对话，切到官方模型后无法继续**（[#9756](https://github.com/farion1231/cc-switch/pull/9756)，见 [#9054](https://github.com/farion1231/cc-switch/issues/9054)）：转换出来的消息 ID 以 `resp_` 开头，官方接口要求以 `msg_` 开头，直连模式下会报 `invalid_id_prefix`。新生成的 ID 改为 `msg_` 开头；已经存下的旧对话不变。
- **Codex 经路由连 AWS Bedrock 上的 Claude 时，每个请求都报 400**（[#8659](https://github.com/farion1231/cc-switch/pull/8659)，见 [#6118](https://github.com/farion1231/cc-switch/issues/6118)）：工具定义里多带了 OpenAI 专用的 `strict` 字段，Bedrock 不接受。现在不再转发这个字段。
- **用量重复计算**：
  - 模型名带网关前缀（如 `antigravity/gemini-3.8-flash-high`）时，同一个请求在路由记录和 Codex 会话日志里各算一次（[#9249](https://github.com/farion1231/cc-switch/pull/9249)）。现在去掉前缀再比对。
  - Gemini 旧会话文件更新后，已经归档的用量又被导入一次；会话里的 token 数变了却没有更新（[#9527](https://github.com/farion1231/cc-switch/pull/9527)，见 [#9523](https://github.com/farion1231/cc-switch/issues/9523)）。
- **用量统计里 Codex 的缓存写入显示 N/A**（[#8191](https://github.com/farion1231/cc-switch/pull/8191)）：现在显示实际数值，只有 Gemini 和 Grok Build 仍显示 N/A（它们不上报缓存写入）。请求日志也不再把 Codex 的缓存写入算进新输入。
- **Antigravity 的输出速度显示为估算值，偏低**（[#9788](https://github.com/farion1231/cc-switch/pull/9788)，见 [#9787](https://github.com/farion1231/cc-switch/issues/9787)）：Antigravity 自己记录了首字时间和流式输出时长，以前没用上，速度按总耗时（含首字前的等待）估算。现在和经路由的请求一样按实际输出时长计算。
- **会话正文搜索出错时，显示「没有会话包含这个词」**（[#9512](https://github.com/farion1231/cc-switch/pull/9512)，见 [#9511](https://github.com/farion1231/cc-switch/issues/9511)）：现在会提示「正文搜索失败，暂时只能按标题、目录和首末消息查找」，可以点「重试」，重试时会把会话重新收录进索引。
- **OpenCode 会话的两个边界问题**（[#7982](https://github.com/farion1231/cc-switch/pull/7982)）：迁移到新格式后又在 OpenCode 1.x 里继续的会话，以前显示的是旧内容；新格式迁移中途中断时，没迁完的会话不再被隐藏。
- **Oh My Pi 的恢复会话命令在 Windows 上粘贴到 PowerShell 会报错**（[#9153](https://github.com/farion1231/cc-switch/pull/9153)，见 [#9152](https://github.com/farion1231/cc-switch/issues/9152)）：Windows 上现在生成 PowerShell 写法，macOS 和 Linux 不变。
- **Linux AppImage 里点链接在浏览器中打开、或打开文件夹，没有任何反应**（[#9113](https://github.com/farion1231/cc-switch/pull/9113)，见 [#9112](https://github.com/farion1231/cc-switch/issues/9112)）：AppImage 自带的旧版 xdg-open 在 KDE Plasma 6 下什么都不做。现在改用系统自己的 xdg-open。deb / rpm、macOS 和 Windows 不受影响。
- **macOS 上把全屏的主界面关到托盘，再打开时被菜单栏和 Dock 遮住**（[#9770](https://github.com/farion1231/cc-switch/pull/9770)，见 [#9769](https://github.com/farion1231/cc-switch/issues/9769)）：现在关到托盘前先退出全屏，从托盘、Dock 等再打开时恢复全屏。
- **主界面打开后只是一条白条**（[#9504](https://github.com/farion1231/cc-switch/pull/9504)，见 [#9496](https://github.com/farion1231/cc-switch/issues/9496)）：记住的窗口尺寸异常小时，打开时恢复成默认大小。
- **编辑供应商时，关掉还在保存的编辑器再打开，「保存」按钮一直转圈**（[#9593](https://github.com/farion1231/cc-switch/pull/9593)，见 [#9592](https://github.com/farion1231/cc-switch/issues/9592)）。
- **Copilot 旧版登录迁移遇到网络超时就放弃，要重启才会再试**（[#9549](https://github.com/farion1231/cc-switch/pull/9549)，见 [#9544](https://github.com/farion1231/cc-switch/issues/9544)）：现在网络恢复后，下次用到 Copilot 时会继续迁移，不用重启；只有令牌失效（401 / 403）或退出登录才放弃。
- **中转站地址被误认成官方厂商**（[#9648](https://github.com/farion1231/cc-switch/pull/9648)）：地址的路径或参数里出现官方域名，或者域名长得像（如 `api.x.ai.example.com`）时，以前会被当成那家厂商：xAI 走专门的处理，余额和套餐额度也按那家的官方模板查。现在只看真正的域名。
- **导入配置、云同步下载等操作中，累加式应用有供应商没写进配置文件，却提示成功**（[#9747](https://github.com/farion1231/cc-switch/pull/9747)）：现在会列出写入失败的供应商。
- **移动技能存储位置后，有应用没能重新链接，却提示成功**（[#9748](https://github.com/farion1231/cc-switch/pull/9748)）：现在会在提示里列出来。
