# CC Switch v4.0.18

今回のリリースでは、Antigravity CLI（agy）に対応しました。CC Switch が管理する 11 番目のアプリです。agy には公式ログインのカードとサードパーティの API キーのカードを追加できます。**注意：Antigravity のプロバイダーは、CC Switch のカードの「このプロバイダーでターミナルを開く」から起動した agy でのみ有効です**。ほかのターミナルで直接 `agy` を実行した場合は使われません。MCP、Skills、プロンプトは agy に同期され、セッションは閲覧と再開ができ、使用量はセッションログから取り込みます。「アプリ」ページで agy のインストール、アップグレード、アンインストールもできます。macOS では、「アカウント」ページで複数の Antigravity アカウントも管理でき、agy のログインをワンクリックで切り替え、アカウントごとの利用枠を確認し、公式カードを特定のアカウントに紐付けられます。また、Windows のアプリ内更新で、ファイルが使用中のためにパソコンが再起動されることはなくなり、MSI のインストール時にデスクトップショートカットを作らないことも選べるようになりました。ページ上部では、実際の接続をアプリ名の横に小さなバッジで表示するようになりました。このほか、macOS で同時リクエストが多いとファイルハンドルを使い切ってルーティングが失敗する、Finder から起動したときに「Codex デーモンを再起動」が `env: node` を報告する、Claude Code のセッションで `/cd` でディレクトリを変えても元のプロジェクトに分類されたままになる、Windows でターミナルを開いた後、そのターミナルウィンドウを閉じるまで読み込み中のままになる、Codex の未使用の利用枠にカウントダウンが表示される、DeepSeek V4.1 Flash に料金が設定されていない、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### Antigravity CLI（agy）

Google の Antigravity CLI（コマンドは `agy`）が独立したアプリになりました。プロバイダー、MCP、Skills、プロンプト、セッション、使用量をそれぞれ持ち、Gemini CLI とは別に管理します（[#8268](https://github.com/farion1231/cc-switch/pull/8268)、[#2959](https://github.com/farion1231/cc-switch/issues/2959)）。

> **⚠️ Antigravity のプロバイダーは、CC Switch からターミナルで起動したときにだけ有効です。** ほかのアプリと違い、CC Switch は agy 自身の設定ファイルを変更しないため、Antigravity のカードには「切り替え」も「使用中」もありません。使いたいカードの「このプロバイダーでターミナルを開く」を押すと、開いたターミナルで実行した agy だけがそのプロバイダーを使います。ほかのターミナルで直接 `agy` を実行した場合は、agy 自身の Google ログインと設定のままです。（macOS の「アカウント」ページでのアカウント切り替えは例外で、agy 全体のログインを変更します。次の節を参照してください。）

- **2 種類のプロバイダーカード。** 公式ログインのカードは agy 自身の Google ログインを使い、ターミナルを開くときにカードで選んだモデルで agy を起動します。このモデルはそのセッションにだけ適用されます。サードパーティのカードには Gemini API 互換のエンドポイントとキーを入力します。エンドポイントを空欄にすると Google の標準 API を使います。キーとエンドポイントはこのターミナルの agy にだけ渡され、agy の設定やシェルの起動ファイルには書き込まれません（起動に使う一時ファイルは自動で削除されます）。モデル一覧は agy 内蔵のモデルカタログから取得し、agy が認識できる表示名が入ります。
- **MCP、Skills、プロンプト。** `~/.gemini/config` に同期します。これは agy のグローバルなカスタマイズ用ディレクトリで、同じパソコンの Antigravity IDE と共有されることがあります。サードパーティのカードで起動した agy でも、これらの MCP、Skills、プロンプトを使えます。
- **セッション。** agy と Antigravity IDE のセッションを閲覧できます。表示するのは入力した内容だけで、agy が自動で付け加えたコンテキストは表示しません。サードパーティのカードで起動したセッションも見つけられ、同じカードで再開できます。
- **使用量。** セッションログから取り込みます（Antigravity IDE のセッションを含む）。ターンごとに選ばれたモデルで記録し、費用は料金表の該当モデルの API 価格で見積もります。
- **公式の利用枠。** 公式カードで利用枠の照会を有効にすると、Gemini と Claude/GPT の 2 グループの利用枠を表示します。各グループには 5 時間と週の 2 つの枠があります。カードには各グループで残りの少ないほうの枠だけを表示し、ドロップダウンを開くと 4 つの枠すべてとそれぞれのリセット時刻を確認できます。
- **「アプリ」ページで agy を管理。** 公式のインストールスクリプトでインストールし、`agy update` でアップグレードします（Homebrew でインストールした場合も同じです）。アンインストールもできます。
- ディープリンクで agy のプロバイダー、MCP、プロンプトもインポートできます。

### 「アカウント」ページで複数の Antigravity アカウントを管理（macOS）

agy は同時に 1 つのアカウントにしかログインできません。「アカウント」ページに Antigravity のグループを追加しました。「Google でログイン」または「アカウントを追加」を押すとブラウザーでアカウントを追加でき、agy ですでにログインしているアカウントも自動で取り込まれます。

- **切り替え。** アカウントのメニューで「agy をこのアカウントに切り替え」を選ぶと、以降に起動する agy はすべてこのアカウントを使います。元のログインのアカウントは先に「アカウント」ページに取り込まれるため、切り替えても失われません。agy が実行中のときは通知が出ます。すでに開いている agy は元のアカウントのままで、元のアカウントを書き戻すこともあるため、先に終了することをおすすめします。
- **アカウントごとの利用枠。** 各行にそれぞれの利用枠を表示するので、切り替えなくても確認できます。利用枠の照会は利用枠を読み取るだけで、モデルは呼び出しません。Antigravity を使えないアカウント（年齢制限があるものなど）には、わかりにくい 403 ではなく、Google が示した理由を表示します。
- **公式カードをアカウントに紐付け。** 公式カードのフォームでアカウントを 1 つ選べます。ターミナルを開く前に agy のログインをそのアカウントに切り替え、すでにそのアカウントなら書き込みません。カードに表示する利用枠もこのアカウントのものです。選ばない場合は agy の現在のログインに従います。カードを別のパソコンに同期した場合は、そのパソコンでもこのアカウントを追加しないと使えません。追加していなければターミナルを開くときに通知が出て、別のアカウントで起動することはありません。
- **アカウントを削除しても agy はログアウトしません。** CC Switch は自分が保存したコピーだけを削除します。

## 改善

**Windows のアプリ内更新でパソコンが再起動されなくなりました**（[#8628](https://github.com/farion1231/cc-switch/pull/8628)、[#8534](https://github.com/farion1231/cc-switch/issues/8534)）。アプリ内更新はダイアログを出さない方式で MSI インストーラーを実行するため、これまではインストール先のファイルが 1 つでも使用中だと、Windows Installer が確認なしにパソコンを再起動していました。現在はインストーラー自体が再起動を禁止しており、旧バージョンからこのバージョンに更新するときにも有効です。

**MSI のインストール時にデスクトップショートカットを作らないことを選べるように**（[#8601](https://github.com/farion1231/cc-switch/pull/8601)、[#5667](https://github.com/farion1231/cc-switch/issues/5667)）。インストール先のページに「Create a desktop shortcut」オプションを追加しました。既定でオンです。サイレントインストールでは `CREATEDESKTOPSHORTCUT=0` を付けるとスキップできます。アップグレード時は現在の状態を保ち、削除したショートカットが再び作られることはありません。デスクトップのフォルダーに書き込めないときも、インストールが失敗しなくなりました。

**ページ上部に実際の接続を表示**（[#8634](https://github.com/farion1231/cc-switch/pull/8634)）。実際の接続先の表示をモードのタブの横からアプリ名の横に移し、現在のモード（直接接続、ルーティング、集約）の色の小さなバッジで示します。別のモードのタブを見ているときも常に表示され、名前が長いときは省略され、ポインターを重ねると全体を確認できます。

**画面の説明文を簡潔に**（[#8633](https://github.com/farion1231/cc-switch/pull/8633)）。プロバイダーのフォーム、OpenClaw、デイリーメモリー、同期、整流器の設定で、隣のラベルや見出しと重複する説明を削除し、補足の説明は既存のヘルプカードに移しました。結果に影響する注意（費用、再起動、同期、削除など）はこれまでどおり表示します。

**使用量ページのアプリの絞り込みには、「アプリ」ページで表示しているアプリだけを並べるように。** セッション管理と同じく、Claude Desktop を表示しているときは Claude Code も残し、現在選んでいるアプリは非表示にしても消えません。

**プリセット：** DIT.ai、hao.ai を追加しました。

## 修正

- **macOS で同時リクエストが多いとルーティングが失敗する問題**（[#8668](https://github.com/farion1231/cc-switch/issues/8668)）。Finder やログイン項目から起動したアプリは、同時に開けるファイル数が 256 個しかありません。ルーティングでは処理中のリクエストごとにクライアント側の接続とアップストリーム側の接続を 1 つずつ使うため、同時リクエストが多いと上限に達し、新しいリクエストを受け付けられず、アップストリームにも接続できず、設定ファイルやデータベースさえ開けなくなっていました。現在は起動時にこの上限をシステムが許す値（最大 10240）まで引き上げます。Linux でも同じように処理します。
- **Finder から起動したとき、「Codex デーモンを再起動」が `env: node: No such file or directory` を報告する問題**（[#8653](https://github.com/farion1231/cc-switch/issues/8653)）。Finder から起動すると CC Switch の PATH にはシステムのディレクトリしかなく、npm でインストールした codex は node で動くため、node が別のディレクトリにあると見つかりませんでした。現在はこの種のコマンドを実行するとき、ツールのインストールやアップグレードと同じく、先にログインシェルの PATH を加えます。OpenCode のモデル一覧の取得も同じ問題の影響を受けていたため、あわせて修正しました。
- **Claude Code のセッションで `/cd` を使ってディレクトリを変えても、セッション管理で元のプロジェクトに分類されたままになる問題**（[#8643](https://github.com/farion1231/cc-switch/pull/8643)、[#6862](https://github.com/farion1231/cc-switch/issues/6862)）。コピーした再開コマンドも先に元のディレクトリへ `cd` するため、そこで `claude --resume` を実行してもこのセッションが見つかりませんでした。現在は Claude Code 自身のルールと同じく、最後に移動したディレクトリで分類します。worktree に出入りした場合も同じです。
- **Windows でターミナルを開いた後、そのターミナルウィンドウを閉じるまでボタンが読み込み中のままになる問題**（[#6712](https://github.com/farion1231/cc-switch/issues/6712)）。現在はターミナルが開いた時点で待機を終えます。
- **Codex で使っていない利用枠にもリセットまでのカウントダウンが表示される問題**（[#8631](https://github.com/farion1231/cc-switch/pull/8631)）。使用量が 0 の枠について Codex が返すリセット時刻は「現在時刻に枠の長さを足したもの」のため、更新するたびにカウントダウンが枠の長さ全体に戻っていました（5 時間枠なら 5 時間）。現在は使用量が 0 の枠にはリセット時刻を表示しません。
- **DeepSeek V4.1 Flash のリクエストが「価格未設定」と表示され、0 として計算される問題。** OpenCode Go、OpenRouter、Hermes のプリセットはモデル名 `deepseek-v4.1-flash` を使っていますが、これまで料金表にありませんでした。現在は DeepSeek Flash の公式価格で計算します。記録済みのリクエストは再計算しません。
- **マニュアルの「公式の利用枠を使い切ると Codex が送信ボタンをロックする」問題の回避方法が使えなくなっていたため、訂正しました**（[#7962](https://github.com/farion1231/cc-switch/issues/7962)）。4.0.16 から集約モードでは ChatGPT のログインを保持するため、サードパーティを集約のデフォルトプロバイダーにしても回避できなくなりました。現在の方法は次のとおりです：直接接続に切り替え、「設定 → アプリ設定 → Codex」の「直接切替時に公式ログインを保持」がオフになっていることを確認し、サードパーティのプロバイダーに切り替えてから Codex を完全に再起動します。利用枠がリセットされたら集約に戻します。

## アップグレードに関する注意

**データベースのバージョンが 20 から 21 に上がります。** MCP と Skills に Antigravity のスイッチを追加するためです。アップグレード前にデータベースは自動でバックアップされます。アップグレード後に旧バージョンに戻すと、旧バージョンはデータベースのバージョンが新しすぎると表示し、開けません。

- Antigravity のプロバイダーは、カードの「このプロバイダーでターミナルを開く」から起動した agy でのみ有効で、ほかのターミナルで直接 `agy` を実行した場合は使われません。
- Antigravity はデフォルトで「アプリ」ページに表示されます。使わない場合はそこで非表示にできます。
- 「アカウント」ページでの Antigravity アカウントの管理は、現在 macOS のみ対応しています。ほかのプラットフォームではアカウントの選択は表示されず、公式カードは agy 自身のログインに従います。Mac から同期された紐付けは無視されます。
