# CC Switch v4.0.37

本版本以修复为主。读不出来的供应商和 MCP 条目（比如由更新版本写入、经 WebDAV / S3 同步过来的）不再被当成空配置、下次保存时被默认值覆盖，而是单独列出来，可以删除；Pi 新增 **Mistral AI** 预设；韩语界面翻译整体改进。

另外修复了本地路由监听地址填 IPv6 时启动不了；「应用到 Claude Code 插件」会把损坏的 `~/.claude/config.json` 整个清空；网速慢时大的技能仓库下载到一半被中断；从访达打开 CC Switch 时 Codex 模型目录探测找不到 Node；工具调用参数里 `_` 开头的字段被删掉后才发给上游；移出又加回故障转移队列的供应商仍被跳过；插件页点「重试」看起来没反应等问题。

---

## 新增

### Pi 新增 Mistral AI 预设

Pi 新增 Mistral AI 预设，走 Pi 自己的 Mistral 协议（`mistral-conversations`），流式的思考内容不会丢（需求见 [#9343](https://github.com/farion1231/cc-switch/issues/9343)，[#9344](https://github.com/farion1231/cc-switch/pull/9344)）。

- 自带 Mistral Large 4 和 Mistral Small 4，思考档位与 Pi 内置的 Mistral 目录一致。
- 供应商名为 `cc-switch-mistral`，不会遮住 Pi 内置的 `mistral`。
- Pi 表单的协议列表里也可以选 `mistral-conversations`。Oh My Pi 和 Kimi Code 不支持这个协议，不显示这个预设。

## 变更

- **读不出来的供应商和 MCP 条目原样保留，可以单独删除**（[#9767](https://github.com/farion1231/cc-switch/pull/9767)）：以前数据读不出来时会被当成空配置，下次保存就把默认值写回去，原来的数据丢了。现在这样的条目在供应商页和 MCP 页单独列出，显示读不出来的原因，不能编辑或启用，可以删除（只删 CC Switch 里的记录，不动各应用的配置文件）；其他条目照常显示和使用，故障转移跳过它；改这一条的操作会被拒绝，有这样的条目时，累加式应用（如 OpenCode）把全部供应商同步到配置文件也会报错。升级到能读的版本后即可恢复。
- **Claude Code 的 1M 标记改写成小写 `[1m]`**（见 [#9757](https://github.com/farion1231/cc-switch/issues/9757)）：和 Claude Code 文档写法一致。Claude Code 本来不区分大小写，已有的 `[1M]` 照常可用。
- **韩语界面翻译改进**（[#9395](https://github.com/farion1231/cc-switch/pull/9395)，[#9349](https://github.com/farion1231/cc-switch/pull/9349)）。
- **授权中心的账号行更好读**（[#9369](https://github.com/farion1231/cc-switch/pull/9369)）：「N 个供应商在用」单独一行，额度名称列按最长的名称定宽，窗口窄时套餐、域名和登录日期不再被挤成省略号；德语、俄语等较长的翻译也能看到百分比。

## 修复

- **本地路由的监听地址填 IPv6（如 `::1`）时启动不了**（见 [#9743](https://github.com/farion1231/cc-switch/issues/9743)）：以前会报「invalid socket address syntax」，现在可以正常监听。
- **开了「应用到 Claude Code 插件」后，损坏的 `~/.claude/config.json` 会被清空**（见 [#9744](https://github.com/farion1231/cc-switch/issues/9744)）：文件不是合法 JSON 时，以前当成空文件重写，里面的其他设置都丢了。现在会报错并指出文件路径，文件原样不动；写入也改成先写临时文件再替换，中途中断不会留下半截文件。
- **网速慢时，大的技能仓库下载到一半被中断**：安装、更新、检查更新和发现技能以前都限制整个下载 60 秒。现在只有连续 60 秒收不到数据才中止，并提示「没有收到数据」；整个下载最长 10 分钟。
- **从访达打开 CC Switch 时，Codex 模型目录探测找不到 Node**（见 [#9764](https://github.com/farion1231/cc-switch/issues/9764)）：用 npm 装的 Codex 因此运行失败，CC Switch 退回用 Codex 桌面版自带、可能较旧的 CLI，聚合模式下的 GPT 模型少了官方信息（比如搜索工具）。现在探测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。
- **工具调用参数里 `_` 开头的字段被删掉后才发给上游**（[#9753](https://github.com/farion1231/cc-switch/pull/9753)）：MCP、数据库、GraphQL 类工具常用 `_id`、`_meta`、`__typename` 这类字段，以前会被当成私有字段删掉，模型看到的调用和实际执行的不一样，严格的供应商可能直接拒绝请求。现在工具调用参数原样保留。
- **从故障转移队列移出再加回的供应商，卡片显示正常但仍会被跳过一段时间**（[#9750](https://github.com/farion1231/cc-switch/pull/9750)）：移出队列或退出某个应用的路由时，现在会同时清掉运行中的熔断状态。开启 OMO / OMO Slim 时没能删掉另一个变体的配置文件，现在也会单独提示。
- **插件页加载超时后点「重试」看起来没反应**（见 [#9758](https://github.com/farion1231/cc-switch/issues/9758)）：已安装、发现和市场三个页签在重试时都会显示加载中。
- **插件页的几处问题**（[#9742](https://github.com/farion1231/cc-switch/pull/9742)）：切到别的应用再切回来，进行中的操作仍显示转圈；Codex 更新插件期间又把它启用，更新结束后不会再被停用；搜索也能按显示名搜到（Pi 通过 git 或本地目录安装的包）；卸掉固定版本的 Pi 包、再从「发现」安装后，它不再留在「发现」里；Windows 上装在 WSL 里的插件现在能显示版本、名称和描述。
- **内存和资源占用**（[#9773](https://github.com/farion1231/cc-switch/pull/9773)）：离开会话阅读器时释放缓存的图片；关闭自动更新时释放已下载的安装包；部分网络请求复用 HTTP 连接，不再每次新建；本地路由收到的请求体（含解压后）上限为 200 MiB，超过返回 413。
- **安装或升级命令行工具后，紧接着的操作偶尔提示「正在进行中」**（[#9775](https://github.com/farion1231/cc-switch/pull/9775)）。
