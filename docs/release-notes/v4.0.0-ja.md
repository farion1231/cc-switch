# CC Switch v4.0

### 新しい画面、新しい集約モード、より安全な設定切り替え

CC Switch 史上最大規模のアップデートです。今回は、モデルへの接続方法、プロバイダーの切り替え方、そして増え続ける AI コーディングツールの管理方法という、CC Switch の最も核となる体験を見直しました。

サイドバーからトレイまで画面をすべて作り直し、アプリ、設定、使用量、セッションのそれぞれにわかりやすい居場所を用意しました。新しい集約モードでは、複数のプロバイダーのモデルを Claude Code や Codex の 1 つのモデル一覧にまとめ、クライアントの中でそのまま切り替えられます。セッション管理もゼロから書き直し、AI が各ターンで何をしたか、何を変更したか、どのステップで失敗したかがひと目でわかるようになりました。さらに設定書き込みの土台も作り直しました。プロバイダーの切り替えはファイル全体の書き直しから重要項目だけの置き換えに変わり、複雑さを大きく減らすと同時に、設定が失われる一連の問題を解消しています。

## 新しい画面

新しい画面はサイドバーレイアウトとオレンジのテーマを採用しています。アプリの切り替えに加え、MCP、Skills、プロンプト、セッション、アカウント、使用量といった共通機能にも、サイドバーから直接移動できます。

<p align="center"><img src="https://raw.githubusercontent.com/farion1231/cc-switch/main/assets/release-notes/v4.0.0/main-en.png" alt="新しい画面：サイドバー、モードタブ、プロバイダーカード" width="720"></p>

- **モードがひと目でわかる**：各アプリページの上部に「直接接続 / ルーティング / 集約」の 3 つのタブがあります。タブを押しても表示が切り替わるだけで、設定は変わりません。実際にモードを切り替えるボタンには何が起きるかが書かれており、直接接続へはワンステップで戻れて、元に戻すこともできます
- **ツールの居場所ができました**：新しい「アプリ」ページで、各 AI コーディングツールのバージョン、インストール場所、入手元をまとめて確認でき、インストール、アップグレード、一括アップグレードもここから行えます
- **すっきりしたプロバイダー追加パネル**：検索してプリセットを選び、フォームに入力するだけです。検索は中国語名やドメインにも対応し、同じ事業者のプランや地域違いは 1 行にまとめられるため、Claude の 96 個のプリセットは 73 行に収まりました。プリセットプロバイダーのおすすめ強調表示もすべて廃止しました
- **残量で表示する利用枠**：カードには「5時間 残り 94%」「残高 8.99 CNY」のように表示され、各枠の後ろにはリセットまでの残り時間（例：「⏱ 2h30m」）も表示されます。普段は控えめなグレーで、割合の枠は 10% を切ると太字になり、残高は使い切ったときにだけ赤くなります。利用枠をクリックすると再取得し、その結果も表示します。Codex のサブスクリプションでは、残りのリセット回数と有効期限も表示されます
- **アプリごとに整理したトレイ**：各行に「名前 · モード · プロバイダー · 利用枠」を表示し、サブメニューには今切り替えられるプロバイダーだけを並べます。トレイアイコンのドットは、本当に対応が必要なときだけ表示されます
- **用途別の設定**：一般、アプリ設定、ローカルルーティング、ネットワーク、データ、情報に分類しました。ローカルルーティングのサービス状態、待ち受けアドレス、フェイルオーバー設定も 1 か所にまとまっています

既存ユーザーには、初回起動時に主な機能の移動先を説明する短い案内が表示されます。

## 集約：複数のプロバイダーを 1 つのモデル一覧で

これまでは別のプロバイダーのモデルを使いたいとき、CC Switch に戻ってプロバイダーを切り替え、それからクライアントに戻る必要がありました。

**集約**モードをオンにしてプロバイダーをいくつか追加すると、それぞれのモデルが Claude Code や Codex のモデル選択画面にまとめて表示されます。選んだモデルに応じてリクエストがそのプロバイダーへ直接送られるので、クライアントから離れる必要はありません。

<p align="center"><img src="https://raw.githubusercontent.com/farion1231/cc-switch/main/assets/release-notes/v4.0.0/agg-codex-en.png" alt="Codex のモデル選択画面に複数プロバイダーのモデルが並ぶ様子" width="560"></p>

- **いつでも追加・削除**：プロバイダーカードの「追加」「削除」を押すだけです。さらに 1 社をデフォルトプロバイダーに選ぶと、集約モデルを指定していないリクエストはそこへ送られます
- **モデルをひと目で見分けられる**：モデル名の後ろには提供元のプロバイダーが付き（例：「Kimi K3（Kimi For Coding）」）、説明には上流の実際のモデル ID とコンテキストウィンドウ（例：`kimi-k3 · 256K`）が表示されます
- **シンプルな設定フォーム**：接続情報とモデル一覧を 1 ページにまとめ、集約に必要な項目だけを入力できます
- **Codex で混在させてもエラーにならない**：公式アカウントをデフォルトにすると、公式モデルとサードパーティのモデルが並んで表示されます。異なるプロバイダーのモデルを行き来しても、コンテキスト圧縮や推論の状態が引き継がれます
- **同じセッション内でモデルを変更**：セッションの途中で別のモデルに切り替えられます。ただし切り替えるたびに新しいモデルでプロンプトキャッシュを作り直すため、切り替え直後の 1 ターン目は料金が明らかに高くなります
- **再起動のお知らせ**：モデル一覧が変わるとクライアントの再起動を促します。Codex CLI はバナーからワンクリックでバックグラウンドサービスを再起動できます

<p align="center"><img src="https://raw.githubusercontent.com/farion1231/cc-switch/main/assets/release-notes/v4.0.0/agg-en.png" alt="集約モード：デフォルトプロバイダー 1 社と、追加済みの 6 社" width="720"></p>

集約は手動でオンにする機能で、現在は Claude Code と Codex に対応しています。選んだモデルごとにリクエストを振り分ける仕組みのため、フェイルオーバーはありません。

| モード | リクエストの流れ | 向いている使い方 |
|------|-----------|--------|
| **直接接続** | クライアントがプロバイダーに直接接続 | 普段の利用 |
| **ルーティング** | ローカルルーティング経由で 1 社に転送。プロトコル変換やフェイルオーバーが可能 | プロトコルが合わないとき、フェイルオーバーが必要なとき |
| **集約** | ローカルルーティング経由で、モデルごとに複数社へ振り分け | 1 つのセッションで複数社のモデルを使い分けたいとき |

> **opencodex への敬意**
>
> 集約モードは [opencodex](https://github.com/lidge-jun/opencodex) から多くを学び、参考にしています。モデル ID にプロバイダーの接頭辞を付けて、複数社のモデルを Claude Code や Codex の選択画面に同時に並べること。サードパーティのモデルでも Codex がコンテキスト圧縮を行えるようにすること。バックグラウンドサービスが古いモデル一覧を使い続けていないか検知して再起動を促すこと。これらの発想はすべて opencodex の探求から生まれたものです。この成果をオープンソースとして公開してくださった opencodex の作者（[@lidge-jun](https://github.com/lidge-jun)）とコントリビューターの皆さんに感謝するとともに、そのオープンソース精神に心からの敬意を表します！
>
> 「あらゆるモデルを Codex と Claude Code で使う」ことに特化したツールをお探しなら、opencodex をぜひお試しください！

## セッション管理：AI コーディングのすべてをはっきりと

AI コーディングツールは各セッションの記録をローカルに丸ごと保存していますが、元の記録は何千行もの JSON で、そのまま読むのはほぼ不可能です。今回のバージョンではセッション管理をゼロから書き直し、記録をできる限り読みやすくしたうえで、トークン使用量と料金の集計も加えました。

<p align="center"><img src="https://raw.githubusercontent.com/farion1231/cc-switch/main/assets/release-notes/v4.0.0/session-en.png" alt="セッションビューア：実行過程の要約、ツール呼び出しの詳細、会話の目次" width="720"></p>

- **9 つのクライアントを同じ読み方で**：Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi、MiniMax Code の記録を構造化して解析し、本文、思考、ツール呼び出し、ツール結果、画像をそれぞれの形で表示します
- **1 ターンの作業を 1 行に要約**：AI の長い一連の操作を「実行過程 · 44 ステップ · コマンド 27 件 · 2 ファイルを変更 · 1 件失敗 · 27m45s」のように 1 行にまとめます。失敗したコマンドは赤で表示され、展開すると引数、出力、終了コードを確認できます。ファイルの読み込みや検索が続く部分は「N ファイルを参照、N 回検索」にまとめられます
- **会話の目次**：右側にあなたの各プロンプトと、そのターンのステップ数や結論を一覧表示します。失敗したステップがあるターンには赤いドットが付き、クリックするとその場所へ移動します
- **3 つの表示**：「すべて」で全過程を、「会話」であなたと AI のやり取りだけを、「変更」で変更されたファイルだけを表示します
- **セッションの全体像をひと目で**：上部にプロジェクトのディレクトリ、開始・終了時刻、プロンプト数、ツール呼び出し数、モデル、合計トークン数、API 価格で計算した料金を表示します
- **セッション内検索**：一致した内容が折りたたまれたツール出力の中にあっても、自動で展開して表示します。長いセッションでも入力がもたつきません
- **読んだらそのまま作業再開**：よく使うターミナル（Ghostty など）でワンクリックでセッションを再開でき、再開コマンドのコピーもできます。Markdown へのエクスポートや、1 ターン単位・会話全体のコピーにも対応しています
- **見つけやすい一覧**：プロジェクト別・時間別にグループ化し、タイトル、ディレクトリ、最初と最後のメッセージ、セッション ID で検索できます。一括削除にも対応しています
- OpenCode 2.x のセッションに対応し、Hermes のセッションも正しく開けるようになりました

セッションビューアの刷新は [@Owlbay](https://github.com/Owlbay) が中心となって進めてくれました。Owlbay の多大な尽力に感謝します。

## プロバイダーを切り替えても、設定はそのまま

今回のアップデートで最も重要な内部の変更です。対象は Claude Code、Codex、Gemini CLI、Grok Build、Claude Desktop です。

CC Switch を公開した 2025 年 8 月当時、API のエコシステムは今ほど成熟しておらず、公式とサードパーティのプロバイダーの間で API の形式が大きく異なることも珍しくありませんでした。そのため当初の設計では、切り替えのたびに設定ファイル全体を上書きする方式を選びました。しかしこの選択は、一連の問題と複雑さを生むことになりました。エコシステムが成熟した今こそ、作り直すときです。

**これまで**：プロバイダーを切り替えると、そのプロバイダーに保存されたスナップショットで設定ファイル全体を書き直していました。`settings.json` に追加した hooks、プラグイン、権限設定や、`config.toml` に追加した MCP サーバーは、切り替え時に失われるか、特定のプロバイダーのスナップショットに取り込まれ、別のプロバイダーに切り替えると消えてしまっていました。

**これから**：切り替えで置き換えるのは、エンドポイント、認証情報、モデル、プロトコルと、そのプロバイダー独自のスイッチだけです。それ以外はすべてそのまま残ります：

- TOML と `.env` ファイルでは、変更しない行はコメントや順序も含めて 1 バイトも変わりません
- JSON ファイルでは、ほかのすべてのキーの値と順序が保たれます
- 共有設定はもともと設定ファイルに残るため、「共通設定スニペット」機能は不要になりました

**エディターの下部に、切り替え後の設定ファイルのプレビューが表示されます**。ここで編集した全体設定は設定ファイルに書き込まれ、保存前にはほかのプログラムがファイルを変更していないかも確認します。

新しい書き込みの仕組みは、いくつもの保護も備えています：

- 設定ファイルの形式に誤りがある場合は書き込みを中止し、元のファイルには手を付けません
- 書き込み前に外部での変更を確認し、ほかのプログラムが保存したばかりの内容を上書きしません
- 複数のファイルを同時に変更するときは、先に操作内容を記録します。途中で予期せず終了しても、次回起動時に自動で後始末をするため、中途半端な状態で止まることはありません
- 新バージョンが各ファイルに初めて書き込む前に、元の状態のバックアップを取ります
- キーを含む設定ファイルは、本人だけが読み書きできるようにしています

ルーティングのオン・オフも、設定全体の「バックアップと復元」に頼らなくなりました。Codex をサードパーティのプロバイダーに切り替えたときに上書きされる ChatGPT のログイン情報はローカルに一時保存され、公式アカウントに戻すと自動で復元されます。

## 使用量

**使用量ページ**では、指標、トレンドグラフ、リクエストログ、そしてプロバイダー、モデル、料金の各統計表を作り直し、すべてページ送りに対応しました。新しい「すべて」の期間では、53 週分のヒートマップで日ごとの使用量を表示します。広い範囲の集計でも、ウィンドウが固まらなくなりました。

<p align="center"><img src="https://raw.githubusercontent.com/farion1231/cc-switch/main/assets/release-notes/v4.0.0/usage-en.png" alt="使用量：53 週ヒートマップとリクエストログ" width="720"></p>

**出力速度**は、最初のトークンまでの待ち時間を除いた生成時間だけで計算するようになりました。ルーティングを使っていなくても、Claude Code や Codex のセッションログから取り込んだリクエストには推定速度が「≈」付きで表示されます。

## その他の改善

- **MCP**：複数のサーバー設定をまとめて貼り付けられ、JSON、TOML、Codex、OpenCode の形式を認識します。あるアプリへの書き込みに失敗してもそのアプリだけ再試行でき、1 つのサーバーのエラーがほかのサーバーに影響しなくなりました
- **Skills**：「インストール済み」と「見つける」を 1 ページに統合し、ワンクリックで一括更新できます。同期方法は自動、シンボリックリンクのみ、コピーのみから選べます
- **プロンプト**：8 つのアプリのプロンプトを 1 ページで管理でき、ほかのアプリへのコピー、既存ファイルの取り込み、削除の取り消しに対応しました
- **アカウント**：アカウント、再ログインの入口、利用枠の残量がひと目でわかります
- **モデル情報の自動補完**：取得したモデルを選ぶと、プリセットと models.dev からコンテキストウィンドウ、出力上限、推論レベル、入力の種類を補完します。入力済みの値は上書きしません
- **Claude Desktop**：モデルマッピングを使うと、ローカルルーティングのサービスが自動で起動し、不要になると自動で停止します
- **OpenCode**：同期しても `opencode.jsonc` のコメントや書式が保たれ、OpenCode 2.x の使用量にも対応しました
- **MiniMax Code**：「アプリ」ページからインストールとアップグレードができ、新しいプロバイダーを作るときにプロバイダーキーを自分で指定できます
- **プリセットと料金**：Command Code のプリセットを追加し、Claude Opus 5.5、GPT-6 Sol / Luna、MiMo V2.6 などの料金を更新しました。756 個のプリセットすべてに正式なアイコンが付きました

## 修正

- macOS で `⌘Q`、Dock の「終了」、ログアウトで終了したあと、クライアントが停止済みのローカルルーティングを向いたままになる問題
- Codex 公式ルートの応答がなかなか表示されず、使用量が 0 と記録される問題
- Codex のモデルカタログで、GPT モデルの公式プロンプト、ツール機能、推論レベルが失われる問題
- MiniMax のツール呼び出しで引数の解析に失敗する問題と、一部モデルの思考内容が本文に混ざって表示される問題
- Codex 0.158 以降、MCP 設定の `type` フィールドが原因でエラーになり、起動すらできなくなる問題
- プロンプトを追加・取り込みしたときに、手書きのプロンプトファイルが空になることがある問題
- Skills の同期で、OpenClaw のディレクトリ内にある同名フォルダーを誤って削除する問題
- 一部の CLI をアップグレードすると、npm のコピーが余分にインストールされる問題
- 古いログを整理してもデータベースファイルが小さくならない問題
- 設定の「保存してサービスを再起動」で、実際にはサービスが再起動されない問題

## アップグレードの前に

**設定の置き場所が変わりました。** 共有設定はクライアントの設定ファイルにそのまま残り、「共通設定スニペット」機能は廃止されました。クライアント内で一時的に選んだモデルや推論強度は、別のプロバイダーに切り替えて戻すと、プロバイダーに設定された値に戻ります。固定したい場合は、プロバイダーエディターで保存してください。

**一部の修正は、一度切り替えると反映されます。** Codex のモデルカタログとセッション履歴の分類に関する修正は、CC Switch が次に Codex の設定を書き込んだときに適用されます。アップグレード後にプロバイダーを一度切り替えてください。既存の MCP 設定は一度同期し直すと、古い `type` フィールドが削除されます。

**切り替え後は案内に従って再起動してください。** Codex、Gemini CLI、Grok Build はモデルを切り替えたあとに再起動が必要です。集約の一覧を変更したあとも、クライアントの再起動が必要です。

**既存のカードはそのままです。** プリセットの更新は新しく作成するプロバイダーにのみ適用されます。新しい料金で補完されるのは、これまで $0 で記録されていたリクエストだけで、それ以外の過去の料金は再計算されません。

**2 つの設定を廃止しました。** プロバイダーのコスト倍率（中継サービスの価格にはすでに倍率が含まれているため、さらに掛けると計算がずれます）と、接続チェックの詳細設定（現在は組み込みの既定値を使用します）です。
