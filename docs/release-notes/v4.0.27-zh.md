# CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 `pi.exe` 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

## 新增

### 搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（[#7896](https://github.com/farion1231/cc-switch/pull/7896)、[#7420](https://github.com/farion1231/cc-switch/issues/7420)）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

- 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
- 索引是单独的本地文件 `session-index.db`，不参与云同步，也不进备份；关闭这个开关会删除它。

### 界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（[#9209](https://github.com/farion1231/cc-switch/pull/9209)）：

- **界面密度**：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
- **界面缩放**：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 `+`、`-` 调整，按 Ctrl/⌘ 加 `0` 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

### 模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（[#9205](https://github.com/farion1231/cc-switch/pull/9205)）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

### Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（[#9234](https://github.com/farion1231/cc-switch/pull/9234)）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 `--always-approve`。

## 变更

- **Skills 已安装页重新排版**（[#9210](https://github.com/farion1231/cc-switch/pull/9210)）：
  - 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
  - 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
  - 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
  - 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
- **供应商图标跟随主题**（[#8438](https://github.com/farion1231/cc-switch/pull/8438)）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
- **右键不再弹出浏览器菜单**（[#8919](https://github.com/farion1231/cc-switch/pull/8919)、[#8921](https://github.com/farion1231/cc-switch/issues/8921)）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
- **熔断日志写明是哪家供应商**（[#9292](https://github.com/farion1231/cc-switch/issues/9292)）：熔断器的日志（`CB-001` 到 `CB-006`）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 `FWD-004`，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
- **预设：** Mistral AI 预设的默认模型改为 `mistral-large-4`（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（[#9269](https://github.com/farion1231/cc-switch/pull/9269)）、TokenPlus（[#9296](https://github.com/farion1231/cc-switch/pull/9296)）。已添加的供应商不受影响。

## 修复

- **配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错**（[#6764](https://github.com/farion1231/cc-switch/issues/6764)、[#9283](https://github.com/farion1231/cc-switch/issues/9283)）。用 dotfiles 工具或同步文件夹管理 `~/.claude/settings.json`、`~/.codex/config.toml`、`opencode.json` 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
- **请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启**（[#7206](https://github.com/farion1231/cc-switch/issues/7206)、[#9292](https://github.com/farion1231/cc-switch/issues/9292)）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
- **Codex 设置了自定义权限后，用 plan 模式报错**（[#7349](https://github.com/farion1231/cc-switch/pull/7349)、[#7294](https://github.com/farion1231/cc-switch/issues/7294)）。较新的 Codex 读取自定义权限时要求 `model_catalog_json` 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 `AbsolutePathBuf deserialized without a base path`。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
- **运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录**（[#7780](https://github.com/farion1231/cc-switch/pull/7780)、[#7772](https://github.com/farion1231/cc-switch/issues/7772)）。Python 运行时生成的 `__pycache__` 和 `.pyc` 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
- **Skills 仓库显示「识别到 0 个技能」**（[#9273](https://github.com/farion1231/cc-switch/issues/9273)）。导入时添加的仓库分支记为 `HEAD`，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
- **Windows 上把 Python 包里的 `pi.exe` 当成 Pi**（[#9267](https://github.com/farion1231/cc-switch/issues/9267)）。PyPI 上有一个无关的 `pi` 包会装出 `Scripts\pi.exe`，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python `Scripts` 目录里的 `pi.exe` 不再被识别为 Pi。
- **模型价格同步失败，只提示 `error decoding response body`**（[#9262](https://github.com/farion1231/cc-switch/issues/9262)）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
- **添加 DeepSeek Harness 供应商时只提示 `Invalid DeepSeek Harness profile YAML`，不知道是哪个文件**（[#9297](https://github.com/farion1231/cc-switch/issues/9297)）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
- **连通性测试把会重定向的中转站判为不通**（[#9253](https://github.com/farion1231/cc-switch/pull/9253)、[#5747](https://github.com/farion1231/cc-switch/issues/5747)）。有的网关在 `/v1` 和 `/v1/` 之间互相重定向，现在测试收到重定向就算连得上。
- **打开对话框时窗口拖不动**（[#9140](https://github.com/farion1231/cc-switch/pull/9140)）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
- **Linux 快捷面板显示异常**：轻量模式下重新打开的面板和窗口渲染出错（[#9233](https://github.com/farion1231/cc-switch/pull/9233)、[#9216](https://github.com/farion1231/cc-switch/issues/9216)），设置了显示缩放时面板被裁掉一部分（[#9287](https://github.com/farion1231/cc-switch/pull/9287)、[#8556](https://github.com/farion1231/cc-switch/issues/8556)）。Linux 上的面板改为不透明背景。
- **供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白**（[#8139](https://github.com/farion1231/cc-switch/pull/8139)）。
- **一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址**（[#8127](https://github.com/farion1231/cc-switch/pull/8127)）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
