# CC Switch v4.0.24

This release adds an "Open the browser when signing in" switch to Accounts; with it off, signing in to an account only copies the sign-in link and you choose which browser to open it in, which suits people who keep each account in its own browser environment. Fixes cover the max thinking level being lowered to xhigh when Claude Code or Claude Desktop used GPT 6.1 Sol / Terra through routing, DeepSeek Harness showing no third-party providers after a model with PDF input was picked, CC Switch exiting right after launch on WSL, and the thinking level of Codex Chat providers no longer being sent after "Supports Reasoning Effort" was turned on again. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

---

## New

### Signing in to an account can just copy the link

Before, signing in to an account in Accounts always opened the sign-in page in the system default browser. If you use a tool such as AdsPower to give each account its own browser environment, the sign-in landed in the wrong browser.

Now Accounts has an "Open the browser when signing in" switch at the top. It applies to Claude, ChatGPT, Copilot, xAI, Antigravity, Kimi and DeepSeek account sign-ins, including sign-ins started from the add-provider form. With it off:

- Clicking sign in only copies the sign-in link to the clipboard; open it in the browser you want, sign in and approve, and CC Switch updates automatically.
- Sign-ins that need a code to be entered no longer copy the code automatically, so the link on the clipboard is not replaced.
- While waiting for the sign-in, you can click "Copy sign-in link" to copy it again; the button that opens the sign-in page is not shown.

On Windows, Claude Code opens the browser itself; with the switch off, CC Switch makes it only print the sign-in link.

The switch is on by default, and it is remembered only on this computer and not synced through the cloud.

**Presets:** A6API moves to the new domain a6api.vip.

## Fixes

- **When Claude Code or Claude Desktop went through routing to an OpenAI-format upstream with the model gpt-6.1-sol or gpt-6.1-terra, the max thinking level was lowered to xhigh before being sent** ([#9122](https://github.com/farion1231/cc-switch/issues/9122)). Now models of GPT 5.6 and later, with no suffix or with the sol, terra, luna or astra suffix, all keep max; other suffixes such as pro, codex and mini are still sent as xhigh.
- **After DeepSeek Harness picked a model with PDF input from the fetched model list, no third-party providers were shown** ([#9116](https://github.com/farion1231/cc-switch/issues/9116)). DeepSeek Harness accepts only text and image as model input types, and a single PDF written in made the whole configuration entry invalid. Now only text and image are written.
- **On WSL, CC Switch exited right after launch, reporting "Permission denied" for the tray icons** ([#9021](https://github.com/farion1231/cc-switch/pull/9021), [#9020](https://github.com/farion1231/cc-switch/issues/9020)). Linux tray icons are now stored in the app's cache directory.
- **After "Supports Reasoning Effort" was turned off and on again for a Codex Chat provider, the chosen thinking level was no longer sent to the upstream** ([#8998](https://github.com/farion1231/cc-switch/pull/8998), [#8954](https://github.com/farion1231/cc-switch/issues/8954)). Upstreams such as GitHub Copilot therefore did not receive any thinking level. Providers saved earlier work again too, without being edited.
- **The "DeepSeek official sign-in" card of DeepSeek Harness said "Sign in with a Claude account"** ([#9058](https://github.com/farion1231/cc-switch/pull/9058)). It now says "Sign in with a DeepSeek account".
