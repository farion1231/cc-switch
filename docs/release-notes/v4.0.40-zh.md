# CC Switch v4.0.40

本版本让 **Grok Build 的官方卡可以绑定授权中心里的 xAI 账号**，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。**插件页**支持 Antigravity CLI；**用量统计**的供应商和模型列表加了缓存命中率；**小米 MiMo** 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

## 新增

### Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（[#9321](https://github.com/farion1231/cc-switch/pull/9321)，关闭 [#8599](https://github.com/farion1231/cc-switch/issues/8599)），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

- 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
- 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 `~/.grok/auth.json`，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
- 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
- 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
- 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

### Antigravity CLI 插件

「插件」页支持 Antigravity CLI（[#9882](https://github.com/farion1231/cc-switch/pull/9882)、[#9885](https://github.com/farion1231/cc-switch/pull/9885)），和其他应用一样调用 `agy` 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

- 更新前先比对市场上的版本号，已是最新就不重装。
- 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
- 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

### 用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

### 小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 [#9404](https://github.com/farion1231/cc-switch/issues/9404)），不用再靠抓控制台 Cookie 的用量脚本：

- Token Plan（`tp-` 开头的 Key）：显示已用和总额度，以及本期结束时间。
- 余额（`sk-` 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

### 授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

### 新增预设

新增 StringAI。

## 变更

- **数据库与本地路由更快**（[#9820](https://github.com/farion1231/cc-switch/pull/9820)、[#9821](https://github.com/farion1231/cc-switch/pull/9821)）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
- **用量同步更快**（[#9817](https://github.com/farion1231/cc-switch/pull/9817)、[#9818](https://github.com/farion1231/cc-switch/pull/9818)）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
- **会话内容搜索更快**（[#9827](https://github.com/farion1231/cc-switch/pull/9827)、[#9896](https://github.com/farion1231/cc-switch/pull/9896)）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
- **「应用」页打开更快**（[#9418](https://github.com/farion1231/cc-switch/pull/9418)、[#9886](https://github.com/farion1231/cc-switch/pull/9886)，关闭 [#9884](https://github.com/farion1231/cc-switch/issues/9884)）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

## 安全

- **深链接导入 MCP**（[#9831](https://github.com/farion1231/cc-switch/pull/9831)）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
- **用量脚本**（[#9829](https://github.com/farion1231/cc-switch/pull/9829)）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
- **SQL 导入**（[#9832](https://github.com/farion1231/cc-switch/pull/9832)）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
- **非本机监听地址的 Host 检查**（[#9833](https://github.com/farion1231/cc-switch/pull/9833)）：路由服务监听 `0.0.0.0` / `::` 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

## 修复

- **Kimi Code Desktop 主 agent 的用量没统计**（[#9505](https://github.com/farion1231/cc-switch/pull/9505)，见 [#9498](https://github.com/farion1231/cc-switch/issues/9498)）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 `unknown`。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
- **Antigravity 输出速度虚高**（[#9858](https://github.com/farion1231/cc-switch/pull/9858)）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
- **T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到**（[#9857](https://github.com/farion1231/cc-switch/pull/9857)，见 [#9838](https://github.com/farion1231/cc-switch/issues/9838)）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
- **Mistral 官方 API 开思考后回复为空**（见 [#9902](https://github.com/farion1231/cc-switch/issues/9902)）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
- **Kimi 原生 Responses 在并行看图后一直报 400**（[#8825](https://github.com/farion1231/cc-switch/pull/8825)，见 [#7504](https://github.com/farion1231/cc-switch/issues/7504)）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
- **WorkBuddy 企业账号积分显示为已用完**（见 [#9694](https://github.com/farion1231/cc-switch/issues/9694)）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
- **托盘里看不到 xAI 额度**（见 [#9899](https://github.com/farion1231/cc-switch/issues/9899)）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
- **托盘里官方账号显示成网站域名**（[#9863](https://github.com/farion1231/cc-switch/pull/9863)）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
- **Skills 页的「发现」里出现重复的技能**：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
- **OpenCode Desktop 自带的 CLI 被提示用 npm 升级**（[#9099](https://github.com/farion1231/cc-switch/pull/9099)）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
- **快到 64 MiB 上限的流式事件被误跳过**（[#9867](https://github.com/farion1231/cc-switch/pull/9867)）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

## 升级说明

- 路由服务监听 `0.0.0.0` / `::`、又在本机用自定义主机名（不以 `.local`、`.internal`、`.localhost` 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
- 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
