# CC Switch v4.0.42

This release lets **GitHub Copilot** providers use Copilot's **Auto model selection**: pick "GitHub Copilot Auto" in the model list of Claude, Codex or Claude Desktop, and Copilot decides which model to use for each conversation; Copilot Free accounts can use it too.

This release also fixes an issue introduced in 4.0.41: provider cards in every app showed "In use by agy", and their subtitle was replaced with the Antigravity account email. In addition, when you switch accounts on an Antigravity official card, a failed first readback from the system keychain no longer revokes the account binding that has already been switched.

---

## New

### GitHub Copilot Auto model selection

([#9564](https://github.com/farion1231/cc-switch/pull/9564), see [#8197](https://github.com/farion1231/cc-switch/issues/8197))

Copilot changed how Auto is accessed upstream, and the earlier approach of omitting the model name no longer works. CC Switch now first asks Copilot's `/auto` which model to use this time, then sends the request to that model with the session token Copilot returned.

- **How to use**: click "Fetch Models" in the Copilot provider form; when the account supports Auto, the list gains a "GitHub Copilot Auto" entry (model ID `copilot-fusion-auto`), and you just pick it. It can be picked in Claude Code, Codex and Claude Desktop; in Claude Desktop you can fill it in for just one tier and fill the other tiers with specific models as usual.
- **Copilot Free works too**: the model catalog of Free accounts doesn't mark the Auto capability, so CC Switch asks `/auto` once on the account's behalf (only to pick a model, no conversation is sent), and shows the Auto option if a model can be picked.
- **The same conversation sticks to the same model where possible**: the model Copilot picked keeps being used while its authorization is valid. After more than 30 minutes idle, when the authorization expires, when the account changes, or after a successful context compaction, CC Switch asks again, and a different model may be picked then.
- **When no model can be picked**: when Copilot refuses, or the picked model can't be used with the current protocol, the request returns an error, and with failover turned on it moves to the next provider. Requests that pick a fixed model work as before.

Local routing must be turned on. See [GitHub Copilot Auto](../user-manual/en/2-providers/2.1-add.md#github-copilot-auto) in the user manual for details.

## Fixes

- **Every provider card showed "In use by agy"** ([#9975](https://github.com/farion1231/cc-switch/pull/9975), closes [#9981](https://github.com/farion1231/cc-switch/issues/9981)): in 4.0.41, after the Antigravity page or the Accounts page had been opened, cards in other apps and Antigravity's relay cards also showed the green "In use by agy" badge, and their subtitle was replaced with the Antigravity account email. Now only Antigravity official cards show the account.
- **An Antigravity official card's binding was revoked after switching accounts** ([#9979](https://github.com/farion1231/cc-switch/pull/9979)): the system keychain sometimes accepted the new sign-in but returned an error on the first readback, and CC Switch then revoked the card's account binding even though agy had actually switched to the new account. Now it reads once more; if it still can't read the sign-in, it tells you that the sign-in has been written and asks you to check which account is currently signed in on the Accounts page before trying again.
