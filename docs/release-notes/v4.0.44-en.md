# CC Switch v4.0.44

This release adds support for ZCode (Zhipu's coding client): you can manage its providers and model limits, MCP, Skills and prompts, view its sessions and import its usage. Antigravity accounts are now handled entirely by agy itself: adding an account opens a terminal where you sign in inside agy, and quota is queried with agy's `/usage`; CC Switch no longer signs in, refreshes tokens or queries quota on agy's behalf. Claude Desktop gains a Command Code preset.

Fixes include: tool calls being rejected when Codex calls Gemini through a Chat Completions relay, saved accounts being overwritten when the account file couldn't be read, the stashed ChatGPT login being lost when clearing leftover third-party Keys, deleting a conflicting environment variable removing every line with the same name, image, video and other non-chat models showing up in fetched model lists, skills.sh failing to install skills stored only under `.claude/skills`, the tray panel showing a scrollbar too early, the Accounts page having no xAI card when only Grok Build is shown, no size limit on a single event when local routing converts streaming responses, and several error messages and hints.

## New

### ZCode support

([#9824](https://github.com/farion1231/cc-switch/pull/9824), following up on [#8076](https://github.com/farion1231/cc-switch/pull/8076) and [#5644](https://github.com/farion1231/cc-switch/pull/5644))

ZCode is the 18th managed app. Like OpenCode and Hermes, it can have several providers added at the same time.

- **Providers**: written to the personal provider layer of `~/.zcode/v2/provider_config.json`; providers you added yourself in ZCode and accounts you signed in to there are neither imported nor changed by CC Switch. ZCode is a desktop app, so after saving you still need to switch to the provider in ZCode's provider picker for it to take effect.
- **Models**: click "Fetch Models" to pull them from the provider, or type model IDs by hand. When a model's context and output limits are left empty, ZCode's recommended values are used; limits you fill in are written and removed together with the provider. ZCode has no model display name, so the form doesn't offer one.
- **MCP, Skills, prompts**: MCP is written to `~/.zcode/cli/config.json`; the prompt file is `AGENTS.md`. ZCode's config directory can be changed in Settings.
- **Sessions and usage**: read from ZCode's `~/.zcode/cli/db/db.sqlite`. Sessions can't be deleted in CC Switch (history and usage both live in ZCode's own database); you are told to delete them in ZCode instead.
- **Deep links**: both provider and MCP links accept `zcode`; provider links must include a model.

ZCode cards using the GLM Coding Plan show the plan quota automatically. The Apps page doesn't install or upgrade ZCode; it updates itself.

### Command Code preset for Claude Desktop

(see [#10045](https://github.com/farion1231/cc-switch/issues/10045))

It matches the Claude Code Command Code preset: requests are forwarded in OpenAI Chat format through local routing, and all three model tiers use `deepseek/deepseek-v4.1-flash` (1M context).

### Presets

Added TeleAI (Xing4.1-Preview) and FastAIToken.

## Changes

### Antigravity accounts no longer use agy's sign-in client

Google recently made it clear that third-party tools may not use Antigravity's built-in OAuth client, which is exactly what CC Switch used to do: it signed in and refreshed tokens with agy's built-in client ID, and queried quota from Google directly as agy. These requests are now gone, and CC Switch no longer sends any request of its own for Antigravity accounts.

- **Add account**: opens a terminal running `agy`; in agy, run `/logout` and then `/login`, and the Accounts page picks up the new login once it appears. The account that was already signed in is collected first, so logging out in agy doesn't lose it.
- **Quota**: queried only with agy's own `/usage`, so only the account agy is currently signed in with can be queried. Other accounts show the last quota fetched before switching away.
- **Plan**: `/usage` doesn't return the plan, so the Accounts page no longer shows the Antigravity plan line.
- **Token refresh** is left to agy. Saved accounts can still be switched as before.

The quota query concurrency and request amplification fixed in [#10004](https://github.com/farion1231/cc-switch/pull/10004), and the black window flashing on Windows during quota queries fixed in [#10047](https://github.com/farion1231/cc-switch/pull/10047), were both in the code removed this time; with `/usage`, neither problem can occur any more.

## Fixes

- **Codex calling Gemini through a Chat Completions relay got a 400 on every tool-calling turn** (see [#9168](https://github.com/farion1231/cc-switch/issues/9168), [#10032](https://github.com/farion1231/cc-switch/issues/10032)): Codex's tool definitions contain two shapes Gemini doesn't accept: the `"encrypted": true` marker on multi-agent tool parameters, and non-string enums such as `{"type": "boolean", "enum": [true]}`. The `encrypted` marker is now always dropped when converting to Chat format; non-string enums are rewritten only when sending to Gemini models, and other models are not affected by this.
- **Saved accounts were overwritten when the account file couldn't be read** ([#10020](https://github.com/farion1231/cc-switch/pull/10020)): when the WorkBuddy, Antigravity, CodeBuddy or Claude account file was corrupted or unreadable, it used to be treated as an empty table, and the next save overwrote every account. The original file is now renamed in place with an `.unreadable-` suffix and a timestamp, and CC Switch then starts from an empty table.
- **Codex lost the stashed ChatGPT login when clearing leftover third-party Keys** ([#10027](https://github.com/farion1231/cc-switch/pull/10027)): when a third-party Key was left as `OPENAI_API_KEY` in `auth.json`, clearing it was treated as you signing out, the stashed ChatGPT login was invalidated, and switching back to the official card no longer signed you in.
- **Deleting a conflicting environment variable removed every line with the same name** ([#10025](https://github.com/farion1231/cc-switch/pull/10025)): only the listed line is deleted now; if the file changed after the scan and that line no longer sets the variable, the deletion is refused.
- **Fetched model lists included image, video, embedding and rerank models** (see [#10026](https://github.com/farion1231/cc-switch/issues/10026)): relays such as new-api list Nano Banana, Seedream, Seedance and the like in their model lists; after "Select all" they were written into the Codex model catalog, and picking one as the chat model made every message fail. These models are now dropped based on the endpoint type the relay tags them with; models without a tag are kept as before.
- **skills.sh couldn't install skills stored only under `.claude/skills`** (see [#10040](https://github.com/farion1231/cc-switch/issues/10040)): this used to report "Skill directory not found"; now, when no visible directory is found, directories starting with `.` are searched as well.
- **The tray panel showed a scrollbar too early** (see [#10034](https://github.com/farion1231/cc-switch/issues/10034)): every app carries quota bars, so five apps already exceeded the old 620 px cap and the last one was pushed into the scroll area. The cap is now 760 px, and the panel still scrolls when there isn't enough room on screen.
- **The Accounts page had no xAI card when only Grok Build was shown** ([#10030](https://github.com/farion1231/cc-switch/pull/10030), closes [#10029](https://github.com/farion1231/cc-switch/issues/10029)): the descriptions of the xAI and GitHub Copilot cards now also mention Grok Build, Codex and Copilot CLI.
- **Single events had no size limit when local routing converted streaming responses** ([#9938](https://github.com/farion1231/cc-switch/pull/9938), closes [#9937](https://github.com/farion1231/cc-switch/issues/9937)): when the upstream never sent a delimiter, memory kept growing. A single event is now capped at 64 MiB; beyond that, an error is reported and the response ends.
- **The plugin "Marketplaces" tab was empty when the CLI output couldn't be read** ([#10024](https://github.com/farion1231/cc-switch/pull/10024)): it now shows that reading failed.
- **Messages about a Skill that can't be overwritten always said Pi** ([#10044](https://github.com/farion1231/cc-switch/pull/10044)): when updating or uninstalling a Skill is refused in apps such as Oh My Pi or MiniMax Code, the message now names the current app.
