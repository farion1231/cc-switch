# CC Switch v4.0.41

This release adds support for **CodeBuddy** (Tencent's CLI and desktop app share one set of configuration): you can manage custom models, MCP, Skills, prompts, sessions and usage, collect several official accounts on the Accounts page, see each account's plan, credits and expiry date, and switch between them at any time. **Copilot CLI** providers can be synced to VS Code's Copilot extension with one toggle; **Grok official cards** show the subscription tier.

This release also makes Claude native forwarding reuse upstream connections, loads less code when the main window and the tray panel start, explains why background requests and provider connectivity checks fail, and hardens the security checks for database file permissions, backup file names, the CONNECT proxy and deep links. Fixes also cover Codex routed to Opus / Sonnet 5.5 reporting "requires adaptive thinking" after tool calls; Gemini Native returning 400 with long tool call histories; failover results from old requests overriding a manually chosen route; the account bound to Antigravity cards getting out of sync with the Accounts page; usage from Codex forked sessions never being counted; Pi plugins being handled as pnpm; Hermes showing two installations on Windows; an extra Dock icon after updating on macOS; and more.

## New

### CodeBuddy

Added CodeBuddy ([#8758](https://github.com/farion1231/cc-switch/pull/8758)). CodeBuddy's desktop app and CLI read the same set of configuration files, so the UI simply calls it CodeBuddy. Like Kimi Code and WorkBuddy, it is additive: several models can be added at the same time.

- **Custom models**: each card is one model in `~/.codebuddy/models.json`, and the card ID is the model name sent upstream, so it can't be changed after saving and there is no "Duplicate". You can fetch the model list from the URL, and picking a model fills in its token limits and capabilities automatically. Other models in the file and fields you added yourself are kept; files with comments or trailing commas are not rewritten; the model set as default in `settings.json` can't be removed. Added DeepSeek, Xiaomi MiMo and LongCat presets.
- **MCP, Skills, prompts**: MCP is written into the one user-level file CodeBuddy actually reads, keeping your own servers; servers enabled in CC Switch are taken off CodeBuddy's disabled list. Skills sync to `~/.codebuddy/skills`, and skills not installed by CC Switch are not deleted. Prompts are written into `CODEBUDDY.md`.
- **Sessions and usage**: the session list shows CodeBuddy sessions and can resume them in a terminal (they can't be deleted from CC Switch); usage statistics import usage from main sessions and subagents, with subagent usage counted toward the session it belongs to.
- **Official accounts**: the Accounts page can collect the CodeBuddy account currently signed in, or sign in to a new account in a terminal; when CodeBuddy is already signed in, you are asked to confirm before it shows the sign-in screen, and cancelling the sign-in restores the original account. The new "CodeBuddy Official Sign-in" card is bound to an account, and clicking "Add" switches to that account; you can also switch from the "…" menu of an account on the Accounts page. Account rows and cards show the plan, credits for the current period and the expiry date. Account copies are kept only on this machine and are not synced.
- **Apps page**: you can install, update and uninstall CodeBuddy CLI.

### Copilot CLI synced to the VS Code Copilot extension

Turn on "Apply to VS Code Copilot extension" under "Settings → App config → Copilot CLI" ([#9435](https://github.com/farion1231/cc-switch/pull/9435), closes [#9433](https://github.com/farion1231/cc-switch/issues/9433)), and the providers and models added in Copilot CLI are written into the VS Code Copilot extension's model configuration, so each side can pick them from its own model list.

- The default and named Profiles of both VS Code stable and Insiders are found automatically and all synced; after that, they update automatically when you add, edit or remove Copilot CLI providers in CC Switch.
- Only the group CC Switch writes is changed, and other settings and comments are kept; a backup is left next to the file before the first change. Turning the toggle off deletes that group.
- When syncing fails, the save on the Copilot CLI side still takes effect, and the message explains why and offers "Retry".
- A few configurations, such as WebSocket and Azure deployments with `apiVersion`, are not supported yet; you are told why when you run into them.

### Grok official cards show the subscription tier

Official cards in Grok Build show the subscription tier after the account, for example `SuperGrok Heavy` ([#9923](https://github.com/farion1231/cc-switch/pull/9923)). Cards bound to an xAI account can also "Configure usage query" and set an auto-refresh interval; turning the usage query off hides the subscription tier too.

## Changes

- **Claude native forwarding reuses upstream connections** ([#9914](https://github.com/farion1231/cc-switch/pull/9914), closes [#9913](https://github.com/farion1231/cc-switch/issues/9913)): when local routing forwards Claude requests as is, it no longer opens a new connection to the upstream every time; both direct connections and connections through a proxy are reused. When a reused old connection fails, the request is resent on a new connection automatically; through a proxy, a new connection is used only if no data has been received yet.
- **Lighter startup** ([#9918](https://github.com/farion1231/cc-switch/pull/9918), [#9920](https://github.com/farion1231/cc-switch/pull/9920)): only the UI language in use is loaded now; the tray panel's "Usage" tab loads only when you switch to it, background refreshing stops while the panel is collapsed, and the code loaded when the tray panel starts drops from about 3.5 MB to about 0.5 MB. The backend allocates less memory when computing usage medians, and network clients that aren't needed are no longer created up front.
- **Network failures explain why** (see [#9911](https://github.com/farion1231/cc-switch/issues/9911)): when a background request at startup fails, you are told once which request it was: the update check states that it reaches dl.ccswitch.io / github.com, and models.dev sync explains that it fetches prices to calculate usage costs; the message lets you choose "Don't show again" or turn off auto sync directly. When a provider connectivity check fails, it now tells apart being blocked by a firewall, no service on the port, a timeout, DNS errors and TLS errors, and gives matching suggestions.
- **Narrower collapsed sidebar** ([#9941](https://github.com/farion1231/cc-switch/pull/9941)): the collapsed sidebar and the highlight of the selected item are narrower, a little wider in "Comfortable" density than in "Compact"; icon sizes are unchanged.

## Security

- **Database, backups, proxy and deep links** ([#9835](https://github.com/farion1231/cc-switch/pull/9835)): on macOS / Linux, exported SQL files and `cc-switch.db` can be read and written only by the current user. Restoring, renaming and deleting backups accept only a single `.db` file name. When connecting upstream through an HTTP proxy (CONNECT), an escaped username and password in the proxy address are decoded before being sent (fixing 407 with special characters), and the size of the response headers returned by the proxy is limited. The risk check for deep link imports flags more exploitable environment variables, as well as commands that run code directly, such as `node -e` and `python -c`.

## Fixes

- **Codex routed to Opus / Sonnet 5.5 returned 400 after tool calls** (see [#9943](https://github.com/farion1231/cc-switch/issues/9943)): when Codex used Opus 5.5 or Sonnet 5.5 over the Anthropic API through local routing, every turn after a tool call reported "requires adaptive thinking". These two models don't allow thinking to be turned off, so adaptive thinking is now sent in this case; a Codex reasoning effort of `none` is sent as `low`. Requests for other models are unchanged.
- **Gemini Native returned 400 with long tool call histories** ([#9009](https://github.com/farion1231/cc-switch/pull/9009)): after more than 64 turns, signatures of earlier tool calls were lost and could be matched to other calls, so Gemini rejected the request. Signatures are now cached separately for longer and matched exactly by call ID; when a signature really can't be recovered, the compatibility marker from Google's documentation is used only for Gemini 3 and later.
- **Failover results from old requests overrode a manually chosen route** ([#9946](https://github.com/farion1231/cc-switch/pull/9946), closes [#9944](https://github.com/farion1231/cc-switch/issues/9944)): after you switch the route manually or turn off automatic failover, old requests still in progress no longer switch the route back to a backup provider, and are no longer shown as the provider in use.
- **The account bound to Antigravity cards was out of sync with the Accounts page** ([#9945](https://github.com/farion1231/cc-switch/pull/9945)): when you bind or change the account on an Antigravity official card and save, agy's sign-in is switched through the Accounts page, and nothing is saved if the switch fails; the card, the account picker and the Accounts page show the same current account. Duplicating a card doesn't switch accounts.
- **Usage from Codex forked sessions was never counted** ([#9638](https://github.com/farion1231/cc-switch/pull/9638), closes [#9637](https://github.com/farion1231/cc-switch/issues/9637)): for old-format Codex sessions forked from an idle session, usage is imported once the copied history is confirmed to belong to the parent session; sessions that can't be determined are still held back.
- **Global proxy settings only half took effect** ([#9930](https://github.com/farion1231/cc-switch/pull/9930)): when the global proxy was saved twice in a row, some requests could use the proxy settings from the other save. The proxy address and network client are now replaced together in one step.
- **Pi plugins were handled as pnpm** ([#9964](https://github.com/farion1231/cc-switch/pull/9964), see [#9960](https://github.com/farion1231/cc-switch/issues/9960)): when the `pi` found on the system was actually pnpm, the Plugins page showed 0 plugins, and clicking install in "Discover" even installed npm packages into `~/.pi/agent`. Now an error is reported directly when Pi's output isn't recognized. Tool path detection is also corrected: tools installed through shortcuts such as pnpm, mise and volta are no longer misidentified, paths printed by terminal startup scripts are no longer taken as tool locations, and pnpm's global install directory is searched on macOS / Linux too.
- **Hermes showed two installations on Windows** (see [#9931](https://github.com/farion1231/cc-switch/issues/9931)): `hermes.cmd` and `hermes.exe` in the same folder now show as one installation, counted as the one Windows actually runs.
- **An extra Dock icon appeared after updating on macOS** ([#9910](https://github.com/farion1231/cc-switch/pull/9910), closes [#8329](https://github.com/farion1231/cc-switch/issues/8329)): when restarting after an in-app update or a config directory change, the new process now waits for the old one to exit completely before starting, reusing the icon pinned in the Dock.
- **SQL import reported success even when syncing afterwards failed** ([#9541](https://github.com/farion1231/cc-switch/pull/9541), closes [#9536](https://github.com/farion1231/cc-switch/issues/9536)): when syncing prompts, prices and settings after an import fails, the matching warning is shown.
- **Scripts in Skills couldn't be run after cloud sync** ([#9539](https://github.com/farion1231/cc-switch/pull/9539), closes [#9534](https://github.com/farion1231/cc-switch/issues/9534)): Skills synced through WebDAV / S3 keep the executable permission of their scripts.
- **A loading icon flashed when reopening Settings** ([#9908](https://github.com/farion1231/cc-switch/pull/9908), closes [#9907](https://github.com/farion1231/cc-switch/issues/9907)): when a cache is available, the settings content is shown directly.
- **Months at the start of the usage heatmap overlapped** (see [#9917](https://github.com/farion1231/cc-switch/issues/9917)): a month with only one or two columns left at the start is no longer labeled, so it no longer crowds into the next month.
- **The progress bar shifted left and right while refreshing quota on the Accounts page**: while refreshing, only the icon spins and the text no longer changes, so the width of that column stays the same.
- **Manually refreshing WorkBuddy quota did nothing**: when WorkBuddy isn't running, or isn't signed in to this account, only the last result can be fetched, and you are now told why.

## Upgrade notes

- **The database version goes from 27 to 28**, adding CodeBuddy toggles for MCP and Skills. The database is backed up automatically before upgrading; if you go back to an older version after upgrading, the older version reports that the database version is too new and can't open it.
- On macOS, the restart that updates an older version to 4.0.41 is still performed by the older version, so an extra Dock icon may still appear this once; later updates and restarts won't show it again.
