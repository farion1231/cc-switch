# CC Switch v4.0.34

Skill repositories in this release can now be on **GitLab, Gitea and Forgejo** (self-hosted instances and Codeberg included), not only on GitHub. **Antigravity CLI** sessions can now be deleted directly on the Sessions page, and with automatic update downloads on, the download starts as soon as a new version is found. WorkBuddy models added by hand can now have thinking effort levels, and S3 sync can clear the config saved on this device, like WebDAV.

Fixes cover "Fetch Models" for Gemini CLI providers reporting an invalid key or returning an empty list; GitHub Copilot models in Codex being treated as not supporting images; S3 sync not working with Alibaba Cloud OSS, Tencent Cloud COS and Huawei Cloud OBS; cloud sync uploads failing entirely when the Skills directory has a broken link; Fable 5.2 showing as Fable 5 in route mode; a low cache hit rate for Gemini models on Copilot; requests failing for Fable models on Copilot with 1M checked; and more.

---

## New

### Skill repositories on GitLab, Gitea and Forgejo

"Manage Skill Repositories" used to accept only github.com addresses; it now also accepts public repositories on GitLab, Gitea and Forgejo (requested in [#1324](https://github.com/farion1231/cc-switch/issues/1324), [#4227](https://github.com/farion1231/cc-switch/pull/4227)), self-hosted instances and Codeberg included:

- `owner/name` is still treated as GitHub. For a full address on another site, CC Switch first asks that site once whether it runs Gitea / Forgejo or GitLab, then downloads the way that platform expects. Custom ports, nested GitLab groups and addresses copied from a Gitea page all work.
- Browsing skills, installing, checking for updates and the "Open docs" link all go to the site the repository is on.
- Only public repositories are supported, and the address must be https. Gitee is not supported yet (its download API requires a token).
- The same `owner/name` can only be kept on one site; adding a repository with the same name on another site replaces the existing one.

### Deleting Antigravity CLI sessions on the Sessions page

Antigravity sessions used to be deletable only in agy. Antigravity CLI sessions can now be deleted directly on the Sessions page; like agy itself, the delete also cleans up the session's index and summary entries, so the session does not come back after agy restarts.

- A session that is open in agy cannot be deleted; close it in agy first.
- Antigravity IDE sessions, and sessions that exist only in the index with no transcript, still have to be deleted in Antigravity.

### Automatic download starts as soon as a new version is found

With "Download updates automatically" on, the download used to wait for the background check about 1 minute after launch, and the "About" page only showed that a new version existed, so the toggle looked like it did nothing. The download now starts as soon as a new version is found at launch, and the "About" page shows "Downloading the new version in the background…" or "Downloaded" under the new-version notice. The icon, text and buttons of the install prompt are also lined up again.

### Thinking effort levels for WorkBuddy models added by hand

Preset WorkBuddy models could already pick a thinking effort in WorkBuddy's model menu, but models added by hand or picked from the model list only had the thinking switch (see [#9599](https://github.com/farion1231/cc-switch/issues/9599)). With thinking on, the model details now let you select which "Thinking effort" levels to offer and set "Thinking can be turned off"; with no level selected, only the thinking switch is shown, as before. Models fetched from the model list also get their available levels filled in automatically, by the same rules as the Pi form.

### Clearing the saved S3 config on this device

S3 sync settings now have "Clear config", like WebDAV: it deletes the saved region, bucket, keys, endpoint and remote folder from this device and stops auto sync. Data already uploaded to the bucket is not deleted.

## Fixes

- **"Fetch Models" for Gemini CLI providers reported an invalid key, or returned an empty list with compatible gateways** (see [#8546](https://github.com/farion1231/cc-switch/issues/8546)): the AI Studio key used to be sent as `Authorization: Bearer`, which Google does not accept; models are now fetched the native Gemini way. The previous release fixed Claude Code / Claude Desktop providers set to the Gemini Native format; this one fixes Gemini CLI's own providers.
- **When using GitHub Copilot in Codex, models that support images were treated as text-only** ([#8027](https://github.com/farion1231/cc-switch/pull/8027), see [#7977](https://github.com/farion1231/cc-switch/issues/7977)): fetching the model list now reads the image input capability Copilot declares. For Copilot providers you already added, fetch the model list again and save, then fully quit and restart Codex.
- **S3 sync didn't work with Alibaba Cloud OSS, Tencent Cloud COS and Huawei Cloud OBS and reported a wrong Access Key** (see [#3996](https://github.com/farion1231/cc-switch/issues/3996)): new buckets on these three services reject the old path-style addresses; CC Switch now automatically uses addresses with the bucket in the domain name. MinIO, R2 and other services are unchanged.
- **The service provider chosen in S3 sync settings was not remembered after reopening the settings page** ([#8644](https://github.com/farion1231/cc-switch/pull/8644)).
- **When the Skills directory had a broken link, the whole cloud sync upload failed** (see [#9615](https://github.com/farion1231/cc-switch/issues/9615)): a broken symlink, or on Windows a directory junction that can't be opened, used to abort the whole upload (reported as `os error 5` on Windows), and downloads failed the same way while backing up the existing Skills. Such links are now skipped with a warning.
- **In route mode with Fable 5.2 upstream, Claude Code's `/model` still showed Fable 5** (see [#9608](https://github.com/farion1231/cc-switch/issues/9608)): Fable 5.2 / 5.1 are now written as the model IDs of their versions, and Claude Desktop is fixed the same way.
- **When using Gemini models through GitHub Copilot, long sessions had a cache hit rate of only about 27%** (see [#9613](https://github.com/farion1231/cc-switch/issues/9613)): Claude Code appends a system message every turn, and Copilot appears to move them all to the start of the request, so the start of the request changed every turn. Now, for Gemini models on Copilot only, system messages in the middle of the conversation are sent as user messages in their original position, so the start no longer changes. Other providers and models are not affected.
- **When using Fable models through GitHub Copilot with 1M checked, requests failed with 400**: Copilot has no 1M versions of Claude models, so the request now falls back to the plain model of the same version. Once the Copilot model list has been fetched, 1M can no longer be checked for models without a 1M version (or a context of at least 1M); models that already have it checked are listed in a warning suggesting you uncheck it, because Claude Code still plans for a 1M context.
- **After changing the Hermes config directory in Settings, providers were not written to the new directory** ([#9567](https://github.com/farion1231/cc-switch/pull/9567)).
- **After one internal error in the MCP connectivity check or the DeepSeek Harness sign-in, CC Switch had to be restarted before they worked again** ([#9572](https://github.com/farion1231/cc-switch/pull/9572)).
- **A provider whose name, address or model name contained "mistral" was treated as Mistral when handling thinking effort** ([#9573](https://github.com/farion1231/cc-switch/pull/9573)): only the official host `api.mistral.ai` is recognized now.
- Added pricing for Qwen4 Max ([#9612](https://github.com/farion1231/cc-switch/pull/9612)).

## Upgrade notes

**The database version goes from 26 to 27**, to record the site each skill repository is on. The database is backed up automatically before the upgrade; if you go back to an older version after upgrading, it will report that the database version is too new and won't open it.
