# CC Switch v4.0.29

This release adds **GitHub Copilot CLI** as a managed app: providers with their own Key are written into Copilot's own `providers.json`, so in `copilot` you can pick them with `/model` alongside the official models, without going through CC Switch. The UI adds Korean and Russian, and all seven languages are now maintained together, so nothing falls back to English anymore.

Fixes cover the Codex desktop app on Windows failing to start on a third-party provider when it runs Codex in WSL; new Codex chats reporting 400 when routed to a third-party native Responses upstream; long Codex answers cut off by the 8192 output limit when routed to an Anthropic-format upstream; official Codex cards in Routing mode not getting the account's own model list; and more.

---

## New

### GitHub Copilot CLI

GitHub Copilot CLI (`copilot`) is a new managed app ([#8753](https://github.com/farion1231/cc-switch/pull/8753), requested in [#5768](https://github.com/farion1231/cc-switch/issues/5768)). There are two kinds of provider cards:

- **Official login**: uses Copilot CLI's own GitHub login and writes no files. "Open Terminal" starts `copilot` with the card's model and reasoning effort; when the card is bound to a GitHub account in Accounts, it starts with that account. The card shows that account's Copilot quota.
- **Providers with their own Key**: clicking "Add" writes the provider into Copilot's own `providers.json` (`$COPILOT_HOME/providers.json`). After that, wherever you start `copilot` on this computer, you can pick "card ID/model" in `/model` next to the official models, and requests go straight to the provider, not through CC Switch's routing. It works without signing in to GitHub.
  - CC Switch only changes this provider's own entry; the other entries in the file (Copilot writes this file too) and their order are kept as they are. A broken `providers.json` stops Copilot from starting, so before writing, the whole file is validated against Copilot's rules, for example that a model's max output cannot take up the entire context window.
  - The provider that holds Copilot's current default model is marked as default and cannot be removed or deleted. To change it, first go into `copilot` and use `/model` to switch to another provider's model.
  - The terminal button on the card works only after the card is added, and starts with the card's first model selected.
  - Presets reuse Pi's provider presets.

Also supported:

- **MCP, Skills, prompts**: synced to Copilot's `mcp-config.json`, Skills directory and instructions file.
- **Session management**: lists Copilot sessions, which can be resumed in a terminal.
- **Usage statistics**: usage is imported from Copilot's session logs; for providers with their own Key, it is attributed to the card selected in the session.
- **One-click import links**: can import Copilot providers, understand the `providers.json` format, support `bearerToken`, and keep every model ID in the link.

### Korean and Russian UI, seven languages maintained together

- **Korean** ([#8794](https://github.com/farion1231/cc-switch/pull/8794), requested in [#2704](https://github.com/farion1231/cc-switch/issues/2704)) and **Russian** ([#7788](https://github.com/farion1231/cc-switch/pull/7788), requested in [#6010](https://github.com/farion1231/cc-switch/issues/6010)): chosen automatically from the system language on first launch; the tray menu and quick panel are translated too. Usage statistics add the Korean won (KRW) as a currency, with automatic exchange rates.
- Turkish, Korean and Russian are no longer community translations that show English wherever a string is missing: every piece of text in the UI exists in all seven languages (Simplified Chinese, Traditional Chinese, English, Japanese, Korean, Turkish and Russian), and new or changed text will be updated in all seven at once from now on.
- The update summary shown after an upgrade is only in Simplified Chinese, Traditional Chinese, English and Japanese for now; other languages show English.

## Changes

- **Copilot explains why the fetched model list is empty** ([#5500](https://github.com/farion1231/cc-switch/issues/5500)): Copilot Free accounts do get models, but none of them can be used in the model picker, and the form used to say only that no models were found. It now says the account may not have Copilot Pro; the Claude Code and Claude Desktop forms also suggest typing `gpt-4.1` or `gpt-4o` manually. When the account has models but none support the selected upstream format, the Codex form says so separately.

## Fixes

- **On Windows, when the Codex desktop app ran Codex in WSL, it failed to start on a third-party provider with "No such file or directory (os error 2)"** ([#9375](https://github.com/farion1231/cc-switch/issues/9375)). Since v4.0.27, CC Switch wrote the model catalog file in `config.toml` as an absolute Windows path, which Codex inside WSL cannot read; Direct, Routing and Aggregation modes were all affected. Now, on Windows with the Codex desktop app set to run Codex in WSL, only the file name is written again, and the next write corrects it automatically.
- **New Codex chats reported 400 when routed to a third-party native Responses upstream** ([#9328](https://github.com/farion1231/cc-switch/pull/9328), related [#7074](https://github.com/farion1231/cc-switch/issues/7074), [#9379](https://github.com/farion1231/cc-switch/issues/9379)). The newer Codex desktop app includes page-context tool results without a `call_id` in new chats, as do automation and cross-task delegation receipts, and strict upstreams reject the whole request. This used to be rewritten only for xAI; now, for every non-official native Responses upstream, such results are rewritten into a user message with the content kept. The official subscription and tool results that have a `call_id` are unaffected.
- **Long Codex answers routed to an Anthropic-format upstream were cut off with "Incomplete response returned, reason: max_output_tokens", and retrying did the same**. Codex requests carry no output limit, so they used to be sent with 8192, which thinking also counts against; a single tool call that writes a whole file could use it up. The default is now 32000. If the upstream's output limit is lower, it reports 400; enter a value it supports in the provider's "Max output tokens".
- **Official Codex cards in Routing mode did not get the account's own model list**: Codex could only use its bundled list, missing account-only models, and with Daybreak on, the Codex desktop app greyed out every official model. Now, when the route is using an official card and "Pause the official login" is off, the route passes the official model list to Codex as is. Third-party providers are not forwarded.
- **Claude Code routed to DeepSeek models on Mistral reported 422 on every turn after a tool call** ([#9385](https://github.com/farion1231/cc-switch/issues/9385), [#9388](https://github.com/farion1231/cc-switch/pull/9388)).
- **For Claude Code cards that only work through routing, after clicking "Open Terminal", Claude Code answered every prompt with "Not logged in" and no request was sent at all**. Credentials for cards such as GitHub Copilot, Codex OAuth and xAI OAuth are provided by the route, and non-Anthropic-format cards rely on the route to convert formats, so a terminal connecting straight to the card's address cannot use them. Now the "Open Terminal" button for these cards is greyed out, with an explanation to turn on Routing and run the client directly in a terminal. On the Codex page, these cards also go from a hidden button to the same greyed-out one.
- **A Claude official card could show another account's quota**: after the default login on this computer changed to a different account, the card in use read the quota of the default login's account. It now first checks that the default login belongs to this account.
- **Antigravity's quota did not match `agy /usage`; Google AI Ultra 5x and 20x were both shown only as "Google AI Ultra"** ([#9317](https://github.com/farion1231/cc-switch/issues/9317), [#9319](https://github.com/farion1231/cc-switch/pull/9319)).
