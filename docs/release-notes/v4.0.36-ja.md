# CC Switch v4.0.36

今回のリリースでは**プラグイン**ページを追加しました。Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi のプラグインを CC Switch からインストール、有効化、更新、アンインストールでき、Claude Code、Codex、Grok Build ではプラグインマーケットプレイスも管理できます。スキルリポジトリは**アクセストークンでプライベートリポジトリを読み取れる**ようになり、ローカルルーティングを経由するプロバイダーには**料金倍率**を設定でき、セッション管理で Claude Code デスクトップ版の**チャプター**を確認できるようになりました。

このほか、Codex で公式クォータ保護をオンにすると自動承認までブロックされる問題、Codex の集約モードで新しくリリースされた公式モデルが表示されるまで長くかかる問題、OpenCode を 2.x にアップグレードした後 1.x のセッションの使用量が集計されなくなる問題、使用量ページのカスタム日付で年を入力するとすぐに 1905 になる問題、Antigravity の複数のモデルが価格未設定と表示される問題などを修正しました。使用量統計では、価格が同じ推論レベルを 1 行にまとめるようになりました。

---

## 新機能

### プラグインページ

サイドバーに「プラグイン」を追加しました。各アプリ自身のコマンドラインを使ってプラグインを管理します（要望：[#791](https://github.com/farion1231/cc-switch/issues/791)、[#9220](https://github.com/farion1231/cc-switch/pull/9220)）。

- Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi に対応し、非表示にしていないアプリだけを表示します。
- 「インストール済み」では有効化、無効化、更新（MiniMax Code は更新できません）、アンインストールができ、「見つける」では検索してインストールできます。Claude Code、Codex、Grok Build では「マーケットプレイス」でプラグインマーケットプレイスを追加、更新、削除することもできます。アドレスには GitHub の `owner/repo`、Git の URL、ローカルフォルダーを指定できます。Pi のプラグインは npm 上の Pi パッケージです。
- Grok Build、OpenClaw、Pi ではインストール前に確認します。プラグインはあなたの権限で動作するため、信頼できる提供元のものだけをインストールしてください。Claude Code でターミナルでの同意が必要なプラグインは、CC Switch が代わりに同意することはなく、ターミナルで対応するインストールコマンドを実行するよう案内します。ログインが必要なアプリでは、ログインコマンドも案内します。
- Codex でプラグインを無効にするときは、`config.toml` にあるそのプラグインの `enabled` だけを変更し、ほかの内容やコメントには触れません。
- 大きなマーケットプレイスのリポジトリはダウンロードに数分かかることがあります。先にダイアログを閉じても構いません。完了すると通知します。

### スキルリポジトリがプライベートリポジトリに対応

「スキルリポジトリを管理」でサイトごとにアクセストークンを設定でき、GitHub、GitLab、Gitea / Forgejo 上のプライベートリポジトリも閲覧、インストール、更新の確認ができるようになりました（要望：[#9666](https://github.com/farion1231/cc-switch/issues/9666)）。

- トークンはサイトごと（`github.com`、`gitlab.example.com` など）に、システムの資格情報ストア（macOS のキーチェーン、Windows の資格情報マネージャー、その他のシステムではこのコンピュータ上の本人だけが読めるファイル）に保存され、クラウド同期されません。読み取り権限だけで十分です。
- ダウンロードに失敗したときは、トークンが未設定なのか、トークンが拒否された（無効、期限切れ、またはこのリポジトリを読み取る権限がない）のかを区別して表示します。

### プロバイダーの料金倍率

中継サービスが割引料金で課金している場合に、使用量統計の費用を倍率で見積もれるようになりました（[#9656](https://github.com/farion1231/cc-switch/pull/9656)）。Claude Code、Codex、Gemini CLI、Grok Build の公式以外のプロバイダーのフォームに「プロバイダーの料金倍率」を追加しました。このプロバイダーの全モデルの参考価格にこの値を掛けます。0.5 は半額、空欄は 1 倍です。

- ローカルルーティングを経由し、かつ設定した後のリクエストにのみ適用されます。直接接続のときにセッション記録から取り込んだ使用量は、引き続き 1 倍で集計されます。

### セッション管理で Claude Code デスクトップ版のチャプターを表示

Claude Code デスクトップ版でモデルが会話に付けたチャプターは、これまで通常の MCP ツール呼び出しとして表示されていました（要望：[#9728](https://github.com/farion1231/cc-switch/issues/9728)、[#9729](https://github.com/farion1231/cc-switch/pull/9729)）。現在はチャプター行として表示され、タイムラインを折りたたんでも見えます。「会話の目次」にはチャプターが並び、クリックするとその位置へジャンプします。検索でもチャプターが見つかり、Markdown にエクスポートするとチャプターは見出しになります。

## 変更

- **使用量統計で価格が同じ推論レベルを 1 行にまとめるように**（[#8845](https://github.com/farion1231/cc-switch/pull/8845)、関連：[#9065](https://github.com/farion1231/cc-switch/issues/9065)）：同じモデルの推論強度違いのバリアントは、入力、出力、キャッシュ読み取り、キャッシュ書き込みの 4 つの価格がすべてベースモデルと同じで、かつベースモデルに完全一致の価格がある場合、ベースモデルの行にまとめます。絞り込み、日別集計、最初のトークンまでの時間もまとめた後の単位で集計し、リクエストログには元のモデル名をそのまま表示します。

## 修正

- **Codex で「公式クォータ保護」をオンにすると、しきい値に達したときに自動承認までブロックされる問題**（[#9733](https://github.com/farion1231/cc-switch/pull/9733)、関連：[#9732](https://github.com/farion1231/cc-switch/issues/9732)）：OpenAI は Codex の自動承認用モデル `codex-auto-review` を無料にし、プランのクォータにも数えないようにしました。現在はクォータ保護がこのモデルを常に通し、ほかの公式モデルはこれまでどおり一時停止します。
- **Codex の集約モードで、新しくリリースされた公式モデル（GPT-6.2 など）が表示されるまで長くかかる問題**：集約モードの Codex は CC Switch が書いたモデルカタログだけを読みます。公式モデル一覧のキャッシュを 6 時間から 1 時間に短縮しました。一覧を取得するときに名乗る Codex のバージョンも、デスクトップ版に同梱の CLI と Codex 自身が記録したバージョンを参照するようにしたため、デスクトップ版が自動更新された後に古いバージョン向けの一部が欠けた一覧を受け取ることはなくなります。
- **OpenCode を 2.x にアップグレードした後、1.x で新規作成または継続したセッションが使用量に含まれない問題**（[#8363](https://github.com/farion1231/cc-switch/pull/8363)、関連：[#8361](https://github.com/farion1231/cc-switch/issues/8361)）：新旧 2 つのデータが共存する場合は両方を読み、同じメッセージは 1 回だけ数えるようにしました。以前にスキャンしたデータベースは前回のスキャン位置から続行し、それより前の記録はさかのぼって取り込みません。
- **使用量ページのカスタム日付で年を手入力すると、入力したとたんに 1905 になる問題**（関連：[#9699](https://github.com/farion1231/cc-switch/issues/9699)）：現在は日付をすべて入力したときだけ反映し、入力の途中で書き換えられることはありません。
- **Antigravity の複数のモデルが使用量統計で「価格未設定」と表示される問題**：Gemini Flash の tiered 版（組み込みブラウザーのサブエージェントが使う `gemini-3.8-flash-tiered` など）は Flash の基本価格で計算します（[#9600](https://github.com/farion1231/cc-switch/pull/9600)）。Hydrogen の tiered 版は基本価格で計算します（[#9706](https://github.com/farion1231/cc-switch/pull/9706)、関連：[#9705](https://github.com/farion1231/cc-switch/issues/9705)）。Orchestrator を使うときの実行ステップは Gemini 4 Hydrogen に振り分け（[#9686](https://github.com/farion1231/cc-switch/pull/9686)、関連：[#9685](https://github.com/farion1231/cc-switch/issues/9685)）、計画ステップは Gemini 4 Neon に振り分けてその価格を追加しました（[#8845](https://github.com/farion1231/cc-switch/pull/8845)）。Claude の Thinking 版（Claude Opus 4.6 (Thinking) など）は対応するベースモデルの価格で計算します。既存の価格未設定の記録は自動的に再計算されます。
- **Claude Desktop のルーティングモードでモデル一覧を空欄にすると、プロバイダーのモデルではなく既定の Claude モデル名が使われる問題**（関連：[#9735](https://github.com/farion1231/cc-switch/issues/9735)）：ルーティングモードではもともとこの動作です。フォームの説明に、直接接続では空欄にすると `/v1/models` を自動で読み取り、ルーティングモードでプロバイダーのモデルを使うにはモデル一覧を入力する必要があることを明記しました。
- **DeepSeek Harness のホームレベルの `cordis.patch.yml` にある MCP が CC Switch に表示されず、説明もない問題**（関連：[#9714](https://github.com/farion1231/cc-switch/issues/9714)）：CC Switch が読み書きするのは各 profile のファイルだけです。MCP のインポートダイアログに、ホームレベルのファイルは読みも書きもしないこと、そこにある MCP はそのファイルで管理することを明記しました。
