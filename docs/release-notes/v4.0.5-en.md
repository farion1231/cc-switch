# CC Switch v4.0.5

### The first fix release for 4.0 stable

Codex can now use a GitHub Copilot account. The "All" heatmap in Usage is no longer limited to the past year: you can go back all the way to the first day with records. This release also fixes subagents always being sent to a worktree when Claude Code is mapped to GPT over the Responses protocol, and GLM and other models disappearing from `/model` in Codex's Aggregation mode; Linux deb and rpm packages can now be updated in-app too. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

> **Linux deb and rpm users, please install this version manually.** Installed deb and rpm versions still carry the old install type marker, so updating to this version in-app still reports insufficient permissions. After you download and install 4.0.5 manually once, automatic updates work normally from then on.

---

## New

**Codex can use a GitHub Copilot account.** When adding a provider in Codex, pick the "GitHub Copilot" preset and sign in to your GitHub account in "Accounts"; a Copilot account already signed in for Claude Code can be used directly. Codex needs Routing turned on. Different models on Copilot support different protocols: local routing picks Responses or Chat Completions automatically for each model, and you can also set it by hand under "Upstream Format" in the editor. Context windows differ by account tier, so the preset defaults to conservative values; clicking "Fetch Models" fills in the model catalog with your account's actual windows and reasoning levels.

**The "All" heatmap shows your full history.** With the time range set to "All", the heatmap used to show only the last 53 weeks. It still shows the last 53 weeks by default; clicking "Show more" adds earlier sections of 53 weeks each, going back to the first day with records. Each section shows its date range, tokens, requests and cost, and the color shading can be compared directly across sections.

## Fixes

- **With Claude Code mapped to GPT over the Responses protocol, subagents were always sent to a worktree.** When Claude Code calls a subagent, "isolation" and "model" are optional parameters, but unless told otherwise the Responses protocol treats optional parameters as required, so the model filled them in every time. As a result, subagents were sent to run in a worktree and failed outright outside a git repository, or the model configured for the subagent was overridden. Conversion now declares these parameters optional explicitly. Providers using the Responses protocol and ChatGPT accounts were both affected, and both are fixed now.
- **In Codex's Aggregation mode, GLM and other models were missing from `/model`.** CC Switch builds the model catalog using the official gpt-5.5 entry as a template; once the official catalog marked that entry hidden, all third-party models in Aggregation were hidden along with it, while the Aggregation count still included them.
- **Codex's MoArk preset showed only one model in `/model`.** The preset came without a model catalog, so Codex listed only the default model. All 5 models are now listed, with their context windows, image input and reasoning levels. MoArk providers you have already added are not updated automatically; add it again from the preset.
- **On Linux, versions installed from deb or rpm reported insufficient permissions when updating in-app.** The updater used to not recognize deb and rpm installs and wrote files into `/usr/bin` the way it does for AppImage. Deb and rpm now have their own update packages. Versions already installed need this version installed manually once; see the note above.
- **On Linux Wayland, the title bar's minimize, maximize and close buttons did nothing when clicked.** When the window was first opened, or reopened from the tray, an invisible area covered the buttons.
- **On Windows, after upgrading with the MSI, the icon pinned to the taskbar went blank after restarting the computer.** The shortcut used to point to an icon cache that was deleted on every upgrade; it now uses the program's own icon. An icon pinned earlier may still go blank once after this upgrade; unpin it and pin it again, and it will not happen on later upgrades.
- **Claude Code installed with npm 12 would not run, and Windows reported the program as incompatible.** npm 12 does not run Claude Code's install script by default but still reports a successful install, leaving only a placeholder file. Installing and upgrading on the "Apps" page, as well as the install commands you can copy, now allow this install script to run.
- **Without Routing on, Grok Build's usage took 10 minutes to appear in Usage**; it now takes about 1 minute.

**Other:**
- The user manual and README are updated to the 4.0 interface.

## Upgrade Notes

**The database schema is unchanged**, still at 20.

**Linux deb and rpm users, please install this version manually**; automatic updates work normally after that.

**Windows users**: if the icon pinned to the taskbar goes blank after upgrading, unpin it and pin it again.
