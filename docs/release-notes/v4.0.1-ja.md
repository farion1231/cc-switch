# CC Switch v4.0.1

### 4.0 プレビュー版の最初の修正リリース

4.0 プレビュー版を試してフィードバックをくださった皆さん、ありがとうございます。このバージョンでは、Gemini CLI のセッションが読み込めない問題や、WSL 環境で Codex の起動が遅くなる問題などを修正し、OpenCode で思考レベルを選べるようにしました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.0-ja.md) をご覧ください。

> **プレビュー版は自動更新されません。** アプリ内の更新は正式版のみが対象です。4.0.0 をインストール済みの場合は、このページから 4.0.1 をダウンロードして手動でインストールしてください。

## 新機能

**OpenCode で思考レベルを選べるようになりました。** OpenCode は「推論対応」とマークされたモデルにだけ思考レベル（Ctrl+T）を提供しますが、CC Switch が書き込むカスタムプロバイダーにはこのマークが付いていなかったため、CC Switch で追加したモデルではレベルを選べませんでした。現在は、推論に対応していることがわかっているプリセットや取得したモデル（プリセットまたは models.dev に基づく）に自動でマークを付けます。レベルは OpenCode 自身が生成するため、OpenCode のバージョンアップにも追従します。

**「Claude Code の初回確認をスキップ」に説明を追加しました。** この項目のヘルプアイコンを開くと、スイッチが実際に何をするか（`~/.claude.json` の `hasCompletedOnboarding` を書き込む／削除する）を確認できます。

## 修正

- **セッション管理で Gemini CLI のセッションが読み込めなかった問題。** 新しい Gemini CLI はセッションを JSONL 形式で記録し、セッション再開時に古いファイルを移行するため、セッション画面に Gemini のセッションが表示されず、使用量の同期でも何も取り込めませんでした。新形式に完全対応し、古いファイルと移行後のファイルが両方ある場合は 1 つだけ表示し、削除時は両方を削除します。セッションタイトルも、CLI が自動挿入するコンテキストやスラッシュコマンドを飛ばすようになりました。
- **WSL 環境の Codex が起動とセッションのスキャンを遅くしていた問題。** Codex の設定ディレクトリが WSL 内にある場合、Windows はそこにある SQLite データベースをロックできず、開くたびに 5 秒のタイムアウトを待っていました。そのため履歴の移行が起動のたびにやり直され、セッションのスキャンも止まっていました。こうしたデータベースはスキップするようになり、セッションタイトルはセッションインデックスから読み込みます。
- **上流がリクエストを拒否したのに「出力の上限に達した」と報告されていた問題。** 一部の Responses 上流（たとえば ChatGPT Codex バックエンドがツール定義を拒否した場合）は、リクエストを処理しないまま使用量 0 で「出力トークンの上限に達した」と返すため、Claude Code は実際には達していない上限を表示していました。現在はこれを上流のエラーとして、拒否の理由とともに正しく報告します。
- **Codex の使用量同期が止まることがあった問題。** 無関係なエラーの後、親セッションを持つ Codex の記録を同期すると止まってしまうことがありました。修正済みです。
- **Grok Build の「API Key を取得」が公式サイトのトップページを開いていた問題。** 他のアプリと同じく、プリセットが提供する登録ページを開くようになりました。

## 使い心地の改善

- **サイドバーの折りたたみと展開がよりなめらかに。** アニメーションをコンポジターで描画し、WebView のメインスレッドの 60 fps に縛られず、ディスプレイのリフレッシュレートで動きます。途中でもう一度クリックすると、現在の位置から続けて動きます。
- **サイドバー下部の区切り線**を上の区切り線と同じスタイルにし、「使用量」を選択しても線に接しなくなりました。
- **リセット回数のドロップダウン矢印**が独立した行にあるとき、上の行のカウントダウンの時計と揃うようになりました。

## ビルドとリリース

macOS の 2 つのアーキテクチャを並列でビルドするようにし、公証の再試行で最初からコンパイルし直す必要がなくなりました。いずれかのプラットフォームで更新用の署名が欠けている場合はビルドがその場で失敗し、そのプラットフォームが抜けた更新マニフェストを公開することはなくなりました。
