# CC Switch v4.0.33

This release fixes Claude Code sessions that were already open continuing to send requests to the previous provider after switching from a third-party provider back to Claude Official, until the session was reopened. The Token Plan quota query adds **Ollama Cloud**, and **Antigravity account switching** in "Accounts" now also works on Windows.

Fixes cover "Fetch Models" always reporting "API Key is invalid or lacks permission" for Claude Code / Claude Desktop providers set to the Gemini Native format; model list fetches being blocked by Cloudflare for some providers; some Antigravity Orchestrator requests still showing as unpriced; WebDAV sync not working at all on some NAS devices; failed WebDAV / S3 uploads showing only "request build failed"; xAI accounts being asked to sign in again after a network blip; a failed skill update deleting the original skill; and more.

---

## New

### Ollama Cloud plan quota

Providers whose address is `ollama.com` can now query their Token Plan quota (requested in [#9382](https://github.com/farion1231/cc-switch/issues/9382)): current plans show the share of this period's included credit that is left and the reset time, and legacy plans show how much is left in the 5-hour and weekly windows. Separately purchased credit is not shown; pay-as-you-go accounts have no plan quota, and the card says why. Ollama running locally (`localhost:11434`) has no plan and is not detected.

- Ollama Cloud providers that are newly added or imported in one click have the quota query on by default; for existing providers, click "Configure usage query" on the card; the Token Plan template is already selected, so turn on "Enable usage query" and save.

### Switching Antigravity accounts on Windows

Antigravity account switching in "Accounts" used to work only on macOS and now works on Windows too: after a switch, agy reads the new account, Antigravity official cards can be bound to an account and show that account's quota, and before a terminal opens you are told which account it will switch to. Linux is not supported yet.

## Fixes

- **After switching from a third-party provider back to Claude Official, Claude Code sessions that were already open kept sending requests to the previous provider until the session was reopened** ([#9247](https://github.com/farion1231/cc-switch/pull/9247), see [#7808](https://github.com/farion1231/cc-switch/issues/7808), [#3057](https://github.com/farion1231/cc-switch/issues/3057)): a running Claude Code only picks up environment variables that are added or changed in `settings.json`; deleted ones stay in the session. When switching, the address, credentials and model mappings to be removed are now first written as empty values, so an open session stops using the previous provider from its next request, and about 10 seconds later they are deleted from the file. The main model set when the session started (`ANTHROPIC_MODEL`) does not follow: if the previous provider set it, pick Default once in the model menu after switching back, or start a new session.
- **For Claude Code / Claude Desktop providers set to the Gemini Native format, "Fetch Models" always reported "API Key is invalid or lacks permission"**: the key is now sent the way Google requires. Actual requests through routing were already fine; only fetching the model list was affected. Pi, Oh My Pi and Kimi Code providers using the Google API also used to list at most 50 models and now get the full catalog.
- **When fetching models, some providers behind Cloudflare rejected the request outright, and it was misreported as "API Key is invalid or lacks permission"** ([#7429](https://github.com/farion1231/cc-switch/pull/7429), see [#7427](https://github.com/farion1231/cc-switch/issues/7427)): requests now send a User-Agent by default; when the provider or its request headers set a User-Agent, that one still takes priority.
- **With Orchestrator selected in Antigravity, some requests still showed as unpriced** ([#9542](https://github.com/farion1231/cc-switch/pull/9542), see [#9493](https://github.com/farion1231/cc-switch/issues/9493)): steps shown as "Gemini 4 Hydrogen (Orchestrator)" are priced at Gemini 4 Hydrogen rates, and history from the last 30 days gets its costs filled in too. Custom prices still take priority.
- **WebDAV sync didn't work at all on some NAS devices: test connection, upload and download all failed** ([#5623](https://github.com/farion1231/cc-switch/pull/5623), see [#5621](https://github.com/farion1231/cc-switch/issues/5621)): these NAS devices answer "create folder" with 400 even when the shared folder already exists; CC Switch used to abort there, and now it checks once more whether the folder exists.
- **When the server cut off a WebDAV / S3 upload midway, the error only said "request build failed"** (see [#9559](https://github.com/farion1231/cc-switch/issues/9559)): the error now tells a request that couldn't be built apart from one that failed while being sent, and includes the specific cause, so you can tell whether it's a network, TLS or server problem. Passwords and signature parameters in the address don't appear in the error.
- **S3 auto sync could still upload once more after being turned off** ([#9528](https://github.com/farion1231/cc-switch/pull/9528)): an auto upload queued while another sync is running now re-reads the settings before it starts, and does not upload if auto sync or S3 sync was turned off in the meantime. WebDAV already worked this way.
- **Querying an xAI account's quota asked you to sign in again after a network blip or an xAI service error** ([#9526](https://github.com/farion1231/cc-switch/pull/9526), see [#9522](https://github.com/farion1231/cc-switch/issues/9522)): that prompt now appears only when the sign-in has really expired; temporary errors are reported as usual, the last quota is kept, and the next query tries again.
- **After a non-default xAI account expired, the default account chosen in "Accounts" was replaced with a different account** ([#9548](https://github.com/farion1231/cc-switch/pull/9548), see [#9543](https://github.com/farion1231/cc-switch/issues/9543)).
- **If copying failed partway through a skill update, the original skill was deleted while the list still showed it as installed** (see [#9521](https://github.com/farion1231/cc-switch/issues/9521)): the new version now replaces the old one only after it has been copied in full, and the old version is kept if copying fails.
- **When Codex requests were converted to Chat format through routing, `required: null` in tool definitions was rejected by strict upstreams** ([#7023](https://github.com/farion1231/cc-switch/pull/7023), see [#7019](https://github.com/farion1231/cc-switch/issues/7019)).
- **On macOS / Linux, when the path of a shell config file contained a colon, deleting or restoring a variable from "Environment Variable Conflicts Detected" failed** ([#7170](https://github.com/farion1231/cc-switch/pull/7170), see [#7169](https://github.com/farion1231/cc-switch/issues/7169)).
- **The Pi presets for PIPELLM, AICodeWith and E-FlowCode showed old model names in the model picker** ([#9514](https://github.com/farion1231/cc-switch/pull/9514)): for example, Claude Opus 5.5 showed as claude-opus-5, while requests actually went to the new model. The DeepSeek Harness, Copilot CLI, Oh My Pi, MiniMax Code and Kimi Code presets generated from these presets are fixed too; providers already added keep the names they were saved with.
- **Providers with an address like `api.commandcode.ai/providers` were treated as Command Code when querying plan quota** ([#9518](https://github.com/farion1231/cc-switch/pull/9518)).
