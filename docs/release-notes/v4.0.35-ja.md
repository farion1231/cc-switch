# CC Switch v4.0.35

今回のリリースでは、Claude Code / Claude Desktop で ChatGPT アカウントを使う Codex カードで **GPT-6.2** を使えるようになり、セッション管理で Codex の `/goal` の**目標全文**を確認でき、リクエスト詳細のリクエスト ID を**ワンクリックでコピー**できるようになりました。

このほか、Claude Code の auto モードが思考をオフにできないモデルでまるごとブロックされる問題、Codex の集約モードと「ターミナルを開く」で Responses-Lite に `reasoning.context` が必要というエラーになる問題、Codex がコンテキストを圧縮した直後のリクエストが拒否される問題、使用量ページのカスタム日付でかなり昔の年を選ぶとフリーズする問題、CC Switch が管理する Skill のコピーがなくなるとアンインストールできない問題などを修正しました。

---

## 新機能

### セッション管理で Codex `/goal` の目標全文を表示

目標が 700 バイトを超えると、Codex が挿入するコンテキストに目標の内容が書かれないため、セッション管理でも目標を確認できませんでした（関連：[#9647](https://github.com/farion1231/cc-switch/issues/9647)）。現在はセッション記録から目標全文を読み取り、「目標 · 状態」という 1 ステップとして表示し、展開すると全文を確認できます。目標と状態がどちらも変わらない重複した記録は表示しなくなりました。

### リクエスト詳細でリクエスト ID 全体をコピー

リクエスト詳細では長い値が省略記号で切り詰められるため、Codex の `resp_...` のような長いリクエスト ID を全文コピーしてログと照らし合わせることができませんでした（関連：[#9681](https://github.com/farion1231/cc-switch/issues/9681)）。現在はリクエスト ID の後ろにコピーボタンを追加しました。

### GPT-6.2 Sol / Astra の価格を追加

公式の標準料金（272K 以内）で計算します。長いコンテキストの料金や Batch / Fast などの区分は、GPT-6 と同じく現時点では区別していません。

## 修正

- **Claude Code / Claude Desktop で ChatGPT アカウントを使う Codex カードで GPT-6.2 を取得できず、手動で入力しても「not supported when using Codex with a ChatGPT account」になる問題**（[#9678](https://github.com/farion1231/cc-switch/pull/9678)、関連：[#9670](https://github.com/farion1231/cc-switch/issues/9670)）：OpenAI は Codex クライアントのバージョンによって提供するモデルを決めていますが、CC Switch が名乗っていたバージョンが古すぎました。現在は Codex 0.169.0 としてリクエストします。モデル ID はひとつもハードコードしていません。
- **Claude Code の auto モードで、思考をオフにできないモデルを使うと Bash や MCP などのツール呼び出しがすべて拒否される問題**（関連：[#8887](https://github.com/farion1231/cc-switch/issues/8887)、[#9671](https://github.com/farion1231/cc-switch/issues/9671)）：auto モードの判定リクエストは思考のオフを求めますが、MiniMax-M3.1-Flash のようなモデルはそれを 400 エラーで返すため、Claude Code は判定サービスが使えないと判断していました。現在はルーティング経由のとき（Claude Code と Claude Desktop）、Anthropic 形式の上流がこのエラーを返したら思考をオフにするフィールドを取り除き、同じプロバイダーで 1 回だけ再試行します。上流がもともと受け付けるリクエストはそのまま送るため、キャッシュには影響しません。
- **Codex の集約モードで「Responses-Lite requires `reasoning.context` to be `all_turns`」になるが、同じプロバイダーでも直接接続とルーティングでは正常に動く問題**（関連：[#9665](https://github.com/farion1231/cc-switch/issues/9665)）：カードにモデルカタログが書かれていない場合、集約モードでも直接接続と同じ GPT-6 の公式設定を使うようにしました。カードから「ターミナルを開く」ときに出ていた同じエラーもあわせて修正しています。
- **Codex をルーティング経由で Chat 形式に変換して使うとき、コンテキストを圧縮した後の最初のリクエストが厳格なゲートウェイに「message content cannot be empty」で拒否される問題**（関連：[#9660](https://github.com/farion1231/cc-switch/issues/9660)）：圧縮時に画像だけを含むユーザーメッセージが空のメッセージになっていたため、Chat 形式に変換するときに内容が空のユーザーメッセージを取り除くようにしました。ほかのメッセージは変わりません。
- **使用量ページのカスタム日付の開始日に 1905 年のようなかなり昔の年を選ぶと、クライアントがフリーズする問題**（関連：[#9691](https://github.com/farion1231/cc-switch/issues/9691)）：現在は最初の使用量記録から今日までの日付だけを選べるようにし、範囲外の日付は選択できず、手入力した日付も範囲内に戻します。
- **CC Switch が管理する Skill のコピーがすでに存在しないと、アンインストールできない問題**（[#9669](https://github.com/farion1231/cc-switch/pull/9669)、関連：[#9668](https://github.com/farion1231/cc-switch/issues/9668)）。
