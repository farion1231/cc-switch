# CC Switch v4.0.26

This release shows each account's subscription plan in Accounts and on official provider cards, and GitHub Copilot accounts list every quota that has a limit; one-click import links can now also import providers for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness and Oh My Pi. Codex cards can keep the official Fast tier for GPT models; when the system proxy takes over requests that Codex or Grok Build send to local routing, CC Switch warns you. DeepSeek Harness can have its config directory set, so it can be managed even when it is installed in WSL. This release also includes a round of performance work: the provider list, main window loading, startup, session reading and routing forwarding are all faster, and the interface no longer freezes while session sync holds the database. Fixes cover requests through routing hanging for over two minutes before being sent when IPv6 is unreachable, MCP servers that require sign-in showing as failed, model changes on Claude Desktop routing cards not taking effect, a lower cache hit rate when Codex goes through routing to Chat, Grok requests through GitHub Copilot failing with 422 and replies being shown twice, and blurry dialogs on non-Retina displays. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### Account subscription plans

Before, only Claude accounts showed their subscription plan in Accounts; other accounts only showed the sign-in date, so a Max account and a Free account of the same service looked exactly the same.

Now GitHub Copilot, ChatGPT, Kimi, Antigravity and xAI accounts also lead their second line with the subscription plan. The official cards of Codex, Kimi, Antigravity and Gemini CLI, as well as Copilot and xAI account cards, also add "· plan name" after the subtitle.

- The plan is fetched in the same query as the quota, so cards do not send a separate request (for Kimi, Antigravity and xAI, that query asks for the plan with one extra request in parallel); the plan appears once the quota has loaded, and cards that do not query quota do not show it.
- When the plan cannot be found, it is simply not shown and the quota is shown as usual; when a refresh fails, the last plan found is kept.
- Grok Build cards that follow the Grok CLI login and Antigravity cards without a bound account do not show a plan yet, because the way they query quota does not return it.

### All GitHub Copilot quotas

Copilot accounts used to show only a percentage for premium requests. Now each quota that has a limit gets its own row, hovering shows "x of y left", and Free accounts can now see their Completions and Chat counts too.

- Premium requests are now called Credits, matching Codex, and the tray uses the same name.
- Free accounts have no Credits; this used to show as "100% left" and now reads "Not in your plan", and provider cards no longer show this item.

### One-click import for more apps

Before, provider links for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness and Oh My Pi were refused outright. Now links for these apps can be imported too.

- **Claude Desktop**: when the link uses the Anthropic format and every model name starts with `claude-` (or no model is given), it is imported as a Direct card; otherwise it is imported as a Model Mapping card, with all four tiers filled from the models in the link.
- **MiniMax Code, Kimi Code, DeepSeek Harness, Oh My Pi**: like Pi, they are imported as a single model, and the link must include a model.
- Oh My Pi reads Keys written in certain forms as environment variable names or commands, so an import could send a secret on your machine to the address in the link. Such Keys (starting with `!`, containing no lowercase letters and so on) are therefore refused.

### Keeping the official Fast tier on Codex cards

GPT models in the model list of third-party Codex cards always had the official Fast speed tier removed, so Fast could not be selected ([#5234](https://github.com/farion1231/cc-switch/issues/5234)). Relays that forward to official ChatGPT accounts (such as CPA) do in fact support Fast.

Now "Advanced Options" in the Codex provider form has "Keep official Fast tier" below "Upstream Format". It is off by default and is shown only when the upstream format is Responses. When it is on and Fast is selected in Codex, requests carry `service_tier=priority`.

- Only relays that forward to official ChatGPT accounts accept it, and it uses quota faster; other upstreams may reject it or bill it at a higher price.
- If you chose Fast earlier under the official card, it takes effect on this provider as soon as you turn this on. It does not apply in Aggregation mode, and Codex needs a restart after you change it.

### Warning when the system proxy takes over local routing

When a proxy tool such as Clash is running, requests that Codex and Grok Build send to local routing (`http://127.0.0.1:<port>`) may be taken over by the system proxy and sent to a remote node, which returns an empty 502 ([#9221](https://github.com/farion1231/cc-switch/issues/9221)). Codex only shows "502 Bad Gateway", and CC Switch never receives the request, so nothing is logged at all and the cause is hard to find.

Now, after Codex or Grok Build enters routing mode, CC Switch sends one request to local routing in the background, following the same proxy rules as the client. If the request does not come back, a warning is written to the log; if you entered routing mode manually, a notice also pops up explaining how to let local addresses connect directly in your proxy tool (for example, by adding `IP-CIDR,127.0.0.0/8,DIRECT,no-resolve` at the top of your Clash rules).

### DeepSeek Harness config directory

Before, DeepSeek Harness only followed `DSH_HOME` or `~/.dsh`, so DSH installed in WSL could not be managed from the Windows version of CC Switch ([#9239](https://github.com/farion1231/cc-switch/issues/9239)).

Now "Settings → App config" has a DeepSeek Harness section where you can set the "Config directory". Providers, Skills, instruction files, sessions and usage import all follow this directory. When you enter a path inside WSL, version detection, installation and upgrades also run in that WSL distribution.

## Changes

- **Performance**:
  - Reading the provider list is faster, and more noticeably so the more providers you have; providers that have not changed are no longer written to the database again, so they no longer trigger cloud sync because of it ([#9180](https://github.com/farion1231/cc-switch/pull/9180)).
  - Secondary pages and the provider editors now load only when they are used, halving the scripts the main window loads at startup ([#9181](https://github.com/farion1231/cc-switch/pull/9181)).
  - Log cleanup at startup now runs in the background; scheduled refreshes pause while the window is hidden or minimized, and keep running while the window is visible but not in front ([#9182](https://github.com/farion1231/cc-switch/pull/9182)).
  - Reading session records makes one less copy of the data, and the session cache is released after entering Lightweight mode ([#9183](https://github.com/farion1231/cc-switch/pull/9183)).
  - Routing makes far fewer memory copies when forwarding streamed responses, especially for long responses; failover also reads the database fewer times ([#9161](https://github.com/farion1231/cc-switch/pull/9161)).
- **The interface no longer freezes during session sync** ([#9178](https://github.com/farion1231/cc-switch/pull/9178)): syncing a large session file holds the database for tens of seconds, and during that time opening the Skills page, switching to Pi or Oh My Pi, opening the Network or Data settings, the icon picker, the universal provider panel, speed tests and other actions froze the whole window and the tray until the sync finished. Now these actions wait in the background and the interface stays responsive.
- **The session reader toolbar has a new layout** ([#9109](https://github.com/farion1231/cc-switch/pull/9109)): the first row holds the path and reading tools, and the second row holds the time, session stats, model and usage; the separator dots that tended to land at the start or end of a line are gone, and long model names wrap, with the full name shown on hover.
- **Presets:** Grok Build's default model changes to `grok-4.7`, the default model of the Kimi presets (except those for Codex) changes to `kimi-k3.1-pro`, and the default model of Hermes's Qianwen AI Platform Coding Plan changes to `qwen3.7-plus` ([#9193](https://github.com/farion1231/cc-switch/pull/9193)); TeamoRouter moves to the teamorouter.com domain; the download link on Claude Desktop's official card changes to claude.com/download. Providers you have already added are not affected.

## Fixes

- **When IPv6 was unreachable, requests through routing hung for over two minutes before being sent** ([#9212](https://github.com/farion1231/cc-switch/issues/9212)). The domains of services such as Zhipu GLM and Alibaba Cloud Bailian resolve to IPv6 addresses first, so on networks where IPv6 does not work, local routing waited for the system to time out every IPv6 address before switching to IPv4: about 150 seconds on macOS and about 43 seconds on Windows. Now, if an IPv6 address cannot connect within 300 milliseconds, IPv4 is tried at the same time; the content of the request is unchanged.
- **MCP servers that require sign-in showed "Connection failed" in connectivity checks** ([#9190](https://github.com/farion1231/cc-switch/issues/9190)). Servers such as Notion and Sentry require an OAuth sign-in; once signed in in the client they work normally, but CC Switch's check does not carry the client's sign-in credentials, so they were judged as failed. Now this case shows a yellow dot, and hovering explains that the server can be reached but requires sign-in. CC Switch still does not read the sign-in credentials saved by the client.
- **After the model on a Claude Desktop routing card was changed, Claude Desktop kept using the old model until the card was deleted and recreated** ([#9203](https://github.com/farion1231/cc-switch/issues/9203)). When "Menu display name" is left empty on save, it is filled with the model name automatically, so when only the model was changed later, the display name stayed the old one. Now a display name that matches the old model name changes along with the new model, and names you chose yourself stay as they are.
- **When Codex went through routing to Chat, the cache hit rate dropped after settings were changed mid-conversation**. For example, after `sandbox_mode` is switched mid-conversation, Codex inserts a note at the start of that turn; it used to be merged into the very beginning of the conversation, rewriting the whole history, so the upstream cache was entirely invalidated. Now the note stays where it is, and the earlier history stays unchanged.
- **When Codex went through routing to Chat, reasoning content from another session could be mixed into the current one**. Tool call IDs from upstreams are easily repeated (such as `exec_command:0`), so after local routing restarted or the cache was evicted, a call with the same ID in another session could be found. Now lookups are separated by Codex session and only search within the same session.
- **When a routed request failed, the request log recorded the client's model name**. For example, a Claude Desktop background task uses `claude-haiku-4-5-20251001`; after it was mapped to the card's model and the upstream answered 429, the log still showed Haiku, which looked like a call to a model you never configured. Now failed requests are written the same way as successful ones: "`claude-haiku-4-5-20251001` → actual model".
- **Official Claude cards that follow the local login kept showing "Token refresh pending" after the login expired, until Claude Code was run again**. Now, when the login has expired, CC Switch has Claude Code refresh the login itself and then reads the quota. This is skipped when the Claude config folder is overridden.
- **When the safety classifier of Claude Code's and Claude Desktop's auto mode was unavailable, the client kept retrying and kept using quota** ([#9201](https://github.com/farion1231/cc-switch/pull/9201), [#9199](https://github.com/farion1231/cc-switch/issues/9199)). Now, when tool results report the classifier as unavailable for 3 turns in a row, local routing returns an error directly instead of sending the request upstream; send a new message to continue.
- **Codex reported 422 when using Grok models through GitHub Copilot** ([#7989](https://github.com/farion1231/cc-switch/pull/7989), [#7988](https://github.com/farion1231/cc-switch/issues/7988)). Grok requests through Copilot now get the same compatibility handling as direct xAI requests.
- **When Codex went through GitHub Copilot, the same reply was shown twice** ([#8025](https://github.com/farion1231/cc-switch/pull/8025), [#7977](https://github.com/farion1231/cc-switch/issues/7977)).
- **When installing or upgrading an app ran into an existing file with the same name, the message only contained npm's suggested `--force`** ([#9196](https://github.com/farion1231/cc-switch/pull/9196), [#9173](https://github.com/farion1231/cc-switch/issues/9173)). The file most likely comes from another installation method, and `--force` would simply overwrite it. Now the message shows the path of the conflicting file and suggests renaming it as a backup before trying again.
- **WebDAV automatic sync failed when Skills contained file symlinks** ([#9197](https://github.com/farion1231/cc-switch/pull/9197)). For example, when `CLAUDE.md` and `GEMINI.md` both link to `AGENTS.md`, packing produced files with duplicate names. Now each file keeps its own name.
- **Two problems with the Codex sub-agent concurrency limit** ([#9148](https://github.com/farion1231/cc-switch/pull/9148)): when a table header in `config.toml` was followed by a comment, changing the limit could overwrite `[features.multi_agent_v2]`; when `[agents]` was written as a quoted key, an extra duplicate field that Codex does not accept was written. The help text now also says the change only applies to new conversations.
- **With a headless profile, DeepSeek Harness could not find the Key saved by CC Switch** and reported `MISSING_CREDENTIAL`. Now, when writing to a headless profile, CC Switch turns on credential reading as DSH's documentation describes; profiles where you changed this setting yourself are left unchanged.
- **On 1x displays, dialogs such as "Select models" were blurry** ([#9238](https://github.com/farion1231/cc-switch/issues/9238)). A centered dialog could land on half a pixel, making text and borders look soft on non-Retina displays.
- **On macOS, the first letter typed into inputs such as the MCP form, prompt editing, Skills repositories and session search was capitalized automatically**, so environment variable names, request headers, commands and addresses could be saved incorrectly.
- **The Linux AppImage bundled an old libwayland-client** ([#9229](https://github.com/farion1231/cc-switch/pull/9229), [#8723](https://github.com/farion1231/cc-switch/issues/8723)), so it might not open on systems with Intel integrated graphics and Wayland.
