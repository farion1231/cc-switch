# CC Switch v4.0.36

本版本新增**插件**页面，可以在 CC Switch 里安装、启用、更新、卸载 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi 的插件，并管理 Claude Code、Codex、Grok Build 的插件市场。技能仓库现在可以用**访问令牌读取私有仓库**；经本地路由的供应商可以设置**费用倍率**；会话管理里能看到 Claude Code 桌面版的**章节**。

另外修复了 Codex 开了官方额度保护后自动审批也被拦下；Codex 聚合模式下新发布的官方模型要很久才出现；OpenCode 升级到 2.x 后 1.x 会话的用量不再统计；用量页自定义日期一输入年份就变成 1905；Antigravity 多个模型显示未定价等问题。用量统计里价格相同的推理档位现在合并成一行。

---

## 新增

### 插件页面

侧栏新增「插件」，通过各应用自己的命令行管理插件（需求见 [#791](https://github.com/farion1231/cc-switch/issues/791)，[#9220](https://github.com/farion1231/cc-switch/pull/9220)）：

- 支持 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi，只列出没有隐藏的应用。
- 「已安装」里可以启用、停用、更新（MiniMax Code 不能更新）、卸载；「发现」里搜索并安装；Claude Code、Codex、Grok Build 还可以在「市场」里添加、刷新、移除插件市场，地址可以是 GitHub 的 `owner/repo`、Git 地址或本地文件夹。Pi 的插件来自 npm 上的 Pi 包。
- Grok Build、OpenClaw、Pi 安装前会先确认：插件以你的权限运行，只装来源可信的。Claude Code 里要在终端同意的插件，CC Switch 不替你同意，会提示到终端运行对应的安装命令；需要先登录的应用也会提示登录命令。
- Codex 停用插件只改 `config.toml` 里这个插件的 `enabled`，其余内容和注释不动。
- 大的市场仓库下载可能要几分钟，可以先关掉对话框，完成后会提示。

### 技能仓库支持私有仓库

「管理技能仓库」里可以按站点设置访问令牌，GitHub、GitLab、Gitea / Forgejo 上的私有仓库都能浏览、安装和检查更新（需求见 [#9666](https://github.com/farion1231/cc-switch/issues/9666)）。

- 令牌按站点保存（如 `github.com`、`gitlab.example.com`），存在系统的凭据存储里（macOS 钥匙串、Windows 凭据管理器，其他系统是本机仅自己可读的文件），不随云同步。只需要只读权限。
- 下载失败时会区分是没设令牌，还是令牌被拒（无效、过期或无权读取这个仓库）。

### 供应商费用倍率

中转按折扣计费时，用量统计里的花费可以按倍率估算（[#9656](https://github.com/farion1231/cc-switch/pull/9656)）。Claude Code、Codex、Gemini CLI、Grok Build 的非官方供应商表单里新增「供应商费用倍率」：这家所有模型的参考价都乘以它，0.5 即半价，留空为 1 倍。

- 只对经本地路由、并且设置之后的请求生效；直连时从会话记录导入的用量仍按 1 倍统计。

### 会话管理里显示 Claude Code 桌面版的章节

Claude Code 桌面版里模型给对话打的章节，以前显示成普通的 MCP 工具调用（需求见 [#9728](https://github.com/farion1231/cc-switch/issues/9728)，[#9729](https://github.com/farion1231/cc-switch/pull/9729)）。现在显示成章节行，收起时间线也能看到；对话目录里会列出章节，点击即跳转；查找能搜到章节，导出 Markdown 时章节变成标题。

## 变更

- **用量统计合并价格相同的推理档位**（[#8845](https://github.com/farion1231/cc-switch/pull/8845)，见 [#9065](https://github.com/farion1231/cc-switch/issues/9065)）：同一个模型的不同推理强度，如果输入、输出、缓存读、缓存写四种价格都和基础模型相同，并且基础模型有精确价格，就合并到基础模型那一行。筛选、每日汇总和首字时间都按合并后统计，请求日志里仍显示原始模型名。

## 修复

- **Codex 开了「官方额度保护」后，达到阈值时自动审批也被拦下**（[#9733](https://github.com/farion1231/cc-switch/pull/9733)，见 [#9732](https://github.com/farion1231/cc-switch/issues/9732)）：OpenAI 已经让 Codex 的自动审批模型 `codex-auto-review` 免费、不计入套餐额度，现在额度保护对它直接放行，其他官方模型照常暂停。
- **Codex 聚合模式下，新发布的官方模型（如 GPT-6.2）要很久才出现**：聚合模式下 Codex 只读 CC Switch 写的模型目录。官方模型列表的缓存从 6 小时缩短到 1 小时；获取列表时报的 Codex 版本也会参考桌面版自带的 CLI 和 Codex 自己记录的版本，桌面版自动更新后不会再按旧版本拿到少一截的列表。
- **OpenCode 升级到 2.x 后，之后在 1.x 里新建或继续的会话不计入用量**（[#8363](https://github.com/farion1231/cc-switch/pull/8363)，见 [#8361](https://github.com/farion1231/cc-switch/issues/8361)）：新旧两套数据并存时现在两套都读，同一条消息只算一次。以前扫描过的数据库从上次扫描处继续，不回补更早的记录。
- **用量页自定义日期手动输入年份时，一输入就变成 1905**（见 [#9699](https://github.com/farion1231/cc-switch/issues/9699)）：现在输入完整的日期才生效，输入过程中不会被改写。
- **Antigravity 多个模型在用量统计里显示「未定价」**：Gemini Flash 的 tiered 版本（如内置浏览器子代理用的 `gemini-3.8-flash-tiered`）按 Flash 基础价计费（[#9600](https://github.com/farion1231/cc-switch/pull/9600)）；Hydrogen 的 tiered 版本按基础价计费（[#9706](https://github.com/farion1231/cc-switch/pull/9706)，见 [#9705](https://github.com/farion1231/cc-switch/issues/9705)）；用 Orchestrator 时的执行步归到 Gemini 4 Hydrogen（[#9686](https://github.com/farion1231/cc-switch/pull/9686)，见 [#9685](https://github.com/farion1231/cc-switch/issues/9685)），规划步归到 Gemini 4 Neon 并新增它的价格（[#8845](https://github.com/farion1231/cc-switch/pull/8845)）；Claude 的 Thinking 版本（如 Claude Opus 4.6 (Thinking)）按对应的基础模型计费。已有的未定价记录会自动补算。
- **Claude Desktop 路由模式下模型列表留空，用的是默认的 Claude 模型名而不是供应商的模型**（见 [#9735](https://github.com/farion1231/cc-switch/issues/9735)）：路由模式本来如此，表单提示现在写清楚了：直连时留空会自动读取 `/v1/models`，路由模式下要用供应商的模型请填写模型列表。
- **DeepSeek Harness 的 home 级 `cordis.patch.yml` 里的 MCP 在 CC Switch 里看不到，也没有说明**（见 [#9714](https://github.com/farion1231/cc-switch/issues/9714)）：CC Switch 只读写各 profile 的文件，MCP 导入对话框现在写明 home 级文件既不读也不写，其中的 MCP 请在那里管理。
