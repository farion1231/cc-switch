# CCSwitchMulti v3.16.5-22

本版本集中修复新版 Codex Desktop 的历史记录恢复、多模态工具上下文，以及切换模型或 Provider 时的上下文压缩问题。

## 历史记录修复

- 按 Codex 官方 thread-store 规则区分用户任务与内部线程：默认只恢复 CLI/VSCode 用户主任务，不再把子 Agent、memory consolidation、内部 feature、developer 环境说明或恢复转录顶进侧边栏。
- 对齐新版 Codex 用户事件结构，同时识别 `event_msg.user_message` 与 `event_msg.item_completed` 中的用户消息。
- 历史正文不再把工具调用、工具结果、developer 指令和子 Agent 转录显示成普通聊天内容。
- 旧版本误修产生的重复记录会按真实用户消息链比较：被更长会话完整覆盖的短快照可回收，真正发生分叉的任务继续保留。
- 清理只移除错误的 SQLite/session index 索引，不删除原始 rollout 文件，并继续要求 Codex Desktop 完全退出后再执行写入修复。

## 图片、音频与文件上下文

- 修复 `view_image` 等工具返回的结构化图片被序列化为 Base64 文本、快速耗尽上下文的问题。
- `function_call_output` 与 `custom_tool_call_output` 现在统一处理文本、图片、音频、加密内容和未知结构化载荷。
- 图片以 Chat 多模态 `image_url` 传递并保留 detail；data audio URL 转换为标准音频输入。
- text-only 模型、远程音频 URL、URL-only 文件及未知二进制内容使用有界占位，不再泄漏或展开 Base64、密文和大载荷。
- 普通 JSON 工具结果保持原有兼容行为，不会被误判为多模态内容。

## 跨模型上下文压缩

- 修复同一任务切换模型或 Provider 后，compact 请求可能沿用错误协议或发送到不存在的 `/responses/compact` 端点的问题。
- 每次 compact 都按请求自身的 model 重新解析 MultiRouter route，不复用上一上下文的 Provider 判断。
- 官方/原生 Responses 路由继续使用 `/responses/compact`；DeepSeek、Qwen 等 Chat 路由转换到 Chat Completions，并重建 Codex 所需的 unary Compact API 输出。
- 保留 Codex compaction 元数据，并在路由日志中记录实际使用的 `responses_compact`、`chat_completions` 或 `messages` transport，便于定位 model downshift 和上下文切换故障。

## 验证

- Responses -> Chat 多模态与压缩转换测试通过。
- Codex MultiRouter 路由、同会话模型切换及 compact route 测试通过。
- Codex 历史恢复、内部转录过滤和分叉保留测试通过。
- Rust `cargo check --lib`、TypeScript typecheck 与差异检查通过。

## 升级说明

1. 安装新版本后完全退出并重新启动 CCSwitchMulti，使新的代理转换逻辑生效。
2. 完全退出 Codex Desktop/ChatGPT App 后，再从 CCSwitchMulti 执行历史记录修复；运行中的 Codex 会触发离线保护并拒绝写入。
3. 修复完成后重新启动 Codex Desktop 验证历史列表。原始 rollout 会保留，可通过修复备份回滚索引修改。

GitHub Release 提供 Windows x64/ARM64、macOS universal 与 Linux x64/ARM64 构建；Windows 用户可下载对应架构的 Setup 安装包。
