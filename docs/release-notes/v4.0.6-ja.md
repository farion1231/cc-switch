# CC Switch v4.0.6

### 4.0 正式版の 2 回目の修正リリース

プロバイダーページのヘッダーに検索ボタンが加わり、API アドレスでも検索できるようになりました。Skills で更新が見つかったらまとめてすべて更新でき、確認の前に更新する Skill が一覧表示されます。利用枠の数字の緑、オレンジ、赤の 3 色が戻り、残りが 20% を切ると色が変わってお知らせします。Codex の集約モードで、メインエージェントとサブエージェントが別のプロバイダーを使うとサブエージェントがタスクを読めない問題は、新しいスイッチをオンにしてクラシックなサブエージェントツールに切り替えられるようになりました。このバージョンでは、Claude Code をルーティング経由で OpenAI Chat 形式に変換したときに最後の応答が失われる問題、Codex の集約モードで公式モデルが消える問題、トレイに Volcengine などの 5 時間枠が表示されない問題なども修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

---

## 新機能

**プロバイダーページに検索ボタンを追加。** これまでは ⌘F / Ctrl+F で検索を開くしかなく、この機能を知らない方も多くいました。現在は「プロバイダーを追加」の隣に検索ボタンがあり、名前、メモ、公式サイトに加えて、API アドレスでも検索できます。検索ボックスを閉じると一覧は全件表示に戻り、絞り込み結果のまま止まることはなくなりました。このボタンが不要な場合は、「設定 → 一般 → サイドバーとヘッダー」で「プロバイダー検索を表示」をオフにできます。ショートカットキーはそのまま使えます。

**Skills をワンクリックですべて更新。** これまでは、まず更新を確認し、一覧を「更新あり」に絞り込んでから、フィルターバーで「すべて更新」を探す必要がありました。現在は更新が見つかると「更新を確認」ボタンがそのまま「すべて更新（N 件）」に変わり、確認ダイアログには更新する各 Skill とその取得元のリポジトリが一覧表示されます。確定するとダイアログはすぐに閉じ、ボタンに更新の進捗が表示されます。再確認は「…」メニューに移りました。

**利用枠の数字の色が戻りました。** 4.0 では利用枠の文字をすべてグレーにしたため、残りが十分なのか、もうすぐ使い切るのかがひと目でわかりにくくなっていました。現在は 3.x の緑、オレンジ、赤の 3 色に戻し、色を付けるのは数字だけで、枠の名前と「残り」の文字はグレーのままです。残りが 20% を切ると色が変わってお知らせします（以前は 10%）。トレイの「残りわずか」も 20% を基準にしました。

**Codex の集約モードで、サブエージェントにクラシックツールを使わせられるように。** 新しい Codex のサブエージェントツールは、メインエージェントから渡すタスクをメインエージェント側のプロバイダーで暗号化させるため、サブエージェントが別のプロバイダーに切り替わると復号できず、エラーになるか空のタスクを受け取るだけでした。「設定 → アプリ設定 → Codex」で「集約モードでサブエージェントにクラシックツールを使う」をオンにすると、集約内のすべてのモデルが Codex のクラシックなサブエージェントツールを使い、タスクを平文で渡します。その代わり、`followup_task`、`interrupt_agent` などの新機能は使えません。スイッチはデフォルトでオフで、集約モードにのみ影響し、変更後は Codex の再起動が必要です。スイッチがオフのままこの状況になった場合、CC Switch はその場でエラーを返して原因を説明し、このスイッチを案内します。サブエージェントが空のタスクのまま動き続けたり、Codex が何度も再試行したりすることはなくなりました。

**Codex でアカウントを切り替えた後、バックグラウンドサービスの再起動を案内するように。** Codex のバックグラウンドサービスはログイン情報を読み直すとは限らず、アカウントを切り替えた後も切り替え前のアカウントを使い続けることがあります。これまでは集約モードでモデル一覧が変わったときにしか再起動を案内していませんでしたが、現在は直接接続、ルーティング、集約の 3 つのモードのどれでもアカウントを切り替えると案内し、ボタンを押して確認してから初めてバックグラウンドサービスを再起動します。Codex のデスクトップ版やエディター拡張機能を使っている場合は、完全に終了してから開き直すよう案内します。

**CC Switch に新しいバージョンがあるとき、サイドバーの「設定」に付く点が緑色になりました**。「設定」をクリックすると「情報」ページが直接開きます。「アプリ」に付くツールの更新の点はこれまでどおりです。

## 修正

- **Claude Code をルーティング経由で OpenAI Chat 形式のプロバイダーに変換したとき、最後の応答がまるごと失われていた問題。** 上流によっては、終了時に終了理由を送らなかったり、終了理由を送った後にさらに内容を追加したりするため、変換後の最後のテキストやツール呼び出しが正しく終了せず、Claude Code がその内容を捨てたうえ、再試行も発生していました。
- **Codex の集約モードで、ウェブ検索の履歴を含むセッションのコンテキストを圧縮すると 502 になっていた問題。** 圧縮時に CC Switch はリクエストからツール定義を削除していましたが、履歴にはウェブ検索や関数呼び出しといったツール呼び出しが残っているため、一部の上流はこうしたリクエストをそのまま拒否していました。現在は圧縮時にツール定義を残し、このターンではツールを呼び出さないようモデルに指示します。
- **Codex の集約モードで、公式アカウントをデフォルトにすると `/model` にサードパーティのモデルしか残らなかった問題。** CC Switch は PATH にある `codex` コマンドのバージョンで公式のモデル一覧を取得していますが、公式は 0.140 以前のバージョンには非表示のモデルしか返しません。Codex のデスクトップ版だけを使っている方は PATH に古いコマンドラインが残っていることが多く、公式モデルがすべて非表示になっていました。現在はこの PC で実際に使われている最新のバージョン（コマンドライン、デスクトップ版、エディター拡張機能のいずれも対象）で取得します。取得した一覧に表示できるモデルがない場合は、CC Switch に同梱の一覧に切り替え、Codex のアップグレードを案内します。
- **Codex でルーティング経由で Chat 形式のサードパーティのプロバイダーや GitHub Copilot を使うと、モデルカタログが公式エントリの変更に引きずられていた問題。** これまで CC Switch は、Codex のローカルキャッシュにある公式の gpt-5.5 エントリをもとにこうしたモデルのカタログを生成していたため、公式がこのエントリを変更するたび（非表示にする、新しいツール形態に変えるなど）にサードパーティのモデルにも反映されていました。キャッシュには GPT-5.5 が 10 月 14 日に提供終了になることも書かれており、終了後は切り替えのたびに Codex のコマンドラインを余分に 1 回起動する必要がありました。現在は常に CC Switch に同梱のテンプレートを使います。
- **CC Switch で管理している ChatGPT アカウントを削除したり、すべてログアウトしたりした後、そのアカウントに紐づいた Codex プロバイダーに切り替えられなかった問題。** これらのプロバイダーが削除済みのアカウントを指したままになっていました。現在は削除やログアウトのときに紐づけも一緒に解除し、プロバイダーは Codex 自身のログインに従うようになります。プロバイダーはクラウド同期されるため、解除するのはこの PC のアカウントの紐づけだけで、ほかのデバイスのアカウントの紐づけには影響しません。
- **npm でインストールした Claude Code を macOS、Linux で「アプリ」ページからアップグレードすると、実行できなくなっていた問題。** 前のバージョンで npm 12 でのインストールは修正しましたが、アップグレード時に呼び出す `claude update` は依然として npm 12 にインストールスクリプトを止められ、しかもアップグレード成功と表示していました。現在はアップグレード時にもインストールスクリプトの実行を許可します。Windows と WSL のアップグレード経路は今回変更していません。
- **Skills のインポートダイアログを閉じられなかった問題。** 「見つける」ページを一度開いていると、インポート時に「見つける」の一覧が GitHub からすべて再ダウンロードされるまで待つ必要があり、ネットワークが遅いとダイアログが固まったままになり、キャンセルも閉じることもできませんでした。
- **トレイで、Volcengine、智譜、MiniMax など 3 段階の利用枠があるプロバイダーの 5 時間枠が表示されなかった問題。** トレイは残りの少ない 2 つの枠しか表示しておらず、5 時間枠は最も頻繁にリセットされて普段いちばん多く残っているため、ほぼ常に省かれていました。現在は 3.x と同じくすべての枠を表示します。
- **ライトモードで、「アプリ」ページの「表示」列のスイッチがオンかオフか見分けにくかった問題。** オンは濃いグレー、オフは中間のグレーでしたが、現在はほかのスイッチと同じ色を使います。

**その他：**
- 中国語版の集約モードガイドを追加し、ユーザーマニュアルに、モデル一覧の取得、models.dev によるパラメータの補完、手動入力の違いの説明を加えました。
- 3 言語のユーザーマニュアルで、Linux のアプリ内ウィンドウボタンの設定場所を更新しました。

## アップグレードに関する注意

**データベースの構造は変わっていません。** バージョンは 20 のままです。

**Codex でルーティング経由で Chat 形式のサードパーティのプロバイダーや GitHub Copilot を使っているセッション**は、アップグレード後に以前のセッションを続けると、コンテキストが自動で 1 回圧縮されます。
