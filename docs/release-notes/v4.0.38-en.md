# CC Switch v4.0.38

This release is mostly fixes. Provider deep links can now import **WorkBuddy** providers; on Linux, **Antigravity** accounts can now be switched in Accounts too; the Antigravity session list no longer mixes in empty sessions and internal sub-sessions, and the session reader shows thinking, tool calls and results.

Fixes also cover every third-party provider disappearing from DeepSeek Harness after its config file passed through some YAML tools; the Apps page marking working npm installs as "Can't run" when CC Switch was opened from Finder; skill repositories not hosted on GitHub / GitLab / Gitea reporting "0 skills detected" instead of an error; the reasoning level chosen for a Codex model sometimes not taking effect; several Codex format conversion errors through local routing; double-counted usage; a session text search failure being shown as "no session contains this term"; the main window opening as a thin strip or hidden under the macOS menu bar; links doing nothing in the Linux AppImage; and more.

---

## New

### Deep links for WorkBuddy

`ccswitch://` provider links can now import WorkBuddy providers ([#9768](https://github.com/farion1231/cc-switch/pull/9768)). The card they create is the same as one added by hand on the WorkBuddy page.

- The link must include a model; `apiFormat` only accepts `openai_chat`.
- If the model ID is already used by another card, the import is refused and no half-created card is left behind.

### Switching Antigravity accounts on Linux

On Linux, agy sign-ins can now be managed and switched in Accounts too, and official cards show the quota of the bound account ([#9774](https://github.com/farion1231/cc-switch/pull/9774), related [#9245](https://github.com/farion1231/cc-switch/issues/9245)).

- Sign-in credentials are stored in the system keyring (Secret Service). While the keyring is locked, background status and quota checks are skipped; switching accounts yourself asks to unlock it.
- On Linux, for a card bound to an account, the "Open Terminal" dialog adds "Use agy's current sign-in for this launch": when the bound account is not on this computer or the keyring is unavailable, you can still open a terminal with the current sign-in, and the card keeps its binding.

## Changes

- **Antigravity session list and session reader** ([#9266](https://github.com/farion1231/cc-switch/pull/9266), see [#9265](https://github.com/farion1231/cc-switch/issues/9265)): the list no longer shows empty sessions left behind by running only `/usage` in the terminal and quitting (shown as `Jan 1`), leftover records of deleted sessions or sessions synced from another device, `/boost` subagents, or `/btw` side questions; their usage is still counted. Sessions without a title use the preview or the first prompt as the title. The session reader shows thinking, text, tool calls (including MCP, browser and others) and tool results (including command exit codes and interrupted status), and file changes show added and removed line counts. After upgrading, the session text index is rebuilt once automatically.
- **Faster session search and usage statistics** ([#9823](https://github.com/farion1231/cc-switch/pull/9823), [#9825](https://github.com/farion1231/cc-switch/pull/9825)): switching apps on the Sessions page no longer rebuilds a search index of every session ID and path, and memory use is much lower; usage statistics queries can use database indexes, first-token times are read only once, and prices are loaded once per request.
- **Google plan names in Accounts no longer repeat "Google"** ([#9834](https://github.com/farion1231/cc-switch/pull/9834)): "Google AI Pro" on Antigravity and Gemini CLI accounts now shows as "AI Pro".

## Fixes

- **Every third-party provider disappeared from DeepSeek Harness** (see [#9785](https://github.com/farion1231/cc-switch/issues/9785)): after `cordis.patch.yml` was saved by some YAML tools, the `off` reasoning level turned into `false`. CC Switch used to store it as is and write it back on every sync, and DeepSeek Harness rejected the whole provider config because of this one invalid key. It is now corrected on both read and write (`false` goes back to `off`, and unknown levels are removed).
- **When CC Switch was opened from Finder, the Apps page marked working npm installs as "Can't run"** (see [#9810](https://github.com/farion1231/cc-switch/issues/9810)): the PATH used to detect installs did not include node, so command-line tools installed with `npm --prefix`, volta, pnpm, bun and similar were judged unable to run, and the page even suggested reinstalling or uninstalling them. Detection now uses the login shell's PATH, as CC Switch already does when running other command-line tools. Windows is not affected.
- **Adding a skill repository on an unsupported site (such as cnb.cool) reported "0 skills detected" instead of an error** (see [#9812](https://github.com/farion1231/cc-switch/issues/9812)): such sites return a web page for any address. The downloaded web page used to be treated as an archive, and the failure was not reported. Now it says "The download isn't a ZIP archive: this site may not be a GitHub / GitLab / Gitea repository, which isn't supported yet".
- **A reasoning level chosen by hand for a Codex model (such as `max` or `ultra`) sometimes did not take effect** ([#9017](https://github.com/farion1231/cc-switch/pull/9017), see [#8952](https://github.com/farion1231/cc-switch/issues/8952)): when the model name matched an official Codex model, the generated model catalog used the official reasoning levels. The levels chosen on the card are now written.
- **Tools with similar names collided when Codex requests were converted to Chat format through local routing** ([#9554](https://github.com/farion1231/cc-switch/pull/9554), see [#9551](https://github.com/farion1231/cc-switch/issues/9551)): when a tool name or namespace already contained `__`, tools could be dropped, or a call could go to the wrong tool. Every tool now gets a unique name, and calls map back exactly.
- **A Codex conversation that had used a third-party model through local routing could not continue after switching to an official model** ([#9756](https://github.com/farion1231/cc-switch/pull/9756), see [#9054](https://github.com/farion1231/cc-switch/issues/9054)): converted message IDs started with `resp_`, but the official API requires IDs that start with `msg_`, so direct mode reported `invalid_id_prefix`. New IDs now start with `msg_`; conversations already saved are unchanged.
- **Codex requests to Claude on AWS Bedrock through local routing all failed with 400** ([#8659](https://github.com/farion1231/cc-switch/pull/8659), see [#6118](https://github.com/farion1231/cc-switch/issues/6118)): tool definitions carried the OpenAI-only `strict` field, which Bedrock does not accept. This field is no longer forwarded.
- **Double-counted usage**:
  - When a model name had a gateway prefix (such as `antigravity/gemini-3.8-flash-high`), the same request was counted once in the routing log and once in the Codex session log ([#9249](https://github.com/farion1231/cc-switch/pull/9249)). The prefix is now removed before comparing.
  - After an old Gemini session file changed, usage that had already been archived was imported again, and changed token counts in a session were not updated ([#9527](https://github.com/farion1231/cc-switch/pull/9527), see [#9523](https://github.com/farion1231/cc-switch/issues/9523)).
- **Codex cache writes were shown as N/A in usage statistics** ([#8191](https://github.com/farion1231/cc-switch/pull/8191)): the actual values are now shown; only Gemini and Grok Build still show N/A (they do not report cache writes). The request log also no longer counts Codex cache writes as fresh input.
- **Antigravity output speed was an estimate and too low** ([#9788](https://github.com/farion1231/cc-switch/pull/9788), see [#9787](https://github.com/farion1231/cc-switch/issues/9787)): Antigravity records its own first-token time and streaming duration, but these were not used, and speed was estimated from the total time (including the wait before the first token). It is now calculated from the actual output time, as for requests through local routing.
- **A session text search error was shown as "no session contains this term"** ([#9512](https://github.com/farion1231/cc-switch/pull/9512), see [#9511](https://github.com/farion1231/cc-switch/issues/9511)): it now says "Text search failed, so only titles, folders and first/last messages can be searched right now", with a "Retry" button; retrying also re-indexes your sessions.
- **Two edge cases in OpenCode sessions** ([#7982](https://github.com/farion1231/cc-switch/pull/7982)): a session migrated to the new format and then continued in OpenCode 1.x used to show its old content; sessions not yet migrated are no longer hidden when a migration to the new format was interrupted.
- **On Windows, the Oh My Pi resume command failed when pasted into PowerShell** ([#9153](https://github.com/farion1231/cc-switch/pull/9153), see [#9152](https://github.com/farion1231/cc-switch/issues/9152)): on Windows it is now written in PowerShell syntax; macOS and Linux are unchanged.
- **In the Linux AppImage, opening a link in the browser or opening a folder did nothing** ([#9113](https://github.com/farion1231/cc-switch/pull/9113), see [#9112](https://github.com/farion1231/cc-switch/issues/9112)): the old xdg-open bundled in the AppImage does nothing on KDE Plasma 6. The system's own xdg-open is now used. deb / rpm, macOS and Windows are not affected.
- **On macOS, a fullscreen main window closed to the tray was covered by the menu bar and Dock when reopened** ([#9770](https://github.com/farion1231/cc-switch/pull/9770), see [#9769](https://github.com/farion1231/cc-switch/issues/9769)): the window now leaves fullscreen before closing to the tray, and returns to fullscreen when reopened from the tray, the Dock and so on.
- **The main window opened as just a thin strip** ([#9504](https://github.com/farion1231/cc-switch/pull/9504), see [#9496](https://github.com/farion1231/cc-switch/issues/9496)): when the remembered window size is abnormally small, the default size is restored on open.
- **When editing a provider, closing the editor while it was still saving and opening it again left the "Save" button spinning** ([#9593](https://github.com/farion1231/cc-switch/pull/9593), see [#9592](https://github.com/farion1231/cc-switch/issues/9592)).
- **The Copilot legacy sign-in migration gave up on a network timeout and only tried again after a restart** ([#9549](https://github.com/farion1231/cc-switch/pull/9549), see [#9544](https://github.com/farion1231/cc-switch/issues/9544)): once the network is back, it now continues the next time Copilot is used, without a restart; it gives up only when the token is invalid (401 / 403) or you sign out.
- **Relay addresses were mistaken for official vendors** ([#9648](https://github.com/farion1231/cc-switch/pull/9648)): when an official domain appeared in the path or query of the address, or the domain only looked similar (such as `api.x.ai.example.com`), the address used to be treated as that vendor: xAI got its special handling, and balance and plan quota were queried with that vendor's official template. Only the real domain is checked now.
- **When importing a config, downloading from cloud sync and similar, a provider of an additive app that failed to be written to the config file was still reported as success** ([#9747](https://github.com/farion1231/cc-switch/pull/9747)): the providers that failed to write are now listed.
- **After moving the skill storage location, apps that failed to relink were still reported as success** ([#9748](https://github.com/farion1231/cc-switch/pull/9748)): they are now listed in the message.
