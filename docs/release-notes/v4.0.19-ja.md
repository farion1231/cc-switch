# CC Switch v4.0.19

今回のリリースでは、Kimi Code に対応しました。CC Switch が管理する 12 番目のアプリです。**Kimi Code の CLI 版とデスクトップ版は同じ設定を共有しているため、CC Switch の対応はどちらにも有効です。**Kimi Code には複数のプロバイダーを同時に設定に書き込むことができ、CC Switch で追加、削除、既定への設定ができます。MCP、Skills、プロンプトは Kimi Code に同期され、セッションは閲覧と再開ができ、使用量はセッションログから取り込みます。「アプリ」ページで Kimi Code のインストール、アップグレード、アンインストールもできます。Kimi のコーディングプランも「アカウント」ページでログインでき、複数のアカウントを追加して、アカウントごとにニックネームと利用枠を表示します。使用量ページのレイアウトも見直しました。期間、アプリ、プロバイダー、モデルを 1 行に並べ、選んだ指標がトレンドグラフとヒートマップの両方に反映され、明細表は件数付きのタブになり、リクエストログは 1 ページの件数を選べるようになりました。このほか、集約モードでサードパーティの GPT からほかのモデルに切り替えた後に Codex が `unsupported call: exec` を出し続ける、Linux/WSL でターミナルから起動したときに「情報」ページを開くとアプリ全体が固まる、Codex でモデルを選ぶと画像入力がオフになる、Claude Code の VS Code 拡張機能が Responses のアップストリーム経由で `redacted_thinking` のエラーを表示する、macOS で Claude サブスクリプションの利用枠がキーチェーンの違う項目を読んでしまう、Antigravity の利用枠に Gemini のグループがない、Hermes を WSL にインストールしているときに Windows 側でダッシュボードが起動する、Esc を 1 回押すと重なったパネルがすべて閉じる、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### Kimi Code

Kimi Code（コマンドは `kimi`）が独立したアプリになりました。プロバイダー、MCP、Skills、プロンプト、セッション、使用量をそれぞれ持ちます（[#8687](https://github.com/farion1231/cc-switch/pull/8687)）。設定は `~/.kimi-code/config.toml` にあり、`KIMI_CODE_HOME` を設定している場合はそのディレクトリを使います。

> **💡 CLI 版とデスクトップ版のどちらにも有効です。** Kimi Code の CLI 版とデスクトップ版は `~/.kimi-code` にある同じ設定とログインを共有しているため、CC Switch で追加したプロバイダー、MCP、Skills、プロンプト、公式アカウントは、どちらのバージョンでもそのまま使えます。

- **プロバイダーを同時に有効にできます。** OpenCode と同じく、複数のプロバイダーを同時に Kimi Code の設定に書き込み、Kimi Code の中で `/model` を使って選びます。「追加できるもの」のカードは「追加」を押すと設定に書き込まれ、既定のモデルは変わりません。追加済みのカードは「削除」でき、「既定にする」はカードのその他のメニューにあります。Kimi Code で既定のモデルやサブエージェントのモデルとして使っているプロバイダーは削除できず、先に Kimi Code で変更するよう案内します。変更するのは CC Switch が管理するプロバイダーとモデルだけで、ほかの設定はそのまま残ります。
- **プロバイダーの追加。** プリセットはほかのアプリと同じく「モデルベンダー」「サードパーティ」「クラウド事業者」「ローカル」に分かれ、さらに Kimi の公式アカウントにログインするための「アカウントでログイン」グループがあります。「モデル一覧を取得」した後に選んだモデルには、コンテキストウィンドウ、思考、画像入力が自動で入力されます。モデルは 1 行に 1 つで、表示名を入力できます（Kimi Code の `/model` にはこの名前が表示されます）。「常に思考」「必要に応じてツールを読み込む」の横には「?」の説明があり、ヘッダーは「詳細オプション」に移しました。
- **MCP、Skills、プロンプト。** MCP は stdio、HTTP、SSE に対応します。Skills は、Kimi Code 自身のディレクトリにある同じ名前のスキルを上書きしません。
- **セッションと使用量。** Kimi Code のセッションを閲覧、再開できます。使用量はセッションログから取り込み、入力、出力、キャッシュ、最初のトークンまでの時間、所要時間を含みます。
- **「アプリ」ページで Kimi Code を管理。** 公式のインストーラーでインストールし、アップグレードとアンインストールもできます。
- Kimi Code はローカルルーティングを経由せず、集約モードもありません。

### Kimi 公式アカウント

「アカウント」ページで「Kimi にログイン」を押し（プロバイダーの追加で「Kimi Code 公式ログイン」を選んでもここに移動します）、中国本土版かグローバル版を選んでブラウザーで認証を済ませると、公式モデルが自動で追加されます（[#8710](https://github.com/farion1231/cc-switch/pull/8710)、[#8726](https://github.com/farion1231/cc-switch/pull/8726)）。

- **複数のアカウント。** 1 つ目のアカウントは Kimi Code 自身のログインの保存場所を使います。その後に追加したアカウントは、それぞれ専用の認証情報、プロバイダー、モデルを持ち、Kimi Code のモデル一覧には「Kimi Subscription <nickname>」と表示されます。「アカウント」ページで「このアカウントを使用」を押すか、カードのその他のメニューで「既定にする」を選ぶと、Kimi Code の既定のモデルがそのアカウントのものに切り替わります。公式カードはプロバイダーページでは編集も削除もできず、「アカウント」ページで管理します。
- **ニックネームと利用枠。** 各アカウントと公式カードにニックネームと利用枠を表示します。期限が近いログインはバックグラウンドで更新し、Kimi Code 自身と同じロックを使うため、Kimi Code と取り合うことはありません。Windows では利用枠を読み取るだけで、ログインの更新はしません。
- **再ログインと削除。** 同じアカウントで再ログインすると既存のものが更新され、重複して増えることはありません。個別に追加したアカウントを削除すると、そのプロバイダー、モデル、認証情報、カードもまとめて削除されます。使用中のアカウントは削除できません。Kimi Code 自身がログインしているアカウントは一覧から外れるだけで、CC Switch が代わりにログアウトすることはありません。
- Kimi Code ですでにログインしているアカウントは、「アカウント」ページに自動で表示されます。

## 改善

**使用量ページのレイアウトを見直しました**（[#8711](https://github.com/farion1231/cc-switch/pull/8711)）。

- ページ右上には同期ボタン（前回の同期時刻を表示）と設定ボタンだけを残し、データソース、表示、料金の設定はすべて設定の中にまとめました。リクエストログに表示する列は、リクエストログのタブの右側にある「リクエストログの列」メニューで選ぶようになりました。
- 期間、アプリ、プロバイダー、モデルを 1 行に並べ、プロバイダーとモデルは 2 階層の 1 つのメニューにまとめました。
- 概要で指標を 1 つ選ぶと、トレンドグラフとヒートマップにその指標が表示されます。入力、出力、キャッシュ読み取り、キャッシュ書き込みの 4 つの Token は 2 行目に展開できます。
- 明細のタブから「設定」をなくし、「リクエストログ」「プロバイダー」「モデル」の 3 つにして、タブに件数を表示するようにしました。表は内容の幅に合わせて並び、幅が広すぎるときは左右にスクロールでき、時刻とアプリの 2 列は左端に固定されます。
- リクエストログは 1 ページに表示する件数を 10、20、50 件から選べます。既定は 20 件で、選んだ件数は記憶されます。データのないセルには「—」を表示します。

**OpenCode、OpenClaw の「既定にする」をその他のメニューに移しました。** これまで追加済みのカードにあった星のアイコンはわかりにくく、選ばれているかどうかも見分けられませんでした。現在はカードのその他のメニューにあり、複数のモデルを持つプロバイダーはサブメニューから既定のモデルを選べます。OpenCode、OpenClaw、Hermes、Kimi Code の既定のプロバイダーは、「使用中」と同じ青色で示すようにしました。

**Pi のプロバイダーキーを常に表示するように。** プリセットから追加するときも表示されて自動で入力され、変更もできます。ほかの Pi のカードと重複すると入力欄の下に通知が出て、保存できません。これまでは保存するまでエラーになりませんでした。

**MCP サーバーにカスタムの表示名を表示**（[#8692](https://github.com/farion1231/cc-switch/pull/8692)）。表示名を設定したサーバーは、一覧と削除の確認ダイアログにその名前を表示し、ID はその横に表示します。

**セッションページのプロジェクトのグループ見出しは、行全体をクリックして展開・折りたたみできるように**（[#8709](https://github.com/farion1231/cc-switch/pull/8709)）。

**プリセット：** BuyToken、V-API を追加しました。

## 修正

- **集約モードでサードパーティの GPT から DeepSeek、Kimi などのモデルに切り替えた後、Codex が毎ターン `unsupported call: exec` を報告する問題**（[#8676](https://github.com/farion1231/cc-switch/issues/8676)）。サードパーティの GPT とほかのモデルではコマンドラインツールの呼び出し方が異なりますが、これまでは切り替えるときに Codex が先に履歴を圧縮しなかったため、新しいモデルが履歴にある自分の対応していない呼び出しをそのまま真似していました。現在はこの 2 種類のモデルの間で切り替えるとき、Codex がまず元のモデルで一度圧縮します。同じ種類のモデル同士の切り替えでは、これまでどおり圧縮しません。
- **Linux または WSL でターミナルから CC Switch を起動すると、「設定 → 情報」を開いたときにアプリ全体が固まる問題**（[#3241](https://github.com/farion1231/cc-switch/issues/3241)）。ツールのバージョンを調べるコマンドがターミナルを占有し、システムによって一時停止されていました。現在はこの照会でターミナルを占有せず、待つのも最大 10 秒です。
- **Codex で取得したモデルを選ぶと、画像入力がオフになる問題**（[#8682](https://github.com/farion1231/cc-switch/issues/8682)）。調べた情報でモデルがテキストのみ対応とされていると、これまでは「テキストのみ対応」と書き込んでいたため、Codex が画像を拒否し、フォームでも元に戻す方法がありませんでした。現在は情報で画像に対応しているとされている場合にだけこの項目を入力し、それ以外は Codex の既定の判断に任せます。
- **一部の中継サービスのモデルを選ぶと、別のベンダーのパラメーターが入力される問題**（[#8765](https://github.com/farion1231/cc-switch/issues/8765)）。たとえば DeepSeek-V4.1-Flash-1017 は models.dev に DeepSeek 自身のエントリがないため、これまでは別の事業者がホストしているファインチューニング版を借りてしまい、「テキストのみ対応」と、実際の 4 分の 1 しかない 262K のコンテキストウィンドウが入力されていました。現在は元のベンダーのエントリが見つからない場合、別の事業者のエントリは借りずに、これらの項目を空欄のままにします。
- **Claude Code の VS Code 拡張機能で OpenAI Responses のアップストリームを経由すると、ツール呼び出しの前に `Unsupported content type: redacted_thinking` が表示される問題**（[#8691](https://github.com/farion1231/cc-switch/issues/8691)）。暗号化された内容しかない思考は、これまで拡張機能が認識できない形式に変換されていました。現在は Anthropic と同じ空の思考ブロックにします。アップストリームに送り返すリクエストは変わりません。最後になってから返される思考の要約も補うようにしました。
- **macOS で Claude サブスクリプションの利用枠の照会が失敗する問題**（[#8764](https://github.com/farion1231/cc-switch/pull/8764)、[#8762](https://github.com/farion1231/cc-switch/issues/8762)）。キーチェーンに同じ名前の項目がいくつもあると、MCP のログイン情報しか保存していない古い項目を読むことがありました。現在はまず現在のユーザーのアカウントで探し、使えるログインが見つからない場合に元の方法に戻ります。
- **macOS で Antigravity 公式カードの利用枠が Claude/GPT だけで、Gemini がない問題。** Google は比較的新しいバージョンの agy にしか Gemini の利用枠を返さないため、現在は照会時にこのパソコンの agy のバージョンを付けて送ります。
- **Windows で Antigravity の利用枠を更新したり、モデル一覧を取得したりするときに、黒いコマンドプロンプトのウィンドウが表示される問題**（[#8700](https://github.com/farion1231/cc-switch/issues/8700)）。
- **Windows で Hermes を WSL にインストールしているとき、Web UI が起動していない状態で「ターミナルを開いて起動」を押すと、Windows 側の Hermes が起動する問題**（[#8689](https://github.com/farion1231/cc-switch/issues/8689)）。Hermes の設定ディレクトリが WSL のパスを指している場合は、現在はその WSL ディストリビューションで `hermes dashboard` を実行します。
- **Codex のリクエストに `session-id` または `thread-id` ヘッダーが付いているとき、ルーティングがセッションを認識できない問題**（[#8718](https://github.com/farion1231/cc-switch/pull/8718)）。
- **Alibaba Cloud Bailian（百炼）、千問の Token Plan の Anthropic アドレスでモデル一覧を取得できない問題**（[#8755](https://github.com/farion1231/cc-switch/pull/8755)）。
- **OpenCode Zen、Go のプロバイダーで、models.dev からモデルのパラメーターを補完しきれない問題。** models.dev がこの 2 つのアドレスを変更したため、現在は古いアドレスでも一致するようにし、`deepseek-v4.1-flash` などのモデルのパラメーターが再び自動で入力されるようになりました。
- **全画面のパネルを重ねて開いているとき、Esc を 1 回押すとすべて閉じてしまう問題。** 現在は一番上のパネルだけを閉じます。
- **ディープリンクのインポート中に 2 つ目のディープリンクが来ると、1 つ目のインポートが終わったときに 2 つ目の確認ダイアログが閉じてしまう問題**（[#8696](https://github.com/farion1231/cc-switch/issues/8696)）。
- **使用量ページの「過去 7 日間」「過去 14 日間」「過去 30 日間」で、夏時間の切り替え前後に 1 日多く、または少なく計算される問題**（[#8719](https://github.com/farion1231/cc-switch/issues/8719)）。
- **リクエストログで後ろのほうのページを表示しているときに総数が減ると、表が空になって戻れなくなる問題。** 現在は最後のページに戻ります。
- **「アプリ」ページで、インストールしていないツールの下に英語の「not installed」が余分に表示される問題。**
- **「詳細オプション」を押したときに文字がずれる問題。**

## アップグレードに関する注意

**データベースのバージョンが 21 から 22 に上がります。** MCP と Skills に Kimi Code のスイッチを追加するためです。アップグレード前にデータベースは自動でバックアップされます。アップグレード後に旧バージョンに戻すと、旧バージョンはデータベースのバージョンが新しすぎると表示し、開けません。

- Kimi Code はデフォルトでサイドバーに表示されます。使わない場合は「アプリ」ページで「Kimi Code をサイドバーに表示」をオフにできます。
