# CC Switch v4.0.34

今回のリリースでは、スキルリポジトリが **GitLab、Gitea、Forgejo**（セルフホストのインスタンスと Codeberg を含む）に対応し、GitHub 以外のリポジトリも追加できるようになりました。セッション管理から **Antigravity CLI** のセッションを直接削除でき、アップデートの自動ダウンロードをオンにしていれば、新しいバージョンが見つかった時点ですぐにダウンロードを始めます。また、WorkBuddy で手動追加したモデルに思考の強度を設定できるようになり、S3 同期でも WebDAV と同じように、このデバイスに保存した設定をクリアできるようになりました。

このほか、Gemini CLI のプロバイダーで「モデル一覧を取得」が Key 無効のエラーになる、または空の一覧が返る問題、Codex で GitHub Copilot のモデルが画像非対応として扱われる問題、Alibaba Cloud OSS、Tencent Cloud COS、Huawei Cloud OBS で S3 同期が使えない問題、Skills ディレクトリにリンク切れがあるとクラウド同期のアップロード全体が失敗する問題、ルーティングモードで Fable 5.2 が Fable 5 と表示される問題、Copilot 上の Gemini モデルのキャッシュヒット率が低い問題、Copilot で 1M にチェックを入れた Fable モデルのリクエストが失敗する問題などを修正しました。

---

## 新機能

### スキルリポジトリが GitLab、Gitea、Forgejo に対応

「スキルリポジトリを管理」はこれまで github.com のアドレスしか受け付けませんでしたが、GitLab、Gitea、Forgejo 上の公開リポジトリも追加できるようになりました（要望は [#1324](https://github.com/farion1231/cc-switch/issues/1324)、[#4227](https://github.com/farion1231/cc-switch/pull/4227)）。セルフホストのインスタンスや Codeberg も対象です：

- `owner/name` と入力した場合は、これまでどおり GitHub として扱います。ほかのサイトの完全なアドレスを入力した場合は、CC Switch がまずそのサイトに Gitea / Forgejo か GitLab かを一度問い合わせ、それに合った方法でダウンロードします。カスタムポート、GitLab の多階層グループ、Gitea のページからコピーしたアドレスにも対応しています。
- スキルの閲覧、インストール、更新の確認、「ドキュメントを開く」リンクは、いずれもリポジトリのあるサイトにアクセスします。
- 対応するのは公開リポジトリだけで、アドレスは https のみ対応しています。Gitee は現時点では対応していません（ダウンロード API にトークンが必要なため）。
- 同じ `owner/name` は 1 つのサイトにしか置けません。別のサイトで同じ名前のリポジトリを追加すると、元のリポジトリと置き換わります。

### セッション管理で Antigravity CLI のセッションを削除

これまで Antigravity のセッションは agy の中でしか削除できませんでした。セッション管理から Antigravity CLI のセッションを直接削除できるようになり、削除時には agy 自身と同じように、セッションのインデックスと要約もあわせて削除するため、agy を再起動しても再び現れることはありません。

- agy でセッションを開いている間は削除できません。先に agy で閉じてください。
- Antigravity IDE のセッションと、インデックスだけがあってセッション記録のないセッションは、引き続き Antigravity で削除する必要があります。

### 新しいバージョンが見つかったらすぐに自動ダウンロード

「アップデートを自動でダウンロード」をオンにしても、これまでは起動から約 1 分後のバックグラウンドチェックまでダウンロードが始まらず、「情報」ページには新しいバージョンがあることしか表示されないため、スイッチが効いていないように見えていました。現在は起動時に新しいバージョンが見つかった時点でダウンロードを始め、「情報」ページの新バージョンのお知らせの下に「新しいバージョンをバックグラウンドでダウンロード中…」または「ダウンロード完了」と表示します。インストール確認ダイアログのアイコン、テキスト、ボタンの配置も整えました。

### WorkBuddy で手動追加したモデルに思考の強度を設定

プリセットの WorkBuddy モデルは以前から WorkBuddy のモデルメニューで思考の強度を選べましたが、手動で追加したモデルやモデル一覧から選んだモデルには思考のオン / オフしかありませんでした（関連：[#9599](https://github.com/farion1231/cc-switch/issues/9599)）。現在は思考をオンにすると、モデルの詳細で提供する「思考の強度」を選び、「思考をオフにできる」を設定できます。どれも選ばなければ、これまでどおり思考のオン / オフだけを表示します。モデル一覧から取得したモデルにも、Pi のフォームと同じルールで使える強度が自動で入ります。

### S3 同期でこのデバイスの設定をクリア

S3 同期の設定に、WebDAV と同じ「設定をクリア」を追加しました。保存したリージョン、バケット、キー、エンドポイント、リモートディレクトリをこのデバイスから削除し、自動同期を停止します。バケットにアップロード済みのデータは削除しません。

## 修正

- **Gemini CLI のプロバイダーで「モデル一覧を取得」が Key 無効のエラーになる、または互換ゲートウェイで空の一覧が返る問題**（関連：[#8546](https://github.com/farion1231/cc-switch/issues/8546)）：これまでは AI Studio の Key を `Authorization: Bearer` で送っていたため、Google に受け付けられませんでした。現在は Gemini ネイティブの方法で取得します。前回のリリースで修正したのは Claude Code / Claude Desktop で Gemini Native 形式を選んだプロバイダーで、今回修正したのは Gemini CLI 自身のプロバイダーです。
- **Codex で GitHub Copilot を使うとき、画像に対応したモデルがテキストのみ対応として扱われる問題**（[#8027](https://github.com/farion1231/cc-switch/pull/8027)、関連：[#7977](https://github.com/farion1231/cc-switch/issues/7977)）：モデル一覧の取得時に、Copilot が宣言している画像入力の対応状況を読み取るようにしました。追加済みの Copilot プロバイダーは、モデル一覧を取得し直して保存し、Codex を完全に終了してから再起動してください。
- **Alibaba Cloud OSS、Tencent Cloud COS、Huawei Cloud OBS で S3 同期が使えず、Access Key が間違っていると表示される問題**（関連：[#3996](https://github.com/farion1231/cc-switch/issues/3996)）：これら 3 社の新しいバケットは従来のパス形式のアドレスを拒否するため、バケットをドメイン名に含めるアドレスに自動で切り替えるようにしました。MinIO、R2 などほかのサービスは変わりません。
- **S3 同期の設定で選んだサービスが、設定ページを開き直すと保持されていない問題**（[#8644](https://github.com/farion1231/cc-switch/pull/8644)）。
- **Skills ディレクトリにリンク切れがあると、クラウド同期のアップロード全体が失敗する問題**（関連：[#9615](https://github.com/farion1231/cc-switch/issues/9615)）：リンク先が存在しないシンボリックリンクや、Windows で開けないディレクトリジャンクションがあると、これまではアップロード全体が中断し（Windows では `os error 5`）、ダウンロード時も既存の Skills をバックアップする段階で失敗していました。現在はこうしたリンクをスキップし、警告を記録します。
- **ルーティングモードで上流が Fable 5.2 のとき、Claude Code の `/model` に Fable 5 と表示される問題**（関連：[#9608](https://github.com/farion1231/cc-switch/issues/9608)）：Fable 5.2 / 5.1 は対応するバージョンのモデル ID で書き込むようにしました。Claude Desktop も同様に修正しています。
- **GitHub Copilot 経由で Gemini モデルを使うと、長いセッションのキャッシュヒット率が約 27% にとどまる問題**（関連：[#9613](https://github.com/farion1231/cc-switch/issues/9613)）：Claude Code は毎ターンシステムメッセージを 1 つ追加しますが、Copilot はそれらをすべてリクエストの先頭に移しているとみられ、リクエストの先頭が毎ターン変わっていました。現在は Copilot 上の Gemini モデルに限り、会話の途中のシステムメッセージを元の位置のままユーザーメッセージとして送るため、先頭が変わらなくなりました。ほかのプロバイダーやモデルには影響しません。
- **GitHub Copilot 経由で Fable モデルを使い 1M にチェックを入れると、リクエストが 400 になる問題**：Copilot には 1M 版の Claude モデルがないため、同じバージョンの通常モデルにフォールバックするようにしました。Copilot のモデル一覧を取得した後は、1M 版がなく、コンテキストも 1M に満たないモデルでは 1M にチェックを入れられなくなります。すでにチェックが入っているものは警告に一覧表示されるので、チェックを外すことをおすすめします。Claude Code は引き続き 1M としてコンテキストを計画するためです。
- **設定で Hermes の設定ディレクトリを変更した後、プロバイダーが新しいディレクトリに書き込まれない問題**（[#9567](https://github.com/farion1231/cc-switch/pull/9567)）。
- **MCP の接続テストや DeepSeek Harness のログインで一度内部エラーが起きると、CC Switch を再起動するまで使えなくなる問題**（[#9572](https://github.com/farion1231/cc-switch/pull/9572)）。
- **プロバイダー名、アドレス、モデル名に mistral という文字列が含まれていると、思考の強度の扱いで Mistral と判定される問題**（[#9573](https://github.com/farion1231/cc-switch/pull/9573)）：現在は公式アドレス `api.mistral.ai` だけで判定します。
- Qwen4 Max の価格を追加しました（[#9612](https://github.com/farion1231/cc-switch/pull/9612)）。

## アップグレードに関する注意

**データベースのバージョンが 26 から 27 に上がります**。スキルリポジトリがどのサイトにあるかを記録するためです。アップグレード前にデータベースは自動でバックアップされます。アップグレード後に旧バージョンに戻すと、旧バージョンではデータベースのバージョンが新しすぎると表示され、開けなくなります。
