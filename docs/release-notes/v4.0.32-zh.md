# CC Switch v4.0.32

本版本新增**后台自动下载更新**：在「设置 → 关于」打开「自动下载更新」后，新版本会在后台下载并校验好，右下角弹出提示问你是否安装，不会未经确认就重启。「设置 → 网络」新增 **IP 检测**，可以查看 CC Switch 经全局代理、临时代理或当前网络访问时的出口 IP 和所在地区。

另外修复了 Codex 经路由换供应商续接旧会话后，上游先回 200 再报「无法解密」导致整轮报废；Codex 经路由或聚合接 Mistral AI 时请求报 422；CC Switch 内部某个操作崩溃一次后，托盘变空、切不了供应商，直到重启；用 mise 装的工具在「应用」页显示两条安装记录等问题。

---

## 新增

### 后台自动下载更新

「设置 → 关于」新增「自动下载更新」开关，默认关闭，每台设备单独设置。

- 打开后，CC Switch 启动一分钟后检查一次，之后每六小时检查一次，有新版本就在后台下载并校验。
- 下载好后，主界面右下角会问你是否安装。安装会重启 CC Switch，正在经本地路由的请求会中断，所以一定要你点「安装并重启」才会进行；路由开着时提示里会写明这一点。
- 点「稍后」只是不再为这个版本弹提示，设置里的红点、「关于」页的按钮，以及托盘菜单和快捷面板里新增的「重启并更新到 vX」仍然可以安装。
- 便携版和 Linux 的 deb / rpm 安装包不能自动安装，开关会置灰并说明原因。

### IP 检测

「设置 → 网络」在全局代理下方新增 IP 检测（[#9449](https://github.com/farion1231/cc-switch/pull/9449)，需求见 [#9448](https://github.com/farion1231/cc-switch/issues/9448)）：选已保存的全局代理或填一个临时代理（只用于这次检测，不保存），点「检测 IP」后会显示出口 IP、两个检测服务的结果是否一致，以及国家或地区、城市、运营商等信息。没设全局代理时，按系统代理或直连检测；指定了代理时，代理连不上不会改用直连。

- 只在点击后运行，会访问 icanhazip.com、ipify.org，并把测得的 IP 发给 ipwho.is 查询位置。
- 测的是 CC Switch 自己经这条线路的出口，不一定等于 Claude Code、Codex 等客户端的出口。

### 其他

- **GitHub Copilot 反代供应商卡片显示绑定的 GitHub 账号**（[#9228](https://github.com/farion1231/cc-switch/pull/9228)，需求见 [#9480](https://github.com/farion1231/cc-switch/issues/9480)）：以前只显示 GitHub Copilot 的官网地址，多个账号时分不清。没绑定时显示授权中心的默认账号，填了备注时备注优先。

## 修复

- **Codex 经路由换供应商续接旧会话时，上游先回 200、再报「Encrypted function output content could not be decrypted or decoded」，Codex 重连五次后这一轮报废**（[#9476](https://github.com/farion1231/cc-switch/issues/9476)）：请求里带着上一家生成的思考记录或加密内容时，CC Switch 会先等上游开始输出再交给 Codex，这时被拒就去掉这些内容后在同一家自动重试一次，会话可以继续。不带这类内容的请求照常直接流式返回。
- **Codex 经路由或聚合接 Mistral AI 时，请求报 422 `extra_forbidden`**（[#9507](https://github.com/farion1231/cc-switch/issues/9507)）：Codex 带的 Responses 专用字段、为 Mistral 上的 DeepSeek / GLM 模型自动加的思考参数，以及用过工具之后每轮都带的 `reasoning_content`，发往 `api.mistral.ai` 时都会去掉。其他上游不受影响。
- **CC Switch 内部某个操作崩溃一次后，托盘菜单变空、切不了供应商，退出时也恢复不了直连，只能重启**（[#9472](https://github.com/farion1231/cc-switch/pull/9472)、[#9483](https://github.com/farion1231/cc-switch/pull/9483)，见 [#8058](https://github.com/farion1231/cc-switch/issues/8058)）：数据库、设置、配置文件写入、MCP、提示词、价格、备份等操作现在都能在崩溃后恢复，崩溃时没写完的改动会回滚。
- **经 GitHub Copilot 用 Claude Code / Claude Desktop 时，Grok 这类在 Copilot 里只支持 Responses 接口的模型报「not accessible via the /chat/completions endpoint」**（[#6954](https://github.com/farion1231/cc-switch/issues/6954)、[#9473](https://github.com/farion1231/cc-switch/pull/9473)）：这类模型现在改走 Responses 接口，两种接口都支持的模型不变。
- **Antigravity 选 Orchestrator 时，用量全部记在一个虚拟模型名下、费用为 0**（[#9493](https://github.com/farion1231/cc-switch/issues/9493)、[#9494](https://github.com/farion1231/cc-switch/pull/9494)）：现在按每一步实际使用的模型计价，并新增 Gemini 4 Hydrogen 的价格。已导入的 Antigravity 历史会重新解析一次，补上费用。
- **开启「统一 Codex 会话历史」或迁移历史后，几个月前的会话在 `codex resume` 里排到了最前面**（[#3866](https://github.com/farion1231/cc-switch/issues/3866)、[#9471](https://github.com/farion1231/cc-switch/pull/9471)）：改写普通 `.jsonl` 会话文件时会保留原来的修改时间，压缩过的文件本来就会保留。已经被改乱的修改时间不会恢复。
- **在 Hermes 里删掉的供应商，CC Switch 里删除按钮一直是灰的**（[#4816](https://github.com/farion1231/cc-switch/issues/4816)、[#9470](https://github.com/farion1231/cc-switch/pull/9470)）：Hermes 里已经没有的供应商现在可以编辑和删除；读不到 Hermes 配置时仍然锁定。
- **从预设新增 OpenClaw 供应商时，`/model` 里列的是预设自带的模型，不是表单里最后保存的**（[#9474](https://github.com/farion1231/cc-switch/pull/9474)，见 [#6729](https://github.com/farion1231/cc-switch/issues/6729)）：在表单里删掉的模型不会再出现，新加的模型也能选；不改动预设直接保存时，会登记预设的全部模型。编辑已有供应商时还不会同步，#6729 仍在跟进。
- **用 mise 安装的工具，「应用」页显示两条安装记录（mise 用 Homebrew 安装时其中一条标成 homebrew）**（[#9515](https://github.com/farion1231/cc-switch/issues/9515)）：mise 的 shim 现在算作它实际指向的那个安装。
- **窗口较矮时，「打开终端」对话框的确认按钮被挤出屏幕，点不到**（[#9478](https://github.com/farion1231/cc-switch/issues/9478)）：对话框内容可以单独滚动，按钮固定在底部；在「附加参数（可选）」输入框里按回车也可以直接打开终端。
- **用量页的汇率状态缺句号，和后面的说明连在一起**（[#9436](https://github.com/farion1231/cc-switch/pull/9436)）。
