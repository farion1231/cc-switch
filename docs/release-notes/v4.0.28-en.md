# CC Switch v4.0.28

This release mainly deals with Codex's incompatible update of November 8.

> ⚠️ **Starting with Codex desktop 26.1103 and CLI 0.167, sessions from the official subscription and from third-party providers are fully separated.** When you switch between the two in Direct mode, the other side's sessions used to just be listed separately; now they become read-only: you can view them but not continue them, and continuing one reports "model provider mismatch". To switch back and forth and keep continuing old sessions, there are two options:
>
> 1. **Use Routing or Aggregation mode instead**: starting with this release, when Routing or Aggregation mode switches to a third party, sessions stay in the same group as the official subscription, so they can be continued after switching either way.
> 2. **Turn on "Unified Codex session history"** ("Settings → App config → Codex"): official and third-party sessions are put in the same group, so you can switch back and forth even in Direct mode.

In addition, a Direct-mode switch that makes sessions read-only now tells you how many; with "Unified Codex session history" on and existing sessions opted into migration, official sessions keep being moved in. When the official quota is used up and Codex locks the send button, you can turn on "Pause the official login" in the routing or aggregation settings and keep using third-party models; official quota protection is now on by default. Installs and upgrades on the Apps page show their queue state and live progress. Fixes cover Codex failover to another vendor still carrying the previous vendor's model name, compaction failing on Kimi For Coding, sessions reporting 400 on every turn after continuing tool calls on Kimi or DeepSeek, and more.

## New

### Adapting to session groups in the new Codex

Codex records sessions by provider ID: the official subscription is recorded under the built-in `openai`, and third-party providers written by CC Switch under `custom`. The new Codex can only continue sessions in the same group as the current provider; the other group is read-only ([#7974](https://github.com/farion1231/cc-switch/issues/7974)). This release makes the following changes around that:

- **Switching to a third party in Routing or Aggregation mode no longer splits sessions into two groups**: when this computer is signed in to ChatGPT and "Unified Codex session history" is off, routing to a third party is also written as the built-in `openai`, just like the official subscription. Requests still go through local routing to the third party, and all sessions stay in the `openai` group. Local routing swaps in the third party's Key and removes request headers such as the ChatGPT account ID and organization, so the third party does not receive your account information.
  - It is still written as `custom` in these cases: this computer has no ChatGPT login, unified session history is on, "Pause the official login" is on, or the provider config sets request retries, stream retries, stream idle timeout or remote compaction, which the built-in `openai` cannot express.
  - If you already use Routing mode, you don't need to do anything: CC Switch rewrites the config once the next time it attaches the route. Direct mode is unchanged.
- **After a Direct-mode switch, you are told how many sessions are now view-only**: with unified session history off, when you switch between the official subscription and a third party in Direct mode, the switch success message gets an extra line, for example "12 sessions from the official subscription are now read-only". Switching from the tray shows no such line.
- **Unified Codex session history** ("Settings → App config → Codex"): once it is on, the official subscription also uses the `custom` ID, so both sides' sessions are in the same group and can all be continued in the new Codex. Turning it on is recommended if you often switch between official and third-party providers.
  - "Also migrate existing official session history" is now checked by default. When it is checked, every later launch of CC Switch moves in sessions that have shown up in the official group again, for example after turning the switch off and on again, or after using Codex without CC Switch.
  - Codex's session database is backed up before both migrating and restoring. Backing up a 42 MB database used to take about 90 seconds; it now takes under 1 second.
  - When the background migration finishes, you are told how many sessions were moved in; restart Codex to continue them.

### Pause the official login (Codex)

When the official ChatGPT quota runs out, Codex checks the quota itself and locks the model picker and the send button, so even a selected third-party model cannot be sent ([#7974](https://github.com/farion1231/cc-switch/issues/7974), [#7962](https://github.com/farion1231/cc-switch/issues/7962)). This happens inside the Codex client, out of reach of local routing; the old workaround of manually changing `requires_openai_auth` to `false` is now overwritten by a single switch.

Now Codex's "Routing settings" and "Aggregation settings" (the gear button at the right end of the mode tab bar, shown while Routing or Aggregation mode is active) have a new "Pause the official login" switch at the top:

- When it is on, Codex stops using the official login, so it no longer locks the send button over the official quota, and the third-party models in Aggregation and Routing keep working. The official login stays saved on this computer; you are not signed out.
- While it is on, official models can't be sent and you are asked to switch to a third-party model; Codex shows no account or usage information and may show its onboarding questions on first launch; the existing sessions under "Projects" in the sidebar are hidden for now and come back when you turn the switch off; new sessions are recorded in the `custom` group and become view-only after you switch back to official.
- While it is on, a notice stays at the top of the Codex page; once the official quota is back, click "Resume official login".
- After turning it on or off, fully quit and reopen Codex. It takes effect only in Routing and Aggregation mode; Direct mode is unaffected.

### Install progress on the Apps page

Installs, upgrades and uninstalls on the Apps page run one at a time. When things were slow, every row used to show a spinner, so you could not tell whether it was downloading, waiting in line or stuck (MiniMax Code's package is about 100 MB and can take over ten minutes on a slow network). Now the row waiting in line says "Queued, waiting for another app to finish", and the row that is running shows the elapsed time and the latest line of command output. The progress is still there after you leave the Apps page and come back.

## Changes

- **Official quota protection is now on by default**: official Codex requests going through local routing are paused once 5-hour usage reaches 95% or weekly usage reaches 98%, while third-party models stay available, so Codex never gets to the point of locking the send button. It is turned on once automatically after the upgrade; if you turn it off afterwards, it will not be turned on again. Change the thresholds in "Settings → App config → Codex → Official quota protection".
- **`disable_response_storage` is no longer written** ([#7524](https://github.com/farion1231/cc-switch/issues/7524)): the new Codex removed this setting and warns about one unrecognized config option on every launch. Presets, templates, universal providers and one-click import links no longer write it, and the line is cleared from an existing `config.toml` on the next switch.
- **Antigravity shows the Argon weekly quota** ([#8913](https://github.com/farion1231/cc-switch/pull/8913)): the Argon weekly quota of the Pro plan used to be missing. Cards now fold it into the Gemini line, while the dropdown and the Accounts page list it separately.
- **Faster first launch on Windows**: when a new database is created, table creation and writing the built-in model prices are each combined into a single commit, making the first launch about 6 seconds faster.

## Fixes

- **When Codex failed over to another vendor, it still carried the previous vendor's model name, and the backup provider reported that the model does not exist** ([#7547](https://github.com/farion1231/cc-switch/issues/7547)). Now, with failover on, before moving to a backup provider CC Switch first checks whether it accepts the model in the request (its own model, or one in its model list), and if not, swaps in that provider's own model; relay queues for the same model are sent as they are. Image generation, image editing and search requests keep their model.
- **Context compaction always failed (HTTP 400) when Codex went through routing to Kimi For Coding**. Kimi does not accept the `tool_choice: "none"` in compaction requests; now when a third-party native Responses upstream rejects a compaction request, it is retried once without `tool_choice`.
- **After Codex continued tool calls on Kimi's or DeepSeek's native Responses, every later turn of that session reported 400**. When an assistant message sits between a tool call and its result, Kimi and DeepSeek both reject the whole history; Kimi also rejects empty assistant messages. Now this kind of history is tidied up only for Kimi (Moonshot) and DeepSeek addresses; other requests are sent unchanged.
- **On Windows, when the Codex directory was inside WSL (`\\wsl.localhost`), usage of forked sessions was never imported**.
