# CC Switch v4.0.34

本版本的技能仓库支持 **GitLab、Gitea 和 Forgejo**（包括自建实例和 Codeberg），不再只能添加 GitHub 上的仓库。会话管理里现在可以直接删除 **Antigravity CLI** 的会话；开启自动下载更新后，发现新版本会立刻开始下载。另外，WorkBuddy 手动添加的模型可以设置思考强度，S3 同步也可以像 WebDAV 一样清除本机保存的配置。

另外修复了 Gemini CLI 的供应商「获取模型列表」报 Key 无效或拿到空列表；Codex 里的 GitHub Copilot 模型被当成不支持图片；阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步；Skills 目录里有失效链接时整个云同步上传失败；路由模式下 Fable 5.2 被显示成 Fable 5；Copilot 上的 Gemini 模型缓存命中率低；Copilot 上勾了 1M 的 Fable 模型请求失败等问题。

---

## 新增

### 技能仓库支持 GitLab、Gitea 和 Forgejo

「管理技能仓库」以前只接受 github.com 的地址，现在也能添加 GitLab、Gitea、Forgejo 上的公开仓库（需求见 [#1324](https://github.com/farion1231/cc-switch/issues/1324)、[#4227](https://github.com/farion1231/cc-switch/pull/4227)），包括自建实例和 Codeberg：

- 填 `owner/name` 仍按 GitHub 处理；填其他站点的完整地址时，CC Switch 会先问一次这个站点是 Gitea / Forgejo 还是 GitLab，再按对应的方式下载。自定义端口、GitLab 的多级分组、Gitea 页面上复制的地址都能用。
- 浏览技能、安装、检查更新和「打开文档」链接都会去仓库所在的站点。
- 只支持公开仓库，地址必须是 https。Gitee 暂不支持（它的下载接口需要令牌）。
- 同一个 `owner/name` 只能保留在一个站点上，在另一个站点添加同名仓库会替换原来的。

### 在会话管理里删除 Antigravity CLI 会话

以前 Antigravity 的会话只能在 agy 里删。现在可以在会话管理里直接删除 Antigravity CLI 的会话，删除时会和 agy 自己一样，把它的会话索引和摘要一并清理，重启 agy 后不会再冒出来。

- 会话正在 agy 里打开时不能删，先在 agy 里关掉它。
- Antigravity IDE 的会话，以及只有索引、没有会话记录的会话，仍然要在 Antigravity 里删除。

### 发现新版本后立刻开始自动下载

开启「自动下载更新」后，以前要等启动约 1 分钟后的后台检查才开始下载，「关于」页只显示有新版本，看起来像开关没生效。现在启动时一发现新版本就开始下载，「关于」页的新版本提示下会显示「正在后台下载新版本…」或「已下载完毕」。安装确认框的图标、文字和按钮也重新对齐了。

### WorkBuddy 手动添加的模型可以设置思考强度

预设里的 WorkBuddy 模型早就能在 WorkBuddy 的模型菜单里选思考强度，手动添加或从模型列表选的模型却只有思考开关（见 [#9599](https://github.com/farion1231/cc-switch/issues/9599)）。现在打开思考后，模型详情里可以勾选要提供的「思考强度」，并设置「可以关闭思考」；都不勾时仍只显示思考开关。从模型列表获取的模型也会按 Pi 表单的规则自动填上可用的强度。

### S3 同步可以清除本机配置

S3 同步设置新增「清除配置」，和 WebDAV 一样：从本机删除保存的区域、存储桶、密钥、端点和远程目录，并停止自动同步，存储桶里已经上传的数据不会删除。

## 修复

- **Gemini CLI 的供应商「获取模型列表」报 Key 无效，或者用兼容网关时拿到空列表**（见 [#8546](https://github.com/farion1231/cc-switch/issues/8546)）：以前按 `Authorization: Bearer` 发 AI Studio Key，Google 不认；现在按 Gemini 原生方式获取。上一版修好的是 Claude Code / Claude Desktop 选 Gemini Native 格式的供应商，这次修的是 Gemini CLI 自己的供应商。
- **Codex 里用 GitHub Copilot 时，支持图片的模型被当成只支持文字**（[#8027](https://github.com/farion1231/cc-switch/pull/8027)，见 [#7977](https://github.com/farion1231/cc-switch/issues/7977)）：获取模型列表时会读取 Copilot 声明的图片输入能力。已经添加的 Copilot 供应商，请重新获取模型列表并保存，再完全退出并重启 Codex。
- **阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步，被提示 Access Key 错误**（见 [#3996](https://github.com/farion1231/cc-switch/issues/3996)）：这三家的新存储桶拒绝旧的路径式地址，现在会自动改用把存储桶放在域名里的地址。MinIO、R2 等其他服务不变。
- **S3 同步设置里选的服务商，重新打开设置页后没记住**（[#8644](https://github.com/farion1231/cc-switch/pull/8644)）。
- **Skills 目录里有失效的链接时，云同步整个上传失败**（见 [#9615](https://github.com/farion1231/cc-switch/issues/9615)）：失效的符号链接，或 Windows 上打不开的目录联接，以前会让上传整体中止（Windows 上报 `os error 5`），下载时也会在备份现有 Skills 这一步失败。现在跳过这类链接并记录警告。
- **路由模式下上游是 Fable 5.2 时，Claude Code 的 `/model` 仍显示 Fable 5**（见 [#9608](https://github.com/farion1231/cc-switch/issues/9608)）：Fable 5.2 / 5.1 现在写成对应版本的模型 ID，Claude Desktop 同样修正。
- **经 GitHub Copilot 用 Gemini 模型时，长会话的缓存命中率只有约 27%**（见 [#9613](https://github.com/farion1231/cc-switch/issues/9613)）：Claude Code 每一轮都会追加一条系统消息，Copilot 看起来会把它们都挪到请求开头，导致每轮请求的开头都变了。现在只对 Copilot 上的 Gemini 模型，把会话中途的系统消息按原位置作为用户消息发送，开头不再变化。其他供应商和模型不受影响。
- **经 GitHub Copilot 用 Fable 模型并勾选 1M 时，请求报 400**：Copilot 没有 1M 版本的 Claude 模型，现在会退回同版本的普通模型。获取过 Copilot 模型列表后，没有 1M 版本（上下文也不到 1M）的模型不能再勾 1M；已经勾了的会列在提示里，建议取消，因为 Claude Code 仍会按 1M 规划上下文。
- **在设置里改了 Hermes 的配置目录后，供应商没有写进新目录**（[#9567](https://github.com/farion1231/cc-switch/pull/9567)）。
- **MCP 连通性检测或 DeepSeek Harness 登录出过一次内部错误后，要重启 CC Switch 才能再用**（[#9572](https://github.com/farion1231/cc-switch/pull/9572)）。
- **供应商名称、地址或模型名里带 mistral 字样，就会被当成 Mistral 处理思考强度**（[#9573](https://github.com/farion1231/cc-switch/pull/9573)）：现在只认官方地址 `api.mistral.ai`。
- 新增 Qwen4 Max 的价格（[#9612](https://github.com/farion1231/cc-switch/pull/9612)）。

## 升级说明

**数据库版本从 26 升到 27**，为技能仓库记录它所在的站点。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
