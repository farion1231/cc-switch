# CC Switch v4.0.41

今回のリリースでは **CodeBuddy** に対応しました（Tencent の CLI 版とデスクトップ版は同じ設定を共有しています）。カスタムモデル、MCP、Skills、プロンプト、セッション、使用量を管理でき、「アカウント」ページに複数の公式アカウントを取り込んで、プラン、クレジット、有効期限を確認しながらいつでも切り替えられます。**Copilot CLI** のプロバイダーをワンクリックで VS Code の Copilot 拡張機能に同期できるようになりました。**Grok 公式カード**にはサブスクリプションのプランが表示されます。

このほか、Claude のネイティブ転送で上流への接続を再利用するようにし、メインウィンドウとトレイパネルの起動時に読み込むコードを減らし、バックグラウンドのリクエストやプロバイダーの接続チェックが失敗したときに理由を表示するようにしました。また、データベースファイルの権限、バックアップのファイル名、CONNECT プロキシ、ワンクリックインポートのリンクのセキュリティチェックを強化しました。さらに、Codex を Opus / Sonnet 5.5 にルーティングするとツール呼び出しの後に「requires adaptive thinking」になる問題、Gemini Native でツール呼び出しの履歴が長くなると 400 になる問題、古いリクエストのフェイルオーバーの結果が手動で選んだルートを上書きする問題、Antigravity のカードに紐付けたアカウントが「アカウント」ページと同期しない問題、Codex のフォークしたセッションの使用量がいつまでも集計されない問題、Pi のプラグインが pnpm として扱われる問題、Windows で Hermes のインストールが 2 か所表示される問題、macOS で更新後に Dock のアイコンが 1 つ増える問題などを修正しました。

## 新機能

### CodeBuddy

CodeBuddy を追加しました（[#8758](https://github.com/farion1231/cc-switch/pull/8758)）。CodeBuddy のデスクトップ版と CLI は同じ設定ファイルを読むため、画面上ではまとめて CodeBuddy と呼びます。Kimi Code や WorkBuddy と同じく共存型で、複数のモデルを同時に追加できます。

- **カスタムモデル**：各カードは `~/.codebuddy/models.json` の 1 つのモデルで、カードの ID がそのまま上流に送るモデル名になります。保存後は変更できず、「複製」もありません。アドレスからモデル一覧を取得でき、モデルを選ぶとトークン上限と機能が自動で入力されます。ファイル内のほかのモデルや、ご自身で追加したフィールドはすべて保持します。コメントや末尾のカンマがあるファイルは書き換えません。`settings.json` でデフォルトに設定されているモデルは削除できません。DeepSeek、Xiaomi MiMo、LongCat のプリセットを追加しました。
- **MCP、Skills、プロンプト**：MCP は CodeBuddy が実際に読むユーザーレベルのファイル 1 つに書き込み、ご自身のサーバーは保持します。CC Switch で有効にしたサーバーは CodeBuddy の無効リストから外します。Skills は `~/.codebuddy/skills` に同期し、CC Switch がインストールしたものでないスキルは削除しません。プロンプトは `CODEBUDDY.md` に書き込みます。
- **セッションと使用量**：セッション一覧で CodeBuddy のセッションを表示し、ターミナルで再開できます（CC Switch から削除することはできません）。使用量統計にはメインセッションとサブエージェントの使用量を取り込み、サブエージェントの使用量は親のセッションに計上します。
- **公式アカウント**：「アカウント」ページに現在ログインしている CodeBuddy アカウントを取り込むか、ターミナルで新しいアカウントにログインできます。CodeBuddy がすでにログインしている場合は、まず確認してから CodeBuddy にログイン画面を表示させ、ログインをキャンセルすると元のアカウントに戻します。「CodeBuddy 公式ログイン」カードを追加しました。アカウントを 1 つ紐付け、「追加」を押すとそのアカウントに切り替わります。「アカウント」ページのアカウントの「…」メニューからも切り替えられます。アカウントの行とカードには、プラン、今期のクレジット、有効期限を表示します。アカウントのコピーはこのマシンにだけ保存され、同期の対象にはなりません。
- **「アプリ」ページ**：CodeBuddy CLI のインストール、更新、アンインストールができます。

### Copilot CLI を VS Code Copilot 拡張機能に同期

「設定 → アプリ設定 → Copilot CLI」で「VS Code Copilot 拡張機能に適用」をオンにすると（[#9435](https://github.com/farion1231/cc-switch/pull/9435)、[#9433](https://github.com/farion1231/cc-switch/issues/9433) をクローズ）、Copilot CLI に追加したプロバイダーとモデルが VS Code Copilot 拡張機能のモデル設定に書き込まれ、それぞれのモデル一覧から選んで使えます。

- VS Code の正式版と Insiders のデフォルトプロファイルと名前付きプロファイルを自動で見つけ、すべてに同期します。その後、CC Switch で Copilot CLI のプロバイダーを追加、編集、削除すると自動で更新されます。
- 変更するのは CC Switch が書き込んだグループだけで、ほかの設定やコメントはすべて保持します。最初に変更する前に、同じ場所にバックアップを 1 つ残します。スイッチをオフにすると、このグループを削除します。
- 同期に失敗しても Copilot CLI 側の保存はそのまま反映され、通知に理由を表示して「再試行」を提供します。
- WebSocket や `apiVersion` 付きの Azure デプロイなど、一部の設定にはまだ対応していません。その場合は理由を表示します。

### Grok 公式カードにサブスクリプションのプランを表示

Grok Build の公式カードで、アカウントの後ろにサブスクリプションのプランを表示します。例：`SuperGrok Heavy`（[#9923](https://github.com/farion1231/cc-switch/pull/9923)）。xAI アカウントを紐付けたカードでも「利用状況を設定」から自動更新の間隔を設定できます。使用量の照会をオフにすると、サブスクリプションのプランも一緒に非表示になります。

## 変更

- **Claude のネイティブ転送で上流への接続を再利用**（[#9914](https://github.com/farion1231/cc-switch/pull/9914)、[#9913](https://github.com/farion1231/cc-switch/issues/9913) をクローズ）：ローカルルーティングが Claude のリクエストをそのまま転送するとき、毎回上流への接続を張り直さなくなりました。直接接続でもプロキシ経由でも接続を再利用します。再利用した古い接続で失敗したときは、自動で新しい接続に切り替えて再送します。プロキシ経由の場合は、まだデータを何も受け取っていないときだけ新しい接続に切り替えます。
- **起動を軽量化**（[#9918](https://github.com/farion1231/cc-switch/pull/9918)、[#9920](https://github.com/farion1231/cc-switch/pull/9920)）：画面の言語パックは使用中の言語だけを読み込むようにしました。トレイパネルの「使用量」タブは切り替えたときに初めて読み込み、パネルを閉じている間はバックグラウンドの更新を止めます。トレイパネルの起動時に読み込むコードは約 3.5 MB から約 0.5 MB に減りました。バックエンドでは使用量の中央値を計算するときのメモリ確保を減らし、使わないネットワーククライアントを先に作成しないようにしました。
- **ネットワークの失敗時に理由を表示**（[#9911](https://github.com/farion1231/cc-switch/issues/9911) を参照）：起動時のバックグラウンドのリクエストが失敗すると、どのリクエストかを一度だけ通知します。アップデートの確認では dl.ccswitch.io / github.com にアクセスしていること、models.dev の同期では使用料金の計算に使う料金を取得するためであることを説明し、通知から「今後表示しない」を選ぶか、自動同期をそのままオフにできます。プロバイダーの接続チェックに失敗したときは、ファイアウォールによるブロック、ポートでサービスが動いていない、タイムアウト、DNS エラー、TLS エラーを区別し、それぞれに合ったアドバイスを表示します。
- **折りたたんだサイドバーを細く**（[#9941](https://github.com/farion1231/cc-switch/pull/9941)）：サイドバーを折りたたんだときの幅と、選択中の項目のハイライトを細くしました。表示密度が「標準」のときは「コンパクト」より少し広くなります。アイコンの大きさは変わりません。

## セキュリティ

- **データベース、バックアップ、プロキシ、ワンクリックインポートのリンク**（[#9835](https://github.com/farion1231/cc-switch/pull/9835)）：macOS / Linux では、エクスポートした SQL ファイルと `cc-switch.db` を現在のユーザーだけが読み書きできるようにしました。バックアップの復元、名前の変更、削除では、単一の `.db` ファイル名だけを受け付けます。HTTP プロキシ（CONNECT）経由で上流に接続するとき、プロキシのアドレスでエスケープされたユーザー名とパスワードを元に戻してから送信し（特殊文字を含むと 407 になる問題を修正）、プロキシが返すレスポンスヘッダーのサイズを制限します。ワンクリックインポートのリンクのリスクチェックでは、悪用されうる環境変数をより多く検出し、`node -e`、`python -c` のようにコードを直接実行するコマンドも警告します。

## 修正

- **Codex を Opus / Sonnet 5.5 にルーティングするとツール呼び出しの後に 400 になる**（[#9943](https://github.com/farion1231/cc-switch/issues/9943) を参照）：Codex がローカルルーティング経由で Anthropic API の Opus 5.5 または Sonnet 5.5 を使うと、ツール呼び出し以降のターンが毎回「requires adaptive thinking」になっていました。この 2 つのモデルは思考をオフにできないため、この場合は適応型思考を送るようにしました。Codex で `none` に設定した思考の強さは `low` として送ります。ほかのモデルのリクエストは変わりません。
- **Gemini Native でツール呼び出しの履歴が長くなると 400 になる**（[#9009](https://github.com/farion1231/cc-switch/pull/9009)）：会話が 64 ターンを超えると、古いツール呼び出しの署名が失われ、別の呼び出しと誤って対応付けられて Gemini に拒否されることがありました。現在は署名を別に、より長くキャッシュし、呼び出し ID で正確に対応付けます。どうしても署名を取り戻せない場合は、Gemini 3 以降に限り Google のドキュメントにある互換用のマーカーを使います。
- **古いリクエストのフェイルオーバーの結果が手動で選んだルートを上書きする**（[#9946](https://github.com/farion1231/cc-switch/pull/9946)、[#9944](https://github.com/farion1231/cc-switch/issues/9944) をクローズ）：手動でルートを切り替えたり自動フェイルオーバーをオフにしたりした後、まだ処理中の古いリクエストがルートを予備のプロバイダーに戻すことはなくなり、使用中のプロバイダーとして表示されることもなくなりました。
- **Antigravity のカードに紐付けたアカウントが「アカウント」ページと同期しない**（[#9945](https://github.com/farion1231/cc-switch/pull/9945)）：Antigravity の公式カードでアカウントを紐付けたり変更したりして保存すると、「アカウント」ページを通じて agy のログインを切り替え、切り替えに失敗した場合は保存しません。カード、アカウントの選択欄、「アカウント」ページには同じ現在のアカウントが表示されます。カードを複製してもアカウントは切り替わりません。
- **Codex のフォークしたセッションの使用量がいつまでも集計されない**（[#9638](https://github.com/farion1231/cc-switch/pull/9638)、[#9637](https://github.com/farion1231/cc-switch/issues/9637) をクローズ）：アイドル状態のセッションからフォークした旧バージョンの Codex セッションは、コピーされた履歴が親セッションのものであることを確認できた時点で使用量を取り込みます。判断できないものはこれまでどおり保留します。
- **グローバルプロキシの設定が半分しか反映されない**（[#9930](https://github.com/farion1231/cc-switch/pull/9930)）：グローバルプロキシを続けて 2 回保存すると、一部のリクエストがもう一方の保存時のプロキシ設定を使うことがありました。現在はプロキシのアドレスとネットワーククライアントをまとめて一度に置き換えます。
- **Pi のプラグインが pnpm として扱われる**（[#9964](https://github.com/farion1231/cc-switch/pull/9964)、[#9960](https://github.com/farion1231/cc-switch/issues/9960) を参照）：システムで見つかった `pi` が実際には pnpm だった場合、「プラグイン」画面に 0 個と表示され、「見つける」でインストールを押すと `~/.pi/agent` に npm パッケージがインストールされていました。現在は Pi の出力と判別できない場合はそのままエラーにします。あわせてツールのパスの判定も修正しました。pnpm、mise、volta のようなショートカット経由でインストールしたツールを誤認せず、ターミナルの起動スクリプトが出力したパスをツールの場所と見なすこともなく、macOS / Linux では pnpm のグローバルインストール先も探します。
- **Windows で Hermes のインストールが 2 か所表示される**（[#9931](https://github.com/farion1231/cc-switch/issues/9931) を参照）：同じフォルダーにある `hermes.cmd` と `hermes.exe` は 1 か所として表示し、Windows が実際に実行するほうを採用します。
- **macOS で更新後に Dock のアイコンが 1 つ増える**（[#9910](https://github.com/farion1231/cc-switch/pull/9910)、[#8329](https://github.com/farion1231/cc-switch/issues/8329) をクローズ）：アプリ内の更新や設定ディレクトリの変更の後に再起動するとき、古いプロセスが完全に終了するのを待ってから新しいプロセスを起動し、Dock に固定したアイコンをそのまま使います。
- **SQL のインポート後に同期が失敗しても成功と表示される**（[#9541](https://github.com/farion1231/cc-switch/pull/9541)、[#9536](https://github.com/farion1231/cc-switch/issues/9536) をクローズ）：インポート後にプロンプト、料金、設定の同期に失敗した場合は、それぞれに対応する警告を表示します。
- **クラウド同期後に Skills のスクリプトを実行できない**（[#9539](https://github.com/farion1231/cc-switch/pull/9539)、[#9534](https://github.com/farion1231/cc-switch/issues/9534) をクローズ）：WebDAV / S3 で同期した Skills は、スクリプトの実行権限を保持します。
- **設定を再び開くと読み込みアイコンが一瞬表示される**（[#9908](https://github.com/farion1231/cc-switch/pull/9908)、[#9907](https://github.com/farion1231/cc-switch/issues/9907) をクローズ）：キャッシュがある場合は設定の内容をすぐに表示します。
- **使用量ヒートマップの先頭の月が重なる**（[#9917](https://github.com/farion1231/cc-switch/issues/9917) を参照）：先頭で 1〜2 列しか残っていない月には月名を表示しないようにし、次の月と重ならなくなりました。
- **「アカウント」ページでクォータを更新するとプログレスバーが左右に揺れる**：更新中はアイコンを回すだけで文字を変えないため、その列の幅が変わりません。
- **WorkBuddy のクォータを手動で更新しても反応しない**：WorkBuddy が起動していない場合や、ログインしているのがこのアカウントでない場合は前回の結果しか取得できないため、その理由を表示するようにしました。

## アップグレード時の注意

- **データベースのバージョンが 27 から 28 に上がります**。MCP と Skills に CodeBuddy のスイッチを追加するためです。アップグレード前にデータベースは自動でバックアップされます。アップグレード後に旧バージョンに戻すと、旧バージョンではデータベースのバージョンが新しすぎると表示され、開けません。
- macOS で旧バージョンから 4.0.41 に更新するときの再起動は旧バージョンが行うため、Dock のアイコンが 1 つ増えることがあります。それ以降の更新と再起動では起きません。
