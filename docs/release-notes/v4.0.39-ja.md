# CC Switch v4.0.39

今回のリリースは修正が中心です。**API キー入力欄**にコピーボタンが付きました。**バックアップ**に合計サイズの上限を設定でき、超えると古いものから削除されます。Claude Code が Codex OAuth 経由で **GPT-6.2 Sol / Astra** を使うとき、システムプロンプトのキャッシュヒット率が大きく上がりました。

このほか、Claude Code と Claude Desktop のネイティブプロバイダーで上流が出力しないまま止まったとき、フェイルオーバーまで最大 600 秒待たされる問題、非常に長いストリーミング応答で使用量とログの収集に使うメモリが増え続ける問題、ワンクリックインポートのリンクで設定のマージに失敗しても確認ダイアログが開く問題、Codex デスクトップ版だけが入っているとプラグイン画面で Codex が未インストールと表示される問題、プラグイン画面がインストールされていないアプリの空の設定フォルダーを作る問題、OpenCode Go の DeepSeek V4.1 Flash に `max` の思考レベルがない問題、すばやくクリックするとポップオーバーやドロップダウンメニューがちらつく問題などを修正しました。

---

## 新機能

### API キーをワンクリックでコピー

プロバイダーフォームの API キー入力欄にコピーボタンが付きました（[#9232](https://github.com/farion1231/cc-switch/pull/9232)）。前後の空白を除いたキーをコピーし、成功しても失敗しても通知が出ます。入力欄が空のときや編集できないときは表示されません。

### バックアップの合計サイズ上限

バックアップ設定に「バックアップ合計サイズ上限」が追加されました（[#9011](https://github.com/farion1231/cc-switch/pull/9011)、関連 [#6706](https://github.com/farion1231/cc-switch/issues/6706)）。既定は「無制限」なので、アップグレードしてもバックアップは削除されません。

- 上限を設定すると、バックアップフォルダーがそのサイズを超えたときに、古いバックアップから順に削除されます。
- 最新のバックアップと、復元に使用中のバックアップは常に残るため、1 つのバックアップが上限より大きい場合はフォルダーが上限を超えることがあります。
- 上限は次回のバックアップか日次メンテナンスのときに適用されます。日次メンテナンスでは、途中でクラッシュしたバックアップが残した 24 時間以上前の一時ファイルも削除します。

## 変更

- **Claude Code が Codex OAuth 経由で GPT-6.2 Sol / Astra を使うときのキャッシュヒット率が向上**（[#9848](https://github.com/farion1231/cc-switch/pull/9848)、[#9847](https://github.com/farion1231/cc-switch/issues/9847) を参照）：システムプロンプトを最初の developer メッセージに置くようにしたため、ChatGPT のバックエンドが会話と一緒にキャッシュします。実測では 2 ターン目以降のヒット率が約 98% でした。ほかのモデルと API キーを使うルートは変わりません。
- **プライバシーフィルターを高速化**（[#9826](https://github.com/farion1231/cc-switch/pull/9826)）：フィルターの結果は変わりません。

## 修正

- **Claude Code と Claude Desktop のネイティブプロバイダーで上流が出力しないまま止まると、フェイルオーバーまで最大 600 秒待たされる**（[#9754](https://github.com/farion1231/cc-switch/pull/9754)）：これらのストリーミングリクエストは非ストリーミング用のタイムアウトを使っていました。現在はほかのストリーミングリクエストと同じく最初のバイトのタイムアウト（既定 60 秒）を使います。
- **非常に長い、または終わらないストリーミング応答で、使用量とログの収集に使うメモリが増え続ける**（[#9846](https://github.com/farion1231/cc-switch/pull/9846)、[#9843](https://github.com/farion1231/cc-switch/issues/9843) を参照）：バッファーの上限を 64 MiB にし、極端に大きいイベントのあとも続きを解析できるようにしました。
- **ワンクリックインポートのリンクで設定のマージに失敗しても、確認ダイアログが開く**（[#9844](https://github.com/farion1231/cc-switch/pull/9844)、[#9841](https://github.com/farion1231/cc-switch/issues/9841) を参照）：現在はエラーだけを表示し、確認ダイアログは開きません。
- **Codex デスクトップ版だけが入っていると、プラグイン画面で Codex が未インストールと表示される**（[#9850](https://github.com/farion1231/cc-switch/issues/9850) を参照）：たとえば Windows に Codex デスクトップ版（MSIX）だけを入れている場合です。単体でインストールされた `codex` が見つからないとき、プラグイン画面など Codex CLI を使う箇所はデスクトップ版に同梱されたものを使うようになりました。「アプリ」ページのインストール、アップグレード、アンインストールは引き続き単体でインストールされた Codex CLI だけを管理します。
- **プラグイン画面がインストールされていないアプリの空の設定フォルダーを作る**（[#9852](https://github.com/farion1231/cc-switch/issues/9852) を参照）：プラグイン画面を開くと、Codex、Grok Build、OpenClaw、Pi、MiniMax Code が入っていなくても `~/.codex` や `~/.grok` などの空のフォルダーが作られていました。現在は CLI が見つかってから作成し、入っていないアプリはこれまでどおり未インストールと表示されます。
- **OpenCode Go の DeepSeek V4.1 Flash に `max` の思考レベルがない**（[#9853](https://github.com/farion1231/cc-switch/issues/9853) を参照）：プリセットに OpenCode Go のモデル一覧どおり `low`、`high`、`max` の 3 段階を明記したため、OpenCode が汎用の `low` / `medium` / `high` に戻らなくなりました。
- **すばやくクリックすると、ポップオーバーやドロップダウンメニューがちらつく**（[#9176](https://github.com/farion1231/cc-switch/pull/9176)、[#9175](https://github.com/farion1231/cc-switch/issues/9175) を参照）：開閉のアニメーション中にもう一度クリックしても、2 回続けて切り替わらなくなりました。
