# CC Switch v4.0.32

This release adds **background update downloads**: turn on "Download updates automatically" in "Settings → About", and new versions are downloaded and verified in the background, then a prompt in the bottom-right corner asks whether to install; CC Switch never restarts without your confirmation. "Settings → Network" adds **IP diagnostics**, which shows the exit IP and location CC Switch gets through the global proxy, a temporary proxy or the current network.

Fixes cover Codex resuming an old session after switching provider through routing, where the upstream first returned 200 and then reported "could not be decrypted", losing the whole turn; Codex getting a 422 when routed or aggregated to Mistral AI; the tray going empty and providers becoming impossible to switch until a restart, after one internal CC Switch operation crashed; tools installed with mise showing two install entries on the "Apps" page; and more.

---

## New

### Background update downloads

"Settings → About" adds a "Download updates automatically" switch, off by default and set separately on each device.

- When it's on, CC Switch checks one minute after launch and then every six hours; when there is a new version, it is downloaded and verified in the background.
- Once the download is ready, a prompt in the bottom-right corner of the main window asks whether to install. Installing restarts CC Switch and cuts off requests going through local routing, so it only happens when you click "Install and restart"; when routing is on, the prompt says so.
- "Later" only stops the prompt for that version; you can still install from the red dot in Settings, the button on the "About" page, and the new "Restart to update to vX" entry in the tray menu and quick panel.
- The portable build and Linux deb / rpm packages can't install updates automatically; there the switch is greyed out, with the reason shown.

### IP diagnostics

"Settings → Network" adds IP diagnostics below the global proxy ([#9449](https://github.com/farion1231/cc-switch/pull/9449), requested in [#9448](https://github.com/farion1231/cc-switch/issues/9448)): pick the saved global proxy or enter a temporary proxy (used only for this check, not saved), click "Check IP", and it shows the exit IP, whether the two check services agree, and details such as country or region, city and ISP. With no global proxy set, the check goes through the system proxy or a direct connection; when a proxy is specified and can't be reached, it does not fall back to a direct connection.

- It runs only when you click, contacting icanhazip.com and ipify.org and sending the observed IP to ipwho.is to look up its location.
- It measures CC Switch's own exit over that route, which is not necessarily the exit used by clients such as Claude Code and Codex.

### Other

- **GitHub Copilot proxy provider cards show the bound GitHub account** ([#9228](https://github.com/farion1231/cc-switch/pull/9228), requested in [#9480](https://github.com/farion1231/cc-switch/issues/9480)): they used to show only GitHub Copilot's website address, so several accounts were hard to tell apart. When no account is bound, the default account from "Accounts" is shown; a note, if set, takes priority.

## Fixes

- **When Codex switched provider through routing and resumed an old session, the upstream first returned 200 and then reported "Encrypted function output content could not be decrypted or decoded"; Codex reconnected five times and the turn was lost** ([#9476](https://github.com/farion1231/cc-switch/issues/9476)): when a request carries thinking records or encrypted content generated by the previous provider, CC Switch now waits for the upstream to start producing output before handing it to Codex; if the upstream rejects it at that point, that content is removed and the request is retried once automatically on the same provider, so the session can continue. Requests without such content still stream straight through as before.
- **Codex routed or aggregated to Mistral AI got 422 `extra_forbidden`** ([#9507](https://github.com/farion1231/cc-switch/issues/9507)): the Responses-only fields Codex sends, the thinking parameters added automatically for DeepSeek / GLM models on Mistral, and the `reasoning_content` carried on every turn once a tool has been used are all removed from requests to `api.mistral.ai`. Other upstreams are unaffected.
- **After one internal CC Switch operation crashed, the tray menu went empty, providers couldn't be switched, and quitting couldn't restore direct mode; only a restart helped** ([#9472](https://github.com/farion1231/cc-switch/pull/9472), [#9483](https://github.com/farion1231/cc-switch/pull/9483), see [#8058](https://github.com/farion1231/cc-switch/issues/8058)): operations on the database, settings, config file writes, MCP, prompts, pricing, backups and more now recover after a crash, and changes the crash left half-written are rolled back.
- **Using Claude Code / Claude Desktop through GitHub Copilot, models such as Grok that Copilot offers only through the Responses API reported "not accessible via the /chat/completions endpoint"** ([#6954](https://github.com/farion1231/cc-switch/issues/6954), [#9473](https://github.com/farion1231/cc-switch/pull/9473)): these models now go through the Responses API; models that support both APIs are unchanged.
- **With Orchestrator selected in Antigravity, all usage was recorded under one virtual model name at zero cost** ([#9493](https://github.com/farion1231/cc-switch/issues/9493), [#9494](https://github.com/farion1231/cc-switch/pull/9494)): each step is now priced by the model it actually used, and a price for Gemini 4 Hydrogen is added. Antigravity history already imported is reparsed once to fill in the costs.
- **After turning on "Unified Codex session history" or migrating history, sessions from months ago jumped to the top of `codex resume`** ([#3866](https://github.com/farion1231/cc-switch/issues/3866), [#9471](https://github.com/farion1231/cc-switch/pull/9471)): rewriting plain `.jsonl` session files now keeps their original modification time, as compressed files already did. Modification times that were already scrambled are not restored.
- **For providers deleted in Hermes, the delete button in CC Switch stayed greyed out** ([#4816](https://github.com/farion1231/cc-switch/issues/4816), [#9470](https://github.com/farion1231/cc-switch/pull/9470)): providers that no longer exist in Hermes can now be edited and deleted; they stay locked while the Hermes configuration can't be read.
- **When adding an OpenClaw provider from a preset, `/model` listed the preset's own models instead of the ones last saved in the form** ([#9474](https://github.com/farion1231/cc-switch/pull/9474), see [#6729](https://github.com/farion1231/cc-switch/issues/6729)): models removed in the form no longer appear, and newly added models can be picked; saving a preset without changing it registers all of the preset's models. Editing an existing provider doesn't sync them yet; #6729 is still being followed up.
- **For tools installed with mise, the "Apps" page showed two install entries (one of them labelled homebrew when mise itself was installed with Homebrew)** ([#9515](https://github.com/farion1231/cc-switch/issues/9515)): a mise shim now counts as the install it actually points to.
- **In a short window, the confirm button of the "Open Terminal" dialog was pushed off screen and couldn't be clicked** ([#9478](https://github.com/farion1231/cc-switch/issues/9478)): the dialog content now scrolls on its own with the buttons fixed at the bottom, and pressing Enter in the "Extra arguments (optional)" field also opens the terminal directly.
- **On the usage page, the exchange rate status was missing its period and ran into the note after it** ([#9436](https://github.com/farion1231/cc-switch/pull/9436)).
