# CC Switch v4.0.23

本版本让 Kimi Code、MiniMax Code、Oh My Pi 的供应商编辑器按应用自己的格式显示配置文件里这一家的部分；Claude Code、Claude Desktop 经路由连 OpenAI 格式和 Gemini 的上游时，客户端选的思考档位能发给更多模型，卡片上还可以选怎么发；授权中心可以一键刷新所有账号的额度；Antigravity、MiniMax Code 的用量记录有了耗时和首字时间。另外修复了 Windows 上进入轻量模式后主窗口回不来、经路由连部分 OpenAI 格式的上游时切换模型失败、DeepSeek Harness 的配置目录是链接时无法编辑供应商、Grok Build 超过 50 MiB 的会话用量不统计、Codex 分支会话用量一直不导入、DeepSeek Harness 等应用测试官方余额时提示 Key 为空、供应商表单里几个编辑器互相覆盖等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

## 新增

### Kimi Code、MiniMax Code、Oh My Pi 的供应商编辑器按原生格式显示

以前这三个应用的供应商编辑器显示的是卡片的 JSON，和它们实际的配置文件对不上，上游文档里的配置片段也贴不进来。现在编辑器只显示配置文件里这一家的部分，位置和格式都和文件一致：

- **Kimi Code**：`config.toml` 里的 `[providers.<key>]` 和它的 `[models."..."]` 表。
- **MiniMax Code**：YAML 里的 `custom_provider.<key>`。
- **Oh My Pi**：`models.yml` 里的 `providers.<key>`。

标题显示实际的文件路径，会跟着目录覆盖和 `KIMI_CODE_HOME` 这类变量变化。草稿有格式错误、写了别家的节点、或者写了 `default_model` 这类全局设置时会提示并拒绝保存，改好之前上方的表单字段暂时不能改，避免把草稿覆盖掉。在编辑器里写的注释不会保存。DeepSeek Harness 的供应商在 profile 补丁里，仍用 JSON 编辑器。

### 经路由连 Gemini 时，思考档位也能发过去

以前 Claude Code、Claude Desktop 经路由转成 Gemini 原生格式时，客户端选的思考档位和「关闭思考」都被丢掉，Gemini 一律用模型的默认设置。现在按 Gemini 自己的 OpenAI 兼容接口的换算方式发：

- **Gemini 2.5**：低、中、高分别是 1024、8192、24576 的思考预算。关闭思考时 Flash 和 Flash-Lite 发 0，Pro 不能关，发最小的 128。
- **Gemini 3 及以后**：发 low、medium、high 档位（Gemini 3 Pro 没有 medium，发 high）。这些模型都不能关闭思考，关闭时发支持的最低档。
- 认不出的模型、图片和语音这类模型、名字里已经带档位的中转别名（如 `gemini-3-pro-high`）不发，请求里本来没有思考设置时也不发。

### 授权中心「全部刷新」

授权中心页头多了「全部刷新」按钮，一次重新查询页面上所有账号的额度（DeepSeek 是余额），各行照常显示更新中（[#9073](https://github.com/farion1231/cc-switch/pull/9073)）。

## 改进

**Claude Code、Claude Desktop 经路由连 OpenAI 格式的上游时，思考档位能发给更多模型**（[#9062](https://github.com/farion1231/cc-switch/issues/9062)）。以前只有 o 系列、GPT-5 以上和 Grok 4.5 以上会收到思考档位，DeepSeek 等其他模型静默丢掉，日志里也没有记录。现在：

- 认得出的供应商按它支持的档位发，比如 DeepSeek 发 low、high、max，OpenRouter 最高到 xhigh；Kimi、GLM、Qwen、MiniMax 这类 OpenAI 接口不收这个参数的不发。
- 认不出的上游只发 low、medium、high，选 xhigh、max 时发 high。
- GPT-3.5、GPT-4、Llama、Mistral 不发；关掉思考时不发。
- 两个应用的供应商表单在这两种格式下多了「思考档位」：「自动（推荐）」按上面的规则发；「原样发送」客户端选哪档发哪档，上游不支持 xhigh 或 max 时会报错；「不发送」用于上游因这个参数报错的情况。托管账号的卡片不显示这一项。

Codex 经路由连 DeepSeek 时的档位换算也改成和 DeepSeek 官方一致：minimal、low 发 low，medium、high、xhigh 发 high，max 发 max。以前 low 会被提到 high，xhigh 会被提到 max。

**Antigravity、MiniMax Code 的用量记录有了耗时和首字时间。** 以前这两个应用的用量里没有速度和首字时间。以前导入的记录也会补上。

**Skills 的发现页和已安装页改成同一种行样式**（[#9081](https://github.com/farion1231/cc-switch/pull/9081)）。仓库名用小号等宽字放在名称旁边，不再显示目录路径；「打开文档」按钮移到最右边；「已安装 · N 个应用」改成「已安装 ›」。从发现页点「已安装」跳过去时，那一行会黄色闪两下再恢复。

**托盘里绑了账号的 Claude 官方卡显示账号**（[#9071](https://github.com/farion1231/cc-switch/pull/9071)）。以前副标题都是 `www.anthropic.com`，有好几张官方卡时分不出来。现在有备注显示备注，没有备注显示账号（邮箱，没有邮箱时显示组织名）；账号不在这台电脑上时仍显示官网。

**Claude Desktop 路由模式下，Haiku 档的模型名改成 `claude-haiku-5-5`**（[#9096](https://github.com/farion1231/cc-switch/issues/9096)）。Claude Desktop 把 `claude-haiku-4-5` 当成旧模型，Haiku 档选不了思考档位。上游本身是旧版 Claude Haiku 时不改。直连模式不受影响。

**Grok Build 补上了 grok-4.6-build、grok-4.7-build、grok-4.7-build-fast 的价格**（[#9026](https://github.com/farion1231/cc-switch/pull/9026)）。

**预设：** 新增 OpenAI API Key 预设、13 家供应商的 Gemini CLI / Antigravity 预设（[#9089](https://github.com/farion1231/cc-switch/issues/9089)），以及讯飞 Astron MaaS 按量付费的 Claude Code 预设（[#9036](https://github.com/farion1231/cc-switch/issues/9036)）。

## 修复

- **Windows 上进入轻量模式后，再次启动 CC Switch，主窗口不出来，托盘也没反应，重启也没用**（[#9090](https://github.com/farion1231/cc-switch/issues/9090)）。
- **经路由连 OpenAI 格式的上游、且上游对非流式请求也返回 SSE 时，切换模型报「Unable to validate model」**（[#9097](https://github.com/farion1231/cc-switch/pull/9097)、[#9095](https://github.com/farion1231/cc-switch/issues/9095)）。现在非流式请求会收到完整的 JSON 响应。
- **DeepSeek Harness 的 profile 通过符号链接指向同一个文件时，编辑供应商、MCP 一律报冲突**（[#9101](https://github.com/farion1231/cc-switch/pull/9101)、[#9100](https://github.com/farion1231/cc-switch/issues/9100)）。
- **Grok Build 的会话日志超过 50 MiB 后整个跳过，长会话的用量一直不统计**（[#9026](https://github.com/farion1231/cc-switch/pull/9026)、[#6660](https://github.com/farion1231/cc-switch/issues/6660)）。现在逐行读取，之后只读新增的部分。
- **Codex 的分支会话在父会话闲置一段时间后一直不导入，用量统计不到**（[#9093](https://github.com/farion1231/cc-switch/pull/9093)、[#9094](https://github.com/farion1231/cc-switch/issues/9094)）。
- **DeepSeek Harness、MiniMax Code、Kimi Code 在用量查询里测试官方余额或 Coding Plan 时提示「API key is empty」**（[#9108](https://github.com/farion1231/cc-switch/pull/9108)、[#9107](https://github.com/farion1231/cc-switch/issues/9107)）。已保存的查询本来就正常，只是测试和自定义模板读不到供应商的 Key 和地址。
- **供应商表单里，改了地址、Key、模型这些字段，再改下方的配置编辑器（或反过来），先改的内容有时被覆盖回去**（[#6777](https://github.com/farion1231/cc-switch/pull/6777)）。
- **启动时界面要等后台的会话用量同步做完才响应**（[#9098](https://github.com/farion1231/cc-switch/pull/9098)、[#9084](https://github.com/farion1231/cc-switch/issues/9084)）。
- **Codex 经 OpenRouter 用 DeepSeek V4 Flash 0731 时，对话里有图片就报 404**（[#6194](https://github.com/farion1231/cc-switch/pull/6194)、[#6176](https://github.com/farion1231/cc-switch/issues/6176)）。
- **Windows 上「本地环境检查」会打开 OpenCode 桌面版**（[#7027](https://github.com/farion1231/cc-switch/pull/7027)、[#6973](https://github.com/farion1231/cc-switch/issues/6973)）。
- **macOS 上添加供应商时，图标选择页的返回按钮被红绿灯挡住**（[#9076](https://github.com/farion1231/cc-switch/pull/9076)、[#9075](https://github.com/farion1231/cc-switch/issues/9075)）。
- **开着本地路由时，MiniMax Code、DeepSeek Harness 表单里拉取到的模型列表两秒后就消失**（[#9068](https://github.com/farion1231/cc-switch/pull/9068)）。
- **MiniMax Code、DeepSeek Harness、Kimi Code 的 Key 输入框用输入法输入时字母重复**（[#9069](https://github.com/farion1231/cc-switch/pull/9069)）。
- **用 mise 安装的 Claude Code，在授权中心添加 Claude 账号时报「default installation is ambiguous」。**
- **ChatGPT 登录真的过期时，CC Switch 一直当成临时错误重试，不提示重新登录**（[#9049](https://github.com/farion1231/cc-switch/pull/9049)）。同一个 PR 还修了 Gemini 的 `.env` 里 `export` 开头的泄漏凭据清不掉。
