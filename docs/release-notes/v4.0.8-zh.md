# CC Switch v4.0.8

### 4.0 正式版的第四个修复版本

只装了 Codex 桌面版、没有单独装 Codex 命令行的用户，现在也能用 Codex 聚合模式了。官方模型列表读不到时，提示会写明原因，问题解决后提示也会自己消失。添加和编辑供应商时，「获取模型列表」会带上你配置的请求头，需要额外请求头的网关不会再拒绝。「设置 → 数据」新增「打开日志」按钮。深色模式的文字调暗了一些，不再那么刺眼。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

---

## 新增

**「设置 → 数据 → 应用诊断日志」新增「打开日志」按钮。** 点击后会在系统的文件管理器里选中 `cc-switch.log`；日志文件还没生成时打开日志所在的文件夹。报告问题时可以直接把它附上，不用再去找隐藏的配置目录。

## 修复

- **只装了 Codex 桌面版时，聚合页提示「读取不到 Codex 模型列表」，聚合模式用不了。** 联网获取官方列表失败时，CC Switch 会改用 Codex 命令行自带的模型列表，但以前只在系统路径里找 `codex` 命令。只装桌面版的用户没有这个命令，所以一直失败。现在找不到时会再去用 Codex 桌面版自带的命令行：macOS 上找「应用程序」里的 ChatGPT.app 和改名前的 Codex.app，两个都在时用 ChatGPT.app，避免旧的 Codex.app 给出过时的模型列表；Windows 上找桌面版安装目录里最新的一个版本。单独安装的 Codex 命令行仍然优先。
- **官方模型列表读不到时，提示看不出原因，问题解决后提示也不会消失。** 以前所有原因都显示成同一句「读取不到 Codex 模型列表」。现在提示下面会列出具体原因，并告诉你怎么处理：Codex 没有可用的 ChatGPT 登录、登录超过 8 天没有刷新、登录信息不完整、读不到 Codex 版本、联网获取失败、返回的数据不完整；Codex 自带的列表则分为找不到 Codex 命令行、命令行没能输出列表、列表里没有能用的模型。联网失败和命令行失败的详细信息会写进日志。另外，以前换用备用列表后，即使官方列表后来恢复了（比如过期的登录被 Codex 自动刷新），提示也要等你下次手动切换才会消失；现在 CC Switch 会自动换回官方列表，提示随之消失。
- **「获取模型列表」不带你配置的请求头，需要额外请求头的网关会拒绝。** 比如 Cloudflare AI Gateway 要求 `cf-aig-authorization` 请求头。现在 OpenCode 供应商会带上它配置的请求头；Claude Code、Codex 和 Grok Build 供应商会带上「Header 覆盖」里填的请求头，格式不对或留空时照常获取。在 Codex 和 Grok Build 的表单里修改「Header 覆盖」后，已经获取的模型列表会清空，避免选到当前身份用不了的模型。
- **深色模式的文字太亮，看久了刺眼。** 三档文字颜色都接近纯白，满屏表格和标签时显得很冲，主次也分不清。现在三档都调暗了一些，次要文字在卡片和选中背景上仍然保持足够的对比度。浅色模式没有变化。

**其他：**
- v4.0.7 发布说明里「压缩 Codex 历史会话」一节补充了怎么打开、什么时候压缩、怎么继续旧会话、CC Switch 里怎么显示和需要注意的地方。
- 英文和日文的额度显示说明、英文、日文和繁体中文的备份提示，改用界面上实际显示的名称。
