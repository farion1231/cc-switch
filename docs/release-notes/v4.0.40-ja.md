# CC Switch v4.0.40

今回のリリースでは、**Grok Build の公式カードに「アカウント」ページの xAI アカウントを紐付けられる**ようになり、Claude や Codex の公式カードと同じように複数の Grok アカウントを切り替えられます。**プラグイン画面**が Antigravity CLI に対応しました。**使用量統計**のプロバイダー別とモデル別の一覧にキャッシュヒット率が加わりました。**Xiaomi MiMo** の残高と Token Plan のクォータ照会を内蔵しました。「アカウント」ページのアカウントカードは、サイドバーのアプリの並び順と非表示の設定に従います。

このほか、ワンクリックインポートのリンクによる MCP のインポート、使用量スクリプト、SQL のインポート、ループバック以外の待ち受けアドレスのセキュリティチェックを強化し、データベース、ローカルルーティング、使用量の同期、セッション検索、「アプリ」ページを高速化しました。また、Kimi Code Desktop のメインエージェントの使用量が集計されない問題、4.0.38 から Antigravity の出力速度が実際より高く表示される問題、T3 Code や単独で実行した ACP の Antigravity セッションが表示されない問題、Mistral 公式 API で思考を有効にすると応答が空になる問題、Kimi のネイティブ Responses で画像を見るツールを並列に呼び出した後ずっと 400 になる問題、WorkBuddy の企業アカウントのクレジットが使い切ったと表示される問題、トレイに xAI のクォータが表示されず公式アカウントがサイトのドメインとして表示される問題、Skills ページの「見つける」に同じスキルが重複して表示される問題、「アプリ」ページがバージョンチェックの完了までインストール状態を表示しない問題などを修正しました。

## 新機能

### Grok 公式カードに xAI アカウントを紐付け

Grok Build の Grok Official フォームに「ログイン方法」が追加されました（[#9321](https://github.com/farion1231/cc-switch/pull/9321)、[#8599](https://github.com/farion1231/cc-switch/issues/8599) をクローズ）。「アカウント」ページの xAI アカウントを選ぶか、「xAI アカウントを追加・管理」、または「Grok CLI のログインに従う」を選べます。使い方は Claude や Codex の公式カードと同じです。

- 紐付けたアカウントごとに別のカードになり、カード名にアカウントが付きます。カードはいくつでも追加できます。アカウントを紐付けないカードは、これまでどおりの固定のカードです。
- アカウントを紐付けたカードに切り替えると、CC Switch はまずそのアカウントのログインを更新してから、Grok CLI の `~/.grok/auth.json` に書き込みます。ファイルのほかの内容は変更しません。Grok CLI がすでにそのアカウントでログインしている場合は書き込みません。ネットワークが一時的に失敗したときはしばらくしてから再試行するよう表示し、アカウントが本当に無効になっている場合だけ「アカウント」ページで再ログインするよう表示します。
- アカウントを切り替える前に、Grok CLI で現在ログインしているアカウントを「アカウント」ページに取り込みます。「Grok CLI のログインに従う」カードに戻すと、初めて切り替える前のアカウントに戻ります。
- 「アカウント」ページでアカウントを削除したとき、Grok CLI が使っているのが CC Switch がそのアカウントのために書き込んだログインであれば、元のログインに戻します。元のアカウントもなくなっている場合はログアウトします。
- アカウントを紐付けたカードは、カード、使用量、トレイのクォータをすべてそのアカウントで照会します。アカウントを紐付けていないカードは、Grok CLI のログインの期限が切れているとき、「アカウント」ページにある同じユーザーのアカウントでクォータを照会します。

### Antigravity CLI のプラグイン

「プラグイン」画面が Antigravity CLI に対応しました（[#9882](https://github.com/farion1231/cc-switch/pull/9882)、[#9885](https://github.com/farion1231/cc-switch/pull/9885)）。ほかのアプリと同じく `agy` 自身のコマンドラインを呼び出し、「見つける」で公式とパートナーのマーケットプレイスのプラグインを閲覧して、インストール、有効化、無効化、アンインストール、更新ができます。

- 更新の前にマーケットプレイスのバージョン番号を比較し、すでに最新なら再インストールしません。
- プラグインが実行中の Antigravity セッションやバックグラウンドサービスで使用中のときは、それらを閉じてから再試行するよう表示します。
- 旧バージョンの Antigravity アプリがインストールしたプラグインは数字の名前のフォルダーにあり、CC Switch では更新できないため、アンインストールしてから「見つける」で再インストールするよう表示します。

### 使用量統計：プロバイダー別・モデル別のキャッシュヒット率

使用量統計の「プロバイダー」と「モデル」の一覧で、「トークン」の後ろに「ヒット率」の列が加わり、どのプロバイダー、どのモデルでキャッシュが効いていないかがわかります。計算方法はリクエストログのヒット率と同じ（キャッシュヒット ÷ キャッシュ可能な入力）で、各行のキャッシュヒットとキャッシュ可能な入力を合計すると上部の合計と一致します。キャッシュ可能な入力がない行は「—」と表示します。

### Xiaomi MiMo の残高と Token Plan のクォータ

Xiaomi MiMo のプロバイダーに 2 種類の公式の照会を内蔵しました（[#9404](https://github.com/farion1231/cc-switch/issues/9404) をクローズ）。コンソールの Cookie を取得する使用量スクリプトに頼る必要はなくなりました：

- Token Plan（`tp-` で始まるキー）：使用量と合計クォータ、今期の終了日時を表示します。
- 残高（`sk-` で始まるキー）：利用可能な残高（凍結分を除く）を表示します。残高が 0 でもキーが無効とは判定しません。

### 「アカウント」ページのカードがサイドバーのアプリに従う

「アカウント」ページのアカウントカードは、「アプリ」ページでドラッグしたアプリの順に並びます。そのアカウントを使うアプリがすべて非表示になっている場合だけカードを非表示にします（Copilot、ChatGPT、xAI のアカウントは Claude Code などのアプリのプロバイダーでも使われます）。プロバイダーフォームから移動してきたカードは常に表示されます。

### 新しいプリセット

StringAI を追加しました。

## 変更

- **データベースとローカルルーティングを高速化**（[#9820](https://github.com/farion1231/cc-switch/pull/9820)、[#9821](https://github.com/farion1231/cc-switch/pull/9821)）：メインデータベースを WAL モードにし、ルーティングがリクエストごとに読む設定、ルート、料金、フェイルオーバーキューをキャッシュから読むようにしました。ルーティングのデータベース処理は別のスレッドで実行し、リクエストを処理するスレッドを占有しないようにしました。リクエストを転送するときに会話内容のコピーを 1 回減らし、書き換えていないリクエストではプライバシーフィルターを重ねて実行しないようにしました。
- **使用量の同期を高速化**（[#9817](https://github.com/farion1231/cc-switch/pull/9817)、[#9818](https://github.com/farion1231/cc-switch/pull/9818)）：各アプリのセッションログを並列にスキャンします。使用量スクリプトは別のスレッドで実行され、ほかのリクエストを遅くしなくなりました。
- **セッション内容の検索を高速化**（[#9827](https://github.com/farion1231/cc-switch/pull/9827)、[#9896](https://github.com/farion1231/cc-switch/pull/9896)）：1〜2 文字の検索で本文全体をスキャンしなくなりました。入力を続けると、前回の終わっていない検索はキャンセルされます。検索インデックスの形式が変わったため、アップグレード後の最初の検索でインデックスを再構築します。
- **「アプリ」ページの表示を高速化**（[#9418](https://github.com/farion1231/cc-switch/pull/9418)、[#9886](https://github.com/farion1231/cc-switch/pull/9886)、[#9884](https://github.com/farion1231/cc-switch/issues/9884) をクローズ）：各ツールのバージョンチェックを待たずに、まずこのマシンのインストールパスから「インストール済み」/「未インストール」のグループを表示します。各ツールのバージョンは同時にチェックし、終わったものから順に表示します。

## セキュリティ

- **ワンクリックインポートのリンクによる MCP のインポート**（[#9831](https://github.com/farion1231/cc-switch/pull/9831)）：確認ダイアログに MCP サーバーのすべてのフィールド（作業ディレクトリ、リクエストヘッダーなどを含む）を表示し、危険度の高いフィールドは赤で警告します。このマシンの環境変数を読み取る、補助コマンドを実行する、作業ディレクトリをネットワーク共有のパスに向ける、またはアドレスが http / https 以外の設定は、インポートを拒否します。
- **使用量スクリプト**（[#9829](https://github.com/farion1231/cc-switch/pull/9829)）：スクリプトが送るリクエストはリダイレクトに従わなくなり、CC Switch 自身のルーティングのポートには送れず、レスポンスは最大 2 MiB まで読み取ります。スクリプトに入れるキーやアドレスなどの変数は正しくエスケープされます。ワンクリックインポートのリンクに含まれる使用量照会のアドレスもチェックし、プライベートネットワークやこのマシンのアドレスの場合は確認ダイアログで警告します。
- **SQL のインポート**（[#9832](https://github.com/farion1231/cc-switch/pull/9832)）：SQL バックアップや WebDAV / S3 の同期スナップショットをインポートするとき、トリガーとビューは作成できず、ファイルは最大 512 MiB で、実行が 30 秒を超えると中止します。
- **ループバック以外の待ち受けアドレスでの Host チェック**（[#9833](https://github.com/farion1231/cc-switch/pull/9833)）：ルーティングサービスが `0.0.0.0` / `::` で待ち受けているとき、このマシンからのリクエストも DNS リバインディング対策の Host チェックを通る必要があります。

## 修正

- **Kimi Code Desktop のメインエージェントの使用量が集計されない**（[#9505](https://github.com/farion1231/cc-switch/pull/9505)、[#9498](https://github.com/farion1231/cc-switch/issues/9498) を参照）：Kimi Code Desktop 1.3.5 でセッションログの形式が変わり、メインエージェントの使用量が飛ばされ、サブエージェントのモデルが `unknown` と表示されていました。現在は両方の形式を読み取れ、重複して数えることもありません。アップグレード後に古いログを一度スキャンし直し、これまで漏れていた使用量とモデルを補います。
- **Antigravity の出力速度が実際より高く表示される**（[#9858](https://github.com/farion1231/cc-switch/pull/9858)）：4.0.38 から、思考に時間がかかったリクエストで数万 tok/s と表示されることがありました。Antigravity の出力トークンには隠れた思考が含まれ、最初のトークンまでの時間にも思考の時間が含まれるため、全体の所要時間で計算する方式に戻しました。
- **T3 Code と単独で実行した ACP の Antigravity セッションが表示されない**（[#9857](https://github.com/farion1231/cc-switch/pull/9857)、[#9838](https://github.com/farion1231/cc-switch/issues/9838) を参照）：これらのセッションがセッション一覧と使用量統計に表示されるようになりました。使える再開コマンドはなく、CC Switch から削除することもできません。T3 Code が質問の外側に付け加える説明は取り除き、タイトルには元の質問を表示します。
- **Mistral 公式 API で思考を有効にすると応答が空になる**（[#9902](https://github.com/farion1231/cc-switch/issues/9902) を参照）：思考を有効にした Mistral 公式 API（Mistral が提供するサードパーティのモデルを含む）は、応答を思考と本文の 2 種類のチャンクに分けて返すため、ローカルルーティングが読み取れず、応答が空になるか思考過程が表示されませんでした。現在は両方のチャンクを順番どおりに読み取ります。上流に送るリクエストは変わりません。
- **Kimi のネイティブ Responses で画像を見るツールを並列に呼び出した後、ずっと 400 になる**（[#8825](https://github.com/farion1231/cc-switch/pull/8825)、[#7504](https://github.com/farion1231/cc-switch/issues/7504) を参照）：Codex Desktop は並列ツール呼び出しの結果の間に通知を挿入しますが、Kimi のように厳格なネイティブ Responses の上流は呼び出しの直後にない結果を捨ててしまうため、そのセッションではそれ以降のターンが毎回 400 になっていました。現在はまずこの呼び出しの結果をまとめて並べ、挿入された通知はその後ろに置きます。
- **WorkBuddy の企業アカウントのクレジットが使い切ったと表示される**（[#9694](https://github.com/farion1231/cc-switch/issues/9694) を参照）：企業アカウントでは企業の使用量を照会し、合計クォータ、使用量、有効期限を表示します。無制限の場合は「無制限、使用 N」と表示し、クォータを取得できないときは「使い切りました（全 0）」ではなく照会の失敗として表示します。
- **トレイに xAI のクォータが表示されない**（[#9899](https://github.com/farion1231/cc-switch/issues/9899) を参照）：Codex と Claude Code の xAI OAuth プロバイダー（Codex の集約のメンバーを含む）も、トレイで紐付けた xAI アカウントのクォータを表示します。紐付けていない場合は「アカウント」ページのデフォルトアカウントを使い、メイン画面のカードと同じになります。
- **トレイで公式アカウントがサイトのドメインとして表示される**（[#9863](https://github.com/farion1231/cc-switch/pull/9863)）：管理アカウントを紐付けた Codex 公式カード、および Codex OAuth、GitHub Copilot、xAI OAuth のカードでは、トレイのサブタイトルにログインしているアカウントを表示します（手動のメモを優先）。メイン画面の xAI OAuth カードにもアカウントを表示します。「アカウント」ページでログイン、デフォルトアカウントの切り替え、削除、ログアウトをすると、トレイも更新されます。
- **Skills ページの「見つける」に同じスキルが重複して表示される**：同じリポジトリ内で末端のフォルダー名が同じ 2 つのスキルは同じフォルダーにインストールされるため、「見つける」でこれまで 2 行に分かれて表示されていました。現在はリポジトリのルートに最も近いものだけを表示します。
- **OpenCode Desktop に同梱の CLI に npm でのアップグレードを案内する**（[#9099](https://github.com/farion1231/cc-switch/pull/9099)）：この CLI のインストール元を OpenCode Desktop と表示し、Desktop アプリと一緒に更新されることを説明します。「すべて更新」の対象にも含めません。単体でインストールした OpenCode はこれまでどおりアップグレードできます。
- **64 MiB の上限に近いストリーミングイベントが誤って飛ばされる**（[#9867](https://github.com/farion1231/cc-switch/pull/9867)）：4.0.39 で追加したバッファーの上限をイベント単位で判定するようにしたため、上限に近い正常なイベントが同じチャンク内の次のイベントと一緒に捨てられることはなくなりました。

## アップグレード時の注意

- ルーティングサービスが `0.0.0.0` / `::` で待ち受けていて、このマシンからカスタムのホスト名（`.local`、`.internal`、`.localhost` で終わらないもの）でルーティングにアクセスしている場合、アップグレード後は 403 になります。設定の「ローカルルーティング」にある「接続先アドレス」にそのホスト名を入力してください（このアドレスは各クライアントの設定にも書き込まれます）。LAN、WSL、Docker 内のほかのデバイスには影響しません。
- セッション内容の検索インデックスはアップグレード後の最初の検索で再構築されるため、セッションが多い場合は最初の検索に少し時間がかかります。
