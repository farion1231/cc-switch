# CC Switch v4.0.30

This release adds a **Privacy Filter**: in Routing and Aggregation modes, local routing can replace personal data and secrets in user input and system prompts with placeholders before forwarding a request, so they are never sent upstream. It is off by default; the switch is in "Settings → Data".

Fixes cover Codex requests routed to a third-party native Responses upstream carrying fields only OpenAI accepts and being rejected outright (400); Codex chats reporting 400 on every turn once a repeated key appeared in tool-call arguments; the main window on Windows opening under the taskbar with buttons out of reach; Antigravity free accounts getting 403 when checking quota, and region-locked accounts giving no hint why; Antigravity usage sync re-reading every session each minute and maxing out the CPU; and more.

---

## New

### Privacy Filter

When on, local routing replaces personal data and secrets in user input and system prompts with placeholders such as `[EMAIL]` and `[SECRET]` before forwarding a request ([#8951](https://github.com/farion1231/cc-switch/pull/8951)). The switch is in "Settings → Data → Privacy Filter", off by default.

- **What is replaced**: email addresses, mainland China mobile numbers, ID card numbers, bank card numbers, IPv4 addresses (except loopback addresses such as 127.0.0.1), plus API keys, tokens, private keys, and credentials written inline such as "password: …" or "api_key=…".
- **What is left alone**: model replies, thinking, tool-call arguments and images.
- **Tool results** (file contents, command output, etc.) are not processed by default; turn them on with the "Also filter tool results" sub-switch. Once it is on, the model sees only placeholders, so edits may fail because they no longer match the original text, and a full-file rewrite may write placeholders back into your files. Turn it on only if you accept that.
- It applies only in Routing and Aggregation modes. In Direct mode, requests don't pass through CC Switch and are not filtered.
- It runs entirely on this computer with rule-based matching and calls no model; replacements can't be undone, and placeholders follow the interface language (Korean and Russian use the English ones for now). The rules are ported from [packyme/privacy-filter](https://github.com/packyme/privacy-filter).

### New model prices

- Built-in prices for Claude Fable 5.2 ([#9426](https://github.com/farion1231/cc-switch/pull/9426)) and Gemini 4 Carbon ([#9421](https://github.com/farion1231/cc-switch/pull/9421), at the introductory price valid through November 30), so usage statistics no longer show "Unpriced" for them. Prices you have already entered yourself are not overwritten.

## Changes

- **The provider editor opens faster** ([#9357](https://github.com/farion1231/cc-switch/pull/9357)): the first edit after a restart used to take 1–2 seconds, with many providers opening and closing the editor also stuttered, and typing in the name field lagged behind. The editor is now preloaded while the app is idle after startup, and opening, closing and typing no longer slow down the whole list.
- **Codex OAuth cards show the account** ([#9300](https://github.com/farion1231/cc-switch/pull/9300)): on Codex OAuth provider cards in Claude Code and Claude Desktop, the subtitle changes from the ChatGPT pricing page URL to "account · plan", matching other official account cards.
- **The Copilot official login card moves into "Added"**: it no longer takes a group of its own and is listed first among the added providers.
- **After you edit `SKILL.md` by hand, the Skills page updates the name and description** ([#9316](https://github.com/farion1231/cc-switch/pull/9316), related [#7848](https://github.com/farion1231/cc-switch/issues/7848)): this is checked in the background, instead of scanning every skill directory when the Skills page opens or a switch is toggled.

## Fixes

- **Codex routed to a third-party native Responses upstream had whole requests rejected with 400** ([#9042](https://github.com/farion1231/cc-switch/issues/9042), [#9077](https://github.com/farion1231/cc-switch/pull/9077)). Since v4.0.28, when a ChatGPT login is present, third-party routes are also written as Codex's built-in `openai`, so Codex sends fields that only OpenAI itself accepts, and strict upstreams such as LM Studio, LiteLLM and some relays reject the whole request. Now, for third parties, all of these fields are removed the same way Codex itself handles non-OpenAI upstreams; official cards and ChatGPT accounts in Accounts are unaffected.
- **Once a repeated key appeared in tool-call arguments, every turn of the Codex chat reported 400 and the chat could not continue** ([#9339](https://github.com/farion1231/cc-switch/issues/9339), [#9341](https://github.com/farion1231/cc-switch/pull/9341)). Models occasionally write the same argument twice in one tool call, and since Codex resends the history as is on every turn, strict upstreams kept rejecting it. Now, before sending to a third-party native Responses upstream, only the last of the repeated keys is kept; the official upstream is unaffected.
- **On Windows, the bottom of the main window opened behind the taskbar, so the update dialog's buttons could not be clicked, even after a restart** ([#9206](https://github.com/farion1231/cc-switch/issues/9206), [#9336](https://github.com/farion1231/cc-switch/pull/9336)). At startup, the window is now moved back into the usable area of the screen, and shrunk if it is too large; the same applies on macOS when the Dock covers it.
- **Antigravity free accounts got "403 You do not have a valid license of this product" when checking quota; region-locked accounts showed their quota as usual in Accounts, with no hint why they could not sign in** ([#9413](https://github.com/farion1231/cc-switch/issues/9413), [#9414](https://github.com/farion1231/cc-switch/pull/9414)). Quota is now checked the same way as `agy` does it; when Google marks an account as ineligible (for example, region not supported), Google's reason is shown.
- **After `agy` was upgraded to 1.5, Accounts did not recognize the Antigravity account in use; after switching accounts, Antigravity official cards not bound to an account still showed the previous account's quota** ([#9318](https://github.com/farion1231/cc-switch/issues/9318), [#9320](https://github.com/farion1231/cc-switch/pull/9320)).
- **With many Antigravity sessions, CC Switch kept one CPU core busy in the background and read the disk heavily** ([#9346](https://github.com/farion1231/cc-switch/pull/9346)). It used to read every session record in full twice a minute; sessions that haven't changed are now skipped.
- **When Gemini was used through routing, usage for streaming requests was recorded under the model name in the request rather than the model that actually answered; successful requests to Vertex AI-style upstreams left no record in usage statistics** ([#7738](https://github.com/farion1231/cc-switch/issues/7738), [#7740](https://github.com/farion1231/cc-switch/pull/7740)).
- **Copilot providers with their own Key still limited input to 128K for models that had "Context window" and "Max output tokens" set but no "Max prompt tokens"**: "Context window − Max output tokens" is now written as the max prompt tokens; values you set yourself are unchanged.
- **On Windows without Copilot CLI but with VS Code installed, Copilot CLI showed as "Installed · can't run"**: the Copilot placeholder program bundled with VS Code is no longer mistaken for Copilot CLI, which now correctly shows as not installed.
- **On macOS and Linux, the update summary shown after an upgrade was squashed down to a single line** ([#9401](https://github.com/farion1231/cc-switch/pull/9401)).
- **None of the buttons in OpenCode's Oh My OpenCode Slim form responded to clicks** ([#2067](https://github.com/farion1231/cc-switch/issues/2067), [#3905](https://github.com/farion1231/cc-switch/pull/3905)).
- **The README / CHANGELOG links at the bottom of the v3.7.0–v3.8.0 release notes were broken** ([#7744](https://github.com/farion1231/cc-switch/issues/7744), [#7750](https://github.com/farion1231/cc-switch/pull/7750)).
