# CC Switch v4.0.38

今回のリリースは修正が中心です。ワンクリックインポートのリンクで **WorkBuddy** のプロバイダーをインポートできるようになり、Linux でも「アカウント」ページで **Antigravity** のアカウントを切り替えられるようになりました。Antigravity のセッション一覧に空のセッションや内部のサブセッションが混ざらなくなり、セッションリーダーで思考、ツール呼び出し、その結果を確認できます。

このほか、DeepSeek Harness の設定ファイルが一部の YAML ツールを経由すると、サードパーティのプロバイダーがすべて消える問題、Finder から CC Switch を開くと「アプリ」ページが正常に使える npm のインストールを「実行できません」と表示する問題、スキルリポジトリが GitHub / GitLab / Gitea でないときにエラーにならず「検出スキル: 0 件」とだけ表示される問題、Codex でモデルに選んだ思考レベルが反映されないことがある問題、Codex のルーティング経由での形式変換のいくつかの誤り、使用量の二重計上、セッションの本文検索に失敗したときに「含むセッションはありません」と表示される問題、メイン画面が細い白い帯になったり macOS のメニューバーに隠れたりする問題、Linux の AppImage でリンクをクリックしても反応しない問題などを修正しました。

## 新機能

### WorkBuddy でワンクリックインポートのリンクに対応

`ccswitch://` のプロバイダーリンクで WorkBuddy のプロバイダーをインポートできるようになりました（[#9768](https://github.com/farion1231/cc-switch/pull/9768)）。作成されるカードは WorkBuddy ページで手動追加したものと同じです。

- リンクにはモデルが必須です。`apiFormat` は `openai_chat` のみ対応します。
- モデル ID がすでに別のカードで使われている場合、インポートは拒否され、作りかけのカードは残りません。

### Linux で Antigravity のアカウントを切り替え

Linux でも「アカウント」ページで agy のログインを管理してアカウントを切り替えられるようになり、公式カードに紐付けたアカウントのクォータが表示されます（[#9774](https://github.com/farion1231/cc-switch/pull/9774)、関連：[#9245](https://github.com/farion1231/cc-switch/issues/9245)）。

- ログイン情報はシステムのキーリング（Secret Service）に保存されます。キーリングがロックされているあいだ、バックグラウンドでの状態とクォータの取得はスキップし、手動でアカウントを切り替えるときにロック解除を求めます。
- Linux でアカウントを紐付けたカードでは、「ターミナルを開く」ダイアログに「今回の起動には agy の現在のログインを使用する」が加わりました。紐付けたアカウントがこの端末にない場合やキーリングが使えない場合も、現在のログインでターミナルを開けます。カードの紐付けはそのまま残ります。

## 変更

- **Antigravity のセッション一覧とセッションリーダー**（[#9266](https://github.com/farion1231/cc-switch/pull/9266)、関連：[#9265](https://github.com/farion1231/cc-switch/issues/9265)）：ターミナルで `/usage` を確認しただけで終了したときに残る空のセッション（`Jan 1` と表示されるもの）、削除済みのセッションやほかの端末から同期されてきた残りの記録、`/boost` のサブエージェントと `/btw` の脇道の質問は一覧に表示されなくなりました。これらの使用量は引き続き集計します。タイトルのないセッションは、プレビューまたは最初の質問をタイトルにします。セッションリーダーでは思考、本文、ツール呼び出し（MCP やブラウザなどを含む）、ツールの結果（コマンドの終了コードや中断状態を含む）を表示し、ファイルの変更は追加・削除の行数を示します。アップグレード後、セッションの本文インデックスは自動で一度再構築されます。
- **セッション検索と使用量統計を高速化**（[#9823](https://github.com/farion1231/cc-switch/pull/9823)、[#9825](https://github.com/farion1231/cc-switch/pull/9825)）：セッションページでアプリを切り替えるたびに、各セッションの ID とパスの検索インデックスを作り直すことはなくなり、メモリ使用量も大幅に減りました。使用量統計のクエリはデータベースのインデックスを使えるようになり、最初のトークンまでの時間は一度だけ読み取り、価格はクエリごとに一度だけ読み込みます。
- **「アカウント」ページで Google アカウントのプラン名から余分な「Google」を削除**（[#9834](https://github.com/farion1231/cc-switch/pull/9834)）：Antigravity と Gemini CLI のアカウントの「Google AI Pro」は「AI Pro」と表示されます。

## 修正

- **DeepSeek Harness でサードパーティのプロバイダーが突然すべて消える問題**（関連：[#9785](https://github.com/farion1231/cc-switch/issues/9785)）：`cordis.patch.yml` を一部の YAML ツールで保存すると、思考レベルの `off` が `false` に変わります。CC Switch はこれまでそれをそのまま保存し、同期のたびに書き戻していたため、DeepSeek Harness はこの不正なキー 1 つのためにプロバイダー設定全体を無効と判定していました。現在は読み込み時と書き込み時の両方で修正します（`false` は `off` に戻し、認識できないレベルは削除します）。
- **Finder から CC Switch を開くと、「アプリ」ページが正常に使える npm のインストールを「実行できません」と表示する問題**（関連：[#9810](https://github.com/farion1231/cc-switch/issues/9810)）：インストールの検出に使う PATH から node が見つからないため、`npm --prefix`、volta、pnpm、bun などでインストールしたコマンドラインツールが実行できないと判定され、画面では再インストールやアンインストールまで勧めていました。現在は検出時にログインシェルの PATH を使います。CC Switch がほかのコマンドラインツールを実行するときと同じです。Windows には影響しません。
- **対応していないサイト（cnb.cool など）のスキルリポジトリを追加すると、エラーにならず「検出スキル: 0 件」とだけ表示される問題**（関連：[#9812](https://github.com/farion1231/cc-switch/issues/9812)）：こうしたサイトはどのアドレスにもウェブページを返します。これまではダウンロードしたウェブページを ZIP アーカイブとして扱い、失敗しても何も表示しませんでした。現在は「ダウンロードしたものは ZIP アーカイブではありません。このサイトは GitHub / GitLab / Gitea のリポジトリではない可能性があり、現在はサポートされていません」と表示します。
- **Codex でモデルに手動で選んだ思考レベル（`max`、`ultra` など）が反映されないことがある問題**（[#9017](https://github.com/farion1231/cc-switch/pull/9017)、関連：[#8952](https://github.com/farion1231/cc-switch/issues/8952)）：モデル名が Codex の公式モデルと一致すると、生成されるモデルカタログには公式の思考レベルが使われていました。現在はカードで選んだとおりに書き込みます。
- **Codex のルーティング経由で Chat 形式に変換するとき、似た名前のツールの名前が衝突する問題**（[#9554](https://github.com/farion1231/cc-switch/pull/9554)、関連：[#9551](https://github.com/farion1231/cc-switch/issues/9551)）：ツール名や名前空間に `__` が含まれていると、これまではツールが失われたり、呼び出しが別のツールに送られたりすることがありました。現在はツールごとに一意の名前を付け、呼び出しを正しく元のツールに対応付けます。
- **Codex のルーティング経由でサードパーティのモデルを使った会話を、公式モデルに切り替えると続けられない問題**（[#9756](https://github.com/farion1231/cc-switch/pull/9756)、関連：[#9054](https://github.com/farion1231/cc-switch/issues/9054)）：変換で生成したメッセージ ID は `resp_` で始まりますが、公式 API は `msg_` で始まることを求めるため、直接接続モードでは `invalid_id_prefix` エラーになっていました。新しく生成する ID は `msg_` で始まるようにしました。すでに保存されている過去の会話は変わりません。
- **Codex のルーティング経由で AWS Bedrock 上の Claude に接続すると、すべてのリクエストが 400 になる問題**（[#8659](https://github.com/farion1231/cc-switch/pull/8659)、関連：[#6118](https://github.com/farion1231/cc-switch/issues/6118)）：ツール定義に OpenAI 専用の `strict` フィールドが余計に含まれており、Bedrock がそれを受け付けませんでした。現在はこのフィールドを転送しません。
- **使用量の二重計上**：
  - モデル名にゲートウェイのプレフィックスが付いている場合（`antigravity/gemini-3.8-flash-high` など）、同じリクエストがルーティングの記録と Codex のセッションログで 1 回ずつ計上されていました（[#9249](https://github.com/farion1231/cc-switch/pull/9249)）。現在はプレフィックスを除いてから照合します。
  - Gemini の古いセッションファイルが更新されると、アーカイブ済みの使用量が再びインポートされていました。また、セッション内のトークン数が変わっても更新されませんでした（[#9527](https://github.com/farion1231/cc-switch/pull/9527)、関連：[#9523](https://github.com/farion1231/cc-switch/issues/9523)）。
- **使用量統計で Codex のキャッシュ書き込みが N/A と表示される問題**（[#8191](https://github.com/farion1231/cc-switch/pull/8191)）：現在は実際の値を表示し、N/A のままなのは Gemini と Grok Build だけです（キャッシュ書き込みを報告しないため）。リクエストログでも Codex のキャッシュ書き込みを新規入力に含めなくなりました。
- **Antigravity の出力速度が推定値で表示され、実際より低く出る問題**（[#9788](https://github.com/farion1231/cc-switch/pull/9788)、関連：[#9787](https://github.com/farion1231/cc-switch/issues/9787)）：Antigravity は最初のトークンまでの時間とストリーミング出力の時間を自分で記録していますが、これまでは使っておらず、速度を合計時間（最初のトークンまでの待ち時間を含む）から推定していました。現在はルーティング経由のリクエストと同じく、実際の出力時間で計算します。
- **セッションの本文検索でエラーが起きたときに、「含むセッションはありません」と表示される問題**（[#9512](https://github.com/farion1231/cc-switch/pull/9512)、関連：[#9511](https://github.com/farion1231/cc-switch/issues/9511)）：現在は「本文検索に失敗しました。今はタイトル・ディレクトリ・最初と最後のメッセージだけで検索しています」と表示し、「再試行」をクリックできます。再試行時にはセッションをインデックスに取り込み直します。
- **OpenCode のセッションに関する 2 つの境界ケース**（[#7982](https://github.com/farion1231/cc-switch/pull/7982)）：新しい形式に移行した後に OpenCode 1.x で続けたセッションは、これまで古い内容が表示されていました。新しい形式への移行が途中で中断された場合も、移行しきれていないセッションが隠れなくなりました。
- **Oh My Pi のセッション再開コマンドを Windows の PowerShell に貼り付けるとエラーになる問題**（[#9153](https://github.com/farion1231/cc-switch/pull/9153)、関連：[#9152](https://github.com/farion1231/cc-switch/issues/9152)）：Windows では PowerShell の書き方で生成するようにしました。macOS と Linux は変わりません。
- **Linux の AppImage でリンクをブラウザで開いたりフォルダーを開いたりしても何も起きない問題**（[#9113](https://github.com/farion1231/cc-switch/pull/9113)、関連：[#9112](https://github.com/farion1231/cc-switch/issues/9112)）：AppImage に同梱された古い xdg-open は KDE Plasma 6 では何もしません。現在はシステム自身の xdg-open を使います。deb / rpm、macOS、Windows には影響しません。
- **macOS でフルスクリーンのメイン画面をトレイに閉じ、再び開くとメニューバーと Dock に隠れる問題**（[#9770](https://github.com/farion1231/cc-switch/pull/9770)、関連：[#9769](https://github.com/farion1231/cc-switch/issues/9769)）：現在はトレイに閉じる前にフルスクリーンを解除し、トレイや Dock などから再び開くときにフルスクリーンに戻します。
- **メイン画面を開くと細い白い帯だけになる問題**（[#9504](https://github.com/farion1231/cc-switch/pull/9504)、関連：[#9496](https://github.com/farion1231/cc-switch/issues/9496)）：記憶したウィンドウサイズが異常に小さい場合は、開くときに既定のサイズに戻します。
- **プロバイダーの編集中に、保存中のエディターを閉じて開き直すと「保存」ボタンが回り続ける問題**（[#9593](https://github.com/farion1231/cc-switch/pull/9593)、関連：[#9592](https://github.com/farion1231/cc-switch/issues/9592)）。
- **Copilot の旧バージョンのログインの移行が、ネットワークのタイムアウトで諦めてしまい、再起動しないと再試行されない問題**（[#9549](https://github.com/farion1231/cc-switch/pull/9549)、関連：[#9544](https://github.com/farion1231/cc-switch/issues/9544)）：現在はネットワークが回復した後、次に Copilot を使うときに再起動なしで移行を続けます。諦めるのはトークンが無効（401 / 403）なときかログアウトしたときだけです。
- **中継サービスのアドレスが公式ベンダーと誤認される問題**（[#9648](https://github.com/farion1231/cc-switch/pull/9648)）：アドレスのパスやパラメーターに公式のドメインが含まれている場合や、ドメインが似ている場合（`api.x.ai.example.com` など）、これまではそのベンダーとして扱われ、xAI は専用の処理を受け、残高やプランのクォータもそのベンダーの公式テンプレートで照会していました。現在は実際のドメインだけを見ます。
- **設定のインポートやクラウド同期のダウンロードなどの操作で、累加型のアプリの一部のプロバイダーが設定ファイルに書き込まれていないのに成功と表示される問題**（[#9747](https://github.com/farion1231/cc-switch/pull/9747)）：現在は書き込みに失敗したプロバイダーを一覧表示します。
- **スキルの保存場所を移動した後、一部のアプリで再リンクに失敗したのに成功と表示される問題**（[#9748](https://github.com/farion1231/cc-switch/pull/9748)）：現在はそれらのアプリを通知に一覧表示します。
