# CC Switch v4.0.25

本版本为 MCP 页面增加了连通性检查，可以一键检查所有已启用的 MCP 服务器能不能连上；Codex 经本地路由用官方账号时，可以在额度快用完前自动暂停官方请求，第三方模型照常可用。另外，用量页的汇率可以自动获取，Codex 供应商表单可以设置子代理并发上限，Claude Code 和 Claude Desktop 经路由或聚合时，模型菜单会写明每个模型来自哪个供应商、实际是哪个模型，会话管理里也能删除 Kimi Code 会话了。还修复了「打开终端」混入路由和聚合设置、路由模式下 OpenCode Go 等供应商让 Claude Code 要求重新登录、给纯文本模型发过一个文件后之后每轮都报错、Windows 上供应商表单内容来回闪、启动时托盘面板打不开、Codex 用了模型映射时用量算两遍等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

## 新增

### MCP 连通性检查

以前 MCP 服务器配好以后，只有在编程工具里用到时才知道能不能连上（[#4498](https://github.com/farion1231/cc-switch/issues/4498)）。

现在 MCP 页面顶部多了「检查连通性」按钮，会检查所有已启用的服务器；每一行的菜单里也有「测试连接」，只检查这一个。

- 打开页面时不会自动检查，没检查过的显示「未检查」；改了某个服务器的连接配置后，它的结果会重置。
- 检查方式是和服务器完成一次 MCP 握手，本地命令（stdio）、HTTP 和旧版 SSE 三种连接方式都支持。每个服务器最多等 30 秒，整个应用同时最多检查 3 个。
- 本地命令启动的服务器检查完会连同它启动的子进程一起结束，不会留下后台进程。macOS 和 Linux 上不从终端启动 CC Switch 时，也能找到 `npx`、`uvx` 这类命令。

### Codex 官方额度保护

Codex 用官方 ChatGPT 账号时，五小时或每周额度用完会进入 Reserve 模式。现在可以在额度快用完时先暂停官方请求，留着额度，第三方模型照常可用。

在「设置 → 应用配置 → Codex 应用增强」里打开「官方额度保护」，可以设置五小时和每周使用率的阈值（默认 95% 和 98%），任一达到就暂停新的官方请求。

- 只对经过 CC Switch 本地路由的 Codex 官方请求生效，默认关闭。
- 使用率直接读官方响应里自带的额度信息，正常使用时不会多发请求；刚开始用或空闲约 5 分钟后，才会先单独查询一次。
- 查不到额度（网络问题、登录过期等）时照常放行，不会误挡。被暂停的请求会直接返回错误，不会转到故障转移队列里的其他供应商。

### 用量页汇率自动获取

用量页「用量设置」里的「显示」区多了「汇率来源」，可以选「手动填写」（默认）或「自动获取」。选了自动获取才会联网，汇率超过 12 小时会自动更新，获取失败时继续用上次的汇率。自动获取的汇率和手动填的分开保存，切回手动填写时你自己填的值还在。费用仍按美元记录，只在显示时换算。

### Codex 子代理并发上限

Codex 供应商表单的「子代理模型」下面多了「子代理并发上限」，设置一个 Codex 会话里最多同时开多少个子代理（[#9055](https://github.com/farion1231/cc-switch/issues/9055)）。这是 Codex 的全局设置，写进 `config.toml` 的 `[agents] max_threads`，切换供应商时保持不变，官方卡片上也能改；留空就用 Codex 的默认值。

### 模型菜单写明供应商和实际模型

Claude Code 在路由模式下，`/model` 菜单里每一档以前只写「Custom Sonnet model」，看不出对应哪家供应商的哪个模型。现在会写成「供应商 · 实际模型 · 窗口」（窗口只在上游标了 1M 时显示），聚合模式下的模型也一样。供应商里自己写过模型说明的，以你写的为准。

Claude Desktop 在路由和聚合模式下，模型下面的说明以前按名字里的 Opus、Sonnet 套用官方文案，聚合模型一律显示同一句。现在也改成「供应商 · 实际模型 · 窗口」。

### 删除 Kimi Code 会话

会话管理里可以直接删除 Kimi Code 会话了，以前只能去 Kimi Code 里删。删除方式和 Kimi Code 自己的一样，子代理的历史会一起删掉。

**定价：** 内置价格表新增 GPT-6.1 Terra。

## 变更

- **本地路由不再接受网页发来的请求**。本地路由会把请求换成你保存的供应商凭据再转发，所以网页如果能把请求发到本地路由，就能用掉你的额度。现在带浏览器来源标记的请求会被拒绝，通过普通域名指向本机的访问也不再接受。编程工具发的请求不受影响。
- **Skills「发现」页的工具栏和「已安装」页对齐**（[#9125](https://github.com/farion1231/cc-switch/pull/9125)）：搜索框位置和宽度一致，刷新按钮改为「刷新仓库」文字按钮，来源、仓库筛选和「只看未安装」挪进表头，「安装到」放在表头右侧。少了一行，功能不变。
- **Windows 上首选终端是 PowerShell 时，装了 PowerShell 7 就用它打开**（[#8992](https://github.com/farion1231/cc-switch/pull/8992)、[#3271](https://github.com/farion1231/cc-switch/issues/3271)），没装才用系统自带的 Windows PowerShell。供应商卡片的「打开终端」和应用的安装、升级都是这样。
- **预设：** 千问 AI 平台和 QwenCloud 的按量付费、Token Plan 改用新的 MaaS 域名，Coding Plan 不变。

## 修复

- **在路由或聚合模式下，Claude Code 卡片的「打开终端」混入了路由和聚合的设置**。终端里的 Claude Code 会同时带上路由的占位凭据和这张卡片的 Key，这张卡片没配的模型档位会用上聚合里的模型名，发到这张卡片的地址上用不了；`/model` 菜单里也会出现其他供应商的模型。现在终端里只用这张卡片自己的设置，你的其他全局设置照常保留。
- **路由模式下，OpenCode Go 等用 `ANTHROPIC_API_KEY` 存 Key 的供应商会让 Claude Code 要求确认自定义 Key，默认选「否」后就是未登录**（[#8111](https://github.com/farion1231/cc-switch/pull/8111)、[#8104](https://github.com/farion1231/cc-switch/issues/8104)）。现在路由模式下占位凭据一律写进 `ANTHROPIC_AUTH_TOKEN`，发给上游的请求不变。
- **给纯文本模型发过一个文件或音频后，之后每一轮都报 400**（[#6274](https://github.com/farion1231/cc-switch/pull/6274)、[#6151](https://github.com/farion1231/cc-switch/issues/6151)）。现在经路由发给纯文本模型时，对话里的文件和音频会换成一段文字说明；智谱 GLM 的中文报错也能认出来。图片的处理不变。
- **Windows 上供应商表单里的名称等内容来回闪**（[#6420](https://github.com/farion1231/cc-switch/pull/6420)、[#6349](https://github.com/farion1231/cc-switch/issues/6349)）。这是 WebView2 的自动填充在覆盖表单内容，现在已对主窗口关掉。
- **启动后的一段时间里托盘面板打不开，也没法从托盘退出**（[#9154](https://github.com/farion1231/cc-switch/pull/9154)）。启动时导入会话用量会占着数据库，托盘面板要等数据。现在面板会先弹出，「打开主窗口」和「退出」马上能用，列表随后加载。
- **Codex 经路由用了模型映射时，同一个请求的用量被算两遍**（[#7643](https://github.com/farion1231/cc-switch/pull/7643)、[#5526](https://github.com/farion1231/cc-switch/issues/5526)）。会话日志里记的是 Codex 用的模型名，路由记的是映射后的模型名，去重时对不上。现在两边能对上了。
- **Pi 官方示例的子代理用的额度没有统计进来**（[#8386](https://github.com/farion1231/cc-switch/pull/8386)、[#8340](https://github.com/farion1231/cc-switch/issues/8340)）。现在会按每个子代理的供应商和模型分别记录，升级后会把以前的 Pi 会话重新读一遍补上。
- **从 Pi 导入 MCP 时，Pi 不支持的服务器也被导入并启用，之后每次同步都失败**（[#7888](https://github.com/farion1231/cc-switch/pull/7888)）。SSE 连接方式、名字不合规、名字只差 `-` 和 `_` 的服务器现在会跳过并提示；没装 Pi 时也不会再创建 Pi 的 MCP 配置文件。
- **只在终端或 CC Switch 里设了代理、没设系统代理时，models.dev 价格同步一直失败**（[#8739](https://github.com/farion1231/cc-switch/pull/8739)、[#6696](https://github.com/farion1231/cc-switch/issues/6696)）。现在改由 CC Switch 后台下载，会走你设的代理；导入模型价格和表单自动填模型参数也一样。
- **Claude Code 经路由连 xAI 时，强制联网搜索的请求被 xAI 拒绝，报 422**（[#8664](https://github.com/farion1231/cc-switch/pull/8664)）。
- **Pi 里的 MiniMax M3.1 Flash 思考档位**（[#8540](https://github.com/farion1231/cc-switch/pull/8540)）：两个 MiniMax 官方预设去掉了这个模型不接受的「关闭」和「最小」，其余档位照常发送。
