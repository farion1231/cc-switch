# CC Switch v4.0.17

This release fixes two issues introduced in 4.0.16 and polishes the tray quick panel. Lightweight mode frees the memory used by the tray panel again, so WebView2 processes exit normally on Windows; Codex no longer gets a long-expired ChatGPT login back when entering routing and gets stuck on the sign-in page. The tray panel no longer jumps while hovering between apps and fits on high-DPI and small Windows displays; quota bars line up and show how long until they reset, and remaining balances are shown in green; on Windows, a left click on the tray icon opens the main window again. The Hermes form now warns when a provider key has the same name as a built-in provider. Other fixes cover the routing port staying taken after quitting on Windows, Codex remote compaction usage recorded as 0, some MCP servers lost when several are toggled at once, URL-only MCP servers synced to Hermes and OpenCode as empty entries, curly quotes inside TOML strings being rewritten, WebDAV sync failing on Data Capsule, macOS capitalizing the first letter of a typed API key, and an MSI installed over a portable folder still being treated as portable. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## Improvements

**Warning when a Hermes provider key has the same name as a built-in provider**. When a key has the same name as a Hermes built-in provider (such as `deepseek` or `openrouter`), Hermes uses the built-in one, asks for that provider's own API key environment variable, and ignores this card's endpoint and key; 4.0.16 only fixed the two MiniMax presets ([#8538](https://github.com/farion1231/cc-switch/pull/8538)). Now, when the key you enter is a Hermes built-in provider ID, a note under the field warns about it and suggests `cc-switch-<key>`; for a card that is already added and whose key can no longer be changed, it suggests adding the provider again under a different key. Aliases such as `kimi` are not affected and are not flagged. The warning does not block saving.

**Quota lines in the tray panel**. Each tier's label, bar and reset time now sit in three aligned columns, so bars start and end at the same place and are longer; the reset time shows how long is left instead of a date, for example "Resets in 1d 23h". For pay-as-you-go balances only the amount is shown in green, matching the provider card; a used-up balance keeps its warning color.

**On Windows, a left click on the tray icon opens the main window again** ([#8572](https://github.com/farion1231/cc-switch/pull/8572)). A right click shows the tray style chosen in Settings (panel or menu). macOS is unchanged: both buttons show the chosen style.

## Fixes

- **The tray panel kept its memory in lightweight mode** ([#8612](https://github.com/farion1231/cc-switch/issues/8612)). Since 4.0.16 the tray panel is on by default; it is a separate window that was only hidden, never closed, after it first opened, so WebView2 processes on Windows did not exit after entering lightweight mode. In lightweight mode the panel is now released as soon as it is hidden and opened again on the next tray click.
- **Codex stuck on the ChatGPT sign-in page after entering routing** ([#8573](https://github.com/farion1231/cc-switch/issues/8573)). Since 4.0.16, entering a third-party route with no login in `auth.json` gives back the most recently set-aside login; that login could have been set aside months earlier and long expired, so Codex desktop kept failing to refresh it, and every time routing was entered or left it was given back again. Expired logins are no longer given back; they stay in the stash and are still returned when switching back to an official card.
- **The tray panel jumped while hovering, and was cut off on scaled Windows displays** ([#8572](https://github.com/farion1231/cc-switch/pull/8572), [#8595](https://github.com/farion1231/cc-switch/pull/8595), [#8549](https://github.com/farion1231/cc-switch/issues/8549), [#8553](https://github.com/farion1231/cc-switch/issues/8553), [#8564](https://github.com/farion1231/cc-switch/issues/8564)). Both columns now follow the main panel's height, and long provider lists scroll in the right column, so rows no longer move under the pointer while hovering between apps, and a single app no longer leaves a large blank area. On Windows, sizes are converted using the monitor's scale factor, and the panel narrows and stays within the screen's work area, so "Open main window" and "Quit" at the bottom are no longer pushed out of view; after moving to a monitor with a different scale, the first popup also displays correctly.
- **On Windows, the routing port stayed taken after quitting CC Switch, and the next start failed with os error 10048** ([#8552](https://github.com/farion1231/cc-switch/issues/8552)). Terminals and command-line tools started by CC Switch inherited the listening port and kept it after CC Switch quit, so the next start could only fall back to direct mode until a reboot or a port change. These child processes no longer inherit the listening port.
- **Codex remote compaction usage recorded as 0** ([#8479](https://github.com/farion1231/cc-switch/pull/8479)). Since Codex 0.153, remote compaction usage is written in a different kind of record that was not read, so those requests counted as 0. They are now counted; records scanned before the upgrade stay as they are.
- **Some MCP servers were not written to the config file when several were toggled at once** ([#8580](https://github.com/farion1231/cc-switch/issues/8580)). Toggles writing the same config file at the same time overwrote each other, so the UI showed a server as enabled while the config file did not have it. Writes now happen one after another.
- **URL-only MCP servers synced to Hermes and OpenCode as empty entries** ([#8579](https://github.com/farion1231/cc-switch/issues/8579)). Servers pasted in JSON mode or imported by deep link with a `url` but no `type` were treated as local commands, so Hermes got an entry with only `enabled: true` and OpenCode one with an empty command, while the UI reported a successful sync. Now, as with Codex, a server with a URL and no command is treated as a remote server.
- **Curly quotes (including Chinese quotes) inside TOML strings were changed to straight quotes** ([#8559](https://github.com/farion1231/cc-switch/issues/8559)). To work with Chinese input methods, MCP import and the Codex config editor convert curly quotes to straight quotes, but they also converted quotes inside strings, turning `"don’t"` into `"don't"` and rejecting some valid configs. Now only quotes used as string delimiters are converted; quotes inside strings are kept, and typing quotes directly with a Chinese input method still works.
- **WebDAV sync uploads failed on Data Capsule with 500** ([#8554](https://github.com/farion1231/cc-switch/issues/8554)). The sync manifest is now uploaded with a generic file type; its content is unchanged, so old and new versions can read each other's manifests. S3 sync is not affected.
- **macOS capitalized the first letter of a typed API key.** With the key shown in plain text, a typed `sk-…` could be changed to `Sk-…` by the system and saved, failing authentication. The field now turns off auto-capitalization, autocorrect and spellcheck. Pasted keys were not affected.
- **An MSI installed over a portable folder was still treated as portable, with updates only by manual download** ([#8529](https://github.com/farion1231/cc-switch/pull/8529), [#3132](https://github.com/farion1231/cc-switch/issues/3132)). The installer now removes the leftover portable marker `portable.ini` from the folder, so the installed app can update in place. Uninstalling does not remove this file.

## Upgrade Notes

**The database schema is unchanged**, still at 20.

- On Windows, a left click on the tray icon opens the main window again (in 4.0.16 it opened the panel with the panel style; the menu style always worked this way); a right click shows the style chosen under "Settings → General → Tray style".
- Codex remote compaction usage is counted only from records read after the upgrade; records already scanned before the upgrade are not backfilled.
