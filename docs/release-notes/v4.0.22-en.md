# CC Switch v4.0.22

This release adds support for DeepSeek Harness, the 14th app managed by CC Switch: providers are written into both its Web and Desktop configurations, MCP, Skills and prompts are synced to it, its sessions can be browsed, and it can be installed, upgraded and uninstalled from the "Apps" page; you can also sign in to a DeepSeek account and see the balance in Accounts, and its usage is recorded. Oh My Pi usage is now recorded as well. "Open Terminal" can skip permission prompts and append launch arguments, and Codex cards can open a terminal too; the WebDAV configuration can be cleared; Skills can open their folder and show their docs from the Discover list; GitHub Copilot's Claude models now use the native endpoint, which greatly raises the prompt cache hit rate. Fixes cover switching Claude accounts failing on macOS when an OAuth remote MCP is connected, adding a Claude account returning 403 with a global proxy on, new Claude Desktop sessions defaulting to Fable, MiniMax weekly quota not showing once used up, balances of providers not in use not refreshing automatically, memory growing when requests were sent back into routing itself, Gemini tool calls failing with 400, xAI rejecting requests from Codex 0.163, and request logs storing full error pages and bloating the database. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### DeepSeek Harness

DeepSeek Harness (the command is `dsh`) is now a separate app with its own providers, MCP, Skills, prompts and sessions ([#8795](https://github.com/farion1231/cc-switch/pull/8795), [#8986](https://github.com/farion1231/cc-switch/pull/8986)). Its configuration is in `~/.dsh`, or wherever `DSH_HOME` points when it is set.

- **Web and Desktop are managed together.** The web and desktop versions of DeepSeek Harness each have their own configuration (profile); CC Switch writes providers and MCP into both, and creates whichever one is missing; headless and acp profiles that are already initialized are written too. The sidebar has a single DeepSeek Harness, and a note next to the "Added" title says Web and Desktop share this list. When one of them has been edited by hand so that it differs from the other, editing is refused with a message, so your changes are not overwritten.
- **Providers can be added side by side.** As with OpenCode, it uses "Add" and "Remove": several providers are written in at once, and you pick the model inside DeepSeek Harness. Three endpoint types are supported, OpenAI Chat Completions, OpenAI Responses and Anthropic Messages, and presets come from Pi's catalog. The API Key is written into DeepSeek Harness's own credentials file `.credentials.yaml`, and the configuration only holds a reference to it; other plugin settings in the configuration are kept as they are, and a failed write is rolled back.
- **Model editing.** Thinking and image input are toggles, and context length and max output are filled in separately, the same as the model rows of Pi and Kimi Code; DeepSeek Harness can also set optional thinking levels and per-model endpoint compatibility options. Model editing for OpenCode and MiniMax Code now works the same way.
- **DeepSeek account sign-in.** In the DeepSeek Harness group in Accounts, sign in to a DeepSeek account through the browser to see the balance and bonus credit; Web and Desktop share this sign-in, so signing in or out in either place applies to both. Choosing "DeepSeek official sign-in" when adding a provider takes you to Accounts. After you sign in, the account shows as an official card at the top of "Added", and the account's models are provided by DeepSeek Harness itself; this card cannot be edited, and it disappears automatically after you sign out.
- **MCP, Skills and prompts.** Both stdio and Streamable HTTP MCP servers are supported.
- **Sessions and usage.** DeepSeek Harness sessions can be browsed (including thinking and tool calls); resume and delete sessions inside DeepSeek Harness. Usage is imported from session records, and requests made through the DeepSeek account are shown separately on the Usage page as "DeepSeek account (OAuth)".
- **DeepSeek Harness on the "Apps" page.** It installs, upgrades and uninstalls `@deepseek-ai/dsh` with npm; uninstalling does not delete your data.
- DeepSeek Harness does not go through local routing.

### Oh My Pi usage

The Usage page now records Oh My Pi usage, under its own app category ([#9046](https://github.com/farion1231/cc-switch/pull/9046), [#8939](https://github.com/farion1231/cc-switch/issues/8939)). Subagent usage and model calls outside the conversation are counted too, and the first import includes earlier subagent sessions. When Oh My Pi and Pi use the same session folder, each imports only its own sessions. Data already imported for Pi does not need to be imported again.

### "Open Terminal" can skip permission prompts and append launch arguments

The "Open Terminal" dialog has two new options ([#9008](https://github.com/farion1231/cc-switch/issues/9008)):

- **Skip permission prompts.** When ticked, Claude Code and Antigravity start with `--dangerously-skip-permissions`, and Codex starts with `--dangerously-bypass-approvals-and-sandbox`. Off by default.
- **Extra arguments (optional).** Enter arguments such as `--debug` or `--append-system-prompt "Be concise"`, and they are appended to the launch command. Separate them with spaces, put values containing spaces in quotes, up to 16 of them. They are passed to the program only as arguments and are never run as commands.

Both apply only to the terminal being opened and are not written into any configuration; once the terminal opens, CC Switch remembers your choices per app.

### Codex cards can "Open Terminal" too

Before, Codex cards had no such button. Now a terminal opened from a third-party card uses only that card: it starts with `codex -c ...`, does not change `config.toml`, and the Key is passed in through an environment variable, so it does not appear on the command line. Settings left in `config.toml` by the current provider are changed, where possible, to values that do not affect this card; for those that cannot be (such as request headers or a selected profile), you are asked to switch to this card first and then open it, so the current provider's Key is not sent elsewhere. The card currently in use starts `codex` directly.

### Clear the WebDAV configuration

Before, once WebDAV sync was set up, you could only turn off auto sync, and the address, account and password stayed on your machine ([#8977](https://github.com/farion1231/cc-switch/issues/8977)). The WebDAV sync settings now have a "Clear config" button; after you confirm, this information is deleted from your machine and auto sync stops. Data already uploaded to the cloud is not deleted.

### Skills: open folder, copy name, view docs

- **Installed Skills** ([#8993](https://github.com/farion1231/cc-switch/pull/8993)): the ⋯ menu has "Open folder", which opens the Skill's folder in the file manager; clicking a Skill's name copies the name. The old "Copy folder name" is removed.
- **Discover** ([#9039](https://github.com/farion1231/cc-switch/issues/9039)): each row has a new "Open docs" button, so you can read the description before installing; when there are no docs, it opens the repository's home page.

## Improvements

**Much higher prompt cache hit rate for GitHub Copilot's Claude models** ([#8908](https://github.com/farion1231/cc-switch/pull/8908)). Before, Copilot's Claude models were always converted to Chat Completions format, which dropped the cache markers, and system messages that Claude Code inserts mid-conversation also broke the cache. Now models for which Copilot supports the native Anthropic endpoint use it directly; in testing, the cache hit rate for long Copilot Enterprise sessions went from about 35% to about 95%.

**Adding, enabling, disabling or deleting a Skill repository now re-reads only that repository** ([#8907](https://github.com/farion1231/cc-switch/pull/8907), [#1426](https://github.com/farion1231/cc-switch/issues/1426)), instead of downloading all repositories again. The refresh button still re-reads all of them.

**The quota of Claude official cards bound to an account now also shows in the tray and in the usage settings.** Before, it only showed on the card; the tray did not have it, and the usage settings dialog showed it as not enabled.

**The Claude Desktop routing service also accepts the token in `x-api-key`** ([#5123](https://github.com/farion1231/cc-switch/pull/5123)), and token checks now use a constant-time comparison ([#7488](https://github.com/farion1231/cc-switch/pull/7488), [#7482](https://github.com/farion1231/cc-switch/issues/7482)).

**When the Claude configuration folder is in WSL, Accounts now says directly that Claude accounts are not supported yet**, and "Add account" and "Sign in again" are unavailable. Before, it suggested using "Open Terminal" instead, but that opens the Claude Code on Windows, which does not work either.

**Hovering a checkbox in the MCP and Skills lists no longer pops up two tooltips at once**; question-mark help cards now show on the right so they no longer cover the pointer, and long content wraps and scrolls inside the card ([#8593](https://github.com/farion1231/cc-switch/pull/8593)).

**Jumping to a group in Accounts from elsewhere no longer moves the rest of the page** ([#8964](https://github.com/farion1231/cc-switch/pull/8964)).

**When the configuration file of OpenCode, OpenClaw or Hermes cannot be read, the providers page shows an error** ([#9044](https://github.com/farion1231/cc-switch/issues/9044)). Before, the page was empty as if nothing had ever been configured, the error only appeared after adding a provider failed, and an extra record was left behind.

**When the sign-in of a managed ChatGPT or xAI account expires, the message now reads "Sign in to this account again in Accounts".** Before, it told you to run a command that does not exist.

**Presets:** Claude Code presets for OspreyAI and iFlytek Spark Astron Coding Plan are added ([#9036](https://github.com/farion1231/cc-switch/issues/9036)); TokenFlux moves to the new domain tokenflux.com, with tokenflux.dev as a fallback address.

## Fixes

- **On macOS, with a remote MCP server that needs OAuth sign-in connected, switching Claude accounts reported "Claude Code's sign-in data is too large for the keychain, so nothing was switched."** ([#9002](https://github.com/farion1231/cc-switch/issues/9002)). The MCP sign-in data and the account are stored in the same Keychain entry, which went over the length limit of a single write. When it is too long, it is now written the same way Claude Code does it.
- **With a global proxy on, adding a Claude account in Accounts returned 403 after a successful browser sign-in** ([#9038](https://github.com/farion1231/cc-switch/issues/9038)). The token exchange is done by Claude Code itself, which used to not use the global proxy. Now, when CC Switch runs Claude Code to sign in or check quota, it passes the global proxy to it (SOCKS proxies are not passed, since Claude Code does not support them).
- **New Claude Desktop sessions defaulted to Fable, and the model order changed each time a configuration was enabled** ([#7491](https://github.com/farion1231/cc-switch/pull/7491), [#7457](https://github.com/farion1231/cc-switch/issues/7457), [#8973](https://github.com/farion1231/cc-switch/issues/8973)). Claude Desktop takes the first entry in the model list as the default model, and the list used to be written in alphabetical order. It is now written in the interface order Sonnet, Opus, Fable, Haiku, so new sessions default to the Sonnet tier.
- **Once the MiniMax weekly quota was used up, the card and the tray no longer showed the weekly quota, and right after the 5-hour quota reset it looked as if the quota were full** ([#8124](https://github.com/farion1231/cc-switch/pull/8124), [#8123](https://github.com/farion1231/cc-switch/issues/8123)). It now shows a red "Used up" and a countdown to the weekly quota reset.
- **Providers not in use did not refresh their balance even with an automatic query interval set** ([#8342](https://github.com/farion1231/cc-switch/pull/8342), [#8335](https://github.com/farion1231/cc-switch/issues/8335)).
- **When the upstream address was set to routing's own address, requests were sent back into routing endlessly and memory kept growing** ([#8598](https://github.com/farion1231/cc-switch/pull/8598)). A configuration error is now reported right away.
- **When Claude Code connected to Gemini through routing, requests failed with 400 after tool calls**: the signature was in the wrong place, giving "Unknown name thoughtSignature" ([#6690](https://github.com/farion1231/cc-switch/pull/6690)); after a CC Switch restart, or in earlier turns, the signature was lost and Gemini 3 and later rejected the request ([#6833](https://github.com/farion1231/cc-switch/issues/6833)); on Vertex, text following a tool result gave "Requests ending with a model turn are not supported" ([#8988](https://github.com/farion1231/cc-switch/issues/8988)).
- **When Claude Code went through routing to OpenAI Responses, WebSearch with blocked domains failed right away with 400** ([#8979](https://github.com/farion1231/cc-switch/issues/8979)). Now, for Responses upstreams connected with an API Key, they are passed through as they are; routing through the official ChatGPT sign-in does not support blocked domains and still reports a clear error.
- **Codex 0.163 and later failed with 400 when connecting to xAI through routing** ([#8997](https://github.com/farion1231/cc-switch/pull/8997), [#8996](https://github.com/farion1231/cc-switch/issues/8996)).
- **When Codex's `config.toml` had an array table such as `[[skills.config]]`, the third-party provider's address was written into that table** ([#9029](https://github.com/farion1231/cc-switch/pull/9029), [#9023](https://github.com/farion1231/cc-switch/issues/9023)).
- **"Connectivity check" on OpenCode providers in the new format (V2) reported a missing `options.baseURL`** ([#8969](https://github.com/farion1231/cc-switch/issues/8969)).
- **When an upstream returned an error, the request log stored the whole HTML error page, so the database and backups kept growing** ([#9010](https://github.com/farion1231/cc-switch/pull/9010), [#6706](https://github.com/farion1231/cc-switch/issues/6706)). Each entry now stores only the first 4096 characters; old records already stored are not cleaned up in this release.
- **On Windows, with a third-party taskbar such as MyDockFinder, clicking the tray icon did nothing** ([#8729](https://github.com/farion1231/cc-switch/pull/8729), [#8565](https://github.com/farion1231/cc-switch/issues/8565)).
- **Kimi Code versions before 0.43.0 stayed at the same version after upgrading from the "Apps" page** ([#9032](https://github.com/farion1231/cc-switch/issues/9032)). Older versions have no option to confirm the upgrade automatically, so the package manager that installed it is now used instead, or the official install script is run again.
- **On the "Apps" page, apps whose program file exists but cannot run were in the "Installed" group but showed "Not installed".** They now show "Can't run", with the reason.
- **With both the Antigravity CLI and IDE installed, usage of old sessions continued in the IDE was not updated, and the sessions could not be opened** ([#8941](https://github.com/farion1231/cc-switch/issues/8941)).

## Upgrade Notes

**The database schema goes from 23 to 24**, adding DeepSeek Harness toggles for MCP and Skills. The database is backed up automatically before the upgrade; if you go back to an older version after upgrading, it reports that the database version is too new and cannot open it.

- DeepSeek Harness shows in the sidebar by default; if you do not use it, turn off "Show DeepSeek Harness in the sidebar" on the "Apps" page.
