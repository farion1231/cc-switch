# CC Switch v4.0.41

本版本新增 **CodeBuddy** 支持（腾讯的 CLI 和桌面版共用一套配置）：可以管理自定义模型、MCP、Skills、提示词、会话和用量，在授权中心收集多个官方账号，查看套餐、积分和到期时间并随时切换。**Copilot CLI** 的供应商可以一键同步到 VS Code 的 Copilot 插件；**Grok 官方卡**显示订阅等级。

本版本还让 Claude 原生转发复用上游连接，主窗口和托盘面板启动时加载的代码更少，后台请求和供应商连通性检查失败时会说明原因，并加固了数据库文件权限、备份文件名、CONNECT 代理和深链接的安全检查。另外修复了 Codex 路由到 Opus / Sonnet 5.5 时工具调用后报「requires adaptive thinking」；Gemini Native 工具调用历史较长时报 400；旧请求的故障转移结果覆盖手动选的路由；Antigravity 卡片绑定的账号和授权中心不同步；Codex 分叉会话的用量一直不入账；Pi 插件被当成 pnpm 处理；Windows 上 Hermes 显示两处安装；macOS 更新后 Dock 栏多出一个图标等问题。

## 新增

### CodeBuddy

新增 CodeBuddy（[#8758](https://github.com/farion1231/cc-switch/pull/8758)）。CodeBuddy 的桌面版和 CLI 读同一套配置文件，所以界面上统一叫 CodeBuddy。它和 Kimi Code、WorkBuddy 一样是累加式，多个模型可以同时添加。

- **自定义模型**：每张卡是 `~/.codebuddy/models.json` 里的一个模型，卡片 ID 就是发给上游的模型名，保存后不能改，也不提供「复制」。可以从地址获取模型列表，选中模型后自动填好 token 上限和能力。文件里其他模型和你自己加的字段都保留；带注释或尾逗号的文件不会被改写；`settings.json` 里设为默认的模型不能移除。新增 DeepSeek、小米 MiMo、LongCat 预设。
- **MCP、Skills、提示词**：MCP 写进 CodeBuddy 实际读取的那一个用户级文件，保留你自己的服务器；在 CC Switch 里启用的服务器会从 CodeBuddy 的停用列表里去掉。Skills 同步到 `~/.codebuddy/skills`，不会删掉不是 CC Switch 装的技能。提示词写进 `CODEBUDDY.md`。
- **会话和用量**：会话列表里能看 CodeBuddy 的会话并在终端里恢复（不能在 CC Switch 里删除），用量统计会导入主会话和子 agent 的用量，子 agent 的用量算在所属会话上。
- **官方账号**：授权中心可以收进当前登录的 CodeBuddy 账号，或在终端里登录一个新账号；CodeBuddy 已登录时，会先确认，再让它显示登录界面，取消登录会还原原来的号。新增「CodeBuddy 官方登录」卡，绑定一个账号，点「添加」即切换到这个号，授权中心账号的「…」菜单也能切换。账号行和卡片显示套餐、本期积分和到期时间。账号副本只存在本机，不参与同步。
- **「应用」页**：可以安装、更新和卸载 CodeBuddy CLI。

### Copilot CLI 同步到 VS Code Copilot 插件

在「设置 → 应用配置 → Copilot CLI」打开「应用到 VS Code Copilot 插件」（[#9435](https://github.com/farion1231/cc-switch/pull/9435)，关闭 [#9433](https://github.com/farion1231/cc-switch/issues/9433)），Copilot CLI 里添加的供应商和模型会写进 VS Code Copilot 插件的模型配置，两边各自在模型列表里选用。

- 自动找到 VS Code 正式版和 Insiders 的默认及命名 Profile，全部同步；之后在 CC Switch 里添加、编辑、移除 Copilot CLI 供应商时自动更新。
- 只改 CC Switch 写的那一组，其他配置和注释都保留；第一次修改前会在旁边留一份备份。关闭开关会删掉这一组。
- 同步失败时，Copilot CLI 那边的保存照常生效，提示里写明原因并提供「重试」。
- WebSocket、带 `apiVersion` 的 Azure 部署等少数配置暂不支持，遇到时会提示原因。

### Grok 官方卡显示订阅等级

Grok Build 的官方卡在账号后面显示订阅等级，例如 `SuperGrok Heavy`（[#9923](https://github.com/farion1231/cc-switch/pull/9923)）。绑定了 xAI 账号的卡也可以「配置用量查询」，设置自动刷新间隔；关掉用量查询时订阅等级一起隐藏。

## 变更

- **Claude 原生转发复用上游连接**（[#9914](https://github.com/farion1231/cc-switch/pull/9914)，关闭 [#9913](https://github.com/farion1231/cc-switch/issues/9913)）：本地路由原样转发 Claude 请求时，不再每次都重新建立到上游的连接，直连和经代理的连接都会复用。复用的旧连接失败时自动换新连接重发；经代理时只在还没收到任何数据的情况下换新连接。
- **启动更轻**（[#9918](https://github.com/farion1231/cc-switch/pull/9918)、[#9920](https://github.com/farion1231/cc-switch/pull/9920)）：界面语言包改为只加载当前用的语言；托盘面板的「用量」页签切过去才加载，面板收起时停止后台刷新，托盘面板启动时加载的代码从约 3.5 MB 减到约 0.5 MB。后端计算用量中位数时少分配内存，用不到的网络客户端不再提前创建。
- **网络失败时说明原因**（见 [#9911](https://github.com/farion1231/cc-switch/issues/9911)）：启动时的后台请求失败会提示一次是哪个请求：检查更新会写明访问的是 dl.ccswitch.io / github.com，models.dev 同步会说明是为了获取价格计算用量费用，提示里可以选「不再提示」或直接关掉自动同步。检查供应商连通性失败时会区分被防火墙拦截、端口没有服务、超时、DNS 和 TLS 错误，给出对应的建议。
- **侧栏收起后更窄**（[#9941](https://github.com/farion1231/cc-switch/pull/9941)）：侧栏收起后的宽度和选中项的高亮变窄，「舒适」密度比「紧凑」略宽，图标大小不变。

## 安全

- **数据库、备份、代理和深链接**（[#9835](https://github.com/farion1231/cc-switch/pull/9835)）：在 macOS / Linux 上，导出的 SQL 文件和 `cc-switch.db` 只有当前用户能读写。恢复、重命名、删除备份时，只接受单个 `.db` 文件名。经 HTTP 代理（CONNECT）连接上游时，代理地址里转义过的用户名密码会先还原再发送（修复带特殊字符时 407），并限制代理返回的响应头大小。深链接导入的风险检查会标出更多可被利用的环境变量，以及 `node -e`、`python -c` 这类直接执行代码的命令。

## 修复

- **Codex 路由到 Opus / Sonnet 5.5 时工具调用后报 400**（见 [#9943](https://github.com/farion1231/cc-switch/issues/9943)）：Codex 经本地路由用 Anthropic 接口的 Opus 5.5 或 Sonnet 5.5 时，工具调用之后的每一轮都报「requires adaptive thinking」。这两个模型不允许关闭思考，现在这种情况下改发自适应思考；Codex 设为 `none` 的思考强度按 `low` 发。其他模型的请求不变。
- **Gemini Native 工具调用历史较长时报 400**（[#9009](https://github.com/farion1231/cc-switch/pull/9009)）：对话超过 64 轮后，较早工具调用的签名会丢失，可能错配到别的调用，Gemini 拒收。现在签名单独缓存更久，并按调用 ID 精确对应；实在找不回签名时，只对 Gemini 3 及以上用 Google 文档里的兼容标记。
- **旧请求的故障转移结果覆盖手动选的路由**（[#9946](https://github.com/farion1231/cc-switch/pull/9946)，关闭 [#9944](https://github.com/farion1231/cc-switch/issues/9944)）：手动切换路由或关掉自动故障转移后，还在进行中的旧请求不会再把路由切回备用供应商，也不会显示成当前使用的供应商。
- **Antigravity 卡片绑定的账号和授权中心不同步**（[#9945](https://github.com/farion1231/cc-switch/pull/9945)）：在 Antigravity 官方卡上绑定或更换账号并保存时，会经授权中心切换 agy 的登录，切换失败则不保存；卡片、账号选择框和授权中心显示同一个当前账号。复制卡片不会切换账号。
- **Codex 分叉会话的用量一直不入账**（[#9638](https://github.com/farion1231/cc-switch/pull/9638)，关闭 [#9637](https://github.com/farion1231/cc-switch/issues/9637)）：从闲置的会话分叉出来的旧版 Codex 会话，核对过复制来的历史属于父会话后即导入用量；判断不了的仍然暂缓。
- **全局代理设置只生效一半**（[#9930](https://github.com/farion1231/cc-switch/pull/9930)）：连续保存两次全局代理时，部分请求可能走的是另一次的代理设置。现在代理地址和网络客户端一次整体替换。
- **Pi 插件被当成 pnpm 处理**（[#9964](https://github.com/farion1231/cc-switch/pull/9964)，见 [#9960](https://github.com/farion1231/cc-switch/issues/9960)）：系统里找到的 `pi` 实际是 pnpm 时，插件页会显示 0 个插件，在「发现」里点安装还会往 `~/.pi/agent` 里装 npm 包。现在认不出 Pi 的输出时直接报错。同时修正了工具路径识别：经 pnpm、mise、volta 这类快捷方式安装的工具不会被认错，终端启动脚本打印的路径不会被当成工具位置，macOS / Linux 上也会查找 pnpm 的全局安装目录。
- **Windows 上 Hermes 显示两处安装**（见 [#9931](https://github.com/farion1231/cc-switch/issues/9931)）：同一个目录里的 `hermes.cmd` 和 `hermes.exe` 现在只显示一处，按 Windows 实际会运行的那个算。
- **macOS 更新后 Dock 栏多出一个图标**（[#9910](https://github.com/farion1231/cc-switch/pull/9910)，关闭 [#8329](https://github.com/farion1231/cc-switch/issues/8329)）：应用内更新或改配置目录后重启时，会等旧进程完全退出再启动新的，复用固定在 Dock 里的图标。
- **SQL 导入后同步失败也提示成功**（[#9541](https://github.com/farion1231/cc-switch/pull/9541)，关闭 [#9536](https://github.com/farion1231/cc-switch/issues/9536)）：导入后同步提示词、价格和设置失败时，会显示对应的警告。
- **云同步后 Skills 里的脚本不能执行**（[#9539](https://github.com/farion1231/cc-switch/pull/9539)，关闭 [#9534](https://github.com/farion1231/cc-switch/issues/9534)）：经 WebDAV / S3 同步的 Skills 会保留脚本的可执行权限。
- **再次打开设置时闪一下加载图标**（[#9908](https://github.com/farion1231/cc-switch/pull/9908)，关闭 [#9907](https://github.com/farion1231/cc-switch/issues/9907)）：已有缓存时直接显示设置内容。
- **用量热力图开头的月份重叠**（见 [#9917](https://github.com/farion1231/cc-switch/issues/9917)）：开头只剩一两列的月份不再标月份，不会和下个月挤在一起。
- **授权中心刷新额度时进度条左右晃动**：刷新时只转图标，不再换文字，那一列宽度不变。
- **WorkBuddy 手动刷新额度没反应**：WorkBuddy 没运行，或登录的不是这个账号时，只能拿到上次的结果，现在会提示原因。

## 升级说明

- **数据库版本从 27 升到 28**，为 MCP 和 Skills 增加 CodeBuddy 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
- macOS 上从旧版本更新到 4.0.41 的这一次重启仍由旧版本执行，可能还会多出一个 Dock 图标；之后的更新和重启不会再出现。
