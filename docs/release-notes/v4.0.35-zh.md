# CC Switch v4.0.35

本版本让 Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片能用上 **GPT-6.2**，会话管理里可以看到 Codex `/goal` 的**完整目标**，请求详情里的请求 ID 可以**一键复制**。

另外修复了 Claude Code 的 auto 模式在关不掉思考的模型上被整体拦下；Codex 聚合模式和「打开终端」报 Responses-Lite 需要 `reasoning.context`；Codex 压缩上下文后第一条请求被拒；用量页自定义日期选到很早的年份时卡死；Skill 的托管副本不在了就卸载不掉等问题。

---

## 新增

### 会话管理里显示 Codex `/goal` 的完整目标

目标超过 700 字节时，Codex 注入的上下文里不写目标内容，会话管理里也就看不到目标（见 [#9647](https://github.com/farion1231/cc-switch/issues/9647)）。现在从会话记录里读出完整目标，显示成一步「目标 · 状态」，展开即是完整内容；目标和状态都没变的重复记录不再显示。

### 请求详情里可以复制完整的请求 ID

请求详情里过长的值会被省略号截断，像 Codex 的 `resp_...` 这类长请求 ID 没法完整复制去对日志（见 [#9681](https://github.com/farion1231/cc-switch/issues/9681)）。现在请求 ID 后面多了一个复制按钮。

### 新增 GPT-6.2 Sol / Astra 的价格

按官方标准档（272K 以内）的价格计费；长上下文档、Batch / Fast 等档位和 GPT-6 一样暂不区分。

## 修复

- **Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片获取不到 GPT-6.2，手动填了也报「not supported when using Codex with a ChatGPT account」**（[#9678](https://github.com/farion1231/cc-switch/pull/9678)，见 [#9670](https://github.com/farion1231/cc-switch/issues/9670)）：OpenAI 按 Codex 客户端版本决定给哪些模型，CC Switch 报的版本太旧。现在按 Codex 0.169.0 请求，没有写死任何模型 ID。
- **Claude Code 的 auto 模式在关不掉思考的模型上，Bash、MCP 等工具调用全部被拒**（见 [#8887](https://github.com/farion1231/cc-switch/issues/8887)、[#9671](https://github.com/farion1231/cc-switch/issues/9671)）：auto 模式的判断请求要求关闭思考，MiniMax-M3.1-Flash 这类模型直接报 400，Claude Code 就认为判断服务不可用。现在经路由时（Claude Code 和 Claude Desktop），Anthropic 格式的上游这样报错会去掉关闭思考的字段，在同一家重试一次。上游本来接受的请求原样发送，不影响缓存。
- **Codex 聚合模式下报「Responses-Lite requires `reasoning.context` to be `all_turns`」，同一家直连和路由都正常**（见 [#9665](https://github.com/farion1231/cc-switch/issues/9665)）：卡片没写模型目录时，聚合模式改用和直连一样的 GPT-6 官方设置。从卡片「打开终端」时出现的同一个报错也一并修好。
- **Codex 经路由转成 Chat 格式时，压缩上下文后第一条请求被要求严格的网关以「message content cannot be empty」拒绝**（见 [#9660](https://github.com/farion1231/cc-switch/issues/9660)）：压缩时只含图片的用户消息会变成空消息，现在转成 Chat 格式时去掉内容为空的用户消息，其他消息不变。
- **用量页自定义日期的起点选到 1905 年这类很早的年份时，客户端卡死**（见 [#9691](https://github.com/farion1231/cc-switch/issues/9691)）：现在只能选从第一条用量记录到今天之间的日期，范围外的日期不可选，手动输入的也会被拉回范围内。
- **Skill 的托管副本已经不在时卸载不掉**（[#9669](https://github.com/farion1231/cc-switch/pull/9669)，见 [#9668](https://github.com/farion1231/cc-switch/issues/9668)）。
