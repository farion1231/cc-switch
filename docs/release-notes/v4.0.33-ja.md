# CC Switch v4.0.33

今回のリリースでは、サードパーティのプロバイダーから Claude 公式に切り替えた後も、すでに開いている Claude Code のセッションが前のプロバイダーにリクエストを送り続け、セッションを開き直さないと元に戻らない問題を修正しました。プランのクォータ照会に **Ollama Cloud** を追加し、「アカウント」ページの **Antigravity アカウントの切り替え**が Windows にも対応しました。

このほか、Claude Code / Claude Desktop のプロバイダーで Gemini Native 形式を選ぶと、モデル一覧の取得が常に「API Key が無効か、権限がありません」になる問題、一部のサービスでモデル一覧の取得が Cloudflare にブロックされる問題、Antigravity Orchestrator の一部のリクエストがまだ「価格未設定」と表示される問題、一部の NAS で WebDAV 同期がまったく使えない問題、WebDAV / S3 のアップロードに失敗すると「request build failed」としか表示されない問題、ネットワークの一時的な不調で xAI アカウントが再ログインを求められる問題、Skill の更新が途中で失敗すると元の Skill が削除される問題などを修正しました。

---

## 新機能

### Ollama Cloud のプランのクォータ

アドレスが `ollama.com` のプロバイダーで、Token Plan のクォータを照会できるようになりました（要望は [#9382](https://github.com/farion1231/cc-switch/issues/9382)）。現行のプランでは今期のプラン内クォータの残り割合とリセット時刻を、旧プランでは 5 時間と週間の 2 つの枠の残り割合を表示します。別途購入したクレジットは表示しません。従量課金のアカウントにはプランのクォータがないため、その理由を表示します。ローカルで動かしている Ollama（`localhost:11434`）にはプランがないため、対象になりません。

- 新たに追加した、またはワンクリックでインポートした Ollama Cloud のプロバイダーは、クォータ照会がデフォルトでオンになります。既存のプロバイダーは、カードの「利用状況を設定」をクリックすると「Token Plan」テンプレートが自動で選ばれるので、「利用状況照会を有効にする」をオンにして保存してください。

### Windows で Antigravity アカウントを切り替え

「アカウント」ページの Antigravity アカウントの切り替えはこれまで macOS だけの対応でしたが、Windows でも使えるようになりました。切り替えた後は agy が新しいアカウントを読み込みます。Antigravity の公式カードではアカウントを紐付けて、紐付けたアカウントのクォータを確認でき、ターミナルを開く前にはどのアカウントに切り替えるかも表示します。Linux はまだ対応していません。

## 修正

- **サードパーティのプロバイダーから Claude 公式に切り替えた後も、すでに開いている Claude Code のセッションが前のプロバイダーにリクエストを送り続け、セッションを開き直さないと元に戻らない問題**（[#9247](https://github.com/farion1231/cc-switch/pull/9247)、関連：[#7808](https://github.com/farion1231/cc-switch/issues/7808)、[#3057](https://github.com/farion1231/cc-switch/issues/3057)）：実行中の Claude Code は `settings.json` で追加・変更された環境変数しか読み込まず、削除された変数はセッションに残ったままになります。現在は切り替え時に、削除するアドレス、認証情報、モデルマッピングをまず空の値として書き込むため、開いているセッションでも次のリクエストから前のプロバイダーを使わなくなり、約 10 秒後にファイルから削除します。セッションの起動時に決まるメインモデル（`ANTHROPIC_MODEL`）は切り替わりません。前のプロバイダーでこれを設定していた場合は、切り替えた後にモデルメニューで一度 Default を選ぶか、新しいセッションを開いてください。
- **Claude Code / Claude Desktop のプロバイダーで Gemini Native 形式を選ぶと、「モデル一覧を取得」が常に「API Key が無効か、権限がありません」になる問題**：現在は Google が求める方法で Key を渡します。ルーティング経由の実際のリクエストはもともと正常で、影響を受けていたのはモデル一覧の取得だけです。また、Pi、Oh My Pi、Kimi Code で Google の API を使うプロバイダーは、これまでモデル一覧が最大 50 件まででしたが、すべて表示されるようになりました。
- **モデル一覧を取得するとき、Cloudflare の背後にある一部のサービスがリクエストをそのまま拒否し、「API Key が無効か、権限がありません」と誤って表示される問題**（[#7429](https://github.com/farion1231/cc-switch/pull/7429)、関連：[#7427](https://github.com/farion1231/cc-switch/issues/7427)）：リクエストにデフォルトで User-Agent を付けるようにしました。プロバイダーやリクエストヘッダーで User-Agent を設定している場合は、引き続きその設定が優先されます。
- **Antigravity で Orchestrator を選ぶと、一部のリクエストがまだ「価格未設定」と表示される問題**（[#9542](https://github.com/farion1231/cc-switch/pull/9542)、関連：[#9493](https://github.com/farion1231/cc-switch/issues/9493)）：「Gemini 4 Hydrogen (Orchestrator)」と表示されるステップは Gemini 4 Hydrogen の料金で計算し、直近 30 日以内の履歴にも料金を補います。カスタム価格は引き続き優先されます。
- **一部の NAS で WebDAV 同期がまったく使えず、接続テスト、アップロード、ダウンロードがすべて失敗する問題**（[#5623](https://github.com/farion1231/cc-switch/pull/5623)、関連：[#5621](https://github.com/farion1231/cc-switch/issues/5621)）：これらの NAS は、共有フォルダーがすでに存在していても「ディレクトリの作成」に 400 を返します。以前はそこで中断していましたが、現在はディレクトリが存在するかどうかをもう一度確認します。
- **WebDAV / S3 のアップロードがサーバーによって途中で切断されたとき、「request build failed」としか表示されない問題**（関連：[#9559](https://github.com/farion1231/cc-switch/issues/9559)）：現在は、リクエストを組み立てられなかったのか、送信中に失敗したのかを区別し、具体的な原因も添えるため、ネットワーク、TLS、サーバーのどこに問題があるのかを判断しやすくなりました。アドレスに含まれるパスワードや署名パラメーターはエラーに表示されません。
- **S3 の自動同期をオフにした後でも、もう一度アップロードされることがある問題**（[#9528](https://github.com/farion1231/cc-switch/pull/9528)）：別の同期の実行中に待機していた自動アップロードは、開始する前に設定を読み直すようになり、その間に自動同期または S3 同期をオフにした場合はアップロードしません。WebDAV はもともとこの動作です。
- **xAI アカウントのクォータを照会すると、ネットワークの一時的な不調や xAI 側のサービスエラーでも再ログインを求められる問題**（[#9526](https://github.com/farion1231/cc-switch/pull/9526)、関連：[#9522](https://github.com/farion1231/cc-switch/issues/9522)）：ログインが本当に無効になった場合だけ再ログインを求めるようにしました。一時的なエラーは通常どおりエラーとして表示し、前回取得したクォータを残したまま、次回の照会で再試行します。
- **デフォルトではない xAI アカウントの期限が切れると、「アカウント」ページで選んでいたデフォルトアカウントが別のアカウントに変わってしまう問題**（[#9548](https://github.com/farion1231/cc-switch/pull/9548)、関連：[#9543](https://github.com/farion1231/cc-switch/issues/9543)）。
- **Skill の更新中にコピーが途中で失敗すると、元の Skill が削除されているのに、一覧ではインストール済みと表示される問題**（関連：[#9521](https://github.com/farion1231/cc-switch/issues/9521)）：新しいバージョンを完全にコピーし終えてから置き換えるようにし、失敗した場合は元のバージョンを残します。
- **Codex がルーティング経由で Chat 形式に変換されるとき、ツール定義の `required: null` が検証の厳しい上流に拒否される問題**（[#7023](https://github.com/farion1231/cc-switch/pull/7023)、関連：[#7019](https://github.com/farion1231/cc-switch/issues/7019)）。
- **macOS / Linux でシェル設定ファイルのパスにコロンが含まれていると、「競合する環境変数を検出しました」で変数を削除または復元すると失敗する問題**（[#7170](https://github.com/farion1231/cc-switch/pull/7170)、関連：[#7169](https://github.com/farion1231/cc-switch/issues/7169)）。
- **PIPELLM、AICodeWith、E-FlowCode の Pi プリセットで、モデル選択に古いモデル名が表示される問題**（[#9514](https://github.com/farion1231/cc-switch/pull/9514)）：たとえば Claude Opus 5.5 が claude-opus-5 と表示されていましたが、実際にリクエストしていたのは新しいモデルです。これらのプリセットから生成される DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code のプリセットもあわせて修正しました。追加済みのプロバイダーは、保存されていた名前をそのまま使います。
- **`api.commandcode.ai/providers` のようなアドレスのプロバイダーが、Command Code のプランとしてクォータを照会されてしまう問題**（[#9518](https://github.com/farion1231/cc-switch/pull/9518)）。
