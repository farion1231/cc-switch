# CC Switch v4.0.25

今回のリリースでは、MCP ページに接続確認を追加し、有効になっているすべての MCP サーバーに接続できるかをワンクリックで確認できるようになりました。Codex がローカルルーティング経由で公式アカウントを使うときは、クォータを使い切る前に公式へのリクエストを自動で一時停止でき、サードパーティのモデルは引き続き使えます。このほか、使用量ページの為替レートを自動で取得できるようになり、Codex のプロバイダーフォームでサブエージェントの同時実行上限を設定できるようになりました。Claude Code と Claude Desktop がルーティングや集約を経由するときは、モデルメニューに各モデルがどのプロバイダーのものか、実際にはどのモデルかが表示されます。セッション管理では Kimi Code のセッションも削除できるようになりました。また、「ターミナルを開く」にルーティングや集約の設定が混ざる、ルーティングモードで OpenCode Go などのプロバイダーを使うと Claude Code が再ログインを求める、テキスト専用モデルに一度ファイルを送るとそれ以降毎回エラーになる、Windows でプロバイダーフォームの内容がちらつく、起動時にトレイパネルが開かない、Codex でモデルマッピングを使うと使用量が二重に計上される、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### MCP の接続確認

これまでは MCP サーバーを設定しても、コーディングツールで実際に使うまで接続できるかどうかわかりませんでした（[#4498](https://github.com/farion1231/cc-switch/issues/4498)）。

現在は MCP ページの上部に「接続を確認」ボタンがあり、有効になっているすべてのサーバーを確認します。各行のメニューにも「接続をテスト」があり、そのサーバーだけを確認できます。

- ページを開いても自動では確認せず、まだ確認していないサーバーは「未確認」と表示されます。サーバーの接続設定を変更すると、そのサーバーの結果はリセットされます。
- 確認はサーバーと MCP のハンドシェイクを 1 回行う方法で、ローカルコマンド（stdio）、HTTP、旧形式の SSE の 3 つの接続方式すべてに対応しています。サーバーごとの待ち時間は最大 30 秒で、アプリ全体で同時に確認するのは最大 3 つです。
- ローカルコマンドで起動したサーバーは、確認が終わると起動された子プロセスごと終了し、バックグラウンドにプロセスが残りません。macOS と Linux では、CC Switch をターミナルから起動していなくても `npx`、`uvx` などのコマンドを見つけられます。

### Codex の公式クォータ保護

Codex で公式の ChatGPT アカウントを使っている場合、5 時間または週間のクォータを使い切ると Reserve モードに入ります。現在は、クォータが尽きそうになった時点で公式へのリクエストを先に一時停止してクォータを残しておけます。サードパーティのモデルは引き続き使えます。

「設定 → アプリ設定 → Codex アプリ拡張」で「公式クォータ保護」をオンにすると、5 時間と週間の使用率のしきい値（既定は 95% と 98%）を設定でき、どちらかに達すると新しい公式リクエストを停止します。

- 対象は CC Switch のローカルルーティングを経由する Codex の公式リクエストだけで、既定ではオフです。
- 使用率は公式レスポンスに含まれるクォータ情報から直接読み取るため、通常の利用で追加のリクエストは発生しません。使い始めや、約 5 分以上アイドルだった後にだけ、先に別途 1 回照会します。
- クォータを確認できない場合（ネットワークの問題、ログイン期限切れなど）は通常どおり通し、誤って止めることはありません。停止されたリクエストはそのままエラーを返し、故障時切り替えキューのほかのプロバイダーには回されません。

### 使用量ページの為替レートを自動取得

使用量ページの「使用量の設定」の「表示」セクションに「レートの取得方法」が加わり、「手動入力」（既定）か「自動取得」を選べます。インターネットに接続するのは自動取得を選んだときだけで、為替レートは 12 時間を過ぎると自動で更新され、取得に失敗した場合は前回のレートを使い続けます。自動取得したレートと手動で入力したレートは別々に保存されるため、手動入力に戻しても自分で入力した値は残っています。費用は引き続き米ドルで記録され、表示するときだけ換算します。

### Codex のサブエージェントの同時実行上限

Codex のプロバイダーフォームの「サブエージェントモデル」の下に「サブエージェントの同時実行上限」が加わり、1 つの Codex セッションで同時に動かせるサブエージェントの最大数を設定できます（[#9055](https://github.com/farion1231/cc-switch/issues/9055)）。これは Codex 全体の設定で、`config.toml` の `[agents] max_threads` に書き込まれ、プロバイダーを切り替えても変わりません。公式カードでも変更できます。空欄なら Codex の既定値を使います。

### モデルメニューにプロバイダーと実際のモデルを表示

Claude Code のルーティングモードでは、これまで `/model` メニューの各段階に「Custom Sonnet model」としか表示されず、どのプロバイダーのどのモデルに対応しているのかわかりませんでした。現在は「プロバイダー · 実際のモデル · ウィンドウ」と表示されます（ウィンドウは上流に 1M と指定されている場合だけ表示）。集約モードのモデルも同様です。プロバイダーに自分でモデルの説明を書いてある場合は、その説明が優先されます。

Claude Desktop のルーティングモードと集約モードでは、これまでモデルの下の説明は名前に含まれる Opus、Sonnet に応じて公式の文言を当てはめており、集約モデルはすべて同じ一文が表示されていました。こちらも「プロバイダー · 実際のモデル · ウィンドウ」に変わりました。

### Kimi Code のセッションを削除

セッション管理で Kimi Code のセッションを直接削除できるようになりました。これまでは Kimi Code の中でしか削除できませんでした。削除の方法は Kimi Code 自身と同じで、サブエージェントの履歴も一緒に削除されます。

**料金：** 組み込みの料金表に GPT-6.1 Terra を追加しました。

## 変更

- **ローカルルーティングが Web ページから送られたリクエストを受け付けなくなりました**。ローカルルーティングはリクエストを保存済みのプロバイダーの認証情報に差し替えて転送するため、Web ページがローカルルーティングにリクエストを送れると、あなたのクォータを使われてしまいます。現在はブラウザ由来を示すヘッダーが付いたリクエストを拒否し、通常のドメイン名でこのパソコンを指すアクセスも受け付けなくなりました。コーディングツールが送るリクエストには影響しません。
- **Skills の「見つける」ページのツールバーを「インストール済み」ページに揃えました**（[#9125](https://github.com/farion1231/cc-switch/pull/9125)）：検索ボックスの位置と幅が同じになり、更新ボタンは「リポジトリを更新」というテキストボタンに変わりました。ソース、リポジトリの絞り込みと「未インストールのみ」は表のヘッダーに移り、「インストール先」はヘッダーの右側に置きました。1 行減りましたが、機能は変わりません。
- **Windows で優先ターミナルが PowerShell の場合、PowerShell 7 がインストールされていればそれで開くようになりました**（[#8992](https://github.com/farion1231/cc-switch/pull/8992)、[#3271](https://github.com/farion1231/cc-switch/issues/3271)）。インストールされていない場合だけ、システム標準の Windows PowerShell を使います。プロバイダーカードの「ターミナルを開く」と、アプリのインストール・アップグレードのどちらも同じです。
- **プリセット：** 千問 AI プラットフォームと QwenCloud の従量課金と Token Plan は新しい MaaS ドメインに変更しました。Coding Plan は変わりません。

## 修正

- **ルーティングモードや集約モードで、Claude Code カードの「ターミナルを開く」にルーティングや集約の設定が混ざる問題**。ターミナルの Claude Code がルーティングのプレースホルダー認証情報とこのカードの Key を同時に持ってしまい、このカードで設定していないモデル段階には集約のモデル名が使われ、このカードのアドレスに送っても使えませんでした。`/model` メニューにもほかのプロバイダーのモデルが表示されていました。現在はターミナルではこのカード自身の設定だけを使い、そのほかのグローバル設定はこれまでどおり引き継がれます。
- **ルーティングモードで、OpenCode Go など `ANTHROPIC_API_KEY` に Key を保存するプロバイダーを使うと、Claude Code がカスタム Key の確認を求め、既定の「No」を選ぶと未ログインになる問題**（[#8111](https://github.com/farion1231/cc-switch/pull/8111)、[#8104](https://github.com/farion1231/cc-switch/issues/8104)）。現在はルーティングモードではプレースホルダー認証情報を常に `ANTHROPIC_AUTH_TOKEN` に書き込みます。上流に送るリクエストは変わりません。
- **テキスト専用モデルに一度ファイルや音声を送ると、それ以降のターンがすべて 400 エラーになる問題**（[#6274](https://github.com/farion1231/cc-switch/pull/6274)、[#6151](https://github.com/farion1231/cc-switch/issues/6151)）。現在はルーティング経由でテキスト専用モデルに送るとき、会話内のファイルと音声を説明テキストに置き換えます。智譜 GLM の中国語のエラーメッセージも認識できるようになりました。画像の扱いは変わりません。
- **Windows でプロバイダーフォームの名前などの内容がちらつく問題**（[#6420](https://github.com/farion1231/cc-switch/pull/6420)、[#6349](https://github.com/farion1231/cc-switch/issues/6349)）。WebView2 の自動入力がフォームの内容を上書きしていたためで、メインウィンドウではこれをオフにしました。
- **起動後しばらくトレイパネルが開かず、トレイから終了することもできない問題**（[#9154](https://github.com/farion1231/cc-switch/pull/9154)）。起動時のセッション使用量の取り込みがデータベースを占有し、トレイパネルはデータを待っていました。現在はパネルを先に表示し、「メインウィンドウを開く」と「終了」はすぐに使え、一覧は後から読み込まれます。
- **Codex がルーティング経由でモデルマッピングを使うと、同じリクエストの使用量が二重に計上される問題**（[#7643](https://github.com/farion1231/cc-switch/pull/7643)、[#5526](https://github.com/farion1231/cc-switch/issues/5526)）。セッションログには Codex が使ったモデル名が、ルーティングにはマッピング後のモデル名が記録され、重複排除のときに一致しませんでした。現在は両者を照合できるようになりました。
- **Pi の公式サンプルのサブエージェントが使った分が集計されない問題**（[#8386](https://github.com/farion1231/cc-switch/pull/8386)、[#8340](https://github.com/farion1231/cc-switch/issues/8340)）。現在はサブエージェントごとにプロバイダーとモデル別に記録し、アップグレード後に以前の Pi セッションを 1 回読み直して補完します。
- **Pi から MCP をインポートすると、Pi が対応していないサーバーもインポートされて有効になり、その後の同期が毎回失敗する問題**（[#7888](https://github.com/farion1231/cc-switch/pull/7888)）。SSE 接続方式のサーバー、名前が規則に合わないサーバー、名前が `-` と `_` の違いしかないサーバーは、現在はスキップして通知します。Pi がインストールされていない場合も、Pi の MCP 設定ファイルを作成しなくなりました。
- **ターミナルや CC Switch でだけプロキシを設定し、システムプロキシを設定していないと、models.dev の料金同期が失敗し続ける問題**（[#8739](https://github.com/farion1231/cc-switch/pull/8739)、[#6696](https://github.com/farion1231/cc-switch/issues/6696)）。現在は CC Switch のバックエンドでダウンロードするようにしたため、設定したプロキシを経由します。モデル料金のインポートと、フォームでのモデルパラメーターの自動入力も同様です。
- **Claude Code がルーティング経由で xAI に接続するとき、Web 検索を強制するリクエストが xAI に拒否され、422 になる問題**（[#8664](https://github.com/farion1231/cc-switch/pull/8664)）。
- **Pi での MiniMax M3.1 Flash の思考レベル**（[#8540](https://github.com/farion1231/cc-switch/pull/8540)）：2 つの MiniMax 公式プリセットから、このモデルが受け付けない「オフ」と「最小」を外しました。それ以外のレベルは通常どおり送信します。
