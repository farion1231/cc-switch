# CC Switch v4.0.31

今回のリリースでは、管理対象アプリに **Tencent WorkBuddy** を追加しました。カスタムモデルは WorkBuddy 自身のモデル設定に書き込まれ、WorkBuddy の中でそのまま選べます。また、複数の WorkBuddy アカウントを切り替えることができ、切り替える前に各アカウントのプラン、残りのクレジット、有効期限を確認できます。インターフェースに**ドイツ語**を追加し、README もインターフェースの 8 つの言語すべての版がそろいました。

このほか、Claude Code がルーティング経由で OpenAI Responses 形式の中継サービスに接続すると、同じ中継サービスによってセッションが別々の Azure リソースに振り分けられた後、毎ターン 400 になって続けられなくなる問題、ルーティング経由で Gemini Native 形式の上流に接続すると、並列ツール呼び出しで 400 になり、キャッシュヒット率も低い問題、macOS でトレイのツールチップが画面に表示されたままになる問題、Codex で再開した古い会話の使用量がまったく取り込まれない問題などを修正しました。

## 新機能

### WorkBuddy

Tencent WorkBuddy が新しい管理対象アプリになりました（[#8757](https://github.com/farion1231/cc-switch/pull/8757)、要望は [#4802](https://github.com/farion1231/cc-switch/issues/4802)、[#5802](https://github.com/farion1231/cc-switch/issues/5802)、[#7419](https://github.com/farion1231/cc-switch/issues/7419)、[#7076](https://github.com/farion1231/cc-switch/issues/7076)）。OpenCode と同じく、複数のプロバイダーを同時に有効にできます：

- **カスタムモデル**：「追加」をクリックすると、プロバイダーのモデルが WorkBuddy 自身の `models.json` に書き込まれ、WorkBuddy のモデル選択に「名前:モデル ID」と表示されます（名前が空のときは「ベンダー表示名」を使います）。WorkBuddy の中で自分で追加したモデルはそのまま残ります。WorkBuddy のカスタムモデルは OpenAI Chat Completions 形式にのみ対応しています。
  - プリセットのモデルは WorkBuddy のモデル選択で思考レベルを選べます（たとえば Kimi K3.1 Pro の low / high / max）。
  - WorkBuddy は現在、同じモデル ID を 2 回使うことに対応していません。プリセットを選ぶと、ほかのカードですでに使われているモデルをスキップし、どのカードで使われているかを表示します。重複したモデル ID を手動で入力すると、その箇所が示され、保存できません。
- **公式アカウント**：WorkBuddy でログインしたことのあるアカウントは自動で「アカウント」ページに取り込まれ、ニックネーム、プラン、残りのクレジット、クレジットの有効期限（3 日以内に期限が切れる場合はオレンジ色）を表示します。アカウントを切り替える方法は 2 つあります：このアカウントを紐付けた「WorkBuddy 公式ログイン」カードを追加するか、「アカウント」ページでこのアカウントのメニューから「WorkBuddy をこのアカウントに切り替え」をクリックします。
  - **切り替える前に WorkBuddy を完全に終了してください**（メニューバー / トレイを含む）。終了しないと、WorkBuddy が現在のログインを書き戻してしまいます。
  - 「別のアカウントでログイン」は、このパソコン上で WorkBuddy をログイン画面で止めるだけで、サーバー側で現在のアカウントをログアウトすることはありません。取り込み済みのアカウントには引き続き切り替えて戻せます。
  - プランとクレジットは、WorkBuddy が起動していて、そのアカウントでログインしているときにのみ取得でき、取得した結果はキャッシュして表示します。
- **MCP、Skills、プロンプト**：WorkBuddy の `mcp.json`、Skills フォルダー、グローバルプロンプト `CODEBUDDY.md` に同期します。WorkBuddy のコネクタが管理する MCP エントリは変更しません。
- **セッション管理と使用量統計**：WorkBuddy のセッションを一覧表示し、セッションログから使用量を取り込みます。セッションをターミナルで再開することはできません。

### ドイツ語のインターフェースと 8 言語の README

- **ドイツ語**：初回起動時にシステムの言語に合わせて自動で選ばれ、トレイメニューとクイックパネルも翻訳済みです。プライバシーフィルターのプレースホルダーは、ドイツ語のインターフェースでも韓国語・ロシア語と同じく当面は英語を使います。
- README に繁体字中国語、韓国語、トルコ語、ロシア語の版を追加し、インターフェースの 8 つの言語と一対一で対応するようになりました。

### その他

- **Skills ページ右上の「⋯」メニューから直接「今すぐ再同期」を実行できるように**（[#9417](https://github.com/farion1231/cc-switch/issues/9417)）：「保存と同期」の中を探す必要がなくなりました。
- **セッション管理で「プロジェクト別」にグループ化したとき、Codex デスクトップ版でどのプロジェクトにも属さない会話を「Codex チャット」の 1 グループにまとめるように**（[#9415](https://github.com/farion1231/cc-switch/issues/9415)）：会話ごとに別々のグループになることはなくなりました。
- **リクエストログのステータスコードの絞り込みに 403、404、502、503、504、520、529 を追加**（[#9425](https://github.com/farion1231/cc-switch/issues/9425)）。

## 変更

- **プライバシーフィルターをリクエスト送信前の最後のステップで適用するように変更**（[#9460](https://github.com/farion1231/cc-switch/pull/9460)）：これまではリクエストがルーティングに入った直後にフィルタしていたため、フェイルオーバーの再試行や、CC Switch 自身が生成する圧縮の要約など、後からリクエストに加わる内容は処理されませんでした。現在は上流に送るたびにフィルタするため、対象範囲が広がりました。ツールの説明文は処理しません。検出も速くなり、結果は以前と同じです。
- **Codex の使用量の取り込みを高速化**（[#9400](https://github.com/farion1231/cc-switch/pull/9400)）：Codex のセッションログを読み込むときの重複した解析とメモリ割り当てを減らしました。

## 修正

- **Claude Code / Claude Desktop がルーティング経由で OpenAI Responses 形式の中継サービスに接続すると、ときどき 400「The requested item was created under a different Azure OpenAI resource」になり、その後は同じセッションで毎ターンエラーになる問題**（[#9424](https://github.com/farion1231/cc-switch/issues/9424)）。中継サービスが同じセッションを別々の Azure OpenAI リソースに振り分けたため、セッション履歴に別のリソースが生成した思考の記録が含まれていました。セッションの途中でプロバイダーを切り替えた場合も、同様の `invalid_encrypted_content` になります。現在は上流がこのように拒否した場合、これらの思考の記録を取り除いて自動で 1 回再試行するため、セッションを続けられます。正常なリクエストには影響しません。
- **Claude Code がルーティング経由で Gemini Native 形式の上流に接続すると、並列ツール呼び出しの後に 400「number of function response parts」になる問題**（[#9453](https://github.com/farion1231/cc-switch/issues/9453)）：複数のメッセージに分かれたツールの実行結果を、1 つにまとめてから送るようにしました。
- **Claude Code がルーティング経由で Gemini Native 形式の上流に接続すると、長いセッションのキャッシュヒット率が 2 割程度にとどまる問題**（[#9450](https://github.com/farion1231/cc-switch/issues/9450)）：Claude Code は毎ターン残りトークン数の通知を 1 件追加しますが、これまではそれが履歴全体の先頭に移されていたため、毎ターンの先頭部分が変わっていました。現在は元の位置に残すため、それより前の履歴は毎ターン変わらず、キャッシュにヒットします。
- **Claude Code がルーティング経由で Gemini Native 形式の上流に接続すると、ストリーミングリクエストで記録される使用量が少なく、キャッシュ読み取りがしばしば 0 と記録される問題**（[#9464](https://github.com/farion1231/cc-switch/issues/9464)）。
- **macOS でトレイアイコンの「CC Switch」のツールチップが画面に表示されたままになり、アプリを終了するしかなかった問題**（[#9445](https://github.com/farion1231/cc-switch/issues/9445)、[#9329](https://github.com/farion1231/cc-switch/issues/9329)、[#9446](https://github.com/farion1231/cc-switch/pull/9446)）：macOS ではこのツールチップを表示しないようにしました。問題があるときは、アイコンのドットとクイックパネルでこれまでどおりお知らせします。
- **macOS でほかのアプリがフルスクリーンのとき、メニューバーのアイコンをクリックしてもクイックパネルが表示されない問題**（[#9331](https://github.com/farion1231/cc-switch/issues/9331)）。
- **Claude Code のルーティングモードで、プロバイダーに設定した `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` が `settings.json` に書き込まれない問題**（[#9451](https://github.com/farion1231/cc-switch/issues/9451)、[#9455](https://github.com/farion1231/cc-switch/pull/9455)）：現在はプロバイダーのほかの固有設定と同じくプロバイダーとともに書き込まれ、あなたがグローバルに設定した値も切り替えによって消されることはありません。
- **Codex で終了済みの古い会話を再開した後、新たに発生した使用量がいつまでも取り込まれない問題**（[#9420](https://github.com/farion1231/cc-switch/issues/9420)）。
- **Codex でサードパーティプロバイダーに直接接続しているとき、「直接切替時に公式ログインを保持」をオフにしてもすぐには反映されず、公式カードに切り替えてから戻す必要があった問題**（[#9367](https://github.com/farion1231/cc-switch/issues/9367)）：現在は設定を変更するとすぐに現在のプロバイダーの設定を書き直します。
- **Codex のサードパーティプロバイダーにある公式と同名の GPT モデルで、モデル選択に自分で設定した表示名が表示されない問題**（[#9380](https://github.com/farion1231/cc-switch/issues/9380)）。
- **macOS で Claude Desktop をアンインストールした後も、「アプリ」ページにインストール済みとして表示される問題**（[#9383](https://github.com/farion1231/cc-switch/issues/9383)）：現在は `Claude.app` だけで判定し、残ったデータフォルダーは数えません。
- **Linux の KDE Wayland で、コピーボタンが成功と表示するのに、クリップボードが空か古い内容のままになる問題**（[#9384](https://github.com/farion1231/cc-switch/issues/9384)）。
- **Copilot CLI 公式カードのアカウントのドロップダウンで、アカウントを紐付けない選択肢が「デフォルトアカウントを使用」と書かれていたのに、実際には Copilot CLI 自身の GitHub ログインを使っていた問題**（[#9408](https://github.com/farion1231/cc-switch/issues/9408)）：現在は「Copilot CLI 自身のログインに従う」と表示します。
- **DeepSeek Harness で手動追加したモデルに互換性オプションを設定できなかった問題**（[#9330](https://github.com/farion1231/cc-switch/issues/9330)）：現在は互換性エディターも表示されるため、百煉（DashScope）の互換モードのような `developer` ロールを受け付けないインターフェースでは、このロールをオフにできます。
- **Skill を有効にするときにシンボリックリンクの作成に失敗したと表示されるだけで、具体的な原因がわからない問題**（[#9439](https://github.com/farion1231/cc-switch/issues/9439)）：エラーメッセージにシステムが返したエラーコード（たとえば Windows の `os error 5`）を含めるようにし、権限の問題なのかほかの原因なのかを判断しやすくしました。
- **サイドバー下部の「アプリ」と「設定」が、ドイツ語・トルコ語・ロシア語のインターフェースで途中で切れて表示される問題**。

## アップグレードに関する注意

**データベースのバージョンが 25 から 26 に上がります。** MCP と Skills に WorkBuddy のスイッチを追加するためです。アップグレード前にデータベースは自動でバックアップされます。アップグレード後に旧バージョンに戻すと、旧バージョンはデータベースのバージョンが新しすぎると表示し、開けません。
