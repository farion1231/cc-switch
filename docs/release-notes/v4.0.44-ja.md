# CC Switch v4.0.44

今回のリリースでは、ZCode（Zhipu のコーディングクライアント）に対応しました。プロバイダーとモデルの上限、MCP、Skills、プロンプトを管理でき、セッションの表示と使用量の取り込みもできます。Antigravity のアカウントは、すべて agy 自身に任せるようになりました。アカウントを追加するとターミナルが開き、agy の中でログインします。残量は agy の `/usage` で確認し、CC Switch が agy の代わりにログイン、トークンの更新、残量の照会を行うことはなくなりました。Claude Desktop に Command Code のプリセットを追加しました。

このほか、Chat Completions の中継経由で Codex から Gemini を呼び出すとツール呼び出しが拒否される問題、アカウントファイルを読み込めないときに保存済みのアカウントが上書きされる問題、サードパーティの Key の残りを片付けるときに一時保存した ChatGPT のログインが失われる問題、競合する環境変数を削除すると同じ名前の行がすべて削除される問題、取得したモデル一覧に画像や動画など会話用以外のモデルが混ざる問題、`.claude/skills` の下にしかないスキルを skills.sh からインストールできない問題、トレイパネルに早い段階でスクロールバーが出る問題、Grok Build だけを表示しているときに「アカウント」ページに xAI のカードがない問題、ローカルルーティングでストリーミング応答を変換するときに 1 つのイベントの大きさに上限がない問題、いくつかのエラーメッセージと案内文を修正しました。

## 新機能

### ZCode に対応

（[#9824](https://github.com/farion1231/cc-switch/pull/9824)。[#8076](https://github.com/farion1231/cc-switch/pull/8076)、[#5644](https://github.com/farion1231/cc-switch/pull/5644) を引き継いでいます）

ZCode は 18 番目の管理対象アプリで、OpenCode や Hermes と同じく、複数のプロバイダーを同時に追加できます。

- **プロバイダー**：`~/.zcode/v2/provider_config.json` の個人のプロバイダー層に書き込みます。ZCode で自分で追加したプロバイダーやログインしたアカウントは、CC Switch では取り込まず、変更もしません。ZCode はデスクトップアプリのため、保存した後に ZCode のプロバイダー選択でこのプロバイダーに切り替えると反映されます。
- **モデル**：「モデル一覧を取得」をクリックしてプロバイダーから取得することも、モデル ID を手動で入力することもできます。各モデルのコンテキストと出力の上限は、空欄なら ZCode の推奨値を使い、入力したものはプロバイダーと一緒に書き込み、一緒に削除します。ZCode にはモデルの表示名がないため、フォームにも表示名の欄はありません。
- **MCP、Skills、プロンプト**：MCP は `~/.zcode/cli/config.json` に書き込みます。プロンプトは `AGENTS.md` です。設定で ZCode の設定ディレクトリを変更できます。
- **セッションと使用量**：ZCode の `~/.zcode/cli/db/db.sqlite` から読み込みます。セッションは CC Switch では削除できず（履歴も使用量も ZCode 自身のデータベースに保存されているため）、ZCode で削除するよう案内します。
- **ディープリンク**：プロバイダーと MCP のリンクのどちらも `zcode` に対応し、プロバイダーのリンクにはモデルの指定が必要です。

GLM Coding Plan を使う ZCode のカードには、プランの残量を自動で表示します。「アプリ」ページでは ZCode のインストールとアップグレードを提供しません。ZCode が自分で更新します。

### Claude Desktop の Command Code プリセット

（[#10045](https://github.com/farion1231/cc-switch/issues/10045) を参照）

Claude Code の Command Code プリセットと同じく、OpenAI Chat 形式でローカルルーティング経由で転送し、3 つのモデル枠すべてで `deepseek/deepseek-v4.1-flash`（1M コンテキスト）を使います。

### プリセット

TeleAI（Xing4.1-Preview）、FastAIToken を追加しました。

## 変更

### Antigravity のアカウントで agy のログインクライアントを使わないように

Google は最近、サードパーティのツールが Antigravity 付属の OAuth クライアントを使うことを認めないと明言しました。CC Switch はこれまでまさにそうしていました。agy に組み込まれたクライアント ID でログインとトークンの更新を行い、agy として Google に直接残量を問い合わせていました。今回これらのリクエストをすべて取り除き、CC Switch が Antigravity のアカウントのために独自のリクエストを送ることはなくなりました。

- **アカウントを追加**：ターミナルを開いて `agy` を実行します。agy の中で `/logout` してから `/login` すると、新しいログインが現れたところで「アカウント」ページが自動で取り込みます。それまでログインしていたアカウントは先に取り込むため、agy でログアウトしても失われません。
- **残量**：agy 自身の `/usage` だけで確認するため、agy に現在ログインしているアカウントの残量しか取得できません。ほかのアカウントには、切り替える前に最後に取得した残量を表示します。
- **プラン**：`/usage` はプランを返さないため、「アカウント」ページに Antigravity のプランの行を表示しなくなりました。
- **トークンの更新**は agy 自身に任せます。保存済みのアカウントはこれまでどおり切り替えられます。

[#10004](https://github.com/farion1231/cc-switch/pull/10004) で修正した残量照会の並列実行とリクエストの増幅、[#10047](https://github.com/farion1231/cc-switch/pull/10047) で修正した Windows で残量を照会するときに黒いウィンドウが一瞬表示される問題は、どちらも今回削除したコードに含まれていました。`/usage` に変更したことで、この 2 つの問題も起きなくなります。

## 修正

- **Chat Completions の中継経由で Codex から Gemini を呼び出すと、ツール呼び出しのたびに 400 エラーになる**（[#9168](https://github.com/farion1231/cc-switch/issues/9168)、[#10032](https://github.com/farion1231/cc-switch/issues/10032) を参照）：Codex のツール定義には、Gemini が受け付けない書き方が 2 つあります。1 つはマルチエージェントのツールのパラメーターに付く `"encrypted": true` マーカー、もう 1 つは `{"type": "boolean", "enum": [true]}` のような文字列以外の列挙値です。現在は Chat 形式に変換するときに `encrypted` マーカーを常に取り除きます。文字列以外の列挙値は Gemini のモデルに送るときだけ書き換え、ほかのモデルはこの点の影響を受けません。
- **アカウントファイルを読み込めないと、保存済みのアカウントが上書きされる**（[#10020](https://github.com/farion1231/cc-switch/pull/10020)）：WorkBuddy、Antigravity、CodeBuddy、Claude のアカウントファイルが壊れているか読み込めない場合、これまでは空の一覧として扱い、次に保存したときにすべてのアカウントを上書きしていました。現在は元のファイル名の後ろに `.unreadable-` とタイムスタンプを付けてその場に残し、空の一覧から始めます。
- **Codex でサードパーティの Key の残りを片付けるときに、一時保存した ChatGPT のログインが失われる**（[#10027](https://github.com/farion1231/cc-switch/pull/10027)）：サードパーティの Key が `OPENAI_API_KEY` として `auth.json` に残っている場合、それを片付ける操作が自分でログアウトしたものとみなされ、一時保存した ChatGPT のログインが無効になり、公式カードに戻してもログインできなくなっていました。
- **競合する環境変数を削除すると、同じ名前の行がすべて削除される**（[#10025](https://github.com/farion1231/cc-switch/pull/10025)）：現在は一覧に表示された行だけを削除します。スキャンした後にファイルが変更され、その行がもうこの変数を設定していない場合は削除を拒否します。
- **取得したモデル一覧に画像、動画、埋め込み、リランクのモデルが混ざる**（[#10026](https://github.com/farion1231/cc-switch/issues/10026) を参照）：new-api のような中継サーバーはモデル一覧に Nano Banana、Seedream、Seedance などを載せており、「すべて選択」すると Codex のモデルカタログに書き込まれ、それを会話用のモデルに選ぶとメッセージのたびにエラーになっていました。現在は中継サーバーが示すエンドポイントの種類に基づいてこれらのモデルを除外します。種類が示されていないモデルはこれまでどおり残します。
- **`.claude/skills` の下にしかないスキルを skills.sh からインストールできない**（[#10040](https://github.com/farion1231/cc-switch/issues/10040) を参照）：これまでは「スキルディレクトリが見つかりません」と表示されていました。現在は見えるディレクトリで見つからない場合、`.` で始まるディレクトリも探します。
- **トレイパネルに早い段階でスクロールバーが出る**（[#10034](https://github.com/farion1231/cc-switch/issues/10034) を参照）：各アプリに残量バーが付くようになり、アプリが 5 つあるだけで従来の上限 620 px を超え、最後のアプリがスクロール領域に押し出されていました。現在は上限を 760 px に引き上げました。画面の空きが足りない場合はこれまでどおりスクロールします。
- **Grok Build だけを表示していると、「アカウント」ページに xAI のカードがない**（[#10030](https://github.com/farion1231/cc-switch/pull/10030)、[#10029](https://github.com/farion1231/cc-switch/issues/10029) をクローズ）：xAI と GitHub Copilot のカードの説明にも、Grok Build、Codex、Copilot CLI を追記しました。
- **ローカルルーティングでストリーミングレスポンスを変換するとき、1 つのイベントのサイズに上限がない**（[#9938](https://github.com/farion1231/cc-switch/pull/9938)、[#9937](https://github.com/farion1231/cc-switch/issues/9937) をクローズ）：上流が区切りをいつまでも送らないと、メモリが増え続けていました。現在は 1 つのイベントの上限を 64 MiB とし、超えた場合はエラーにしてそのレスポンスを終了します。
- **プラグインの「マーケットプレイス」が CLI の出力を読み込めないと空で表示される**（[#10024](https://github.com/farion1231/cc-switch/pull/10024)）：現在は読み込みに失敗したことを表示します。
- **Skill の上書きを拒否したときのメッセージが常に Pi になっている**（[#10044](https://github.com/farion1231/cc-switch/pull/10044)）：Oh My Pi や MiniMax Code などのアプリで Skill の更新やアンインストールが拒否されたとき、メッセージには現在のアプリ名を表示します。
