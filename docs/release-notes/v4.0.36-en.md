# CC Switch v4.0.36

This release adds a **Plugins** page for installing, enabling, updating and uninstalling plugins for Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw and Pi from within CC Switch, and for managing plugin marketplaces for Claude Code, Codex and Grok Build. Skill repositories can now **read private repositories with access tokens**; providers used through local routing can set a **cost multiplier**; and the Sessions page shows Claude Code desktop **chapters**.

Fixes cover Codex auto-approval being blocked too once "Official quota protection" was on; new official models taking a long time to appear in Codex aggregation mode; usage from OpenCode 1.x sessions no longer being counted after upgrading to 2.x; a custom date on the usage page turning into 1905 as soon as a year was typed; several Antigravity models shown as unpriced; and more. Equally priced reasoning tiers are now merged into one row in usage statistics.

---

## New

### Plugins page

A new "Plugins" item in the sidebar manages plugins through each app's own CLI (requested in [#791](https://github.com/farion1231/cc-switch/issues/791), [#9220](https://github.com/farion1231/cc-switch/pull/9220)):

- Supports Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw and Pi; only apps that are not hidden are listed.
- In "Installed" you can enable, disable, update and uninstall plugins (MiniMax Code has no update); in "Discover" you search for and install them; in "Marketplaces" (Claude Code, Codex and Grok Build) you add, refresh and remove plugin marketplaces, from a GitHub `owner/repo`, a Git URL or a local folder. Pi's plugins are Pi packages from npm.
- For Grok Build, OpenClaw and Pi, CC Switch asks for confirmation before installing: plugins run with your permissions, so only install them from sources you trust. For a Claude Code plugin that needs consent in a terminal, CC Switch does not give that consent for you; it tells you which install command to run in a terminal. Apps that need you to sign in first show the sign-in command too.
- In `config.toml`, disabling a Codex plugin only changes that plugin's `enabled`; everything else, comments included, is left as is.
- Downloading a large marketplace repository can take a few minutes. You can close the dialog in the meantime; you'll be notified when it finishes.

### Private skill repositories

In "Manage Skill Repositories" you can now set an access token per site, so private repositories on GitHub, GitLab and Gitea / Forgejo can be browsed, installed from and checked for updates (requested in [#9666](https://github.com/farion1231/cc-switch/issues/9666)).

- Tokens are saved per site (such as `github.com` or `gitlab.example.com`) in the system credential store (macOS Keychain, Windows Credential Manager; on other systems, a file on this computer that only you can read) and are not cloud-synced. Read-only access is enough.
- When a download fails, the message now tells a missing token apart from a rejected one (invalid, expired, or without permission to read the repository).

### Provider cost multiplier

When a relay bills at a discount, the cost in usage statistics can be estimated with a multiplier ([#9656](https://github.com/farion1231/cc-switch/pull/9656)). The forms for non-official providers of Claude Code, Codex, Gemini CLI and Grok Build have a new "Provider cost multiplier" field: the reference prices of all of that provider's models are multiplied by it. 0.5 means half price; empty means 1x.

- It applies only to requests that go through local routing and are made after it is set; usage imported from session logs in direct mode is still counted at 1x.

### Claude Code desktop chapters on the Sessions page

Chapters that the model marks in a Claude Code desktop conversation used to be shown as ordinary MCP tool calls (requested in [#9728](https://github.com/farion1231/cc-switch/issues/9728), [#9729](https://github.com/farion1231/cc-switch/pull/9729)). They are now shown as chapter rows, which stay visible when the timeline is collapsed; the conversation outline lists them and jumps to one when clicked; Find matches them; and they become headings when exported to Markdown.

## Changes

- **Usage statistics merge reasoning tiers that have the same price** ([#8845](https://github.com/farion1231/cc-switch/pull/8845), see [#9065](https://github.com/farion1231/cc-switch/issues/9065)): when a model's reasoning-effort variants have the same input, output, cache read and cache write prices as the base model, and the base model has an exact price, they are merged into the base model's row. Filters, daily summaries and time to first token use the merged grouping; request logs still show the original model name.

## Fixes

- **With "Official quota protection" on, Codex auto-approval was also blocked once a threshold was reached** ([#9733](https://github.com/farion1231/cc-switch/pull/9733), see [#9732](https://github.com/farion1231/cc-switch/issues/9732)): OpenAI has made Codex's auto-approval model `codex-auto-review` free and not counted against the plan's quota, so quota protection now always lets it through; other official models are still paused as before.
- **In Codex aggregation mode, newly released official models (such as GPT-6.2) took a long time to appear**: in aggregation mode Codex reads only the model catalog that CC Switch writes. The official model list is now cached for 1 hour instead of 6; the Codex version reported when fetching the list also takes into account the CLI bundled with the desktop app and the version Codex itself records, so after the desktop app auto-updates, the list is no longer fetched for the old version with models missing.
- **After upgrading OpenCode to 2.x, sessions created or continued in 1.x afterwards were not counted in usage** ([#8363](https://github.com/farion1231/cc-switch/pull/8363), see [#8361](https://github.com/farion1231/cc-switch/issues/8361)): when the old and new data layouts coexist, both are now read, and each message is counted once. Databases scanned before continue from where the last scan stopped and do not backfill earlier records.
- **Typing a year by hand into a custom date on the usage page turned it into 1905 right away** (see [#9699](https://github.com/farion1231/cc-switch/issues/9699)): a typed date now takes effect only once it is complete, and is not rewritten while you type.
- **Several Antigravity models showed as "Unpriced" in usage statistics**: Gemini Flash tiered versions (such as `gemini-3.8-flash-tiered`, used by the built-in browser sub-agent) are billed at the Flash base price ([#9600](https://github.com/farion1231/cc-switch/pull/9600)); Hydrogen tiered versions are billed at the base price ([#9706](https://github.com/farion1231/cc-switch/pull/9706), see [#9705](https://github.com/farion1231/cc-switch/issues/9705)); with Orchestrator, worker steps are attributed to Gemini 4 Hydrogen ([#9686](https://github.com/farion1231/cc-switch/pull/9686), see [#9685](https://github.com/farion1231/cc-switch/issues/9685)), and planner steps to Gemini 4 Neon, whose price is added ([#8845](https://github.com/farion1231/cc-switch/pull/8845)); Claude Thinking versions (such as Claude Opus 4.6 (Thinking)) are billed like their base model. Existing unpriced records are repriced automatically.
- **In Claude Desktop route mode, leaving the model list empty used the default Claude model names instead of the provider's models** (see [#9735](https://github.com/farion1231/cc-switch/issues/9735)): this is how route mode works, and the form hint now says so: in direct mode an empty list makes Claude Desktop fetch `/v1/models` automatically; in route mode, fill in the model list to use the provider's models.
- **MCP servers in DeepSeek Harness's home-level `cordis.patch.yml` did not show up in CC Switch, with no explanation** (see [#9714](https://github.com/farion1231/cc-switch/issues/9714)): CC Switch reads and writes only each profile's files. The MCP import dialog now states that the home-level file is neither read nor written, and that its MCP servers are managed in that file.
