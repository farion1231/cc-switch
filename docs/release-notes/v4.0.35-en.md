# CC Switch v4.0.35

This release makes **GPT-6.2** available to the Codex cards in Claude Code / Claude Desktop that use a ChatGPT account, shows the **full objective** of Codex `/goal` on the Sessions page, and lets you **copy** the request ID in request details with one click.

Fixes cover Claude Code's auto mode being blocked entirely on models that cannot turn thinking off; Codex reporting that Responses-Lite requires `reasoning.context` in aggregation mode and from "Open Terminal"; the first Codex request after a context compaction being rejected; the usage page freezing when a custom date was set to a very early year; Skills that could not be uninstalled once their managed copy was gone; and more.

---

## New

### Full Codex `/goal` objective on the Sessions page

When an objective is longer than 700 bytes, Codex leaves it out of the context it injects, so the Sessions page could not show the objective either (see [#9647](https://github.com/farion1231/cc-switch/issues/9647)). The full objective is now read from the session log and shown as a "Goal · status" step that expands to the full text; repeated entries where neither the objective nor the status changed are no longer shown.

### Copying the full request ID in request details

Long values in request details are cut off with an ellipsis, so long request IDs such as Codex's `resp_...` could not be copied in full to match against logs (see [#9681](https://github.com/farion1231/cc-switch/issues/9681)). There is now a copy button after the request ID.

### Pricing for GPT-6.2 Sol / Astra

Billed at the official standard tier (up to 272K); the long-context tier and tiers such as Batch / Fast are not distinguished yet, same as GPT-6.

## Fixes

- **Codex cards in Claude Code / Claude Desktop using a ChatGPT account could not fetch GPT-6.2, and entering it by hand failed with "not supported when using Codex with a ChatGPT account"** ([#9678](https://github.com/farion1231/cc-switch/pull/9678), see [#9670](https://github.com/farion1231/cc-switch/issues/9670)): OpenAI decides which models to offer based on the Codex client version, and the version CC Switch reported was too old. Requests now identify as Codex 0.169.0, with no model IDs hard-coded.
- **Claude Code's auto mode denied every Bash, MCP and other tool call on models that cannot turn thinking off** (see [#8887](https://github.com/farion1231/cc-switch/issues/8887), [#9671](https://github.com/farion1231/cc-switch/issues/9671)): auto mode's check request asks for thinking to be turned off, models such as MiniMax-M3.1-Flash reject that with a 400, and Claude Code then treats the check as unavailable. Now, in route mode (Claude Code and Claude Desktop), when an Anthropic-format upstream returns this error the field that turns thinking off is removed and the request is retried once with the same provider. Requests the upstream already accepts are sent unchanged, so caching is not affected.
- **Codex reported "Responses-Lite requires `reasoning.context` to be `all_turns`" in aggregation mode, while the same provider worked in direct and route mode** (see [#9665](https://github.com/farion1231/cc-switch/issues/9665)): for cards without a model catalog, aggregation mode now uses the same official GPT-6 settings as direct mode. The same error when using "Open Terminal" from a card is fixed too.
- **When Codex was routed to a Chat-format provider, the first request after a context compaction was rejected by strict gateways with "message content cannot be empty"** (see [#9660](https://github.com/farion1231/cc-switch/issues/9660)): compaction turns user messages that held only images into empty messages; user messages with empty content are now dropped when converting to the Chat format, and other messages are unchanged.
- **The app froze when the start of a custom date range on the usage page was set to a very early year such as 1905** (see [#9691](https://github.com/farion1231/cc-switch/issues/9691)): only dates from the first usage record to today can be selected now; dates outside that range are disabled, and dates typed by hand are pulled back into the range.
- **A Skill could not be uninstalled once its managed copy was gone** ([#9669](https://github.com/farion1231/cc-switch/pull/9669), see [#9668](https://github.com/farion1231/cc-switch/issues/9668)).
