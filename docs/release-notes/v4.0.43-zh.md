# CC Switch v4.0.43

本版本为授权中心增加了「自动查询额度」开关：关掉后，官方账号的额度只在你点刷新时才查，适合经代理上网、不想在代理就绪前直连官方服务的情况。托盘里也能直接切换 Antigravity 官方账号，每个账号旁边显示剩余额度。「应用」页现在认得 OpenCode 2，能正确检查更新、升级和卸载；OpenCode 2.4 的会话也能显示助手回复了。用量统计的速度只算成功的请求，并剔除中转缓冲后一次性吐出的异常值。

修复包括：先用 Chat Completions 供应商、再在直连模式下切回官方 ChatGPT 时 Codex 会话无法继续，macOS 每次退出后菜单栏图标位置被重置，`~/.gemini/.env` 里带引号的值，带块注释的 OpenClaw 配置被写坏，删除环境变量后 shell 配置丢了末尾换行，以及 Pi 的插件识别和更新问题。

## 新增

### 授权中心「自动查询额度」开关

（[#9325](https://github.com/farion1231/cc-switch/pull/9325)，见 [#8990](https://github.com/farion1231/cc-switch/issues/8990)）

打开授权中心、当前官方卡定时刷新、鼠标悬停托盘，都会自动向官方服务查询账号额度。经代理上网时，如果代理还没就绪，这些请求就会直连出去。现在授权中心顶部「登录时自动打开浏览器」下方多了一个「自动查询额度」开关，默认打开。

- **关掉后**：Claude、ChatGPT（Codex）、xAI、Kimi、Antigravity、GitHub Copilot、WorkBuddy、CodeBuddy 等官方账号的额度只在你点账号行的 ↻ 或「全部刷新」时查询。打开授权中心、卡片定时刷新、悬停托盘都不再自动发请求，已查到的结果照常显示。
- **没查过的账号**：显示「点刷新查询额度」和刷新按钮，不会是一片空白。
- **启动时**：设置读出来之前不查额度，关了开关的用户不会在启动那一刻漏出一次请求。
- **不受影响的**：第三方供应商的余额脚本照常刷新；DeepSeek 账号的余额和登录状态一起显示，也不受这个开关影响。

另外，「全部刷新」现在会刷新页面上所有账号（关掉自动查询时也一样）；WorkBuddy、CodeBuddy 还会跳过后台 5 分钟的缓存，拿到最新数字。

### 托盘切换 Antigravity 官方账号

托盘里多了一个 Antigravity 分区，列出授权中心里保存的 Antigravity 账号，每个账号旁边显示剩余额度（按 Gemini、Claude/GPT、Argon 分组，取每组最低的一档）。

- 勾选的是 agy 当前登录的账号。点另一个账号即切换，和在授权中心切换一样写入系统钥匙串；agy 正在运行时，会提示已打开的会话重启后生效。
- 当前账号的额度随托盘一起刷新，其他账号最多每 5 分钟刷新一次，各用各的登录，不需要先切过去。在授权中心查到的额度也会同步到托盘。
- 「管理账号…」打开授权中心；切换失败时也会打开授权中心。
- 授权中心里没有保存 Antigravity 账号时，不显示这个分区，也不会读钥匙串。

### 「应用」页支持 OpenCode 2

（覆盖 [#8727](https://github.com/farion1231/cc-switch/pull/8727)）

OpenCode 2 是一个单独的 npm 包（`@opencode/cli`，Homebrew 是 `anomalyco/tap/opencode-v2`），和 1.x 的 `opencode-ai` 并存。以前「应用」页只认 `opencode-ai`，装了 OpenCode 2 的用户会遇到：

- 最新版本取自 1.x，比本地的 2.x 还低，所以永远提示不了 2.x 的更新；
- 升级时装的是 `opencode-ai@latest`：npm 会报 EEXIST 失败，Windows 上的 pnpm 则不报错，却把 `opencode` 换成了一个没装好的 1.x，命令直接坏掉；
- 卸载不认 npm 和 `opencode-v2` 装的版本，还会留下安装脚本建的 `opencode2` 别名。

现在 CC Switch 按实际安装位置判断是 1.x 还是 2.x，更新检查、升级命令、npm 安装脚本设置和 Node 版本要求都用对应的包；卸载能找到所属的 npm 包（包括 WSL），认得 `opencode-v2`，只在 `opencode2` 确实是安装脚本建的时候才删它。新安装仍然装 1.x，不会替你在两条线之间切换；用 Volta 装的分不出来，仍按 1.x 处理。

## 变更

- **速度统计更准确**（[#9952](https://github.com/farion1231/cc-switch/pull/9952)，关闭 [#9950](https://github.com/farion1231/cc-switch/issues/9950)）：直通的流式响应按各协议（Anthropic、OpenAI Responses、OpenAI Chat、Gemini）识别真正的第一个输出 token，不再把元数据事件当成首字。速度和首字时间只算成功（2xx）的请求，超过 10,000 tok/s 的视为中转缓冲后一次性吐出，不算速度，请求详情里会说明原因。按供应商、模型汇总的速度仍是总输出 token 除以总生成时间。
- **Claude 会话日志的耗时从实际发出请求算起**：请求卡住时，Claude Code 会重发同一个请求。以前没开路由时，导入的耗时和首字时间从触发这次回复的消息算起，把卡住的那段（常常十几分钟）也算了进去，拉低了估算速度。较新的 Claude Code 会记下每次实际发出请求的时间，现在从那一刻算起。旧版日志照旧计算，已经导入的记录不变。
- **用量统计的应用筛选和侧栏顺序一致**（[#10006](https://github.com/farion1231/cc-switch/pull/10006)，关闭 [#10005](https://github.com/farion1231/cc-switch/issues/10005)）：包括在「应用」页拖过的顺序。
- **Codex「保留官方 Fast 档」说明**（见 [#10000](https://github.com/farion1231/cc-switch/issues/10000)）：卡片没有模型列表时，这个开关打开了也存不进去，现在会锁住并提示先在模型列表里加上 GPT 模型。说明里也写明：Codex 桌面版要登录 ChatGPT 才显示 Fast，用第三方卡时请打开设置里的「非接管切换时保留官方登录」（或使用路由模式），请求仍发往这张卡；命令行版不需要登录（`/fast`）。
- **插件页显示所属项目**（[#9963](https://github.com/farion1231/cc-switch/pull/9963)，关闭 [#9962](https://github.com/farion1231/cc-switch/issues/9962)）：Claude Code 的 `local` / `project` 插件在行下方显示所属项目目录，也能按目录搜索。删除多个项目的同名插件后不会再残留删不掉的行。
- **Linux 支持系统默认终端**（[#9987](https://github.com/farion1231/cc-switch/pull/9987)，关闭 [#9986](https://github.com/farion1231/cc-switch/issues/9986)）：「打开终端」在已知的终端都找不到时，会再依次尝试 `x-terminal-emulator` 和 `xdg-terminal-exec`，首选终端仍排在最前。
- **Skills 页 Pi 列的说明**（[#9971](https://github.com/farion1231/cc-switch/pull/9971)）：改为说明 Pi 也会读 `~/.agents/skills`，那里的技能没勾选也能直接用。

## 修复

- **直连模式下 Codex 会话切回官方 ChatGPT 后无法继续**（见 [#9054](https://github.com/farion1231/cc-switch/issues/9054)）：先用 Chat Completions 供应商时，转换出来的思考条目 ID 是 `rs_<response id>`。部分上游的回复 ID 正好是 32 位十六进制，形状和官方后端会去查找的 ID 一样，在直连模式下切回官方 ChatGPT 后报 `Item with id 'rs_resp_...' not found`，会话无法继续。现在 ID 末尾加上序号，官方后端不会再去查它。已经存在旧会话里的条目 ID 不会变，这些会话在直连模式下仍然会报错，请新开会话。
- **macOS 菜单栏图标位置每次退出后被重置**（见 [#6631](https://github.com/farion1231/cc-switch/pull/6631)）：从托盘退出、关闭主窗口退出和重启时，CC Switch 都会先移除托盘图标，而 macOS 移除时会删掉你按住 ⌘ 拖到的位置，Hidden Bar 这类工具的分组也随之失效。macOS 上不再主动移除，进程退出时系统会自己收走图标。
- **OpenCode 2.4 的会话不显示助手回复**（见 [#9982](https://github.com/farion1231/cc-switch/issues/9982)）：OpenCode 2.4 把助手回复的各段内容存进了新的 `session_part` 表，会话管理以前只读旧表，只看得到你的提问。现在两张表合起来读，搜索和删除会话也包括新表。
- **`~/.gemini/.env` 里带引号的值**（[#9928](https://github.com/farion1231/cc-switch/pull/9928)，关闭 [#9926](https://github.com/farion1231/cc-switch/issues/9926)）：Gemini CLI 官方文档就是用引号写的，以前导入后 Key 和地址会带着引号和行尾注释，路由也把它们原样发给上游。现在和 Gemini CLI 一样去掉。
- **OpenClaw 配置里有块注释时被写坏**（[#10002](https://github.com/farion1231/cc-switch/pull/10002)，关闭 [#10001](https://github.com/farion1231/cc-switch/issues/10001)）：`openclaw.json` 里有 `/* ... */` 时，CC Switch 一写就把结尾的 `/` 弄丢，文件再也读不出来。
- **删除冲突的环境变量后 shell 配置丢了末尾换行**（[#9929](https://github.com/farion1231/cc-switch/pull/9929)，关闭 [#9927](https://github.com/farion1231/cc-switch/issues/9927)）：之后再往文件末尾追加一行，会和最后一行粘在一起。现在除了删掉的那一行，其他内容（包括 CRLF 换行和末尾换行）原样保留。
- **通过 Vite+ 安装的 Pi 识别不出插件**（[#9976](https://github.com/farion1231/cc-switch/pull/9976)，见 [#9960](https://github.com/farion1231/cc-switch/issues/9960)）：从桌面启动的 CC Switch 拿不到 shell 配置里的 `VP_HOME` 等变量，`pi list` 实际跑成了 `vp list`。现在会从登录 shell 补上 Vite+ 用到的几个目录变量。
- **Pi 官方安装器装的版本点更新会再用 npm 装一份**（[#10015](https://github.com/farion1231/cc-switch/pull/10015)，关闭 [#10013](https://github.com/farion1231/cc-switch/issues/10013)）：现在改用 Pi 自己的 `pi update`。
- **Antigravity 卡换号失败时，云同步可能上传了没生效的绑定**（[#9978](https://github.com/farion1231/cc-switch/pull/9978)）：WebDAV / S3 现在会等换号完成或回滚后再取快照。
