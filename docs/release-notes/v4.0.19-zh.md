# CC Switch v4.0.19

本版本新增对 Kimi Code 的支持，它是 CC Switch 管理的第 12 个应用。**Kimi Code 的命令行版和桌面版共用同一份配置，所以 CC Switch 的支持对两者都适用。**Kimi Code 的多个供应商可以同时写进它的配置，在 CC Switch 里添加、移除、设为默认；MCP、Skills、提示词同步给 Kimi Code，会话可以浏览和恢复，用量从会话日志导入；「应用」页可以安装、升级、卸载 Kimi Code。Kimi 编程套餐也能在授权中心登录，可以添加多个账号，每个账号显示昵称和额度。用量统计页重新排了版：时间、应用、供应商和模型放在同一行，选中的指标同时决定趋势图和热力图，明细表改成带数量的页签，请求日志可以选每页条数。另外修复了聚合模式下从第三方 GPT 切到其他模型后 Codex 一直报 `unsupported call: exec`、在 Linux/WSL 上从终端启动时打开「关于」页整个应用卡死、给 Codex 选模型后图片输入被关掉、Claude Code 的 VS Code 扩展经 Responses 上游时显示 `redacted_thinking` 报错、macOS 上 Claude 订阅额度读错钥匙串条目、Antigravity 额度缺少 Gemini 一组、Hermes 装在 WSL 里时控制台在 Windows 上启动、按 Esc 一次关掉所有叠起来的面板等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

## 新增

### Kimi Code

Kimi Code（命令是 `kimi`）现在是一个独立的应用，有自己的供应商、MCP、Skills、提示词、会话和用量（[#8687](https://github.com/farion1231/cc-switch/pull/8687)）。配置在 `~/.kimi-code/config.toml`，设置了 `KIMI_CODE_HOME` 时用它指定的目录。

> **💡 命令行版和桌面版都适用。** Kimi Code 的命令行版和桌面版共用 `~/.kimi-code` 里的同一份配置和登录，在 CC Switch 里添加的供应商、MCP、Skills、提示词和官方账号，两个版本都能直接用。

- **供应商可以同时启用。** 和 OpenCode 一样，多个供应商可以同时写进 Kimi Code 的配置，在 Kimi Code 里用 `/model` 选择。「可添加」的卡片点「添加」写进配置，不改默认模型；已添加的卡片可以「移除」，「设为默认」在卡片的更多菜单里。Kimi Code 正在用作默认模型或子代理模型的供应商不能移除，会提示你先在 Kimi Code 里换掉。只改 CC Switch 管的那些供应商和模型，其他配置原样保留。
- **添加供应商。** 预设和其他应用一样按「模型厂商」「第三方平台」「云服务商」「本地」分组，另有「账号登录」分组用来登录 Kimi 官方账号。「获取模型列表」后选中的模型会自动填上上下文窗口、思考和图片输入；每个模型一行，可以填显示名称（Kimi Code 的 `/model` 里显示它）。「始终思考」「按需加载工具」旁边有「?」说明；请求头挪进了「高级选项」。
- **MCP、Skills、提示词。** MCP 支持 stdio、HTTP 和 SSE；Skills 不会覆盖 Kimi Code 自己目录里的同名技能。
- **会话和用量。** 可以浏览和恢复 Kimi Code 的会话；用量从会话日志导入，包括输入、输出、缓存、首字时间和耗时。
- **「应用」页管理 Kimi Code。** 用官方安装程序安装，可以升级和卸载。
- Kimi Code 不经过本地路由，也没有聚合模式。

### Kimi 官方账号

在授权中心可以「登录 Kimi」（添加供应商里选「Kimi Code 官方登录」也会带你过去），选国内版或海外版，在浏览器里完成授权后自动添加官方模型（[#8710](https://github.com/farion1231/cc-switch/pull/8710)、[#8726](https://github.com/farion1231/cc-switch/pull/8726)）。

- **多个账号。** 第一个账号用 Kimi Code 自己的登录位置；之后添加的每个账号都有自己的凭据、供应商和模型，在 Kimi Code 的模型列表里显示为「Kimi 订阅 <昵称>」。在授权中心点「使用此账号」，或在卡片更多菜单里选「设为默认」，就把 Kimi Code 的默认模型换成这个号的。官方卡片不能在供应商页编辑或删除，要在授权中心管理。
- **昵称和额度。** 每个账号和官方卡片都显示昵称和额度。快过期的登录会在后台续期，和 Kimi Code 自己用同一把锁，不会和它抢；Windows 上只读取额度，不续期。
- **重新登录和删除。** 重新登录同一个号会更新原来的那一份，不会多出一个；删除单独添加的账号会一起删掉它的供应商、模型、凭据和卡片，正在使用时不能删。Kimi Code 自己登着的号只会从列表里移出，CC Switch 不会替它退出登录。
- 在 Kimi Code 里已经登录的号会自动出现在授权中心。

## 改进

**用量统计页重新排版**（[#8711](https://github.com/farion1231/cc-switch/pull/8711)）。

- 页面右上角只留一个同步按钮（显示上次同步时间）和一个设置按钮，数据来源、显示和价格设置都在设置里。请求日志显示哪些列，改在请求日志页签右侧的「请求日志的列」菜单里选。
- 时间、应用、供应商和模型放在同一行，供应商和模型合成一个两级菜单。
- 概览里点选一个指标，趋势图和热力图就显示它；输入、输出、缓存读写四项 Token 可以展开成第二行。
- 明细页签去掉了「设置」，剩下「请求日志」「供应商」「模型」三个，标签上带数量；表格按内容宽度排列，太宽时左右滚动，时间和应用两列固定在左边。
- 请求日志可以选每页 10、20 或 50 条，默认 20 条，会记住你的选择。没有数据的格子显示「—」。

**OpenCode、OpenClaw 的「设为默认」挪进更多菜单。** 以前已添加卡片上的星形图标不好认，也看不出有没有选中。现在在卡片的更多菜单里，有多个模型的供应商可以从子菜单里选默认模型。OpenCode、OpenClaw、Hermes、Kimi Code 的默认供应商改用和「使用中」一样的蓝色标出。

**Pi 的供应商标识始终显示。** 用预设添加时也会显示并预填，可以修改；和别的 Pi 卡片重复时，输入框下方会提示，不能保存。以前要到保存时才报错。

**MCP 服务器显示自定义的显示名称**（[#8692](https://github.com/farion1231/cc-switch/pull/8692)）。设置了显示名称的服务器，列表和删除确认框里都显示它，标识写在旁边。

**会话页的项目分组标题整行都能点击展开和收起**（[#8709](https://github.com/farion1231/cc-switch/pull/8709)）。

**预设：** 新增 BuyToken、V-API。

## 修复

- **聚合模式下从第三方 GPT 切到 DeepSeek、Kimi 等模型后，Codex 每一轮都报 `unsupported call: exec`**（[#8676](https://github.com/farion1231/cc-switch/issues/8676)）。第三方 GPT 和其他模型调用命令行工具的方式不同，以前切换时 Codex 不会先压缩历史，新模型照抄了历史里它不支持的调用。现在在这两类模型之间切换时，Codex 会先用原来的模型压缩一次；同一类模型之间切换照旧不压缩。
- **在 Linux 或 WSL 上从终端启动 CC Switch，打开「设置 → 关于」整个应用卡死**（[#3241](https://github.com/farion1231/cc-switch/issues/3241)）。查询工具版本的命令占住了终端，被系统暂停。现在这个查询不再占用终端，最多等 10 秒。
- **给 Codex 选了获取到的模型后，图片输入被关掉**（[#8682](https://github.com/farion1231/cc-switch/issues/8682)）。查到的资料说模型只支持文字时，以前会写成「只支持文字」，Codex 就拒绝图片，表单里也没有办法改回来。现在只在资料说支持图片时才填这一项，其他情况交给 Codex 默认的判断。
- **选了中转站的某些模型后，填进来的是别家的参数**（[#8765](https://github.com/farion1231/cc-switch/issues/8765)）。以 DeepSeek-V4.1-Flash-1017 为例，models.dev 上没有 DeepSeek 自己的这个条目，以前会借用另一家托管的微调版本，填进去的是「只支持文字」和 262K 的上下文窗口，只有实际窗口的四分之一。现在查不到原厂条目时不再借用别家托管的条目，这几项留空。
- **Claude Code 的 VS Code 扩展经 OpenAI Responses 上游时，工具调用前显示 `Unsupported content type: redacted_thinking`**（[#8691](https://github.com/farion1231/cc-switch/issues/8691)）。只有加密内容的思考以前转成了扩展不认识的格式，现在改成和 Anthropic 一样的空思考块；发回上游的请求不变。只在最后才给出的思考摘要也会补上。
- **macOS 上 Claude 订阅额度查询失败**（[#8764](https://github.com/farion1231/cc-switch/pull/8764)、[#8762](https://github.com/farion1231/cc-switch/issues/8762)）。钥匙串里有好几条同名条目时，可能读到一条只存了 MCP 登录信息的旧条目。现在先按当前用户的账号找，找不到可用的登录再回到原来的方式。
- **macOS 上 Antigravity 官方卡的额度只有 Claude/GPT，没有 Gemini。** Google 只把 Gemini 额度返回给较新版本的 agy，现在查询时会带上本机 agy 的版本。
- **Windows 上刷新 Antigravity 额度、获取模型列表时弹出黑色命令行窗口**（[#8700](https://github.com/farion1231/cc-switch/issues/8700)）。
- **Windows 上 Hermes 装在 WSL 里时，Web UI 未启动时点「打开终端并启动」，启动的是 Windows 上的 Hermes**（[#8689](https://github.com/farion1231/cc-switch/issues/8689)）。Hermes 配置目录指向 WSL 路径时，现在会在那个 WSL 发行版里运行 `hermes dashboard`。
- **Codex 请求带 `session-id` 或 `thread-id` 头时，路由认不出会话**（[#8718](https://github.com/farion1231/cc-switch/pull/8718)）。
- **阿里云百炼、千问 Token Plan 的 Anthropic 地址获取不到模型列表**（[#8755](https://github.com/farion1231/cc-switch/pull/8755)）。
- **OpenCode Zen、Go 的供应商从 models.dev 补不全模型参数。** models.dev 换了这两家的地址，现在旧地址也能对上，`deepseek-v4.1-flash` 等模型又能自动填上参数。
- **叠着打开好几个全屏面板时，按一次 Esc 全部关掉。** 现在只关最上面那个。
- **一个深链接还在导入时又来了第二个，第一个导入完成后会把第二个的确认框关掉**（[#8696](https://github.com/farion1231/cc-switch/issues/8696)）。
- **用量页的「近 7 天」「近 14 天」「近 30 天」在夏令时切换前后多算或少算一天**（[#8719](https://github.com/farion1231/cc-switch/issues/8719)）。
- **请求日志停在后几页时，总数变少后表格变空、回不去。** 现在会退回最后一页。
- **「应用」页没安装的工具下面多出一行英文的「not installed」。**
- **按下「高级选项」时文字跳动。**

## 升级说明

**数据库版本从 21 升到 22**，为 MCP 和 Skills 增加 Kimi Code 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。

- Kimi Code 默认显示在侧栏，不用的话可以在「应用」页关掉「在侧栏显示 Kimi Code」。
