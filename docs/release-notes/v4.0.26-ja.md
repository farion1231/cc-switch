# CC Switch v4.0.26

今回のリリースでは、「アカウント」ページと公式プロバイダーカードに各アカウントのサブスクリプションプランが表示されるようになり、GitHub Copilot アカウントでは上限のあるクォータがすべて表示されます。ワンクリックインポートのリンクで Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi のプロバイダーもインポートできるようになりました。Codex のカードでは GPT モデルの公式の Fast ティアを残すかどうかを選べるようになり、Codex や Grok Build からローカルルーティングへのリクエストがシステムプロキシに横取りされたときは CC Switch が知らせます。DeepSeek Harness は設定ディレクトリを指定できるようになり、WSL にインストールしている場合も管理できます。今回はパフォーマンスの改善も行い、プロバイダー一覧、メインウィンドウの読み込み、起動、セッションの読み込み、ルーティングの転送がいずれも速くなりました。セッション同期がデータベースを占有している間も画面が固まらなくなりました。また、IPv6 が使えない環境でルーティング経由のリクエストが 2 分以上待たされる、ログインが必要な MCP サーバーが接続失敗と表示される、Claude Desktop のルーティングカードでモデルを変更しても反映されない、Codex がルーティング経由で Chat に変換するときにキャッシュヒット率が下がる、GitHub Copilot の Grok リクエストが 422 になったり返信が重複して表示されたりする、非 Retina ディスプレイでダイアログがぼやける、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### アカウントのサブスクリプションプラン

これまで「アカウント」ページでサブスクリプションプランが表示されるのは Claude アカウントだけで、ほかのアカウントはログイン日しか表示されず、同じサービスの Max アカウントと Free アカウントの見分けがつきませんでした。

現在は GitHub Copilot、ChatGPT、Kimi、Antigravity、xAI のアカウントでも 2 行目の先頭にプランが表示されます。Codex、Kimi、Antigravity、Gemini CLI の公式カードと、Copilot、xAI のアカウントカードでも、サブタイトルの後ろに「· プラン名」が付きます。

- カードのプラン名はクォータの照会結果をそのまま使うため、リクエストは増えません（Kimi、Antigravity、xAI はクォータの照会時にプラン名を取得するリクエストが 1 つ並行して増えます）。プラン名はクォータが読み込まれてから表示され、クォータを照会しないカードには表示されません。
- プラン名を取得できない場合は表示されないだけで、クォータは通常どおり表示されます。更新に失敗したときは前回取得したプランを表示したままにします。
- Grok CLI のログインに従う Grok Build カードと、アカウントを紐付けていない Antigravity カードには、まだプラン名が表示されません。これらのカードのクォータの照会方法ではこの情報を取得できないためです。

### GitHub Copilot のクォータをすべて表示

Copilot アカウントにはこれまでプレミアムリクエストの割合しか表示されませんでした。現在は上限のあるクォータごとに 1 行ずつ表示され、ホバーすると「残り / 合計」を確認できます。Free アカウントのコード補完とチャットの回数も表示されるようになりました。

- プレミアムリクエストの表示名を Credits に変更し、Codex の呼び方に揃えました。トレイでも同じです。
- Free アカウントには Credits がなく、これまでは「残り 100%」と表示されていましたが、現在は「現在のプランに含まれません」と表示し、プロバイダーカードにはこの項目を表示しなくなりました。

### ワンクリックインポートの対応アプリを拡大

これまで Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi のプロバイダーのリンクはそのまま拒否されていました。現在はこれらのアプリのリンクもインポートできます。

- **Claude Desktop**：リンクが Anthropic 形式で、モデル名がすべて `claude-` で始まる（またはモデルの指定がない）場合は直接接続のカードとしてインポートします。それ以外の場合はモデルマッピングのカードとしてインポートし、4 つの段階にリンク内のモデルを設定します。
- **MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi**：Pi と同じく 1 つのモデルとしてインポートします。リンクにはモデルの指定が必要です。
- Oh My Pi は特定の書き方の Key を環境変数名やコマンドとして読み取るため、インポートするとこのパソコンのシークレットがリンク内のアドレスに送られるおそれがあります。そのため、このような Key（`!` で始まるもの、小文字を含まないものなど）はインポートを拒否します。

### Codex カードで公式の Fast ティアを残す

これまで Codex のサードパーティカードのモデル一覧では、GPT モデルから公式の Fast 速度ティアが一律に取り除かれ、Fast を選べませんでした（[#5234](https://github.com/farion1231/cc-switch/issues/5234)）。しかし、公式の ChatGPT アカウントへ転送する中継（CPA など）は実際には Fast に対応しています。

現在は Codex のプロバイダーフォームの「詳細オプション」で、「上流フォーマット」の下に「公式の Fast ティアを残す」が加わりました。既定ではオフで、上流フォーマットが Responses のときだけ表示されます。オンにすると、Codex で Fast を選んだときのリクエストに `service_tier=priority` が付きます。

- 受け付けるのは公式の ChatGPT アカウントへ転送する中継だけで、クォータの消費も速くなります。それ以外の上流ではエラーになったり、より高い料金で課金されたりすることがあります。
- 以前に公式カードで Fast を選んでいた場合は、オンにするとすぐにこのプロバイダーで有効になります。集約モードでは使われません。変更後は Codex を再起動してください。

### システムプロキシがローカルルーティングへのリクエストを横取りしたときに通知

Clash などのプロキシツールを使っていると、Codex と Grok Build からローカルルーティング（`http://127.0.0.1:<port>`）へのリクエストがシステムプロキシに横取りされ、リモートのノードに回された結果、空の 502 が返ることがあります（[#9221](https://github.com/farion1231/cc-switch/issues/9221)）。Codex には「502 Bad Gateway」としか表示されず、CC Switch 側にもリクエストが届かないためログが一切残らず、原因を突き止めにくい問題でした。

現在は Codex または Grok Build がルーティングモードに入ると、CC Switch がバックグラウンドで、クライアントと同じプロキシ規則に従ってローカルルーティングにリクエストを 1 回送ります。リクエストが戻ってこない場合はログに警告を記録します。手動でルーティングモードに入った場合は画面にも通知を表示し、プロキシツールでループバックアドレスを直結にする方法（例：Clash のルールの先頭に `IP-CIDR,127.0.0.0/8,DIRECT,no-resolve` を追加）を案内します。

### DeepSeek Harness の設定ディレクトリ

これまで DeepSeek Harness は `DSH_HOME` か `~/.dsh` しか認識せず、WSL にインストールした DSH を Windows 版の CC Switch で管理できませんでした（[#9239](https://github.com/farion1231/cc-switch/issues/9239)）。

現在は「設定 → アプリ設定」に DeepSeek Harness の項目が加わり、設定ディレクトリを指定できます。プロバイダー、Skills、指示ファイル、セッション、使用量の取り込みはすべてこのディレクトリに従います。WSL 内のパスを指定すると、バージョンの検出、インストール、アップグレードもその WSL ディストリビューションで行います。

## 変更

- **パフォーマンスの改善**：
  - プロバイダー一覧の読み込みが速くなり、プロバイダーが多いほど効果が大きくなります。変更のないプロバイダーをデータベースに書き直さなくなったため、それによってクラウド同期が発生することもなくなりました（[#9180](https://github.com/farion1231/cc-switch/pull/9180)）。
  - 補助的なページとプロバイダーエディターを使うときに初めて読み込むようにし、メインウィンドウの起動時に読み込むスクリプトが半分になりました（[#9181](https://github.com/farion1231/cc-switch/pull/9181)）。
  - 起動時のログの整理をバックグラウンドで行うようにしました。ウィンドウが非表示または最小化されている間は定期更新を一時停止し、ウィンドウが表示されていれば前面になくても通常どおり更新します（[#9182](https://github.com/farion1231/cc-switch/pull/9182)）。
  - セッション記録を読み込むときのデータのコピーを 1 回減らし、軽量モードに入るとセッションのキャッシュを解放するようにしました（[#9183](https://github.com/farion1231/cc-switch/pull/9183)）。
  - ルーティングでストリーミングレスポンスを転送するときのメモリコピーを大幅に減らし、レスポンスが長いほど効果が大きくなります。フェイルオーバーでデータベースを読む回数も減りました（[#9161](https://github.com/farion1231/cc-switch/pull/9161)）。
- **セッション同期中も画面が固まらなくなりました**（[#9178](https://github.com/farion1231/cc-switch/pull/9178)）：大きなセッションファイルを同期すると数十秒間データベースが占有され、その間に Skills ページを開く、Pi や Oh My Pi に切り替える、「ネットワーク」や「データ」の設定を開く、アイコンを選ぶ、統合プロバイダーのパネルを開く、速度テストを行うといった操作をすると、同期が終わるまでウィンドウ全体とトレイが固まっていました。現在はこれらの操作はバックグラウンドで待機し、画面は通常どおり反応します。
- **セッション閲覧ページのツールバーのレイアウトを見直しました**（[#9109](https://github.com/farion1231/cc-switch/pull/9109)）：1 行目にパスと閲覧ツール、2 行目に時刻、セッションの統計、モデル、使用量を配置しました。行の先頭や末尾に来やすかった区切りの点を取り除き、長いモデル名は折り返して表示し、ホバーで完全な名前を確認できます。
- **プリセット：** Grok Build の既定のモデルを `grok-4.7` に、Kimi のプリセット（Codex 用を除く）の既定のモデルを `kimi-k3.1-pro` に、Hermes の千問 Coding Plan の既定のモデルを `qwen3.7-plus` に変更しました（[#9193](https://github.com/farion1231/cc-switch/pull/9193)）。TeamoRouter は teamorouter.com ドメインに変更しました。Claude Desktop 公式カードのダウンロードリンクは claude.com/download に変更しました。追加済みのプロバイダーには影響しません。

## 修正

- **IPv6 が使えない環境で、ルーティング経由のリクエストが送信されるまで 2 分以上待たされる問題**（[#9212](https://github.com/farion1231/cc-switch/issues/9212)）。智譜 GLM、Alibaba Cloud 百炼などのサービスのドメインは先に IPv6 アドレスが解決されるため、IPv6 が使えないネットワークでは、システムがすべての IPv6 アドレスでタイムアウトするまでローカルルーティングが IPv4 に切り替えず、macOS では約 150 秒、Windows では約 43 秒かかっていました。現在は IPv6 アドレスに 300 ミリ秒以内に接続できなければ IPv4 も同時に試します。送信するリクエストの内容は変わりません。
- **ログインが必要な MCP サーバーで、接続確認の結果が「接続失敗」になる問題**（[#9190](https://github.com/farion1231/cc-switch/issues/9190)）。Notion や Sentry などのサーバーは OAuth ログインが必要で、クライアントでログインすれば正常に使えますが、CC Switch の確認ではクライアントのログイン情報を使わないため、失敗と判定されていました。現在はこの場合は黄色の丸で表示し、ホバーするとサーバーには接続できるがログインを求められていることを説明します。CC Switch がクライアントの保存したログイン情報を読み取らない点は変わりません。
- **Claude Desktop のルーティングカードでモデルを変更しても Claude Desktop では古いモデルのままで、削除して作り直すしかなかった問題**（[#9203](https://github.com/farion1231/cc-switch/issues/9203)）。保存時に「メニュー表示名」が空欄だとモデル名が自動で入るため、その後モデルだけを変更しても表示名は古いままでした。現在は表示名が古いモデル名と同じ場合は新しいモデルに合わせて変わり、自分で付けた名前はそのまま残ります。
- **Codex がルーティング経由で Chat に変換するとき、会話の途中で設定を変えるとキャッシュヒット率が下がる問題**。たとえば途中で `sandbox_mode` を切り替えると、Codex はそのターンの先頭に説明のメッセージを挿入します。これまではこのメッセージが会話の先頭にまとめられて履歴全体が書き換わり、上流のキャッシュがすべて無効になっていました。現在はこのメッセージを元の位置に残し、それまでの履歴は変わりません。
- **Codex がルーティング経由で Chat に変換するとき、別のセッションの思考内容が現在のセッションに混ざることがある問題**。上流が返すツール呼び出しの ID は重複しやすく（`exec_command:0` など）、ローカルルーティングの再起動後やキャッシュから追い出された後に、別のセッションにある同じ ID の呼び出しが見つかることがありました。現在は Codex のセッションごとに区別し、同じセッションの中だけで探します。
- **ルーティングのリクエストが失敗したとき、リクエストログにクライアントのモデル名が記録される問題**。たとえば Claude Desktop のバックグラウンドタスクは `claude-haiku-4-5-20251001` を使います。このカードのモデルにマッピングされた後で上流が 429 を返しても、ログには Haiku と表示され、設定していないモデルを呼び出したように見えていました。現在は失敗したリクエストも成功したリクエストと同じく「`claude-haiku-4-5-20251001` → 実際のモデル」と記録します。
- **ローカルのログインに従う Claude 公式カードで、ログインの期限が切れると「トークンの更新待ち」のまま変わらず、もう一度 Claude Code を実行するまで戻らなかった問題**。現在はログインの期限が切れると、CC Switch が Claude Code 自身にログインを更新させてからクォータを読み取ります。Claude の設定ディレクトリを指定している場合はこの処理を行いません。
- **Claude Code と Claude Desktop の自動モードの安全分類器が使えないとき、クライアントが再試行を続けてクォータを消費し続ける問題**（[#9201](https://github.com/farion1231/cc-switch/pull/9201)、[#9199](https://github.com/farion1231/cc-switch/issues/9199)）。現在はツール結果が 3 ターン続けて分類器が使えないことを報告すると、ローカルルーティングが上流に送らずに直接エラーを返します。新しいメッセージを送れば続けられます。
- **Codex が GitHub Copilot 経由で Grok モデルを使うと 422 になる問題**（[#7989](https://github.com/farion1231/cc-switch/pull/7989)、[#7988](https://github.com/farion1231/cc-switch/issues/7988)）。現在は Copilot の Grok リクエストにも、xAI に直接接続する場合と同じ互換処理を行います。
- **Codex が GitHub Copilot を経由するとき、同じ返信が 2 回表示される問題**（[#8025](https://github.com/farion1231/cc-switch/pull/8025)、[#7977](https://github.com/farion1231/cc-switch/issues/7977)）。
- **アプリのインストールやアップグレードで既存の同名ファイルとぶつかったとき、通知に npm が提案する `--force` しか表示されない問題**（[#9196](https://github.com/farion1231/cc-switch/pull/9196)、[#9173](https://github.com/farion1231/cc-switch/issues/9173)）。このファイルはたいてい別の方法でインストールしたもので、`--force` を使うとそのまま上書きされます。現在は競合したファイルのパスを表示し、名前を変えてバックアップしてから再試行するよう案内します。
- **Skills にファイルのシンボリックリンクがあると、WebDAV の自動同期が失敗する問題**（[#9197](https://github.com/farion1231/cc-switch/pull/9197)）。たとえば `CLAUDE.md` と `GEMINI.md` がどちらも `AGENTS.md` へのリンクの場合、アーカイブに同じ名前のファイルができていました。現在は各ファイルが自分の名前を保ちます。
- **Codex のサブエージェントの同時実行上限に関する 2 つの問題**（[#9148](https://github.com/farion1231/cc-switch/pull/9148)）：`config.toml` でテーブルヘッダーの後ろにコメントがあると、上限を変更したときに `[features.multi_agent_v2]` が上書きされることがありました。また、`[agents]` が引用符付きのキー名で書かれていると、Codex が受け付けない重複フィールドが余計に書き込まれていました。説明文にも、変更は新しいセッションにだけ反映されることを追記しました。
- **DeepSeek Harness で headless プロファイルを使うと、CC Switch が保存した Key が見つからない問題**。`MISSING_CREDENTIAL` が報告されていました。現在は headless プロファイルに書き込むときに、DSH のドキュメントに従って認証情報の読み取りを有効にします。この項目を自分で変更したプロファイルはそのまま残します。
- **1x ディスプレイで「モデルを選択」などのダイアログがぼやけて表示される問題**（[#9238](https://github.com/farion1231/cc-switch/issues/9238)）。ダイアログを中央に配置するときに半ピクセルの位置に来ることがあり、非 Retina ディスプレイでは文字や枠線がにじんでいました。
- **macOS で、MCP フォーム、プロンプトの編集、Skills のリポジトリ、セッション検索などの入力欄に入力すると、先頭の文字が自動で大文字になる問題**。そのため環境変数名、リクエストヘッダー、コマンド、アドレスが誤った内容で保存されることがありました。
- **Linux の AppImage に古いバージョンの libwayland-client が同梱されていた問題**（[#9229](https://github.com/farion1231/cc-switch/pull/9229)、[#8723](https://github.com/farion1231/cc-switch/issues/8723)）。Intel の内蔵 GPU と Wayland の環境では起動できないことがありました。
