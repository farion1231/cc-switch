# CC Switch v4.0.42

本版本让 **GitHub Copilot** 供应商支持 Copilot 的 **Auto 自动选模型**：在 Claude、Codex 或 Claude Desktop 的模型列表里选「GitHub Copilot 自动选择」，每次对话由 Copilot 决定用哪个模型，Copilot Free 账号也能用。

本版本还修复了 4.0.41 引入的问题：所有应用的供应商卡片都显示「agy 在用」，副标题也被换成 Antigravity 账号邮箱。另外，Antigravity 官方卡换号时，系统钥匙串第一次读回失败不会再把已经换好的账号绑定撤销。

---

## 新增

### GitHub Copilot Auto 自动选模型

（[#9564](https://github.com/farion1231/cc-switch/pull/9564)，见 [#8197](https://github.com/farion1231/cc-switch/issues/8197)）

Copilot 上游调整了 Auto 的接入方式，之前省略模型名的做法已经不能用。现在 CC Switch 会先向 Copilot 的 `/auto` 询问这次该用哪个模型，再带着 Copilot 给的会话令牌向那个模型发请求。

- **怎么用**：在 Copilot 供应商的表单里点「获取模型列表」，账号支持 Auto 时列表里会多一项「GitHub Copilot 自动选择」（模型 ID `copilot-fusion-auto`），选它即可。Claude Code、Codex 和 Claude Desktop 都可以选，Claude Desktop 可以只给某一档填它、其他档照常填具体模型。
- **Copilot Free 也能用**：Free 账号的模型目录里没有标明 Auto 能力，CC Switch 会替这个账号试问一次 `/auto`（只让它选模型，不发对话），能选出来就显示 Auto 选项。
- **同一段对话尽量用同一个模型**：Copilot 选出的模型在授权有效期内会接着用。闲置超过 30 分钟、授权到期、账号换了，或者上下文压缩成功之后，会重新问一次，这时可能换成别的模型。
- **选不出来时**：Copilot 拒绝或选出的模型不能用当前协议时，请求会报错，开了故障转移的会切到下一家。选固定模型的请求和以前一样。

需要开启本地路由。详见用户手册 [GitHub Copilot Auto](../user-manual/zh/2-providers/2.1-add.md#github-copilot-auto)。

## 修复

- **所有供应商卡片都显示「agy 在用」**（[#9975](https://github.com/farion1231/cc-switch/pull/9975)，关闭 [#9981](https://github.com/farion1231/cc-switch/issues/9981)）：4.0.41 里，打开过 Antigravity 页或授权中心之后，其他应用的卡片、Antigravity 的中转卡片也会显示「agy 在用」的绿色标签，副标题被换成 Antigravity 账号邮箱。现在只有 Antigravity 官方卡才显示账号。
- **Antigravity 官方卡换号后绑定被撤销**（[#9979](https://github.com/farion1231/cc-switch/pull/9979)）：系统钥匙串有时写入了新登录，第一次读回却报错，CC Switch 会把卡片的账号绑定撤销，实际上 agy 已经换到了新账号。现在会再读一次；还是读不到时，提示登录已经写入，请先到授权中心看当前登录的是哪个账号再重试。
