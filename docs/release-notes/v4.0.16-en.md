# CC Switch v4.0.16

This release turns the tray into a quick panel and fixes a batch of Codex and routing issues. Clicking the tray icon now opens a panel that shows each app's in-use provider, mode, quota and usage, and lets you search and switch providers directly; if you prefer the old menu, switch back under "Settings → General → Tray style". In Codex Aggregation mode, a session that moves between the default provider and other members no longer gets stuck on the previous one with compaction failing over and over; with Codex routed, having to sign in to ChatGPT again after every restart of CC Switch is also fixed. When Codex reaches a Chat upstream through routing, parallel tool results are no longer split by a notice inserted in the middle and rejected with a 400; a GPT context window you fill in yourself now also applies to official models of the same name, and the 272K cap added in 4.0.13 now only limits windows borrowed from the vendor's data. When the upstream is a 5.5 model, Claude Code routing and Claude Desktop route mode now use the 5.5 model IDs. It also fixes Zhipu pay-as-you-go accounts showing "Quota unavailable", quota on newly created Volcengine plan cards erroring right away, Node tools managed by fnm not being recognized on Windows, idle cards that couldn't be deleted, the "Get API Key" link disappearing when editing a provider, and other issues; the macOS icon background is also now a soft light grey. OpenCode cards can now be set as OpenCode's default model. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

**The tray is now a quick panel** ([#8432](https://github.com/farion1231/cc-switch/pull/8432)). On macOS and Windows, clicking the tray icon now opens a quick panel: the "Configuration" tab lists each app's in-use provider, current mode (Direct, Routing and Aggregation in the same colors as the main window) and quota, and lets you search and switch providers; the trend chart on the "Usage" tab follows the currency and chart style chosen in the main window. On macOS it uses the system frosted glass and stays readable over dark windows; on Windows it uses opaque cards. To get the old menu back, choose "Menu" for "Tray style" under "Settings → General → Window and terminal"; it takes effect immediately, no restart needed. Linux keeps the native menu, with a new "Open quick panel" item at the top.

**OpenCode cards can be set as the default model** ([#8509](https://github.com/farion1231/cc-switch/issues/8509)). At startup, OpenCode reads `opencode.json` and picks the model in its top-level `model`; CC Switch had no way to set it before, so you had to edit the file by hand. Added OpenCode cards now have "Set as default": just pick a model. Only the top-level `model` is changed; comments and `small_model` are left as they are.

## Improvements

**The official MiniMax presets default to MiniMax-M3.1-Flash** ([#8518](https://github.com/farion1231/cc-switch/pull/8518)). Claude Code, Claude Desktop, Codex, Hermes, OpenCode, OpenClaw and Pi are all updated; MiniMax-M3 can still be selected.

**The "Get API Key" link is light blue again**, without an underline.

**The sidebar "Today" line has its "Today" prefix back**, reverting the 4.0.15 change.

**Price updates**: Kimi K3 gets its cache write price (3 USD per million tokens; it was recorded as 0); the Step 5 Preview cache read price is changed to 0.70 CNY per million tokens following StepFun's October 14 price change; prices are added for qwen3.7-flash, qwen3.6-27b and qwen3.8-omni-flash. The two price changes are applied automatically to existing price tables, except for prices you edited by hand.

**The invite code is removed from Zhipu's "Get API Key" links.**

**Turkish**: 17 UI strings are reworded ([#8481](https://github.com/farion1231/cc-switch/pull/8481)).

**Presets:** Added AllTokens SI.

## Fixes

- **In Codex Aggregation mode, a session kept failing after moving to another provider** ([#8485](https://github.com/farion1231/cc-switch/issues/8485)). When a session switched models between the Aggregation default provider and another Aggregation member, Codex first compacted the context with the previous provider; when that provider was out of quota, the compaction failed and every later turn got stuck at the same point. In Aggregation mode, third-party route models now use the same compaction identifier as Aggregation members, so this compaction is no longer triggered, and sessions that are already stuck recover too. The official route is not affected.
- **With Codex routed, you had to sign in to ChatGPT again after every restart of CC Switch** ([#8431](https://github.com/farion1231/cc-switch/issues/8431)). Since Codex desktop 26.1013, resuming a chat requires being signed in to ChatGPT. With "Keep official login for direct switches" off and a third-party direct provider, quitting CC Switch stashed the login and deleted `auth.json`, and the next launch didn't give it back. Quitting CC Switch now always keeps the login, while actually leaving routing still follows that setting; when entering or attaching a third-party route, if `auth.json` has no login, the most recently stashed one is put back, which also recovers logins already lost this way.
- **When Codex reached a Chat upstream through routing, parallel tool results were split by a notice in the middle, giving 400 "No tool output found"** ([#7190](https://github.com/farion1231/cc-switch/issues/7190), [#7569](https://github.com/farion1231/cc-switch/issues/7569)). For example, the `image_resize_notice` Codex inserts when viewing images. Such notices no longer break up tool results, and Chat upstreams with strict validation (such as DeepSeek) no longer reject the request.
- **A GPT context window you filled in yourself didn't apply to official models of the same name** ([#8366](https://github.com/farion1231/cc-switch/issues/8366), [#8350](https://github.com/farion1231/cc-switch/issues/8350)). Windows filled in per provider or per model are now written into Codex's model catalog, and the auto-compact threshold follows; when nothing is filled in, the official defaults are still used. When Codex reaches Gemini through routing and the input is too long, it now gets a "context too long" error that Codex recognizes, so Codex compacts on its own.
- **The 272K GPT cap in 4.0.13 also capped platforms that really have 1.05M windows.** Now only windows borrowed from the vendor's data are capped to 272K: presets with the same address and providers that models.dev recognizes by address use their own windows, and a window you type in is used as is; when a GPT window is above 272K, the Codex, Hermes, OpenClaw, OpenCode and Pi forms show a note below the input box. The OpenRouter, Vercel AI Gateway, Cloudflare AI Gateway and DigitalOcean presets get their 1.05M windows back.
- **When routing to a 5.5 upstream model, Claude Code still treated it as a 5 model** ([#8450](https://github.com/farion1231/cc-switch/pull/8450)). Now, when the upstream for the Opus or Sonnet tier is a 5.5 model, Claude Code is given `claude-opus-5-5` / `claude-sonnet-5-5`, so it shows the correct model and its output limit goes from 64K to 128K; the sub-agent model is handled the same way.
- **In Claude Desktop route mode, requests to a 5.5 target were rejected by the upstream** ([#8082](https://github.com/farion1231/cc-switch/issues/8082)). The model names published to Desktop used to be fixed as `claude-opus-5` / `claude-sonnet-5`, so Desktop built requests with the 5 parameters, which the 5.5 upstream doesn't accept; editing the generated config by hand was overwritten on the next write. Now the 5.5 model ID is published when the target is 5.5; the mapping table itself is unchanged, and requests from old configs still go to the original target.
- **Claude Code using WebSearch with a usage limit through Codex OAuth failed right away** ([#7936](https://github.com/farion1231/cc-switch/pull/7936)). It used to be allowed only when WebSearch was forced; now it also works when not forced, the usage limit is enforced through an instruction, and once the limit is exceeded the rest of that turn's response is cut off.
- **Cards for Zhipu pay-as-you-go accounts showed "Quota unavailable"** ([#8465](https://github.com/farion1231/cc-switch/issues/8465)). Zhipu cards query the plan quota by default, and accounts without a Coding Plan were treated as an error. Now, when there is no plan, the account balance is shown instead (team plans don't fall back).
- **Newly created Volcengine Agent / Coding Plan cards showed "Quota unavailable" right away** ([#8494](https://github.com/farion1231/cc-switch/issues/8494)). Volcengine plan quota has to be queried with the account's AccessKey ID and SecretAccessKey, not the API Key used for inference. Now Volcengine is preselected in the usage settings, but the query isn't enabled until the AccessKey is filled in; import links that explicitly enable it are still enabled.
- **In the Codex official card's editor, `auth.json` showed an old login.** It used to show a login snapshot stored by older versions, which no longer matched `~/.codex/auth.json` once Codex rotated its tokens; cards that follow the current login showed it as empty. Now, for official cards not bound to a managed account, it shows what `auth.json` will contain after switching to this card; if you save without touching the box, the card's original login info stays unchanged. The file actually written on switching was always correct.
- **On Windows, with Node managed by fnm, installed tools such as Codex weren't recognized** ([#8484](https://github.com/farion1231/cc-switch/issues/8484)). fnm only adds to PATH temporarily in each terminal, so CC Switch couldn't find node and npm, and in-app installs also failed with "'npm' is not recognized as an internal or external command". Now the directory of fnm's default Node version is added to the end of PATH, and the existing PATH still takes precedence.
- **Idle provider cards couldn't be deleted, with "无法删除当前正在使用的供应商" (the provider is currently in use)** ([#8506](https://github.com/farion1231/cc-switch/issues/8506)). This was common after upgrading with an old Claude Desktop mapping card, when the old "current" flag in the database still pointed at it. Now only the direct provider actually in use and the route target count, matching the rule the UI uses to disable delete.
- **The "Get API Key" link was missing when editing a provider.** When editing, the matching preset is now found by the current address and its link is shown, the same as when adding.
- **False environment variable conflicts on macOS / Linux.** Environment variables CC Switch inherited from the program that launched it were also counted (for example `ANTHROPIC_BASE_URL` that comes with terminals opened from Claude Desktop), and these couldn't be removed in the app either. Now only definitions in shell config files are checked; Windows is unchanged.
- **Some MiniMax Code usage records showed the model as unknown.** The model name is now recovered from the reply in the same session at the same time, so they are priced normally; records already imported stay as they are.
- **Requests never went out after adding the official MiniMax provider in Hermes** ([#8538](https://github.com/farion1231/cc-switch/pull/8538)). When the Provider Key was filled in as `minimax`, it clashed with Hermes's built-in MiniMax provider, so Hermes used the built-in one and asked for `MINIMAX_API_KEY`. The MiniMax presets now prefill `cc-switch-minimax` / `cc-switch-minimax-en`; if you already added it as `minimax`, add it again with a different key. MiniMax-M3.1-Flash is also marked as supporting image input.
- **The usage chart's Y axis was too wide in Chinese and Japanese.** Ticks such as "5000万" and "2000亿" are now written as "5千万" and "2千亿", and the Y axis on the usage page and in the tray panel adjusts its width to the widest tick, so short ticks no longer leave empty space and long amounts are no longer cut off.
- **The white background of the macOS icon was too bright** ([#8495](https://github.com/farion1231/cc-switch/issues/8495)). The white rounded square from 4.0.15 is now light grey with the same shape; Windows and Linux icons are unchanged.
- **The logo on the "About" card was blurry** ([#8470](https://github.com/farion1231/cc-switch/issues/8470)). It now uses the vector image.

## Upgrade Notes

**The database schema is unchanged**, still at 20.

- After upgrading, clicking the tray icon opens the quick panel; to use the old menu, choose "Menu" under "Settings → General → Tray style" (macOS, Windows). On Windows, a left click on the tray icon used to open the main window and now also opens the panel; use "Open main window" at the bottom of the panel to get there.
- Saved GPT model windows are not migrated. For Codex GPT models saved before 4.0.13 with an auto-filled 1.05M window, that value now takes effect; you'll see a note when you open the form, and if the real window is only 272K, lower it by hand.
