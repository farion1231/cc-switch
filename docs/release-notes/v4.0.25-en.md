# CC Switch v4.0.25

This release adds connectivity checks to the MCP page, so you can check in one click whether every enabled MCP server can be reached; when Codex uses an official account through local routing, official requests can be paused automatically before the quota runs out, while third-party models stay usable. In addition, the usage page can fetch exchange rates automatically, the Codex provider form can set a sub-agent concurrency limit, when Claude Code and Claude Desktop go through routing or Aggregation the model menu shows which provider each model comes from and which model it actually is, and Kimi Code sessions can now be deleted in session management. Fixes cover "Open Terminal" picking up routing and Aggregation settings, OpenCode Go and similar providers making Claude Code ask to sign in again in routing mode, every later turn failing after a file was sent to a text-only model once, provider form contents flickering on Windows, the tray panel not opening during startup, and Codex usage being counted twice when model mapping was used. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### MCP connectivity checks

Before, once an MCP server was configured, you only found out whether it could be reached when a coding tool used it ([#4498](https://github.com/farion1231/cc-switch/issues/4498)).

Now the MCP page has a "Check connectivity" button at the top that checks every enabled server; each row's menu also has "Test connection", which checks only that one.

- Opening the page does not run any check, and servers that have not been checked show "Not checked"; after you change a server's connection config, its result is reset.
- A check completes one MCP handshake with the server, and all three connection types are supported: local command (stdio), HTTP and legacy SSE. Each server is given at most 30 seconds, and at most 3 checks run at once across the whole app.
- A server started by a local command is ended together with the child processes it started once the check finishes, so no background processes are left behind. On macOS and Linux, commands such as `npx` and `uvx` are found even when CC Switch is not launched from a terminal.

### Codex official quota protection

When Codex uses an official ChatGPT account, running out of the five-hour or weekly quota puts it into Reserve mode. Now official requests can be paused when the quota is about to run out, so some quota is kept, while third-party models stay usable.

Turn on "Official quota protection" in "Settings → App config → Codex App Enhancements" to set thresholds for five-hour and weekly usage (95% and 98% by default); once either is reached, new official requests are paused.

- It only applies to official Codex requests that go through CC Switch's local routing, and it is off by default.
- Usage is read straight from the quota information that official responses already carry, so no extra requests are sent during normal use; only when you have just started or after about 5 minutes of inactivity is it queried once on its own first.
- When the quota cannot be read (network problems, an expired sign-in and so on), requests are let through as usual, so nothing is blocked by mistake. A paused request returns an error directly and is not passed to other providers in the failover queue.

### Automatic exchange rates on the usage page

The "Display" section of "Usage settings" on the usage page gains "Rate source", where you can choose "Manual" (the default) or "Automatic (daily)". Nothing goes online unless automatic is chosen; rates older than 12 hours are updated automatically, and if fetching fails the last rate keeps being used. Automatic rates and the ones you enter are saved separately, so the values you entered yourself are still there when you switch back to manual. Costs are still recorded in US dollars and are only converted for display.

### Codex sub-agent concurrency limit

"Sub-agent concurrency limit" is added below "Sub-agent Model" in the Codex provider form, setting how many sub-agents one Codex session can run at the same time ([#9055](https://github.com/farion1231/cc-switch/issues/9055)). This is a Codex-wide setting written to `config.toml` as `[agents] max_threads`; it stays the same when you switch providers and can also be changed on official cards. Leave it empty to use Codex's default.

### The model menu shows the provider and the actual model

In routing mode, each tier in Claude Code's `/model` menu used to say only "Custom Sonnet model", so you could not tell which model of which provider it mapped to. Now it reads "provider · upstream model · window" (the window is shown only when the upstream is marked 1M), and models in Aggregation mode are described the same way. If you wrote a model description for the provider yourself, yours is used.

In Claude Desktop's routing and Aggregation modes, the description under each model used to apply the official text according to Opus or Sonnet in its name, and every Aggregation model showed the same sentence. Now it also reads "provider · upstream model · window".

### Deleting Kimi Code sessions

Kimi Code sessions can now be deleted directly in session management; before, they could only be deleted in Kimi Code. They are deleted the same way Kimi Code itself does it, and sub-agent history is deleted along with them.

**Pricing:** GPT-6.1 Terra is added to the built-in pricing table.

## Changes

- **Local routing no longer accepts requests sent from web pages**. Local routing swaps requests over to your saved provider credentials before forwarding them, so a web page that could send requests to local routing could spend your quota. Now requests carrying a browser origin marker are rejected, and access through an ordinary domain name pointing to this computer is no longer accepted either. Requests sent by coding tools are not affected.
- **The toolbar of the Skills "Discover" page now matches the "Installed" page** ([#9125](https://github.com/farion1231/cc-switch/pull/9125)): the search box has the same position and width, the refresh button becomes a "Refresh repos" text button, the source switch, repository filter and "Not installed only" move into the table header, and "Install to" sits at the right of the header. There is one row less, and the features are unchanged.
- **On Windows, when the preferred terminal is PowerShell, PowerShell 7 is used if it is installed** ([#8992](https://github.com/farion1231/cc-switch/pull/8992), [#3271](https://github.com/farion1231/cc-switch/issues/3271)), and the built-in Windows PowerShell is used only when it is not. This applies to "Open Terminal" on provider cards as well as to installing and upgrading apps.
- **Presets:** Qianwen AI Platform and QwenCloud pay-as-you-go and Token Plan move to the new MaaS domains; Coding Plan is unchanged.

## Fixes

- **In routing or Aggregation mode, "Open Terminal" on Claude Code cards picked up the routing and Aggregation settings**. Claude Code in the terminal carried both the routing placeholder credential and the card's own Key, model tiers the card did not configure used model names from Aggregation, which did not work against the card's endpoint, and the `/model` menu also listed other providers' models. Now the terminal uses only the card's own settings, and your other global settings are still kept.
- **In routing mode, OpenCode Go and other providers that store the Key in `ANTHROPIC_API_KEY` made Claude Code ask you to confirm a custom Key, and after the default "No" you were signed out** ([#8111](https://github.com/farion1231/cc-switch/pull/8111), [#8104](https://github.com/farion1231/cc-switch/issues/8104)). Now in routing mode the placeholder credential is always written to `ANTHROPIC_AUTH_TOKEN`, and requests sent to the upstream are unchanged.
- **After a file or audio was sent once to a text-only model, every later turn failed with 400** ([#6274](https://github.com/farion1231/cc-switch/pull/6274), [#6151](https://github.com/farion1231/cc-switch/issues/6151)). Now when requests go through routing to a text-only model, files and audio in the conversation are replaced with a short text note, and Zhipu GLM's Chinese error message is recognized too. Images are handled as before.
- **On Windows, the name and other contents of the provider form flickered back and forth** ([#6420](https://github.com/farion1231/cc-switch/pull/6420), [#6349](https://github.com/farion1231/cc-switch/issues/6349)). WebView2's autofill was overwriting the form contents; it is now turned off for the main window.
- **For a while after launch, the tray panel did not open and CC Switch could not be quit from the tray** ([#9154](https://github.com/farion1231/cc-switch/pull/9154)). Importing session usage at startup holds the database, and the tray panel waited for its data. Now the panel pops up first, "Open main window" and "Quit" work right away, and the list loads afterwards.
- **When Codex used model mapping through routing, the usage of a single request was counted twice** ([#7643](https://github.com/farion1231/cc-switch/pull/7643), [#5526](https://github.com/farion1231/cc-switch/issues/5526)). The session log records the model name Codex used, while routing records the mapped model name, so deduplication could not match them. Now the two are matched.
- **Quota used by subagents of Pi's official example was not counted** ([#8386](https://github.com/farion1231/cc-switch/pull/8386), [#8340](https://github.com/farion1231/cc-switch/issues/8340)). Now it is recorded separately by each subagent's provider and model, and after upgrading, earlier Pi sessions are read again once to fill it in.
- **When importing MCP from Pi, servers Pi does not support were imported and enabled too, and every later sync failed** ([#7888](https://github.com/farion1231/cc-switch/pull/7888)). Servers using the SSE connection type, with invalid names, or with names that differ only by `-` and `_` are now skipped with a notice; when Pi is not installed, Pi's MCP config file is no longer created either.
- **When a proxy was set only in the terminal or in CC Switch and no system proxy was set, models.dev price sync kept failing** ([#8739](https://github.com/farion1231/cc-switch/pull/8739), [#6696](https://github.com/farion1231/cc-switch/issues/6696)). Now CC Switch downloads it in the background, through the proxy you set; importing model prices and autofilling model parameters in the form work the same way.
- **When Claude Code connected to xAI through routing, requests that forced web search were rejected by xAI with 422** ([#8664](https://github.com/farion1231/cc-switch/pull/8664)).
- **Thinking levels for MiniMax M3.1 Flash in Pi** ([#8540](https://github.com/farion1231/cc-switch/pull/8540)): the two official MiniMax presets drop "off" and "minimal", which this model does not accept; the other levels are sent as usual.
