# CC Switch v4.0.11

今回のリリースでは、アプリにアンインストール機能を追加し、「アプリ」ページでコーディングツールのインストール、更新、アンインストールができるようになりました。アンインストール前の確認ダイアログには、アンインストールするインストール先のパスと実行するコマンドが表示されます。アンインストールするのはインストール元を確認できるものだけで、設定とセッションのデータはすべて残ります。メニューには、インストール方法ごとの手動アンインストールコマンドもあります。プラン型のプロバイダー（Kimi、智譜、MiniMax など）を追加すると、Claude Code だけでなくすべてのアプリでプラン枠のクエリがデフォルトで有効になります。ワンクリックインポートのリンクも同様です。Codex の使用量統計では 2 つの問題を修正しました。フォークしたセッションを毎分まるごと読み直すことはなくなり、Codex デスクトップ版の長いセッションでページが切り替わった後に分岐したサブエージェントの使用量も集計できるようになりました。また、Windows で CC Switch の自動更新による再起動後にツールのインストールやアップグレードで npm が見つからない問題、フルスクリーンのページを開くときのちらつき、Skills と MCP の一括切り替えがすべて失敗しても成功と表示される問題なども修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

---

## 新機能

**「アプリ」ページで、インストール済みのツールをアンインストールできるようになりました。** インストール済みの各ツールの横に「アンインストール」ボタンを追加しました。押すとまず現在使われているのがどのインストールかを調べ、アンインストールするインストール先のパスと実行するコマンドを確認ダイアログに表示し、確認してから実行します。実行の直前にもう一度確認し、インストールの状況が変わっていれば実行しません。アンインストールするのは、インストール元を確認できるものだけです。

- npm でグローバルにインストールしたもの（パッケージ名とインストールプレフィックスを照合します）。
- Homebrew でインストールした Claude Code、Codex（cask）と Gemini CLI、OpenCode（formula）。ほかの Homebrew パッケージには一切触れません。
- 公式インストールスクリプトでインストールした Claude Code、Codex、Grok Build、OpenCode。現在使われている実行ファイルとその起動エントリーだけを削除し、ディレクトリは削除しません。Claude Code のほかの旧バージョンは残ります。
- Hermes は自身の `hermes uninstall --yes` を呼び出します。OpenClaw はまず公式コマンドで Gateway サービスをアンインストールし、成功してから CLI をアンインストールします。
- Windows で WSL 内にインストールしたツールは、対応するディストリビューション内でアンインストールします。バージョン検出と同じシェルを使うため、nvm などでインストールしたツールも見つけられます。

設定とセッションのデータはすべて残ります。インストールが複数ある場合は、現在使われている 1 つだけをアンインストールし、ほかは残します。インストール元を判別できないものは自動ではアンインストールせず、手動のコマンドを使うよう案内します。「アプリ」ページのメニューに「手動アンインストールコマンド」を追加しました。インストール方法（npm、pnpm、Bun、Homebrew など）と実行環境ごとに各ツールのアンインストールコマンドを一覧表示し、コピーしてターミナルで実行できます。

**プリセット：** StreamLake 中国版、AIComing、SoruxGPT Coding Plan、GrooRoute Pro を追加しました。StreamLake グローバル版の OpenCode、OpenClaw、Pi のプリセットのアドレスを修正しました。AIGoCode は新しいドメインに移行しました。

## 改善

**プラン枠のクエリが、すべてのアプリでデフォルトで有効になりました。** アドレスがプランに該当するプロバイダー（Kimi、智譜、MiniMax、Volcengine、OpenCode Go、Command Code）を追加したとき、これまでプラン枠のクエリがデフォルトで有効になるのは Claude Code だけで、Codex、OpenCode、Pi、Hermes などのアプリではもう一度手動で有効にする必要がありました。現在はすべてのアプリでデフォルトで有効になります。ワンクリックインポートのリンクも同様で、リンクに使用量クエリスクリプトがなく、アドレスがプランに該当する場合は、インポート後にデフォルトで有効になり、確認ダイアログに「プラン枠：Kimi For Coding」のようにプラン名が表示されます。リンクに `usageEnabled=false` と書かれていれば引き続きオフです。ZenMux は引き続き Claude Code でのみデフォルトで有効です。追加済みのプロバイダーには影響しません。

**フルスクリーンのページがフェードイン・フェードアウトしなくなりました。** v4.0.10 ではプロバイダーの追加・編集ページのフェードイン・フェードアウトをなくしましたが、「価格設定を追加」「利用状況を設定」「API エンドポイント管理」、統合プロバイダー、ワークスペースのファイルなどのページは、Windows で開くときにまだ一瞬ちらついていました。現在はすべてのフルスクリーンページでフェードイン・フェードアウトをしなくなり、macOS と Linux でも同じです。アカウントのページが右からスライドインするアニメーションは残しています。ワークスペースのファイルとデイリーメモリーは、内容を読み込み終えてから編集ページを開くようになり、先に読み込み中の画面が一瞬表示されることはなくなりました。

## 修正

- **Windows で CC Switch の自動更新による再起動後、ツールのインストールやアップグレードで npm が見つからなかった問題**（[#8171](https://github.com/farion1231/cc-switch/issues/8171)）。インストーラーによる更新後に自動で再起動した CC Switch は、ユーザーの完全な PATH を取得できていませんでした。バージョン検出ではこれまでもレジストリから PATH を補っていたため、ツールはインストール済みと表示されていましたが、インストールやアップグレードのコマンドの実行には欠けたままの PATH を使っていたため、npm が見つかりませんでした。現在はコマンドの実行時にも補った PATH を使います。アンインストールも同様です。
- **Codex でフォークしたセッションが、毎分まるごと読み直されていた問題**（[#8217](https://github.com/farion1231/cc-switch/issues/8217)、[#8209](https://github.com/farion1231/cc-switch/issues/8209)）。サブエージェントのセッションや、「新しいチャットに分岐」や巻き戻しで生じたフォークセッションは、親セッションがまだフォークの時点まで書き込まれていない場合、使用量の取り込みでいったんスキップし、後で再試行します。v3.18 以降、60 秒ごとの同期のたびにこれらのセッションをまるごと読み直し、ログに警告を 1 件書き込んでいました。フォークセッションが多いユーザーでは累計の読み込み量が数 TB に達し、ログもすぐにローテーションの上限まで膨らんでいました。現在は子セッションと親セッションのファイルの状態を記録し、ファイルが変わっていなければそのままスキップし、変わったときにだけ再試行します。課金のルールは変わりません。親セッションがフォークの時点まで書き込まれないままのセッション（長く放置した後にフォークした場合など）の使用量は引き続き計上されません。この扱いはまだ議論中です（[#5687](https://github.com/farion1231/cc-switch/issues/5687)）。
- **Codex デスクトップ版の長いセッションでページが切り替わった後、分岐したサブエージェントの使用量がすべて失われていた問題**（[#7084](https://github.com/farion1231/cc-switch/issues/7084)、[#8210](https://github.com/farion1231/cc-switch/issues/8210)）。Codex デスクトップ版は長いセッションをページに分けて保存し、最初のページがいっぱいになると新しいファイルに続きを書きます。CC Switch はこれまで最初のページしか見つけられず、ページが切り替わった後に分岐したサブエージェントはずっと「親セッションがまだフォークの時点まで書き込まれていない」と判定され、使用量は v3.20.1 から集計されていませんでした。現在は同じセッションの各ページを順番につなげてから判定します。これらのサブエージェントのセッションはこれまで取り込まれていなかったため、セッションファイルが残っていれば、アップグレード後の次の同期で自動的に補完されます。フォークしたスレッド自体のページが切り替わった後の続きのページはまだ集計できず、今後のバージョンで対応します（[#8161](https://github.com/farion1231/cc-switch/issues/8161)）。
- **Skills と MCP の一括有効化・無効化がすべて失敗しても、成功と表示されていた問題。** 現在はすべて失敗したときに赤いエラー通知を、一部が失敗したときに警告を表示します。元に戻す操作も実際の結果に応じて通知し、常に「元に戻しました」と表示することはなくなりました。
- **ワークスペースエディターが、前のファイルの内容を現在のファイルに保存してしまうことがあった問題。** あるファイルを開いて閉じ、続けて別のファイルを開いたとき、後者の読み込みに失敗すると、編集ページは新しいファイル名のまま前のファイルの内容を表示し続け、ここで保存を押すと新しいファイルが上書きされていました。現在は読み込みに失敗するとファイル一覧に戻ります。

## アップグレードに関する注意

**データベースの構造は変わっていません。** バージョンは 20 のままです。

- Codex のサブエージェントの使用量の補完は、アップグレード後の次の同期で自動的に行われます。対象は、これまで親セッションのページ分割のためにスキップされ続けていた子セッションだけで、取り込み済みの使用量が重複して計上されることはありません。
- プラン枠のデフォルト有効化は、新しく追加またはインポートするプロバイダーにだけ影響します。既存のプロバイダーで有効にするには、カードの「利用状況を設定」を押して Token Plan テンプレートを選んでください。
