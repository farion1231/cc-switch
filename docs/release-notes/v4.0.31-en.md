# CC Switch v4.0.31

This release adds **Tencent WorkBuddy** as a managed app: custom models are written into WorkBuddy's own model configuration and can be picked right inside WorkBuddy; you can also switch between several WorkBuddy accounts, seeing each account's plan, remaining credits and expiry date before you switch. The interface gains **German**, and the README is now available in all eight interface languages.

Fixes cover Claude Code routed to a relay in OpenAI Responses format getting a 400 on every turn and never being able to continue once the relay spread the session across different Azure resources; parallel tool calls getting a 400 and a very low cache hit rate when routed to a Gemini Native upstream; the macOS tray hover tooltip staying on screen; usage from old Codex conversations that were resumed never being imported; and more.

---

## New

### WorkBuddy

Tencent WorkBuddy becomes a new managed app ([#8757](https://github.com/farion1231/cc-switch/pull/8757), requested in [#4802](https://github.com/farion1231/cc-switch/issues/4802), [#5802](https://github.com/farion1231/cc-switch/issues/5802), [#7419](https://github.com/farion1231/cc-switch/issues/7419), [#7076](https://github.com/farion1231/cc-switch/issues/7076)). Like OpenCode, several providers are active at the same time:

- **Custom models**: after you click "Add", the provider's models are written into WorkBuddy's own `models.json` and appear in WorkBuddy's model picker as "name:model ID", using the "Vendor label" when the name is left empty. Models you added inside WorkBuddy itself are kept as they are. WorkBuddy's custom models support only the OpenAI Chat Completions format.
  - Models from presets offer a choice of thinking effort in WorkBuddy's model picker (for example low / high / max for Kimi K3.1 Pro).
  - WorkBuddy doesn't yet support the same model ID appearing twice. When you pick a preset, models already used by another card are skipped, with a note saying which card; a duplicate model ID typed by hand is flagged and can't be saved.
- **Official accounts**: accounts you have signed in to in WorkBuddy are collected into "Accounts" automatically, showing nickname, plan, remaining credits and credit expiry (orange when expiring within three days). There are two ways to switch accounts: add a "WorkBuddy Official Sign-in" card bound to the account, or click "Switch WorkBuddy to this account" in that account's menu in Accounts.
  - **Quit WorkBuddy completely before switching** (including the menu bar / tray), or it will write its current sign-in back.
  - "Sign in to another account" only makes WorkBuddy open at its sign-in page on this computer; it does not sign the current account out on the server, and accounts already collected can still be switched back to.
  - Plan and credits can only be fetched while WorkBuddy is running and signed in to that account; once fetched, they are cached and shown.
- **MCP, Skills and prompts**: synced to WorkBuddy's `mcp.json`, Skills directory and global prompt `CODEBUDDY.md`. MCP entries managed by WorkBuddy's connectors are left untouched.
- **Session management and usage statistics**: WorkBuddy sessions are listed, and usage is imported from session logs. Sessions can't be resumed in a terminal.

### German interface, README in eight languages

- **German**: chosen automatically on first launch based on the system language; the tray menu and quick panel are translated too. As with Korean and Russian, Privacy Filter placeholders use English in the German interface for now.
- New Traditional Chinese, Korean, Turkish and Russian versions of the README, matching the eight interface languages one to one.

### Other

- **"Resync now" is right in the "⋯" menu at the top right of the Skills page** ([#9417](https://github.com/farion1231/cc-switch/issues/9417)): no more digging for it in "Storage and sync".
- **When session management groups "By project", Codex desktop conversations that don't belong to any project are put into one "Codex chats" group** ([#9415](https://github.com/farion1231/cc-switch/issues/9415)): no longer one group per conversation.
- **The request log status code filter adds 403, 404, 502, 503, 504, 520 and 529** ([#9425](https://github.com/farion1231/cc-switch/issues/9425)).

## Changes

- **The Privacy Filter now runs as the last step before a request is sent** ([#9460](https://github.com/farion1231/cc-switch/pull/9460)): it used to filter when the request first entered routing, so content added to the request later, such as failover retries and compaction summaries generated by CC Switch itself, was not processed. It now filters before every send to the upstream, for fuller coverage; tool descriptions are not processed. Detection is also faster, with the same results as before.
- **Faster Codex usage import** ([#9400](https://github.com/farion1231/cc-switch/pull/9400)): less repeated parsing and memory allocation when reading Codex session logs.

## Fixes

- **Claude Code / Claude Desktop routed to a relay in OpenAI Responses format occasionally got 400 "The requested item was created under a different Azure OpenAI resource", after which every turn of the same session failed** ([#9424](https://github.com/farion1231/cc-switch/issues/9424)). The relay had spread one session across different Azure OpenAI resources, so the session history carried thinking records generated by another resource; switching provider mid-session gave a similar `invalid_encrypted_content`. Now, when the upstream rejects a request this way, these thinking records are removed and the request is retried once automatically, so the session can continue. Normal requests are unaffected.
- **Claude Code routed to a Gemini Native upstream got 400 "number of function response parts" after parallel tool calls** ([#9453](https://github.com/farion1231/cc-switch/issues/9453)): tool results spread over several messages are now merged before sending.
- **Claude Code routed to a Gemini Native upstream had a cache hit rate of only about 20% in long sessions** ([#9450](https://github.com/farion1231/cc-switch/issues/9450)): Claude Code appends a remaining-token notice every turn, which used to be moved to the very front of the whole history, so every turn started differently. It now stays where it was, so the earlier history stays the same from turn to turn and can hit the cache.
- **Claude Code routed to a Gemini Native upstream recorded too little usage for streaming requests, often with cache reads recorded as 0** ([#9464](https://github.com/farion1231/cc-switch/issues/9464)).
- **On macOS, the "CC Switch" hover tooltip on the tray icon stayed on screen, and only quitting the app got rid of it** ([#9445](https://github.com/farion1231/cc-switch/issues/9445), [#9329](https://github.com/farion1231/cc-switch/issues/9329), [#9446](https://github.com/farion1231/cc-switch/pull/9446)): macOS no longer shows this tooltip; when something is wrong, the dot on the icon and the quick panel still let you know.
- **On macOS, clicking the menu-bar icon didn't open the quick panel while another app was in full screen** ([#9331](https://github.com/farion1231/cc-switch/issues/9331)).
- **In Claude Code's Routing mode, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` set in a provider was not written to `settings.json`** ([#9451](https://github.com/farion1231/cc-switch/issues/9451), [#9455](https://github.com/farion1231/cc-switch/pull/9455)): it is now written with the provider, like the provider's other exclusive settings, and a value you set globally yourself is no longer cleared by switching.
- **After resuming an old Codex conversation that had ended, the new usage was never imported** ([#9420](https://github.com/farion1231/cc-switch/issues/9420)).
- **With Codex directly on a third-party provider, turning off "Keep official login for direct switches" didn't take effect right away; you had to switch to the official card and back** ([#9367](https://github.com/farion1231/cc-switch/issues/9367)): changing the setting now rewrites the current provider's configuration.
- **For GPT models in a Codex third-party provider that share a name with official ones, the model picker didn't show the display name you set** ([#9380](https://github.com/farion1231/cc-switch/issues/9380)).
- **On macOS, after Claude Desktop was uninstalled, the "Apps" page still listed it as installed** ([#9383](https://github.com/farion1231/cc-switch/issues/9383)): only `Claude.app` counts now; a leftover data directory no longer does.
- **On Linux KDE Wayland, copy buttons reported success, but the clipboard was empty or still held the old content** ([#9384](https://github.com/farion1231/cc-switch/issues/9384)).
- **In the account dropdown of the Copilot CLI official card, the option that binds no account read "Use default account", but it actually uses Copilot CLI's own GitHub login** ([#9408](https://github.com/farion1231/cc-switch/issues/9408)): it now reads "Follow Copilot CLI's own sign-in".
- **Models added by hand in DeepSeek Harness had no way to set compatibility options** ([#9330](https://github.com/farion1231/cc-switch/issues/9330)): the compatibility editor is now shown for them too, so you can turn off the `developer` role for endpoints that don't accept it, such as Alibaba Cloud Bailian's compatible mode.
- **Enabling a Skill reported that creating a symbolic link failed, with no clue to the actual cause** ([#9439](https://github.com/farion1231/cc-switch/issues/9439)): the error now includes the error code the system reports (for example `os error 5` on Windows), making it easier to tell whether it's a permission problem or something else.
- **The "Apps" and "Settings" items at the bottom of the sidebar were truncated in the German, Turkish and Russian interfaces**.

## Upgrade Notes

**The database schema goes from 25 to 26**, adding WorkBuddy toggles for MCP and Skills. The database is backed up automatically before the upgrade; if you go back to an older version after upgrading, it reports that the database version is too new and cannot open it.
