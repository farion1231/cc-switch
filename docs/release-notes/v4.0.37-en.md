# CC Switch v4.0.37

This release is mostly fixes. Providers and MCP entries that cannot be read (for example, ones written by a newer version and synced over WebDAV / S3) are no longer treated as empty configs and overwritten with defaults on the next save; instead they are listed separately and can be deleted. Pi adds a **Mistral AI** preset, and the Korean translation of the interface has been improved throughout.

Fixes also cover local routing failing to start when its listen address was IPv6; "Apply to Claude Code extension" wiping a broken `~/.claude/config.json`; large skill repositories being cut off mid-download on slow connections; the Codex model catalog probe not finding Node when CC Switch was opened from Finder; fields starting with `_` being removed from tool-call arguments before they were sent upstream; providers removed from and re-added to the failover queue still being skipped; clicking "Retry" on the Plugins page appearing to do nothing; and more.

---

## New

### Mistral AI preset for Pi

Pi adds a Mistral AI preset that uses Pi's own Mistral protocol (`mistral-conversations`), so streamed reasoning content is not lost (requested in [#9343](https://github.com/farion1231/cc-switch/issues/9343), [#9344](https://github.com/farion1231/cc-switch/pull/9344)).

- Comes with Mistral Large 4 and Mistral Small 4, with thinking levels matching Pi's built-in Mistral catalog.
- The provider is named `cc-switch-mistral`, so it does not shadow Pi's built-in `mistral`.
- `mistral-conversations` can also be selected in the Pi form's protocol list. Oh My Pi and Kimi Code do not support this protocol and do not show this preset.

## Changes

- **Unreadable providers and MCP entries are kept as is and can be deleted individually** ([#9767](https://github.com/farion1231/cc-switch/pull/9767)): previously, data that could not be read was treated as an empty config, and the next save wrote the defaults back, losing the original data. Such entries are now listed separately on the provider page and the MCP page with the reason they cannot be read; they cannot be edited or enabled, but can be deleted (this removes only CC Switch's record and does not touch any app's config files). Other entries are shown and used as usual, and failover skips the unreadable one; operations that change that entry are refused, and while it exists, syncing all of an additive app's providers (such as OpenCode's) to its config file also reports an error. Upgrading to a version that can read it restores it.
- **Claude Code's 1M marker is now written in lowercase as `[1m]`** (see [#9757](https://github.com/farion1231/cc-switch/issues/9757)): this matches how the Claude Code documentation writes it. Claude Code was already case-insensitive here, so existing `[1M]` markers keep working.
- **Improved Korean translation of the interface** ([#9395](https://github.com/farion1231/cc-switch/pull/9395), [#9349](https://github.com/farion1231/cc-switch/pull/9349)).
- **Account rows in Accounts are easier to read** ([#9369](https://github.com/farion1231/cc-switch/pull/9369)): "Used by N provider(s)" is on its own line, the quota label column is sized to the longest label, and in narrow windows the plan, domain and sign-in date are no longer squeezed into an ellipsis; percentages also stay visible with longer translations such as German and Russian.

## Fixes

- **Local routing did not start when its listen address was IPv6 (such as `::1`)** (see [#9743](https://github.com/farion1231/cc-switch/issues/9743)): it used to report "invalid socket address syntax"; it now listens normally.
- **With "Apply to Claude Code extension" on, a broken `~/.claude/config.json` was wiped** (see [#9744](https://github.com/farion1231/cc-switch/issues/9744)): when the file was not valid JSON, it used to be rewritten as if it were empty, losing every other setting in it. Now CC Switch reports an error naming the file path and leaves the file as is; writes also go to a temporary file first and then replace the original, so an interrupted write no longer leaves a truncated file.
- **On slow connections, large skill repositories were cut off mid-download**: install, update, update check and skill discovery used to limit the whole download to 60 seconds. Now a download is stopped only when no data arrives for 60 seconds in a row, with a "no data received" message; the whole download can take up to 10 minutes.
- **When CC Switch was opened from Finder, the Codex model catalog probe could not find Node** (see [#9764](https://github.com/farion1231/cc-switch/issues/9764)): an npm-installed Codex therefore failed to run, CC Switch fell back to the CLI bundled with the Codex desktop app, which may be older, and GPT models in aggregation mode lost their official metadata (such as the search tool). The probe now uses the login shell's PATH, as CC Switch already does when running other command-line tools.
- **Fields starting with `_` were removed from tool-call arguments before being sent upstream** ([#9753](https://github.com/farion1231/cc-switch/pull/9753)): MCP, database and GraphQL tools often use fields such as `_id`, `_meta` and `__typename`, which used to be removed as private fields, so the call the model saw differed from the one actually executed, and strict providers may reject the request outright. Tool-call arguments are now kept as is.
- **A provider removed from and re-added to the failover queue looked fine on its card but was still skipped for a while** ([#9750](https://github.com/farion1231/cc-switch/pull/9750)): removing a provider from the queue, or leaving routing for an app, now also clears the circuit breaker state in the running router. When enabling OMO / OMO Slim fails to delete the other variant's config file, a dedicated warning is now shown as well.
- **Clicking "Retry" after the Plugins page timed out while loading appeared to do nothing** (see [#9758](https://github.com/farion1231/cc-switch/issues/9758)): the Installed, Discover and Marketplaces tabs now all show loading while retrying.
- **Several Plugins page issues** ([#9742](https://github.com/farion1231/cc-switch/pull/9742)): an operation in progress still shows its spinner after switching to another app and back; a Codex plugin enabled again while it is being updated is no longer disabled when the update finishes; search also matches the name shown (for Pi packages installed from git or a local folder); a pinned-version Pi package that was uninstalled and then installed from "Discover" no longer stays in "Discover"; on Windows, plugins installed in WSL now show their version, name and description.
- **Memory and resource usage** ([#9773](https://github.com/farion1231/cc-switch/pull/9773)): cached images are released when leaving the session reader; a downloaded installer is released when auto-update is turned off; some network requests reuse HTTP connections instead of opening a new one each time; request bodies received by local routing (including after decompression) are capped at 200 MiB, and larger ones get a 413.
- **Right after installing or upgrading a command-line tool, the next action occasionally reported "An app operation is still running"** ([#9775](https://github.com/farion1231/cc-switch/pull/9775)).
