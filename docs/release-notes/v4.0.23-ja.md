# CC Switch v4.0.23

今回のリリースでは、Kimi Code、MiniMax Code、Oh My Pi のプロバイダーエディターが、設定ファイルのうちそのプロバイダーの部分をアプリ自身の形式で表示するようになりました。Claude Code、Claude Desktop がルーティング経由で OpenAI 形式や Gemini の上流に接続するとき、クライアントで選んだ思考レベルをより多くのモデルに送れるようになり、送り方もカードで選べます。「アカウント」ページではすべてのアカウントの利用枠をまとめて更新できるようになり、Antigravity、MiniMax Code の使用量の記録には所要時間と最初のトークンまでの時間が加わりました。このほか、Windows で軽量モードに入るとメインウィンドウが戻らない、ルーティング経由で一部の OpenAI 形式の上流につなぐとモデル切り替えに失敗する、DeepSeek Harness の設定フォルダーがリンクのときプロバイダーを編集できない、Grok Build の 50 MiB を超えるセッションの使用量が集計されない、Codex の分岐セッションの使用量がいつまでも取り込まれない、DeepSeek Harness などで公式残高をテストすると Key が空と表示される、プロバイダーフォームのエディター同士が互いに上書きする、といった問題を修正しました。4.0 の更新内容の全体は [v4.0 リリースノート](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-ja.md) をご覧ください。

## 新機能

### Kimi Code、MiniMax Code、Oh My Pi のプロバイダーエディターをネイティブ形式で表示

これまでこの 3 つのアプリのプロバイダーエディターはカードの JSON を表示していたため、実際の設定ファイルと対応せず、上流のドキュメントにある設定例も貼り付けられませんでした。現在のエディターは設定ファイルのうちこのプロバイダーの部分だけを表示し、位置も形式もファイルと同じです：

- **Kimi Code**：`config.toml` の `[providers.<key>]` と、それに属する `[models."..."]` テーブル。
- **MiniMax Code**：YAML の `custom_provider.<key>`。
- **Oh My Pi**：`models.yml` の `providers.<key>`。

タイトルには実際のファイルパスが表示され、フォルダーの上書き設定や `KIMI_CODE_HOME` などの変数に応じて変わります。下書きに形式の誤りがある、ほかのプロバイダーのノードを書いた、`default_model` のようなグローバル設定を書いた、といった場合は通知を表示して保存を拒否し、直すまでは上のフォームの項目を一時的に編集できなくして、下書きが上書きされるのを防ぎます。エディターで書いたコメントは保存されません。DeepSeek Harness のプロバイダーは profile のパッチにあるため、引き続き JSON エディターを使います。

### ルーティング経由で Gemini に接続するときも思考レベルを送信

これまで Claude Code、Claude Desktop がルーティング経由で Gemini ネイティブ形式に変換するとき、クライアントで選んだ思考レベルと「思考オフ」はどちらも捨てられ、Gemini は常にモデルの既定の設定を使っていました。現在は Gemini 自身の OpenAI 互換インターフェースと同じ換算方法で送ります：

- **Gemini 2.5**：低、中、高をそれぞれ 1024、8192、24576 の思考予算にします。思考オフのとき Flash と Flash-Lite には 0 を送り、Pro はオフにできないため最小の 128 を送ります。
- **Gemini 3 以降**：low、medium、high のレベルを送ります（Gemini 3 Pro には medium がないため high を送ります）。これらのモデルはどれも思考をオフにできないため、オフのときは対応している最も低いレベルを送ります。
- 認識できないモデル、画像や音声のようなモデル、名前にすでにレベルが含まれている中継サービスのエイリアス（`gemini-3-pro-high` など）には送りません。リクエストにもともと思考の設定がない場合も送りません。

### 「アカウント」ページの「すべて更新」

「アカウント」ページのヘッダーに「すべて更新」ボタンが追加され、ページ上のすべてのアカウントの利用枠（DeepSeek は残高）を一度に照会し直します。各行にはいつもどおり「更新中…」と表示されます（[#9073](https://github.com/farion1231/cc-switch/pull/9073)）。

## 改善

**Claude Code、Claude Desktop がルーティング経由で OpenAI 形式の上流に接続するとき、より多くのモデルに思考レベルを送れるようになりました**（[#9062](https://github.com/farion1231/cc-switch/issues/9062)）。これまでは o シリーズ、GPT-5 以降、Grok 4.5 以降にしか思考レベルが送られず、DeepSeek などほかのモデルでは黙って捨てられ、ログにも記録されませんでした。現在は次のとおりです：

- 認識できるプロバイダーには、そのプロバイダーが対応するレベルで送ります。たとえば DeepSeek には low、high、max を送り、OpenRouter は xhigh までです。Kimi、GLM、Qwen、MiniMax のように OpenAI インターフェースがこのパラメーターを受け付けないものには送りません。
- 認識できない上流には low、medium、high だけを送り、xhigh、max を選んだときは high を送ります。
- GPT-3.5、GPT-4、Llama、Mistral には送りません。思考をオフにしているときも送りません。
- 両アプリのプロバイダーフォームで、この 2 つの形式のときに「思考レベル」が追加されました。「自動（推奨）」は上記のルールで送ります。「そのまま送信」はクライアントで選んだレベルをそのまま送り、上流が xhigh や max に対応していない場合はエラーになります。「送信しない」は上流がこのパラメーターでエラーを返す場合に使います。マネージドアカウントのカードにはこの項目は表示されません。

Codex がルーティング経由で DeepSeek に接続するときのレベルの換算も、DeepSeek 公式と同じにしました：minimal、low は low、medium、high、xhigh は high、max は max を送ります。これまでは low が high に、xhigh が max に引き上げられていました。

**Antigravity、MiniMax Code の使用量の記録に所要時間と最初のトークンまでの時間が加わりました。** これまでこの 2 つのアプリの使用量には速度と最初のトークンまでの時間がありませんでした。以前に取り込んだ記録にも補われます。

**Skills の「見つける」ページと「インストール済み」ページを同じ行のスタイルにしました**（[#9081](https://github.com/farion1231/cc-switch/pull/9081)）。リポジトリ名は小さな等幅文字で名前の横に表示し、フォルダーのパスは表示しなくなりました。「ドキュメントを開く」ボタンは右端に移り、「インストール済み · N アプリ」は「インストール済み ›」になりました。「見つける」ページで「インストール済み」をクリックして移動すると、その行が黄色く 2 回点滅してから元に戻ります。

**トレイで、アカウントを選んだ Claude 公式カードにアカウントを表示するようにしました**（[#9071](https://github.com/farion1231/cc-switch/pull/9071)）。これまではサブタイトルがすべて `www.anthropic.com` で、公式カードが何枚もあると区別できませんでした。現在はメモがあればメモを、なければアカウント（メールアドレス、ない場合は組織名）を表示します。アカウントがこのパソコンにない場合は、これまでどおり公式サイトを表示します。

**Claude Desktop のルーティングモードで、Haiku クラスのモデル名を `claude-haiku-5-5` に変更しました**（[#9096](https://github.com/farion1231/cc-switch/issues/9096)）。Claude Desktop は `claude-haiku-4-5` を古いモデルとして扱うため、Haiku クラスで思考レベルを選べませんでした。上流そのものが旧版の Claude Haiku の場合は変更しません。直接接続モードには影響しません。

**Grok Build に grok-4.6-build、grok-4.7-build、grok-4.7-build-fast の価格を追加しました**（[#9026](https://github.com/farion1231/cc-switch/pull/9026)）。

**プリセット：** OpenAI API Key のプリセット、13 社のプロバイダーの Gemini CLI / Antigravity プリセット（[#9089](https://github.com/farion1231/cc-switch/issues/9089)）、iFlytek Astron MaaS 従量課金の Claude Code プリセット（[#9036](https://github.com/farion1231/cc-switch/issues/9036)）を追加しました。

## 修正

- **Windows で軽量モードに入った後、CC Switch をもう一度起動するとメインウィンドウが表示されず、トレイも反応せず、再起動しても直らない問題**（[#9090](https://github.com/farion1231/cc-switch/issues/9090)）。
- **ルーティング経由で OpenAI 形式の上流につなぎ、上流が非ストリーミングのリクエストにも SSE を返す場合、モデルを切り替えると「Unable to validate model」になる問題**（[#9097](https://github.com/farion1231/cc-switch/pull/9097)、[#9095](https://github.com/farion1231/cc-switch/issues/9095)）。現在は非ストリーミングのリクエストに完全な JSON レスポンスを返します。
- **DeepSeek Harness の profile がシンボリックリンクで同じファイルを指していると、プロバイダーや MCP の編集がすべて競合として報告される問題**（[#9101](https://github.com/farion1231/cc-switch/pull/9101)、[#9100](https://github.com/farion1231/cc-switch/issues/9100)）。
- **Grok Build のセッションログが 50 MiB を超えると丸ごとスキップされ、長いセッションの使用量がいつまでも集計されない問題**（[#9026](https://github.com/farion1231/cc-switch/pull/9026)、[#6660](https://github.com/farion1231/cc-switch/issues/6660)）。現在は 1 行ずつ読み込み、以降は追加された部分だけを読みます。
- **Codex の分岐セッションが、親セッションがしばらくアイドルになった後いつまでも取り込まれず、使用量が集計されない問題**（[#9093](https://github.com/farion1231/cc-switch/pull/9093)、[#9094](https://github.com/farion1231/cc-switch/issues/9094)）。
- **DeepSeek Harness、MiniMax Code、Kimi Code で、使用量クエリの公式残高や Coding Plan をテストすると「API key is empty」と表示される問題**（[#9108](https://github.com/farion1231/cc-switch/pull/9108)、[#9107](https://github.com/farion1231/cc-switch/issues/9107)）。保存済みのクエリはもともと正常で、テストとカスタムテンプレートだけがプロバイダーの Key とアドレスを読み取れていませんでした。
- **プロバイダーフォームで、アドレス、Key、モデルなどの項目を変更してから下の設定エディターを変更すると（またはその逆）、先に変更した内容が元に戻されることがある問題**（[#6777](https://github.com/farion1231/cc-switch/pull/6777)）。
- **起動時に、バックグラウンドのセッション使用量の同期が終わるまで画面が反応しない問題**（[#9098](https://github.com/farion1231/cc-switch/pull/9098)、[#9084](https://github.com/farion1231/cc-switch/issues/9084)）。
- **Codex が OpenRouter 経由で DeepSeek V4 Flash 0731 を使うとき、会話に画像があると 404 になる問題**（[#6194](https://github.com/farion1231/cc-switch/pull/6194)、[#6176](https://github.com/farion1231/cc-switch/issues/6176)）。
- **Windows で「ローカル環境チェック」が OpenCode のデスクトップ版を起動してしまう問題**（[#7027](https://github.com/farion1231/cc-switch/pull/7027)、[#6973](https://github.com/farion1231/cc-switch/issues/6973)）。
- **macOS でプロバイダーを追加するとき、アイコン選択ページの戻るボタンがウィンドウの信号機ボタンに隠れる問題**（[#9076](https://github.com/farion1231/cc-switch/pull/9076)、[#9075](https://github.com/farion1231/cc-switch/issues/9075)）。
- **ローカルルーティングがオンのとき、MiniMax Code、DeepSeek Harness のフォームで取得したモデル一覧が 2 秒後に消える問題**（[#9068](https://github.com/farion1231/cc-switch/pull/9068)）。
- **MiniMax Code、DeepSeek Harness、Kimi Code の Key 入力欄で、IME を使って入力すると文字が重複する問題**（[#9069](https://github.com/farion1231/cc-switch/pull/9069)）。
- **mise でインストールした Claude Code で、「アカウント」ページから Claude アカウントを追加すると「default installation is ambiguous」になる問題。**
- **ChatGPT のログインが本当に期限切れになったとき、CC Switch が一時的なエラーとして再試行し続け、再ログインを促さない問題**（[#9049](https://github.com/farion1231/cc-switch/pull/9049)）。同じ PR で、Gemini の `.env` にある `export` で始まる漏洩した認証情報を削除できない問題も修正しました。
