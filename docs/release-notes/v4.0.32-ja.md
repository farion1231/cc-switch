# CC Switch v4.0.32

今回のリリースでは、**アップデートのバックグラウンド自動ダウンロード**を追加しました。「設定 → 情報」で「アップデートを自動でダウンロード」をオンにすると、新しいバージョンをバックグラウンドでダウンロードして検証し、右下にインストールするかどうかを確認する通知を表示します。確認なしに再起動することはありません。「設定 → ネットワーク」には **IP 診断**を追加し、CC Switch がグローバルプロキシ、一時プロキシ、または現在のネットワークで接続したときの出口 IP と地域を確認できるようになりました。

このほか、Codex がルーティング経由でプロバイダーを切り替えて古いセッションを再開すると、上流がいったん 200 を返した後に「復号できない」と報告し、そのターン全体が失敗する問題、Codex がルーティングまたは集約モードで Mistral AI に接続するとリクエストが 422 になる問題、CC Switch 内部のある操作が一度クラッシュすると、再起動するまでトレイが空になりプロバイダーを切り替えられなくなる問題、mise でインストールしたツールが「アプリ」ページに 2 件のインストールとして表示される問題などを修正しました。

---

## 新機能

### アップデートのバックグラウンド自動ダウンロード

「設定 → 情報」に「アップデートを自動でダウンロード」スイッチを追加しました。デフォルトはオフで、デバイスごとに設定します。

- オンにすると、CC Switch の起動から 1 分後に 1 回確認し、その後は 6 時間ごとに確認します。新しいバージョンがあれば、バックグラウンドでダウンロードして検証します。
- ダウンロードが終わると、メイン画面の右下でインストールするかどうかを確認します。インストールすると CC Switch が再起動し、ローカルルーティングを経由中のリクエストは中断されるため、「インストールして再起動」をクリックしない限りインストールは行いません。ルーティングがオンのときは、通知にその旨を表示します。
- 「後で」をクリックしても、このバージョンの通知を再び出さなくなるだけです。設定の赤いドット、「情報」ページのボタン、トレイメニューとクイックパネルに追加された「再起動して vX に更新」からは引き続きインストールできます。
- ポータブル版と Linux の deb / rpm パッケージでは自動インストールができないため、スイッチはグレーアウトし、理由を表示します。

### IP 診断

「設定 → ネットワーク」のグローバルプロキシの下に IP 診断を追加しました（[#9449](https://github.com/farion1231/cc-switch/pull/9449)、要望は [#9448](https://github.com/farion1231/cc-switch/issues/9448)）。保存済みのグローバルプロキシを選ぶか、一時プロキシ（今回の検査にだけ使い、保存しません）を入力して「IP を検査」をクリックすると、出口 IP、2 つの検査サービスの結果が一致しているかどうか、国・地域、都市、ISP などの情報を表示します。グローバルプロキシを設定していない場合は、システムプロキシまたは直接接続で検査します。プロキシを指定した場合、プロキシに接続できなくても直接接続には切り替えません。

- クリックしたときだけ実行し、icanhazip.com と ipify.org に接続して、観測した IP を ipwho.is に送って位置を照会します。
- 検査するのは CC Switch 自身がこの経路で接続したときの出口で、Claude Code や Codex などのクライアントの出口と同じとは限りません。

### その他

- **GitHub Copilot リバースプロキシのプロバイダーカードに、紐付けた GitHub アカウントを表示**（[#9228](https://github.com/farion1231/cc-switch/pull/9228)、要望は [#9480](https://github.com/farion1231/cc-switch/issues/9480)）：これまでは GitHub Copilot の公式サイトの URL しか表示されず、複数のアカウントを使っていると区別できませんでした。紐付けていない場合は「アカウント」ページのデフォルトアカウントを表示し、メモを入力している場合はメモを優先します。

## 修正

- **Codex がルーティング経由でプロバイダーを切り替えて古いセッションを再開すると、上流がいったん 200 を返した後に「Encrypted function output content could not be decrypted or decoded」と報告し、Codex が 5 回再接続した後にそのターン全体が失敗する問題**（[#9476](https://github.com/farion1231/cc-switch/issues/9476)）：リクエストに前のプロバイダーが生成した思考の記録や暗号化された内容が含まれている場合、CC Switch は上流が出力を始めるまで待ってから Codex に渡します。その時点で拒否されたら、これらの内容を取り除いて同じプロバイダーで自動的に 1 回再試行するため、セッションを続けられます。こうした内容を含まないリクエストは、これまでどおりそのままストリーミングで返します。
- **Codex がルーティングまたは集約モードで Mistral AI に接続すると、リクエストが 422 `extra_forbidden` になる問題**（[#9507](https://github.com/farion1231/cc-switch/issues/9507)）：Codex が付ける Responses 専用のフィールド、Mistral 上の DeepSeek / GLM モデル向けに自動で付けていた思考パラメーター、ツールを一度使った後は毎ターン付く `reasoning_content` を、`api.mistral.ai` に送るときはすべて取り除くようにしました。ほかの上流には影響しません。
- **CC Switch 内部のある操作が一度クラッシュすると、トレイメニューが空になり、プロバイダーを切り替えられず、終了時に直接接続にも戻せなくなって、再起動するしかなかった問題**（[#9472](https://github.com/farion1231/cc-switch/pull/9472)、[#9483](https://github.com/farion1231/cc-switch/pull/9483)、関連：[#8058](https://github.com/farion1231/cc-switch/issues/8058)）：データベース、設定、設定ファイルの書き込み、MCP、プロンプト、料金、バックアップなどの操作は、クラッシュの後も回復できるようになりました。クラッシュ時に書き込みが終わっていなかった変更はロールバックされます。
- **GitHub Copilot 経由で Claude Code / Claude Desktop を使うと、Grok のように Copilot で Responses API にしか対応していないモデルが「not accessible via the /chat/completions endpoint」になる問題**（[#6954](https://github.com/farion1231/cc-switch/issues/6954)、[#9473](https://github.com/farion1231/cc-switch/pull/9473)）：こうしたモデルは Responses API を使うようにしました。両方の API に対応しているモデルは変わりません。
- **Antigravity で Orchestrator を選ぶと、使用量がすべて 1 つの仮想モデル名で記録され、料金が 0 になる問題**（[#9493](https://github.com/farion1231/cc-switch/issues/9493)、[#9494](https://github.com/farion1231/cc-switch/pull/9494)）：各ステップで実際に使われたモデルで料金を計算するようにし、Gemini 4 Hydrogen の料金を追加しました。取り込み済みの Antigravity の履歴は一度だけ解析し直し、料金を補います。
- **「Codex セッション履歴を統一」をオンにしたり履歴を移行したりした後、数か月前のセッションが `codex resume` の一番上に並ぶ問題**（[#3866](https://github.com/farion1231/cc-switch/issues/3866)、[#9471](https://github.com/farion1231/cc-switch/pull/9471)）：通常の `.jsonl` セッションファイルを書き換えるときも、元の更新日時を保持するようにしました。圧縮されたファイルはもともと保持されていました。すでに変わってしまった更新日時は元に戻りません。
- **Hermes で削除したプロバイダーが、CC Switch で削除ボタンがグレーアウトしたままになる問題**（[#4816](https://github.com/farion1231/cc-switch/issues/4816)、[#9470](https://github.com/farion1231/cc-switch/pull/9470)）：Hermes にもう存在しないプロバイダーは編集・削除できるようになりました。Hermes の設定を読み込めない場合は、これまでどおりロックされます。
- **プリセットから OpenClaw のプロバイダーを追加すると、`/model` に表示されるのがフォームで最終的に保存したモデルではなく、プリセットに含まれるモデルになる問題**（[#9474](https://github.com/farion1231/cc-switch/pull/9474)、関連：[#6729](https://github.com/farion1231/cc-switch/issues/6729)）：フォームで削除したモデルは表示されなくなり、追加したモデルも選べるようになりました。プリセットを変更せずにそのまま保存した場合は、プリセットのモデルをすべて登録します。既存のプロバイダーを編集した場合はまだ同期されず、#6729 で引き続き対応中です。
- **mise でインストールしたツールが「アプリ」ページに 2 件のインストールとして表示される問題（mise を Homebrew でインストールした場合は、そのうち 1 件が homebrew と表示される）**（[#9515](https://github.com/farion1231/cc-switch/issues/9515)）：mise の shim は、実際に指しているインストールとして数えるようにしました。
- **ウィンドウの高さが低いと、「ターミナルを開く」ダイアログの確認ボタンが画面外に押し出されてクリックできない問題**（[#9478](https://github.com/farion1231/cc-switch/issues/9478)）：ダイアログの内容だけをスクロールできるようにし、ボタンを下部に固定しました。「追加の引数（任意）」の入力欄で Enter キーを押しても、そのままターミナルを開けます。
- **使用量ページの為替レートの状態表示に句点がなく、後ろの説明とつながって見える問題**（[#9436](https://github.com/farion1231/cc-switch/pull/9436)）。
