# CC Switch v4.0.28

今回のリリースは、主に 11 月 8 日の Codex の互換性のない更新への対応です。

> ⚠️ **Codex デスクトップ版 26.1103、CLI 0.167 から、公式サブスクリプションとサードパーティプロバイダーのセッションが完全に分かれました。** 直接接続モードで両者を切り替えると、これまでは両方のセッションが分かれて表示されるだけでしたが、現在はもう一方のセッションが読み取り専用になります。閲覧はできますが続けられず、続けようとすると「モデルプロバイダーが一致しない」と表示されます。切り替えながら古いセッションを続けるには、次の 2 つの方法があります：
>
> 1. **ルーティングまたは集約モードを使う**：今回のバージョンから、ルーティングまたは集約モードでサードパーティに切り替えても、セッションは公式サブスクリプションと同じグループに残り、どちらに切り替えても続けられます。
> 2. **「Codex セッション履歴を統一」をオンにする**（「設定 → アプリ設定 → Codex」）：公式とサードパーティのセッションが同じグループにまとまり、直接接続モードでも切り替えながら続けられます。

このほか、直接接続の切り替えでセッションが読み取り専用になるときは、その件数を表示するようになりました。「Codex セッション履歴を統一」をオンにして既存セッションの移行を選んだ場合、公式のセッションを継続的に移行するようになりました。公式クォータを使い切り、Codex が送信ボタンをロックしたときは、ルーティングまたは集約の設定で「公式ログインを一時停止」をオンにすると、サードパーティのモデルを引き続き使えます。公式クォータ保護は既定でオンになりました。アプリページのインストールとアップグレードでは、順番待ちの状態とリアルタイムの進捗が表示されます。また、Codex が別のプロバイダーにフェイルオーバーしても前のプロバイダーのモデル名のまま送られる、Kimi For Coding で圧縮に失敗する、Kimi や DeepSeek でツール呼び出しを続けた後にセッションがずっと 400 を返す、といった問題を修正しました。

---

## 新機能

### 新しい Codex のセッショングループに対応

Codex はプロバイダー識別子ごとにセッションを記録します。公式サブスクリプションは組み込みの `openai` に、CC Switch が書き込むサードパーティプロバイダーは `custom` に記録されます。新しい Codex では、現在のプロバイダーと同じグループのセッションしか続けられず、もう一方のグループは読み取り専用になります（[#7974](https://github.com/farion1231/cc-switch/issues/7974)）。今回のバージョンでは、これに合わせて次の変更を行いました：

- **ルーティングまたは集約モードでサードパーティに切り替えても、セッションが 2 つのグループに分かれなくなりました**：このパソコンで ChatGPT にログインしていて、「Codex セッション履歴を統一」をオンにしていない場合、サードパーティへのルーティングも公式と同じく組み込みの `openai` として書き込みます。リクエストはこれまでどおりローカルルーティングを経由してサードパーティに送られ、すべてのセッションが `openai` のグループに入ります。サードパーティの Key はローカルルーティングが差し替え、ChatGPT のアカウント ID や組織などのリクエストヘッダーは取り除くため、サードパーティにあなたのアカウント情報は渡りません。
  - 次の場合は引き続き `custom` として書き込みます：このパソコンに ChatGPT のログインがない場合、セッション履歴の統一がオンの場合、「公式ログインを一時停止」がオンの場合、またはプロバイダーの設定にリクエストの再試行、ストリームの再試行、ストリームのアイドルタイムアウト、リモート圧縮といった、組み込みの `openai` では表現できない設定がある場合。
  - すでにルーティングモードを使っている場合は操作不要で、CC Switch が次にルーティングに接続するときに自動で 1 回書き直します。直接接続モードは変わりません。
- **直接接続で切り替えた後、閲覧のみになったセッションの件数を表示**：セッション履歴の統一がオフのとき、直接接続モードで公式サブスクリプションとサードパーティを切り替えると、切り替え成功の通知に 1 行加わります。例：「公式サブスクリプションで作成した 12 件のセッションは閲覧のみになりました」。トレイから切り替えたときは表示しません。
- **Codex セッション履歴を統一**（「設定 → アプリ設定 → Codex」）：オンにすると公式サブスクリプションも `custom` 識別子を使い、両方のセッションが同じグループに入るため、新しい Codex でもどちらも続けられます。公式とサードパーティをよく切り替える場合はオンにすることをおすすめします。
  - 「既存の公式セッション履歴も移行する」を既定でチェックするようにしました。チェックすると、以後 CC Switch を起動するたびに、再び公式グループに現れたセッションを移行します。たとえばこのスイッチをオフにしてから再びオンにした場合や、CC Switch を経由せずに Codex を使った場合です。
  - 移行と復元の前には Codex のセッションデータベースをバックアップする必要があります。これまで 42 MB のデータベースのバックアップに約 90 秒かかっていましたが、現在は 1 秒もかかりません。
  - バックグラウンドの移行が終わると、移行したセッションの件数を通知します。Codex を再起動すれば続けられます。

### 公式ログインを一時停止（Codex）

公式の ChatGPT クォータを使い切ると、Codex は自分でクォータを照会し、モデルの選択と送信ボタンをロックします。サードパーティのモデルを選んでも送信できません（[#7974](https://github.com/farion1231/cc-switch/issues/7974)、[#7962](https://github.com/farion1231/cc-switch/issues/7962)）。これは Codex クライアント内の処理で、ローカルルーティングでは対処できません。以前の、`requires_openai_auth` を手動で `false` に書き換える方法は、現在は 1 回切り替えると上書きされます。

現在は Codex の「ルーティング設定」と「集約設定」（ルーティングまたは集約モードが有効なときに、モードタブの右端に表示される歯車ボタン）の一番上に「公式ログインを一時停止」スイッチが加わりました：

- オンにすると Codex は公式ログインを使わなくなるため、公式クォータを理由に送信ボタンをロックしなくなり、集約とルーティングのサードパーティのモデルを引き続き使えます。公式ログインはこのパソコンに保存されたままで、ログアウトはしません。
- オンの間は、公式モデルでは送信できず、サードパーティのモデルに切り替えるよう案内します。Codex にはアカウントと使用量の情報が表示されず、初回起動時に初期設定の質問が表示されることがあります。サイドバーの「プロジェクト」にある既存のセッションは一時的に表示されませんが、スイッチをオフにすると戻ります。新しいセッションは `custom` グループに記録され、公式に戻すと閲覧のみになります。
- オンの間は Codex ページの上部に通知が表示され続けます。公式クォータが回復したら「公式ログインを再開」をクリックしてください。
- オン・オフのあとは、Codex を完全に終了して開き直す必要があります。ルーティングと集約モードでのみ有効で、直接接続には影響しません。

### アプリページにインストールの進捗を表示

アプリページのインストール、アップグレード、アンインストールは一度に 1 つずつ実行されます。これまでは時間がかかると全部の行が回転し続け、ダウンロード中なのか、順番待ちなのか、止まっているのか見分けられませんでした（MiniMax Code のインストールパッケージは約 100 MB で、回線が遅いと十数分かかります）。現在は順番待ちの行に「順番待ち中（前のアプリの完了待ち）」と表示し、実行中の行には経過時間とコマンド出力の最新の 1 行を表示します。アプリページを離れて戻ってきても、進捗は残っています。

## 変更

- **公式クォータ保護を既定でオンにしました**：ローカルルーティングを経由する Codex の公式リクエストは、5 時間の使用率が 95% または週間の使用率が 98% に達した時点で停止します。サードパーティのモデルは引き続き使えるため、Codex が送信ボタンをロックする段階まで進まずに済みます。アップグレード後に自動で 1 回オンにします。その後手動でオフにした場合は、再びオンにはなりません。しきい値は「設定 → アプリ設定 → Codex → 公式クォータ保護」で変更できます。
- **`disable_response_storage` を書き込まないようにしました**（[#7524](https://github.com/farion1231/cc-switch/issues/7524)）：新しい Codex ではこの設定が削除され、起動するたびに認識できない設定項目が 1 つあると表示されていました。プリセット、テンプレート、統一プロバイダー、ワンクリックインポートのリンクのいずれもこれを書き込まなくなり、既存の `config.toml` にあるこの行は次の切り替え時に削除します。
- **Antigravity で Argon の週間クォータを表示**（[#8913](https://github.com/farion1231/cc-switch/pull/8913)）：Pro プランの Argon の週間クォータはこれまで表示されていませんでした。現在はカードでは Gemini の行にまとめ、ドロップダウンメニューと「アカウント」ページでは個別に表示します。
- **Windows での初回起動を高速化**：新しいデータベースを作るときのテーブル作成と組み込みのモデル料金の書き込みをそれぞれ 1 回のコミットにまとめ、初回起動が約 6 秒速くなりました。

## 修正

- **Codex が別のプロバイダーにフェイルオーバーしても前のプロバイダーのモデル名のまま送られ、予備のプロバイダーがモデルが存在しないと返す問題**（[#7547](https://github.com/farion1231/cc-switch/issues/7547)）。現在はフェイルオーバーがオンのとき、予備のプロバイダーに切り替える前に、リクエストのモデルをそのプロバイダーが扱えるか（そのプロバイダー自身のモデルか、モデル一覧にあるか）を確認し、扱えなければそのプロバイダー自身のモデルに置き換えます。同じモデルの中継キューはそのまま送ります。画像生成、画像編集、検索のリクエストではモデルを置き換えません。
- **Codex がルーティング経由で Kimi For Coding に接続すると、コンテキストの圧縮が常に失敗する（HTTP 400）問題**。Kimi は圧縮リクエストの `tool_choice: "none"` を受け付けません。現在はサードパーティのネイティブ Responses 上流が圧縮リクエストを拒否した場合、`tool_choice` を取り除いてもう一度試します。
- **Codex が Kimi または DeepSeek のネイティブ Responses でツール呼び出しを続けた後、そのセッションの以降のターンがすべて 400 になる問題**。ツール呼び出しとその結果の間にアシスタントメッセージが挟まっていると、Kimi も DeepSeek も履歴全体を拒否します。Kimi は空のアシスタントメッセージも拒否します。現在は Kimi（Moonshot）と DeepSeek のアドレスに限ってこうした履歴を整理し、その他のリクエストはそのまま送ります。
- **Windows で Codex のディレクトリが WSL 内（`\\wsl.localhost`）にあると、分岐したセッションの使用量がいつまでもインポートされない問題**。
