# CC Switch v4.0.43

今回のリリースでは、「アカウント」ページに「残量を自動で取得」スイッチを追加しました。オフにすると、公式アカウントの残量は更新をクリックしたときだけ取得します。プロキシ経由でインターネットに接続していて、プロキシの準備が整う前に公式サービスへ直接接続したくない場合に便利です。トレイからも Antigravity の公式アカウントを直接切り替えられるようになり、各アカウントの横に残量を表示します。「アプリ」ページが OpenCode 2 を認識するようになり、更新の確認、アップグレード、アンインストールを正しく行えます。OpenCode 2.4 のセッションでも、アシスタントの返信が表示されるようになりました。使用量統計の速度は成功したリクエストだけで計算し、中継サーバーがバッファリングしてから一度にまとめて返した異常値を除外します。

このほか、Chat Completions のプロバイダーを使った後に直接接続モードで公式 ChatGPT に戻すと Codex のセッションを続けられない問題、macOS で終了するたびにメニューバーのアイコンの位置がリセットされる問題、`~/.gemini/.env` の引用符付きの値の扱い、ブロックコメントを含む OpenClaw の設定が壊れる問題、環境変数を削除すると shell 設定の末尾の改行が失われる問題、Pi のプラグインの認識と更新に関する問題を修正しました。

## 新機能

### 「アカウント」ページの「残量を自動で取得」スイッチ

（[#9325](https://github.com/farion1231/cc-switch/pull/9325)、[#8990](https://github.com/farion1231/cc-switch/issues/8990) を参照）

「アカウント」ページを開いたとき、現在の公式カードの定期更新、トレイにマウスを重ねたときには、いずれも公式サービスにアカウントの残量を自動で問い合わせます。プロキシ経由でインターネットに接続している場合、プロキシの準備が整う前だと、これらのリクエストはプロキシを通らずに直接送られてしまいます。今回、「アカウント」ページ上部の「ログイン時にブラウザを自動で開く」の下に「残量を自動で取得」スイッチを追加しました。デフォルトはオンです。

- **オフにすると**：Claude、ChatGPT（Codex）、xAI、Kimi、Antigravity、GitHub Copilot、WorkBuddy、CodeBuddy などの公式アカウントの残量は、アカウントの行の ↻ か「すべて更新」をクリックしたときだけ取得します。「アカウント」ページを開いたとき、カードの定期更新、トレイへのマウスオーバーでは自動でリクエストを送らなくなります。取得済みの結果はこれまでどおり表示します。
- **まだ取得していないアカウント**：空白にはならず、「更新をクリックして残量を取得」と更新ボタンを表示します。
- **起動時**：設定を読み込むまでは残量を取得しないため、スイッチをオフにしているユーザーが起動した瞬間に 1 回だけリクエストを送ってしまうことはありません。
- **影響を受けないもの**：サードパーティのプロバイダーの残高スクリプトはこれまでどおり更新します。DeepSeek アカウントの残高はログイン状態と一緒に表示され、このスイッチの影響も受けません。

また、「すべて更新」はページ上のすべてのアカウントを更新するようになりました（自動取得をオフにしている場合も同じです）。WorkBuddy と CodeBuddy では、バックグラウンドの 5 分間のキャッシュも使わずに最新の数値を取得します。

### トレイから Antigravity の公式アカウントを切り替え

トレイに Antigravity のセクションを追加しました。「アカウント」ページに保存した Antigravity のアカウントを一覧表示し、各アカウントの横に残量を表示します（Gemini、Claude/GPT、Argon のグループに分け、グループごとに最も残りの少ない枠を表示）。

- チェックが付いているのは、agy に現在ログインしているアカウントです。別のアカウントをクリックすると切り替わり、「アカウント」ページで切り替えたときと同じくシステムのキーチェーンに書き込みます。agy の実行中は、開いているセッションには再起動後に反映されることを表示します。
- 現在のアカウントの残量はトレイと一緒に更新し、ほかのアカウントは最大 5 分に 1 回更新します。それぞれのアカウントのログイン情報を使うため、先に切り替える必要はありません。「アカウント」ページで取得した残量もトレイに反映されます。
- 「アカウントを管理…」で「アカウント」ページを開きます。切り替えに失敗したときも「アカウント」ページを開きます。
- 「アカウント」ページに Antigravity のアカウントが保存されていない場合は、このセクションを表示せず、キーチェーンも読みません。

### 「アプリ」ページで OpenCode 2 に対応

（[#8727](https://github.com/farion1231/cc-switch/pull/8727) の内容を含む）

OpenCode 2 は別の npm パッケージ（`@opencode/cli`、Homebrew では `anomalyco/tap/opencode-v2`）で、1.x の `opencode-ai` と共存します。これまで「アプリ」ページは `opencode-ai` しか認識しなかったため、OpenCode 2 をインストールしたユーザーには次の問題がありました。

- 最新バージョンを 1.x から取得していたため、ローカルの 2.x より低くなり、2.x の更新をいつまでも案内できませんでした。
- アップグレードで `opencode-ai@latest` をインストールしていました。npm では EEXIST エラーで失敗し、Windows の pnpm ではエラーにならないまま、`opencode` がインストールの完了していない 1.x に置き換わり、コマンドがそのまま使えなくなりました。
- アンインストールが npm や `opencode-v2` でインストールしたバージョンを認識せず、インストールスクリプトが作った `opencode2` エイリアスも残っていました。

現在の CC Switch は、実際のインストール場所から 1.x か 2.x かを判断し、更新の確認、アップグレードコマンド、npm のインストールスクリプトの設定、Node のバージョン要件のすべてで対応するパッケージを使います。アンインストールでは所属する npm パッケージを見つけられ（WSL を含む）、`opencode-v2` も認識し、`opencode2` は確かにインストールスクリプトが作ったものである場合にだけ削除します。新規インストールではこれまでどおり 1.x をインストールし、2 つの系統の間で勝手に切り替えることはありません。Volta でインストールしたものは区別できないため、引き続き 1.x として扱います。

## 変更

- **速度統計をより正確に**（[#9952](https://github.com/farion1231/cc-switch/pull/9952)、[#9950](https://github.com/farion1231/cc-switch/issues/9950) をクローズ）：そのまま転送するストリーミングレスポンスでは、プロトコル（Anthropic、OpenAI Responses、OpenAI Chat、Gemini）ごとに本当の最初の出力トークンを識別し、メタデータのイベントを最初のトークンとみなさなくなりました。速度と最初のトークンまでの時間は成功した（2xx）リクエストだけで計算します。10,000 tok/s を超えるものは中継サーバーがバッファリングしてから一度にまとめて返したものとみなして速度に含めず、リクエストの詳細にその理由を表示します。プロバイダー別、モデル別に集計した速度は、引き続き出力トークンの合計を生成時間の合計で割った値です。
- **Claude のセッションログの所要時間を実際にリクエストを送った時点から計算**：リクエストが止まったとき、Claude Code は同じリクエストを再送します。これまでローカルルーティングを使っていない場合、取り込んだ所要時間と最初のトークンまでの時間は、その返信のきっかけになったメッセージから計算していたため、止まっていた時間（十数分になることもよくあります）まで含まれ、推定速度が下がっていました。新しい Claude Code は実際にリクエストを送るたびにその時刻を記録するため、現在はその時点から計算します。古いバージョンのログはこれまでどおりに計算し、取り込み済みの記録は変わりません。
- **使用量統計のアプリの絞り込みをサイドバーと同じ順序に**（[#10006](https://github.com/farion1231/cc-switch/pull/10006)、[#10005](https://github.com/farion1231/cc-switch/issues/10005) をクローズ）：「アプリ」ページでドラッグして変えた順序も反映します。
- **Codex の「公式の Fast ティアを残す」の説明**（[#10000](https://github.com/farion1231/cc-switch/issues/10000) を参照）：カードにモデル一覧がない場合、このスイッチはオンにしても保存されなかったため、現在はロックし、先にモデル一覧に GPT モデルを追加するよう案内します。説明には、Codex のデスクトップ版は ChatGPT にログインしないと Fast を表示しないこと、サードパーティのカードを使うときは設定の「直接切替時に公式ログインを保持」をオンにする（またはルーティングモードを使う）こと、その場合もリクエストはこのカードに送られることも明記しました。CLI 版はログイン不要です（`/fast`）。
- **プラグインページに所属プロジェクトを表示**（[#9963](https://github.com/farion1231/cc-switch/pull/9963)、[#9962](https://github.com/farion1231/cc-switch/issues/9962) をクローズ）：Claude Code の `local` / `project` プラグインは、行の下に所属するプロジェクトのディレクトリを表示し、ディレクトリでも検索できます。複数のプロジェクトにある同名のプラグインを削除した後に、削除できない行が残ることもなくなりました。
- **Linux でシステムのデフォルトのターミナルに対応**（[#9987](https://github.com/farion1231/cc-switch/pull/9987)、[#9986](https://github.com/farion1231/cc-switch/issues/9986) をクローズ）：「ターミナルを開く」で既知のターミナルが見つからない場合に、`x-terminal-emulator` と `xdg-terminal-exec` を順に試すようになりました。優先するターミナルは引き続き最初に試します。
- **Skills ページの Pi 列の説明**（[#9971](https://github.com/farion1231/cc-switch/pull/9971)）：Pi は `~/.agents/skills` も読み込むため、そこにあるスキルはチェックしていなくてもそのまま使える、という説明に変更しました。

## 修正

- **直接接続モードで Codex のセッションを公式 ChatGPT に戻すと続けられない**（[#9054](https://github.com/farion1231/cc-switch/issues/9054) を参照）：先に Chat Completions のプロバイダーを使うと、変換された推論アイテムの ID は `rs_<response id>` になります。上流によっては返信 ID がちょうど 32 桁の 16 進数で、公式バックエンドが検索しにいく ID と同じ形になるため、直接接続モードで公式 ChatGPT に戻すと `Item with id 'rs_resp_...' not found` というエラーになり、セッションを続けられませんでした。現在は ID の末尾に連番を付けるため、公式バックエンドがこの ID を検索することはなくなりました。既存のセッションにすでに含まれているアイテムの ID は変わらないため、それらのセッションは直接接続モードでは引き続きエラーになります。新しいセッションを開始してください。
- **macOS で終了するたびにメニューバーのアイコンの位置がリセットされる**（[#6631](https://github.com/farion1231/cc-switch/pull/6631) を参照）：トレイから終了したとき、メインウィンドウを閉じて終了したとき、再起動したときに、CC Switch はまずトレイアイコンを削除していましたが、macOS はこの削除の際に ⌘ キーを押しながらドラッグして決めた位置を消してしまい、Hidden Bar のようなツールのグループ分けも効かなくなっていました。macOS では自分から削除しないようにしました。プロセスが終了すると、システムが自動でアイコンを片付けます。
- **OpenCode 2.4 のセッションでアシスタントの返信が表示されない**（[#9982](https://github.com/farion1231/cc-switch/issues/9982) を参照）：OpenCode 2.4 はアシスタントの返信の各パートを新しい `session_part` テーブルに保存するようになりましたが、セッション管理はこれまで古いテーブルしか読まなかったため、ご自身の質問しか表示されませんでした。現在は 2 つのテーブルを合わせて読み込み、セッションの検索と削除も新しいテーブルを対象にします。
- **`~/.gemini/.env` の引用符付きの値**（[#9928](https://github.com/farion1231/cc-switch/pull/9928)、[#9926](https://github.com/farion1231/cc-switch/issues/9926) をクローズ）：Gemini CLI の公式ドキュメントでも引用符を使って書かれていますが、これまではインポートすると Key とアドレスに引用符と行末のコメントが付いたままになり、ルーティングもそれをそのまま上流に送っていました。現在は Gemini CLI と同じく取り除きます。
- **OpenClaw の設定にブロックコメントがあると壊れる**（[#10002](https://github.com/farion1231/cc-switch/pull/10002)、[#10001](https://github.com/farion1231/cc-switch/issues/10001) をクローズ）：`openclaw.json` に `/* ... */` があると、CC Switch が書き込むたびに末尾の `/` が失われ、ファイルを読めなくなっていました。
- **競合する環境変数を削除すると shell 設定の末尾の改行が失われる**（[#9929](https://github.com/farion1231/cc-switch/pull/9929)、[#9927](https://github.com/farion1231/cc-switch/issues/9927) をクローズ）：その後ファイルの末尾に 1 行追加すると、最後の行とつながってしまっていました。現在は削除した行以外の内容（CRLF の改行や末尾の改行を含む）をそのまま保持します。
- **Vite+ でインストールした Pi のプラグインを認識できない**（[#9976](https://github.com/farion1231/cc-switch/pull/9976)、[#9960](https://github.com/farion1231/cc-switch/issues/9960) を参照）：デスクトップから起動した CC Switch は shell 設定にある `VP_HOME` などの変数を受け取れず、`pi list` が実際には `vp list` として実行されていました。現在はログイン shell から、Vite+ が使ういくつかのディレクトリ変数を補います。
- **Pi 公式インストーラーでインストールしたバージョンで更新をクリックすると、npm でもう 1 つインストールされる**（[#10015](https://github.com/farion1231/cc-switch/pull/10015)、[#10013](https://github.com/farion1231/cc-switch/issues/10013) をクローズ）：現在は Pi 自身の `pi update` を使います。
- **Antigravity のカードでアカウントの切り替えに失敗したとき、反映されていない紐付けをクラウド同期がアップロードすることがある**（[#9978](https://github.com/farion1231/cc-switch/pull/9978)）：WebDAV / S3 は、アカウントの切り替えが完了するかロールバックされるのを待ってからスナップショットを取るようになりました。
