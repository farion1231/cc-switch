# CC Switch v3.20.4

> 本リリースは修正が中心ですが、新たな統合も 1 つあります：**MiniMax Code が 10 番目の管理対象アプリになりました**。プロバイダ・MCP・Skills・プロンプト・セッションブラウザ・使用量統計をまとめて接続し、既定モデル・ログイン・セッション削除は引き続き MiniMax Code 自身が管理します。修正は主にローカルプロキシ経由で Codex を使う場面に集中しており、Codex を使い続けられなくなる 4 つの問題を本リリースで解消しました：Codex 0.154 以降 `additional_tools` に入れられたツールが厳格な Chat ゲートウェイでそのまま 400 になる問題、`detail: "original"` のスクリーンショット 1 枚でセッション全体がその後毎ターン 400 になる問題、一部の Codex プロバイダで、編集したり別のプロバイダへ切り替えたりすると保存済みの API Key がこっそり消える問題、そして削除済みの ChatGPT アカウントに紐づいたカードが、別のプロバイダへ切り替えることも紐づけを変えることもできない問題です。Claude Code 側では、GitHub Copilot 下の auto mode が再び使えるようになり、`/effort` の `xhigh`・`max` と Grok 4.6 の推論強度がいずれも選んだ段階どおりに送られます。Claude Desktop のサードパーティ設定も Linux に対応しました。**本リリースにはデータベースマイグレーション（v18 → v19）が含まれます。アップグレード前に一度手動でデータベースをバックアップすることをおすすめします**。詳しくは[アップグレード時の注意](#本リリースにはデータベースマイグレーションが含まれます)を参照してください。

## 概要

MiniMax Code は MiniMax のコーディングエージェントで、ターミナル版の `mcode` とデスクトップ版が `~/.minimax` データディレクトリを共有します。CC Switch はこれを OpenCode・Hermes・Pi と同じ加算モードで管理します：各プロバイダは `~/.minimax/config.yaml` の `custom_provider` 配下の 1 項目で、複数のプロバイダが共存し、書き込み時は MiniMax Code 自身のその他の設定を保持して、その設定ファイルロックを守ります。MCP は `~/.minimax/mcp.json` と双方向に同期し、Skills は `~/.minimax/skills/` へデプロイし、プロンプトライブラリは `~/.minimax/AGENTS.md` へ書き込みます。セッションの閲覧は読み取り専用で、使用量は MiniMax Code 自身のデータベースから増分インポートします。統合の範囲は意図的に狭く絞っています：既定モデル・ログイン・クラウド機能・セッション削除はすべて MiniMax Code に任せ、ローカルプロキシの引き継ぎ・フェイルオーバー・トレイ・共通設定スニペット・プロファイル（Profiles）も対象外です。（[#7383](https://github.com/farion1231/cc-switch/pull/7383)、[#7578](https://github.com/farion1231/cc-switch/pull/7578)）

修正のうち最も比重が大きいのは、ローカルプロキシ経由で Codex を使う場面の一群です。Codex 0.154 以降、プラグインや実行名前空間などの追加ツールは 1 つの `additional_tools` 入力項目に入れられますが、変換器はこれをメッセージとして扱い、`content: null` の system メッセージを生成していました。厳格な Chat ゲートウェイはそのまま 400 を返し、中のツールも捨てられていました（[#7454](https://github.com/farion1231/cc-switch/pull/7454)）。Codex はスクリーンショットに `detail: "original"` を付けますが、この値は Responses API でしか有効ではありません。これがそのまま Chat リクエストへ写されると、Ark/Doubao・SenseNova・GLM・vLLM といったゲートウェイはリクエスト全体に 400 を返します。Codex は毎ターン完全な履歴をリプレイするため、画像 1 枚でそのセッションは以後毎ターン失敗していました（[#7476](https://github.com/farion1231/cc-switch/pull/7476)）。残る 2 件はアカウントデータの問題です：自前の認証情報ソースを持つ Codex プロバイダを編集して保存するか、別のプロバイダへ切り替えると、保存済みの API Key が live の空の auth で上書きされていました（[#7434](https://github.com/farion1231/cc-switch/pull/7434)）。認証センターで ChatGPT アカウントを削除して再ログインすると、旧アカウントに紐づいたカードは切り替え・引き継ぎ・起動時の復元のたびに「账号不存在」（アカウントが存在しません）を報告していました（[#7395](https://github.com/farion1231/cc-switch/pull/7395)）。

Claude Code の変換済みリクエストにもいくつか修正があります：説明のないツールは `"description": null` として送られなくなりました（[#7319](https://github.com/farion1231/cc-switch/pull/7319)、[#7378](https://github.com/farion1231/cc-switch/pull/7378)）。GitHub Copilot 下で auto mode の分類器が `stop` パラメータのせいで 400 になることはなくなりました（[#5404](https://github.com/farion1231/cc-switch/pull/5404)）。`/effort xhigh` は捨てられなくなり、Grok 4.6 へマッピングされたモデルには再び推論強度が送られるようになり、GPT-5.6 と GPT-6 Astra の `max` は `xhigh` へ下げられなくなりました（[#7318](https://github.com/farion1231/cc-switch/pull/7318)、[#7531](https://github.com/farion1231/cc-switch/pull/7531)）。その他の修正は、Skills のインストール（skills.sh の id とディレクトリ名の不一致、10,000 を超えるファイルを持つリポジトリ、[#6381](https://github.com/farion1231/cc-switch/pull/6381)、[#7489](https://github.com/farion1231/cc-switch/pull/7489)）、プロンプトへの外部変更の読み戻し（[#7194](https://github.com/farion1231/cc-switch/pull/7194)）、WSL 上の OMO 統一設定（[#7550](https://github.com/farion1231/cc-switch/pull/7550)）、バージョン情報ページのバージョン検出（[#7346](https://github.com/farion1231/cc-switch/pull/7346)、[#7348](https://github.com/farion1231/cc-switch/pull/7348)）、Windows のタスクバー（[#6348](https://github.com/farion1231/cc-switch/pull/6348)）に及びます。新機能としては、Claude Desktop のサードパーティ設定が Linux に対応し（[#7331](https://github.com/farion1231/cc-switch/pull/7331)）、リクエストログに毎秒の出力トークン数が表示され（[#3369](https://github.com/farion1231/cc-switch/pull/3369)）、OpenCode のプロバイダフォームで取得したモデルを検索して一括追加できるようになりました（[#7515](https://github.com/farion1231/cc-switch/pull/7515)）。

プリセットは一巡メンテナンスしました：国内ベンダーの Codex プリセットを各社の Responses ドキュメントに合わせ（Kimi For Coding は K2.8 Preview・1M ウィンドウへ、DeepSeek の既定は `deepseek-flash` へ）、MiniMax 国内サイトと BaiLing は現在の公式ドメインへ移行し、AICodeWith の Codex 系エンドポイントを `/v1` へ訂正し、ほかにいくつかのプリセットを追加しました。DeepSeek は 2026-09-12 に V4 Pro を V4.1 Flash の価格で課金するという発表を撤回したため、v3.20.3 で前倒し実施した価格改定を本リリースで取り消し、ピーク段階の料金へ戻しました。本リリースにはデータベースマイグレーションが含まれます：`SCHEMA_VERSION` 18 → 19 で、MCP と Skills のテーブルに MiniMax Code の有効化列を追加します。

## 新機能

### MiniMax Code が 10 番目の管理対象アプリに

MiniMax Code（`app_type` は `mcode`）のターミナル版とデスクトップ版は 1 つのデータディレクトリを共有します。既定は `~/.minimax` で、`MINIMAX_DATA_DIR`（または旧来の `MAVIS_DATA_DIR`）で別の場所へ変えられます。（[#7383](https://github.com/farion1231/cc-switch/pull/7383)、[#7578](https://github.com/farion1231/cc-switch/pull/7578)）

- **プロバイダ**：OpenCode・Hermes・Pi と同じ加算モードです。各プロバイダは `~/.minimax/config.yaml` の `custom_provider` 配下の 1 項目で、カードが「追加済み」かどうかはファイルにそのキーがあるかどうかだけで決まります。フォームは OpenCode 風の構造化エディタを踏襲し、JSON エディタも備え、`anthropic-messages`・`openai-completions`・`openai-responses` の 3 つの API 形式に対応します。プリセットは Pi のプリセットカタログから派生し、リリース時点で計 41 個です。MiniMax Code で新規作成したカスタムプロバイダは一覧の読み込み時にインポートされ、MiniMax Code 側で行った変更も同期して戻ってきます。アカウント型のプロバイダ（`kind` が `custom` でないもの）はインポートも上書きもしません。書き込み時は `config.yaml` のほかのキーをすべて保持し、MiniMax Code 自身の `config.yaml.lock` ディレクトリロックを守ります（10 秒を超えたロックは回収され、そうでなければ保存は失敗して再試行を促します）。ネイティブファイルへの書き込みが失敗した場合はデータベースの変更をロールバックします。`config.yaml` から特定のプロバイダを削除すると、そのカードはすぐに未追加の状態へ更新され、再び追加できます（[#7578](https://github.com/farion1231/cc-switch/pull/7578)）。
- **既定モデルは MiniMax Code が管理します**：CC Switch は `defaultModel` / `defaultLightModel` を決して書き込みません。あるプロバイダやモデルがこの 2 つの項目から参照されている間、CC Switch はその削除や無効化を拒否するため、先に MiniMax Code で既定モデルを別のものに変える必要があります。
- **MCP**：`~/.minimax/mcp.json` と双方向に同期します。編集はトランスポートのフィールド（`command`、`args`、`env`、`url`、`headers`、`type`）だけを置き換え、`timeout` のようなネイティブのオプションは保持します。id が同じでもトランスポート方式が異なるサーバーはスキップして通知し、上書きしません。全量の再同期はスイッチがオフのエントリを削除せず、明示的な無効化または削除のときだけ取り除きます。データベースのコミットが失敗した場合はネイティブファイルを元に戻します。
- **Skills とプロンプト**：Skills は `~/.minimax/skills/` へデプロイされ、Pi の所有権チェックを踏襲し、同名でも CC Switch がデプロイしたものでない Skill には一切触れません。プロンプトライブラリは有効なプロンプトを `~/.minimax/AGENTS.md` へ書き込みます：切り替え前に、ファイルへの外部変更をまず現在のプロンプトへ書き戻します。MiniMax Code のプロンプトをまだ 1 つも有効にしていないときは、ファイル内の一致しない内容を先にバックアップのプロンプトとして保存します。最後のプロンプトを無効にするとファイルを空にします。プロンプト 1 つあたりの上限は 32 KiB（UTF-8 のバイト数で計算）です。
- **Deep link**：MCP の deep link の `apps` は `mcode` に対応します。MiniMax Code のプロバイダ deep link は拒否されます。
- **本リリースの対象外**：MiniMax Code のネイティブログインとクラウド機能、ローカルプロキシの引き継ぎとフェイルオーバー、トレイの入口、共通設定スニペット、ユニバーサルプロバイダ、プロファイル（MiniMax Code のページではプロジェクト切り替えを非表示）、カード単位のプロバイダチェック、設定でのディレクトリ上書き、そして「設定 → バージョン情報」からのインストールやアップグレード。

### MiniMax Code のセッションと使用量がダッシュボードに

セッションブラウザは `~/.minimax/v2/sqlite/runtime-state.sqlite` を読み取り専用で開き、MiniMax Code の会話を一覧表示します（非表示・アーカイブ済み・サブセッション、および peek/channel/cron セッションは表示しません）。各セッションには resume コマンド `env MINIMAX_DATA_DIR=<dir> mcode --session <id>`（Windows では PowerShell の書き方）が用意されます。セッションは MiniMax Code の実行状態と結びついているため、画面上からは削除できず、バックエンドも削除を拒否します。

使用量は同じデータベースの `local_runtime_token_usage` テーブルから増分インポートされ、ソースは「MiniMax Code (Session)」で、ダッシュボードには独立したアプリフィルタがあります。推論トークンは出力に計上されます。モデル id は最初の `/` 以降の部分を取ります（`custom_provider:router/vendor/model` は `vendor/model` として記録）。MiniMax Code 自身が算出した `cost_usd` が有限の非負数であればそのまま採用し、欠落・負数・非有限値の場合は CC Switch の価格表で計算し直します。ネイティブのコストがちょうど $0 の行は $0 として記録されますが、トークンを持つほかの $0 行と同じく、そのモデルに価格表で価格が付いた時点で、共有の料金補填によって価格が付け直されます。Pi と同様に、MiniMax Code を含む合計には「キャッシュ書き込みが不完全」の注記が付きます。（[#7383](https://github.com/farion1231/cc-switch/pull/7383)）

### Claude Desktop のサードパーティ設定が Linux に対応

これまで Linux で Claude Desktop のサードパーティ設定を書き込むと、プラットフォーム未対応のエラーになっていました。いまでは Linux も macOS・Windows と同じファイル構成を使います：設定のルートディレクトリは `$XDG_CONFIG_HOME`（絶対パスである必要があります）で、未設定なら `~/.config` です。CC Switch はその下の `Claude/` と `Claude-3p/` の 2 つのディレクトリにある設定ファイルを管理します。CC Switch が Flatpak で動作しているとき（`/.flatpak-info` で識別）は、サンドボックス固有の `XDG_CONFIG_HOME` ではなく、常にホストの `~/.config` へ書き込みます。お使いの Claude Desktop が独自の XDG ディレクトリを使っている場合は、ネイティブのインストールパッケージを使ってください。同梱の Flatpak マニフェストはすでにホームディレクトリへのアクセス権を付与しています。macOS と Windows のパスは変わりません。マニュアル（zh/en/ja）には Linux のパスとサポート範囲の表を追加しました。（[#7331](https://github.com/farion1231/cc-switch/pull/7331)、[#4855](https://github.com/farion1231/cc-switch/issues/4855) を修正）

### リクエストログに毎秒の出力トークン数を表示

リクエストログの表では出力トークンの横に生成速度（例：`1,234/56 tps`）を表示し、リクエスト詳細パネルでは出力トークンの後ろに括弧書きで表示します。ストリーミングリクエストで最初のトークンの時刻が記録されている場合、速度 = 出力トークン ÷（総レイテンシ − 最初のトークンまでの時間）で、最初のトークン以降の生成だけを計算します。非ストリーミングリクエストは総レイテンシを使うため、最初のトークンを待つ時間も含まれます。速度が 1 以上なら整数に丸め、1 未満なら小数第 1 位まで残します。出力トークンがない行や有効な時間幅がない行には表示されず、Claude Code・Codex・Gemini のセッションログからインポートした行もレイテンシのデータを持たないためこれに当たります。速度は表示時に保存済みのフィールドから計算するため、スキーマやログの変更は伴いません。（[#3369](https://github.com/farion1231/cc-switch/pull/3369)、[#5936](https://github.com/farion1231/cc-switch/issues/5936) を修正）

### OpenCode のプロバイダフォーム：モデルを検索して一括追加

「モデル一覧を取得」を押すと、フォームの上部に検索可能な複数選択リストが現れます：モデル ID または所有者で絞り込み、欲しいモデルにチェックを入れ（検索語を変えてもチェックは保持されます）、「選択したモデルを追加（N件）」を押せば一度に追加でき、モデル ID は設定キーと初期表示名の両方に使われます。設定済みのモデルはチェック済み・選択不可で「追加済み」と表示され、既存エントリの名前・制限・オプションは変わりません。Base URL または API Key を変更すると候補リストはクリアされ、前のエンドポイントから遅れて届いた応答は破棄されます。検索ボックスで Enter を押してもフォームは送信されません。各行の既存のドロップダウン選択はそのまま残ります。OpenCode のフィールドを流用する MiniMax Code のプロバイダフォームにも同じセレクタがあります。（[#7515](https://github.com/farion1231/cc-switch/pull/7515)、[#7423](https://github.com/farion1231/cc-switch/issues/7423) を修正）

## 修正

### Codex 0.154 以降の `additional_tools` を含むリクエストが Chat ゲートウェイで 400 にならなくなりました

Codex 0.154 以降、リクエストの追加ツール（`functions` / `collaboration` 実行名前空間、プラグイン）は 1 つの `additional_tools` 入力項目に置かれます：`{"type":"additional_tools","role":"developer","tools":[…]}` で、`role` はあるものの `content` はありません。Codex の Responses→Chat 変換器は `role` を持つ項目をすべてメッセージとして扱い、`messages[1]` に `{"role":"system","content":null}` を生成していました。厳格な Chat ゲートウェイは `messages[1]: missing field "content"` を報告してリクエスト全体を拒否し、これらのツールは Chat と Anthropic の両方の変換経路でもこっそり捨てられていました。いまではメッセージの走査がこのキャリアを読み飛ばし、中のツールはトップレベルの `tools` と重複を除いて統合されます（同名の場合はトップレベルの宣言が優先）。名前空間は展開され（`functions` 配下の `exec_command` は `functions__exec_command` になります）、レスポンス側で名前を Codex が認識する形へ戻します。キャリアを持たないリクエストの変換結果は、以前と 1 バイトも変わりません。（[#7454](https://github.com/farion1231/cc-switch/pull/7454)、[#7451](https://github.com/farion1231/cc-switch/issues/7451)・[#6158](https://github.com/farion1231/cc-switch/issues/6158) を修正）

### `detail: "original"` の画像 1 枚で Codex のセッションが永久に失敗しなくなりました

モデルの Codex カタログエントリが `supports_image_detail_original` を宣言していると、Codex はツールが返した画像（例：`view_image` のスクリーンショット）に `detail: "original"` を付けますが、この値は Responses API でしか有効ではありません。Chat 上流へ変換するとき、これがそのまま `image_url.detail` へ写され、厳格な OpenAI 互換ゲートウェイ（Ark/Doubao・SenseNova・GLM・vLLM など）はリクエスト全体に 400 を返していました。Codex は毎ターン完全な履歴をリプレイするため、画像 1 枚でそのセッションは以後毎ターン失敗し、テキストだけのターンも例外ではありませんでした。

修正は 2 層です：プロキシは Chat の画像で `original` を `auto` へ下げ（`auto`・`low`・`high` はそのまま保持）、これによって、すでに壊れたセッションも、履歴を自分で修正しない Codex 0.155.0 より前のバージョンも、アップグレード後すぐに回復します。Chat 変換向けに生成する Codex カタログには常に `supports_image_detail_original: false` を書き込み、発生源で Codex に `original` を送らせないようにします。会話に直接貼り付けた画像はこれまで一度も影響を受けていません。（[#7476](https://github.com/farion1231/cc-switch/pull/7476)、[#6495](https://github.com/farion1231/cc-switch/issues/6495)・[#7458](https://github.com/farion1231/cc-switch/issues/7458) を修正）

### Codex プロバイダを編集しても、別のプロバイダへ切り替えても、保存済みの API Key が消えなくなりました

一部の Codex プロバイダは `[model_providers.*]` テーブルに自前の認証情報ソース（`env_key`、`auth` / `aws` テーブル、または `http_headers` 内の `Authorization`）を持ちます。この種のプロバイダは `config.toml` へトークンを注入しない一方、既定モードではサードパーティへ切り替えるたびに共有の `~/.codex/auth.json` を削除するため、live スナップショットの auth は常に空で、データベースの `OPENAI_API_KEY` がキーの唯一のコピーになります。2 つの経路がこの空の auth を正しい値として扱っていました：現在のプロバイダの編集ダイアログは live スナップショットでフォームを埋め、別のプロバイダへ切り替える際のバックフィルは live スナップショットをデータベースへ書き戻していました。その結果、エディタを開いてそのまま保存するか、単に別のプロバイダへ切り替えるだけで、キーはこっそり消えていました。さらに使用量スクリプトのダイアログはこのキーのないカードを公式サブスクリプションとみなし、保存済みのスクリプトをリセットしていました。

いまでは両方の箇所で「認証情報のない live auth」（`auth.json` が存在しない、または `auth_mode` のログアウトマーカーしか残っていない）をフィールドの欠落として扱います：保存済みの auth を保持しつつ、live の `config.toml` は通常どおり取り込みます。live auth に実際の認証情報がある場合は引き続きそれが優先され、`~/.codex/auth.json` を手動で変更した場合もこれまでどおり有効です。（[#7434](https://github.com/farion1231/cc-switch/pull/7434)、[#7433](https://github.com/farion1231/cc-switch/issues/7433) を修正）

### ChatGPT アカウントを削除した後、それに紐づいた Codex カードを紐づけ直したり、別のプロバイダへ切り替えたりできます

認証センターで管理対象の ChatGPT アカウントを削除して再ログインすると、同じ ChatGPT ユーザーとワークスペースであっても、新しいローカルアカウント id が生成されます。旧 id に紐づいたままの Codex カードは、その後ルーティングの切り替え・引き継ぎのオン/オフ・起動時の復元・紐づけ直しのたびに `账号不存在: <id>` を報告し、ユーザーはプロバイダを変えることも、このカードで新しいアカウントを選ぶこともできませんでした。

いまではこのカードから切り替える際に、「アカウントが削除された」場合と「アカウントは存在するが、live に対応するトークンがないだけ」の場合を区別します：削除されたアカウントは cc-switch の所有マーカーだけを解放し、`~/.codex/auth.json` には触れません。こうすることで、後からネイティブの Codex CLI でログインした同じユーザーが、cc-switch 管理のログインとして削除されることはありません。永続化された `codex_oauth_auth.json` の検証が通ったときだけ、アカウントは削除済みと判断します。ファイルが読めない・形式が不正・アカウントが実はまだディスク上にある場合は、切り替えを中止して live ファイルを変えず、推測はしません。カード自身の紐づけが無効になったときは、プロバイダカードで「アカウントを選択」を押して紐づけ直すようエラーで案内します。自動では紐づけ直しません。（[#7395](https://github.com/farion1231/cc-switch/pull/7395)、[#7392](https://github.com/farion1231/cc-switch/issues/7392) を修正）

### 説明のないツールが `null` として送られなくなりました

Claude→OpenAI Chat と Claude→Responses の変換器は各ツールの `description` をそのままリクエストへ写すため、説明のないツールは `"description": null` になり、厳格な OpenAI 互換上流は 400 `expected string, received null` でそのターン全体を拒否していました。Anthropic のホスト型ツール（`web_search` など）は定義上説明を持たず、説明を書いていないカスタムツールや MCP ツールでも発生し、壊れるのはそのツールだけでなくリクエスト全体でした。いまでは欠落または明示的に `null` の説明は単に省略し、その他の値はそのままパススルーします。フィールドは引き続き `name` → `description` → `parameters` の順で書き込まれ、説明を持つツールのシリアライズ結果は以前と 1 バイトも変わらないため、prompt cache には影響しません。Codex の Responses→Chat 変換器にも関数ツールで同じ問題があり、あわせて修正しました（[#7378](https://github.com/farion1231/cc-switch/pull/7378)）。（[#7319](https://github.com/farion1231/cc-switch/pull/7319)、[#7303](https://github.com/farion1231/cc-switch/issues/7303) を修正）

### Claude Code の auto mode が GitHub Copilot 経由で使えるように

Claude Code の auto mode の分類器は、安全チェックのたびに `stop_sequences` を送ります。GitHub Copilot を経由するとき、Anthropic→OpenAI Chat 変換はこれを `stop` へマッピングしますが、Copilot が Claude モデル向けに提供する Chat Completions ルートはこのパラメータに 400 を返すため、分類器は毎回失敗する一方で、通常の会話は正常に動いていました。いまではプロバイダが GitHub Copilot のときだけ変換で生じた `stop` を取り除き、その他の OpenAI 互換上流（OpenRouter など）では従来どおり残します。（[#5404](https://github.com/farion1231/cc-switch/pull/5404)、[#5175](https://github.com/farion1231/cc-switch/issues/5175) を修正）

### `/effort` の段階が OpenAI と Grok の上流へそのまま届きます

Claude Code の推論強度を OpenAI 形式（Chat の `reasoning_effort`、Responses の `reasoning.effort`）へ変換する際に 3 つの穴があり、いずれも塞ぎました：

- `/effort xhigh` は `output_config.effort: "xhigh"` を送りますが、パーサーはこの値を認識しませんでした。さらに明示的な `output_config.effort` は `thinking` へのフォールバックを遮るため、結果としてどの段階も送られていませんでした。いまでは `xhigh` が 1 対 1 で対応します。
- 推論対応モデルのリストには `grok-4.5` 系列と `grok-build-*` しかなく、`grok-4.6` / `grok-4.6-build` へマッピングされた Claude モデルは `max` を含むすべての段階を失っていました。いまではリストに `grok-4.6` と `grok-4.6-*` が加わりました。
- 明示的な `max` は常に `xhigh` へ下げられていました。いまでは独立した max 段階を持つ `gpt-5.6`・`gpt-5.6-sol`・`gpt-5.6-terra`・`gpt-5.6-luna`・`gpt-6-astra` には `max` をそのまま送り、その他のモデルは引き続き `xhigh` へフォールバックします。

`low`・`medium`・`high` のリクエストは変わりません。（[#7318](https://github.com/farion1231/cc-switch/pull/7318)・[#7531](https://github.com/farion1231/cc-switch/pull/7531)、[#7314](https://github.com/farion1231/cc-switch/issues/7314)・[#6197](https://github.com/farion1231/cc-switch/issues/6197)・[#3389](https://github.com/farion1231/cc-switch/issues/3389)・[#5367](https://github.com/farion1231/cc-switch/issues/5367) を修正）

v3.20.3 は DeepSeek の「2026-09-14 から V4 Pro を V4.1 Flash へルーティングする」という発表に基づき、`deepseek-v4-pro` を前倒しで Flash 段階の価格（100 万トークンあたり $0.30 / $1.20、キャッシュ読み取り $0.006）に変えていました。DeepSeek は 2026-09-12 にこの発表を撤回し、V4 Pro は従来どおり元の価格で課金されているため、V4 Pro のリクエストは実際の費用よりずっと低く計算され続けていました。本リリースは料金を 100 万トークンあたり入力 $1.32・出力 $3.96・キャッシュ読み取り $0.044（ピーク段階、つまり CNY 9 / 27 / 0.3）に戻します。修正は 4 つの価格列がまだ v3.20.3 の書き込んだ値（0.3 / 1.2 / 0.006 / 0）のままの行だけを書き換え、カスタマイズ済みの行には触れません。`deepseek-v4-flash`・`deepseek-flash` など Flash 系列の id は引き続き V4.1 Flash 段階で計算します。

### プロンプト一覧が live ファイルへの外部変更を読み戻します

CC Switch の外でグローバルの `CLAUDE.md`・`AGENTS.md` やその他のアプリの live プロンプトファイルを変更しても、プロンプト一覧は再起動するまでデータベースの古い内容を表示し続けていました。いまではプロンプト一覧の読み込み時に live ファイルを読み戻し、内容が異なれば現在有効なプロンプトを更新します。ウィンドウが再びフォーカスを得たときも、開いているプロンプトパネルが更新されます（編集・確認・書き込みの最中は待機します）。更新するのは有効なプロンプトだけで、ほかのテンプレートには触れません。ファイルが存在しない・読めない・空・空白のみの場合は保存済みの内容を保持します。同期や復元の実行中は更新をスキップします。Pi は引き続き独自の `AGENTS.md` ベースの有効化の仕組みを使っており、対象外です。（[#7194](https://github.com/farion1231/cc-switch/pull/7194)）

### Skills のインストール：id とディレクトリ名の不一致、ファイル数の多すぎるリポジトリ

- skills.sh はスキルの `skillId` をディレクトリ名として渡してきますが、id がリポジトリ内のディレクトリ名と一致するとは限りません。例えば `tencent/WeChatReading` は `skills/SKILL.md` で `name: weread-skills` を公開しているため、インストールに失敗していました。仮にインストールできても、更新チェックはディレクトリ名でしか照合しないため、そのスキルを見つけられませんでした。いまでは検索時にまず明示的なパスと同名ディレクトリを試し、次にメタデータの `name` が id と同じ `SKILL.md` を受け入れます（一意である必要があり、同じ名前を宣言するディレクトリが複数ある場合は、適当に 1 つを選ばずにインストールを拒否します）。更新チェックは保存済みのソースパスを優先するため、スキルがリポジトリ内で移動や改名をしても更新を続けられます。（[#6381](https://github.com/farion1231/cc-switch/pull/6381)、[#6365](https://github.com/farion1231/cc-switch/issues/6365) を修正）
- スキルのインストールは GitHub リポジトリ全体のアーカイブをダウンロードするため、`hugohe3/ppt-master` のように 13,248 エントリを持つリポジトリは 10,000 エントリの上限に当たり、`ARCHIVE_TOO_MANY_ENTRIES` を報告していました。リモートアーカイブ・ローカル ZIP インストール・WebDAV 復元のエントリ上限をすべて 30,000 へ引き上げました。実際の制限は引き続き 512 MiB の展開予算です。（[#7489](https://github.com/farion1231/cc-switch/pull/7489)、[#7475](https://github.com/farion1231/cc-switch/issues/7475) を修正）

### WSL 上の OpenCode ディレクトリでも OMO の統一設定を見つけられます

OpenCode の設定ディレクトリが WSL を指している（`\\wsl.localhost\<distro>\home\<user>\.config\opencode` または `\\wsl$\…`）とき、OMO 4.19.3 以降は統一設定を WSL 側のホームディレクトリ（`~/.omo/omo.jsonc` または `omo.json`）に置きます。CC Switch は Windows のホームディレクトリしか探さず、見つからないと OMO がもう読まない旧プラグインファイル（`oh-my-opencode.jsonc`）へ黙ってフォールバックしていたため、切り替えは成功したように見えて、実際には効いていませんでした。いまでは OpenCode ディレクトリの WSL パスから WSL のホームディレクトリを導き出し、読み取り・書き込み・削除のいずれもまずそこを確認します。どちらにも統一設定がないときは、引き続き旧ファイルへフォールバックします。（[#7550](https://github.com/farion1231/cc-switch/pull/7550)、[#7363](https://github.com/farion1231/cc-switch/issues/7363) を修正）

### Windows のメインウィンドウを別の入口から開いてもタスクバーボタンが残ります

サイレント起動やトレイへ閉じた後、Windows のメインウィンドウは `skip_taskbar(true)` で隠されますが、`show()` の前にこのフラグをリセットするのはトレイの「メインウィンドウを開く」だけでした。別の入口からウィンドウを呼び戻すとタスクバーボタンがなく、一度最小化すると完全に見つけられなくなっていました。いまではこれらの入口がいずれも先に `set_skip_taskbar(false)` を呼びます：起動中にショートカットやスタートメニューから再度起動したとき、メインウィンドウへフォーカスする `ccswitch://` deep link、URL オープンイベント、そしてバージョン不一致時に表示されるデータベース復元画面です。（[#6348](https://github.com/farion1231/cc-switch/pull/6348)）

### 「AI署名を非表示」が Claude Code のセッションリンクも隠します

Claude Code がウェブ版と Remote Control のセッション向けに作るコミットと PR には claude.ai のセッションリンクが付きます。これは独立した `attribution.sessionUrl` で制御されるため、`commit` と `pr` を空にするだけではもう署名をすべて隠せません。Claude エディタの「AI署名を非表示」トグルはいま `attribution: {commit: "", pr: "", sessionUrl: false}` を書き込み、3 項目すべてを満たしたときだけチェック済みと表示されます。チェックを外すと、引き続き `attribution` オブジェクト全体を削除します。（[#7053](https://github.com/farion1231/cc-switch/pull/7053)）

### バージョン情報ページのバージョン検出：npm メタデータ全体をダウンロードせず、Ubuntu のバージョンをツールのバージョンと取り違えません

- npm で配布されるツールの最新バージョンを照会する際、これまでは完全な npm packument（Codex・OpenCode・OpenClaw のようにリリースの頻繁なパッケージでは展開後 14–25 MB）をダウンロードしていました。その中の `dist-tags` を読むためだけにです。しかもこれは 15 秒のタイムアウトを設定していない唯一の検出で、共有クライアントの 600 秒へフォールバックしていたため、遅いネットワークではカードが「読み込み中」のまま数分間止まっていました。いまでは専用の `/-/package/{package}/dist-tags` エンドポイント（レスポンスは数十バイトから数 KB）を使い、15 秒のタイムアウトを設定します。タイムアウト・ネットワークエラー・404 の場合は「不明」と表示します。（[#7346](https://github.com/farion1231/cc-switch/pull/7346)、[#7339](https://github.com/farion1231/cc-switch/issues/7339) を修正）
- Windows で WSL 内のツールを検出する際は、ログインの対話シェルで `<tool> --version` を実行し、stdout の最初の `x.y.z` を取っていました。Ubuntu は毎日最初のログイン時に MOTD（「Welcome to Ubuntu 24.04.4 LTS …」）を出力するため、Claude Code カードが `24.04.4` と表示されていました。いまではツールを実行する前に番兵文字列を出力し、最後の番兵より後の出力だけを解析します。（[#7348](https://github.com/farion1231/cc-switch/pull/7348)、[#7347](https://github.com/farion1231/cc-switch/issues/7347) を修正）

### Zhipu の Responses エンドポイントでモデル一覧を取得できるように

Zhipu の OpenAI Responses エンドポイント（`https://open.bigmodel.cn/api/v1`、Zhipu GLM の Codex プリセットの Base URL）が返す `/models` は、OpenAI / Anthropic の `data[].id` ではなく Codex のリモートカタログ形式（`models[].slug`）のため、Codex のプロバイダフォームでモデルを取得すると常に空でした。いまでは `data` フィールドがないときに `models[].slug` の読み取りへフォールバックし、`data` があるときの挙動は変わりません。（[#7330](https://github.com/farion1231/cc-switch/pull/7330)）

### AICodeWith の Codex 系エンドポイントを `/v1` に変更

AICodeWith の Responses エンドポイントは `https://api.aicodewith.ai/v1` で、ベンダーのブログに書かれた `/chatgpt/v1` はドキュメントの誤りです（ベンダーに確認済み）。Codex プリセットと、同じエンドポイントを流用する Hermes・OpenClaw・Pi のプリセットを `/v1` に変更しました。既存のカードは手動での変更が必要です。アップグレード時の注意を参照してください。

### Claude Desktop が DeepSeek V4 のルートで 1M コンテキストを提供します

DeepSeek V4 ファミリーは 1M コンテキストですが、これらのモデルに固定された Claude Desktop プリセットは `supports1m` を有効にしていなかったため、Claude Desktop のモデル一覧に 1M の選択肢が現れませんでした。DeepSeek（Sonnet / Opus は `deepseek-v4-pro`、Haiku は `deepseek-v4-flash`）、OpenCode Go（`deepseek-v4-flash`）、Baidu Qianfan Token Plan（`deepseek-v4-pro`）のプリセットはいずれも 1M を宣言するようになりました。`[1m]` サフィックスは Claude Desktop のローカルでのみ作用し、プロバイダへ送る内容は変わりません。

### アプリを切り替えるとプロバイダ一覧が先頭へ戻ります

プロバイダビューはアプリの切り替え時にスクロールコンテナを再利用し、中のアニメーションリストだけを差し替えていたため、前のアプリのスクロール位置が持ち越されていました：一番下までスクロールした長い一覧から切り替えると、次のアプリが空白のページのように見えることがありました。いまではアプリを切り替えると、ページのメインコンテナとプロバイダ一覧のコンテナの両方が描画前に左上へ戻ります。（[#5211](https://github.com/farion1231/cc-switch/pull/5211)）

### UI の細部

- **古くなった使用量の段階を表示しなくなりました**：使用量スクリプトをオフにするか公式サブスクリプションのテンプレートへ切り替えた後、プロバイダカードに古いスクリプト結果の複数段階の展開ボタンは表示されなくなりました。公式プロバイダのカードも同様です。
- **単色のプリセットアイコン**：プリセットセレクタの単色アイコンは前景色を使うようになり、フォームのプレビューやプロバイダカードと揃いました（9527CODE などのアイコンはこれまでやや灰色がかって見えていました）。
- **Pi のプロバイダアイコン**：アイコンを設定していない Pi のプロバイダが Pi のアプリロゴとして保存されることはなくなり、カードには名前の頭文字が表示されます。ほかのアプリのカスタムプロバイダと同じです。（[#6826](https://github.com/farion1231/cc-switch/pull/6826)）
- **繁体字中国語の用語**：Pi フォームの重複キーの注意は、フィールドラベルと一致する「供應商識別碼」を使うようになりました。（[#7187](https://github.com/farion1231/cc-switch/pull/7187)）

## アップグレード時の注意

### 本リリースにはデータベースマイグレーションが含まれます

`SCHEMA_VERSION` 18 → 19：`mcp_servers` と `skills` テーブルにそれぞれ `enabled_mcode` 列を 1 つ追加し、既定はオフです。マイグレーションは初回起動時に自動で実行されます。CC Switch はまずデータベースのバックアップを試み、バックアップは `~/.cc-switch/backups/`（ファイル名は `db_backup_` で始まります）に置かれます。ただし、バックアップに失敗してもログに記録するだけで、アップグレードは中止されません。本リリースを一度実行すると、v3.20.3 以前のバージョンは「データベースのバージョンが新しすぎます」としてデータベースを開くことを拒否し、ダウングレードするにはアップグレード前のバックアップを復元するしかありません。念のため、アップグレード前に CC Switch を終了し、手動でコピーを 1 つ取っておいてください：

```bash
cp ~/.cc-switch/cc-switch.db ~/cc-switch-before-v3.20.4.db
```

Windows では既定で `%USERPROFILE%\.cc-switch\cc-switch.db` にあります。設定で設定ディレクトリを変更している場合、データベースと `backups/` はどちらもそのディレクトリにあります。

### アプリ切り替えバーに MiniMax Code が既定で表示されます

本リリースより前の設定を持つインストールでも表示されます。使わない場合は「設定 → ホームページ表示」でオフにできます。

### 既存の MiniMax Code のデータは自動で取り込まれます

- `~/.minimax/config.yaml` にある既存のカスタムプロバイダは、MiniMax Code のページを初めて開いたときにインポートされます。
- `~/.minimax/AGENTS.md` は、すべてのアプリのプロンプトライブラリがまだ空で（実質的には新規インストール）、かつファイルが 32 KiB 以下のときにだけ、起動時にインポートされます。Claude や Codex などのプロンプトをすでに持つアップグレードユーザーには自動インポートされません。MiniMax Code のプロンプトを初めて有効にするとき、ファイルの内容はまずバックアップのプロンプトとして保存されるため、失われることはありません。
- 最初の使用量同期は `local_runtime_token_usage` の全履歴をインポートするため、ダッシュボードの MiniMax Code の合計にはすぐに過去の使用量が含まれます。
- 既存の MCP サーバーと Skills は MiniMax Code に対して既定でオフで、手動でオンにするまで CC Switch は `~/.minimax` へ何も書き込みません。

### MiniMax Code のデータディレクトリは環境変数だけで決まります

CC Switch は自身の環境変数から `MINIMAX_DATA_DIR`、`MAVIS_DATA_DIR` の順に読み取り、どちらもなければ `~/.minimax` を使います。設定にディレクトリ上書きの項目はありません。MiniMax Code がカスタムディレクトリを使っている場合は、CC Switch を起動するときにも同じ環境変数を付けてください。

### 既定モデルは MiniMax Code で変更してください

`defaultModel` / `defaultLightModel` から参照されているプロバイダやモデルを削除または無効化するには、先に MiniMax Code で既定モデルを別のものに変えてください。MiniMax Code が設定ロックを保持している間、保存は失敗して再試行を促し、待ち続けることはありません。

### 削除済みの ChatGPT アカウントに紐づいた Codex カードは手動で一度紐づけ直す必要があります

自動では紐づけ直しません：カードで「アカウントを選択」を押し、新しいログインを選べば完了です。紐づけ直すまで、このカードでは Codex 引き継ぎを有効にできません。前回終了時に引き継ぎがオンだった場合、起動時の復元は紐づけチェックの失敗により Codex 引き継ぎをオフにし、`~/.codex/auth.json` には触れません。紐づけ直した後で、引き継ぎをもう一度有効にしてください。（[#7395](https://github.com/farion1231/cc-switch/pull/7395)）

### すでに消えた Codex の API Key は自動では復元されません

修正は今後消えるのを防ぐだけです。ある Codex プロバイダのキーが以前の編集や切り替えですでに失われている場合は、もう一度入力してください。使用量スクリプトがそのせいでリセットされた場合も、設定し直す必要があります。（[#7434](https://github.com/farion1231/cc-switch/pull/7434)）

### 「AI署名を非表示」はもう一度チェックし直す必要があります

トグルは `attribution.sessionUrl` も `false` のときにだけオンとみなすようになったため、旧形式 `{commit: "", pr: ""}` で保存された設定はアップグレード後に未チェックと表示されます。もう一度チェックすれば `sessionUrl: false` が補われます。既存の設定が自動で書き換えられることはありません。（[#7053](https://github.com/farion1231/cc-switch/pull/7053)）

### プロンプト一覧を開くと live ファイルへの外部変更が採用されます

あるアプリの live プロンプトファイル（`CLAUDE.md`、`AGENTS.md` など）の内容が有効なプロンプトと異なり、かつ空でない場合、プロンプト一覧を開くとファイルの内容でデータベースに保存された内容を上書きします。有効でないテンプレートは影響を受けず、Pi は対象外です。（[#7194](https://github.com/farion1231/cc-switch/pull/7194)）

### 推論強度は選んだ段階どおりに送られます

`gpt-5.6`・`gpt-5.6-sol`・`gpt-5.6-terra`・`gpt-5.6-luna`・`gpt-6-astra` での `/effort max` は、いまでは本当に `max` 段階を要求します（[#7531](https://github.com/farion1231/cc-switch/pull/7531)）。`/effort xhigh`、および `grok-4.6` / `grok-4.6-*` へマッピングされたモデルでのあらゆる段階は、推論強度を送るようになりました。以前は何も送っていませんでした（[#7318](https://github.com/farion1231/cc-switch/pull/7318)）。推論トークンの使用量とレイテンシがそれに伴って増える可能性があります。

### 一部の変換済みリクエストはアップグレード後に一度だけプレフィックスキャッシュのミスが発生します

2 種類のリクエストはアップグレード後にバイト列が一度だけ変わり、その後は安定します：1 つは、緩い Chat または Anthropic 上流での、`additional_tools` キャリアを持つ Codex リクエストです（[#7454](https://github.com/farion1231/cc-switch/pull/7454)）。`content: null` の system メッセージが消え、キャリア内のツールが `tools` に統合されます。もう 1 つは、これまで `"description": null` を受け付けていた緩い上流での、説明のないツールを含むリクエストです（[#7319](https://github.com/farion1231/cc-switch/pull/7319)、[#7378](https://github.com/farion1231/cc-switch/pull/7378)）。説明を持つツールのシリアライズ結果は変わりません。

### `Ling-2.6-1T` はテキスト専用モデルとして扱われます

これはプリセットに限らず、この id を使うすべてのプロバイダに適用されます：プロキシのメディアフォールバックを有効にしている場合、このモデルへ送る画像は上流へリクエストする前に `[Unsupported Image]` マーカーへ置き換えられます。

### Linux の Claude Desktop に移行作業は不要です

Claude Desktop のプロバイダに切り替えて Claude Desktop を再起動すれば完了で、ほかのプラットフォームと同じです。ご自身でビルドした Flatpak の権限が同梱マニフェストより狭い場合は、`xdg-config/Claude` と `xdg-config/Claude-3p` の読み書き権限を付与する必要があります。例えば次のとおりです（最後の app id はご自身のビルドのものに置き換えてください）：

```bash
flatpak override --user --filesystem=xdg-config/Claude --filesystem=xdg-config/Claude-3p com.ccswitch.desktop
```

### アイコンのない既存の Pi プロバイダは引き続き Pi のアイコンを表示します

名前の頭文字の表示に変わるのは、今後保存するプロバイダだけです。古いカードを更新したい場合は、フォームでアイコンを一度変更してください。（[#6826](https://github.com/farion1231/cc-switch/pull/6826)）

### プリセット変更は新規作成のプロバイダにのみ影響します

既存カードは作成時のスナップショットを保持します。本リリースで該当するのは：

- **MiniMax 国内サイト**：既存カードは `api.minimaxi.com` のままですが、使用量検出・Codex のネイティブ Responses カタログ・`web_search` スイッチはいずれもこのドメインを引き続き認識するため、そのまま使えます。
- **BaiLing**：既存カードは `api.tbox.cn` のままで、Codex 以外のアプリは `Ling-2.5-1T` のままです。Base URL とモデルを編集するか、プリセットを追加し直してください。
- **AICodeWith**：既存の Codex・Hermes・OpenClaw・Pi のカードを手動で `https://api.aicodewith.ai/v1` に変更してください。
- **APIKEY.FUN**：既存カードは `api.apikey.fun` のままです。
- **SudoCode.chat の予備エンドポイント `api.sudorelay.com`**：新規作成した Claude Code・Claude Desktop・Codex・Grok Build のカードにだけ書き込まれます。既存カードでは、エンドポイントの速度テストでこれをカスタムエンドポイントとして追加できます。
- **Codex のモデルカタログ**：Kimi For Coding の K2.8 Preview 行（1M ウィンドウ、`low` / `high` / `max`）、DeepSeek の `deepseek-flash` の既定値とテキスト専用の `deepseek-v4-pro` 行、Hunyuan の `hy4-preview`、そして Qwen のオープンウェイトモデルの行です。カードのモデルカタログで手動で追加するか、プリセットを追加し直してください。
- **Claude Desktop の 1M の選択肢**（DeepSeek、OpenCode Go、Baidu Qianfan Token Plan のプリセット）：プロバイダエディタで該当するルートの「1M 対応を宣言」にチェックを入れるか、プリセットを追加し直してください。
- **Kimi 国際版**：既存の Kimi カードは国内ドメイン（`api.moonshot.cn` / `api.kimi.com`）のままです。国際版 kimi.ai のキーには、新しい Kimi Global / Kimi For Coding Global プリセットを使ってください。

### Codex のカタログ系修正は次回のプロバイダ切り替え時に有効になります

`config.toml` とカタログファイルはプロバイダの切り替え時に再生成されます。本リリースで該当するのは：Chat 上流のカードは `supports_image_detail_original` を宣言しなくなりました（[#7476](https://github.com/farion1231/cc-switch/pull/7476)）。`stepfun.com`・`stepfun.ai`・`qianfan.baidubce.com`・`xf-yun.com`・`minimax.cn` 上のネイティブ Responses カードは `web_search = "disabled"` を書き込みます。`minimax.cn` 上のカードはネイティブ Responses カタログを使います。`Ling-2.6-1T` はテキスト専用と宣言されます。影響を受けるカードから一度別のプロバイダへ切り替え、再び戻せば完了です。プロキシ側で `original` を `auto` へ下げる処理はすぐに有効になり、スクリーンショットで壊れたセッションも履歴を手動で編集する必要はありません。

### 料金

- 5 つの新しい料金行は `INSERT OR IGNORE` で書き込まれ（ご自身ですでに追加した同名の行は保持されます）、起動時の補填がこれらの id でこれまで $0 として記録された過去のリクエストにコストを付けます。すでに 0 でないコストを持つ行は変わりません。
- `deepseek-v4-pro` の修正は、その行がまだ v3.20.3 の書き込んだ 0.3 / 1.2 / 0.006 / 0 そのものである場合にだけ、1.32 / 3.96 / 0.044 へ戻します。カスタマイズ済みの行には触れませんが、手動でちょうどこれらの値に設定した行は区別できないため、同じくリセットされます。v3.20.3 の期間中に記録された V4 Pro のコストは再計算*されません*。補填はコストが $0 以下かつトークン使用量のある行しか処理しないため、アップグレード後のリクエストだけが元に戻した価格で計上されます。
- Grok 4.7 は 200K トークン未満の基本段階で計算します。xAI は 200K トークン以上のプロンプトを 2 倍（$4 / $12）で課金しますが、価格表はこの段階を区別しません。

## ダウンロードとインストール

[Releases](https://github.com/farion1231/cc-switch/releases/latest) からお使いのシステムに合ったビルドをダウンロードするか、公式サイト [ccswitch.io](https://ccswitch.io) から入手してください（ダウンロードは Cloudflare のエッジノード経由で配信され、GitHub への到達性に依存しません）。

### システム要件

| システム | 最低バージョン           | アーキテクチャ                      |
| -------- | ------------------------ | ----------------------------------- |
| Windows  | Windows 10 以降          | x64 / ARM64                         |
| macOS    | macOS 12 (Monterey) 以降 | Intel (x64) / Apple Silicon (arm64) |
| Linux    | 下表参照                 | x64 / ARM64                         |

### Windows

| ファイル                                 | 説明                                             |
| ---------------------------------------- | ------------------------------------------------ |
| `CC-Switch-v3.20.4-Windows.msi`          | **推奨** - MSI インストーラ、自動更新対応        |
| `CC-Switch-v3.20.4-Windows-Portable.zip` | ポータブル版、解凍してすぐ使用、レジストリ不使用 |

Windows ARM64 デバイスでは、ファイル名に `arm64` を含む成果物を選んでください。

### macOS

| ファイル                         | 説明                                                 |
| -------------------------------- | ---------------------------------------------------- |
| `CC-Switch-v3.20.4-macOS.dmg`    | **推奨** - DMG インストーラ、Applications へドラッグ |
| `CC-Switch-v3.20.4-macOS.zip`    | 解凍後 Applications へドラッグ、Universal Binary     |
| `CC-Switch-v3.20.4-macOS.tar.gz` | Homebrew でのインストールと自動更新用                |

Homebrew でのインストール：

```bash
brew install --cask cc-switch
```

アップデート：

```bash
brew upgrade --cask cc-switch
```

### Linux

Linux の成果物は **x86_64** と **ARM64**（`aarch64`）の両アーキテクチャで提供されます。ファイル名のアーキテクチャ表記を、お使いのマシンの `uname -m` の出力に合わせて選んでください：

- `CC-Switch-v3.20.4-Linux-x86_64.AppImage` / `.deb` / `.rpm`
- `CC-Switch-v3.20.4-Linux-arm64.AppImage` / `.deb` / `.rpm`

| ディストリビューション                  | 推奨形式    | インストール方法                                                           |
| --------------------------------------- | ----------- | -------------------------------------------------------------------------- |
| Ubuntu / Debian / Linux Mint / Pop!\_OS | `.deb`      | `sudo dpkg -i CC-Switch-*.deb` または `sudo apt install ./CC-Switch-*.deb` |
| Fedora / RHEL / CentOS / Rocky Linux    | `.rpm`      | `sudo rpm -i CC-Switch-*.rpm` または `sudo dnf install ./CC-Switch-*.rpm`  |
| openSUSE                                | `.rpm`      | `sudo zypper install ./CC-Switch-*.rpm`                                    |
| Arch Linux / Manjaro                    | `.AppImage` | 実行権限を付与して直接実行、または AUR を利用                              |
| その他 / 不明な場合                     | `.AppImage` | `chmod +x CC-Switch-*.AppImage && ./CC-Switch-*.AppImage`                  |
