# CC Switch v4.0.23

This release lets the provider editors of Kimi Code, MiniMax Code and Oh My Pi show this provider's part of the configuration file in the app's own format; when Claude Code and Claude Desktop connect through routing to OpenAI-format and Gemini upstreams, the thinking level chosen in the client is sent to more models, and the card also lets you choose how it is sent; Accounts can refresh the quota of every account at once; Antigravity and MiniMax Code usage records now include latency and first-token time. Fixes cover the main window not coming back after entering lightweight mode on Windows, model switching failing on some OpenAI-format upstreams behind the route, providers not being editable when the DeepSeek Harness configuration folder is a link, usage of Grok Build sessions over 50 MiB not being counted, usage of Codex fork sessions never being imported, testing the official balance in DeepSeek Harness and other apps reporting that the Key is empty, and several editors in the provider form overwriting each other. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

## New

### Kimi Code, MiniMax Code and Oh My Pi provider editors show the native format

Before, the provider editors of these three apps showed the card's JSON, which did not match their actual configuration files, and configuration snippets from the upstream docs could not be pasted in. Now the editor shows only this provider's part of the configuration file, at the same location and in the same format as in the file:

- **Kimi Code**: in `config.toml`, the `[providers.<key>]` table and its `[models."..."]` tables.
- **MiniMax Code**: `custom_provider.<key>` in the YAML.
- **Oh My Pi**: in `models.yml`, the `providers.<key>` entry.

The title shows the actual file path, which follows directory overrides and variables such as `KIMI_CODE_HOME`. When a draft has a syntax error, contains another provider's node, or sets a global setting such as `default_model`, you get a message and it cannot be saved; until it is fixed, the form fields above cannot be changed, so the draft is not overwritten. Comments written in the editor are not saved. DeepSeek Harness providers live in the profile patch, so they still use the JSON editor.

### Thinking levels are sent when connecting to Gemini through routing

Before, when Claude Code and Claude Desktop went through routing converted to Gemini's native format, the thinking level chosen in the client was dropped, and so was turning thinking off; Gemini always used the model's default setting. They are now sent using the same conversion as Gemini's own OpenAI-compatible API:

- **Gemini 2.5**: low, medium and high are thinking budgets of 1024, 8192 and 24576. With thinking off, Flash and Flash-Lite get 0; Pro cannot turn thinking off, so it gets the minimum of 128.
- **Gemini 3 and later**: the low, medium and high levels are sent (Gemini 3 Pro has no medium, so high is sent). None of these models can turn thinking off, so with thinking off the lowest supported level is sent.
- Nothing is sent for unrecognized models, image and audio models, and relay aliases whose name already carries a level (such as `gemini-3-pro-high`), nor when the request had no thinking setting to begin with.

### "Refresh all" in Accounts

The Accounts page header has a new "Refresh all" button that re-queries the quota of every account on the page at once (for DeepSeek, the balance), and each row shows that it is updating as usual ([#9073](https://github.com/farion1231/cc-switch/pull/9073)).

## Improvements

**When Claude Code and Claude Desktop connect through routing to OpenAI-format upstreams, thinking levels are sent to more models** ([#9062](https://github.com/farion1231/cc-switch/issues/9062)). Before, only o-series, GPT-5 and later, and Grok 4.5 and later received the thinking level; other models such as DeepSeek silently lost it, and nothing was logged either. Now:

- Recognized providers get the levels they support: DeepSeek, for example, gets low, high and max, and OpenRouter goes up to xhigh; providers whose OpenAI APIs do not take this parameter, such as Kimi, GLM, Qwen and MiniMax, get none.
- Unrecognized upstreams get only low, medium and high; when xhigh or max is chosen, high is sent.
- GPT-3.5, GPT-4, Llama and Mistral get none; nothing is sent when thinking is off.
- For these two formats, the provider forms of both apps have a new "Reasoning effort" option: "Auto (recommended)" sends by the rules above; "Send as is" sends whatever level the client picks, and returns an error when the upstream does not support xhigh or max; "Don't send" is for upstreams that return an error because of this parameter. Cards of managed accounts do not show this option.

When Codex connects to DeepSeek through routing, the level mapping now also matches DeepSeek's official one: minimal and low are sent as low, medium, high and xhigh as high, and max as max. Before, low was raised to high and xhigh to max.

**Antigravity and MiniMax Code usage records now include latency and first-token time.** Before, usage of these two apps had no speed or first-token time. Records imported earlier are filled in too.

**The Discover and Installed pages of Skills now use the same row style** ([#9081](https://github.com/farion1231/cc-switch/pull/9081)). The repository name is shown in small monospace text next to the name, and the folder path is no longer shown; the "Open docs" button moves to the far right; "Installed · N apps" becomes "Installed ›". When you click "Installed" on the Discover page to jump over, that row flashes yellow twice and then returns to normal.

**Claude official cards bound to an account show the account in the tray** ([#9071](https://github.com/farion1231/cc-switch/pull/9071)). Before, the subtitle was always `www.anthropic.com`, so several official cards could not be told apart. Now it shows the note if there is one, or else the account (its email, or the organization name when there is no email); when the account is not on this computer, it still shows the website.

**In Claude Desktop routing mode, the model name for the Haiku tier is now `claude-haiku-5-5`** ([#9096](https://github.com/farion1231/cc-switch/issues/9096)). Claude Desktop treats `claude-haiku-4-5` as an old model, so no thinking level could be chosen for the Haiku tier. It is not changed when the upstream itself is an older Claude Haiku. Direct mode is not affected.

**Grok Build gets prices for grok-4.6-build, grok-4.7-build and grok-4.7-build-fast** ([#9026](https://github.com/farion1231/cc-switch/pull/9026)).

**Presets:** an OpenAI API Key preset and Gemini CLI / Antigravity presets for 13 providers are added ([#9089](https://github.com/farion1231/cc-switch/issues/9089)), as well as a Claude Code preset for iFlytek Astron MaaS pay-as-you-go ([#9036](https://github.com/farion1231/cc-switch/issues/9036)).

## Fixes

- **On Windows, after entering lightweight mode, launching CC Switch again did not bring up the main window, the tray did not respond, and restarting did not help** ([#9090](https://github.com/farion1231/cc-switch/issues/9090)).
- **On the route to an OpenAI-format upstream that returned SSE even for non-streaming requests, switching models reported "Unable to validate model"** ([#9097](https://github.com/farion1231/cc-switch/pull/9097), [#9095](https://github.com/farion1231/cc-switch/issues/9095)). Non-streaming requests now get a complete JSON response.
- **When DeepSeek Harness profiles pointed to the same file through a symbolic link, editing providers and MCP always reported a conflict** ([#9101](https://github.com/farion1231/cc-switch/pull/9101), [#9100](https://github.com/farion1231/cc-switch/issues/9100)).
- **Grok Build session logs over 50 MiB were skipped entirely, so usage of long sessions was never counted** ([#9026](https://github.com/farion1231/cc-switch/pull/9026), [#6660](https://github.com/farion1231/cc-switch/issues/6660)). They are now read line by line, and afterwards only the new part is read.
- **Codex fork sessions were never imported once the parent session had been idle for a while, so their usage was not counted** ([#9093](https://github.com/farion1231/cc-switch/pull/9093), [#9094](https://github.com/farion1231/cc-switch/issues/9094)).
- **Testing the official balance or Coding Plan in the usage query of DeepSeek Harness, MiniMax Code and Kimi Code reported "API key is empty"** ([#9108](https://github.com/farion1231/cc-switch/pull/9108), [#9107](https://github.com/farion1231/cc-switch/issues/9107)). Saved queries already worked; only the test and custom templates could not read the provider's Key and address.
- **In the provider form, after changing fields such as the address, Key or model and then the configuration editor below (or the other way round), the earlier changes were sometimes reverted** ([#6777](https://github.com/farion1231/cc-switch/pull/6777)).
- **At startup, the interface did not respond until the background session usage sync had finished** ([#9098](https://github.com/farion1231/cc-switch/pull/9098), [#9084](https://github.com/farion1231/cc-switch/issues/9084)).
- **When Codex used DeepSeek V4 Flash 0731 through OpenRouter, conversations containing images returned 404** ([#6194](https://github.com/farion1231/cc-switch/pull/6194), [#6176](https://github.com/farion1231/cc-switch/issues/6176)).
- **On Windows, "Local environment check" opened the OpenCode desktop app** ([#7027](https://github.com/farion1231/cc-switch/pull/7027), [#6973](https://github.com/farion1231/cc-switch/issues/6973)).
- **On macOS, when adding a provider, the back button of the icon picker was covered by the traffic lights** ([#9076](https://github.com/farion1231/cc-switch/pull/9076), [#9075](https://github.com/farion1231/cc-switch/issues/9075)).
- **With local routing on, the model list fetched in the MiniMax Code and DeepSeek Harness forms disappeared after two seconds** ([#9068](https://github.com/farion1231/cc-switch/pull/9068)).
- **Typing with an input method in the Key fields of MiniMax Code, DeepSeek Harness and Kimi Code duplicated letters** ([#9069](https://github.com/farion1231/cc-switch/pull/9069)).
- **With Claude Code installed through mise, adding a Claude account in Accounts reported "default installation is ambiguous".**
- **When the ChatGPT sign-in had really expired, CC Switch kept retrying it as a temporary error instead of asking you to sign in again** ([#9049](https://github.com/farion1231/cc-switch/pull/9049)). The same PR also fixed leaked credentials in Gemini's `.env` on lines starting with `export` not being cleaned up.
