# XSEC Agent Shield 开发计划

日期：2026-10-19。状态：规划基线 v1；本轮完成仓库清理和设计文档，生产安全功能尚未开始实现。

需求来源：[项目总结](xsec-agent-shield-project-summary.md)。配套：[架构](architecture.md)、[威胁模型](threat-model.md)、[测试策略](testing.md)、[仓库基线](repository-baseline.md)。

## 1. 产品范围与开发决策

| 事项 | 本轮规划决策 | 依据 / 边界 |
| --- | --- | --- |
| 产品方向 | XSEC Agent Shield，本地优先、可逆脱敏 | 沿用项目总结建议；公开仓库、域名与发布身份尚待确认 |
| 工程组织 | 保留 Tauri + React + Rust，先新增后端 `shield` 模块 | 已有代理和适配代码可复用；不提前拆成 5 个 crate |
| 首个平台 | macOS 本地开发验证，其他平台逐个验收 | 当前工作环境；钥匙串集成必须先落地 |
| 首个 Agent | 暂定 Claude Code 的 Anthropic Messages 文本路径 | P0 先记录真实版本/配置并探测协议；不预先承诺其所有模式 |
| 第二个 Agent | Codex Responses | 首个 Agent 验收之后，再验证工具事件、压缩与状态引用 |
| 敏感检测 | 配置字面量 + 有测试样本的确定性规则 | 不在首期引入远端检测模型，不宣称覆盖全部敏感语义 |
| 安全模式 | 默认严格；不支持内容、状态异常则阻断 | 兼容模式与例外管理后置 |
| 运行方式 | 桌面进程内安全运行时与现有本地代理 | 退出保持受管 Agent 指向本地端点；独立 daemon 后置 |
| 密钥与映射 | 系统密钥服务 + 独立加密映射库 | 现有 SQLite 配置库不等于加密密钥库 |
| MVP UI | 安全状态、支持范围、规则、最小事件 | 全面重排导航放在核心链路验收后 |
| 明确后置 | MCP Server、多模态、企业管理、跨平台发布、兼容模式、独立服务 | 均不得影响 MVP 的失败安全与证据要求 |

### P5–P7：范围扩展

P5 首先验证 Codex Responses：多种 input item、tool arguments delta、压缩/历史引用、持久上下文及子 Agent 路径。协议状态或签名内容不能安全转换时保持阻断，并记录明确不支持项。只有出现两个真实适配实现后再提炼共享接口。

P6 增加项目/会话策略、规则误报反馈、事件过滤、保留期、策略导入导出及用户明确授权的例外；不得导出密钥和原始映射。P7 为文档、图片、音频、企业身份和集中策略分别立项，MCP 可作为策略查询或受控工具入口，不能替代出口保护。

## 5. MVP 完成定义

必须同时满足：

1. 一个已记录版本的 Agent 在独立环境完成多轮文本请求、多个敏感值、工具结果文本和 JSON/SSE 响应验证。
2. 以 mock 上游真实捕获为准，支持范围内每个发送 attempt 无合成业务秘密；授权本地响应正确恢复。
3. 跨会话/项目、未知/伪造/过期 token 均不误恢复；工具恢复遵循明确授权。
4. 密钥、策略、检测或映射提交失败时，上游请求数为零；停止/崩溃不静默恢复明文直连。
5. 映射库、WAL、日志、备份、错误和 UI 中无不允许的明文；测试源/指定客户端输出是明确例外。
6. 所有声明支持的字段、端点、传输和流式分支均有测试；不支持项阻断；旁路报告明确覆盖缺口。
7. 性能、误报/漏报和恢复指标有样本数及环境；没有证据不标“零泄漏”或百分比承诺。
8. P0 隔离已完成，前后端回归通过；首平台密钥后端和安全变更完成复核。

## 6. 推进方式与交付证据

每个工作包独立提交，提交描述关联 ID 和 Vxx 用例；更新本文复选状态和测试报告。出现基线失败时先区分既有问题与新回归，再决定修复，不把未运行视为通过。

开发期用合成数据和本地 mock 完成大部分测试。真实服务验证在隔离配置、合成内容和明确目标下进行，记录实际版本；不自动读取用户日常对话作为测试材料。

发布配置独立于功能开发：专属品牌资源、包标识、签名/公证、更新校验、漏洞渠道、隐私说明和第三方清单全部完成后才开启发布工作流。旧发布流程已从工作树移除，可从 Git 基线参考。
