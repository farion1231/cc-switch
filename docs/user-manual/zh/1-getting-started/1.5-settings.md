# 1.5 个性化配置

本节介绍如何根据个人偏好配置 CC Switch。

## 打开设置

- 点击左侧栏底部的 **设置**
- 或使用快捷键 `Cmd/Ctrl + ,`（直接打开「通用」）

设置单独占一屏，左侧栏换成设置目录，分为 6 组：**通用、应用配置、本地路由、网络、数据、关于**。点目录上方的「返回」（或按 `Esc`）回到之前的页面。设置里只放偏好；MCP、Skills、提示词、会话等功能页都在左侧栏。

开关类设置即时保存；路径类设置（配置目录）改完要点该块的「保存」。

## 通用

### 外观

| 设置 | 说明 |
| ---- | ---- |
| 界面语言 | 简体中文、繁體中文、English、日本語，切换后立即生效，无需重启 |
| 明暗 | 跟随系统 / 浅色 / 深色 |

### 侧栏与页头

- **在侧栏显示哪些应用**：点「前往「应用」」跳到侧栏的「应用」页，在那里选择显示哪些应用（可选 Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi、MiniMax Code，至少保留一个）
- **显示项目切换**：打开后，Claude Code、Claude Desktop、Codex 页面顶部会出现项目切换器。默认关闭

> 💡 **使用场景**：如果你只使用 Claude Code 和 Codex，可以隐藏其他应用，保持侧栏简洁。

### 各应用的新版本

**启动时检查各应用的新版本**：打开后，每次启动 CC Switch 会查一次已安装的命令行应用有没有新版本，查到了就在侧栏「应用」上显示一个圆点。不会自动升级。升级在「应用」页进行，见 [1.2 安装指南](./1.2-installation.md#可选安装要管理的工具)。

### 窗口与终端

#### 开机自启

开启后，系统启动时自动运行 CC Switch。

- **Windows**：通过注册表实现
- **macOS**：通过 LaunchAgent 实现
- **Linux**：通过 XDG autostart 实现

开启后会多出一个 **静默启动** 开关：启动时不显示主窗口，仅在系统托盘运行。

#### 关闭时最小化到托盘

| 「关闭时最小化到托盘」 | 点击窗口关闭按钮时         |
| ---------------------- | -------------------------- |
| 开启（默认）           | 隐藏到系统托盘，继续在后台运行 |
| 关闭                   | 完全退出应用               |

推荐保持开启，方便通过托盘快速切换供应商。

#### 启用应用级窗口按钮（仅 Linux）

开启后使用应用自建的最小化、最大化/还原、关闭按钮；关闭后沿用系统窗口模式。

#### 首选终端

选择点击供应商卡片上的「打开终端」时使用的终端应用。选的终端不可用时，改用系统默认终端。

| 平台    | 终端选项                                                           |
| ------- | ------------------------------------------------------------------ |
| macOS   | Terminal、iTerm2、Alacritty、Kitty、Ghostty、Otty、WezTerm、Kaku、Warp |
| Windows | 命令提示符、PowerShell、Windows Terminal                           |
| Linux   | GNOME Terminal、Konsole、Xfce4 Terminal、Alacritty、Kitty、Ghostty |

#### 轻量模式

轻量模式是一种**仅托盘运行**的状态，用于把空闲时的桌面占用降到最低。

**触发方式**：右键系统托盘图标 → 点击「轻量模式」。主窗口会被**销毁**（而不是隐藏），UI 资源和内存随之释放。

**退出方式**：从托盘菜单点击「打开主界面」，或通过深链接 / 再次启动 CC Switch。窗口会按需**重建**，状态保持一致。

| 特性         | 最小化到托盘         | 轻量模式                 |
| ------------ | -------------------- | ------------------------ |
| UI 进程      | 保留在内存中         | 完全销毁                 |
| 空闲资源占用 | 与正常运行相当       | 接近零                   |
| 再次打开速度 | 瞬时（直接显示）     | 略慢（需要重建窗口）     |
| 托盘切换功能 | 可用                 | 可用                     |
| 深链接唤起   | 可用                 | 可用（按需重建）         |

> ⚠️ **注意**：轻量模式状态不持久 — 下次正常启动时会回到普通模式。需要长期使用可搭配开机自启。

## 应用配置

每个应用一块，放只属于它的开关和配置目录。

### Claude Code

- **应用到 Claude Code 插件**：开启后，VS Code 中 Claude Code 插件的供应商会随 CC Switch 切换（写入 `~/.claude/config.json` 的 `primaryApiKey`）。同时使用 Claude Code CLI 和 VS Code 插件时，开启它可以保持两者一致
- **跳过 Claude Code 初次安装确认**：开启后跳过 Claude Code 首次启动时的初次安装确认。

> ⚠️ **注意**：「跳过 Claude Code 初次安装确认」会在 `~/.claude.json` 中写入 `hasCompletedOnboarding: true`；关闭时删除该字段。

### Codex 应用增强

Codex 这一块有两个开关，默认都关闭：

**非接管切换时保留官方登录**：

- **关闭**：未开启本地路由时，每次切换到第三方供应商都会删除 `~/.codex/auth.json`，使用第三方供应商期间 Codex 里没有官方登录。删除前 CC Switch 会把登录暂存到本机（`~/.cc-switch/codex-login-stash.json`，不参与云同步），切回官方供应商时自动还原，无需重新登录
- **开启**：直接切换到第三方供应商时保留 `~/.codex/auth.json`，使用第三方供应商期间官方登录仍然在，可以继续使用需要官方登录的功能

第三方供应商的 API Key 始终只写入 `~/.codex/config.toml`，不会写进 `auth.json`；开启本地路由后，官方登录始终保留。详见攻略 [使用第三方 API 时保留 Codex 远程操作和官方插件](../../../guides/codex-official-auth-preservation-guide-zh.md)。

**统一 Codex 会话历史**：开启后，官方订阅以共享的 custom 供应商标识运行，官方与第三方会话出现在同一个历史列表中，并可选择把现有官方会话一并迁入（迁移前自动备份）；关闭时可按备份恢复。注意：跨供应商继续旧会话时，对方后端可能无法解密会话中的推理内容，导致继续失败。详见攻略 [统一 Codex 会话历史](../../../guides/codex-unified-session-history-guide-zh.md)。

### 配置目录

Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi 这 8 个应用各有一行「配置目录」，可以指向别的位置；留空用默认值。MCP、Skills、提示词路径会随之变化。

| 应用            | 默认值                |
| --------------- | --------------------- |
| Claude Code     | `~/.claude/`          |
| Codex           | `~/.codex/`           |
| Gemini CLI      | `~/.gemini/`          |
| Grok Build      | `~/.grok/`            |
| OpenCode        | `~/.config/opencode/` |
| OpenClaw        | `~/.openclaw/`        |
| Hermes          | `~/.hermes/`          |
| Pi              | `~/.pi/agent/`        |

Claude Desktop 和 MiniMax Code 不支持在这里覆盖目录（所以应用配置里没有它们）。MiniMax Code 的数据目录默认为 `~/.minimax/`，可以用环境变量 `MINIMAX_DATA_DIR`（或 `MAVIS_DATA_DIR`）指定；Hermes 另外识别 `HERMES_HOME`，Pi 另外识别 `PI_CODING_AGENT_DIR`。

> 💡 **WSL**：CC Switch 不会自动识别 WSL。在 Windows 上可以把目录改成 WSL 里的路径（如 `\\wsl.localhost\Ubuntu\home\<用户名>\.claude`），CC Switch 就会读写 WSL 里的配置。

> ⚠️ **注意**：修改目录后需要重启应用，且对应的 CLI 工具也需要配置相同的目录。

> 💡 **Skills 的存储位置和同步方式**不在设置里：在侧栏「Skills」页点「存储与同步」，可以选主副本放在「CC Switch 目录」还是「通用目录」（`~/.agents/skills`），以及同步到各应用用软链接还是复制。

## 本地路由

设置 → 本地路由

这一组集中管理本地路由的全局部分：

- **服务**：显示路由服务的运行状态（已运行时间、总请求数、成功率、活跃连接），可「启动」/「停止」；「监听地址与端口」默认 `127.0.0.1`，修改后点「保存并重启服务」；「记录请求用量」关闭后，用量统计里没有经路由的请求明细。还有应用在用路由服务时不能停止，需要先让它们回到直连
- **正在使用路由的应用**：列出当前处于路由或聚合模式的应用，点「前往」跳到该应用页；「全部回到直连」让所有应用写回直连配置并停止路由服务，路由目标、队列和聚合名单会保留
- **自动故障转移**：调各应用的超时、重试和熔断。队列在各应用页的「路由」页签里管理。详见 [4.3 故障转移](../4-proxy/4.3-failover.md)
- **整流器**：自动修复部分上游不兼容的请求，例如 Thinking 签名不兼容时移除相关内容后重试

进入路由或聚合的入口在各应用页顶部的「直连 / 路由 / 聚合」标签，详见 [4.1 本地路由服务](../4-proxy/4.1-service.md)。

## 网络

设置 → 网络

**全局出站代理**：配置 CC Switch 访问外部 API 时使用的 HTTP/HTTPS 代理，适用于需要通过代理访问外部 API 的场景。

## 数据

设置 → 数据

### 存储位置

**CC Switch 配置目录**：CC Switch 自身数据的存储位置，默认为 `~/.cc-switch/`，可以指定到云同步文件夹。改完点「保存」，需要重启应用生效。

### 数据管理

#### 导出配置

点击「导出 SQL 备份」按钮，保存包含以下内容的 SQL 备份文件：

- 所有供应商配置
- MCP 服务器配置
- Prompts 预设
- 用量日志
- 应用设置

导出文件名格式为 `cc-switch-export-{timestamp}.sql`。

#### 导入配置

1. 点击「选择 SQL 文件」（仅支持导入由 CC Switch 导出的备份）
2. 选择之前导出的备份文件
3. 按钮变为「导入」后，点击它开始导入
4. 导入成功后，界面会显示本次导入前自动创建的备份 ID

> ⚠️ **注意**：导入会覆盖现有配置，建议先导出当前配置作为备份。

### 备份与恢复

备份管理面板提供对数据库备份的全面控制。

#### 自动备份设置

| 配置     | 选项                               | 默认值    |
| -------- | ---------------------------------- | --------- |
| 自动备份间隔 | 禁用、6h、12h、24h、48h、7d        | 24 小时   |
| 备份保留数量 | 3、5、10、15、20、30、50           | 10 个备份 |

设置间隔后，CC Switch 会按计划自动备份数据库。超出保留数量的旧备份会自动删除。

#### 备份列表

面板显示所有现有备份，包含：
- **显示名称**（根据时间戳自动生成，如 `db_backup_20260315_143000`）
- **创建时间**
- **文件大小**（如 "1.5 MB"）

#### 备份操作

| 操作         | 说明                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| **立即备份** | 立即创建一个备份                                                         |
| **恢复**     | 从选定的备份恢复数据库。恢复前会自动创建当前数据库的安全备份             |
| **重命名**   | 修改备份的显示名称                                                       |
| **删除**     | 永久删除备份（需确认）                                                   |

> ⚠️ **重要**：恢复备份会覆盖当前数据库。恢复操作前始终会自动创建安全备份，以便在需要时恢复。

#### 其他备份

备份列表下方的「其他备份」总览列出 CC Switch 在各处留下的备份（Skill 卸载备份、配置文件首次写入备份、Codex 会话迁移备份、Hermes / OpenClaw 配置备份、旧版遗留文件等），显示每项的位置和占用大小，合计占用写在标题旁。每项可「在文件管理器中显示」，也可以自己选择「删除」（需确认，永久删除）。数据库备份在上方列表中管理。

> ⚠️ 有些备份删除后无法恢复对应内容，例如删掉「配置文件首次写入备份」后找不到改写前的原文件，删掉「Skill 卸载备份」后已卸载的 Skill 无法再恢复；每项下方的说明会写清后果。

### 云同步

通过 **WebDAV** 或 **S3 兼容存储** 在多台设备间同步配置，两种方式同一时间只能启用一种。使用 **v2 协议**，支持双层版本控制，提高可靠性。

#### WebDAV

| 配置项   | 说明                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 服务商   | 坚果云 / Nextcloud / 群晖 NAS / 自定义                                         |
| WebDAV 服务器地址 | WebDAV 服务器 URL                                                     |
| WebDAV 账户 | 登录用户名                                                           |
| WebDAV 密码 | 登录密码（应用专用密码；已保存的凭据在未修改时会被保留）                     |
| 远程根目录 | 远程存储路径（默认 `cc-switch-sync`）                                        |
| 同步配置名 | 设备配置文件名（默认 `default`）                                             |
| 自动同步 | 开启后每次数据库变更都会自动上传                                             |

#### S3 兼容存储

| 配置项            | 说明                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------- |
| 服务商            | AWS S3 / MinIO / Cloudflare R2 / 阿里云 OSS / 腾讯云 COS / 华为云 OBS / S3 兼容服务（自定义） |
| 区域 (Region)     | 如 `us-east-1`；R2 填 `auto`                                                           |
| 存储桶 (Bucket)   | 存放同步数据的存储桶                                                                  |
| Access Key ID / Secret Access Key | 访问凭据                                                             |
| Endpoint          | AWS 可留空，多数 S3 兼容服务需要填写                                                  |
| 远程根目录        | 默认 `cc-switch-sync`                                                                 |
| 同步配置名        | 默认 `default`                                                                        |
| 自动同步          | 开启后每次数据库变更都会自动上传                                                      |

#### 操作

| 操作         | 说明                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| **测试连接** | 验证服务地址和凭据是否有效                                                                   |
| **上传**     | 将本地数据库上传到远程，显示进度指示器                                                       |
| **下载**     | 下载远程数据库。下载前显示远程快照信息（协议版本、数据库版本、时间戳、大小）供确认。覆盖本地数据库前会自动创建安全备份 |

#### 自动同步

启用 **自动同步** 后：
- 首次激活时会显示确认对话框
- 每次数据库变更后，CC Switch 会自动把数据库上传到云端
- 面板中显示上次同步时间；自动同步失败时会显示错误，并在后续变更时继续重试

#### 远程快照信息

下载前，CC Switch 会显示远程快照的详细信息：
- 协议版本（v2）
- 数据库兼容版本
- 远程备份的时间戳
- 文件大小
- 兼容性状态（不兼容时显示警告）

> ⚠️ **注意**：上传会覆盖远程数据，下载会覆盖本地数据。下载前始终会自动创建安全备份。

### 应用诊断日志

| 配置项           | 说明                                                        |
| ---------------- | ----------------------------------------------------------- |
| 启用应用诊断日志 | 控制 `cc-switch.log`；不影响请求用量记录和 `crash.log`       |
| 日志级别         | error / warn / info / debug / trace                         |

日志级别说明：

- **error** - 仅记录错误
- **warn** - 记录警告和错误
- **info** - 记录一般信息（默认）
- **debug** - 记录调试信息
- **trace** - 记录所有详细信息

## 授权中心（Beta）

登录入口在左侧栏的「授权中心」，不在设置里。授权中心统一管理第三方 OAuth 凭据，目前支持三类账号：

| 账号类型                     | 用途                                            |
| ---------------------------- | ----------------------------------------------- |
| **GitHub Copilot**           | 配合 Copilot 反向代理使用                       |
| **ChatGPT (Codex OAuth)**    | 配合 Codex OAuth 反向代理使用，管理 ChatGPT 账号   |
| **xAI (Grok OAuth)**         | 配合 xAI Responses API 反向代理使用               |

**你可以在这里**：

- 通过 Device Code 流程登录 ChatGPT / GitHub / xAI 账号
- 查看已登录账号列表和认证状态
- 为多账号设置默认账号
- 移除单个账号或一键注销所有账号

xAI 集成使用 OAuth 2.0 Device Authorization Grant，不使用本机回环回调。其网络依赖契约如下：

| 依赖 | 端点 |
| ---- | ---- |
| OpenID discovery | `https://auth.x.ai/.well-known/openid-configuration` |
| 设备授权 | discovery 返回的 `device_authorization_endpoint`（当前为 `https://auth.x.ai/oauth2/device/code`） |
| Token 交换/刷新 | discovery 返回的 `token_endpoint`（当前为 `https://auth.x.ai/oauth2/token`） |
| 推理 | `https://api.x.ai/v1/responses` |
| 模型发现 | `https://api.x.ai/v1/models` |

流程不占用任何本地回调端口；认证和模型请求均复用 CC Switch 的全局出站代理设置。

xAI 集成**不使用**注册给 CC Switch 的 OAuth 应用，而是复用 xAI 官方 Grok CLI 注册的公共 OAuth 客户端身份与 scope（`client_id: b1a00492-073a-47ea-816f-4c329264a828`，包含 `grok-cli:access`）获取账号型 API 访问权限。

> ⚠️ **警告**：这些账号型反向代理使用逆向接入的 OAuth 流程，存在账号与服务条款风险。复用上游产品的 OAuth 客户端可能不受官方支持，并可能导致服务商限制或封禁账号。请在使用前审阅对应服务商条款并自行承担风险；现有 Codex 流程另见 [2.1 添加供应商 → Codex OAuth 反向代理](../2-providers/2.1-add.md#codex-oauth-反向代理claude-供应商) 的完整风险提示。

## 关于页面

设置 → 关于

### 版本信息

显示当前 CC Switch 版本号，支持：

- 检查更新，有新版本时点「更新到 vX」下载并安装（便携版需手动下载）
- 查看 GitHub、官方网站、更新日志
- 「近期更新」：重新查看最近几个版本的更新摘要

### 工具的安装与升级

各 AI 编程工具的版本检测、安装、升级和「全部升级」不在这里，而在左侧栏的「应用」页，详见 [1.2 安装指南](./1.2-installation.md#可选安装要管理的工具)。在 Windows 上，如果在「应用配置」里把某个工具的目录设为 WSL 路径，「应用」页会在对应的 WSL 发行版里检测和升级该工具。
