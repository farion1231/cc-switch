# 4.2 应用路由

## 功能说明

应用路由是指让 CC Switch 路由特定应用的 API 请求。每个应用有三种连接模式，在应用页顶部用「直连 / 路由 / 聚合」标签查看：

| 模式 | 说明 |
|------|------|
| 直连 | 客户端直接连供应商，切换只改配置文件里的关键字段 |
| 路由 | 请求先经过本机的 CC Switch，再转给供应商；可做格式转换和故障转移 |
| 聚合 | 仅 Claude Code 和 Codex。按 `/model` 里选的模型把请求分给多家供应商，不做故障转移；官方账号只能作默认供应商，不能加入聚合 |

本页讲「路由」。进入路由后：
- 应用的 API 请求会通过本地路由转发
- 可以记录请求日志和统计用量
- 可以使用故障转移功能

## 前提条件

路由需要 CC Switch 保持运行。路由服务不用事先启动，进入路由时会自动启动。

支持路由的应用：Claude Code、Codex、Gemini CLI、Grok Build。

## 开始路由

### 操作位置

应用页顶部的「路由」标签。

### 操作步骤

1. 在侧栏选中要路由的应用
2. 点击顶部的「路由」标签（只是查看，不改配置）
3. 点击「开始路由」，在弹出的确认框里选择「路由到」哪家供应商，再点「开始路由」确认

确认框会写明后果：会改写客户端配置里的地址和密钥，真实密钥留在 CC Switch 里，其他设置不动；之后在「路由」标签里换供应商，不再改写配置文件；CC Switch 需要保持运行，退出时自动写回直连，下次启动再接上。

可以同时让多个应用进入路由。「设置 → 本地路由」里的「正在使用路由的应用」会列出它们。

> ⚠️ 官方供应商（如 Claude Official）不能经本地路由转发，路由模式下无法切换到这类供应商，卡片上提示「官方订阅不经过路由，回到直连后可用」；Codex 的 OpenAI Official 除外。

## 路由原理

### 配置修改

进入路由后，CC Switch 会修改应用的配置文件，将 API 端点指向本地路由。

**Claude 配置变更**：

```json
// 路由前
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com"
  }
}

// 路由后
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:15721"
  }
}
```

**Codex 配置变更**：

```toml
# 路由前
[model_providers.custom]
base_url = "https://api.example.com/v1"

# 路由后
[model_providers.custom]
base_url = "http://127.0.0.1:15721/v1"
```

**Gemini 配置变更**：

```bash
# 路由前
GOOGLE_GEMINI_BASE_URL=https://generativelanguage.googleapis.com

# 路由后
GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:15721
```

**Grok Build 配置变更**：`~/.grok/config.toml` 中路由供应商那张模型表的请求地址改为 `http://127.0.0.1:15721/grokbuild/v1`。Grok Build 的官方账号不能经本地路由使用：当前是官方供应商时开始路由会报错，请先切到第三方供应商。

路由期间，配置文件中的 API Key 会替换为占位符 `PROXY_MANAGED`，真实 Key 由本地路由在转发时注入。和切换供应商一样，进入路由只改这些关键字段，配置文件里的其他内容不动。

### 请求转发

路由收到请求后：

1. 识别请求来源（Claude/Codex/Gemini/Grok Build）
2. 查找该应用当前的路由目标（开了故障转移时按队列）
3. 按需转换接口格式，将请求转发到供应商的实际端点
4. 记录请求日志
5. 返回响应给应用

## 路由状态指示

### 应用页指示

路由生效后：

- 「路由」标签上有生效标记，标签右侧显示「路由生效中 → 供应商名」（故障转移开启时显示「按队列」）
- 正在路由的供应商卡片显示「路由中」状态
- 如果路由服务没有运行，应用页会提示，并给出「启动服务」和「回到直连」按钮

### 供应商卡片状态

| 状态 | 说明 |
|------|------|
| 路由中 | 路由实际使用的供应商 |
| 直连 | 直连供应商，退出路由后恢复为它（鼠标悬停提示「退出路由后恢复为这个供应商」） |
| 路由到此 | 其他供应商上的按钮，点击后把路由目标换到这一家 |

## 关闭路由

### 操作步骤

- 在应用页点「回到直连」，只退出这一个应用
- 或在「设置 → 本地路由」点「全部回到直连」，所有应用一起退出并停止路由服务，详见 [4.1 本地路由服务](./4.1-service.md#停止本地路由)

### 配置恢复

退出路由时，CC Switch 会：

1. 把应用的配置文件写回直连供应商（进入路由前在用、卡片上标「直连」的那个），不依赖进入路由时的备份
2. 保存当前的请求日志

退出 CC Switch 时，也会先把配置文件写回直连供应商，应用的模式保持不变；下次启动 CC Switch 时再重新接上本地路由。

## 路由与供应商切换

### 路由模式下切换供应商

在路由模式下切换供应商：

1. 在「路由」标签里点击供应商卡片上的「路由到此」（故障转移开启时，改在队列里调整，见 [4.3 故障转移](./4.3-failover.md)）
2. 路由立即使用新供应商转发请求
3. **无需重启 CLI 工具**

这是路由模式的一大优势：切换供应商即时生效。切换 Codex、Gemini CLI 或 Grok Build 后，界面仍会提示重启；路由时，只要切换没有改变模型，就可以不重启。

路由模式下切换的只是路由使用的供应商，直连供应商保持不变，卡片上标「直连」，退出路由后回到它。如果新供应商写进配置文件的内容（本地地址、模型名等）和原来一样，切换时不会改动配置文件；不一样时（比如模型名不同），CC Switch 会先更新配置文件，这时 Codex、Gemini CLI、Grok Build 需要重启才能用上新模型。

### 直连模式下切换

在直连模式下切换供应商：

1. 修改配置文件
2. 需要重启 CLI 工具才能生效

## 多应用路由

可以同时路由多个应用，每个应用独立管理：

- 独立的供应商配置
- 独立的故障转移队列
- 独立的请求统计

## 使用场景

### 场景一：用量监控

进入路由 + 「记录请求用量」，逐条记录经过本地路由的请求。不开路由时，CC Switch 也会从各工具的本地会话记录统计用量，详见 [4.4 用量统计](./4.4-usage.md)。

### 场景二：快速切换

进入路由后，切换供应商无需重启 CLI 工具。

### 场景三：接口格式转换

使用 OpenAI 或 Gemini 格式的供应商配合 Claude Code，或使用 Chat Completions / Anthropic Messages 格式的供应商配合 Codex、Grok Build，都需要进入路由。

### 场景四：故障转移

进入路由是使用故障转移功能的前提。

## 注意事项

### 性能影响

路由会增加少量延迟（通常 < 10ms），对于大多数场景可以忽略。

### 网络要求

路由模式下，CLI 工具需要能够访问本地路由地址。

### 配置备份

进入路由不依赖备份：退出路由时，CC Switch 按直连供应商重新写入配置文件。另外，CC Switch 第一次改写每个配置文件之前，会把原文件备份到 `~/.cc-switch/backups/live-first-write/`。

## 常见问题

### 路由后请求失败

检查：
- 路由服务是否正常运行（设置 → 本地路由）
- 供应商配置是否正确
- 网络是否正常

### 回到直连后配置未恢复

可能原因：
- 路由异常退出
- 配置文件被其他程序修改

解决方法：
- 手动编辑供应商，重新保存
- 或重新进入再退出路由
