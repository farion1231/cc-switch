# 4.1 本地路由服务

## 功能说明

本地路由在本机启动一个 HTTP 服务。为某个应用开启路由后，该应用的 API 请求会先发到 CC Switch，再由 CC Switch 转发给当前供应商。

**主要用途**：
- 转换接口格式：让 Claude Code 使用 OpenAI 或 Gemini 格式的供应商，让 Codex、Grok Build 使用 Chat Completions 或 Anthropic Messages 格式的供应商
- 自动故障转移：当前供应商请求失败时，按队列切换到备用供应商
- 热切换：切换供应商后立即作用于后续请求
- 记录每次请求的用量与状态

支持本地路由的应用：**Claude Code**、**Codex**、**Gemini CLI**、**Grok Build**。Claude Desktop 的「模型映射」模式也经由本地路由转发，详见 [2.6 Claude Desktop](../2-providers/2.6-claude-desktop.md)。

> 💡 统计用量不一定要开启本地路由：不开路由时，CC Switch 也会从各工具的本地会话记录统计用量，详见 [4.4 用量统计](./4.4-usage.md)。

## 启动本地路由

### 方式一：设置页面

1. 打开「设置 → 路由 → 本地路由」
2. 打开「路由总开关」，启动本地服务
3. 在「路由启用」中打开要路由的应用（Claude / Codex / Gemini / Grok Build）

![image-20260108011338922](../../assets/image-20260108011338922.png)

### 方式二：主界面开关

在「设置 → 路由 → 本地路由」中打开「在主页面显示本地路由开关」后，Claude、Codex、Gemini、Grok Build 页面顶部会出现本地路由开关（Claude Desktop 页面另有自己的路由开关，见 [2.6 Claude Desktop](../2-providers/2.6-claude-desktop.md)）。

这个开关只控制**当前应用**的路由：
- 打开时，如果本地路由还没运行，会自动启动
- 关闭时，只关闭当前应用的路由；没有其他应用还开着路由时，本地路由会自动停止

开关状态：
- ⚪ 白色：当前应用未开启路由
- 🟢 绿色：当前应用正在经本地路由转发

![image-20260108011353927](../../assets/image-20260108011353927.png)

## 路由配置

### 基础配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 监听地址 | 本地路由绑定的 IP 地址 | `127.0.0.1` |
| 监听端口 | 本地路由监听的端口（1024–65535） | `15721` |
| 记录请求用量 | 将路由请求的用量与状态写入本地统计数据库 | 开启 |

监听地址和端口只在本地路由停止时显示；「记录请求用量」开关在本地路由运行时显示。重试次数和超时时间在「设置 → 路由 → 自动故障转移」中按应用配置，见 [4.3 故障转移](./4.3-failover.md)。

### 修改配置

1. **关闭「路由总开关」**（必须先停止本地路由，才能看到地址和端口设置）
2. 修改监听地址或端口
3. 点击「保存」
4. 重新打开「路由总开关」

### 监听地址说明

| 地址 | 说明 |
|------|------|
| `127.0.0.1` | 仅本机可访问（推荐） |
| `0.0.0.0` | 允许局域网访问 |

面板会按应用显示故障转移队列：

队列说明：

## 工作原理

### 请求流程

```mermaid
sequenceDiagram
    participant CLI as CLI 工具 (Claude)
    participant Proxy as 本地路由 (CC Switch)
    participant API as API 供应商 (Anthropic)
    participant DB as 数据存储 (Logger)

    CLI->>Proxy: 发送 API 请求
    Proxy->>DB: 记录请求日志/统计用量
    Proxy->>API: 转发请求
    API-->>Proxy: 返回响应
    Proxy-->>CLI: 返回响应
```

### 配置修改

启动本地路由并为应用开启路由后，CC Switch 会把该应用的请求地址改为本地路由：

**Claude**：
```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:15721"
  }
}
```

**Codex**：
```toml
[model_providers.custom]   # 当前供应商的配置段
base_url = "http://127.0.0.1:15721/v1"
```

**Gemini**：
```
GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:15721
```

**Grok Build**：`~/.grok/config.toml` 中的请求地址指向 `http://127.0.0.1:15721/grokbuild/v1`。

开启路由期间，配置文件中的 API Key 会被替换为占位符，真实 Key 保存在 CC Switch 中，由本地路由在转发时注入。

## 接口格式转换

本地路由会按供应商配置的「上游格式」自动转换请求和响应，同时支持流式和非流式请求。

**Claude Code / Claude Desktop 侧**（客户端发出 Anthropic Messages 请求）：

| 供应商上游格式 | 本地路由行为 |
|-----------------|----------|
| **Anthropic Messages** | 透传（不转换） |
| **OpenAI Chat Completions** | 转换为 OpenAI Chat 格式，响应反向转换 |
| **OpenAI Responses API** | 转换为 OpenAI Responses 格式，响应反向转换 |
| **Gemini Native generateContent** | 转换为 Gemini 原生格式，响应反向转换 |

**Codex / Grok Build 侧**（客户端发出 OpenAI Responses 请求）：

| 供应商上游格式 | 本地路由行为 |
|-----------------|----------|
| **Responses（原生）** | 透传（不转换） |
| **Chat Completions** | 转换为 Chat Completions 格式，响应反向转换 |
| **Anthropic Messages** | 转换为 Anthropic Messages 格式，响应反向转换 |

上游格式在添加或编辑供应商时于高级选项中按供应商配置，详见 [2.1 添加供应商 → 上游格式（Claude）](../2-providers/2.1-add.md#上游格式claude) 和 [Codex / Grok Build 的上游格式与模型映射](../2-providers/2.1-add.md#codex--grok-build-的上游格式与模型映射)。

> **注意**：格式转换需要本地路由运行，并为对应应用开启路由。

## 上游要求会话标识怎么办

部分按会话路由的上游会要求每个请求携带稳定、且能区分不同对话的会话标识；缺少标识时，上游会直接拒绝请求，CC Switch 日志中通常出现 `[FWD-003] Provider <供应商> 请求失败`。OpenCode Go 的典型响应是：

```json
{
  "type": "error",
  "error": {
    "type": "MissingSessionID",
    "message": "Request is missing x-opencode-session and cannot be routed efficiently."
  }
}
```

这类问题常出现在不经 CLI、直接调用本地路由 API（例如 `/v1/messages`）的旁路请求中，例如 IDE 插件生成会话标题、提交信息或提示词增强。Claude Code CLI 的正常对话会携带 `x-claude-code-session-id`（或请求体 `metadata` 中的会话标识），因此通常不受影响；IDE 旁路调用可能不带任何会话标识，最终表现为某个附加功能报错、无结果或没有反应。

**Header 覆盖是供应商级静态配置**：它会为该供应商的每次转发写入同一个值，不会按对话生成 ID，也不会只在 Header 缺失时补充。因此，它可用于临时确认 400 是否由缺失 `x-opencode-session` 引起，或用于仅承载单一逻辑会话的受限场景，但不能替代调用方传递正确的会话标识。OpenCode Go 要求每个对话保持稳定且可区分的 ID；正常使用时应让客户端发送原生会话 Header。

如仅用于上述受限场景，可在对应供应商中临时注入固定值：

1. 编辑使用 OpenCode Go 的 Claude（或 Codex）非官方供应商。
2. 展开「高级选项」，找到「本地代理请求覆盖」→「Header 覆盖」。
3. 填写并保存：

```json
{
  "x-opencode-session": "cc-switch-single-session-diagnostic"
}
```

该配置只会在本地路由开启后生效，并在协议转换完成后、请求发往上游前应用。它会作用于该供应商的全部非 Copilot 转发，并替换同名 Header，而不只是影响缺少标识的 IDE 旁路调用。多对话共用同一个值会丢失会话区分，并可能影响路由和提示缓存；不要把它作为通用修复。

> **安全边界**：受保护 Header 按具体名称精确匹配，没有 `x-forwarded-*` 通配规则。转发相关项只包括 `x-forwarded-host`、`x-forwarded-port`、`x-forwarded-proto` 和 `forwarded`；其它 `x-forwarded-*` 不在这层保护内。协议、凭据和代理管理类 Header 也按具体名称保护，例如 `host`、`content-length`、`transfer-encoding`、`connection`、`content-type`、`authorization`、`x-api-key`、`x-goog-api-key`、`chatgpt-account-id`、`session_id`、`x-client-request-id`、`x-codex-window-id`。这些名称会被前端校验拒绝；若旧数据绕过前端，后端也会在转发前忽略，不能用于修改上游地址、凭据或代理管理标识。

## 停止本地路由

### 方式一：设置页面

在「设置 → 路由 → 本地路由」中关闭「路由总开关」。

### 方式二：主界面开关

在各应用页面关闭顶部的本地路由开关（需已开启「在主页面显示本地路由开关」）。所有应用的路由都关闭后，本地路由会自动停止。

### 停止后的处理

停止本地路由时，CC Switch 会：

1. 恢复各应用的配置到开启路由前的状态
2. 保存请求日志
3. 关闭所有连接

## 请求日志

### 开启记录

在本地路由设置中开启「记录请求用量」开关（默认开启）。

### 日志内容

每条请求记录包含：

| 字段 | 说明 |
|------|------|
| 时间 | 请求时间 |
| 应用 | Claude / Codex / Gemini / Grok Build |
| 供应商 | 使用的供应商 |
| 模型 | 请求的模型 |
| Token | 输入/输出 token 数 |
| 延迟 | 请求耗时 |
| 状态 | 成功/失败 |

### 查看日志

在「设置 → 使用统计」Tab 中查看请求日志。

## 常见问题

### 端口被占用

错误信息：`Address already in use`

解决方法：
1. 更换端口（1024–65535 之间）
2. 或关闭占用端口的程序

### 本地路由启动失败

检查：
- 端口是否被占用
- 是否有足够权限
- 防火墙是否阻止

### 请求超时

可能原因：
- 网络问题
- 供应商服务器问题
- 本地路由配置错误

解决方法：
- 检查网络连接
- 尝试直接访问供应商 API
- 检查供应商配置
