# 4.5 连通检测

## 功能说明

连通检测用于快速判断供应商的地址能不能连上：

- CC Switch 向供应商的请求地址（base URL）发送一个轻量请求，收到任意 HTTP 响应（包括 401、403、404、5xx）即判定为「可达」
- 只有 DNS 解析失败、连接被拒、TLS 错误、超时等网络层面的错误才判定为「不可达」
- 延迟为收到响应头的耗时

> ⚠️ **连通检测不发送真实模型请求**，也不验证 API Key 和模型名。「可达」只说明地址能连上，不代表鉴权或模型配置一定正确。

> 💡 v3.16.3 之前，这里叫「模型检查」（Stream Check），会向供应商发送真实的流式模型请求。由于许多第三方网关会拦截这类请求、造成误判，现已改为连通检测，也不再需要配置测试模型。

除 MiniMax Code 外，各应用的非官方供应商都可以检测。官方供应商（如 Claude Official、Claude Desktop Official）没有可供探测的地址；官方供应商和 MiniMax Code 的供应商卡片上，检测按钮显示为灰色、不可点击。

## 执行检测

1. 鼠标悬停在供应商卡片上，显示操作按钮
2. 点击 **检测连通** 按钮
3. 等待检测完成，结果以提示消息显示

| 结果 | 说明 |
|------|------|
| 连通正常（xxx ms） | 地址可达，延迟在「较慢阈值」以内 |
| 连通但较慢（xxx ms） | 地址可达，但延迟超过「较慢阈值」 |
| 无法连通 | 无法建立连接（DNS / 连接 / TLS / 超时），请检查请求地址与网络 |

## 检测参数

设置 → 高级 → 连通检测配置

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| 超时时间（秒） | 单次探测的最长等待时间 | 8 | 2-60 |
| 最大重试次数 | 仅在超时类失败时重试；连接被拒、DNS 失败等会立即返回 | 1 | 0-5 |
| 较慢阈值（毫秒） | 可达但延迟超过此值时，标记为「较慢」 | 6000 | 1000-30000 |

## 与故障转移的关系

连通检测**不会**影响故障转移和熔断器：一个返回 403 的供应商在连通检测中算「可达」，但对真实请求来说是不可用的。故障转移和熔断只根据经本地路由转发的真实请求的成败来判断，详见 [4.3 故障转移](./4.3-failover.md)。

## 常见问题

### 检测显示可达，但实际请求失败

连通检测不验证鉴权和模型。请检查：
- API Key 是否正确、是否与预设匹配
- 模型名是否被供应商支持
- 上游格式是否与供应商的接口一致（见 [2.1 添加供应商](../2-providers/2.1-add.md)）

### 显示无法连通

可能原因：
- 请求地址填写错误
- 网络不通，或需要通过代理才能访问（可在「设置 → 路由 → 全局出站代理」中配置）
- 防火墙阻止了连接

### 延迟过高

可能原因：
- 网络延迟
- 供应商服务器负载高

解决方法：
- 使用 [端点测速](../2-providers/2.1-add.md#端点测速) 选择更快的端点
- 调整较慢阈值
