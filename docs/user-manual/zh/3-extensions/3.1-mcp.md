# 3.1 MCP 服务器管理

## 什么是 MCP

MCP (Model Context Protocol) 是一种协议，允许 AI 工具访问外部数据源和工具。通过 MCP 服务器，你可以让 AI：

- 访问文件系统
- 执行网络请求
- 查询数据库
- 调用外部 API

## 打开 MCP 面板

点击左侧栏的 **MCP**。它是全局页，不属于某个应用：不管当前选中哪个应用，打开的都是同一个面板（Claude Desktop 没有自己的 MCP，这里也不会出现它的列）。

页面是一张矩阵表：**每行一个 MCP 服务器，每列一个应用**，格子里的开关就是「这个 MCP 在这个应用里启用」。

- 搜索框：按名称、命令或地址过滤
- 只显示在侧栏「应用」页里设为显示的应用的列；隐藏只影响界面，已经写进隐藏应用的配置照常保留、照常同步

- 某个应用写入失败时，该行会标出失败的应用，可以点「重试」

## 添加 MCP 服务器

### 使用模板

1. 点击页头的 **添加 MCP**，右侧打开抽屉
2. 在「从模板开始」里选一个模板，或者留空自己填
3. 按需修改，在「写入到」里勾选要启用的应用
4. 点击添加

### 粘贴配置

抽屉里的「粘贴配置」可以直接贴一段 JSON 或 TOML，自动识别 `mcpServers`、Codex 的 `[mcp_servers.名称]`、OpenCode 的 local / remote 写法，并填入下面的表单。一次贴了多个服务器时，会列出「新的」和「已存在同名」的条目，同名的可以选择跳过或覆盖。

### 常用模板

| 模板 | 包名 | 功能说明 |
|------|------|----------|
| fetch | mcp-server-fetch | HTTP 请求工具，让 AI 能够获取网页内容 |
| time | mcp-server-time（通过 `uvx` 运行） | 时间工具，提供当前时间信息 |
| memory | @modelcontextprotocol/server-memory | 记忆工具，让 AI 能够存储和检索信息 |
| sequential-thinking | @modelcontextprotocol/server-sequential-thinking | 思维链工具，增强 AI 推理能力 |
| context7 | @upstash/context7-mcp | 文档搜索工具，查询技术文档 |

### 自定义配置

不选模板、自己填写时，需要填写：

| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | 是 | 写进各应用配置文件里的键名，不能有空格；保存后不能改名，要改就新建一个再删旧的 |
| 连接方式 | 是 | 本地命令（stdio）/ HTTP / SSE |
| 命令 | 是* | 本地命令类型必填，只写程序（如 `npx`、`uvx`），参数另填 |
| 参数 | 否 | 命令行参数，一项一行 |
| 环境变量 | 否 | 传递给服务器的环境变量 |
| 工作目录 | 否 | 本地命令类型可选，留空时由应用决定 |
| 地址 | 是* | HTTP / SSE 类型必填，以 `http://` 或 `https://` 开头 |
| 请求头 | 否 | HTTP / SSE 类型的请求头 |
| 显示名、描述、标签、主页、文档 | 否 | 收在「说明与链接」里，只在 CC Switch 里显示，不写进应用配置 |

也可以点「在 JSON 中编辑」直接改整份配置，和表单是同一份数据，切换时自动同步；环境变量和请求头的值在 JSON 里显示为 `••••••••`，保存时保留原值。

## 传输类型

### stdio（标准输入输出）

最常用的类型，通过启动本地进程通信。

```json
{
  "command": "uvx",
  "args": ["mcp-server-fetch"],
  "env": {}
}
```

**要求**：
- 需要安装对应的命令（如 `uvx`、`npx`）
- 服务器程序需要在 PATH 中

### http

通过 HTTP 协议与远程服务器通信。

```json
{
  "url": "http://localhost:8080/mcp"
}
```

### sse（Server-Sent Events）

通过 SSE 协议与服务器通信，支持实时推送。Pi 不支持 SSE 类型。

```json
{
  "url": "http://localhost:8080/sse"
}
```

## 应用绑定

每个 MCP 服务器可以独立控制在哪些应用里启用：点矩阵里该行、该应用列的开关即可。

### 应用列说明

| 应用 | 作用 | 配置文件路径 |
|------|------|--------------|
| Claude Code | 同步到 Claude Code | `~/.claude.json` 的 `mcpServers` |
| Codex | 同步到 Codex | `~/.codex/config.toml` 的 `[mcp_servers]` |
| Gemini CLI | 同步到 Gemini CLI | `~/.gemini/settings.json` 的 `mcpServers` |
| Grok Build | 同步到 Grok Build | `~/.grok/config.toml` 的 `[mcp_servers]` |
| OpenCode | 同步到 OpenCode | `~/.config/opencode/opencode.json` 的 `mcp` |
| Hermes | 同步到 Hermes | `~/.hermes/config.yaml` 的 `mcp_servers` |
| Pi | 同步到 Pi（需 Pi 1.0 及以上） | `~/.pi/agent/mcp.json` |
| MiniMax Code | 同步到 MiniMax Code | `~/.minimax/mcp.json` |

> ⚠️ **注意**：Claude Desktop 和 OpenClaw 不支持 CC Switch 的 MCP 同步，所以表格里没有这两列。MCP 共支持上面 8 个应用。

点列头可以对这一列做批量操作：「启用其余 N 个」「全部启用」「全部关闭」，只作用于当前列表（搜索或筛选后则只作用于结果）里的条目，操作后可以点「撤销」。每行的 ⋯ 菜单里也有「在所有应用启用」和「全部关闭」。

### 开关实现机制

当开启某个应用的开关时，CC Switch 会：

1. **更新数据库**：将服务器在该应用上的启用状态设为 `true`
2. **同步到 Live 配置**：将服务器配置写入对应应用的配置文件
3. **即时生效**：下次启动 CLI 工具时自动加载新的 MCP 服务器

当关闭某个应用的开关时，CC Switch 会：

1. **更新数据库**：将对应应用状态设为 `false`
2. **从 Live 配置移除**：从应用配置文件中删除该服务器
3. **即时生效**：下次启动 CLI 工具时不再加载该 MCP 服务器

> 💡 CC Switch 只管理数据库里存在的服务器，你在各工具配置里手动添加、未导入 CC Switch 的服务器不会被改动；但直接改应用配置里与 CC Switch 同名的条目会被覆盖，以 CC Switch 里的为准。**MiniMax Code 和 Pi 例外**：批量同步时，在它们上面未启用的服务器不会从 `mcp.json` 中删除；只有在 CC Switch 里显式关闭或删除时才会移除。

### 同步条件

MCP 服务器同步仅在对应应用已安装时执行：

- **Claude**：需存在 `~/.claude/` 目录或 `~/.claude.json` 文件
- **Codex**：需存在 `~/.codex/` 目录
- **Gemini**：需存在 `~/.gemini/` 目录
- **Grok Build**：需存在 `~/.grok/` 目录
- **OpenCode**：需存在 `~/.config/opencode/` 目录
- **Hermes**：需存在 `~/.hermes/` 目录
- **Pi**：写入 `~/.pi/agent/mcp.json`（Pi 配置目录可用 `PI_CODING_AGENT_DIR` 指定）

> 💡 **提示**：如果某个 CLI 工具未安装，开启对应开关不会报错，但配置不会写入。MiniMax Code 例外：CC Switch 不检查它是否安装，会直接写入 `~/.minimax/mcp.json`，目录不存在时自动创建。

关闭开关后，配置会从文件中移除。

## 编辑服务器

1. 点击服务器行右侧的「编辑」按钮
2. 在抽屉里修改配置（名称不能改）
3. 点击「保存」

修改会立即同步到已启用的应用配置文件。

## 删除服务器

1. 点击服务器行右侧 ⋯ 菜单里的「删除」
2. 确认删除

删除后无法撤销，配置会从 CC Switch 以及所有已启用它的应用的配置文件中移除。

## 导入现有配置

如果你已经在 CLI 工具中配置了 MCP 服务器，可以导入到 CC Switch：

1. 点击 MCP 页面顶部的「从应用导入」按钮
2. CC Switch 会一次读取所有支持 MCP 的应用（Claude Code / Codex / Gemini CLI / Grok Build / OpenCode / Hermes / Pi / MiniMax Code）的现有配置并导入
3. 完成后弹出「导入完成」，列出新增了哪些 MCP 和读取了哪些文件；没有发现新服务器时会提示没有发现新的 MCP

导入只读用户级配置：Claude Code 里用 `claude mcp add` 默认加到项目里的 MCP、插件自带的 MCP 不会导入。

导入的服务器会自动在来源应用上启用；与已有服务器同名的，只会打开对应应用的开关，配置仍以 CC Switch 里的为准。从 MiniMax Code 导入时，启用状态沿用 `mcp.json` 里的 `enabled` 字段；与已有服务器配置冲突或配置无效的条目不会导入，此时会提示「有应用没有读到」并列出原因。

## 配置文件格式

### Claude (`~/.claude.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

### Codex (`~/.codex/config.toml`)

```toml
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

### Gemini (`~/.gemini/settings.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## 常见问题

### 服务器启动失败

检查：
- 命令是否正确安装（如 `uvx`）
- 命令是否在 PATH 中
- 参数是否正确

### 配置不生效

确保：
- 对应应用的开关已开启
- 重启了 CLI 工具
