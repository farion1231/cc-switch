# 4.2 App Routing

## Overview

App routing means letting CC Switch route a specific application's API requests through the local routing service. Each app has three connection modes, shown as the "Direct / Routing / Aggregation" tabs at the top of the app page:

| Mode | Description |
|------|-------------|
| Direct | The client connects straight to the provider; switching only changes key fields in the config file |
| Routing | Requests go through CC Switch on your machine first, then on to the provider; format conversion and failover are available |
| Aggregation | Claude Code and Codex only. Requests are split across multiple providers by the model picked in `/model`, with no failover; an official account can only be the default provider and can't join Aggregation |

This page covers "Routing". Once an app is routing:
- The app's API requests are forwarded through local routing
- Request logs and usage statistics can be recorded
- Failover functionality becomes available

## Prerequisites

Routing needs CC Switch to keep running. You don't need to start the routing service beforehand; it starts automatically when an app enters routing.

Apps that support routing: Claude Code, Codex, Gemini CLI, Grok Build.

## Start Routing

### Location

The "Routing" tab at the top of the app page.

### Steps

1. Select the app you want to route in the sidebar
2. Click the "Routing" tab at the top (viewing only; nothing is changed)
3. Click "Start routing", choose which provider to "Route to" in the confirmation dialog, then click "Start routing" to confirm

The dialog spells out the consequences: the address and key in the client config are rewritten, the real key stays in CC Switch, and other settings are untouched; after that, changing providers in the "Routing" tab no longer rewrites the config file; CC Switch needs to keep running, writes the direct config back when it quits, and reconnects on the next start.

Multiple apps can be routing at the same time. "Apps using routing" under "Settings → Local routing" lists them.

> ⚠️ Official providers (such as Claude Official) cannot be forwarded through local routing, so you can't switch to them in routing mode; the card shows "Official subscriptions don't go through routing; available again in direct mode." Codex's OpenAI Official is the exception.

## How Routing Works

### Configuration Changes

Once an app enters routing, CC Switch modifies the app's configuration file to point the API endpoint to the local routing service.

**Claude configuration change**:

```json
// Before routing
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com"
  }
}

// After routing
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:15721"
  }
}
```

**Codex configuration change**:

```toml
# Before routing
[model_providers.custom]
base_url = "https://api.example.com/v1"

# After routing
[model_providers.custom]
base_url = "http://127.0.0.1:15721/v1"
```

**Gemini configuration change**:

```bash
# Before routing
GOOGLE_GEMINI_BASE_URL=https://generativelanguage.googleapis.com

# After routing
GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:15721
```

**Grok Build configuration change**: the request address in the routing provider's model table in `~/.grok/config.toml` changes to `http://127.0.0.1:15721/grokbuild/v1`. Grok Build's official account can't be used through local routing: starting routing while the official provider is current reports an error, so switch to a third-party provider first.

While routing, the API Key in the config file is replaced with the placeholder `PROXY_MANAGED`; the real Key is injected by local routing when it forwards requests. As with switching providers, entering routing changes only these key fields; nothing else in the config file is touched.

### Request Forwarding

When the routing service receives a request:

1. Identifies the request source (Claude/Codex/Gemini/Grok Build)
2. Looks up the app's current routing target (by the queue when failover is on)
3. Converts the request format if needed and forwards the request to the provider's actual endpoint
4. Records the request log
5. Returns the response to the app

## Routing Status Indicators

### App Page Indicators

Once routing is active:

- The "Routing" tab carries an active marker, and "Routing is active → provider name" appears to its right ("by queue" when failover is on)
- The provider card being routed shows the "Routing" state
- If the routing service isn't running, the app page shows a notice with "Start service" and "Back to direct" buttons

### Provider Card States

| State | Description |
|-------|-------------|
| Routing | The provider actually used by routing |
| Direct | The direct provider, which is restored after leaving routing (the hover hint reads "Leaving routing mode switches back to this provider") |
| Route here | A button on other providers; click it to move the routing target to that provider |

## Leave Routing

### Steps

- Click "Back to direct" on the app page; this takes only that app out
- Or click "Switch all back to direct" in "Settings → Local routing"; all apps leave together and the routing service stops. See [4.1 Local Routing Service](./4.1-service.md#stop-local-routing)

### Configuration Restoration

When leaving routing, CC Switch will:

1. Write the app's config file back to the direct provider (the one in use before it entered routing, labeled "Direct" on its card), without relying on a backup taken when it entered routing
2. Save current request logs

Quitting CC Switch also writes the config file back to the direct provider first, while the app's mode stays as it is; local routing is reconnected the next time CC Switch starts.

## Routing and Provider Switching

### Switching Providers in Routing Mode

When switching providers in routing mode:

1. In the "Routing" tab, click "Route here" on a provider card (with failover on, adjust the queue instead; see [4.3 Failover](./4.3-failover.md))
2. The routing service immediately uses the new provider to forward requests
3. **No need to restart the CLI tool**

This is a major advantage of routing mode: provider switching takes effect instantly. After switching Codex, Gemini CLI, or Grok Build, the interface still prompts you to restart; while routing, you can skip the restart as long as the switch doesn't change the model.

In routing mode, switching changes only the provider that routing uses; the direct provider stays the same, is labeled "Direct" on its card, and is what you return to when you leave routing. If what the new provider writes to the config file (the local address, model name, etc.) is the same as before, switching doesn't touch the config file; if it differs (for example, a different model name), CC Switch updates the config file first, and Codex, Gemini CLI, and Grok Build then need a restart to use the new model.

### Switching in Direct Mode

When switching providers in direct mode:

1. Configuration file is modified
2. CLI tool must be restarted for changes to take effect

## Multi-app Routing

Multiple apps can be routed simultaneously, each managed independently:

- Independent provider configurations
- Independent failover queues
- Independent request statistics

## Use Cases

### Scenario 1: Usage Monitoring

Enter routing + "Record Request Usage" to record every request that passes through local routing. With routing off, CC Switch also collects usage from each tool's local session logs; see [4.4 Usage Statistics](./4.4-usage.md).

### Scenario 2: Quick Switching

Once routing, switching providers does not require restarting CLI tools.

### Scenario 3: Format Conversion

Using a provider with OpenAI or Gemini format with Claude Code, or a provider with Chat Completions / Anthropic Messages format with Codex or Grok Build, requires entering routing.

### Scenario 4: Failover

Entering routing is a prerequisite for using the failover feature.

## Notes

### Performance Impact

Routing adds minimal latency (typically < 10ms), negligible for most scenarios.

### Network Requirements

In routing mode, CLI tools must be able to access the local routing address.

### Configuration Backup

Routing doesn't rely on a backup: when you leave routing, CC Switch writes the config file again from the direct provider. Separately, before CC Switch rewrites each config file for the first time, it backs up the original to `~/.cc-switch/backups/live-first-write/`.

## FAQ

### Requests Fail After Entering Routing

Check:
- Is the routing service running normally (Settings → Local routing)
- Is the provider configuration correct
- Is the network working properly

### Configuration Not Restored After Going Back to Direct

Possible causes:
- Routing service exited abnormally
- Configuration file was modified by another program

Solutions:
- Manually edit the provider and re-save
- Or enter routing again and then leave it
