# 4.4 Usage Statistics

## Overview

The usage statistics feature records and analyzes API request data, helping you:

- Understand API usage patterns
- Estimate cost expenditure
- Analyze usage patterns
- Troubleshoot issues

Usage is a global page in the sidebar. Usage data comes from two sources:

| Data Source                     | Coverage                                  | Local Routing Required? |
| ------------------------------- | ----------------------------------------- | ----------------------- |
| **Routing request log**         | All requests forwarded through local routing | Yes                  |
| **CLI session log**             | Local session logs of Claude Code, Codex, Gemini CLI, Grok Build, OpenCode, Pi, MiniMax Code | No |

- Works without local routing: by default, CC Switch periodically scans each tool's local session logs and tallies requests, tokens, cache hit rate and cost by provider and model
- **Codex sessions**: **Precisely parsed** from JSONL session logs; model names are normalized for consistent pricing lookup
- The Usage page supports **per-app filtering** so data from different apps does not mix
- OpenClaw and Hermes don't support usage statistics yet; for Claude Desktop, only "Model Mapping" requests forwarded through local routing are counted, and they are included under the Claude Code filter

## Prerequisites

Depending on which data source you use, the prerequisites differ:

**Routing request log** (covers all requests forwarded through local routing):

1. ✅ Local routing started
2. ✅ Routing enabled for the corresponding app
3. ✅ "Record request usage" turned on (on by default, under Settings → Local routing)

**CLI session log** (no local routing required):

1. ✅ The corresponding CLI has session history files
2. ✅ "Scan session logs automatically" stays on (on by default). When it's off, scanning only happens when you click "Sync Now"
3. ✅ CC Switch scans once at startup and every 60 seconds after that, importing usage data

> Session logs can't tell which provider was used, so for these records the Provider column shows "{App} · Session logs".

## Open Usage Statistics

Click **Usage** in the left sidebar. It's a global page: you don't need to pick an app first, or turn on local routing.

The top right of the page has:

- **Sync Now**: scans the session logs right away (the last sync time is shown next to it)
- **Auto refresh**: sets how often the page data refreshes automatically; can be turned off
- **Data sources**: opens a side panel to manage session log scanning, "Record request usage", and Codex usage maintenance (see below)

## Statistics Overview

### Summary Cards

Key metrics displayed at the top of the page:

| Metric | Description |
|--------|-------------|
| Total Cost | Cost estimated from the pricing configuration |
| Total Requests | Total number of requests in the time period |
| Tokens Processed | Fresh input + output + cache writes + cache hits |
| Cache Hit Rate | Cache hits ÷ (fresh input + cache writes + cache hits) |

Click "More metrics" to expand the separate numbers for fresh input, output, cache writes and cache hits. Some protocols (such as OpenAI) don't report cache writes, so cache writes and tokens processed may read low.

When you change the time range, app, provider or model filter, these numbers update together and stay aligned with the logs and stats below.

### Time Range and Filters

| Time range | Description |
|------------|-------------|
| Today | From 00:00 today to now |
| Last 24 hours / Last 7 days / Last 14 days / Last 30 days | The corresponding period up to now |
| All | All history |
| Calendar Filter | Custom start and end date and time |

The filter row lets you:

- Filter by app: All / Claude Code / Codex / Gemini / OpenCode / Grok Build / Pi / MiniMax Code (Claude Desktop requests forwarded through local routing count toward Claude Code)
- Filter by provider and model from the dropdowns (the model list follows the selected provider)

OpenClaw and Hermes don't support usage statistics yet.

## Heatmap and Trend Charts

### Usage Heatmap

Shows daily usage over the last 53 weeks; darker colors mean more usage.

### Usage Trends

A line chart showing change over time; switch between three metrics: **Tokens / Requests / Cost**:

- Last 24 hours (and Today): shown by hour
- 7 days, 30 days and other longer ranges: shown by day
- Hover to see the exact numbers at that point in time

> 💡 **Cache Token explanation**: Anthropic API supports Prompt Caching. Creating cache incurs a higher fee (typically 1.25x input price), but subsequent cache hits only charge 0.1x, significantly reducing costs for repeated requests.

## Detailed Data

Four tabs at the bottom of the page: **Request Logs**, **Providers**, **Models**, **Pricing** (pricing is covered in the next section).

### Request Logs

Record of each request:

| Field | Description |
|-------|-------------|
| Time | Request time |
| App | The app it belongs to |
| Provider | Provider name used (records imported from session logs show "{App} · Session logs") |
| Model | Requested model |
| Fresh Input | Input tokens, excluding cache |
| Output | Output tokens |
| Cache Hit | Cache hit token count |
| Cost | Estimated cost (USD); models without pricing show "Unpriced" |
| Speed | Output tokens per second (see below) |

Hover to see details such as duration, time to first token and cache writes; click a request row to open the details panel, which shows the source (the routing service with its status code, or a session log), token usage, a cost breakdown and performance info. The status code filter at the top right of the table lets you view only requests with a certain kind of status code.

#### How Speed Is Calculated

Speed is output tokens per second, measured from the first token to the end. It's only counted for requests that went through local routing and output at least 100 tokens; for models that don't expose their thinking, it's an approximation.

With routing off, speed is estimated from session log timestamps and shown as "≈ xx tok/s": there's no first-token timing and the wait for the first token is included, so it reads low, and only requests with at least 200 output tokens are estimated.

### Providers

Statistics grouped by provider: requests, tokens, cost, success rate, speed.

### Models

Statistics grouped by model: requests, tokens, cost, average cost, success rate, speed.

## Data Sources Panel

Click "Data sources" at the top right of the page to open it:

- **Scan session logs automatically**: a switch, plus "Sync Now". The panel lists the apps covered, and "Hermes and OpenClaw don't support usage stats yet"
- **Record request usage**: shows whether it's on; click "Change" to jump to Settings → Local routing to adjust it
- **Codex Usage Maintenance**: "Rebuild Codex Usage" clears the existing Codex session details and aggregates, then re-imports them from the local Codex logs. The database is backed up automatically before rebuilding; history belonging to logs that have already been deleted can't be re-imported

## Pricing Configuration

### Open Pricing Configuration

Usage page → **Pricing** tab

"Pricing Defaults" at the top of the page decides whether each app matches pricing by the "requested model" or the "returned model"; click "Change" to adjust it. It only applies to requests through local routing; usage imported from session logs is priced by the model recorded in the log.

Below it is the "Model Pricing" table. Besides entering prices manually, you can click "Import from models.dev" in the "Add Pricing" / "Edit Pricing" dialog to import public model pricing.

### Configure Model Prices

Set prices for each model (per million tokens):

| Field | Description |
|-------|-------------|
| Model ID | Model identifier (e.g., claude-3-sonnet) |
| Display Name | Custom display name |
| Input Price | Price per million input tokens |
| Output Price | Price per million output tokens |
| Cache Read Price | Price per million cache hit tokens |
| Cache Creation Price | Price per million cache creation tokens |

### Model ID Normalization Rules

Before matching pricing, CC Switch normalizes the requested model ID:

- Remove everything before the last `/` and convert to lowercase
- Remove everything after `:` and trim a trailing `[1m]`
- Replace `@` with `-`
- Remove common wrapper prefixes, version suffixes, and date suffixes (`-YYYY-MM-DD`, `-YYYYMMDD`)
- Some model families can match a short ID to a versioned pricing entry

When adding pricing entries, enter the normalized Model ID rather than the full raw model name from the request.

| Raw model name | Model ID to enter | Note |
|-------|-------------------|------|
| `stepfun-ai/step-3.5-flash` | `step-3.5-flash` | Removes the provider prefix |
| `moonshotai/kimi-k2-0905:exa` | `kimi-k2-0905` | Removes the prefix and the `:` suffix |
| `gpt-5.2-codex@low` | `gpt-5.2-codex-low` | Replaces `@` with `-` |
| `OpenAI/GPT-5.5-2026-05-14` | `gpt-5.5` | Removes the prefix and date suffix |
| `anthropic/claude-opus-4.8` | `claude-opus-4-8` | Removes the prefix and matches dotted format |
| `global.anthropic.claude-opus-4-8-v1:0` | `claude-opus-4-8` | Removes wrapper prefix, version suffix, and `:` suffix |
| `claude-haiku-4-5` | `claude-haiku-4-5-20251001` | Matches a short ID to versioned pricing |

### Operations

- **Add**: Click the "Add" button to add model pricing
- **Edit**: Click the edit icon at the end of the row to modify
- **Delete**: Click the delete icon at the end of the row to remove

The Pricing tab also has "Automatic models.dev pricing sync": when on, CC Switch updates the prices of the models you choose from models.dev at startup (at most once every 6 hours). Both built-in and manually set prices for the same model ID are overwritten, so a confirmation appears before you turn it on. You can "Choose models", or let it include common models automatically.

## FAQ

### Statistics Data Is Empty

Check:
- Is "Scan session logs automatically" on, and does the corresponding CLI have session history (the data source when local routing is off)
- If you rely on routing request logs: is local routing running, is routing enabled for the corresponding app, and is "Record Request Usage" on
- Does the app support usage statistics (OpenClaw and Hermes don't yet)

### Cost Estimates Are Inaccurate

Possible causes:
- Pricing configuration doesn't match actual prices
- Using a relay service with special pricing

Solutions:
- Update pricing configuration
- Refer to the provider's actual invoices

### Token Count Differs from Provider

CC Switch uses its own method to estimate token counts, which may slightly differ from the provider's calculation. Refer to the provider's invoice for authoritative numbers.
