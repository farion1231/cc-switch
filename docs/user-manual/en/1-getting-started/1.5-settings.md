# 1.5 Personalization

This section describes how to configure CC Switch according to your preferences.

## Open Settings

- Click **Settings** at the bottom of the left sidebar
- Or use the shortcut `Cmd/Ctrl + ,` (opens "General" directly)

Settings takes a full screen: the left sidebar is replaced by the settings menu, which has 6 groups: **General, App config, Local routing, Network, Data, About**. Click "Back" above the menu (or press `Esc`) to return to the previous page. Settings only holds preferences; feature pages such as MCP, Skills, Prompts, and Sessions are in the left sidebar.

Toggle-type settings are saved immediately; path-type settings (configuration directories) need a click on that block's "Save" after you change them.

## General

### Appearance

| Setting | Description |
|---------|-------------|
| Language | Simplified Chinese, Traditional Chinese, English, Japanese; takes effect immediately without restarting |
| Light & dark | System / Light / Dark |

### Sidebar and header

- **Which apps show in the sidebar**: Click "Open Apps" to jump to the sidebar's "Apps" page and choose there which apps are shown (Claude Code, Claude Desktop, Codex, Gemini CLI, Grok Build, OpenCode, OpenClaw, Hermes, Pi, and MiniMax Code are available; at least one must stay visible)
- **Show project switcher**: When on, a project switcher appears at the top of the Claude Code, Claude Desktop, and Codex pages. Off by default

> 💡 **Use case**: If you only use Claude Code and Codex, you can hide the other apps to keep the sidebar clean.

### New versions of your apps

**Check for new versions of your apps at launch**: When on, CC Switch checks once at every launch whether the installed command-line apps have new versions, and shows a dot on "Apps" in the sidebar if it finds any. It does not upgrade anything automatically. Upgrades are done on the "Apps" page; see [1.2 Installation Guide](./1.2-installation.md#optional-install-the-tools-to-manage).

### Window and terminal

#### Launch on Startup

When enabled, CC Switch automatically runs when the system starts.

- **Windows**: Implemented via the registry
- **macOS**: Implemented via LaunchAgent
- **Linux**: Implemented via XDG autostart

Once enabled, a **Silent Startup** toggle appears: the main window is not shown at launch, and the app runs in the system tray only.

#### Minimize to Tray on Close

| "Minimize to tray on close" | When you click the window's close button |
|--------|-------------|
| On (default) | The window hides to the system tray and the app keeps running in the background |
| Off | The app exits completely |

Keeping it on is recommended, so you can switch providers quickly from the tray.

#### Application-level Window Buttons (Linux only)

When on, the app's own minimize, maximize/restore, and close buttons are used; when off, the system window mode is kept.

#### Preferred Terminal

Choose the terminal application used when you click "Open terminal" on a provider card. If the chosen terminal is unavailable, the system default terminal is used instead.

| Platform | Terminal Options |
|----------|-----------------|
| macOS | Terminal, iTerm2, Alacritty, Kitty, Ghostty, Otty, WezTerm, Kaku, Warp |
| Windows | CMD, PowerShell, Windows Terminal |
| Linux | GNOME Terminal, Konsole, Xfce4 Terminal, Alacritty, Kitty, Ghostty |

#### Lightweight Mode

Starting from v3.13.0, CC Switch adds **Lightweight Mode** — a **tray-only** running state that minimizes desktop footprint when idle.

**How to enter**: Right-click the tray icon → click **Lightweight mode**. The main window is **destroyed** (not just hidden), freeing UI resources and memory.

**How to exit**: Click **Open CC Switch** from the tray menu, or trigger CC Switch via deep link / relaunch. The window is **rebuilt on demand**, with state preserved.

| Aspect | Minimize to Tray | Lightweight Mode |
|--------|------------------|------------------|
| UI process | Kept in memory | Fully destroyed |
| Idle resource footprint | Same as normal run | Near zero |
| Reopen speed | Instant (direct show) | Slightly slower (window rebuild) |
| Tray switching | Available | Available |
| Deep link wake | Available | Available (on-demand rebuild) |

> ⚠️ **Note**: Lightweight Mode state is not persistent — the next normal launch returns to normal mode. Combine with Launch on Startup for long-term use.

## App config

One block per app, holding the toggles and configuration directory that belong only to it.

### Claude Code

- **Apply to Claude Code extension**: When on, the provider of the Claude Code extension in VS Code follows CC Switch when you switch (writes `primaryApiKey` to `~/.claude/config.json`). If you use both the Claude Code CLI and the VS Code extension, turning it on keeps the two in sync
- **Skip Claude Code first-run confirmation**: When on, skips the first-run confirmation that Claude Code shows on its first launch.

> ⚠️ **Note**: "Skip Claude Code first-run confirmation" writes `hasCompletedOnboarding: true` to `~/.claude.json`; turning it off removes the field.

### Codex App Enhancements

Contains two toggles, both off by default:

**Keep official login for direct switches**:

- **Off**: When local routing is not enabled, every switch to a third-party provider deletes `~/.codex/auth.json`, so Codex has no official login while you use the third-party provider. Before deleting it, CC Switch stashes the login on this computer (`~/.cc-switch/codex-login-stash.json`, not included in cloud sync) and restores it automatically when you switch back to the official provider, so you don't need to log in again
- **On**: Direct switches to a third-party provider keep `~/.codex/auth.json`, so the official login stays in place while you use the third-party provider and features that need it keep working

A third-party provider's API key is always written only to `~/.codex/config.toml` and never to `auth.json`; with local routing enabled, the official login is always kept. See the guide [Keep Codex Remote Control and Official Plugins While Using Third-Party APIs](../../../guides/codex-official-auth-preservation-guide-en.md).

**Unified Codex session history**: When enabled, the official subscription runs under a shared custom provider ID, so official and third-party sessions appear in the same history list; you can optionally migrate existing official sessions as well (they are backed up automatically before migration). When turned off, they can be restored from the backup. Note: when you continue an old session with a different provider, that provider's backend may be unable to decrypt the reasoning content in the session, and the continuation will fail. See the guide [Unified Codex Session History](../../../guides/codex-unified-session-history-guide-en.md).

### Configuration Directory

Claude Code, Codex, Gemini CLI, Grok Build, OpenCode, OpenClaw, Hermes, and Pi — these 8 apps each have a "Config directory" row that can point somewhere else; leave it empty to use the default. MCP, Skills, and prompt paths change accordingly.

| App | Default |
|-----|---------|
| Claude Code | `~/.claude/` |
| Codex | `~/.codex/` |
| Gemini CLI | `~/.gemini/` |
| Grok Build | `~/.grok/` |
| OpenCode | `~/.config/opencode/` |
| OpenClaw | `~/.openclaw/` |
| Hermes | `~/.hermes/` |
| Pi | `~/.pi/agent/` |

Claude Desktop and MiniMax Code do not support overriding the directory here (so they are not in App config). MiniMax Code's data directory defaults to `~/.minimax/` and can be set with the `MINIMAX_DATA_DIR` (or `MAVIS_DATA_DIR`) environment variable; Hermes also recognizes `HERMES_HOME`, and Pi also recognizes `PI_CODING_AGENT_DIR`.

> 💡 **WSL**: CC Switch does not detect WSL automatically. On Windows, you can set a directory to a path inside WSL (e.g. `\\wsl.localhost\Ubuntu\home\<username>\.claude`); CC Switch then reads and writes the configuration inside WSL.

> ⚠️ **Note**: After changing directories, the app must be restarted, and the corresponding CLI tools must also be configured to use the same directory.

> 💡 **Skill storage location and sync method** are not in Settings: on the sidebar's "Skills" page, click "Storage and sync" to choose whether the master copies live in the "CC Switch directory" or the "Common directory" (`~/.agents/skills`), and whether syncing to each app uses symlinks or copies.

## Local routing

Settings → Local routing

This group centralizes the global parts of local routing:

- **Service**: Shows the routing service's running state (uptime, total requests, success rate, active connections) and lets you "Start" / "Stop" it. The "Listen address and port" defaults to `127.0.0.1`; click "Save and restart service" after changing it. When "Record request usage" is off, Usage has no per-request details for routed requests. The service cannot be stopped while apps are still using it; switch them back to direct first
- **Apps using routing**: Lists the apps currently in Routing or Aggregation mode; click "Open" to jump to that app's page. "Switch all back to direct" writes every app's direct configuration back and stops the routing service; route targets, queues, and aggregation lists are kept
- **Auto Failover**: Tune each app's timeouts, retries, and circuit breaker. Queues are managed on the "Routing" tab of each app page. See [4.3 Failover](../4-proxy/4.3-failover.md)
- **Rectifier**: Automatically fixes some requests that are incompatible with the upstream; for example, when a Thinking signature is incompatible, it removes the related content and retries

The entry to Routing or Aggregation is the "Direct / Routing / Aggregation" tabs at the top of each app page; see [4.1 Local Routing Service](../4-proxy/4.1-service.md).

## Network

Settings → Network

**Global Outbound Proxy**: Configure the HTTP/HTTPS proxy CC Switch uses when accessing external APIs, applicable for scenarios where external API access requires a proxy.

## Data

Settings → Data

### Location

**CC Switch configuration directory**: The storage location for CC Switch's own data, defaulting to `~/.cc-switch/`; it can be pointed at a cloud-synced folder. Click "Save" after changing it; the app must be restarted for it to take effect.

### Data Management

#### Export Configuration

Click the "Export SQL Backup" button to save a SQL backup file containing:

- All provider configurations
- MCP server configurations
- Prompt presets
- Usage logs
- App settings

The exported file name format is `cc-switch-export-{timestamp}.sql`.

#### Import Configuration

1. Click "Select SQL File"
2. Select a previously exported backup file
3. When the button changes to "Import", click it to start importing
4. After a successful import, the backup ID that was created automatically before the import is shown

> ⚠️ **Note**: Importing will overwrite existing configuration. It is recommended to export your current configuration as a backup first.

### Backup & Restore

The Backup Management panel provides full control over database backups.

#### Auto-Backup Settings

| Setting | Options | Default |
|---------|---------|---------|
| Auto-backup Interval | Disabled, 6h, 12h, 24h, 48h, 7d | 24 hours |
| Backup Retention | 3, 5, 10, 15, 20, 30, 50 | 10 backups |

When an interval is set, CC Switch automatically backs up the database on schedule. Older backups beyond the retention count are automatically removed.

#### Backup List

The panel displays all existing backups with:
- **Display name** (auto-generated from timestamp, e.g., `db_backup_20260315_143000`)
- **Creation time**
- **File size** (e.g., "1.5 MB")

#### Backup Operations

| Action | Description |
|--------|-------------|
| **Backup Now** | Create a backup immediately |
| **Restore** | Restore the database from a selected backup. A safety backup of the current database is created automatically before restoring |
| **Rename** | Change the backup's display name |
| **Delete** | Permanently remove a backup (with confirmation) |

> ⚠️ **Important**: Restoring a backup overwrites the current database. A safety backup is always created before the restore operation, so you can recover if needed.

#### Other Backups

The "Other Backups" overview below the backup list lists the backups CC Switch has left in various places (Skill uninstall backups, first-write backups of configuration files, Codex session migration backups, Hermes / OpenClaw configuration backups, leftover files from older versions, and so on), showing each item's location and size, with the total size next to the heading. Each item can be shown in the file manager, or you can "Delete" it yourself (with confirmation; permanent). Database backups are managed in the list above.

> ⚠️ For some backups, deleting them means the matching content can no longer be recovered: for example, after deleting the "first-write backup of configuration files" you can no longer find the original files from before they were rewritten, and after deleting a "Skill uninstall backup" an uninstalled Skill can no longer be restored; the note under each item spells out the consequences.

### Cloud Sync

Sync configurations across multiple devices via **WebDAV** or **S3-compatible storage**; only one of the two can be enabled at a time. Uses **v2 protocol** with dual-layer versioning for improved reliability.

#### WebDAV

| Setting | Description |
|---------|-------------|
| Provider | Jianguoyun / Nextcloud / Synology NAS / Custom |
| WebDAV Server URL | WebDAV server URL |
| WebDAV Account | Login username |
| WebDAV Password | Login password (app-specific password; saved credentials are preserved if left unchanged) |
| Remote Root Directory | Remote storage path (default: `cc-switch-sync`) |
| Sync Profile Name | Device profile name (default: `default`) |
| Auto Sync | When enabled, every database change is uploaded automatically |

#### S3-Compatible Storage

| Setting | Description |
|---------|-------------|
| Provider | AWS S3 / MinIO / Cloudflare R2 / Alibaba Cloud OSS / Tencent Cloud COS / Huawei OBS / S3 Compatible (Custom) |
| Region | e.g. `us-east-1`; use `auto` for R2 |
| Bucket | The bucket that stores the sync data |
| Access Key ID / Secret Access Key | Access credentials |
| Endpoint | Can be left empty for AWS; required by most S3-compatible services |
| Remote Root Directory | Default: `cc-switch-sync` |
| Sync Profile Name | Default: `default` |
| Auto Sync | When enabled, every database change is uploaded automatically |

#### Operations

| Action | Description |
|--------|-------------|
| **Test Connection** | Verify that the service address and credentials are valid |
| **Upload** | Upload local database to remote. Shows progress spinner |
| **Download** | Download remote database. Shows remote snapshot info (protocol version, DB version, timestamp, size) before confirming. A safety backup of the local database is created automatically before overwriting |

#### Auto-Sync

When **Auto Sync** is enabled:
- A confirmation dialog is shown on first activation
- After every database change, CC Switch automatically uploads the database to the cloud
- The panel shows the last sync time; if an auto sync fails, the error is displayed and the upload is retried on subsequent changes

#### Remote Snapshot Info

Before downloading, CC Switch displays details about the remote snapshot:
- Protocol version (v2)
- Database compatibility version
- Timestamp of the remote backup
- File size
- Compatibility status (warning if incompatible)

> ⚠️ **Note**: Upload overwrites remote data, and download overwrites local data. A safety backup is always created before downloading.

### Application Diagnostic Logs

| Setting | Description |
|---------|-------------|
| Enable Diagnostic Logs | Controls `cc-switch.log`; does not affect request usage records or `crash.log` |
| Log Level | error / warn / info / debug / trace |

Log level descriptions:

- **error** - Critical errors only
- **warn** - Warnings and errors
- **info** - General information (default)
- **debug** - Detailed debugging information
- **trace** - All verbose information

## Accounts (Beta)

The sign-in entry is "Accounts" in the left sidebar, not in Settings. Added in v3.13.0, **Accounts** (formerly the OAuth Authentication Center) provides unified management for third-party OAuth credentials. It currently supports three account types:

| Account Type              | Purpose                                                    |
| ------------------------- | ---------------------------------------------------------- |
| **GitHub Copilot**        | Used with the Copilot reverse proxy                        |
| **ChatGPT (Codex OAuth)** | Used with the Codex OAuth reverse proxy; manage ChatGPT accounts |
| **xAI (Grok OAuth)**      | Used with the xAI Responses API reverse proxy                   |

**What you can do here**:

- Log in to ChatGPT / GitHub / xAI accounts via the Device Code flow
- View the list of logged-in accounts and authentication status
- Set a default account when managing multiple accounts
- Remove individual accounts or log out all accounts at once

The xAI integration uses the OAuth 2.0 Device Authorization Grant, not a loopback callback. Its network contract is explicit:

| Dependency | Endpoint |
| ---------- | -------- |
| OpenID discovery | `https://auth.x.ai/.well-known/openid-configuration` |
| Device authorization | `device_authorization_endpoint` from discovery (currently `https://auth.x.ai/oauth2/device/code`) |
| Token exchange / refresh | `token_endpoint` from discovery (currently `https://auth.x.ai/oauth2/token`) |
| Inference | `https://api.x.ai/v1/responses` |
| Model discovery | `https://api.x.ai/v1/models` |

There is no local callback port. Authentication and model requests use CC Switch's global outbound proxy configuration.

The xAI integration does **not** use an OAuth application registered to CC Switch. It reuses the public OAuth client identity and scopes registered for the official Grok CLI (`client_id: b1a00492-073a-47ea-816f-4c329264a828`, including `grok-cli:access`) to obtain account-backed API access.

> ⚠️ **Warning**: These account-backed reverse proxies use reverse-engineered OAuth integrations and carry account and Terms of Service risk. Reusing an upstream product's OAuth client may be unsupported and may cause the provider to restrict or suspend the account. Review the applicable provider terms and use these features at your own risk. For the existing Codex flow, also read the full risk notice in [2.1 Add Provider → Codex OAuth Reverse Proxy](../2-providers/2.1-add.md#codex-oauth-reverse-proxy-claude-provider).

## About Page

Settings → About

### Version Information

Displays the current CC Switch version number, with support for:

- Checking for updates; when a new version is available, click "Update to vX" to download and install it (the portable version must be downloaded manually)
- Viewing GitHub, the official website, and the release notes
- "Recent updates": view the update summaries of the last few versions again

### Tool Installation and Upgrades

Version detection, installation, upgrades, and "Update All" for the AI coding tools are not here but on the sidebar's "Apps" page; see [1.2 Installation Guide](./1.2-installation.md#optional-install-the-tools-to-manage). On Windows, if you set a tool's directory to a WSL path in "App config", the "Apps" page detects and updates that tool in the corresponding WSL distribution.
