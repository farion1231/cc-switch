# 3.1 MCP Server Management

## What is MCP

MCP (Model Context Protocol) is a protocol that allows AI tools to access external data sources and tools. Through MCP servers, you can enable AI to:

- Access file systems
- Make network requests
- Query databases
- Call external APIs

## Open the MCP Panel

Click **MCP** in the left sidebar. It is a global page that does not belong to any one app: whichever app is currently selected, you open the same panel (Claude Desktop has no MCP of its own, so it has no column here either).

The page is a matrix table: **one row per MCP server, one column per app**. The switch in each cell means "this MCP is enabled in this app".

- Page header: "Import from apps", "Add MCP", and a ⋯ menu ("Rewrite every app's config from these switches", "Copy all as mcpServers JSON")
- Search box: filters by name, command, or URL
- Only the columns for apps set to show on the sidebar's "Apps" page are displayed; hiding only affects the UI, and configuration already written to a hidden app is kept and still synced
- Each row has an "Edit" button on the right and a ⋯ menu (Copy as JSON, Open docs, Enable in all apps, Turn off everywhere, Delete)
- If writing to an app fails, the row marks the failed app and you can click "Retry"

## Add MCP Server

### Using a Template

1. Click **Add MCP** in the page header; a drawer opens on the right
2. Under "Start from a template", pick a template, or leave it empty and fill things in yourself
3. Adjust as needed, and tick the apps to enable under "Write to"
4. Click Add

### Paste a Config

"Paste a config" in the drawer accepts a block of JSON or TOML directly. It recognizes `mcpServers`, Codex's `[mcp_servers.name]`, and OpenCode's local / remote format, and fills in the form below. If you paste several servers at once, the entries are listed as "New" or "Name already exists", and for same-name entries you can choose Skip or Replace.

### Common Templates

| Template | Package Name | Description |
|----------|-------------|-------------|
| fetch | mcp-server-fetch | HTTP request tool that enables AI to fetch web content |
| time | mcp-server-time (run via `uvx`) | Time tool that provides current time information |
| memory | @modelcontextprotocol/server-memory | Memory tool that enables AI to store and retrieve information |
| sequential-thinking | @modelcontextprotocol/server-sequential-thinking | Chain-of-thought tool that enhances AI reasoning |
| context7 | @upstash/context7-mcp | Documentation search tool for querying technical docs |

### Custom Configuration

If you don't pick a template and fill things in yourself, you need:

| Field | Required | Description |
|-------|----------|-------------|
| Name | Yes | The key written into each app's config file; no spaces allowed. It can't be changed after saving; to rename, create a new one and delete the old one |
| Transport | Yes | Local command (stdio) / HTTP / SSE |
| Command | Yes* | Required for local command type; enter only the program (such as `npx` or `uvx`), and put arguments in their own field |
| Arguments | No | Command-line arguments, one per line |
| Environment variables | No | Environment variables passed to the server |
| Working directory | No | Optional for local command type; if left empty, the app decides |
| URL | Yes* | Required for HTTP / SSE type; must start with `http://` or `https://` |
| Headers | No | Request headers for HTTP / SSE type |
| Display name, Description, Tags, Homepage, Docs | No | Grouped under "Description & links"; shown only in CC Switch and not written to app configs |

You can also click "Edit in JSON" to edit the whole configuration directly. It is the same data as the form and stays in sync when you switch; the values of environment variables and headers appear as `••••••••` in JSON, and the original values are kept when you save.

## Transport Types

### stdio (Standard I/O)

The most common type, communicating by launching a local process.

```json
{
  "command": "uvx",
  "args": ["mcp-server-fetch"],
  "env": {}
}
```

**Requirements**:
- The corresponding command must be installed (e.g., `uvx`, `npx`)
- The server program must be in PATH

### http

Communicates with a remote server via HTTP protocol.

```json
{
  "url": "http://localhost:8080/mcp"
}
```

### sse (Server-Sent Events)

Communicates with a server via SSE protocol, supporting real-time push. Pi does not support the SSE type.

```json
{
  "url": "http://localhost:8080/sse"
}
```

## App Binding

Each MCP server can independently control which apps it is enabled for: click the switch in that row and app column of the matrix.

### App Columns

| App | Effect | Configuration File Path |
|--------|--------|------------------------|
| Claude Code | Sync to Claude Code | `~/.claude.json`'s `mcpServers` |
| Codex | Sync to Codex | `~/.codex/config.toml`'s `[mcp_servers]` |
| Gemini CLI | Sync to Gemini CLI | `~/.gemini/settings.json`'s `mcpServers` |
| Grok Build | Sync to Grok Build | `~/.grok/config.toml`'s `[mcp_servers]` |
| OpenCode | Sync to OpenCode | `~/.config/opencode/opencode.json`'s `mcp` |
| Hermes | Sync to Hermes | `~/.hermes/config.yaml`'s `mcp_servers` |
| Pi | Sync to Pi (requires Pi 1.0 or later) | `~/.pi/agent/mcp.json` |
| MiniMax Code | Sync to MiniMax Code | `~/.minimax/mcp.json` |

> ⚠️ **Note**: Claude Desktop and OpenClaw do not support CC Switch MCP sync, so the table has no columns for them. MCP is supported for the 8 apps above.

Click a column header for bulk actions on that column: "Enable the other N", "Enable all", and "Turn all off". They apply only to the entries in the current list (or only to the results after a search or filter), and you can click "Undo" afterwards. Each row's ⋯ menu also has "Enable in all apps" and "Turn off everywhere".

### Toggle Implementation

When enabling an app's toggle, CC Switch will:

1. **Update database**: Set the server's enabled status for that app to `true`
2. **Sync to live configuration**: Write the server configuration to the corresponding app's configuration file
3. **Take effect immediately**: The new MCP server is automatically loaded the next time the CLI tool starts

When disabling an app's toggle, CC Switch will:

1. **Update database**: Set the corresponding app status to `false`
2. **Remove from live configuration**: Delete the server from the app's configuration file
3. **Take effect immediately**: The MCP server is no longer loaded the next time the CLI tool starts

> 💡 CC Switch only manages servers that exist in its database; servers you added by hand in a tool's configuration and never imported into CC Switch are left untouched; however, if you edit an entry with the same name as one in CC Switch directly in an app's configuration, it is overwritten and CC Switch's version wins. **MiniMax Code and Pi are the exceptions**: during a bulk sync, servers that are not enabled for them are not deleted from `mcp.json`; they are removed only when you explicitly turn them off or delete them in CC Switch.

### Sync Conditions

MCP server sync only executes when the corresponding app is installed:

- **Claude Code**: Requires `~/.claude/` directory or `~/.claude.json` file to exist
- **Codex**: Requires `~/.codex/` directory to exist
- **Gemini CLI**: Requires `~/.gemini/` directory to exist
- **Grok Build**: Requires `~/.grok/` directory to exist
- **OpenCode**: Requires `~/.config/opencode/` directory to exist
- **Hermes**: Requires `~/.hermes/` directory to exist
- **Pi**: Writes to `~/.pi/agent/mcp.json` (the Pi configuration directory can be set with `PI_CODING_AGENT_DIR`)

> 💡 **Tip**: If a CLI tool is not installed, enabling its toggle will not cause an error, but the configuration will not be written. MiniMax Code is the exception: CC Switch does not check whether it is installed and writes `~/.minimax/mcp.json` directly, creating the directory if it does not exist.

When the toggle is disabled, the configuration is removed from the file.

## Edit Server

1. Click the "Edit" button on the right side of the server row
2. Modify the configuration in the drawer (the name can't be changed)
3. Click "Save"

Changes are immediately synced to enabled app configuration files.

## Delete Server

1. Click "Delete" in the ⋯ menu on the right side of the server row
2. Confirm deletion

Deletion cannot be undone. The configuration is removed from CC Switch and from the configuration files of every app it was enabled for.

## Import Existing Configurations

If you have already configured MCP servers in CLI tools, you can import them into CC Switch:

1. Click the "Import from apps" button at the top of the MCP page
2. CC Switch reads the existing configuration of every MCP-capable app (Claude Code / Codex / Gemini CLI / Grok Build / OpenCode / Hermes / Pi / MiniMax Code) in one pass and imports it
3. When finished, an "Import finished" dialog lists which MCP servers were added and which files were read; if no new servers are found, it tells you no new MCP servers were found

Import reads only user-level configuration: MCP servers that `claude mcp add` adds to a project by default in Claude Code, and MCP servers bundled with plugins, are not imported.

Imported servers are automatically enabled for the app they came from; for servers with the same name as an existing one, only the switch for the corresponding app is turned on, and the configuration stays as it is in CC Switch. When importing from MiniMax Code, the enabled status follows the `enabled` field in `mcp.json`; entries that conflict with an existing server's configuration or are invalid are not imported, in which case a message "Some apps couldn't be read" appears along with the reasons.

## Configuration File Formats

### Claude (`~/.claude.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

### Codex (`~/.codex/config.toml`)

```toml
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

### Gemini (`~/.gemini/settings.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## FAQ

### Server Fails to Start

Check:
- Is the command properly installed (e.g., `uvx`)
- Is the command in PATH
- Are the arguments correct

### Configuration Not Taking Effect

Ensure:
- The corresponding app toggle is enabled
- The CLI tool has been restarted
