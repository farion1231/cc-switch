# 3.3 Skills Management

## Overview

Skills are reusable capability extensions that give AI tools specialized abilities in specific domains.

Skills exist as folders containing:

- Prompt templates
- Tool definitions
- Example code

## Supported Applications

Skills are supported in the following applications:

- **Claude Code** (the Skills page on the Claude Desktop page also works on Claude Code)
- **Codex**
- **Gemini CLI**
- **Grok Build**
- **OpenCode**
- **Hermes**
- **Pi**
- **MiniMax Code**

OpenClaw does not support Skills management yet.

## Open the Skills Page

Click **Skills** in the left sidebar. It is a global page that does not belong to any one app: whichever app is currently selected, you open the same page (Claude Desktop has no Skills of its own, so it has no column here either).

The top of the page has two views you can switch between: **Installed** and **Discover**.

## Page Overview

"Installed" is a matrix table: **one row per Skill, one column per app**. The switch in each cell means "this Skill is enabled in this app".

- Page header: the "Add Skill" button, and a ⋯ menu (Check Updates, Restore from backup, Manage repositories, Storage and sync)
- Search box: searches by name, directory, description, or repository
- Filters: All / Has updates / Not enabled anywhere / Enabled in a given app, and you can also filter by source repository
- Only the columns for apps set to show on the sidebar's "Apps" page are displayed; hiding only affects the UI, and Skills already enabled are kept
- After selecting several rows you can bulk "Enable in" an app, Disable, Update, or Uninstall them
- Click a column header to bulk-enable or turn off a whole column; it applies only to the entries in the current list
- Pi has no separate switch data; whether a Skill is enabled is determined by whether that directory exists in `~/.pi/agent/skills`

## Discover Skills

Switch to the "Discover" view to browse and search for installable Skills.

### Pre-configured Repositories

CC Switch comes pre-configured with several GitHub skill repositories, including Anthropic Official (`anthropics/skills`) and ComposioHQ (`ComposioHQ/awesome-claude-skills`). The "Repos" button in Discover lets you choose which repositories take part in discovery, and "Reload repositories" re-scans them to get the latest skills.

### Search

- "Repos" source: search by Skill name or repository name, filtering as you type; you can switch between "Show all" and "Not installed only"
- "skills.sh" source: search the [skills.sh](https://skills.sh) public registry; enter at least 2 characters and press Enter to search, and results can be extended with "Load More"

## Install Skills

### Steps

1. Find the Skill you want to install in the "Discover" view
2. First choose under "Install to" which apps to enable it in (your last choice is remembered and used by default)
3. Click "Install" on that row and wait for it to finish

Once installed, it is enabled in the chosen apps right away, and you can adjust that at any time under "Installed". Besides installing from a repository, the page header's "Add Skill" menu offers:

- **Browse in Discover**: switch to the "Discover" view
- **Install from ZIP**: pick a ZIP containing `SKILL.md`; Skills whose directory name is already taken are skipped, and to use the version in the ZIP, uninstall the one with the same name first and then install
- **Import from this computer**: import Skills that already exist in the apps' directories on this computer but are not yet managed by CC Switch. Importing copies them into CC Switch's directory and leaves the originals untouched

When the page shows a notice such as "N Skills on this computer aren't managed by CC Switch", you can click "Review and import".

### Installation Location

| Application | Install Directory |
|-------------|-------------------|
| Claude Code | `~/.claude/skills/` |
| Codex | `~/.codex/skills/` |
| Gemini CLI | `~/.gemini/skills/` |
| Grok Build | `~/.grok/skills/` |
| OpenCode | `~/.config/opencode/skills/` |
| Hermes | `~/.hermes/skills/` |
| Pi | `~/.pi/agent/skills/` |
| MiniMax Code | `~/.minimax/skills/` |

If you override a configuration directory in Settings, the install directory changes accordingly (MiniMax Code's data directory can be set with the `MINIMAX_DATA_DIR` environment variable, and Pi additionally recognizes `PI_CODING_AGENT_DIR`). The master copy of each skill lives in the directory chosen under "Storage and sync" (default `~/.cc-switch/skills/`; see [Storage and Sync](#storage-and-sync) below) and is synced to each app's directory by symlink or file copy.

### Installation Contents

Installation copies the skill folder to your local machine:

```
~/.claude/skills/
└── skill-name/
    ├── README.md
    ├── prompt.md
    └── tools/
        └── ...
```

## Uninstall Skills

### Steps

1. Under "Installed", find the Skill and click "Uninstall" in that row's ⋯ menu (you can also select several and uninstall them in bulk)
2. Confirm uninstallation

### Uninstall Effect

- **Automatic backup**: Before deletion, the skill is backed up to `~/.cc-switch/skill-backups/`
- Removes the skill from every app's skills directory
- Removes the skill from the storage directory holding the master copy (default `~/.cc-switch/skills/`)
- Deletes the skill record from the database

### Restore from Backup

If you need to restore a previously uninstalled skill:

1. Open the Skills page
2. Click **Restore from backup** in the page header's ⋯ menu
3. Select the backup you want to restore from the list (shows skill name and backup date) and click "Restore"
4. The skill is restored and enabled in the apps chosen under "Install to" in Discover

### Delete Backups

To remove old skill backups:

1. In the restore dialog, find the backup you want to remove
2. Click the **Delete** button next to the backup entry
3. Confirm deletion — this cannot be undone

## Repository Management

### Open Repository Management

Click "Manage repositories" in the page header's ⋯ menu (the "Repos" button in the Discover view also has an "Add or manage repositories" entry).

### Add Custom Repository

1. In "Repository URL", enter `owner/name` or the full `https://github.com/owner/name`
2. Fill in the branch (default main)
3. The skills path is optional: the subdirectory containing skills; leave it empty to scan the root directory
4. Click "Add Repository"

After it is added successfully, a message tells you how many skills were detected.

### Delete Repository

In the "Added Repositories" list, click the delete button on the right of the repository.

After deleting a repository, skills already installed will not disappear, but they can no longer be updated from that repository.

## Skill Row Information

Each row under "Installed" displays:

| Information | Description |
|-------------|-------------|
| Name, description | Skill name and function description |
| Source | The repository it belongs to; locally imported ones show "Local" |
| Per-app switches | Which apps it is enabled in; apps where writing failed are marked, and you can click "Change sync method" to adjust |
| New version | Shows "Update" when the remote has an update |

## Skill Updates

Skills support **update detection** and **batch updates** — no need to uninstall and reinstall.

### Update Detection Mechanism

CC Switch compares installed skills with the remote repository version using **SHA-256 content hashes**. Whenever the remote has any file content changes, the corresponding skill is marked as updatable.

### Check for Updates

Click "Check Updates" in the page header's ⋯ menu, or "Check Updates" next to the search box under "Installed", to re-scan the remote repositories. The page shows the "Last checked" time; if some repositories couldn't be read, a notice appears and the update results may be incomplete.

### Single Update and Update All

- For a Skill with a new version, click "Update" on that row
- When Skills have updates, the page header shows "N updates"; click it to show only those with updates. "Update all (N)" in the filter bar updates them in bulk, with a confirmation before updating

> ⚠️ Updating replaces the local directory with the repository's content; local changes are kept only in the backup.

## Storage and Sync

Click "Storage and sync" in the page header's ⋯ menu to set two things:

### Where Master Copies Are Kept

| Location | Description |
|----------|-------------|
| **CC Switch folder** | Default location `~/.cc-switch/skills/`, managed by CC Switch |
| **Shared folder** (`~/.agents/skills`) | A shared directory conforming to community agent tool conventions, better for cross-tool collaboration |

When switching, click "Move and switch"; CC Switch moves the master copies one by one and then points the links in each app to the new location, so no skill state is lost. Do not quit CC Switch until the move finishes.

> ⚠️ After choosing the "Shared folder", Codex, Gemini CLI, OpenCode and others read this folder directly, so the per-app switches no longer fully apply to them.

### How Skills Reach Each App

| Method | Description |
|--------|-------------|
| Automatic (recommended) | Symlink first, copy if that fails |
| Symlink only | Requires Developer Mode on Windows |
| Copy only | Uses more disk space; copied again after each update |

Changes only apply to Skills you enable or update afterwards; to make already-enabled Skills use the current method too, click "Resync now".

## Troubleshooting

### Empty Skill List

Possible causes:

- Network issues preventing GitHub access
- Incorrect repository configuration

Solutions:

- Check network connection
- Click "Reload repositories" to retry
- Verify repository configuration

### Installation Failed

Possible causes:

- Network issues
- Insufficient disk space
- Permission issues

Solutions:

- Check network connection
- Check disk space
- Check directory permissions

### Update Button Not Showing

Possible causes:

- The remote repository has no new content
- CC Switch has not finished the latest scan

Solutions:

- Click "Check Updates" to rescan
- Confirm the repository configuration points to the right branch and path
