# 3.2 Prompts Management

## Overview

The Prompts feature manages system prompt presets. System prompts influence the AI's behavior and response style.

With CC Switch, you can:

- Create multiple prompt presets
- Quickly switch prompts for different scenarios
- Sync prompt configurations across devices

## Open the Prompts Panel

Click **Prompts** in the left sidebar. It is a global page, and the dropdown on the left of the page header selects the app: Claude Code, Codex, Gemini CLI, Grok Build, OpenCode, Hermes, Pi, MiniMax Code (only apps set to show on the "Apps" page are listed).

- Claude Desktop has no prompts of its own; entering from its page works on Claude Code's prompts.
- OpenClaw is not on the Prompts page; its AGENTS.md and other files are managed with the [workspace editor](./3.5-workspace.md).
- For Hermes, this page manages the persona file `SOUL.md`; `MEMORY.md` and `USER.md` are edited on the "Memory" page of the Hermes page.

## Create a Preset

### Steps

1. Click **Add Prompt** in the page header; a drawer opens on the right
2. Enter a name, and optionally a description (shown only in CC Switch)
3. Write the prompt in Markdown in the text box
4. Click "Add"

Content that is already in the file but not yet in CC Switch can be saved as an entry with "Import current xxx" in the page header's ⋯ menu; the file is not modified.

### Prompt Writing Tips

**Structured format**:

```markdown
# Role Definition

You are a professional code review expert.

## Core Capabilities

- Code quality analysis
- Performance optimization suggestions
- Security vulnerability detection

## Response Style

- Clear and concise
- Provide specific examples
- Give improvement suggestions

## Notes

- Do not modify business logic
- Maintain consistent code style
```

## Enable a Preset

### How to Enable

Click the "Enable" button on the preset row; the enabled row shows "Enabled" and the button becomes "Disable".

### One Enabled at a Time

Each app can have only one enabled prompt at a time. Enabling a new one automatically disables the previous one. Once enabled, its text overwrites the target file; after it is disabled, the file is emptied (Pi's `AGENTS.md` is deleted).

### Sync Target

After enabling, the prompt is written to the corresponding app's file:

| Application | File Path |
|-------------|-----------|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Grok Build | `~/.grok/AGENTS.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |
| Hermes | `~/.hermes/SOUL.md` (Hermes's persona; takes effect in newly started sessions) |
| Pi | `~/.pi/agent/AGENTS.md` |
| MiniMax Code | `~/.minimax/AGENTS.md` (content must not exceed 32 KiB) |

If you override a configuration directory in Settings, the file path changes accordingly. MiniMax Code has no directory override setting; its data directory can be set with the `MINIMAX_DATA_DIR` environment variable. Pi additionally recognizes `PI_CODING_AGENT_DIR`.

### Extra Content for Pi

Pi's Prompts page has three tabs:

| Tab | Description |
|-----|-------------|
| Library | An AGENTS.md prompt library; only one can be enabled at a time, and it is written to Pi's global `AGENTS.md` |
| System prompt | Edit `APPEND_SYSTEM.md` (appended after Pi's built-in base prompt; recommended) or `SYSTEM.md` (replaces Pi's built-in base prompt); it takes effect whenever the file exists, no enabling needed |
| Templates | Manage Pi's prompt templates; after saving, type `/command-name` in Pi to invoke one, no enabling needed |

A Pi that is already open does not hot-reload automatically; run `/reload` when it is idle. A newly started Pi reads the files automatically.

## Edit a Preset

1. Click the "Edit" button on the preset row (or click the row)
2. Modify the name, description, or text in the drawer
3. Click "Save"

If the edited preset is the enabled one, the target file is overwritten immediately after saving.

## Delete a Preset

1. Click "Delete" in the preset row's ⋯ menu
2. Confirm deletion

An enabled preset cannot be deleted; disable it first. Deleting only affects that entry in CC Switch; the target file is not modified.

## What Happens When You Edit the File by Hand

You can edit the target file directly in a CLI or an external editor, and CC Switch will not let those changes be lost:

| Scenario | Handling |
|----------|----------|
| The file for the enabled entry was edited elsewhere | The next time you open this page, the changes are pulled into the enabled entry |
| The file contains content CC Switch doesn't have | Before another prompt is enabled, that content is saved as an "Original prompt" entry, then overwritten |
| The file already has content but the list is still empty | Use "Import current xxx" in the page header's ⋯ menu, or "Import existing content" on the empty-list page, to save it as an entry |

## Cross-app Usage

Prompts are managed separately per app: switch the app in the header dropdown and the list changes to that app's presets.

To use the same prompt in several apps, you don't need to retype it: click "Copy to other apps" in the preset row's ⋯ menu and tick the target apps. Each gets its own independent copy that is not enabled automatically, and later edits do not affect each other (Hermes's SOUL.md is a persona, so it is unticked by default).

## Import & Export

### Share via Deep Link

You can generate deep links to share presets:

```
ccswitch://v1/import?resource=prompt&app=claude&name=<name>&content=<Base64-encoded prompt content>
```

For parameters and examples, see [5.3 Deep Link Protocol](../5-faq/5.3-deeplink.md).

### Via Configuration Export

Exporting configuration includes all presets, which can be restored upon import.
