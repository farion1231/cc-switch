# Quick Provider Setup

CC Switch includes a quick setup wizard for Claude Code and Codex. It is
intended for OpenAI-compatible and Anthropic-compatible gateways.

## Before You Start

You need:

- The provider API key.
- The provider base URL, usually ending in `/v1`.
- A model ID supported by the provider, if the provider does not expose
  `/models`.

Do not paste a full endpoint unless the URL is explicitly an endpoint such as
`/v1/messages`, `/v1/chat/completions`, or `/v1/responses`. The wizard detects
these forms and marks them as full endpoints.

## Run The Wizard

1. Open the provider list for Claude Code or Codex.
2. Click **Add provider** and choose **Quick setup**.
3. Enter the provider name, base URL, and API key.
4. Click **Allow connection test**.
5. Confirm the small probe request. The wizard first checks `/models`, then
   tests the available protocol endpoints with a minimal request.
6. Select Claude Code, Codex, or both.
7. Review the detected model and protocol.
8. Review the preview, including direct/proxy mode and files that will change.
9. Click **Apply configuration**.

The API key is kept in the wizard state and is masked in the preview. It is
not included in the probe result or preview response.

## Protocols

| Protocol | Typical endpoint | Claude Code | Codex |
| --- | --- | --- | --- |
| Anthropic Messages | `/v1/messages` | Direct | Local routing |
| OpenAI Chat Completions | `/v1/chat/completions` | Local routing | Local routing |
| OpenAI Responses | `/v1/responses` | Local routing | Direct |

OpenAI-compatible does not always mean that both Chat Completions and
Responses are available. The wizard tests them separately.

## Authentication

Anthropic gateways commonly use either:

```text
x-api-key: YOUR_KEY
```

or:

```text
Authorization: Bearer YOUR_KEY
```

The model fetch and inference probe use the detected auth mode. If the
provider requires a custom header or a non-standard models endpoint, use the
advanced provider form and set the request headers/models URL explicitly.

## Routing And Restarting

When the selected protocol is not native to an IDE, the wizard enables local
routing only after the preview is confirmed. Keep CC Switch running while a
routed IDE is in use.

- Claude Code: open a new session after enabling routing.
- Codex: restart Codex after applying the configuration.

The wizard does not configure Claude Desktop, Gemini CLI, OpenCode, OpenClaw,
Hermes, Pi, or Grok Build yet. Use their existing advanced provider forms.

## Troubleshooting

- `401` or `403`: check the API key and whether the gateway expects Bearer or
  `x-api-key` authentication.
- `404` or `405`: check whether the base URL already contains `/v1` and whether
  the provider supports the selected protocol.
- No models found: enter the model ID manually or use the advanced form to set
  a custom models URL.
- A routed request fails: confirm that the local proxy is running and that the
  IDE was restarted when requested by the preview.
