# 2.2 プロバイダーの切り替え

## メイン画面での切り替え

プロバイダーリストで、対象のプロバイダーカードの「有効化」ボタンをクリックします。

OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は共存型アプリで、複数のプロバイダーを同時に追加できます。操作方法は下記の [共存型アプリ](#共存型アプリ) を参照してください。

### 切り替えフロー

1. 「有効化」ボタンをクリック
2. CC Switch が設定ファイルを更新
3. カードのステータスが「現在有効」に変更
4. アプリごとの方法で反映（下記「反映方法」を参照）

### ステータス表示

| ステータス | 表示 | 説明 |
|------|------|------|
| 現在有効 | 青い枠 + ラベル | 設定ファイル内の現在のプロバイダー |
| ルーティングアクティブ | 緑の枠 | ローカルルーティング有効時に実際にリクエストを転送しているプロバイダー |
| 通常 | デフォルトのスタイル | 有効化されていないプロバイダー |

## トレイでの素早い切り替え

システムトレイから素早く切り替えられ、メイン画面を開く必要がありません。

### 操作手順

1. システムトレイの CC Switch アイコンを右クリック
2. 対応するアプリのサブメニュー（例：「Claude · 現在のプロバイダー」）にマウスを合わせる
3. 切り替えたいプロバイダー名をクリック
4. 切り替え完了、トレイに短い通知が表示

### トレイメニュー構造

v3.13.0 より、トレイメニューがフラットなリストから **アプリ別サブメニュー** にリファクタリングされ、各アプリに独立したサブメニューが用意されました：

| サブメニュー | 説明                                                                 |
| ------------ | -------------------------------------------------------------------- |
| Claude       | Claude のすべてのプロバイダー（Codex OAuth リバースプロキシを含む）  |
| Codex        | Codex のすべてのプロバイダー                                         |
| Gemini       | Gemini のすべてのプロバイダー                                        |
| Grok Build   | Grok Build のすべてのプロバイダー                                    |

トレイに含まれるのは、ローカルルーティングに対応したこの 4 つのアプリだけです。Claude Desktop と共存型アプリはメイン画面で操作してください。

**リファクタリングの利点**：

- **メニューのオーバーフロー防止**：プロバイダーが多数ある場合、フラットなリストでは画面の高さを超えますが、アプリ別サブメニューは自然にスケールします
- **サブメニューのタイトルに現在有効なプロバイダーと使用量サマリーを表示**：サブメニューを開かなくても、Claude / Codex / Gemini / Grok Build がどのプロバイダーを使用中か、利用可能なキャッシュ済み使用量情報とあわせて確認できます
- **アプリ別の分離**：Claude のプロバイダーを切り替えても他のアプリのビューには影響しません

> **ヒント**：バックグラウンド常駐 + 軽量モード + アプリ別サブメニューの組み合わせは、複数のアプリを頻繁に切り替えるヘビーユーザーに特に適しています。[1.5 個人設定 → 軽量モード](../1-getting-started/1.5-settings.md) を参照してください。

## 反映方法

### Claude Code

**切り替え後に即時反映**、再起動は不要です。

Claude Code はホットリロードに対応しており、設定ファイルの変更を自動検出して再読み込みします。

### Claude Desktop

切り替え後に Claude Desktop の再起動が必要です。「モデルマッピング」モードのプロバイダーは、CC Switch を起動したままにしておく必要もあります。詳しくは [2.6 Claude Desktop](./2.6-claude-desktop.md) を参照してください。

### Codex

切り替え後は再起動が必要：
- 現在のターミナルウィンドウを閉じる
- ターミナルを再度開く

### Gemini CLI

**切り替え後に即時反映**、再起動は不要です。

Gemini CLI はリクエストごとに `.env` ファイルを再読み込みします。

### Grok Build

切り替え後に Grok Build の再起動が必要です。切り替えに成功すると通知が表示されます。

### ローカルルーティング有効時

ローカルルーティングを有効にすると、Claude Code、Codex、Gemini CLI、Grok Build のリクエストはすべて CC Switch 経由で転送されるため、プロバイダーの切り替えは以降のリクエストに即座に反映されます。ただし、切り替えによってモデルが変わる場合、Codex と Grok Build は再起動が必要になることがあります。

## 設定ファイルの変更

プロバイダーを切り替える際、CC Switch は以下のファイルを変更します：

### Claude

```
~/.claude/settings.json
```

変更内容：
```json
{
  "env": {
    "ANTHROPIC_API_KEY": "新しい API Key",
    "ANTHROPIC_BASE_URL": "新しいエンドポイント"
  }
}
```

### Codex

```
~/.codex/config.toml
```

サードパーティのプロバイダーの API Key は `config.toml` 内の該当プロバイダーの `experimental_bearer_token` に書き込まれ、`~/.codex/auth.json` には書き込まれません。`auth.json` は OpenAI 公式の ChatGPT ログイン専用です。サードパーティのプロバイダーに切り替えたときにこれを保持するかどうかは、「設定 → 一般 → Codex アプリ拡張」で決まります。モデルマッピングを設定したプロバイダーでは、`~/.codex/cc-switch-model-catalog.json` も生成されます。

### Gemini

```
~/.gemini/.env
~/.gemini/settings.json
```

### Grok Build

```
~/.grok/config.toml
```

### Claude Desktop

Claude Desktop の 3P プロファイル設定に書き込みます（macOS では `~/Library/Application Support/Claude-3p/` 配下）。詳しくは [2.6 Claude Desktop](./2.6-claude-desktop.md) を参照してください。

## 共存型アプリ

OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は、複数のプロバイダーを同時にツール自身の設定へ書き込めます。どれを使うかはツール側で選択します：

| アプリ | ボタン | 書き込み先 |
|------|------|----------|
| OpenCode | 追加 / 削除 | `~/.config/opencode/opencode.json` |
| OpenClaw | 追加 / 削除 | `~/.openclaw/openclaw.json` |
| Hermes | 追加 / 削除 | `~/.hermes/config.yaml` の `custom_providers` |
| Pi | 有効化 / 削除 | `~/.pi/agent/models.json` |
| MiniMax Code | 追加 / 削除 | `~/.minimax/config.yaml` の `custom_provider` |

追加した後：

- **Hermes**：カードには「有効化 / 使用中」ボタンもあり、「有効化」をクリックすると `config.yaml` の `model.provider` と `model.default` がそのプロバイダーに設定されます
- **OpenClaw**：カードには「デフォルトに設定 / 現在のデフォルト」ボタンもあり、OpenClaw のデフォルトモデルを設定できます
- **OpenCode、Pi、MiniMax Code**：ツール側で使用するモデルを選択します

共存型アプリは、トレイでの切り替えとフェイルオーバーキューに対応していません。ほとんどの場合プロバイダーはそのまま削除できますが、以下は例外です：

- Hermes で現在使用中のプロバイダー、Hermes 自身が管理する読み取り専用のプロバイダー
- OpenClaw のデフォルトモデルから参照されているプロバイダー
- MiniMax Code の `defaultModel` / `defaultLightModel` から参照されているプロバイダー
- Pi：Pi 自身の状態を読み込むまでは、削除ボタンは使用できません

## 切り替え失敗時の対処

切り替えに失敗した場合、考えられる原因：

### 設定ファイルがロックされている

他のプログラムが設定ファイルを使用中です。

**解決方法**：実行中の CLI ツールを閉じてから、再度切り替えを試みてください。

### 権限不足

設定ファイルへの書き込み権限がありません。

**解決方法**：設定ディレクトリの権限設定を確認してください。

### 設定形式エラー

プロバイダー設定の JSON 形式に誤りがあります。

**解決方法**：プロバイダーを編集して、JSON 形式を確認・修正してください。
