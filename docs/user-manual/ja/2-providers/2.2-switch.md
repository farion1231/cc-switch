# 2.2 プロバイダーの切り替え

## 接続モード

Claude Code、Codex、Gemini CLI、Grok Build のアプリページの上部には、「直接接続 / ルーティング / 集約」の 3 つのタブがあります（集約があるのは Claude Code と Codex のみ）：

| モード | リクエストの流れ | プロバイダーの切り替え |
|------|-----------|-----------|
| 直接接続 | クライアントがプロバイダーに直接接続 | クライアント設定ファイルの主要フィールドを書き換える |
| ルーティング | リクエストはまずこのマシン上の CC Switch を通り、フォーマット変換やフェイルオーバーができる | ルーティング先だけを変更し、設定ファイルはもう書き換えない |
| 集約 | `/model` で選んだモデルに応じてリクエストを複数のプロバイダーに振り分ける。フェイルオーバーはしない | 切り替わるのはデフォルトのプロバイダー |

**タブをクリックしても、そのページを見るだけで設定は変わりません。** 実際にモードを切り替えるには、ページ上で結果が明記されたボタン「ルーティングを開始」「集約に切り替え」「直接接続に戻す」をクリックします。タブの横の「有効」マークが、現在実際にどのモードかを示します。ルーティングと集約の詳細は [4.2 アプリケーションルーティング](../4-proxy/4.2-routing.md) を参照してください。

まず最も一般的な、直接接続での切り替えを説明します。

## メイン画面での切り替え

直接接続のページで、対象のプロバイダーカードの「切り替え」ボタンをクリックします。

OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は共存型アプリで、複数のプロバイダーを同時に追加できます。操作方法は下記の [共存型アプリ](#共存型アプリ) を参照してください。Claude Desktop にはモードのタブがありません。[2.6 Claude Desktop](./2.6-claude-desktop.md) を参照してください。

### 切り替えフロー

1. 「切り替え」ボタンをクリック
2. CC Switch が設定ファイルを更新
3. カードのボタンが「使用中」の状態に変わる
4. アプリごとの方法で反映（下記「反映方法」を参照）

### ステータス表示

| ステータス | 表示 | 説明 |
|------|------|------|
| 使用中 | 直接接続の色の枠 + 「使用中」 | 直接接続モードで、設定ファイル内で現在使われているプロバイダー |
| 転送中 | ルーティングの色の枠 + 「転送中」 | ルーティングモードで、実際にリクエストを転送しているプロバイダー |
| 現在の既定 | 集約の色の枠 + 「現在の既定」 | 集約モードでのデフォルトのプロバイダー |
| 通常 | デフォルトのスタイル | その他のプロバイダー |

モードとカード上のボタンは次のように対応します：

- 直接接続のページで、実際にはルーティングまたは集約になっている場合、他のカードのボタンは「直接接続に戻して使う」です。
- ルーティングのページでは、他のカードのボタンは「ここへ転送」です。
- 「ルーティングが必要」と表示されたプロバイダー（フォーマット変換が必要なものなど）は直接接続できません。そのまま切り替えようとすると案内が表示され、「ルーティングを開始して使う」を選べます。
- 公式サブスクリプションはルーティングを通りません（Codex の OpenAI Official は例外）。ルーティングのページではグレー表示になります。

## トレイでの素早い切り替え

システムトレイから素早く切り替えられ、メイン画面を開く必要がありません。

### 操作手順

1. システムトレイの CC Switch アイコンを右クリック
2. 対応するアプリのサブメニューにマウスを合わせる
3. 切り替えたいプロバイダー名をクリック
4. 切り替え完了、トレイに短い通知が表示（例：「Claude Code を xxx に切り替えました。反映するには Claude Code を再起動してください」）

### トレイメニュー構造

トレイには、切り替え式のアプリごとにサブメニューが 1 行ずつあります：

| サブメニュー | 説明 |
| ------ | ---- |
| Claude Code | このアプリのプロバイダー |
| Claude Desktop | このアプリのプロバイダー。モデルマッピングのプロバイダーには「 · モデルマッピング」が付く |
| Codex | このアプリのプロバイダー |
| Gemini CLI | このアプリのプロバイダー |
| Grok Build | このアプリのプロバイダー |

サブメニューのタイトルは「アプリ名 · [ルーティング / 集約 ·] 使用中のプロバイダー · クォータの概要」の形で、開かなくても、今どのプロバイダーを使っていて、どのモードかが分かります。サブメニュー内の動作は現在のモードに従います：

- **直接接続**：プロバイダーをクリックすると切り替わります。ルーティングが必要なプロバイダーの後ろには「（ルーティングが必要）…」と表示され、クリックするとアプリページが開いて案内が表示されます。
- **ルーティング**：プロバイダーをクリックするとルーティング先が変わります。公式サブスクリプションには「（公式サブスクリプションはルーティングを通りません）」と表示され、クリックできません。
- **ルーティング + フェイルオーバー有効**：読み取り専用で、キューの順序が一覧表示されます。調整するにはアプリページで行ってください。
- **集約**：集約リストにあるプロバイダーだけが表示され、クリックするとそのプロバイダーがデフォルトになります。

トレイに並ぶのはこの 5 つの切り替え式アプリだけです。共存型アプリはメイン画面で操作してください。

> **ヒント**：バックグラウンド常駐 + 軽量モード + トレイのサブメニューの組み合わせは、複数のアプリを頻繁に切り替えるヘビーユーザーに特に適しています。[1.5 個人設定 → 軽量モード](../1-getting-started/1.5-settings.md) を参照してください。

## 反映方法

### Claude Code

**切り替え後に即時反映**、再起動は不要です。

Claude Code はホットリロードに対応しており、設定ファイルの変更を自動検出して再読み込みします。

### Claude Desktop

切り替え後に Claude Desktop の再起動が必要です。「モデルマッピング」モードのプロバイダーは、CC Switch を起動したままにしておく必要もあります。詳しくは [2.6 Claude Desktop](./2.6-claude-desktop.md) を参照してください。

### Codex

切り替え後は Codex の再起動が必要です。CLI は終了してから `codex` を再実行し、デスクトップ版は完全に終了（macOS では ⌘Q）してから開き直します。

### Gemini CLI

切り替え後は Gemini CLI の再起動が必要です（終了してから `gemini` を再実行）。切り替えに成功すると通知が表示されます。

Gemini CLI は起動時に `.env` と `settings.json` を読み込むため、実行中のセッションには切り替え後のキー、アドレス、モデルが反映されません。

### Grok Build

切り替え後に Grok Build の再起動が必要です。切り替えに成功すると通知が表示されます。

### ルーティングと集約モードのとき

リクエストはすべて CC Switch 経由で転送されます。ルーティングのページでプロバイダーを切り替えると、変わるのはルーティング先だけで、以降のリクエストに即座に反映されます。切り替えによってモデルが変わる場合、Codex、Gemini CLI、Grok Build は再起動が必要になることがあります。

ルーティング中も、直接接続のときに使っていたプロバイダーはそのまま残ります（カードに「直接接続時に使用」と表示）。直接接続に戻すと、設定ファイルはそのプロバイダーに書き戻されます。

集約モードでは、Claude Code の集約モデルリストの変更は即座に反映されます。Codex は完全に再起動しないと新しいモデルリストが見えません。CLI ではページの案内にある「Codex デーモンを再起動」をクリックし（実行中のタスクが中断されます）、デスクトップ版は ⌘Q で完全に終了してから開き直し、エディタ拡張はウィンドウを開き直します。

ルーティングと集約は CC Switch を起動したままにしておく必要があります。CC Switch を終了すると自動的に直接接続に戻り、次回起動時に再び接続されます。詳しくは [4.2 アプリケーションルーティング](../4-proxy/4.2-routing.md) を参照してください。

## 設定ファイルの変更

プロバイダーを切り替える際、CC Switch は以下のファイルの**主要フィールド**だけを置き換えます：リクエスト先アドレス、Key、モデル名、API プロトコル、およびプロバイダーに付随する一部の互換オプション（コンテキストウィンドウなど）。プラグイン、Hook、権限、MCP、自分で追加した設定、コメントや書式はそのまま残ります。各ファイルで具体的にどのキーを変更するかは [5.1 設定ファイルの説明](../5-faq/5.1-config-files.md) を参照してください。

### Claude

```
~/.claude/settings.json
```

変更内容（主要フィールドのみを示しています。ファイル内のその他の内容は変更されません）：
```json
{
  "env": {
    "ANTHROPIC_API_KEY": "新しい API Key",
    "ANTHROPIC_BASE_URL": "新しいエンドポイント"
  }
}
```

### Codex

```
~/.codex/config.toml
```

サードパーティのプロバイダーの API Key は `config.toml` 内の該当プロバイダーの `experimental_bearer_token` に書き込まれ、`~/.codex/auth.json` には書き込まれません。`auth.json` は OpenAI 公式の ChatGPT ログイン専用です。サードパーティのプロバイダーに切り替えたときにこれを保持するかどうかは、「設定 → アプリ設定」の「直接切替時に公式ログインを保持」で決まります。モデルマッピングを設定したプロバイダーでは、`~/.codex/cc-switch-model-catalog.json` も生成されます。

### Gemini

```
~/.gemini/.env
~/.gemini/settings.json
```

`.env` は主要フィールドの行だけを変更し、`settings.json` は認証方式（`security.auth.selectedType`）とモデル名（`model.name`）だけを変更します。

### Grok Build

```
~/.grok/config.toml
```

変更するのはデフォルトモデル（`[models]` の `default`）と、CC Switch が書き込んだ `[model."<名前>"]` テーブルだけです。

### Claude Desktop

Claude Desktop の 3P プロファイル設定に書き込みます（macOS では `~/Library/Application Support/Claude-3p/` 配下）。直接接続のプロバイダーはアドレスと Key をそのまま書き込み、モデルマッピングのプロバイダーはローカルのルーティングサービスを指します。詳しくは [2.6 Claude Desktop](./2.6-claude-desktop.md) を参照してください。

## 共存型アプリ

OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は、複数のプロバイダーを同時にツール自身の設定へ書き込めます。どれを使うかはツール側で選択します：

| アプリ | ボタン | 書き込み先 |
|------|------|----------|
| OpenCode | 追加 / 削除 | `~/.config/opencode/opencode.json` |
| OpenClaw | 追加 / 削除 | `~/.openclaw/openclaw.json` |
| Hermes | 追加 / 削除 | `~/.hermes/config.yaml` の `custom_providers` |
| Pi | 有効化 / 削除 | `~/.pi/agent/models.json` |
| MiniMax Code | 追加 / 削除 | `~/.minimax/config.yaml` の `custom_provider` |

追加した後：

- **Hermes**：カードには「有効化 / 使用中」ボタンもあり、「有効化」をクリックすると `config.yaml` の `model.provider` と `model.default` がそのプロバイダーに設定されます
- **OpenClaw**：カードには「デフォルトに設定 / 現在のデフォルト」ボタンもあり、OpenClaw のデフォルトモデルを設定できます
- **OpenCode、Pi、MiniMax Code**：ツール側で使用するモデルを選択します

共存型アプリは、トレイでの切り替えとフェイルオーバーキューに対応していません。ほとんどの場合プロバイダーはそのまま削除できますが、以下は例外です：

- Hermes で現在使用中のプロバイダー、Hermes 自身が管理する読み取り専用のプロバイダー
- OpenClaw のデフォルトモデルから参照されているプロバイダー
- MiniMax Code の `defaultModel` / `defaultLightModel` から参照されているプロバイダー
- Pi：Pi 自身の状態を読み込むまでは、削除ボタンは使用できません

## 切り替え失敗時の対処

切り替えに失敗した場合、考えられる原因：

### 設定ファイルがロックされている

他のプログラムが設定ファイルを使用中です。

**解決方法**：実行中の CLI ツールを閉じてから、再度切り替えを試みてください。

### 権限不足

設定ファイルへの書き込み権限がありません。

**解決方法**：設定ディレクトリの権限設定を確認してください。

### 設定形式エラー

プロバイダー設定の JSON 形式に誤りがあります。

**解決方法**：プロバイダーを編集して、JSON 形式を確認・修正してください。
