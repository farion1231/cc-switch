# 2.3 プロバイダーの編集

## 編集パネルを開く

1. 編集したいプロバイダーカードを見つける
2. カードにマウスをホバーして操作ボタンを表示
3. 「編集」ボタンをクリック

## 編集可能な内容

### 基本情報

| フィールド | 説明 |
|------|------|
| 名前 | プロバイダーの表示名 |
| メモ | 付加情報 |
| Web サイトリンク | プロバイダーの公式サイトまたはコンソールアドレス |
| アイコン | カスタムアイコンと色 |

### アイコンのカスタマイズ

CC Switch は豊富なアイコンカスタマイズ機能を提供しています：

#### アイコン選択画面

1. アイコンエリアをクリックしてアイコン選択画面を開く
2. 検索ボックスで名前からアイコンを検索
3. クリックしてアイコンを選択

アイコンライブラリには一般的な AI サービスプロバイダーと技術アイコンが含まれており、以下をサポートします：
- 名前によるあいまい検索
- アイコン名のツールチップ表示
- 選択結果のリアルタイムプレビュー

### 設定情報

フォームの API Key、エンドポイントアドレス、モデルなどと、パネル下部の設定エディタについては、下の [設定エディタ](#設定エディタ) を参照してください。

## 設定エディタ

Claude Code、Codex、Gemini CLI、Grok Build の編集パネル下部には、**このプロバイダーに切り替えた後のツールの設定ファイルの姿**が表示されます：

| アプリ | エディタ |
|------|--------|
| Claude Code | `~/.claude/settings.json` |
| Codex | `~/.codex/config.toml`（Key は上の API Key 入力ボックスにあり、エディタには重複して表示されません） |
| Gemini CLI | `~/.gemini/.env` と `~/.gemini/settings.json` |
| Grok Build | `~/.grok/config.toml` |

エディタの内容は 2 種類に分かれます。エディタの上にある 1 行の説明に、このアプリで 1 種類目に含まれるものが列挙されています：

- **プロバイダーに合わせて切り替わるもの**：リクエスト先アドレス、Key、モデル名、API プロトコルなどの主要フィールドと、プロバイダーに付随する一部の互換オプション（コンテキストウィンドウなど）。このプロバイダー自身の値が表示され、保存するとこのプロバイダーに保存されます。
- **グローバル設定**：それ以外のすべての内容（プラグイン、Hook、権限、MCP、自分で追加した環境変数など）。ツールの設定ファイルの現在の内容が表示され、保存するとそのまま設定ファイルに書き込まれ、すべてのプロバイダーに適用されます。

現在のプロバイダーを編集する場合も、他のプロバイダーを編集する場合も、ルールはまったく同じです。どのプロバイダーを編集していても、グローバル設定を変更するとすぐに設定ファイルに書き込まれます。ローカルルーティングが有効な場合も、エディタの主要フィールドにはプロバイダー自身の実際のアドレスと Key が表示され、ローカルルーティングのアドレスは表示されません。

### ツール側で変更した設定

- **グローバル設定**：ツール側で変更した内容（プラグインのインストールなど）は、編集パネルを開けばそのまま表示され、プロバイダーを切り替えても変更されません。
- **主要フィールド**：ツール側で一時的に変えたモデル（Claude Code の `/model` など）はプロバイダーに保存されず、別のプロバイダーに切り替えてから戻すと、プロバイダーに保存された値に戻ります。恒久的に変更したい場合は、ここでプロバイダーを編集してください。

> 💡 旧バージョンでは、現在のプロバイダーを編集するときに設定ファイル全体をプロバイダーに読み戻していました（「バックフィル」）。新バージョンではバックフィルを行いません。共有設定はもともと設定ファイルに残っているため、特定のプロバイダーに保存する必要がないからです。

### 編集中に設定ファイルが変更された場合

保存時、CC Switch はエディタで変更した設定だけを書き込み対象とし、1 件ずつ確認します：編集パネルを開いた後に、その設定が設定ファイル内でツールや他のプログラムによって変更されていないかどうかです。

- 変更されていない：そのまま書き込みます。
- 変更されている：「編集中に設定ファイルが変更されました」が表示され、該当する設定が一覧表示されます。「外部の変更を残す」か「自分の編集で上書き」を選択してください。その他の変更は通常どおり保存されます。

変更していない設定は書き込み対象にならないため、その間にツールが書き込んだ内容を上書きすることはありません。

### 切り替えで反映されない設定

旧バージョンの「バックフィル」、ディープリンクでのインポート、古いプリセットによって、プロバイダーに主要フィールド以外の設定が保存されていることがあります。これらの設定は設定ファイルに書き込まれず、エディタの下に一覧表示されます：

- **Claude Code、Gemini CLI**：項目をクリックすると上のエディタに追加され、保存するとグローバル設定として設定ファイルに書き込まれます。
- **Codex、Grok Build**：項目をクリックするとその TOML がコピーされるので、必要に応じて上のエディタに貼り付けてください。

プロバイダーに保存された元の値は削除されません。

### 設定ファイルを読み込めない場合

ツールの設定ファイルの形式に誤りがある場合、エディタには代わりにプロバイダーに保存された内容が表示され、上部に原因が表示されます。設定ファイルを修正してから、編集パネルを開き直してください。

## モデル自動取得

プロバイダーの編集時に、プロバイダーのエンドポイントから利用可能なモデルリストを自動取得できます：

1. API Key とエンドポイントアドレスが入力されていることを確認
2. モデル入力フィールドの横にある **モデル取得** ボタン（ダウンロードアイコン）をクリック
3. グループ化されたドロップダウンからモデルを選択

詳しくは [2.1 プロバイダーの追加 - モデル自動取得](./2.1-add.md#モデル自動取得) をご覧ください。

## クイックトグル（Claude）

Claude プロバイダーの編集時、JSON エディタの上部にツール検索、自動アップグレード無効化、チームメイト、最大強度思考などのよく使う設定のクイックトグルスイッチが利用できます。このうち「Tool Search を有効化」と「Artifact ツールを無効化」はプロバイダーごとの設定で、それ以外はグローバル設定です。詳しくは [2.1 プロバイダーの追加 - Claude クイックトグル](./2.1-add.md#claude-クイックトグル) をご覧ください。

## API Key の変更

プロバイダーの編集時に、**API Key** 入力ボックスから直接変更できます：

1. プロバイダーカードの「編集」ボタンをクリック
2. 「API Key」入力ボックスに新しいキーを入力
3. 「保存」をクリック

> **ヒント**：API Key 入力ボックスは表示/非表示の切り替えに対応しています。右側の目のアイコンをクリックするとキーの全文を確認できます。

## エンドポイントアドレスの変更

プロバイダーの編集時に、**エンドポイントアドレス** 入力ボックスから直接変更できます：

1. プロバイダーカードの「編集」ボタンをクリック
2. 「エンドポイントアドレス」入力ボックスに新しい URL を入力
3. 「保存」をクリック

### エンドポイントアドレスの形式

| アプリ | 形式の例 |
|------|----------|
| Claude | `https://api.example.com` |
| Codex | `https://api.example.com/v1` |
| Gemini | `https://api.example.com` |

## カスタムエンドポイントの追加

プロバイダーには複数のエンドポイントを設定でき、以下の用途に使用します：

- 速度テスト時に複数のアドレスをテスト
- フェイルオーバー時のバックアップエンドポイント

### 自動収集

プロバイダーの追加時に、CC Switch は設定からエンドポイントアドレスを自動抽出します。

### 手動追加

プロバイダーの編集時に、「エンドポイント管理」エリアで以下の操作が可能です：

- 新しいエンドポイントの追加
- 既存のエンドポイントの削除
- デフォルトエンドポイントの設定

## JSON エディタ

設定は JSON 形式を使用し、エディタは以下を提供します：

- シンタックスハイライト
- フォーマット検証
- エラー通知

### よくあるエラー

**引用符の欠落**：
```json
// ❌ 間違い
{ env: { KEY: "value" } }

// ✅ 正しい
{ "env": { "KEY": "value" } }
```

**余分なカンマ**：
```json
// ❌ 間違い
{ "env": { "KEY": "value", } }

// ✅ 正しい
{ "env": { "KEY": "value" } }
```

**閉じ括弧の欠落**：
```json
// ❌ 間違い
{ "env": { "KEY": "value" }

// ✅ 正しい
{ "env": { "KEY": "value" } }
```

## 保存と反映

1. 「保存」ボタンをクリック
2. フォームが非ブロッキングな問題を検出した場合、「それでも保存」の確認が表示されます。確認すると保存できます
3. グローバル設定の変更は、編集しているのが現在のプロバイダーかどうかに関係なく、すぐに設定ファイルに書き込まれます
4. 主要フィールドの変更はプロバイダーに保存されます。ローカルルーティングが無効な場合、現在のプロバイダーを編集していれば、設定ファイルにも同時に書き込まれます。ローカルルーティングが有効な場合、ルーティングが使用中のプロバイダーを編集していて、かつその変更がローカルルーティングの設定ファイルへの書き込み内容に影響するとき（モデル名など）は、設定ファイルも合わせて更新されます
5. ツールの再起動が必要かどうかは、プロバイダーの切り替えと同じです。[2.2 プロバイダーの切り替え](./2.2-switch.md) を参照してください

## 編集のキャンセル

「キャンセル」ボタンをクリックするか `Esc` キーを押して編集パネルを閉じると、すべての変更は保存されません。
