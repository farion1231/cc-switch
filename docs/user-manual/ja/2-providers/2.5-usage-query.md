# 2.5 使用量クエリ

CC Switch のクォータ・残高表示は 2 つのカテゴリに分かれます：**自動表示**（OAuth アカウント系、すぐに使える）と **手動有効化**（内蔵テンプレート + カスタムスクリプト、プロバイダーカードで設定した後に表示）。

> このページで説明するのは、プロバイダーカード上の **クォータ / 残高** です。リクエスト数、Token、コストの統計は左サイドバーの「使用量」ページにあります。[4.4 使用量統計](../4-proxy/4.4-usage.md) を参照してください。

| カテゴリ                           | 範囲                                                                              | ユーザー操作必要 |
| ---------------------------------- | --------------------------------------------------------------------------------- | ---------------- |
| **自動表示**                       | GitHub Copilot、Codex OAuth リバースプロキシ、xAI OAuth                           | 不要             |
| **手動有効化（内蔵テンプレート）** | 公式サブスクリプション（Claude / Codex / Gemini / Grok Build の公式プロバイダー）、Token Plan、第三者残高クエリ | 必要（下記参照） |
| **手動有効化（カスタムスクリプト）** | 内蔵テンプレート未対応の中継サービス、プライベートデプロイ、特殊 API            | 必要（下記参照） |

## 自動表示（OAuth アカウント系）

以下のアカウント系プロバイダーは、有効化すると **自動的** にカード下部にクォータが表示され、追加設定は不要です：

| カテゴリ               | 対象プロバイダー                              | 表示内容                             |
| ---------------------- | --------------------------------------------- | ------------------------------------ |
| GitHub Copilot         | Copilot プロバイダーカード                    | Premium interactions 残量            |
| Codex OAuth            | Codex OAuth リバースプロキシカード（Claude プロバイダー） | ChatGPT アカウント Codex クォータ |
| xAI OAuth              | xAI (Grok) OAuth プロバイダーカード           | Grok アカウントのクォータ            |

### 自動表示の操作

- **カード下部表示**：クォータは常に「残り」で表示されます（例：「5時間 残り 62%」）。横にリセットまでのカウントダウンが付きます。普段はグレーで、いずれかの枠の残りが 10% を切ると文字が濃く太くなります。使い切ると「使い切り」、プランの期限が切れると「プラン期限切れ」、取得に失敗すると「残量を取得できません」（赤）と表示されます
- **手動更新**：クォータの文字をクリックして再取得します（ホバーすると「クリックで再取得」と更新時刻が表示されます）
- **カードの簡略化**：これらのプロバイダーのクォータは内蔵ロジックで表示されるため、カードの「その他」メニューに「利用状況を設定」はありません
- **ログイン期限切れ通知**：Token の更新に失敗した場合、カードに「ログインの期限切れ」または「トークンの更新待ち」と表示されます。左サイドバーの **アカウント** で再ログインしてください

## 手動有効化（内蔵テンプレート + カスタムスクリプト）

上記の自動表示されるアカウント系プロバイダー以外、**その他すべてのプロバイダー**（公式サブスクリプション、Token Plan、第三者残高クエリ、各種中継サービスを含む）では、プロバイダーカード上で **手動で「利用状況照会を有効にする」をオン** にして初めてクォータが表示されます。

### 公式サブスクリプションのクォータ

v3.16.2 以降、Claude / Codex / Gemini / Grok Build の公式プロバイダーのサブスクリプションクォータは、**デフォルトで無効** の内蔵テンプレートに変わりました：

1. 公式プロバイダーのカード右側の「その他」（⋯）ボタンをクリックし、**利用状況を設定** を選択
2. 「利用状況照会を有効にする」をオンにし、テンプレートで **公式サブスクリプション** を選択
3. 保存すると、カード下部にサブスクリプションクォータが表示されます（Grok Build の場合は SuperGrok のクォータ）。公式サブスクリプションのクォータは、このマシン上の CLI の OAuth 認証情報を読み取って公式 API を呼び出すもので、有効にしたときだけリクエストされます

例外：アカウントページの ChatGPT アカウントに紐付けられた OpenAI Official プロバイダーは、デフォルトで有効です。

### なぜ手動有効化が必要なのか？

重要な理由の一つは：**同じリクエスト URL（同じベンダー）が複数のクエリモードを提供している場合がある** ことです —— プランごとのクォータクエリと、アカウント残高クエリの両方が存在する可能性があります。CC Switch はどちらをクエリすべきか自動判定できないため、このようなプロバイダーの内蔵クエリは **デフォルトで無効** になっており、適切なテンプレートを選択してから有効化する必要があります。

### 内蔵テンプレートの対象範囲

v3.13.0 では以下のカテゴリに **すぐに使える内蔵テンプレート** を提供しており、有効化後にスクリプトを書く必要はありません：

| カテゴリ        | 対象プロバイダー                                          | テンプレートタイプ        |
| --------------- | --------------------------------------------------------- | ------------------------- |
| 公式サブスクリプション | Claude / Codex / Gemini / Grok Build の公式プロバイダー | 公式サブスクリプションクォータ |
| Token Plan      | Kimi / Zhipu GLM / MiniMax / Volcengine（火山方舟） / OpenCode Go / Command Code | プランクォータ（使用進捗付き） |
| 第三者残高      | DeepSeek / StepFun / SiliconFlow / OpenRouter / Novita AI | 公式残高クエリ            |

> **ヒント**：上記の内蔵テンプレート以外で対象外のプロバイダーには、**カスタムスクリプト** 方式（下記参照）で独自のクエリロジックを記述できます。

### 有効化手順

1. プロバイダーカードにマウスをホバーし、右側の「その他」（⋯）ボタンをクリック
2. **利用状況を設定** を選択（初回は確認が表示されるので「理解しました、設定する」をクリック）
3. 設定パネル上部の **利用状況照会を有効にする** スイッチをオンにする
4. 適切な内蔵テンプレート（Token Plan、第三者残高など）または「カスタム」を選択
5. 必要に応じて API Key / Base URL / Access Token などのパラメータを入力（多くの場合は空欄のままプロバイダー自身の認証情報を使用可能）
6. 「スクリプトをテスト」をクリックして正常に応答するか確認
7. 設定を保存 —— カード下部にクォータが表示されます

> ⚠️ **注意**：有効化後の自動更新間隔は「自動照会間隔」フィールドで制御します（`0` に設定すると自動更新を無効化）。プロバイダーが「使用中」状態のときのみバックグラウンドクエリがトリガーされます。

## カスタムスクリプトクエリ（高度）

### 機能説明

プロバイダーが **内蔵テンプレートの対象範囲外** の場合、JavaScript でカスタムクエリスクリプトを記述できます。中継サービス、プライベートデプロイ、特殊な API 形式などに適しています。

**使用シーン**：
- API アカウントの残額確認
- プランの使用状況の監視
- 複数プランの残額を集約表示

## 設定を開く

1. プロバイダーカードにマウスをホバーし、右側の「その他」（⋯）ボタンをクリック
2. 「利用状況を設定」を選択
3. 使用量クエリ設定パネルが開く

## 使用量クエリの有効化

設定パネル上部の「利用状況照会を有効にする」スイッチをオンにします。

## プリセットテンプレート

プリセットテンプレートのドロップダウンには、カスタム、General、NewAPI、Sub2API のほか、上で説明した Token Plan、公式、公式サブスクリプションなどの内蔵テンプレートがあります。カスタムスクリプトでよく使う 4 種類は次のとおりです：

### カスタムテンプレート

リクエストと抽出ロジックを完全にカスタマイズします。特殊な API 形式に対応します。

### 汎用テンプレート

ほとんどの標準的な API 形式のプロバイダーに適しています：

```javascript
({
  request: {
    url: "{{baseUrl}}/user/balance",
    method: "GET",
    headers: {
      "Authorization": "Bearer {{apiKey}}",
      "User-Agent": "cc-switch/1.0"
    }
  },
  extractor: function(response) {
    return {
      isValid: response.is_active || true,
      remaining: response.balance,
      unit: "USD"
    };
  }
})
```

**設定パラメータ**：
| パラメータ | 説明 |
|------|------|
| API Key | 認証用のキー（任意、空欄の場合はプロバイダーに設定されたキーを使用） |
| Base URL | API ベースアドレス（任意、空欄の場合はプロバイダーのエンドポイントを使用） |

### New API テンプレート

New API タイプの中継サービス専用に設計されています：

```javascript
({
  request: {
    url: "{{baseUrl}}/api/user/self",
    method: "GET",
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Bearer {{accessToken}}",
      "New-Api-User": "{{userId}}"
    },
  },
  extractor: function (response) {
    if (response.success && response.data) {
      return {
        planName: response.data.group || "デフォルトプラン",
        remaining: response.data.quota / 500000,
        used: response.data.used_quota / 500000,
        total: (response.data.quota + response.data.used_quota) / 500000,
        unit: "USD",
      };
    }
    return {
      isValid: false,
      invalidMessage: response.message || "クエリ失敗"
    };
  },
})
```

**設定パラメータ**：
| パラメータ | 説明 |
|------|------|
| Base URL | New API サービスアドレス |
| Access Token | アクセストークン |
| User ID | ユーザー ID |

### Sub2API テンプレート

Sub2API で構築された中継サイト向けです。プロバイダー自身の API Key で `/v1/usage` を照会するため、アクセストークンは不要です。プロバイダーアドレスに `/v1` が付いていても付いていなくても動作します。

```javascript
({
  request: {
    url: "{{baseUrl}}".replace(/\/+$/, "").replace(/\/v1$/, "") + "/v1/usage",
    method: "GET",
    headers: {
      "Authorization": "Bearer {{apiKey}}",
      "User-Agent": "cc-switch/1.0"
    }
  },
  extractor: function (response) {
    var quota = response.quota || {};
    var result = {
      isValid: response.isValid !== false,
      unit: response.unit || quota.unit || "USD"
    };
    if (typeof response.planName === "string") result.planName = response.planName;
    if (typeof response.remaining === "number" && response.remaining >= 0) {
      result.remaining = response.remaining;
    }
    if (quota.limit > 0) {
      result.used = quota.used;
      result.total = quota.limit;
    }
    if (!result.isValid) {
      result.invalidMessage = response.status
        ? String(response.status)
        : "照会に失敗しました";
    }
    return result;
  },
})
```

- ウォレット残高、サブスクリプショングループ、キー単位の上限のいずれでも残額を表示します。上限なしのサブスクリプショングループはグループ名だけを表示し、数値は表示しません。
- キーに総額上限が設定されている場合は、使用量と総額も表示します。

**設定パラメータ**：
| パラメータ | 説明 |
|------|------|
| API Key | 認証に使うキー（任意。空欄ならプロバイダーのキーを使用） |
| Base URL | サイトアドレス（任意。空欄ならプロバイダーのエンドポイントを使用） |

## 共通設定

### タイムアウト時間

リクエストのタイムアウト時間（秒）、デフォルトは 10 秒。

### 自動クエリ間隔

使用量データの自動更新間隔（分）：
- `0` に設定すると自動クエリを無効化
- 範囲：0-1440 分（最長 24 時間）。5〜60 分を推奨
- プロバイダーが「使用中」のときのみ動作

## エクストラクターの戻り値形式

エクストラクター関数は以下のフィールドを含むオブジェクトを返します。すべてのフィールドは任意です：

| フィールド | 型 | 必須 | 説明 |
|------|------|------|------|
| `isValid` | boolean | いいえ | アカウントが有効かどうか、デフォルト true |
| `invalidMessage` | string | いいえ | 無効時の通知メッセージ |
| `remaining` | number | いいえ | 残額 |
| `unit` | string | いいえ | 単位（例：USD、CNY、回） |
| `planName` | string | いいえ | プラン名（複数プラン対応） |
| `total` | number | いいえ | 総額 |
| `used` | number | いいえ | 使用済み額 |
| `extra` | string | いいえ | 追加表示テキスト |

## スクリプトのテスト

設定完了後、「スクリプトをテスト」ボタンをクリックして確認します：

1. 設定された URL にリクエストを送信
2. エクストラクター関数を実行
3. 結果またはエラー情報を表示

## 表示効果

設定が成功すると、プロバイダーカードに以下が表示されます：

- **単一プラン**：残額を直接表示
- **複数プラン**：「N プラン」と表示し、「展開」をクリックすると詳細を確認できます
- プラン系のクォータも同様に「残り」が中心です。取得に失敗すると「残量を取得できません」と表示されます

## 変数プレースホルダー

スクリプト内で以下のプレースホルダーを使用でき、実行時に自動的に置換されます：

| プレースホルダー | 説明 |
|--------|------|
| `{{apiKey}}` | 設定された API Key |
| `{{baseUrl}}` | 設定された Base URL |
| `{{accessToken}}` | 設定された Access Token（New API） |
| `{{userId}}` | 設定された User ID（New API） |

## 一般的なプロバイダーの設定例

### トラブルシューティング

### 公式サブスクリプションまたはアカウント系プロバイダーにクォータが表示されない

**確認事項**：
1. 公式プロバイダー（Claude / Codex / Gemini / Grok Build）：「使用量クエリ」で「利用状況照会を有効にする」をオンにし、**公式サブスクリプション** テンプレートを選択しているか（デフォルトは無効）
2. プロバイダーが「使用中」状態か（使用中でないときはバックグラウンドクエリがトリガーされません）
3. OAuth アカウント系（Copilot / Codex OAuth / xAI OAuth）の場合、Token がまだ有効期限内か確認。カードに「セッション期限切れ」と表示される場合は、左サイドバーの **アカウント** で再ログインしてください
4. 公式クォータエンドポイントへのネットワークアクセス可否

### 手動有効化後もクォータが表示されない

**確認事項**：
1. プロバイダーカードの「使用量クエリ」パネル上部にある **利用状況照会を有効にする** スイッチがオンか
2. 適切な内蔵テンプレート（Token Plan / 第三者残高 / カスタム）が選択されているか
3. 「スクリプトをテスト」をクリックして具体的なエラー情報を確認
4. API Key / Base URL などの必須フィールドが正しく入力されているか
5. プロバイダーのクォータエンドポイントへのネットワークアクセス可否
6. プロバイダーが「使用中」状態のときのみ、バックグラウンドの自動更新がトリガーされます

### クエリ失敗

**確認事項**：
1. API Key が正しいか
2. Base URL が正しいか
3. ネットワークがアクセス可能か
4. タイムアウト時間が十分か

### 返却データが空

**確認事項**：
1. エクストラクター関数に `return` 文があるか
2. レスポンスのデータ構造がエクストラクターと一致しているか
3. 「スクリプトをテスト」で生のレスポンスを確認

### フォーマット失敗

スクリプトに構文エラーがある場合、「整形」ボタンをクリックするとエラー箇所が表示されます。

## 時間帯別料金（ピーク / 閑時）

プロバイダーの中には**呼び出す時間**によって料金を変えるところがあります。DeepSeek は閑時のリクエストを割引し、ピーク時は定額で課金します。「ピーク」は UTC の固定された帯で、平日のみ、中国の祝日を除きます。

CC Switch ではこれを**時間帯別ルール**で表現します。1 つのモデルについて、「曜日 + 時刻」の帯の中だけ 4 つの単価を置き換えます。

**場所**: 使用量ページ → 使用量設定 → **料金を管理…** → **時間帯別料金**。

### 照会の仕組み

- ルールが一致するには、次の条件が**すべて**成立する必要があります: リクエストの課金モデルがルールの**モデル ID**と一致する、曜日がチェックされている、現地時刻が半開区間 `[開始, 終了)` に収まる、今日の現地日付が**除外日**に含まれない。
- ルールは**上から順に照会され、最初に一致したものが適用されます**。ダイアログに表示されている並びがそのまま優先順位です——上下ボタンで入れ替えられ、並べ替えるとすぐ保存されます。
- **どのルールにも一致しない場合は、そのモデル本来の単一料金がそのまま使われ、変更はありません。**ルールは自分の帯の中だけ単価を上書きします。
- 開始と終了を同時刻にすると 24 時間全体を意味します。開始が終了より後だと午夜を跨ぐので、`22:00 → 08:00` は一晩全体を覆います。
- オフセットは**夏時間を考慮しない固定オフセット**です。`UTC+08:00` は一年中北京時間です。夏時間のある地域では、この数値を年 2 回変更する必要があります。
- 各ルールの下にある要約行は、保存前に必ず読んでください——ルールが実際に何を言っているかを短文にしたものです。

### 具体例: DeepSeek

DeepSeek の公表料金（100 万トークンあたり USD）:

| 区分       | 入力（キャッシュミス） | 出力 | キャッシュ命中 |
| ---------- | ---------------------- | ---- | -------------- |
| 閑時       | 0.15                   | 0.60 | 0.003          |
| ピーク     | 0.30                   | 1.20 | 0.006          |

ピークは `月〜金 01:00–04:00 UTC` と `月〜金 06:00–10:00 UTC` で、中国の祝日を除きます。**3 つのルールをこの順序で**入力します:

| # | ラベル       | 曜日   | 時刻帯（UTC+00:00） | 除外日      | 入力 | 出力 | キャッシュ命中 | キャッシュ書き込み |
| - | ------------ | ------ | ------------------- | ----------- | ---- | ---- | -------------- | ------------------ |
| 1 | ピーク・早朝 | 月〜金 | 01:00–04:00         | 2026-10-01 … | 0.30 | 1.20 | 0.006          | 0.30               |
| 2 | ピーク・午前 | 月〜金 | 06:00–10:00         | 2026-10-01 … | 0.30 | 1.20 | 0.006          | 0.30               |
| 3 | 閑時         | 毎日   | 終日                | —           | 0.15 | 0.60 | 0.003          | 0.15               |

気をつける点:

- **ルール 3 は最後に置いてください。**2 つのピーク ルール以外のすべての時間に一致するため、上に並ぶとピーク帯を丸飲み込み、上の 2 つが永遠に適用されません。新しいルールが末尾に追加されるのはこのためです。
- **除外日が「祝日を除く」の表現です。**日付は 1 つずつ列挙してください——CC Switch は祝日カレンダーを取得しません。2026 年の国慶節であれば `2026-10-01` から `2026-10-07` まで、つまり `2026-10-01, 2026-10-02, …, 2026-10-07` と入力します。
- **キャッシュ書き込みの単価は推定値であり、公表されている数字ではありません。**DeepSeek が公表しているのは上の 3 つの価格だけで、キャッシュ書き込みの料金は別途示されていません。この例では同じ区分の入力コストをキャッシュ書き込みにも設定しています（ピーク 0.30、閑時 0.15）。これが DeepSeek の実際の請求額です。**活用する前に自分の請求書で確認してください。**また、キャッシュ書き込みが本当に無料でない限り 0 のままにしないでください——0 はすべてのキャッシュ書き込みを無料として計算します。
- ルール 1 は `ピーク・早朝 · deepseek-chat · Mon–Fri 01:00–04:00 (UTC+00:00) · except 2026-10-01, …` と読み上げられます。要約行は英語固定です（曜日略称、UTC オフセット、日付はローカライズしません）。この文が意図と違うなら、ルールも意図と違います。

### 知っておくべき 2 つの制限

1. **既存のリクエストログは再計算されません。**各リクエストのコストは、行が書き込まれた時点で 1 度だけ計算されます。ルールを追加・変更しても変わるのは**以降**のリクエストのコストだけで、すでにログにある行は書き込み時に計算されたコストを保ちます。
2. **夏時間に非対応。**UTC オフセットはタイムゾーン名ではなく固定の分数です。夏時間のある地域では、ルールを年 2 回調整してください。

- 頻繁なリクエストを避けるため、適切な自動クエリ間隔を設定してください
- 機密情報（API Key、Token）はローカルに安全に保存されます
