# 4.6 Codex Desktop Live 音声

## 概要

CC Switch は Codex Desktop Live 音声の 2 つの通信をローカルプロキシで中継できます。

1. WebRTC 通話を作成する HTTP リクエスト
2. 返された通話 ID に結び付く WebSocket Sideband

この機能は既定で無効です。Live のエラーは通常の Codex テキストプロバイダーのサーキットブレーカーに加算されません。

![Codex Live voice settings](../../assets/codex-live-settings-en.png)

## サポート表

| ルート                           | 要件                                                                                               | 消費するクォータ                                               |
| -------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| ChatGPT 公式アカウント           | Apple Silicon Mac、ChatGPT OAuth、DeviceCheck を含む署名済み OpenAI 公式デスクトップアプリ         | ChatGPT サブスクリプション                                     |
| 現在のプロバイダー               | Codex Live の HTTP 作成と WebSocket Sideband を明示的に実装。OpenAI の証明は第三者へ転送されません | 現在のプロバイダー                                             |
| 公式の失敗後に現在のプロバイダー | 上記両方                                                                                           | 公式を先に使用し、対象となる失敗時のみ現在のプロバイダーを使用 |

第三者向けプロキシ処理自体はプラットフォーム非依存ですが、そのプラットフォームで Codex Desktop が利用可能である必要があります。公式証明のローカル生成は現在 Apple Silicon macOS のみです。

## 前提条件

- CC Switch ローカルプロキシを起動し、Codex の接管を有効にします。
- リッスンアドレスは `127.0.0.1`、`::1`、または `localhost` にします。`0.0.0.0` や LAN アドレスでは Live を拒否します。
- Codex Desktop の Live ボタンから開始します。通話作成には Codex の `x-oai-attestation` ヘッダーが必要で、ブラウザーの `Origin` または `Sec-Fetch-*` を含むリクエストは拒否されます。
- 公式ルートでは Codex または CC Switch の管理 OAuth ストアで ChatGPT にログインします。
- 第三者ルートでは、Responses API や Chat Completions だけでなく、以下の Live 契約を実装していることを確認します。

## 第三者プロバイダーの設定

1. Codex プロバイダーを編集し、**詳細オプション**を開きます。
2. **Codex Live 音声をサポート**を有効にします。
3. 作成エンドポイントを設定します。既定値は `live` です。
4. Sideband テンプレートを設定します。既定値は `live/{call_id}` で、`{call_id}` は 1 回だけ必要です。
5. 保存し、現在のプロバイダールートで使う場合は現在の Codex プロバイダーにします。

![Third-party Codex Live capability](../../assets/codex-live-provider-en.png)

エンドポイントは相対パスのみです。絶対 URL、クエリ、フラグメント、空白、バックスラッシュ、パストラバーサルは拒否されます。フル URL モードのプロバイダーでは Live を有効にできないため、先にベース URL へ切り替えてください。認証には既存のプロバイダー API 設定を使います。

### 必須のアップストリーム契約

プロバイダーは次を実装する必要があります。

- `sdp` と `session` を含む multipart 作成リクエストを受信する
- 成功時に末尾が `rtc_*` ID または UUID の `Location` ヘッダーを返す
- `{call_id}` を置換したパスで WebSocket Sideband を受信する
- 選択した WebSocket サブプロトコルを返す
- HTTP と WebSocket の両方で同じプロバイダー認証を受け付ける

CC Switch は成功した `Location` をローカルプロキシへ書き換え、通話 ID とプロバイダーの対応を最大 10 分間メモリに保持します。有効な ID がない成功応答は `502` になります。

OpenAI の `x-oai-attestation` は第三者へ転送しません。この証明を必要とする第三者ルートは未対応です。

## ルートの選択

**設定 > 一般 > Codex アプリ拡張**で **Live 音声**を有効にし、次から選びます。

| 設定                             | 動作                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| ChatGPT 公式アカウントのみ       | 組み込み OpenAI Official と ChatGPT OAuth のみを使用                                                    |
| 現在のプロバイダーのみ           | Live 対応を明示した現在の Codex プロバイダーのみを使用                                                  |
| 公式の失敗後に現在のプロバイダー | 公式を先に試し、`401`、`403`、`429`、またはリクエスト未送信と確認できる事前処理・接続失敗時だけ切り替え |

`5xx`、タイムアウト、または通話作成済みの可能性がある不確定な通信失敗では別プロバイダーへ再試行しません。重複課金と孤立通話を防ぐため、その結果を Codex に返します。Live はテキスト用フェイルオーバーキューを走査せず、プロバイダー順も変更しません。

Codex 接管を有効にした時点で Codex Desktop が起動中なら、Codex Desktop を再起動してから Live ボタンを使います。

## セキュリティとプライバシー

- Live は loopback リスナーでのみ利用できます。
- リクエストの `Host` も loopback を示す必要があります。ブラウザー由来のリクエストを拒否し、Codex の非単純 attestation ヘッダーを受信した場合にのみ置換証明を生成できるため、通常の Web ページから課金通話を開始されることを防ぎます。
- 公式証明は固定の OpenAI Official ルートにだけ生成します。CC Switch は DeviceCheck モジュールを読む前に、アプリのコード署名、OpenAI Team ID、Bundle ID を検証します。
- 公式アップストリームには厳格なヘッダー許可リストを適用してから ChatGPT OAuth を追加します。クライアントの API キー、Cookie、Authorization、プロバイダー Secret は OpenAI へ転送しません。
- 証明にはロケール、優先言語、タイムゾーン、画面サイズの要約、スケール、一時セッション ID が含まれ、OpenAI に送信されます。
- 第三者ルートでは SDP、音声関連セッションデータ、Sideband メッセージをそのプロバイダーへ送ります。課金、保持、プライバシー、利用条件を確認してください。
- HTTP 本文は 2 MiB、WebSocket メッセージは 8 MiB、フレームは 2 MiB に制限されます。保留中のバインドは最大 128 件、アクティブ Sideband は最大 16 件です。上流 Sideband のハンドシェイク成功後にだけバインドを消費し、設定失敗時は同じバインドを安全な再試行のため復元します。5 分間無通信または 20 秒を超える書き込みで接続を閉じます。

## 既知の制限

- 公式証明は現在 Apple Silicon macOS と対応する署名済み OpenAI 公式アプリが必要です。
- WebSocket プロキシは未対応です。CC Switch の明示的なグローバル送信プロキシが設定されている場合、Live は上流へ接続する前に通話作成を拒否し、課金される可能性のある HTTP 通話を先に作成した後で Sideband がプロキシを迂回または失敗する事態を防ぎます。
- `Location` 内の `rtc_*` ID または UUID のみ対応し、JSON のみの通話 ID は未対応です。
- バインドはメモリ内だけで、CC Switch 終了時に失われます。
- Live を無効化またはローカルプロキシを停止すると新規ハンドシェイクは拒否されますが、確立済み Sideband はまだ自動終了しません。機能またはプロキシを停止する前に Codex Desktop 側で Live セッションを閉じてください。
- loopback サービスに個別のクライアント認証トークンはありません。ブラウザー対策は HTTP ヘッダーを偽装できる悪意あるローカルプロセスまでは防ぎません。loopback のまま使用し、不要時は Live を無効にしてください。

## トラブルシューティング

| エラーまたは症状                        | 確認事項                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------- |
| `codex_live_voice_disabled`             | Codex アプリ拡張で Live を有効にする                                                      |
| `codex_live_loopback_required`          | リッスンアドレスを loopback に戻す                                                        |
| `codex_live_client_rejected`            | Codex Desktop から開始し、loopback `Host` と `x-oai-attestation` が保たれているか確認する |
| `codex_live_capacity_reached`           | 不要な Live セッションを閉じて再試行する。Sideband は最大 16 接続                         |
| `codex_live_outbound_proxy_unsupported` | 明示的なグローバル送信プロキシを解除するか、WebSocket プロキシ対応後に Live を開始する    |
| 現在のプロバイダーが Live 未宣言        | HTTP と WebSocket の両方を実装した後にだけ有効にする                                      |
| `codex_live_invalid_upstream_response`  | 有効な `Location` 通話 ID を返すようアップストリームを修正する                            |
| 公式証明の準備失敗                      | Apple Silicon、公式アプリ署名、ChatGPT OAuth を確認する                                   |
| Sideband バインドがない、または期限切れ | 新しい Live 通話を開始する。バインドは 10 分で失効し再起動でも消える                      |

テキストモデルの接続テストだけでは Live 対応を確認できません。実際の Codex Desktop Live セッションで HTTP 作成と WebSocket Sideband の両方を検証してください。
