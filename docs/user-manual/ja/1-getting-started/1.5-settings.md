# 1.5 個人設定

このセクションでは、個人の好みに合わせて CC Switch を設定する方法を説明します。

## 設定を開く

- 左サイドバー下部の **設定** をクリック
- またはショートカット `Cmd/Ctrl + ,`（「一般」が直接開きます）

設定は 1 画面を使い、左サイドバーが設定の目次に切り替わります。グループは 6 つあります：**一般、アプリ設定、ローカルルーティング、ネットワーク、データ、情報**。目次の上の「戻る」をクリックする（または `Esc` を押す）と、元のページに戻ります。設定には好みに関する項目だけが入っており、MCP、Skills、プロンプト、セッションなどの機能ページは左サイドバーにあります。

スイッチ類の設定は即時に保存されます。パス類の設定（設定ディレクトリ）は、変更後にそのブロックの「保存」をクリックする必要があります。

## 一般

### 外観

| 設定 | 説明 |
| ---- | ---- |
| 表示言語 | 簡体中文、繁體中文、English、日本語。切り替えると即座に反映され、再起動は不要です |
| テーマ | システムに合わせる / ライト / ダーク |

### サイドバーとヘッダー

- **サイドバーに表示するアプリ**：「「アプリ」を開く」をクリックするとサイドバーの「アプリ」ページに移動し、そこで表示するアプリを選べます（Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi、MiniMax Code から選択。少なくとも 1 つは残す必要があります）
- **プロジェクト切り替えを表示**：オンにすると、Claude Code、Claude Desktop、Codex のページ上部にプロジェクト切り替えが表示されます。デフォルトはオフです

> 💡 **使用シーン**：Claude Code と Codex のみを使用する場合、他のアプリを非表示にしてサイドバーをシンプルに保てます。

### 各アプリの新しいバージョン

**起動時に各アプリの新しいバージョンを確認**：オンにすると、CC Switch の起動ごとに 1 回、インストール済みのコマンドラインアプリに新しいバージョンがないかを確認し、見つかればサイドバーの「アプリ」に点を表示します。自動ではアップグレードしません。アップグレードは「アプリ」ページで行います。[1.2 インストールガイド](./1.2-installation.md#任意管理するツールのインストール) を参照してください。

### ウィンドウとターミナル

#### 起動時に自動実行

有効にすると、システム起動時に CC Switch が自動的に起動します。

- **Windows**：レジストリを使用
- **macOS**：LaunchAgent を使用
- **Linux**：XDG autostart を使用

有効にすると **サイレント起動** スイッチが追加されます。起動時にメインウィンドウを表示せず、システムトレイでのみ動作します。

#### 閉じるときトレイへ最小化

| 「閉じるときトレイへ最小化」 | ウィンドウの閉じるボタンをクリックしたとき |
| ------------ | ---------------------------- |
| オン（デフォルト） | システムトレイに隠れ、バックグラウンドで動作を続ける |
| オフ     | アプリを完全に終了する   |

トレイからプロバイダーを素早く切り替えられるため、オンのままにしておくことを推奨します。

#### アプリ内ウィンドウボタンを有効化（Linux のみ）

オンにすると、アプリ独自の最小化、最大化/元に戻す、閉じるボタンを使用します。オフにすると、システムのウィンドウモードのままになります。

#### 優先ターミナル

プロバイダーカードの「ターミナルを開く」をクリックしたときに使うターミナルアプリを選択します。選んだターミナルが使えない場合は、システムの既定のターミナルを使います。

| プラットフォーム    | ターミナル選択肢                                                           |
| ------- | ------------------------------------------------------------------ |
| macOS   | Terminal、iTerm2、Alacritty、Kitty、Ghostty、Otty、WezTerm、Kaku、Warp |
| Windows | CMD、PowerShell、Windows Terminal                                  |
| Linux   | GNOME Terminal、Konsole、Xfce4 Terminal、Alacritty、Kitty、Ghostty |

#### 軽量モード

軽量モードは **トレイのみで実行** する状態で、アイドル時のデスクトップ占有を最小限に抑えます。

**開始方法**：トレイアイコンを右クリック → 「軽量モード」をクリック。メインウィンドウは **破棄**（単に非表示ではなく）され、UI リソースとメモリが解放されます。

**終了方法**：トレイメニューから「CC Switch を開く」をクリック、またはディープリンク / CC Switch の再起動で呼び出します。ウィンドウは **必要に応じて再構築** され、状態は保持されます。

| 項目                 | トレイへ最小化   | 軽量モード             |
| -------------------- | ---------------- | ---------------------- |
| UI プロセス          | メモリに保持     | 完全に破棄             |
| アイドル時リソース   | 通常実行と同じ   | ほぼゼロ               |
| 再表示速度           | 瞬時（直接表示） | やや遅い（ウィンドウ再構築） |
| トレイ切り替え       | 利用可能         | 利用可能               |
| ディープリンク起動   | 利用可能         | 利用可能（必要時再構築）|

> ⚠️ **注意**：軽量モードの状態は永続化されません — 次回の通常起動では通常モードに戻ります。長期的に使用する場合は「起動時に自動実行」と組み合わせてください。

## アプリ設定

アプリごとに 1 ブロックあり、そのアプリ専用のスイッチと設定ディレクトリがあります。

### Claude Code

- **Claude Code 拡張に適用**：オンにすると、VS Code の Claude Code 拡張のプロバイダーも CC Switch での切り替えに追従します（`~/.claude/config.json` の `primaryApiKey` に書き込み）。Claude Code CLI と VS Code 拡張を同時に使用する場合、オンにすると両方を一致させられます
- **Claude Code の初回確認をスキップ**：オンにすると、Claude Code の初回起動時に表示される初回インストール確認をスキップします。

> ⚠️ **注意**：「Claude Code の初回確認をスキップ」は `~/.claude.json` に `hasCompletedOnboarding: true` を書き込みます。オフにするとこのフィールドを削除します。

### Codex アプリ拡張

2 つのスイッチがあり、どちらもデフォルトでオフです：

**直接切替時に公式ログインを保持**：

- **オフ**：ローカルルーティングを使っていない場合、サードパーティのプロバイダーに切り替えるたびに `~/.codex/auth.json` が削除され、サードパーティのプロバイダーを使っている間、Codex には公式ログインがありません。削除の前に CC Switch はログインをこのマシンに一時保存し（`~/.cc-switch/codex-login-stash.json`、クラウド同期の対象外）、公式プロバイダーに戻したときに自動で復元するため、再ログインは不要です
- **オン**：サードパーティのプロバイダーに直接切り替えても `~/.codex/auth.json` を保持します。サードパーティのプロバイダーを使っている間も公式ログインが残るため、公式ログインが必要な機能を引き続き使えます

サードパーティプロバイダーの API Key は常に `~/.codex/config.toml` にのみ書き込まれ、`auth.json` には書き込まれません。ローカルルーティングを有効にしている場合、公式ログインは常に保持されます。詳しくはガイド [サードパーティ API 利用時に Codex のリモート操作と公式プラグインを保持する](../../../guides/codex-official-auth-preservation-guide-ja.md) を参照してください。

**Codex セッション履歴を統一**：有効にすると、公式サブスクリプションが共有の custom プロバイダー ID で動作し、公式とサードパーティのセッションが同じ履歴一覧に表示されます。既存の公式セッションもまとめて移行するかを選べます（移行前に自動バックアップ）。オフにする際はバックアップから復元できます。注意：プロバイダーをまたいで古いセッションを続けると、相手側のバックエンドがセッション内の推論内容を復号できず、続行に失敗することがあります。詳しくはガイド [Codex セッション履歴の統一](../../../guides/codex-unified-session-history-guide-ja.md) を参照してください。

### 設定ディレクトリ

Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi の 8 つのアプリには、それぞれ「設定ディレクトリ」の行があり、別の場所を指定できます。空欄の場合はデフォルト値が使われます。MCP、Skills、プロンプトのパスもそれに応じて変わります。

| アプリ                  | デフォルト値          |
| ----------------------- | --------------------- |
| Claude Code             | `~/.claude/`          |
| Codex                   | `~/.codex/`           |
| Gemini CLI              | `~/.gemini/`          |
| Grok Build              | `~/.grok/`            |
| OpenCode                | `~/.config/opencode/` |
| OpenClaw                | `~/.openclaw/`        |
| Hermes                  | `~/.hermes/`          |
| Pi                      | `~/.pi/agent/`        |

Claude Desktop と MiniMax Code は、ここでのディレクトリ上書きに対応していません（そのためアプリ設定にはこの 2 つはありません）。MiniMax Code のデータディレクトリはデフォルトで `~/.minimax/` で、環境変数 `MINIMAX_DATA_DIR`（または `MAVIS_DATA_DIR`）で指定できます。Hermes は `HERMES_HOME`、Pi は `PI_CODING_AGENT_DIR` も認識します。

> 💡 **WSL**：CC Switch は WSL を自動認識しません。Windows ではディレクトリを WSL 内のパス（例：`\\wsl.localhost\Ubuntu\home\<ユーザー名>\.claude`）に変更すると、CC Switch が WSL 内の設定を読み書きします。

> ⚠️ **注意**：ディレクトリを変更した後はアプリの再起動が必要で、対応する CLI ツールも同じディレクトリを設定する必要があります。

> 💡 **Skills の保存場所と同期方式**は設定にはありません。サイドバーの「Skills」ページで「保存と同期」をクリックすると、マスターコピーを「CC Switch フォルダ」と「共通フォルダ」（`~/.agents/skills`）のどちらに置くか、各アプリへの同期にシンボリックリンクとコピーのどちらを使うかを選べます。

## ローカルルーティング

設定 → ローカルルーティング

このグループでは、ローカルルーティングの全体に関わる部分をまとめて管理します：

- **サービス**：ルーティングサービスの稼働状況（稼働時間、リクエスト数、成功率、アクティブ接続）を表示し、「起動」/「停止」ができます。「待ち受けアドレスとポート」のデフォルトは `127.0.0.1` で、変更後は「保存してサービスを再起動」をクリックします。「リクエストの使用量を記録」をオフにすると、使用量にルーティング経由のリクエストの明細が残りません。また、ルーティングサービスを使っているアプリがあるときは停止できないため、先にそれらを直接接続に戻してください
- **ルーティングを使用中のアプリ**：現在ルーティングまたは集約モードのアプリを一覧表示し、「開く」でそのアプリのページに移動できます。「すべて直接接続に戻す」を押すと、すべてのアプリに直接接続の設定を書き戻してルーティングサービスを停止します。転送先、キュー、集約のリストは保持されます
- **自動フェイルオーバー**：各アプリのタイムアウト、再試行、サーキットブレーカーを調整します。キューは各アプリページの「ルーティング」タブで管理します。詳しくは [4.3 フェイルオーバー](../4-proxy/4.3-failover.md) をご覧ください
- **整流器**：一部の上流で互換性のないリクエストを自動的に修正します。たとえば Thinking 署名に互換性がない場合は、該当する内容を取り除いてから再試行します

ルーティングや集約を開始する入口は、各アプリページ上部の「直接接続 / ルーティング / 集約」タブです。詳しくは [4.1 ローカルルーティングサービス](../4-proxy/4.1-service.md) をご覧ください。

## ネットワーク

設定 → ネットワーク

**グローバル送信プロキシ**：CC Switch が外部 API にアクセスする際に使う HTTP/HTTPS プロキシを設定します。外部 API にプロキシ経由でアクセスする必要がある場合に使用します。

## データ

設定 → データ

### 保存場所

**CC Switch 設定ディレクトリ**：CC Switch 自体のデータの保存場所で、デフォルトは `~/.cc-switch/` です。クラウド同期フォルダを指定することもできます。変更後は「保存」をクリックし、反映にはアプリの再起動が必要です。

### データ管理

#### 設定のエクスポート

「SQL バックアップをエクスポート」ボタンをクリックして、以下の内容を含む SQL バックアップファイルを保存します：

- すべてのプロバイダー設定
- MCP サーバー設定
- Prompts プリセット
- 使用量ログ
- アプリ設定

エクスポートされるファイル名の形式は `cc-switch-export-{timestamp}.sql` です。

#### 設定のインポート

1. 「SQL ファイルを選択」をクリック（CC Switch でエクスポートしたバックアップのみインポートできます）
2. 以前にエクスポートしたバックアップファイルを選択
3. ボタンが「インポート」に変わったら、クリックしてインポートを開始
4. インポートが成功すると、インポート前に自動作成されたバックアップの ID が表示されます

> ⚠️ **注意**：インポートは既存の設定を上書きするため、事前に現在の設定をエクスポートしてバックアップすることをお勧めします。

### バックアップと復元

バックアップ管理パネルでは、データベースバックアップを完全に管理できます。

#### 自動バックアップ設定

| 設定 | オプション | デフォルト |
|------|---------|---------|
| 自動バックアップ間隔 | 無効、6時間、12時間、24時間、48時間、7日 | 24時間 |
| バックアップ保持数 | 3、5、10、15、20、30、50 | 10件 |

間隔を設定すると、CC Switch はスケジュールに従って自動的にデータベースをバックアップします。保持数を超えた古いバックアップは自動的に削除されます。

#### バックアップリスト

パネルには既存のすべてのバックアップが以下の情報とともに表示されます：
- **表示名**（タイムスタンプから自動生成、例：`db_backup_20260315_143000`）
- **作成日時**
- **ファイルサイズ**（例：「1.5 MB」）

#### バックアップ操作

| 操作 | 説明 |
|------|------|
| **今すぐバックアップ** | 即座にバックアップを作成 |
| **復元** | 選択したバックアップからデータベースを復元。復元前に現在のデータベースの安全バックアップが自動的に作成される |
| **名前変更** | バックアップの表示名を変更 |
| **削除** | バックアップを完全に削除（確認あり） |

> ⚠️ **重要**：バックアップの復元は現在のデータベースを上書きします。復元前に安全バックアップが自動作成されるため、必要に応じて元に戻すことができます。

#### その他のバックアップ

バックアップリストの下にある「その他のバックアップ」の一覧には、CC Switch がさまざまな場所に残したバックアップ（Skill アンインストール時のバックアップ、設定ファイル初回書き込みバックアップ、Codex セッション移行バックアップ、Hermes / OpenClaw 設定のバックアップ、旧バージョンの残存ファイルなど）が表示され、各項目の場所と使用サイズが分かります。合計サイズは見出しの横に表示されます。各項目は「ファイルマネージャーで表示」でき、自分で「削除」することもできます（確認あり、完全に削除されます）。データベースのバックアップは上のリストで管理します。

> ⚠️ 削除すると対応する内容を復元できなくなるバックアップがあります。たとえば「設定ファイル初回書き込みバックアップ」を削除すると書き換え前の元ファイルが見つからなくなり、「Skill アンインストール時のバックアップ」を削除するとアンインストール済みの Skill を復元できなくなります。各項目の下の説明に結果が書かれています。

### クラウド同期

**WebDAV** または **S3 互換ストレージ** を使って複数のデバイス間で設定を同期します。同時に有効にできるのはどちらか一方だけです。信頼性の向上のため、デュアルレイヤーバージョニングを備えた **v2 プロトコル** を使用しています。

#### WebDAV

| 設定項目   | 説明                                  |
| -------- | ------------------------------------- |
| サービス | 坚果云 / Nextcloud / Synology NAS / カスタム    |
| WebDAV サーバー URL | WebDAV サーバー URL                     |
| ユーザー名   | ログインユーザー名                            |
| パスワード   | ログインパスワード（アプリ専用パスワード、保存済みの場合は未変更で保持） |
| リモートルートディレクトリ | リモート保存パス（デフォルト `cc-switch-sync`） |
| 同期プロファイル名 | デバイスプロファイル名（デフォルト `default`）      |
| 自動同期 | 有効にすると、データベースが変更されるたびに自動でアップロード |

#### S3 互換ストレージ

| 設定項目          | 説明                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------- |
| サービス          | AWS S3 / MinIO / Cloudflare R2 / Alibaba Cloud OSS / Tencent Cloud COS / Huawei OBS / S3互換サービス（カスタム） |
| リージョン (Region) | 例：`us-east-1`。R2 では `auto` を入力                                              |
| バケット (Bucket) | 同期データを保存するバケット                                                          |
| Access Key ID / Secret Access Key | アクセス用の認証情報                                                 |
| Endpoint          | AWS では空欄可。多くの S3 互換サービスでは入力が必要                                  |
| リモートルートディレクトリ | デフォルト `cc-switch-sync`                                                  |
| 同期プロファイル名 | デフォルト `default`                                                                 |
| 自動同期          | 有効にすると、データベースが変更されるたびに自動でアップロード                        |

#### 操作

| 操作 | 説明 |
|------|------|
| **接続テスト** | サービスのアドレスと認証情報が有効か確認 |
| **アップロード** | ローカルデータベースをリモートにアップロード。進捗スピナーを表示 |
| **ダウンロード** | リモートデータベースをダウンロード。確認前にリモートスナップショット情報（プロトコルバージョン、DB バージョン、タイムスタンプ、サイズ）を表示。上書き前にローカルデータベースの安全バックアップを自動作成 |

#### 自動同期

**自動同期** を有効にすると：
- 初回有効化時に確認ダイアログが表示される
- データベースが変更されるたびに、CC Switch が自動的にデータベースをクラウドにアップロード
- パネルに前回の同期時刻が表示される。自動同期に失敗した場合はエラーが表示され、以降の変更時に再試行が続けられる

#### リモートスナップショット情報

ダウンロード前に、CC Switch はリモートスナップショットの詳細を表示します：
- プロトコルバージョン（v2）
- データベース互換バージョン
- リモートバックアップのタイムスタンプ
- ファイルサイズ
- 互換性ステータス（非互換の場合は警告）

> ⚠️ **注意**：アップロードはリモートデータを、ダウンロードはローカルデータを上書きします。ダウンロード前に安全バックアップが自動作成されます。

### アプリ診断ログ

| 設定項目         | 説明                                                        |
| ---------------- | ----------------------------------------------------------- |
| 診断ログを有効化 | `cc-switch.log` を制御します。リクエストの使用量記録と `crash.log` には影響しません |
| ログレベル       | error / warn / info / debug / trace                         |

ログレベルの説明：

- **error** - エラーのみ記録
- **warn** - 警告とエラーを記録
- **info** - 一般情報を記録（デフォルト）
- **debug** - デバッグ情報を記録
- **trace** - すべての詳細情報を記録

## アカウント（Beta）

ログインの入口は左サイドバーの「アカウント」にあり、設定の中にはありません。アカウントではサードパーティの OAuth 認証情報を一元管理します。現在、以下の 3 種類のアカウントタイプをサポートしています：

| アカウントタイプ              | 用途                                                            |
| ----------------------------- | --------------------------------------------------------------- |
| **GitHub Copilot**            | Copilot リバースプロキシと組み合わせて使用                     |
| **ChatGPT (Codex OAuth)**     | Codex OAuth リバースプロキシと組み合わせて使用、ChatGPT アカウントを管理 |
| **xAI (Grok OAuth)**          | xAI Responses API リバースプロキシと組み合わせて使用                    |

**ここでできること**：

- Device Code フローで ChatGPT / GitHub / xAI アカウントにログイン
- ログイン済みアカウント一覧と認証状態の確認
- マルチアカウント時のデフォルトアカウント設定
- 個別アカウントの削除や全アカウントの一括ログアウト

xAI 連携はローカルのループバックコールバックではなく、OAuth 2.0 Device Authorization Grant を使用します。ネットワーク依存関係は次のとおりです：

| 依存関係 | エンドポイント |
| -------- | -------------- |
| OpenID discovery | `https://auth.x.ai/.well-known/openid-configuration` |
| デバイス認証 | discovery の `device_authorization_endpoint`（現在は `https://auth.x.ai/oauth2/device/code`） |
| Token 交換・更新 | discovery の `token_endpoint`（現在は `https://auth.x.ai/oauth2/token`） |
| 推論 | `https://api.x.ai/v1/responses` |
| モデル取得 | `https://api.x.ai/v1/models` |

ローカルのコールバックポートは使用しません。認証およびモデルリクエストは CC Switch のグローバル送信プロキシ設定を共有します。

xAI 連携は CC Switch 用に登録された OAuth アプリケーションを**使用しません**。公式 Grok CLI 用に登録された公開 OAuth クライアントの ID とスコープ（`client_id: b1a00492-073a-47ea-816f-4c329264a828`、`grok-cli:access` を含む）を再利用して、アカウントベースの API アクセスを取得します。

> ⚠️ **警告**：これらのアカウント型リバースプロキシは、リバースエンジニアリングされた OAuth 連携を使用しており、アカウントおよび利用規約上のリスクがあります。上流製品の OAuth クライアント再利用は公式にサポートされない可能性があり、サービス提供者によるアカウントの制限・停止につながるおそれがあります。各プロバイダーの規約を確認し、自己責任で使用してください。既存の Codex フローについては [2.1 プロバイダーの追加 → Codex OAuth リバースプロキシ](../2-providers/2.1-add.md#codex-oauth-リバースプロキシclaude-プロバイダー) の完全なリスクに関する注意事項も参照してください。

設定 → 情報

### バージョン情報

現在の CC Switch バージョン番号を表示し、以下をサポートします：

- 更新の確認。新しいバージョンがあるときは「v{{version}} に更新」をクリックしてダウンロードとインストール（ポータブル版は手動ダウンロード）

### ツールのインストールとアップグレード

各 AI プログラミングツールのバージョン検出、インストール、アップグレード、「すべて更新」はここではなく、左サイドバーの「アプリ」ページにあります。詳しくは [1.2 インストールガイド](./1.2-installation.md#任意管理するツールのインストール) を参照してください。Windows で「アプリ設定」の中のあるツールのディレクトリを WSL のパスに設定している場合、「アプリ」ページは対応する WSL ディストリビューション内でそのツールを検出・アップグレードします。
