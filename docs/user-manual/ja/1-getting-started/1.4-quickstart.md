# 1.4 クイックスタート

このセクションでは、5 分で初回設定を完了する方法を説明します。

## ステップ 1：プロバイダーの追加

1. 左サイドバーで管理したいツールを選び、ページ右上の **+**（プロバイダーを追加）をクリック
2. 「プロバイダータイプ」からプロバイダーを選択
   - よく使われるプリセット：Zhipu GLM、MiniMax、DeepSeek、Kimi、PackyCode
   - または「カスタム」を選択して手動設定
3. **API Key** を入力
4. 「追加」をクリック

> 💡 **ヒント**：追加パネルは中国語名とドメインでの検索に対応しており、同じ提供元のプランやリージョンは 1 行にまとめられます。プリセットではエンドポイントアドレスが自動入力されるため、API Key のみ入力すれば使用できます。

## ステップ 2：プロバイダーの切り替え

追加が完了すると、プロバイダーがリストに表示されます。

**方法 1：アプリページで切り替え**
- プロバイダーカードの「切り替え」ボタンをクリックすると、状態が「使用中」になります
- OpenCode、OpenClaw、Hermes、MiniMax Code は共存型アプリで、ボタンは「追加」（Pi は「有効化」）です。複数のプロバイダーを同時に追加できます

**方法 2：トレイで素早く切り替え**
- システムトレイアイコンを右クリック
- ツールごとに 1 行、「名前 · モード · プロバイダー · クォータ」と表示されます。サブメニューでプロバイダー名を直接クリックします（Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build に対応）

## ステップ 3：反映方法

プロバイダーを切り替えた後、各 CLI ツールの反映方法は異なります：

| アプリ | 反映方法 |
|------|----------|
| Claude Code | ✅ 即時反映（ホットリロード対応） |
| Claude Desktop | Claude Desktop の再起動が必要 |
| Codex | ターミナルの再起動が必要 |
| Gemini | Gemini CLI の再起動が必要 |
| Grok Build | Grok Build の再起動が必要 |
| OpenCode | ターミナルの再起動が必要 |
| OpenClaw | ターミナルの再起動が必要 |
| Hermes / Pi / MiniMax Code | プロバイダーを追加するとツールの設定に書き込まれます。Pi と MiniMax Code ではツール側で使用するモデルを選択し、Hermes ではカードの「有効化」をクリックして現在のプロバイダーに設定できます |

ルーティングモードの場合、Claude Code、Codex、Gemini CLI、Grok Build でのプロバイダー切り替えは以降のリクエストに即座に反映されます。ただし、切り替えによってモデルが変わる場合、Codex、Gemini CLI、Grok Build は再起動が必要になることがあります。

## 直接接続、ルーティング、集約（任意）

Claude Code、Codex、Gemini CLI、Grok Build のページ上部には「直接接続 / ルーティング」のタブがあり、Claude Code と Codex には「集約」もあります。タブをクリックしても表示が切り替わるだけで設定は変更されません。実際に切り替えるには、ページ上の結果が明記されたボタン「ルーティングを開始」「集約に切り替え」を押します。直接接続に戻すときは「直接接続に戻す」を押します。

- **直接接続**（デフォルト）：クライアントがプロバイダーに直接接続します。日常の利用ではこれを選びます
- **ルーティング**：リクエストをこのマシン上の CC Switch 経由で転送し（デフォルトは `127.0.0.1:15721`）、API フォーマットの変換やフェイルオーバーができます。Claude Code で OpenAI や Gemini 形式のプロバイダーを使いたい場合や、Codex で Claude を使いたい場合に選びます
- **集約**：複数プロバイダーのモデルを 1 つのモデルリストにまとめ、選んだモデルのプロバイダーへリクエストを送ります。フェイルオーバーは行いません

ルーティングと集約は CC Switch が起動し続けている必要があります。CC Switch を終了すると自動的に直接接続に戻り、次回起動時に再び接続されます。公式サブスクリプションはルーティングを経由しません（Codex の OpenAI Official は例外）。詳細は [ローカルルーティングの有効化](../4-proxy/4.1-service.md) を参照してください。

### Claude Code の初回インストール時の注意

Claude Code を初めて起動するときに**ログイン**の要求や初期化ガイドが表示される場合は、CC Switch で「Claude Code の初回確認をスキップ」オプションを有効にしてください：

1. CC Switch の「設定 → アプリ設定」を開き、Claude Code のブロックを探す
2. 「Claude Code の初回確認をスキップ」スイッチをオンにする
3. Claude Code を再起動

## 設定の確認

再起動後、対応する CLI ツールを起動して簡単な質問でテストします：

```bash
# Claude Code - 起動後にテスト質問を入力
claude
> こんにちは、簡単に自己紹介してください

# Codex - 起動後にテスト質問を入力
codex
> こんにちは、簡単に自己紹介してください

# Gemini - 起動後にテスト質問を入力
gemini
> こんにちは、簡単に自己紹介してください

# OpenCode - 起動後にテスト質問を入力
opencode
> こんにちは、簡単に自己紹介してください

# OpenClaw - 起動後にテスト質問を入力
openclaw
> こんにちは、簡単に自己紹介してください
```

AI が正常に回答すれば、設定は成功です。

> **注意**：初回起動時、CC Switch は Claude Code、Codex、Gemini CLI、Grok Build の既存設定を `default` という名前のプロバイダーとして自動的にインポートし、これらのツールと Claude Desktop に公式プロバイダーを追加します。既存の設定は失われません。

## よくある質問

### 切り替えても反映されない場合

ターミナルまたは CLI ツールを再起動してください。設定ファイルは切り替え時に更新されますが、実行中のプログラムは自動的に設定を再読み込みしません。

### プリセットが見つからない場合

プロバイダーがプリセットリストにない場合は、「カスタム」を選択して手動設定してください。設定形式については [プロバイダーの追加](../2-providers/2.1-add.md) を参照してください。

### 公式ログインに戻すには

Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build のプロバイダーリストには、それぞれ公式プロバイダー（Claude Official、OpenAI Official、Google Official、Grok Official など）が最初から含まれています。そちらに切り替えてクライアントを再起動し、各ツール自身のログインフローに従ってください。リストにない場合（削除した場合や旧バージョンからアップグレードした場合など）は、プリセットから追加し直せます。
