# 5.3 ディープリンクプロトコル

## 機能説明

CC Switch は `ccswitch://` ディープリンクプロトコルをサポートしており、リンクからワンクリックで設定をインポートできます。

**使用シーン**：
- チーム内での設定共有
- チュートリアルでのワンクリック設定
- デバイス間の素早い同期

## オンライン生成ツール

CC Switch はオンラインのディープリンク生成ツールを提供しています：

**アクセス先**：[https://ccswitch.io/deplink.html](https://ccswitch.io/deplink.html)

> 自分のサイトに「CC Switch にワンクリックでインポート」ボタンを置きたいサイト運営者は、[サイト運営者向け連携ガイド](https://github.com/farion1231/cc-switch/blob/main/docs/guides/deeplink-site-integration-guide-ja.md)を参照してください。ユーザーごとのリンク生成、ボタンの組み込み方、インポート直後に残高を表示する方法を説明しています。

### 使用方法

1. 上記の Web ページを開く
2. インポートタイプを選択（プロバイダー / MCP / プロンプト / Skill リポジトリ）
3. 設定情報を入力
4. 「リンクを生成」をクリック
5. 生成されたディープリンクをコピー
6. 他の人に共有するか、別のデバイスで使用

## プロトコル形式

### V1 プロトコル

URL パラメータ形式で、読みやすく生成しやすい形式です：

```
ccswitch://v1/import?resource={type}&app={app}&name={name}&...
```

**共通パラメータ**：

| パラメータ | 必須 | 説明 |
|------|------|------|
| `resource` | はい | リソースタイプ：`provider` / `mcp` / `prompt` / `skill` |
| `app` | はい | アプリタイプ（provider、prompt で必要）：`claude` / `codex` / `gemini` / `agy` / `grokbuild` / `opencode` / `openclaw` / `hermes` / `pi`。prompt ではさらに `mcode` に対応。Claude Desktop、MiniMax Code のプロバイダーは現在ディープリンクでのインポートに対応していません |
| `name` | provider、prompt で必須 | 名前（MCP のサーバー ID は `config` 内の `mcpServers` のキーから取得。Skill では不要） |

**プロバイダーパラメータ**（resource=provider）：

| パラメータ | 必須 | 説明 |
|------|------|------|
| `endpoint` | いいえ | API エンドポイントアドレス（カンマ区切りで複数 URL 対応） |
| `apiKey` | いいえ | API キー |
| `homepage` | いいえ | プロバイダー公式サイト |
| `model` | いいえ | デフォルトモデル。純正の Claude モデルを提供する場合、Claude Code では空欄で構いません。Pi では必須 |
| `apiFormat` | いいえ | API 形式：`anthropic` / `openai_chat` / `openai_responses` / `gemini_native`。アプリごとに変換されます（OpenCode の `npm`、OpenClaw と Pi の `api`、Hermes の `api_mode`。Claude Code、Codex、Grok Build でネイティブ以外の形式を指定した場合はローカルルーティングが必要）。省略時はアプリのデフォルト形式。アプリが対応しない形式は拒否されます |
| `haikuModel` | いいえ | Haiku モデル（Claude のみ） |
| `sonnetModel` | いいえ | Sonnet モデル（Claude のみ） |
| `opusModel` | いいえ | Opus モデル（Claude のみ） |
| `notes` | いいえ | メモ |
| `icon` | いいえ | CC Switch 内蔵アイコン名。英小文字・数字と `. _ -` のみ使用でき、それ以外は無視されます |
| `iconUrl` | いいえ | 独自アイコン画像の URL（v4.0.10 以降）。確認ダイアログを開いた時点でダウンロードし、インポート後はカードのアイコンになります。https・ドメイン名・デフォルトポートであること、公開アクセス可能であること、256 KB 以下で `Content-Type` が PNG / JPEG / WebP / SVG のいずれかかつ実際の形式と一致していることが条件です。ダウンロードに失敗してもエラーにはならず、`icon` または名前の頭文字が表示されます |
| `config` | いいえ | Base64 エンコードされた設定内容。Codex は `{"auth": {...}, "config": "<config.toml のテキスト>"}` の形式、または `configFormat=toml` で config.toml 全体を渡します。選択された `[model_providers.*]` テーブルの接続・認証フィールド（`wire_api`、`http_headers`、`supports_websockets`、エンドポイントと同一オリジンの `model_catalog_url` など）と、トップレベルのモデル・推論レベル・`web_search` などのみをインポートし、ルートは常に `custom` に変更されます。`[features]`、MCP、権限などのグローバル設定はインポートされません。テーブルに `auth`、`aws`、`gateway_oauth`、`env_http_headers` を含むリンクは拒否され、`env_key` は無視されます（リンク自身のキーを使用） |
| `configFormat` | いいえ | 設定形式：`json` / `toml` |
| `configUrl` | いいえ | 未対応です。指定したリンクは拒否されるため、`config` でインライン指定してください |
| `enabled` | いいえ | 確認ダイアログの「インポート後に切り替える」スイッチの初期値（OpenCode、OpenClaw、Hermes、Pi では「アプリの設定へ追加する」で、省略時はオン）。インポート時はスイッチの状態に従います |
| `usageScript` | いいえ | 使用量クエリスクリプト |
| `usageEnabled` | いいえ | 使用量クエリを有効にするか。省略時は `usageScript` があれば有効、なければ無効です。`false` を指定するとインポートのみ行い有効化しません（アプリ内で後から有効にできます）。スクリプト本文はインポート確認ダイアログに全文表示されます |
| `usageApiKey` | いいえ | 使用量クエリ専用 API Key |
| `usageBaseUrl` | いいえ | 使用量クエリ専用アドレス |
| `usageAccessToken` | いいえ | 使用量クエリアクセストークン |
| `usageUserId` | いいえ | 使用量クエリユーザー ID |
| `usageAutoInterval` | いいえ | 自動クエリ間隔（分） |

Grok Build の `config` も `{"config": "<config.toml のテキスト>"}` の形式、または `configFormat=toml` で config.toml 全体を渡せます。`[models] default` が指す `[model."<名前>"]` テーブル（表示名、`description`、`api_backend`、`context_window`、サンプリング・リトライ設定など）のみをインポートし、エンドポイントとキーは常にリンクのパラメーターを使用します。他のモデルテーブルはインポートされません。テーブルに `auth_provider`、`env_http_headers`、`mtls_cert_dir` を含むリンクは拒否され、`env_key` は無視されます。

**プロンプトパラメータ**（resource=prompt）：

| パラメータ | 必須 | 説明 |
|------|------|------|
| `content` | はい | プロンプト内容。Base64 エンコードが必要（さらに URL エスケープ） |
| `description` | いいえ | 説明 |
| `enabled` | いいえ | 確認ダイアログの「インポート後に有効にする」スイッチの初期値。インポート時はスイッチの状態に従います |

**MCP パラメータ**（resource=mcp）：

| パラメータ | 必須 | 説明 |
|------|------|------|
| `apps` | はい | アプリリスト（カンマ区切り、例：`claude,codex,gemini,grokbuild`）。指定可能な値：`claude` / `codex` / `gemini` / `agy` / `grokbuild`（`grok` とも書けます）/ `opencode` / `hermes` / `pi` / `mcode`。`openclaw` は MCP に対応しておらず無視されます |
| `config` | はい | MCP 設定の JSON。形式は `{"mcpServers": {"<サーバー ID>": {...}}}` で、Base64 エンコードが必要（さらに URL エスケープ） |
| `enabled` | いいえ | 現在は効果がありません |

**Skill パラメータ**（resource=skill）：ディープリンクで追加されるのは Skill リポジトリで、Skill が直接インストールされるわけではありません。追加後に「Skills」ページでインストールする Skill を選びます。

| パラメータ | 必須 | 説明 |
|------|------|------|
| `repo` | はい | リポジトリ（形式：`owner/name`） |
| `directory` | いいえ | ディレクトリパス |
| `branch` | いいえ | Git ブランチ |

**例**：
```
ccswitch://v1/import?resource=provider&app=claude&name=My%20Provider&endpoint=https%3A%2F%2Fapi.example.com&apiKey=sk-xxx
```

## インポートタイプの例

### プロバイダーのインポート

```
ccswitch://v1/import?resource=provider&app=claude&name=My%20Provider&endpoint=https%3A%2F%2Fapi.example.com&apiKey=sk-xxx
```

### MCP サーバーのインポート

```
ccswitch://v1/import?resource=mcp&apps=claude,codex&config=eyJtY3BTZXJ2ZXJzIjp7Im1jcC1mZXRjaCI6eyJjb21tYW5kIjoidXZ4IiwiYXJncyI6WyJtY3Atc2VydmVyLWZldGNoIl19fX0%3D
```

ここで `config` は `{"mcpServers":{"mcp-fetch":{"command":"uvx","args":["mcp-server-fetch"]}}}` を Base64 エンコードしたものです（末尾の `=` は `%3D` にエスケープ）。

### Prompt プリセットのインポート

```
ccswitch://v1/import?resource=prompt&app=claude&name=%E4%BB%A3%E7%A0%81%E5%AE%A1%E6%9F%A5&content=IyDop5LoibIK5L2g5piv5LiA5Liq5LiT5Lia55qE5Luj56CB5a6h5p%2Bl5LiT5a62
```

ここで `content` は、中国語のサンプルプロンプト（見出し `# 角色` の後に、プロのコードレビュー担当者という役割を指定する 1 文が続くもの）を Base64 エンコードしたものです（`+` は `%2B` にエスケープ）。

### Skill のインポート

```
ccswitch://v1/import?resource=skill&repo=owner/repo&directory=skills/my-skill&branch=main
```

## ディープリンクの生成

### 手動生成

1. パラメータを準備
2. V1 プロトコル形式で URL を組み立て
3. 特殊文字を URL エンコード

**例**：

```javascript
const params = new URLSearchParams({
  resource: 'provider',
  app: 'claude',
  name: 'My Provider',
  endpoint: 'https://api.example.com',
  apiKey: 'sk-xxx'
});

const url = `ccswitch://v1/import?${params.toString()}`;
```

### オンラインツール

CC Switch 公式のオンラインディープリンク生成ツールを使用するとより便利です。

## ディープリンクの使用

### リンクのクリック

ブラウザや他のアプリでディープリンクをクリック：

1. システムが CC Switch を開くかどうかを確認
2. 確認後、CC Switch が起動
3. インポート確認ダイアログを表示
4. インポートを確認

### インポートの確認

インポート前に確認ダイアログが表示され、以下が含まれます：

- インポートタイプ
- 設定のプレビュー
- 確認/キャンセルボタン

確認後の動作はタイプによって異なります：プロバイダーは対応するアプリのプロバイダー一覧に追加され、すぐに切り替えるかどうか（OpenCode、OpenClaw、Hermes、Pi ではアプリの設定へ追加するかどうか）はダイアログのスイッチで決まります。MCP は指定したすべてのアプリの設定ファイルにすぐ書き込まれます。プロンプトをすぐに有効にするかどうかもダイアログのスイッチで決まり、有効にすると同じアプリの他のプロンプトは無効になります。設定に疑わしい内容（ローカルや社内ネットワークを指すアドレス、プロセスの読み込み動作を変えられる環境変数、シェルでコマンド全体を実行するもの、使用量照会スクリプトなど）が含まれる場合、ダイアログにリスク警告が表示されるので、項目ごとに確認してください。

**セキュリティ上の注意**：信頼できるソースからの設定のみインポートしてください。

## プロトコルの登録

### 自動登録

CC Switch のインストール時に `ccswitch://` プロトコルが自動登録されます。

### 手動登録

プロトコルが正しく登録されていない場合：

**macOS**：
アプリを再インストールしてください（CC Switch を「アプリケーション」フォルダに入れ、少なくとも一度起動します）。

**Windows**：
アプリを再インストールするか、レジストリを確認：
```
HKEY_CLASSES_ROOT\ccswitch
```

**Linux**：
`.desktop` ファイルの `MimeType` 設定を確認。

## セキュリティに関する考慮事項

### 機密情報

ディープリンクには機密情報（API Key など）が含まれる場合があります：

- API Key を含むリンクを公開の場で共有しない
- 共有前に機密情報を削除または置換
- 安全なチャネルでリンクを送信

### ソースの確認

インポート前に CC Switch は以下を実行します：

1. データ形式の検証
2. 設定のプレビュー表示
3. ユーザーの確認を要求

### 悪意のあるリンクからの防護

CC Switch は以下を確認します：

- データ形式が正当か
- 必須フィールドが揃っているか
- 設定値が妥当な範囲内か

## トラブルシューティング

### リンクが開けない

**確認事項**：
1. CC Switch がインストールされているか
2. プロトコルが正しく登録されているか
3. リンクの形式が正しいか

### インポートに失敗する

**考えられる原因**：
- Base64 エンコードのエラー
- JSON 形式のエラー
- 必須フィールドの不足

**解決方法**：
1. 元の JSON 形式を確認
2. Base64 エンコードをやり直す
3. すべての必須フィールドが存在することを確認
