# 3.2 Prompts プロンプト管理

## 機能説明

Prompts 機能は、システムプロンプトのプリセットを管理します。システムプロンプトは AI の動作や回答スタイルに影響します。

CC Switch を使用すると：

- 複数のプロンプトプリセットを作成
- さまざまなシーンのプロンプトを素早く切り替え
- デバイス間でプロンプト設定を同期

## Prompts パネルを開く

左サイドバーの **プロンプト** をクリックします。これはグローバルなページで、ヘッダー左側のドロップダウンでアプリを選びます：Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、Hermes、Pi、MiniMax Code（サイドバーの「アプリ」ページで表示にしたアプリだけが並びます）。

- Claude Desktop には独自のプロンプトがなく、そのページから開いた場合に操作するのは Claude Code のプロンプトです。
- OpenClaw はプロンプトページにはありません。AGENTS.md などのファイルは [ワークスペースエディター](./3.5-workspace.md) で管理します。
- Hermes でここから管理するのはペルソナファイル `SOUL.md` です。`MEMORY.md` と `USER.md` は Hermes ページの「メモリ」ページで編集します。

ページ上部に現在のアプリの**対象ファイル**（パスとサイズ）が表示され、その下にプロンプトの一覧があります。各行に「有効にする / 無効にする」ボタン、「編集」ボタン、⋯ メニュー（ほかのアプリにコピー、本文をコピー、削除）があります。一覧が空でないときは検索ボックスが表示され、名前・説明・本文で検索できます。

## プリセットの作成

### 操作手順

1. ヘッダーの **プロンプトを追加** をクリックすると、右側にドロワーが開きます
2. 名前を入力します。説明は任意です（CC Switch 内でのみ表示）
3. 本文欄に Markdown でプロンプトを書きます
4. 「追加」をクリックします

ファイルにすでにあって CC Switch にはまだない内容は、ヘッダーの ⋯ メニューにある「現在の xxx を取り込む」で 1 件として保存できます。ファイルは変更されません。

### プロンプトの書き方のヒント

**構造化フォーマット**：

```markdown
# 役割定義

あなたはプロのコードレビュー専門家です。

## コア能力

- コード品質分析
- パフォーマンス最適化の提案
- セキュリティ脆弱性の検出

## 回答スタイル

- 簡潔明瞭
- 具体的な例を提供
- 改善提案を提示

## 注意事項

- ビジネスロジックを変更しない
- コードスタイルの一貫性を保つ
```

## プリセットの有効化

### 操作方法

プリセット行の「有効にする」ボタンをクリックします。有効なものは「有効」と表示され、ボタンは「無効にする」に変わります。

### 単一有効化

各アプリで同時に有効にできるプリセットは 1 つだけです。新しいものを有効にすると、以前のものは自動的に無効になります。有効にすると、そのプリセットの本文が対象ファイルを上書きします。無効にするとファイルは空になります（Pi の `AGENTS.md` は削除されます）。

### 同期先

有効化後、プロンプトは対応するアプリのファイルに書き込まれます：

| アプリ | ファイルパス |
|------|----------|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Grok Build | `~/.grok/AGENTS.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |
| Hermes | `~/.hermes/SOUL.md`（Hermes のペルソナ。新しく開いたセッションから反映） |
| Pi | `~/.pi/agent/AGENTS.md` |
| MiniMax Code | `~/.minimax/AGENTS.md`（内容は 32 KiB 以内） |

設定で設定ディレクトリを上書きしている場合、ファイルパスもそれに合わせて変わります。MiniMax Code にはディレクトリの上書き設定がなく、データディレクトリは環境変数 `MINIMAX_DATA_DIR` で指定できます。Pi はさらに `PI_CODING_AGENT_DIR` も認識します。

### Pi の追加内容

Pi の Prompts パネルは 3 つのタブに分かれています：

| タブ | 説明 |
|------|------|
| ライブラリ | AGENTS.md のプロンプトライブラリ。同時に有効にできるのは 1 件で、Pi のグローバル `AGENTS.md` に書き込まれます |
| システムプロンプト | `APPEND_SYSTEM.md`（Pi 内蔵の基本プロンプトの後ろに追記、推奨）または `SYSTEM.md`（Pi 内蔵の基本プロンプトを置き換え）を編集します。ファイルが存在すれば反映されるため、有効化は不要です |
| テンプレート | Pi のプロンプトテンプレートを管理します。保存後は Pi で `/コマンド名` と入力して呼び出します。有効化は不要です |

すでに開いている Pi は自動では更新されません。アイドル時に `/reload` を実行してください。新しく起動した Pi は自動で読み込みます。

## プリセットの編集

1. プリセット行の「編集」ボタンをクリック（または行をクリック）
2. ドロワーで名前・説明・本文を変更
3. 「保存」をクリック

現在有効なプリセットを編集した場合、保存後に対象ファイルが即座に上書きされます。

## プリセットの削除

1. プリセット行の ⋯ メニューの「削除」をクリック
2. 削除を確認

有効になっているプリセットは削除できません。先に無効にしてください。削除は CC Switch 内のその 1 件にだけ影響し、対象ファイルは変更されません。

## 手動でファイルを変更した場合

CLI や外部エディタで対象ファイルを直接編集しても、CC Switch はその変更を失いません：

| シーン | 処理方法 |
|------|----------|
| 有効なプリセットに対応するファイルを別の場所で編集した | 次にこのページを開いたとき、変更が有効なプリセットに取り込まれる |
| ファイルに CC Switch にない内容がある | 別のプロンプトを有効にする前に、その内容を「元のプロンプト」として 1 件保存してから上書きする |
| ファイルに内容があるのに一覧が空 | ヘッダー ⋯ メニューの「現在の xxx を取り込む」、または空の一覧ページの「既存の内容を取り込む」で 1 件として保存する |

## アプリ間での使用

Prompts はアプリごとに個別に管理されます。ヘッダーのドロップダウンでアプリを切り替えると、一覧がそのアプリのプリセットに変わります。

複数のアプリで同じプロンプトを使いたいときは、入力し直す必要はありません。プリセット行の ⋯ メニューの「ほかのアプリにコピー」でコピー先のアプリをチェックすると、それぞれに独立した 1 件としてコピーされます。自動では有効にならず、以後の編集は互いに影響しません（Hermes の SOUL.md はペルソナなので、既定ではチェックされません）。

## インポート・エクスポート

### ディープリンクで共有

ディープリンクを生成してプリセットを共有できます：

```
ccswitch://v1/import?resource=prompt&app=claude&name=<名前>&content=<Base64 エンコードされたプロンプト内容>
```

パラメータの説明と例は [5.3 ディープリンクプロトコル](../5-faq/5.3-deeplink.md) を参照してください。

### 設定のエクスポートで共有

設定をエクスポートするとすべてのプリセットが含まれ、インポートで復元できます。
