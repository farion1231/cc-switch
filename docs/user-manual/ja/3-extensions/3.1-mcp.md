# 3.1 MCP サーバー管理

## MCP とは

MCP (Model Context Protocol) は、AI ツールが外部データソースやツールにアクセスできるようにするプロトコルです。MCP サーバーにより、AI は以下のことが可能になります：

- ファイルシステムへのアクセス
- ネットワークリクエストの実行
- データベースのクエリ
- 外部 API の呼び出し

## MCP パネルを開く

左サイドバーの **MCP** をクリックします。これはグローバルなページで、特定のアプリに属しません。どのアプリを選択していても同じパネルが開きます（Claude Desktop には独自の MCP がなく、ここにも列はありません）。

## パネル概要

ページはマトリクス表です。**1 行が 1 つの MCP サーバー、1 列が 1 つのアプリ**で、セルのスイッチが「この MCP をこのアプリで有効にする」を表します。

- ヘッダー：「アプリから取り込む」「MCP を追加」と、⋯ メニュー（「ここのスイッチで各アプリの設定を書き直す」「すべてを mcpServers JSON としてコピー」）
- 検索ボックス：名前・コマンド・URL で絞り込み
- サイドバーの「アプリ」ページで表示にしたアプリの列だけを表示します。非表示は画面にだけ影響し、非表示のアプリに書き込み済みの設定はそのまま残り、同期も続きます
- 各行の右側に「編集」ボタンと ⋯ メニュー（JSON としてコピー、ドキュメントを開く、すべてのアプリで有効化、すべてオフ、削除）があります
- あるアプリへの書き込みに失敗した場合、その行に失敗したアプリが表示され、「再試行」を押せます

## MCP サーバーの追加

### テンプレートを使用

1. ヘッダーの **MCP を追加** をクリックすると、右側にドロワーが開きます
2. 「テンプレートから始める」でテンプレートを選びます。空のまま自分で入力することもできます
3. 必要に応じて内容を変更し、「書き込み先」で有効にするアプリをチェックします
4. 「追加」をクリックします

### 設定を貼り付け

ドロワーの「設定を貼り付け」に JSON または TOML をそのまま貼り付けると、`mcpServers`、Codex の `[mcp_servers.名前]`、OpenCode の local / remote 形式を自動認識し、下のフォームに入力します。複数のサーバーをまとめて貼り付けた場合は、「新規」と「同名あり」のエントリーが一覧表示され、同名のものはスキップか上書きを選べます。

### 主なテンプレート

| テンプレート | パッケージ名 | 機能説明 |
|------|------|----------|
| fetch | mcp-server-fetch | HTTP リクエストツール、AI が Web コンテンツを取得可能に |
| time | mcp-server-time（`uvx` で実行） | 時間ツール、現在の時刻情報を提供 |
| memory | @modelcontextprotocol/server-memory | メモリツール、AI が情報を保存・検索可能に |
| sequential-thinking | @modelcontextprotocol/server-sequential-thinking | 思考連鎖ツール、AI の推論能力を強化 |
| context7 | @upstash/context7-mcp | ドキュメント検索ツール、技術ドキュメントをクエリ |

### カスタム設定

テンプレートを選ばずに自分で入力する場合は、以下を入力します：

| フィールド | 必須 | 説明 |
|------|------|------|
| 名前 | はい | 各アプリの設定ファイルに書き込まれるキー名。空白は使えません。保存後は変更できないため、変えたい場合は新規作成して古いものを削除します |
| 接続方式 | はい | ローカルコマンド（stdio）/ HTTP / SSE |
| コマンド | はい* | ローカルコマンドの場合は必須。プログラムだけ（例：`npx`、`uvx`）を書き、引数は別に入力します |
| 引数 | いいえ | コマンドライン引数。1 項目ずつ入力します |
| 環境変数 | いいえ | サーバーに渡す環境変数 |
| 作業ディレクトリ | いいえ | ローカルコマンドの場合は任意。空欄ならアプリが決めます |
| URL | はい* | HTTP / SSE の場合は必須。`http://` または `https://` で始めます |
| ヘッダー | いいえ | HTTP / SSE のリクエストヘッダー |
| 表示名、説明、タグ、ホームページ、ドキュメント | いいえ | 「説明とリンク」にまとまっており、CC Switch 内でだけ表示され、アプリの設定には書き込まれません |

「JSON で編集」をクリックして設定全体を直接編集することもできます。フォームと同じデータで、切り替え時に自動で同期されます。環境変数とヘッダーの値は JSON 内では `••••••••` と表示され、保存時は元の値が保持されます。

## 転送タイプ

### stdio（標準入出力）

最も一般的なタイプで、ローカルプロセスを起動して通信します。

```json
{
  "command": "uvx",
  "args": ["mcp-server-fetch"],
  "env": {}
}
```

**要件**：
- 対応するコマンド（例：`uvx`、`npx`）がインストールされている必要あり
- サーバープログラムが PATH に含まれている必要あり

### http

HTTP プロトコルでリモートサーバーと通信します。

```json
{
  "url": "http://localhost:8080/mcp"
}
```

### sse（Server-Sent Events）

SSE プロトコルでサーバーと通信し、リアルタイムプッシュをサポートします。Pi は SSE タイプに対応していません。

```json
{
  "url": "http://localhost:8080/sse"
}
```

## アプリバインド

各 MCP サーバーは、有効にするアプリを個別に制御できます。マトリクス内のその行・そのアプリ列のスイッチをクリックします。

### アプリ列の説明

| アプリ | 作用 | 設定ファイルパス |
|------|------|--------------|
| Claude Code | Claude Code に同期 | `~/.claude.json` の `mcpServers` |
| Codex | Codex に同期 | `~/.codex/config.toml` の `[mcp_servers]` |
| Gemini CLI | Gemini CLI に同期 | `~/.gemini/settings.json` の `mcpServers` |
| Grok Build | Grok Build に同期 | `~/.grok/config.toml` の `[mcp_servers]` |
| OpenCode | OpenCode に同期 | `~/.config/opencode/opencode.json` の `mcp` |
| Hermes | Hermes に同期 | `~/.hermes/config.yaml` の `mcp_servers` |
| Pi | Pi に同期（Pi 1.0 以降が必要） | `~/.pi/agent/mcp.json` |
| MiniMax Code | MiniMax Code に同期 | `~/.minimax/mcp.json` |

> ⚠️ **注意**：Claude Desktop と OpenClaw は CC Switch の MCP 同期に対応していないため、表にはこの 2 列がありません。MCP は上記の 8 アプリに対応しています。

列ヘッダーをクリックすると、その列を一括操作できます：「残り N 件を有効化」「すべて有効化」「すべてオフ」。対象は現在の一覧（検索や絞り込み後は結果）のエントリーだけで、操作後に「元に戻す」を押せます。各行の ⋯ メニューにも「すべてのアプリで有効化」と「すべてオフ」があります。

### スイッチの動作

あるアプリのスイッチをオンにすると、CC Switch は以下を実行します：

1. **データベースの更新**：そのアプリでのサーバーの有効状態を `true` に設定
2. **Live 設定に同期**：サーバー設定を対応アプリの設定ファイルに書き込み
3. **即時反映**：次回 CLI ツール起動時に新しい MCP サーバーが自動的にロード

あるアプリのスイッチをオフにすると、CC Switch は以下を実行します：

1. **データベースの更新**：対応アプリのステータスを `false` に設定
2. **Live 設定から削除**：アプリの設定ファイルからそのサーバーを削除
3. **即時反映**：次回 CLI ツール起動時にその MCP サーバーはロードされない

> 💡 CC Switch が管理するのはデータベースに存在するサーバーだけです。各ツールの設定に手動で追加し、CC Switch にインポートしていないサーバーは変更されません。ただし、アプリの設定内で CC Switch と同名のエントリーを直接編集した場合は上書きされ、CC Switch 側の内容が優先されます。**MiniMax Code と Pi は例外**：一括同期の際、これらで有効になっていないサーバーは `mcp.json` から削除されません。CC Switch で明示的にオフにするか削除した場合にのみ削除されます。

### 同期条件

MCP サーバーの同期は、対応アプリがインストールされている場合のみ実行されます：

- **Claude**：`~/.claude/` ディレクトリまたは `~/.claude.json` ファイルが存在する必要あり
- **Codex**：`~/.codex/` ディレクトリが存在する必要あり
- **Gemini**：`~/.gemini/` ディレクトリが存在する必要あり
- **Grok Build**：`~/.grok/` ディレクトリが存在する必要あり
- **OpenCode**：`~/.config/opencode/` ディレクトリが存在する必要あり
- **Hermes**：`~/.hermes/` ディレクトリが存在する必要あり
- **Pi**：`~/.pi/agent/mcp.json` に書き込みます（Pi の設定ディレクトリは `PI_CODING_AGENT_DIR` で指定できます）

> **ヒント**：CLI ツールがインストールされていない場合、対応するスイッチをオンにしてもエラーにはなりませんが、設定は書き込まれません。MiniMax Code は例外で、CC Switch はインストールの有無を確認せず `~/.minimax/mcp.json` に直接書き込み、ディレクトリがなければ自動的に作成します。

スイッチをオフにすると、設定はファイルから削除されます。

## サーバーの編集

1. サーバー行の右側にある「編集」ボタンをクリック
2. ドロワーで設定を変更（名前は変更できません）
3. 「保存」をクリック

変更は有効になっているアプリの設定ファイルに即座に同期されます。

## サーバーの削除

1. サーバー行の右側にある ⋯ メニューの「削除」をクリック
2. 削除を確認

削除は元に戻せません。設定は CC Switch と、そのサーバーを有効にしているすべてのアプリの設定ファイルから削除されます。

## 既存の設定のインポート

CLI ツールで既に MCP サーバーを設定している場合、CC Switch にインポートできます：

1. MCP ページ上部の「アプリから取り込む」ボタンをクリック
2. CC Switch が MCP 対応のすべてのアプリ（Claude Code / Codex / Gemini CLI / Grok Build / OpenCode / Hermes / Pi / MiniMax Code）の既存設定を一度に読み取ってインポート
3. 完了すると「取り込み完了」が表示され、追加された MCP と読み込んだファイルが一覧されます。新しいサーバーが見つからなかった場合は、新しい MCP は見つかりませんでした、と表示されます

インポートで読むのはユーザー単位の設定だけです。Claude Code で `claude mcp add` を使って既定でプロジェクトに追加した MCP や、プラグイン同梱の MCP はインポートされません。

インポートしたサーバーは、インポート元のアプリで自動的に有効になります。既存のサーバーと同名のものは該当アプリのスイッチがオンになるだけで、設定は引き続き CC Switch のものが優先されます。MiniMax Code からインポートする場合、有効状態には `mcp.json` の `enabled` フィールドの値がそのまま使われます。既存のサーバー設定と競合するエントリーや無効な設定のエントリーはインポートされず、その場合は「読み込めなかったアプリがあります」と表示され、理由が一覧されます。

## 設定ファイル形式

### Claude (`~/.claude.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

### Codex (`~/.codex/config.toml`)

```toml
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

### Gemini (`~/.gemini/settings.json`)

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## よくある質問

### サーバーの起動に失敗する

確認事項：
- コマンドが正しくインストールされているか（例：`uvx`）
- コマンドが PATH に含まれているか
- 引数が正しいか

### 設定が反映されない

確認事項：
- 対応するアプリのスイッチがオンになっているか
- CLI ツールを再起動したか
