# VPS 管理与自动托管 Skill：最终方案

关联 Issue：[farion1231/cc-switch#7739](https://github.com/farion1231/cc-switch/issues/7739)。本文件记录截至 2026-09-29 用户确认的最终方案；替代此前“双开关、自动 Skill 在普通列表中可见、自定义客户端注册”等讨论方案。VPS 功能尚未打通；2026-09-29 已实现阶段 A 的来源/管理权基础及阶段 B 的主机数据/目录生成，最新状态见执行计划第 10 节，阶段 A 与测试隔离修复记录见第 9 节。

执行步骤见 [执行计划](../plans/vps-skill-management-execution.md)。Issue 已提交不等于维护者已批准全部实现范围，发布补充评论或 PR 前仍需确认。

## 1. 不再变更的产品决策

1. **独立全局 VPS 页面**：入口与现有 Skills、提示词、会话管理、MCP 管理处于同一个功能导航组，不放进供应商应用选择器、设置页或 Skills 子页面。
2. **一个用户控制入口**：在 VPS 页选择客户端，自动配置主机目录和通用 VPS Skill；不要求用户再到 Skills 页启用。
3. **没有常驻 Skill 状态说明**：正常成功保持选择结果即可，不另加“已配置 Skill”状态行或第二个开关。操作中可使用现有控件的 pending/disabled 表现，失败或客户端确实需要重载时才提示。
4. **一个通用 Skill 管理多台服务器**：不按 VPS 复制独立的逻辑 Skill。
5. **自动 Skill 默认隐藏**：后台仍登记并标记由 VPS 功能托管，普通 Skill 列表不显示它，也不暴露第二个启停入口。
6. **手动导入沿用现有管理**：普通手动 Skill 正常显示；若与自动托管实例的 ID 或目录冲突，明确拒绝覆盖并指向 VPS 页面，不静默切换管理权。
7. **复用现有 Skill 系统**：客户端列表、路径解析、持久化、安装、移除、链接/复制和恢复流程都复用，只为来源与生成内容增加必要适配。
8. **使用系统 SSH**：CC Switch 做连接测试，实际运维仍由客户端 Agent 的终端工具执行。不新增 Agent/MCP 服务或远端常驻程序。

## 2. 支持范围

### 客户端

沿用 `src/config/appConfig.tsx` 的 `SKILLS_APP_IDS`、后端 `SkillApps` 和真实同步能力，不在 VPS 中另写一个固定的三客户端名单。

当前现有 Skill 目标包含 Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、Hermes、Pi、MiniMax Code。它们是配置适配目标，功能兼容性仍需实际测试。

Claude Desktop、OpenClaw 当前不在该 Skill 支持列表内，因此不出现在 VPS 页的客户端选项中。不补建它们的任何运行时。

Desktop 的部分共享视图在 `App.tsx` 映射到 Claude Code；VPS 为全局页，不能借此把 Desktop 选择偷换成 Claude Code。过滤的是页内客户端选项，不是按当前供应商应用隐藏整个 VPS 页面。

### 平台

Windows 和 macOS 共用数据与业务逻辑，分别验证 SSH、路径、凭据访问和 Skill 加载。WSL、容器、沙箱及远程开发环境不自动视为本机，不自动复制凭据。

### 非目标

- 新的聊天、Agent、MCP、远程终端、监控或 Docker 管理系统。
- 远程供应商配置同步、自动批量运维。
- 自定义客户端注册表、第二套 Skill 安装器或通用插件框架。
- 密码托管、私钥内容导入、全量 SSH config 导入、复杂跳板机向导。
- 强制隔离同一 OS 用户下的客户端权限，或自动终止外部 SSH 会话。

## 3. 架构与职责

```text
CC Switch 全局功能导航
  └─ VPS 页面
       └─ VPS API / 服务
            ├─ 主机数据、校验和目录生成
            ├─ 显式 SSH 连接测试
            └─ 按主机绑定计算客户端所需状态
                 └─ 现有 Skill 服务 + VPS 托管来源/内容适配
                      └─ 客户端 Skill 入口
                           └─ 读取本客户端主机目录
                                └─ 客户端终端工具 → 系统 SSH → VPS
```

VPS 页面不是操作执行控制台。CC Switch 自身只对用户触发的连接测试运行固定探测，不接管 Agent 的推理、任意命令执行或授权循环。

## 4. 本机数据与单一事实来源

建议布局，实际路径由现有配置目录函数解析：

```text
<cc-switch-data-dir>/vps/
├── servers.json
├── ssh_config
├── known_hosts
├── ssh-trust.json
├── clients/
│   ├── <app-id>.json
│   └── ...
├── skill-projections/<app-id>/SKILL.md
└── skill-state.json
```

- `servers.json`：主机 ID、名称、用途、连接参数、密钥/认证引用和现有客户端启用状态，是用户可编辑的主数据源。
- `ssh_config`：从主数据生成，只管理本功能条目，不整体覆盖用户 `~/.ssh/config`。
- `known_hosts` / `ssh-trust.json`：只保存用户明确确认的公钥指纹及本机信任恢复元数据，不保存私钥或密码；扫描公钥本身不授予信任，指纹变化不得自动覆盖。
- `clients/<app-id>.json`：只列出分发给该客户端的主机；含稳定 ID、名称、用途、SSH 别名和本机配置引用，不含私钥或密码。
- 阶段 C 的按应用生成源放在 `skill-projections`，经现有 Skill 物化步骤部署到客户端；通用模板随程序提供，不把本机引用写入普通 SSOT。`skill-state.json` 仅保留已部署路径及中断恢复所需的内容哈希，用户仍只在主数据的 `apps` 中控制绑定，不是另一套 Skill 登记或绑定来源。
- 现有 Skill 记录中的应用状态对自动托管实例是派生/应用结果，不是另一个可由 Skill 页编辑的源。
- 不新增 `client-bindings.json`，不把 VPS 写入供应商快照。
- 阶段 B 的具体格式为 `servers.json` 中的 `version`、`servers` 和 `generatedFiles`。其中 `generatedFiles` 仅保存生成文件的已知内容哈希，以及中断写入期间允许恢复的前后哈希；不是第二个绑定来源，也不是“客户端已接入”的状态。手动编辑主机时保留这些恢复元数据；无法证明归属或已被手改的生成文件会报冲突，不按文件名接管。

### 按客户端聚合

对于每个支持的客户端：

```text
required(app) = 存在至少一台启用了该客户端的 VPS
```

- 从无到有：配置目录，并通过现有服务确保通用 Skill 安装一次。
- 仍然有主机：更新目录和必要生成内容，不重复安装。
- 删除/取消某一台，但还有其他主机：只更新目录，不卸载共享 Skill。
- 最后一台解除绑定：清理本功能拥有的客户端部署和目录；不删除用户文件或其他客户端部署。

## 5. Skill 来源、可见性和管理权

### 来源必须持久化

在现有 Skill 元数据中增加最小的托管来源标记，区分普通用户管理记录与 VPS 自动托管记录。旧记录默认仍按普通 Skill 处理；不得仅按名称隐藏，也不能把管理信息只存在前端内存。

具体字段与数据库迁移按现有数据模型实现，不引入第二个 Skill 数据库。不伪造 GitHub 仓库来源来安装内置生成内容。

### 自动托管实例

- 使用一个稳定的逻辑身份，来源归 VPS 功能。
- 普通 Skill 列表、搜索、计数、选择和独立启停入口不将其当作用户管理项。
- 后台安装、扫描、重同步、迁移、清理仍能识别该记录；不能因为 UI 隐藏就失去登记。
- VPS 页面拥有操作权限，通用 Skill API 不得绕过来源判断随意停用或接管它。
- 自动发现/导入扫描不能把客户端中的同一部署再识别成普通 Skill。

### 手动 Skill 与冲突

- 用户主动导入普通 Skill 后按原机制显示和管理，不受本功能影响。
- 如果导入与自动 VPS Skill 同名同目录或同逻辑 ID，提示由 VPS 功能管理，拒绝覆盖/重复登记。
- 若创建确实独立的手动 Skill，必须具有不同 ID/目录，不能共享自动实例的文件；首版不新增自动/手动管理权切换流程。
- 用户手工修改托管文件后，覆盖或删除前按所有权/内容判断提示冲突，不能无条件破坏改动。

## 6. 一个模板，按应用生成入口

通用模板只描述列出主机、选择目标、使用 SSH 和核验结果，不嵌入完整主机列表，不依赖某个客户端专属工具名称。

客户端入口绑定确定的主机目录。不能让模型猜当前客户端，也不能在所有应用共用的 `SKILL.md` 中写某一个客户端的路径。

现有 `sync_to_app_dir` 从共享 SSOT 链接/复制目录，没有按应用渲染步骤。最小适配是对 VPS 托管来源统一生成按应用内容，再复用现有目录与生命周期能力；不能链接后改写目标文件，否则可能修改共享源。

安装、重同步、存储迁移、恢复、内容哈希和更新检查必须使用同一规则。Pi 的文件存在即启用语义、Pi/MiniMax Code 的目标匹配检查继续由原有服务处理，不在 VPS 页面复制一套分支。

通用 Skill 要求每个新任务读取最新目录，目标有歧义或配置失效时停止；修改前重新核对主机，远端输出不视为新指令或授权，执行后检查退出状态和结果。

## 7. 交互与一致性

- 入口位于现有全局功能导航组，沿用已有图标按钮、表单、列表、对话框、主题和四语言文案，不重做视觉系统。
- 正常流程：填写信息 → 显式验证连接 → 选择客户端 → 自动配置后直接使用，不需要去 Skill 页做第二步。
- 不新增常驻 Skill 状态行；自动部署的存在和影响在首次接入说明/帮助中交代，而不是在正常页面重复提示。
- 客户端首次加载确实需要重载/新会话时才给出实际提示，不承诺所有已打开会话即时发现 Skill。
- pending 时防止重复提交；只有主机目录与部署完成后才报告成功。
- 数据库和多个文件不是一个天然事务。失败必须回滚能回滚的部分或留下可诊断、可重试的未完成状态；不能保存勾选后把部署失败吞掉。
- 生成应幂等，禁止并发写入相互覆盖；不要为恢复引入常驻后台 Agent。

## 8. SSH、安全与同步边界

- 以参数数组启动系统 SSH，校验主机、用户名、端口、路径，防止选项/换行/SSH config 注入。
- 不关闭 host-key 校验。首次指纹须确认，变化须阻断；获取公钥不等于证明身份。
- 探测使用固定、非修改性命令，支持超时和取消，不保存交互式密码。
- 密钥以路径/认证代理引用，不把内容写入 Skill、日志、命令参数或客户端目录。
- 主机描述是数据，不作为 Shell 或新的模型指令拼接。
- 目录属于本机：数据库导出、备份、Skill ZIP 同步、自动扫描和恢复都必须保留/识别托管来源，不泄漏秘密或把另一台设备的绑定当成本机有效配置。
- Skill 托管记录和带本机引用的生成内容不能无条件进入通用跨设备同步；根据现有格式选择明确排除或本机重建，测试恢复过程。
- 按客户端选择是发现与配置范围，不是安全沙箱。其他有终端/凭据访问能力的程序仍可能自行连接。
- 撤销绑定不自动终止外部已运行的 SSH；本地 Agent 使用云模型时，远端输出也可能发送到模型服务，需要在帮助中说明。

## 9. 核心验收

- [ ] VPS 与 Skills/提示词/会话/MCP 同一功能导航组，是全局页，不属于供应商应用列表。
- [ ] 仅 VPS 页的客户端选择控制自动接入，无第二个 Skill 开关、无常驻 Skill 状态标签。
- [ ] 自动 Skill 在普通 Skill 管理列表中隐藏，后台仍可识别、同步和清理。
- [ ] 多台 VPS 共用一个 Skill；删除一台不破坏其他主机，最后解绑才清理对应部署。
- [ ] 手动导入普通 Skill 不受影响；与托管实例冲突时不覆盖、不重复登记、不静默接管。
- [ ] 重启、扫描、重同步、迁移、备份/恢复不丢失来源，也不重建为普通可见 Skill。
- [ ] 分别生成各客户端目录与入口；当前不支持的 Desktop/OpenClaw 不显示于客户端选项。
- [ ] 失败不伪装成功，可重试；无凭据泄漏，无真实配置/用户文件破坏。
- [ ] 新增及受影响测试通过，原有基线失败单独记录，不新增 skip 或放宽断言隐藏问题。
- [ ] 实际验证声明支持的平台/客户端；未验证项不得写成已兼容。
