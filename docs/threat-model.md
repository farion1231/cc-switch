# 威胁模型与保护边界

状态：设计阶段；以下控制均须由实现与测试证明。日期：2026-10-19。

## 资产与信任边界

保护对象为模型业务请求中的配置敏感值、本地令牌映射、密钥、会话授权、策略和覆盖状态。上游服务商、返回内容、输入文档、工具结果、客户端提供的 session ID 都是不可信输入。

信任边界依次为：Agent → 本地认证入口 → Shield 内核 → 现有路由/适配器 → 网络发送；上游响应 → 协议解析 → 作用域恢复 → 授权本地 Agent。磁盘、日志、备份、桌面 IPC 和退出配置恢复是额外边界。

MVP 假设操作系统、Shield 进程和系统密钥服务未被攻击者控制；不抵御 root/管理员、进程注入、任意内存读取或已获取同用户凭据的攻击。Agent 本地原始会话、源码和工具执行文件不自动纳入加密保护范围。

## 严格模式的准确含义

严格模式仅约束进入受控路径的请求：验证失败则拒绝发送。它不自动阻止操作系统里的其他网络请求。对于手动配置直连、独立环境变量、子进程、遥测、MCP 工具外发等旁路，要标记“未覆盖”，不能把不存在的系统级拦截记为测试成功。

兼容模式延后到 MVP 之后；届时任何降低保护的例外必须有范围、期限和明确操作，不能后台自动回退明文。

## 残余风险与发布条件

- 规则检测会有误报与漏报；发布报告必须说明合成/标注样本范围和指标分母。
- 模型可能利用上下文推断被隐藏值，令牌化不消除推断风险。
- 已恢复文本可能被 Agent 写入自己的历史或再次发送；下一次受管请求需要再次保护，工具和直连旁路仍有风险。
- 系统钥匙串与加密映射不防御已控制用户会话的攻击者；TTL 删除不保证闪存介质物理擦除。
- 当前全部 V01–V14 都是待实现/待验收项。任何发布声明必须引用具体测试报告、Agent 版本、协议、操作系统和配置。

范围扩展（新协议、工具恢复、多模态、企业租户或跨重启恢复）前更新本文件，再修改实现及测试。
