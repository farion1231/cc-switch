## 修订记录（实施阶段实测修正，最终代码以本记录为准）

本 spec 定稿于 2026-08-12；实施与实机验证（Claude Code 2.1.233）中发现 4 处设计需要修正，正文各章节保留原始设计供对照：

1. §1.1/§4.2 `[1m]` 追加条件：原「只有窗口 >= 1,000,000 才追加」→ 修正为「任何配置了窗口（>0）的接管别名都追加 `[1m]`」。实测：别名不带 `[1m]` 时 Claude Code 不读取 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` / `CLAUDE_CODE_AUTO_COMPACT_WINDOW` env，一律落 200K 默认；转发前剥离，无上游泄漏。
2. 自动同步直连解冻：原以为直连模式下自动同步不生效；实测直连模式同样生效，两种模式共用同一套 watcher。
3. §2.1/§2.4/§4.4 账本 userExplicit 来源：原三类来源方案实施中发现边界情况复杂、会反过来覆盖自动同步的正常行为，最终移除 userExplicit，仅保留 lastWritten / staticInjected。取舍：以上次切换模型的参数为主用参数；用户想手动写全局窗口值时，关掉同步开关后直接在 JSON 文件里写。
4. 窗口输入加强：原「仅数字 tokens」→ 支持 `200k` / `2m` 原始串输入，原始串另存 contextWindowTokens 仅用于回显，写 live 前剥离。

差异动机与验证细节见 PR 回复正文。

## 1. P1 阻断项

### 1.1 窗口编码进模型名：代理接管错误声明 + 直连后缀泄漏（Review: P1-1 + P1-3）

**根因**

窗口值被写进模型名，导致两个出口都出问题：

- 代理接管层把任意后缀当成 1M 并追加 `[1m]`，200K 模型被 Claude Code 按 100 万组织上下文；`claude-` 前缀下 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 不生效，env 压不回来。
- 直连层没有剥离逻辑，`deepseek-xxx[200k]` 会原样发往上游。

**技术选型理由 / 参考**

- 采用独立字段方案，模型名不再承载窗口。
- 参考仓库既有 Kimi / Codex OAuth 静态注入模式，以及 CodexPlusPlus“后缀只作输入语法、保存时剥离”的方式。

**澄清与分歧**

- 解析层能识别多格式与代理接管层错误声明可以同时成立，两条路径不同。
- 结论：以独立字段方案为准。

**具体改法**

- 新增 `contextWindows` 内部字段，key 为各角色 env 字段名，模型名保持干净。
- 旧数据兼容：读取已有配置时，把模型名中合法旧后缀迁移到 `contextWindows` 并清理模型名；迁移必须持久化写回 DB，不能只做内存解析。后端读取时保留兼容解析（不回写），保证未保存前旧数据也可用。
- 窗口来源回退顺序：`contextWindows[role]` → 解析模型名旧后缀 → 默认窗口；解析不到时按“不写 env、走 Claude 原生行为”处理。
- 空窗口：用户留空 = 不写入 `contextWindows` 对应值 = 不写 ACW/MAX env，交由 Claude 原生模式决定（未知模型默认 200K，`[1m]` 原生后缀仍可用）。
- 代理接管：只有窗口 >= 1,000,000 才追加 `[1m]`；先补回归测试：`glm-5.2` + 200K 窗口不得产出 `claude-sonnet-4-6[1m]`。
- 直连写 live 前保留防御性剥离（兼容外部修改），窗口从 `contextWindows` 转成 ACW/MAX env 注入；`[1m]` 也统一剥离，避免 #5177 同类 400。

### 1.2 Kimi For Coding 默认注入被移除（Review: P1-2）

**根因**

PR 把 main 的自动注入改成只透传显式值，watcher 又默认关闭，默认行为回退到 200K。

**技术选型理由 / 参考**

- Kimi 是直连、非 `claude-` 前缀，env 注入真实生效，是仓库既有且已验证的机制。
- 静态注入是默认路径，watcher 只做增强。

**澄清与分歧**

- “静态注入”指切换/激活供应商时立即写入 live settings 的 ACW/MAX，不依赖 watcher；Kimi 固定 262144、Codex OAuth 固定兜底窗口，以及 `contextWindows` 默认生成都属于静态注入。
- 与 backfill 来源识别中的“静态注入”是同一个概念。
- 结论：恢复静态注入，watcher 不覆盖它。

**具体改法**

- 恢复 `apply_kimi_for_coding_context_defaults` 自动注入 262144，恢复 `apply_codex_oauth_claude_context_defaults` 静态注入，用户显式值优先。
- 优先级：用户显式值 > 静态注入 > watcher 增强。
- Kimi / Codex OAuth 场景下，静态注入写 live 后 watcher 不再监管、不覆盖该值；只有用户显式修改或下次切换供应商时才更新。

## 2. P2 问题

### 2.1 backfill 识别三类来源（Review: P2-1）

**根因**

backfill 按全角色最大窗口计算期望值，watcher 按当前激活角色写值，策略不对称；且只认 watcher 写入会漏掉静态注入值。

**技术选型理由 / 参考**

- 账本统一区分三类来源：`lastWritten`（watcher 自动写入）、`staticInjected`（静态注入）、`userExplicit`（用户显式）。
- backfill 只清理自动来源的值，用户显式值始终保留。

**具体改法**

- `autoSyncState` 扩展为：
  ```json
  {
    "lastWritten": { "ACW": "200000", "MAX": "200000" },
    "staticInjected": { "ACW": "262144", "MAX": "262144" },
    "userExplicit": { "ACW": null, "MAX": "250000" }
  }
  ```
- 静态注入写 live 时记录 `staticInjected`；watcher 写时记录 `lastWritten`。
- backfill 清理条件：live 值等于 `lastWritten` 或 `staticInjected`，且 `userExplicit` 无对应值。
- 判定顺序固定：先 `userExplicit`，再 `lastWritten` / `staticInjected`。
- 无任何记录时，按当前激活角色优先、否则最大窗口兜底。

### 2.2 编辑当前供应商不显示 live 配置（Review: P2-2）

**根因**

`formResetScopeRef` 把 `form.reset` 门控为每 scope 一次；`liveSettings` 异步到达后 reset 被跳过，live 数据进不了表单，保存即丢。

**技术选型理由 / 参考**

- `EditProviderDialog` 已有 `hasLoadedLive` 状态，加载成功/失败都会置 true。
- loading gate 把“首次渲染时机”作为 gate，而不是“reset 次数”。

**澄清与分歧**

- `hasLoadedLive` 在加载失败时也是 true；如果失败时用 DB 快照渲染并允许保存，用户保存会用 DB 快照覆盖 live 里真实存在的值。
- 需要区分“live 不存在”和“加载失败”。

**具体改法**

- `EditProviderDialog` 在 live 加载完成前显示加载中，不渲染 `ProviderForm`。
- 加载失败时显示错误并禁用保存，或进入只读态，不能静默用 DB 快照覆盖 live。
- 用“表单已初始化标记”替代 `formResetScopeRef`：首次渲染 reset 一次；preset 切换、Codex 模板重置等原有 reset 路径保持各自逻辑，并补对应测试。

### 2.3 i18n 键错位（Review: P2-3）

**具体改法**

- 补 en / ja / zh-TW / zh 的 `autoSyncContextWindowTooltipOn`。

### 2.4 来源区分、关闭/打开行为与写入监测（Review: P2-4）

**根因**

`removeClaudeContextWindowEnvFields` 无条件删除 env 中的 ACW/MAX，不区分来源。

**技术选型理由 / 参考**

- 使用 `lastWritten` / `staticInjected` / `userExplicit` 三类账本。

**澄清与分歧**

写 live 文件前（无论开关开/关）都先检测用户是否修改了 ACW/MAX：

- 开关开启：live 值既不是 `lastWritten` 也不是 `staticInjected` 时，视为用户手填，记录到 `userExplicit`。
- 开关关闭默认行为：关闭瞬间清空 live 中的 ACW/MAX，DB 保留三类记录。
- 关闭瞬间用户同时写入：若 live 值不是自动来源，则保留该值，覆盖 DB 中旧 `userExplicit`，不删除。

**具体改法**

- 写 live 前置检测步骤：读当前 live → 比较三类账本 → 更新 `userExplicit`。
- 关闭：清空 live ACW/MAX；若有用户显式值则保留并覆盖旧值。
- 打开：恢复 `userExplicit`；没有显式值则恢复 `staticInjected` 或 `lastWritten`。
- watcher 写失败时不更新 `lastWritten`，写成功后才记账，避免 backfill 误判。
- watcher 写入采用原子读-改-写或写入前二次校验，发现冲突则跳过本次写入。

### 2.5 前端解析与 Rust 对齐（Review: P2-5）

**根因**

前端 `parseInt/parseFloat` 部分解析，Rust 全串拒绝。

**具体改法**

- 前后端统一规则：trim 后接受纯数字、`数字 + K/k`、`数字 + M/m`，大小写都接受；小数、逗号、下划线、空格、`1e3` 等一律拒绝且不写入。

### 2.6 Codex 上下文 UI（Review: P2-6）

**根因**

PR 解除 main 中被注释禁用的 Codex 上下文 UI，但未论证字段现状。

**技术选型理由 / 参考**

- 参考 CodexPlusPlus 的当前实现：独立数字输入，写 config.toml 顶层 `model_context_window` / `model_auto_compact_token_limit`。
- 按 CodexPlusPlus 现有方法处理顶层字段与 catalog 字段：两者并行写入，顶层字段作为 config.toml 的生效限制，catalog 字段负责模型列表/能力展示；实现时以 CodexPlusPlus 实测行为为准。

**具体改法**

- Codex 表单恢复独立数字输入，只允许数字。
- 保存时写顶层 `model_context_window` / `model_auto_compact_token_limit`。
- catalog 保留 `context_window` / `auto_compact_token_limit=null` / `truncation_policy` 独立逻辑。

### 2.7 cc-switch 内部字段不得泄漏（实现约束）

- `contextWindows`、`autoSyncState`、`autoSyncContextWindow`、`autoSyncCompactRatio` 均为 cc-switch 内部字段。
- Claude：`sanitize_claude_settings_for_live` 必须剥离全部内部字段，不写入 `settings.json`。
- Codex：写 config.toml 时只输出 `model_context_window` / `model_auto_compact_token_limit`，不输出内部字段。
- 补测试：sanitize 后 live 对象不含任何内部字段；Codex 输出不含 `contextWindows` / `autoSyncState`。

## 4. 技术选型结论汇总

1. Claude 窗口存独立字段 `contextWindows`，模型名干净；空窗口不写 env，走 Claude 原生。
2. 代理接管只对 >= 1M 的窗口追加 `[1m]`；直连/代理出口均防御性剥离。
3. Kimi / Codex OAuth 恢复静态注入；优先级：用户显式 > 静态注入 > watcher。
4. 账本统一三类来源：`lastWritten` / `staticInjected` / `userExplicit`。
5. backfill 只清理自动来源值，用户显式值保留。
6. 写 live 前检测用户修改；关闭清空 live、DB 保留；关闭瞬间用户写入保留并覆盖旧值。
7. watcher 同时监听 model 与 ACW/MAX 变化；写成功才记账；原子读-改-写防竞态。
8. 编辑页 live 加载完成后再渲染；失败时禁用保存。
9. 前端解析与 Rust 对齐（trim + 纯数字 / Kk / Mm）。
10. Codex 按 CodexPlusPlus 方法；内部字段不泄漏到 Claude / Codex 配置。

## 5. 数据流

1. 编辑保存：模型名干净 + `contextWindows` 写入 DB；旧后缀迁移持久化。
2. 切换供应商写 live：先检测用户是否手改 ACW/MAX，再按来源写入并记账（静态注入记 `staticInjected`）。
3. Claude Code 切换角色：watcher 按 `contextWindows` 写 ACW/MAX，记 `lastWritten`；同时监听 ACW/MAX 变化以记录 `userExplicit`。
4. 用户手改 live：写入前置检测识别为非自动来源，记 `userExplicit`。
5. backfill：清理 `lastWritten` / `staticInjected` 中无 `userExplicit` 的值。
6. 关闭自动同步：清空 live；关闭瞬间用户写入保留并覆盖 DB 旧值。
7. 打开自动同步：恢复 `userExplicit`，否则恢复 `staticInjected` / `lastWritten`。

## 6. 兼容与错误处理

- 旧后缀迁移：编辑保存时持久化写回；后端读取时兼容解析。
- `contextWindows` 缺失：按角色回退解析旧后缀，再回退“不写 env”。
- `userExplicit` 与自动来源值相同：以 `userExplicit` 为准。
- 无账本记录：backfill 按当前激活角色优先、否则最大窗口兜底。
- watcher 写失败：不更新 `lastWritten`，保留旧账本。
- live 加载失败：编辑页显示错误并禁用保存，避免 DB 快照覆盖 live。
- 内部字段泄漏防护：Claude sanitize、Codex 输出白名单。
