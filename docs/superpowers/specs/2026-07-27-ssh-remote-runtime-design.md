# CC Switch SSH 远程运行设计

## 1. 背景与目标

CC Switch 当前是单机 Tauri 应用。前端通过 Tauri `invoke` 调用同一进程内的 Rust 命令，Rust 服务直接访问本机的 SQLite、CLI 配置文件、代理端口和系统能力。项目目前没有 SSH 传输层，也没有可在无图形环境运行的后端入口。

本功能允许用户在本地 CC Switch 中保存多台 Linux 服务器，并把整个窗口切换到本机或其中一台远程服务器。进入远程环境后，所有适用于 Linux 的 CC Switch 数据和系统操作都在远端执行，本地界面保持现有布局、组件和交互习惯。

目标包括：

- 支持常见 Linux 服务器，包括 x86_64 和 aarch64。
- 复用系统 OpenSSH、`~/.ssh/config`、私钥、ssh-agent 和 `ProxyJump`。
- 自动部署与本地桌面端版本匹配的无界面 `cc-switch-agent`。
- 不要求 root，不在远端开放监听端口，不安装常驻服务。
- 支持请求、响应、事件、取消、心跳和大文件传输。
- 保存多台服务器，但单个窗口同一时刻只绑定本机或一台远端。
- 在断线、版本不兼容和部分能力不可用时提供明确、可恢复的状态。

## 2. 非目标与平台边界

第一版不支持 Windows Server、macOS 远端、SSH 密码保存、keyboard-interactive 登录或远程桌面转发。

下列能力始终属于本地桌面端：

- 主题、语言、窗口、托盘、开机启动和桌面应用更新。
- 本地文件选择器、保存对话框和系统通知。
- SSH 连接元数据与当前选择的运行环境。

下列能力在远程环境中由 Agent 执行：

- 供应商、MCP、Prompts、Skills、Profiles 与通用配置。
- 远端代理、故障转移、用量、会话、备份、同步和工作区文件。
- 远端 CLI live 配置、环境检查、模型读取和网络请求。

Linux 上不存在的桌面集成会返回结构化的 `CAPABILITY_UNAVAILABLE`，界面显示禁用原因。例如 Claude Desktop 集成不会在远端伪装成功。

## 3. 总体架构

系统增加四个边界清晰的模块：

1. `RuntimeTarget`：描述当前窗口操作本机还是某个远端，负责本地持久化和切换状态。
2. `RemoteConnectionManager`：管理 OpenSSH 子进程、Agent 部署、握手、心跳、重连和事件转发。
3. `RemoteCommandGateway`：提供统一命令调用入口，按命令能力表决定本地执行、远端执行或拒绝。
4. `cc-switch-agent`：复用现有数据库与 service 层的 Linux 无界面二进制，通过 stdio 提供协议服务。

前端不直接理解 SSH。新的 `appInvoke(command, args, options)` 替代业务代码中的直接 `invoke`：

- 当前目标为本机时，继续调用原 Tauri 命令，保持现有行为。
- 当前目标为远端时，调用本地 Tauri 的 `remote_invoke`，再由网关发送给 Agent。
- 连接管理、文件对话框、窗口、托盘和更新等本地命令显式标记为 `local_only`。
- 未登记命令默认拒绝远程执行，避免新增命令被意外暴露。

为了控制风险，不一次性重写全部 Tauri 命令。先完成供应商管理的端到端纵向闭环，再按能力域迁移其余命令。每一批都必须保持本机模式完全兼容，并有独立的能力清单和测试。

## 4. SSH 与 Agent 生命周期

连接流程如下：

1. 使用 `ssh -G <host-alias>` 解析系统 OpenSSH 配置，不自行解析 `~/.ssh/config`。
2. 使用批处理模式执行预检，验证主机密钥、认证方式、远端系统和架构。
3. 若主机密钥尚未进入 `known_hosts`，返回 `HOST_KEY_NOT_TRUSTED`。界面提供“在终端验证主机”操作，使用系统终端执行一次普通 `ssh <alias>`；CC Switch 不静默接受未知主机。
4. 根据 `uname -s` 与 `uname -m` 选择 Linux x86_64 或 aarch64 Agent。
5. 从本地签名缓存取得与桌面端匹配的 Agent；没有缓存时从官方 release manifest 下载并校验 SHA-256 与签名。
6. 上传到 `~/.cc-switch/agents/<app-version>/cc-switch-agent.tmp`，校验摘要后原子重命名并设置 `0700`。
7. 启动 `ssh <alias> ~/.cc-switch/agents/<version>/cc-switch-agent --stdio`，完成协议握手。
8. SSH 会话结束时 Agent 随 stdio EOF 退出。旧 Agent 仅保留最近两个版本，连接成功后异步清理更旧版本。

远端无需访问互联网、无需 sudo、无需 systemd，也不开放 TCP 端口。

## 5. 协议

协议运行在 SSH stdio 上。Agent 的日志只能写 stderr，stdout 只能写协议帧。

每帧由固定魔数、帧类型、协议版本、负载长度和负载组成。控制帧使用 JSON，文件块使用二进制负载。支持以下帧：

- `hello` / `hello_ack`：协商协议、应用版本、数据库 schema、平台和能力。
- `request` / `response`：命令调用与结果。
- `event`：转发 provider、profile、proxy、sync 等 Tauri 事件。
- `cancel`：取消仍在运行的可取消请求。
- `ping` / `pong`：连接健康检查。
- `chunk` / `chunk_ack`：带请求 ID、序号、总长度和 SHA-256 的文件分块。
- `protocol_error`：无法关联到普通请求的协议错误。

每个请求包含唯一 ID、命令名、参数、超时、目标环境 ID 和客户端操作 ID。写操作不会在断线后自动重试；只有明确标记为幂等的读操作可以在重连后重放。

握手返回协议 major/minor、CC Switch 版本、schema 版本、Agent 构建哈希和能力集合。major 不一致直接拒绝；minor 差异通过能力协商降级。数据库版本过新时只允许诊断和 Agent 升级，不允许业务写入。

## 6. 命令执行模型

Agent 不启动 Tauri 或 WebView。现有业务逻辑逐步下沉到不依赖 `AppHandle`、`State`、对话框或窗口的 service API，Agent 与 Tauri command 共同调用这些 API。

新增 `CommandCapabilityRegistry`，每条可调用能力声明：

- 运行位置：`local_only`、`remote_supported` 或 `platform_conditional`。
- 是否只读、是否幂等、默认超时和是否可取消。
- 所需远端能力和最小协议版本。
- 参数及返回值的稳定序列化名称。

命令注册采用显式白名单。Agent 收到未注册命令返回 `COMMAND_NOT_EXPOSED`。涉及文件路径的参数必须经过远端路径策略验证，禁止把本地绝对路径误当成远端路径。

首个纵向闭环覆盖：

- 获取供应商列表与当前供应商。
- 新增、编辑、删除、排序和切换供应商。
- live 配置写入和切换事件。
- Agent 状态、错误映射和前端 Query 缓存失效。

后续按 MCP/Prompts/Skills/Profiles、代理与用量、会话与工作区、同步与备份、认证与订阅的顺序扩展。

## 7. 本地数据模型

SSH 连接元数据保存在本机设备级设置中，不进入远端数据库或 WebDAV/S3 同步：

- 稳定 UUID、显示名称和 OpenSSH Host 别名。
- 可选用户名、端口和私钥路径覆盖；默认完全使用 OpenSSH 配置。
- 最后成功连接时间、远端平台、Agent 版本和能力缓存。
- 自动连接开关和排序信息。

不复制私钥，不保存 SSH 密码，不把凭据写入日志。UI 与日志中的主机、用户名和路径按场景脱敏。

当前运行目标保存在本机设置中。应用启动时若上次目标为远端，先显示本地壳和“正在连接”，连接失败则进入远端离线只读态，不自动切回本机，避免用户误操作本机配置。

## 8. 前端交互

视觉与交互沿用现有 CC Switch：

- 在现有顶部工具区增加紧凑的运行环境切换器，使用服务器图标、名称和状态点。
- 下拉菜单第一项为“本机”，其后为已保存服务器，并提供“管理服务器”。
- 设置页增加“远程服务器”分区，列表、增删改对话框、确认提示和 toast 复用当前组件。
- 切换环境时清空环境相关 Query cache，重新加载目标数据；切换期间禁用写操作。
- 顶部状态点区分连接中、在线、重连中、离线和不兼容。
- 离线时保留最后一次成功读取的数据供查看，页面显示持续状态条，所有写按钮禁用并解释原因。
- 远端不支持的能力保持原布局位置，使用禁用态和 tooltip 说明，不让页面结构跳动。
- “打开终端”在本机首选终端中执行 SSH，并在远端通过 Agent 生成一次性供应商环境启动命令。

连接对话框只要求显示名称和 Host 别名；用户名、端口、私钥路径放在高级选项中。测试连接会依次显示 SSH、平台、Agent 和 CC Switch 数据状态，不暴露原始命令行或凭据。

## 9. 文件与对话框语义

远端 Agent 不显示图形对话框：

- 导入本地文件：本地选择并读取，按分块协议上传到远端临时目录，再调用远端导入服务。
- 导出远端文件：Agent 生成临时文件并下载，本地再显示保存对话框。
- 远端路径选择：使用现有工作区文件浏览模式，不调用本地文件对话框。
- 所有临时文件采用随机名称、`0600` 权限，并在成功、失败、取消或连接关闭后清理。

单文件默认限制 256 MiB，可在后续根据备份规模调整。分块默认 1 MiB，支持流式校验和取消，不在内存中同时保留完整文件的多个副本。

## 10. 连接状态与错误处理

连接状态机为：`local`、`connecting`、`online`、`reconnecting`、`offline`、`incompatible`。

- 心跳间隔 15 秒，连续两个周期无响应进入重连。
- 重连采用带抖动的指数退避，1 秒起步，最高 30 秒。
- SSH 进程退出、协议损坏和 Agent panic 都会终止当前会话并记录结构化诊断。
- 读请求在断线时可返回带时间戳的最后成功数据；写请求立即返回 `REMOTE_OFFLINE`。
- 连接恢复后统一增加环境 generation，废弃旧 generation 的迟到响应，并按能力域失效 Query cache。
- 用户主动切换环境或断开时取消未完成请求，不自动重放写操作。

错误码至少覆盖 SSH 不可用、主机未信任、认证失败、平台不支持、架构不支持、Agent 缺失、Agent 校验失败、协议不兼容、命令不暴露、能力不可用、超时、取消、远端 I/O 和远端业务错误。

## 11. 安全设计

- 完全依赖 OpenSSH 的配置、known_hosts、密钥权限和 ssh-agent。
- 所有 SSH 参数使用参数数组传递，不拼接 shell 命令；Host 别名与远端路径经过严格校验。
- Agent 仅接受当前 SSH stdio 会话，不监听套接字。
- Agent artifact 必须同时通过签名和 SHA-256 校验，上传后再次校验。
- Agent 命令显式白名单，默认拒绝；危险文件操作限制在 CC Switch 管理目录和已声明的 CLI 配置路径。
- API key、token、私钥路径、完整 SSH 命令和协议敏感字段不进入普通日志。
- 远端命令返回的错误经过长度限制与控制字符清理后才能显示。

## 12. 测试策略

测试分四层：

1. 协议单元测试：帧编解码、半包、粘包、超限、取消、版本协商和损坏输入。
2. Agent 服务测试：内存数据库与临时 HOME 下的命令白名单、供应商 CRUD、live 文件和事件。
3. 本地连接测试：使用可控的假 SSH 进程验证部署、心跳、重连、迟到响应和 stderr 隔离。
4. Linux 集成测试：CI 容器中启动真实 sshd，使用临时密钥完成 Agent 上传、握手、供应商闭环、断线恢复和文件传输。

前端使用 MSW/Tauri mock 增加本机、连接中、在线、离线、不兼容及能力禁用状态。所有新增和修改代码必须包含中文维护型注释，重点解释远程状态、重试边界、幂等性和安全取舍。

## 13. 分阶段交付

### 阶段 A：协议与运行时基础

- Agent 二进制、协议 crate、能力注册表和假 SSH 测试工具。
- 本地连接管理、环境数据模型、SSH 预检和 Agent 部署框架。
- `appInvoke` 统一调用入口与本地模式回归测试。

### 阶段 B：供应商纵向闭环

- 环境切换器和服务器管理。
- 供应商读写、切换、live 配置、事件和缓存失效。
- 真实 Linux sshd 集成测试。

### 阶段 C：核心配置管理

- MCP、Prompts、Skills、Profiles、通用配置、设置、导入导出和备份。
- 文件上传下载与远端路径语义。

### 阶段 D：运行与观测能力

- 代理、故障转移、用量、请求日志、会话、工作区和 OpenClaw/Hermes Linux 能力。
- 长任务进度、取消和断线恢复。

### 阶段 E：认证、同步与完整覆盖

- 适用于远端 Linux 的 OAuth/订阅流程、WebDAV/S3、Deep Link 目标选择和剩余能力。
- 完整能力矩阵、版本升级回退、安装包内 Agent artifact 发布流水线和安全审计。

每个阶段必须满足：本机模式无回归、远程能力显式声明、失败可恢复、日志不泄密、测试通过后再扩大命令覆盖。

## 14. 成功标准

- 用户可保存多台 Linux 服务器并在本机/远端间切换，且不会混淆两边数据。
- 首次连接无需在远端手动安装 CC Switch、无需 sudo、无需开放端口。
- 供应商纵向闭环在真实 SSH 环境中与本机行为一致。
- 断线后没有重复写入，界面明确进入离线只读态，恢复后数据自动刷新。
- 平台不支持项有稳定的禁用态和原因，不出现假成功。
- 最终能力矩阵覆盖所有适用于远端 Linux 的 CC Switch 功能。
- 本地模式的现有 API、数据、测试和用户操作保持兼容。
