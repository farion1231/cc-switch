## Por que o CC Switch?

A codificação moderna baseada em IA depende de ferramentas como Claude Code, Claude Desktop, Codex, Gemini CLI, Grok Build, OpenCode, OpenClaw e Hermes — mas cada uma tem seu próprio formato de configuração. Alternar provedores de API significa editar manualmente arquivos JSON, TOML ou `.env`, e não há uma maneira unificada de gerenciar MCP e Skills entre várias ferramentas.

**CC Switch** fornece um único aplicativo desktop para gerenciar todas as ferramentas de IA suportadas. Em vez de editar arquivos de configuração manualmente, você obtém uma interface visual para importar provedores com um clique, alternar entre eles instantaneamente, com 50+ predefinições de provedores integrados, gerenciamento unificado de MCP e Skills, e alternância rápida da bandeja do sistema — tudo respaldado por um confiável banco de dados SQLite com gravações atômicas que protegem suas configurações da corrupção.

- **Um App, Oito Ferramentas** — Gerencie Claude Code, Claude Desktop, Codex, Gemini CLI, Grok Build, OpenCode, OpenClaw e Hermes em uma única interface
- **Sem Mais Edição Manual** — 50+ predefinições de provedores incluindo AWS Bedrock, NVIDIA NIM e retransmissões comunitárias; apenas escolha e alterne
- **MCP e Skills Unificados** — Um painel para gerenciar servidores MCP e Skills entre Claude, Codex, Gemini, Grok Build, OpenCode e Hermes com sincronização bidirecional
- **Alternância Rápida da Bandeja do Sistema** — Alterne provedores instantaneamente do menu da bandeja, sem necessidade de abrir o aplicativo completo
- **Sincronização em Nuvem** — Sincronize dados de provedores entre dispositivos via Dropbox, OneDrive, iCloud ou servidores WebDAV
- **Multiplataforma** — Aplicativo desktop nativo para Windows, macOS e Linux, desenvolvido com Tauri 2
- **Utilitários Integrados** — Inclui várias utilidades para confirmação de login na primeira execução, bypass de assinatura, sincronização de extensões de plugin e mais

## Perguntas Frequentes

<details>
<summary><strong>Quais ferramentas de IA o CC Switch suporta?</strong></summary>

O CC Switch suporta oito ferramentas: **Claude Code**, **Claude Desktop**, **Codex**, **Gemini CLI**, **Grok Build**, **OpenCode**, **OpenClaw** e **Hermes**. Cada ferramenta tem predefinições e gerenciamento de configuração dedicados.

</details>

<details>
<summary><strong>É necessário reiniciar o terminal após alternar provedores?</strong></summary>

Para a maioria das ferramentas, sim — reinicie seu terminal ou a CLI para que as alterações entrem em vigor. A exceção é **Claude Code**, que atualmente suporta alternância a quente de dados de provedores sem reiniciar.

</details>

<details>
<summary><strong>Minha configuração de plugins desapareceu após alternar provedores — o que aconteceu?</strong></summary>

O CC Switch fornece um recurso "Trecho de Configuração Comum" para passar dados comuns (além de chaves de API e endpoints) entre provedores. Vá para "Editar Provedor" → "Painel de Configuração Comum" → clique em "Extrair do Editor Atual" para salvar todos os dados comuns. Ao criar um novo provedor, marque "Aplicar Configuração Comum" (ativado por padrão) para incluir dados de plugins no novo provedor. Todas as suas configurações são preservadas no provedor padrão importado quando você inicia o aplicativo pela primeira vez.

</details>

<details>
<summary><strong>Instalação no macOS</strong></summary>

O CC Switch para macOS é assinado e notariado pela Apple. Você pode baixar e instalar diretamente — nenhuma etapa adicional necessária. Recomendamos usar o instalador `.dmg`.

</details>

<details>
<summary><strong>Por que não consigo excluir o provedor atualmente ativo?</strong></summary>

O CC Switch segue o princípio de "mínima interrupção" — mesmo que você desinstale o aplicativo, suas ferramentas CLI continuarão funcionando normalmente. O sistema sempre mantém uma configuração ativa, porque excluir todas as configurações tornaria a CLI correspondente inutilizável. Se você raramente usa uma CLI específica, você pode ocultá-la nas Configurações. Para voltar ao login oficial, veja a próxima pergunta.

</details>

<details>
<summary><strong>Como voltar para o login oficial?</strong></summary>

Adicione um provedor oficial da lista de predefinições. Após alternar para ele, execute o fluxo de logout/login, e então você pode alternar livremente entre o provedor oficial e provedores de terceiros. O Codex suporta alternância entre diferentes provedores oficiais, facilitando a troca entre várias contas Plus ou Team.

</details>

<details>
<summary><strong>Onde meus dados são armazenados?</strong></summary>

- **Banco de Dados**: `~/.cc-switch/cc-switch.db` (SQLite — provedores, MCP, prompts, skills)
- **Configurações Locais**: `~/.cc-switch/settings.json` (preferências de UI em nível de dispositivo)
- **Backups**: `~/.cc-switch/backups/` (rotação automática, mantém 10 mais recentes)
- **Skills**: `~/.cc-switch/skills/` (vinculados aos aplicativos correspondentes por padrão)
- **Backups de Skills**: `~/.cc-switch/skill-backups/` (criado automaticamente antes de desinstalar, mantém 20 mais recentes)

</details>

<details>
<summary><strong>Linux (Wayland + NVIDIA): cliques não registram e a janela fica preta ao redimensionar</strong></summary>

O AppImage força `GDK_BACKEND=x11` (XWayland) para evitar um antigo crash no Wayland nativo. Em configurações mais novas de Wayland + NVIDIA, isso pode deixar a área de conteúdo web sem resposta ao clique (os botões da barra de título ainda funcionam) e preto ao redimensionar. Lanç̧e com o escape hatch de opt-in para alternar de volta para Wayland nativo:

```bash
CC_SWITCH_GDK_BACKEND=wayland ./CC-Switch-*.AppImage
```

Se você iniciar a partir de um ícone da área de trabalho, adicione-o ao `Exec=` da `.desktop` (ex: `env CC_SWITCH_GDK_BACKEND=wayland /caminho/para/AppImage`) ou defina-o no ambiente da sessão. A variável é genérica: em compositores Wayland tiling (sway/Hyprland) onde cliques não registram, experimente `CC_SWITCH_GDK_BACKEND=x11` ao invés disso. Deixá-la sem definir mantém o comportamento padrão.

</details>

### Princípios de Design

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend (React + TS)                    │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐    │
│  │ Components  │  │    Hooks     │  │  TanStack Query  │    │
│  │   (UI)      │──│ (Bus. Logic) │──│   (Cache/Sync)   │    │
│  └─────────────┘  └──────────────┘  └──────────────────┘    │
└────────────────────────┬────────────────────────────────────┘
                         │ Tauri IPC
┌────────────────────────▼────────────────────────────────────┐
│                  Backend (Tauri + Rust)                     │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐    │
│  │  Commands   │  │   Services   │  │  Models/Config   │    │
│  │ (API Layer) │──│ (Bus. Layer) │──│     (Data)       │    │
│  └─────────────┘  └──────────────┘  └──────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

**Principais Padrões de Design**

- **SSOT** (Single Source of Truth): Todos os dados são armazenados em `~/.cc-switch/cc-switch.db` (SQLite)
- **Armazenamento de Camada Dupla**: SQLite para dados sincronizáveis, JSON para configurações em nível de dispositivo
- **Sincronização de Mão Dupla**: Grava em arquivos ativos ao alternar, preenche a partir do ativo ao editar o provedor ativo
- **Gravações Atômicas**: Arquivo temporário + padrão de renomear previne corrupção de configuração
- **Seguro contra Concorrência**: Conexão com banco de dados protegida por Mutex evita condições de corrida
- **Arquitetura em Camadas**: Separação clara (Comandos → Serviços → DAO → Banco de Dados)

**Principais Componentes**

- **ProviderService**: CRUD de provedores, alternância, preenchimento retroativo, ordenação
- **McpService**: Gerenciamento de servidores MCP, importação/exportação, sincronização de arquivos ativos
- **ProxyService**: Modo proxy local com alternância a quente e conversão de formato
- **SessionManager**: Navegação pelo histórico de conversas entre fontes de sessão suportadas
- **ConfigService**: Importação/exportação de configuração, rotação de backup
- **SpeedtestService**: Medição de latência de endpoints de API

### Desenvolvimento do Backend em Rust

```bash
cd src-tauri

# Formatar código Rust
cargo fmt

# Executar verificações do clippy
cargo clippy

# Executar testes do backend
cargo test

# Executar testes específicos
cargo test test_name

# Executar testes com recurso test-hooks
cargo test --features test-hooks
```

### Guia de Testes

**Testes do Frontend**:

- Utiliza **vitest** como framework de testes
- Utiliza **MSW (Mock Service Worker)** para mockar chamadas da API do Tauri
- Utiliza **@testing-library/react** para testes de componentes

**Executando Testes**:

```bash
# Executar todos os testes
pnpm test:unit

# Modo watch (re-execução automática)
pnpm test:unit:watch

# Com relatório de cobertura
pnpm test:unit --coverage
```

## Contribuindo

Issues e sugestões são muito bem-vindas!

Antes de enviar PRs, certifique-se de:

- Passar na verificação de tipos: `pnpm typecheck`
- Passar na verificação de formatação: `pnpm format:check`
- Passar nos testes unitários: `pnpm test:unit`

Para novos recursos, abra uma issue para discussão antes de enviar um PR. PRs para recursos que não se encaixam bem no projeto podem ser fechados.
