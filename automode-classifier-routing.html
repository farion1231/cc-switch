让 Auto Mode 分类器流量走单独供应商

目标：在 Claude Code 与上游之间的 LLM 网关里，识别出 auto mode 权限分类器发出的请求，并把它们转发到与主对话不同的供应商。本文汇总已核实的请求特征、相关环境变量、推荐实现和验证方法。

1. 一句话结论

可以做，但不能只靠 x-claude-code-request-class。这个头只有三个取值：main、subagent、auxiliary（外加 compaction 和 workflow 两个特例）。分类器和标题生成、记忆抽取等所有 side query 一样都是 auxiliary。要把分类器从其它辅助请求里单独挑出来，必须看 anthropic-beta 头（条件性存在）或请求体特征（稳定存在）。

2. 已核实的事实

  • 已核实 2.1.273 变更日志原文：新增 x-claude-code-request-class、x-claude-code-agent-type、x-claude-code-prev-tool-durations、x-claude-code-compaction、x-claude-code-context-compacted 请求头，"for LLM gateways"，通过 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 开启。
  • 已核实 分类器是客户端发起的独立 API 请求，走和主对话同一个 base URL。分类器分两阶段，两阶段的 querySource 都是 "auto_mode"。另外存在 "auto_mode_critique" 和 "auto_mode_setup_propose" 两个来源，属于 auto mode 的辅助请求。
  • 已核实 x-claude-code-request-class 的映射函数：querySource 以 repl_main_thread 开头或等于 sdk 为 main；以 agent: 开头或等于 hook_agent 为 subagent；其余一律 auxiliary。外层再把 compact 改为 compaction，workflow 内子代理改为 workflow。所以 auto_mode、标题生成、记忆抽取、compact 检查等共用 auxiliary，该头无法单独识别分类器。
  • 已核实 分类器专属 beta：anthropic-beta: auto-mode-classifier-2026-07-16。但只在 provider 判定为 firstParty 且另外两个条件成立时才附加，走 Bedrock、Vertex 或被识别为 gateway 登录方式时不附加。存在时是最干净的头级信号。
  • 已核实 cc_workload 和 User-Agent 里的 workload/... 来自 AsyncLocalStorage，在一轮对话开始时按 turn 设置（例如 cron 触发），不按请求类型区分，对本需求无用。
  • 已核实 开关逻辑：环境变量 CLAUDE_CODE_GATEWAY_HINT_HEADERS 若设置则以其为准；否则若登录方式被识别为 gateway 则默认开启；否则仅第一方 API 时依赖远程 feature flag。
  • 已核实 分类器请求强制携带归因头（forceAttributionHeader: true），格式为 x-anthropic-billing-header: cc_version=...; cc_entrypoint=...。该头对主对话也会发送，不能用于区分。
  • 已核实 分类器请求体特征：skipSystemPromptPrefix: true（不带 Claude Code 主 system prompt 前缀）；messages 里把对话包在两个独立的 text block "<transcript>\n" 和 "</transcript>\n" 之间；第二阶段设 stop_sequences: ["</block>"] 或 ["</severity>"]；显式设置 temperature。
  • 已核实 max_tokens：第一阶段 fast 为 256 加余量，thinking 变体为 64 加余量；第二阶段为 8192 加余量。
  • 已核实 分类器模型由独立函数 getPermissionClassifierExternalDefault 与 getPermissionClassifierFlagshipRerouteTarget 决定，与主对话模型解耦。默认值没有读到。
  • 已核实 存在环境变量 CLAUDE_CODE_AUTO_MODE_SERVER，控制 thirdPartyServerClassifierEnabled。未设置时，默认为"非（禁用实验 beta 且不由宿主管理供应商）"。

3. 可用于路由的信号

信号位置可靠性说明
anthropic-beta 含 auto-mode-classifier-2026-07-16请求头已核实分类器专属。仅在 firstParty provider 且附加条件成立时出现，抓包确认你的部署下是否存在。若存在，用它做第一判定。
x-claude-code-request-class = auxiliary请求头已核实需要 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1。只能把分类器和主对话、子代理分开，不能和其它辅助请求分开。用作预过滤，减少需要解析 body 的请求数。
stop_sequences 含 </block> 或 </severity>请求体已核实主对话不会设置这两个 stop sequence。覆盖第二阶段和带 severity 的第一阶段，不覆盖 fast 第一阶段。
messages 含独立 text block <transcript>\n请求体已核实覆盖分类器所有阶段。检查 messages[].content[].text 是否恰好等于该字符串。
system 不以 Claude Code 主 prompt 前缀开头请求体已核实辅助信号，单独使用会误伤其它 side query（如标题生成、compact）。
model 字段请求体推断分类器模型独立配置，通常与主对话不同，但用户手动改主模型后可能重合，不建议作为唯一依据。

4. 相关环境变量

变量作用建议
CLAUDE_CODE_GATEWAY_HINT_HEADERS开启网关提示头，包括 request-class设为 1
CLAUDE_CODE_AUTO_MODE_SERVER是否启用"第三方服务端分类器"。启用时分类器可能作为 beta 附在主请求上由服务端执行，网关看不到独立请求设为 0，强制走客户端独立请求（推断，见第 7 节）
CLAUDE_CODE_ATTRIBUTION_HEADER为 0 时关闭归因头不要关闭，保留 cc_workload 作为交叉信号
ANTHROPIC_CUSTOM_HEADERS用户自定义头，所有请求统一附加无法按请求类型区分，不适合本需求

5. 推荐实现

在网关的请求处理入口按下面顺序判定，命中任一条即视为分类器请求并转发到分类器专用上游。头信号优先，体信号兜底。

function isAutoModeClassifier(req):
    betas = req.headers.get("anthropic-beta", "")
    if "auto-mode-classifier-" in betas:        # 分类器专属 beta，存在即命中
        return True

    cls = req.headers.get("x-claude-code-request-class")
    if cls is not None and cls != "auxiliary":  # main / subagent / compaction / workflow 直接放行
        return False

    body = req.json
    stops = body.get("stop_sequences", [])
    if "</block>" in stops or "</severity>" in stops:
        return True

    for msg in body.get("messages", []):
        content = msg.get("content")
        if isinstance(content, list):
            for block in content:
                if block.get("type") == "text" and block.get("text") == "<transcript>\n":
                    return True
    return False

转发到不同供应商时要处理的兼容点：

  • 分类器请求可能带 anthropic-beta 和 extraBodyParams。代码里有"beta 被拒绝（HTTP 400）后去掉该 beta 重试"的逻辑，所以目标供应商不支持某个 beta 时返回 400 即可，客户端会自行降级并记住。
  • 分类器解析响应文本中的 XML 标签（<block>、<severity>）。目标供应商必须原样返回文本，不能做内容改写或截断。
  • stop_reason 为 refusal 时客户端会判定为"被安全机制拒绝"并阻止操作。目标供应商如果不产生这个值，行为是安全侧的。
  • 分类器有超时和 deadline，按阶段区分。目标供应商延迟过高会导致分类器超时，auto mode 退回人工确认。

6. 验证步骤

  1. 启动 Claude Code 时设置 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1，ANTHROPIC_BASE_URL 指向网关。
  2. 网关开启请求日志，至少记录：所有 x-claude-code-* 头、x-anthropic-billing-header、anthropic-beta、model、max_tokens、stop_sequences、system 前 80 字符。
  3. 进入 auto mode，让 Claude 执行一个会触发权限判定的操作，例如写文件或运行非只读 shell 命令。
  4. 在日志里找到主对话请求之外的额外请求。用第 3 节的信号逐一核对，记录 x-claude-code-request-class 的实际值和 cc_workload 的实际值，回填到第 5 节的 CLASSIFIER_CLASSES。
  5. 启用路由规则，再触发一次权限判定，确认分类器上游收到了请求、主对话上游没收到，且 Claude Code 端显示 "Allowed by auto mode classifier" 或 "Denied by auto mode classifier" 而不是回退到人工确认。
  6. 覆盖 fast 第一阶段：确认没有 stop_sequences 的小 max_tokens 请求也被 transcript 规则命中。

7. 未确认项

  1. anthropic-beta: auto-mode-classifier-2026-07-16 在你的部署下是否出现。 附加条件之一是 provider 为 firstParty，另两个条件的函数没读到。抓包一次即知，不出现就完全依赖 body 规则。
  2. 分类器默认模型。 由 getPermissionClassifierExternalDefault 决定，值未读到。同样抓包即得。
  3. CLAUDE_CODE_AUTO_MODE_SERVER 的完整语义。 符号名显示存在 serverClassifierRequest、serverClassifierResults、isThirdPartyServerClassifierRefused、serverClassifierFallbackChoice。推断：服务端分类器模式下，判定结果随主请求返回；第三方上游拒绝该 beta 后客户端会记住并提示 fallback 选择。需要在两种取值下各抓一次包对比。
  4. auto_mode_critique 和 auto_mode_setup_propose 是否也要分流。 它们不是权限判定本身。建议先只分流 auto_mode，观察后再决定。

8. 风险

auto mode 本身会阻止对它的分析。 本文的信息来自对本机二进制的字符串与代码片段检索。在 auto mode 下执行这类检索时，分类器会以 "Auto-Mode Bypass" 为由拒绝命令。执行本任务的 agent 若需要继续读二进制，请在非 auto 模式下运行，或提前添加允许规则。

  • 分流后分类器质量取决于目标供应商的模型。分类器 prompt 是为 Anthropic 模型调的，换供应商可能提高误判率，两个方向都可能。
  • 分类器请求体包含完整对话 transcript。转发到另一供应商等于把对话内容也发过去，注意数据合规。
  • Claude Code 升级后 querySource 或头名可能变化。把路由规则做成配置而不是硬编码，并保留体信号兜底。

9. 区分 auxiliary 下的各类请求

所有非主线程、非子代理的请求在 x-claude-code-request-class 里都是 auxiliary（compact 除外，见下）。forkLabel 只用于遥测，不进请求头。要细分到"标题生成、记忆抽取、auto mode"这一级，只能靠请求体。二进制里的辅助请求按构造方式分三类，每类的识别位置不同。

三种构造方式

  • A. 独立 side query。 自带 system prompt，不带 Claude Code 主 prompt 前缀，无 tools，通常有很小的 max_tokens。识别位置：system 开头或 messages[0] 开头。
  • B. 带 JSON schema 的 side query。 同 A，但多数带 output_format: {type: "json_schema"}。识别位置：system 开头加 schema 字段名。
  • C. fork 主对话。 复用主对话的 system prompt、tools 和完整 messages，只在末尾追加一条 user 消息。model 也是主模型。识别位置：最后一条 user 消息的开头。这类请求除了 request-class 头以外，和主对话请求长得几乎一样。

function classifyAuxiliary(req):
    h = req.headers
    if "auto-mode-classifier-" in h.get("anthropic-beta", ""):
        return "auto_mode"
    cls = h.get("x-claude-code-request-class")
    if cls == "compaction" or "x-claude-code-compaction" in h:
        return "compact"
    if cls in ("main", "subagent", "workflow"):
        return cls

    body = req.json
    sys_text = first_text(body.get("system"))          # string 或 [{type:"text",text}]
    last_user = last_user_text(body["messages"])        # 最后一条 role=user 的首个 text block
    stops = body.get("stop_sequences", [])

    # A/B 类：看 system 开头
    if sys_text.startswith("You are naming a coding session"):          return "generate_session_title"
    if sys_text.startswith("Generate a short kebab-case name"):          return "rename_generate_name"
    if sys_text.startswith("Write a short summary label"):               return "tool_use_summary_generation"
    if sys_text.startswith("You write the terminal status line"):        return "narration"
    if "title of the Github issue" in sys_text:                          return "feedback"

    # auto mode 分类器（无 beta 头时）
    if has_text_block(body["messages"], "<transcript>\n") or set(stops) & {"</block>", "</severity>"}:
        return "auto_mode"

    # C 类：看最后一条 user 消息开头
    if last_user.startswith("You are now acting as the memory extraction subagent."): return "extract_memories"
    if last_user.startswith("CRITICAL: Respond with TEXT ONLY."):                     return "compact"
    if last_user.startswith("[SUGGESTION MODE:"):                                      return "prompt_suggestion"
    if last_user.startswith("Describe your most recent action in 3-5 words"):        return "agent_summary"
    if last_user.startswith("The user stepped away and is coming back."):            return "away_summary"
    if "Sessions since last consolidation" in last_user:                              return "auto_dream"
    if "Simply answer the question with the information you have." in last_user:     return "side_question"
    if "Please generate a title and branch name for this session" in last_user:      return "teleport_generate_title"
    if last_user.startswith("Summarize this portion of a Claude Code session"):      return "insights"
    if last_user.startswith("2-4 word lowercase label"):                              return "agent_namer"
    if body.get("max_tokens") == 1 and last_user == "Hi":                            return "model_validation"
    return "auxiliary_other"

注意事项：提示词文本随版本变化，把这些前缀做成配置表并在升级后回归一次。C 类请求的 messages 很大，只解析最后一条 user 消息即可，不要扫描全文。
